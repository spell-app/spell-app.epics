Two separate problems with epic lint, both seen on 2026-11-14 and 15.

The first is a hang. The agent splitting run-on items into paragraphs ran epic lint on language, epic-engine and editor. Running it on the same epic twice in a row sometimes hung for more than 2 minutes: on epic-engine, and once on editor. The agent stopped those runs. Editor's lint ran fine when it ran on its own.

The hang may not be lint's own fault. At the same time, filing this item (an epic add) also took more than 2 minutes. Later on the 15th, epic agents done and epic add failed with "epic-engine.plan.html.lock held for 20s: stuck?" while other agents were editing the page. So the suspicion is that commands are waiting on each other for the epic page's lock. That is a suspicion, not proven.

The second is a miscount. T74's check flags an item with a paragraph of 5 or more sentences (DENSE: in epic lint). It counts each item of a numbered list written inside a sentence ("1. Example, 2. Markup, 3. ...") as a sentence of its own. So epic-engine's M12 is flagged by mistake.

Fixing the hang means finding what holds the page lock that long: an edit that is slow while it holds the lock, a migration running on every edit, or a lock that is never freed. While a command waits, it should also say who holds the lock.

Fixing the miscount means the sentence count skips list numbers.

Measured first: one edit of epic-engine's page took about 40 seconds, and 33 of them were one migration, "changes-after-goal", which runs on every edit. For each phase's Changes field it walked the whole page to work out comment anchors, even when the field was already in its place.

The fix: check whether the field is in its place first, and skip the anchors when it is. An edit then takes about 4 seconds.

Waiting: an edit waits up to two minutes for the page instead of failing at 20 seconds, and after five seconds it says who holds the page ("waiting for the page by pid 123 (epic add ...)"). A timeout names the holder too.

The miscount: a number like "2." in a list written inline no longer ends a sentence.
