Found by T71's live trial. The session-start hook says P72's stand-aside words only when ClaudeHome.isPluginEnabled() finds superpowers in the person's own settings. Turned on any other way (a project's .claude/settings.json, which is how a team shares a plugin, a local settings file, or claude --plugin-dir), a session started in an epic's worktree without /epic gets no words at all, and the clashes bite.

  • Install (clash 11): with no words, 1 of 4 Opus runs of superpowers' worktree skill ran npm install in the yarn repo. It wrote a package-lock.json and rewrote yarn.lock's resolved line to registry.npmjs.org with no hash.
  • Finish (clash 4): with no words, its option 1 ran a bare git -C <main checkout> merge sp-test, skipping all of /epic done.
  • With the words, the same prompts did neither: 3 of 3 runs with the hook's words, 3 of 3 with them in the repo's AGENTS.md, 2 of 2 in a session /epic had started.
  • One way: read enabledPlugins from the project and local settings too.
  • Or: epic init offers to put the words in the repo's AGENTS.md, which the trial shows superpowers obeys.
