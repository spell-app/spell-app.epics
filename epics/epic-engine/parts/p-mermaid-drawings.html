Spell UI can't draw a Mermaid diagram: a page shows its text as code.

A new Spell UI component, <ui-mermaid>: you write a diagram in Mermaid's text format, and the page draws it, in the page's own colours.

  • "phase: new spell-ui component: mermaid drawing which takes mermaid format input and draws in various styles. Check the latest features of mermaid and make the phase description but don't write it."

  • Mermaid text in, a drawing out. The diagram's text goes inside the tag, as <ui-code>'s does, or comes from a file.
    • Change the text (or the file) and the drawing redraws.
    • Its script API matches <ui-diagram>'s: get the drawing as an SVG file's text, or download it.
  • "Various styles." By default the drawing wears the page's look: Spell UI's colour and font tokens, light or dark as the page is.
    • It redraws by itself when the page switches theme, or between light and dark.
    • On top, a few picked looks: Mermaid's line styles (classic, hand-drawn, and its newer "neo"), and a few colour presets (Spell's own README look, and some of Mermaid's themes).
    • Which ones, and what the attributes are called, are this phase's choices (below).
  • Every kind of diagram Mermaid 12.3 draws (released 2026-11-03).
    • The classics: flowchart, sequence, class, state, entity-relationship, Gantt, pie, user journey, git graph, mindmap, timeline.
    • The newer ones: architecture, block, packet, kanban, radar, treemap, Sankey, XY chart, quadrant, requirement, C4, venn, Ishikawa, Wardley, Cynefin, tree view, swimlanes, use case, event modeling, agent flow.
    • Left out: ZenUML, a separate plugin of its own.
    • The components page shows a handful; the rest work the same way.
  • Pages without it pay nothing. Mermaid loads the first time a page shows a <ui-mermaid>, as <ui-code>'s highlighter does.
    • Then each kind of diagram loads its own piece only when a page uses it.
  • A clear message for a mistake in the text. When the text can't be read, the drawing's place says so in plain words (the novice voice), and which line.
    • Mermaid's own message is folded under it, and the text is shown so you can find the mistake.
    • Never Mermaid's own "bomb" picture, and never a blank space.
  • Safe by default. Text in the diagram can't run scripts or add markup: Mermaid's strictest setting, always.
  • Its components page and docs, as every Spell UI component has: a page with live examples of each look and some diagram kinds, in light and dark; its vocabulary, in English and Spanish.

What Mermaid is now, and what this was planned from:

  • Mermaid 12.3.0 is the latest (2026-11-03). 12.0 (2026-09-10) was a big step:
    • It made ELK, the fancier layout engine, the default for flowcharts, state, class and ER diagrams, and bundled it in.
    • It added the "neo" look and the redux themes, and the use case diagram.
    • It needs a 2024 browser (Safari 17.4 or newer).
  • Looks (look): classic, hand-drawn, neo. Since 12.0 each kind of diagram can have its own.
  • Themes: 11 of them (default, neutral, dark, forest, base, neo, neo-dark, redux, redux-dark, redux-color, redux-dark-color). Only base takes your own colours (themeVariables), and only as hex colours. So the component turns the page's tokens into hex before each drawing.
  • Dark mode is not automatic: Mermaid draws in whatever colours it was given, so the component redraws on a switch.
  • Settings can also ride at the top of the diagram's own text (its "frontmatter" config: block); the diagram's own settings win.
  • Icons (architecture diagrams, flowchart icon shapes): icon packs are registered and fetched only when a diagram names one.
  • Size, measured on 12.3.0: the first load is about 134 kB gzipped; each kind of diagram adds its own piece; ELK adds about 509 kB, and maths (KaTeX) about 79 kB, only for a diagram that uses them.
  • Sources: Mermaid's releases (12.0.0 to 12.3.0), its docs, theming, usage and securityLevel, icons; the sizes from the npm package, gzipped.
  • A new component, <ui-mermaid>, draws Mermaid text in the page's colours, light or dark, in a few picked looks.
  • Mermaid loads only on pages that use it.
  • Its components page shows each look and a handful of diagram kinds.

Which "styles" it offers. The page's own look is always the default; the question is what else.

  • Line styles: classic, hand-drawn, neo (Mermaid's newest).
  • Colours: the page's tokens (default), Spell's README look, and Mermaid's own neutral, forest and redux.
  • Each preset has a dark twin, picked by itself when the page is dark.
  • All 11 of Mermaid's themes, by their own names.
  • More to choose from, but most ignore the page's colours, and you pick dark ones by hand.
  • Smallest: every drawing matches the page, and nothing else.
  • A different look comes from a Spell UI theme, as for every other component.

What the attributes are called. Spell UI already uses theme on <ui-root> for light and dark, so Mermaid's own word would mean two things.

  • look="hand-drawn", palette="forest", layout="elk".
  • Kebab-case values, as every Spell UI attribute; each has a Spanish name.
  • theme="forest", look="handDrawn": what Mermaid's docs say, copied as is.
  • Familiar to Mermaid users, but theme clashes with Spell UI's.
  • appearance="hand-drawn", as <ui-button appearance="basic">, plus palette.
  • Reads like the rest of Spell UI, but Mermaid users look for "look".

How it relates to yarn mermaid:pretty, the tool that gives the READMEs' Mermaid pictures Spell's look. GitHub draws those pictures itself, so the tool stays either way.

  • The tool's colours move into Spell UI; the tool reads them from there, and the component offers them as its spell preset.
  • A README picture and the same diagram on a page look alike, and a colour change lands in both.
  • The tool stays as it is; the component has only the page's tokens and Mermaid's presets.
  • Two copies of "Spell's look" that can drift.

Which layout engine by default. Mermaid 12 switched to ELK, which lays out big flowcharts better but is a 509 kB download.

  • Most pages never fetch the 509 kB; layout="elk", or the diagram's own settings, ask for it.
  • Drawings look as they did before Mermaid 12.
  • Neater big flowcharts, as Mermaid's own site now draws them; every flowchart page fetches the 509 kB.

Adding Mermaid itself. It's a new dependency, which the house style asks you about first.

  • Installed with the kit, so it works offline (airplane mode) and in tests.
  • On the published package's optional list: the spell and epic commands don't install it.
  • No new dependency, but no drawings offline, and a page depends on a third-party site.
  • Smaller, but leaves out ELK, mindmaps' layout and maths: some diagrams would draw differently or not at all.

  1. Add Mermaid, lazily. mermaid@^12.3 becomes a Spell UI dependency (the dependency choice).
    • On the published package's optional list, so the spell and epic commands don't install it.
    • It loads through one engine file, imported only on first use: the same shape as <ui-code>'s highlighter and its lazy engine.
    • One Mermaid per page: set up once, every drawing queued through it, since Mermaid draws one diagram at a time.
  2. The component, <ui-mermaid>, in its own folder, laid out as every Spell UI family is.
    • Its text: its own content (a <script type="text/plain"> keeps < exact), or a source file: the loading component <ui-code> is built on, reused.
    • Draws into its shadow root, each drawing with its own id, so two on a page never mix up their styles.
    • Script API named as <ui-diagram>'s: the SVG's text, and a download of it.
    • The text shows plain until the drawing arrives, so the page never jumps from nothing.
  3. The page's look. Mermaid takes only hex colours, so before each drawing the component reads the page's tokens as hex and hands them to Mermaid's customisable theme.
    • Reuses the colour probe the tokens docs page already has, moved into Spell UI's runtime so both share it (coherence).
    • Background, text, lines, accent and font come from the tokens; Mermaid works out the rest.
    • Redraws when a theme is applied (Spell UI's theme-applied event) and when the page goes light or dark (the kit's one dark-mode query, and the dark class).
  4. The picked looks, as the choices say: the line styles (classic, hand-drawn, neo), the colour presets with their dark twins, and the layout engine.
    • The Spell preset is mermaid:pretty's palette, moved into Spell UI and read by the tool from there (the third choice; coherence).
    • A diagram's own settings, in its text, still win over the attributes.
  5. Safe text. Always Mermaid's strict mode: markup in labels is shown as text, and click handlers are off. A test checks a script in the text never runs.
  6. The error state. The text is checked first; when Mermaid can't read it:
    • A short message in the novice voice, naming the line, e.g. "This drawing has a mistake on line 3, so it can't be shown yet."
    • Mermaid's own message folded under it, and the text below, so you can find the mistake.
    • The ui-error event every loading component sends, so a page can react.
    • The wording passes spell voice check.
  7. Vocabulary and Spanish. Its tag, attributes, values and texts in its English vocabulary; a Spanish dictionary beside it.
  8. Markdown (if the last choice says so): a ```mermaid block in <ui-markdown> draws as a <ui-mermaid>.
  9. Its components page, ui-mermaid.html, made with site:new and listed in the index.
    • Live examples: a flowchart in each look, then a sequence diagram, a state diagram, a mindmap, an architecture diagram with icons, a kanban board, a packet and a radar chart.
    • An example with a mistake, to show the error state.
  10. Checked, as Verify says:
    • Browser tests (the browser project): each look draws; theme and light / dark switches redraw; the error state; the script never runs.
    • yarn measure: a page without the tag loads nothing more.
    • The designer check over its page, light and dark, desktop and phone.
    • yarn mermaid:pretty --check, then yarn review in Spell UI and the kit.
