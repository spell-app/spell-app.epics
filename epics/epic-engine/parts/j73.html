r9's point 8 wasn't a selector at all. Both symptoms came from one stale setting, EPIC_CHECKOUT, which repo-split's VS Code window had carried since it was opened from the long-gone spell-app.worktrees/epic-eject worktree.

  • How it leaked: epic window runs code with EPIC_CHECKOUT set, and VS Code gives the window it opens that command's environment, so every Claude session in the window inherited it. Seen live: repo-split's Claude process had EPIC_CHECKOUT=/Users/owen/www/spell-app/spell-app.worktrees/epic-eject.
  • What it broke: the docs tools take EPIC_CHECKOUT as their checkout, so check-spell.js looked for pages in epic-eject/pages ("epic server not used"), and with --base asked 4747 for /../../spell-app.epics/...: a 404 page, with no <main>, hence the getBoundingClientRect crash.
  • The fixes:
    • window.mjs opens windows without the engine's own settings (codeEnv())
    • the prompt and handoff hooks always take the session's own folder, never an inherited EPIC_CHECKOUT
    • an EPIC_CHECKOUT that names no folder is left out, with a line on stderr (envCheckout(), for pages.js and window.mjs)
    • check-spell.js stops with a plain message on a page outside the content folder, or a server's error page, instead of crashing; and no longer assumes a <main>
  • The alternative: only guarding the selector would have hidden it; the check would have "passed" on a 404 page.
