How should epic live with superpowers, the skills plugin a couple of devs you know like? The full evaluation is in P72 · Superpowers, sections 1-4.

  • Why it comes up: someone with superpowers installed who tries epic gets two plugins that both want to plan, both make worktrees, and both finish the branch.
  • They're mostly complementary: superpowers is about how the agent works (test first, root cause, proof); epic is about how you and the agent agree, and what's kept.
What it takes What breaks or is lost
A. Side by side, epic in charge, borrowing two disciplines A paragraph in the epic skill and guide, a few lines at session start in an epic's worktree, a "proof" rule for Done, a plan-check agent per phase, a README section, a trial run. About 4-6h. One more agent per phase. superpowers' brainstorm and plan files aren't used inside an epic.
B. Side by side only The paragraph, the session-start lines, the README section, the trial. About 2-3h. epic gains nothing of superpowers' discipline unless superpowers is installed.
C. Compatible: plans both ways A verb writing a phase's plan as a superpowers plan file, and one reading a superpowers design doc in as a new epic. About 8-12h, plus A or B. Their plans are far finer (code written out per task); an epic plan exported is thin for their executor. Two plan records to keep in step.
D. Nothing Nothing, beyond this evaluation. A superpowers user who tries epic meets the clashes in section 4 unwarned.

A is recommended: B is cheaper but leaves the clashes to whoever installs both with no gain for anyone who doesn't; C is real work for devs who haven't asked for it yet.

  • P72's build plan is built as written.
  • In an epic, superpowers stands aside for planning, worktrees and finishing, and its test, debugging and proof skills are used inside a phase.
  • Every epic's phase gets a plan check and a Done list with the checks' output, superpowers or not.
  • Plans both ways (C) stays a todo.
