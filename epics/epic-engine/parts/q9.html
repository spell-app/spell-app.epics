  • The repos only use what's BELOW them: spell-lang needs just the kit, and spell-epic sits above it, so spell-lang can't import spell-epic's code.
  • And spell-lang is checked in CI without spell-epic cloned: the translator must still run there, as a batch.
  • The translator runs epic choices ... as a separate program, the way a person would, and reads its JSON.
  • Only when asked (a flag such as --ask): without it, or with no epic installed, it runs as a batch, as today.
  • No code moves; spell-lang names no spell-epic file, only a command.
  • Cost: a command's output is the contract, so it's tested and kept stable.
  • The kit gets a tiny helper both use: write the rows file, wait on the answer file, read it. The page server and the page stay spell-epic's.
  • Cost: the files' shapes live in the kit, away from the page that reads them; two repos change together.
  • The whole choice page, elements and all, moves down into the kit, so spell-lang imports it.
  • Cost: a big move for one caller; the kit's elements would need the epics' look.
