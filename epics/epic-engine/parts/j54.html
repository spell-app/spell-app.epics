For I47, a command naming another repo's epic (/epic resume epic-engine in spell-app's window) is let through with a note, not blocked: Claude asks, then runs epic window launch epic-engine --prompt "/epic resume epic-engine", which opens spell-epic's window from here. The session is NOT renamed: a spell-app session titled 🚧 epic-engine would count as the epic's session, and the launch would type into it.

  • Why not a block: a block makes Owen type the launch himself; the note matches how /epic <name> in another worktree already works. The worktree hook still refuses the worktree if Claude goes on anyway.
  • Why the launch, not EnterWorktree with a path: per its own docs, EnterWorktree only enters a worktree of the session's own repo (or one nested in it), so a spell-app session can't enter spell-epic.worktrees/epic-engine. The refusal names the path for a session started in spell-epic.
  • Also: epic list --json run in spell-epic now gives spell-app's epics a repo and a checkout of ../spell-app (or their worktree there), not main, which meant spell-epic's main.
  • The other way: block the prompt, or have the hook run the launch itself.
