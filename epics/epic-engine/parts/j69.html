The epic server now starts spell dev bundles build --stale with the CLI of the spell-app checkout it uses (.spell-app) as it starts, in the background, so it never waits for spell-app's page server to build Spell UI's site bundle (r8 point 5).

  • How: it reuses spell-app's own BundleBuild from the page-server package ($/page-server, a new alias in tsconfig.base.json): the same command, log lines (bundles: ... in server.log), and a request for a missing bundle file waiting while it runs. EpicServer.start({ bundles }), on by default; the tests pass bundles: false, so no test builds in the real checkout.
  • Checked: a scratch server on port 4911 logged bundles: ui-site: current, bundles: brand: current.
  • The alternative: a small spawner of spell-epic's own, which would repeat what BundleBuild already does.
