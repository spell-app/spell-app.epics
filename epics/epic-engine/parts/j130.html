Your M1 said a node with no key is matched by its place (its tag and its index among same-tag siblings). I kept that for addresses and for every node that changed, but first line up the siblings that are UNCHANGED (the longest run in common), then match the rest by place between them.

  • Why: by place alone, a paragraph added at the top of a section is a text edit in every paragraph below it, plus an insert at the end. Lined up first, it is one insert, which is the 'as granular as possible' you asked for.
  • Addresses are still by place (#p-x/section[2]/p[3]), so a list the server works out later reads the same.
  • Over 250,000 pairs to compare in one parent, it falls back to place alone.
