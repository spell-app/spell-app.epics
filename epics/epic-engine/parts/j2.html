spell-epic tracks .spell-app as a relative link, ../spell-app. From the main checkout that is spell-app's main checkout; from a worktree, one folder deeper (spell-epic.worktrees/<name>/), it is spell-epic.worktrees/spell-app, which wasn't there, so the packages that come through it (portal:./.spell-app/packages/...) failed to install (I13).

  • What I chose: the worktree hook (linkOutside()) runs right after git worktree add. For every tracked link that leaves the worktree, finds nothing from there, and resolves in the main checkout, it makes the missing target as a link to what main's link finds. For spell-epic that is ONE link, spell-epic.worktrees/spell-app -> ../spell-app, the same one you made by hand, shared by every worktree there.
  • Why: nothing in the worktree changes, so git sees nothing and a merge or reset can't undo it; it works for any repo with such a link, not only spell-epic; and a fresh clone still installs with no tool run first (bin/epic itself needs the install).
  • Not chosen: pointing each worktree's .spell-app at main's target (a tracked file changed in every worktree, hidden with skip-worktree); or an untracked link written from .epic/config.json5, as engineFolder is (a fresh clone couldn't install before running epic, which needs the install).
  • It never replaces anything already there, makes no folders, and a link it can't make is a warning. Tested in WorktreeHook.test.ts.
