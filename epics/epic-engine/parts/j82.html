Two different rules for the two merges, both saying per repo what happened (repo-split's C5):

  • epic worktree merge-main merges each repo's main into its <epic> branch, the child repos lowest first, the top last. A repo that stops on conflicts, or fails, is reported and the others still merge: merging main in only ever touches the epic's own branches. --continue goes on only where a merge is in progress.
  • epic merge <epic> moves the repos' mains, so it checks every repo whose branch has commits first (on main, clean, holding all of main), and merges nothing if one fails. Fast-forward only, as before; repos with no commits are left alone.
