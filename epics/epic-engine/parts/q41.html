For P49 · One Repo Tooling: what happens to the main checkout's old child-repo clones (~/www/spell/spell-ui, spell-parser, spell-epic, spell-app) once repo-split's P20 has merged them into the kit.

  • An older worktree's child checkouts are git worktrees OF those clones: deleting a clone breaks them, and their unmerged commits live only there.
  • The new folders have other names (ui/ ...), so the clones don't collide with them.
  • Main's .gitignore keeps ignoring /spell-*/ until then.
  • A new epic worktree retire-clones deletes them, and refuses while any worktree still has a child checkout of one, or a branch in one has commits nobody has carried across.
  • Cost: four old folders beside the new ones for a while (the install, the page server and VS Code's Quick Open must skip them).
  • The kit's main folder is clean at once.
  • Cost: git worktree repair in each older worktree's child checkouts; a missed one loses its git until repaired.
  • Nothing left over.
  • Cost: only safe when every older branch has crossed first (the crossing question, option C).

Example: with A, after P20 ls ~/www/spell shows ui/ and spell-ui/; once debut, elemental-spell and epic-engine have crossed, epic worktree retire-clones removes the four spell-* folders but spell-brand.

  • the old clones stay, ignored, until a command retires them
  • no older worktree loses its git
