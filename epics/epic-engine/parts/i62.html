The 31 seconds is I67's bug, already fixed there (the commit is on main too). I measured it, then took the rest of the time out as well.

Where the time went, in epic worktree status no-such-name from ~/www/spell/spell-app:

  • Nearly all of it is Sessions.named(): it looks for sessions titled with the name, or that worked in its worktree, by reading every saved session transcript.
  • Before I67 it resolved real paths on disk for every line of every transcript: 29.7 seconds on this machine (the old code, run on its own).
  • After I67 it resolves each folder once, but still reads all 197 transcripts (1.6GB): 1.65 seconds of a 1.9 second command, and growing with every session.
  • So the command no longer reproduces the 31 seconds, and the 'worktree status' test passes in the full suite. No step needed to be skipped for an unknown name, because a session can be titled with a name that has no worktree.

What changed:

  • A new TranscriptIndex remembers what each transcript names (its titles and the folders it worked in), in ~/.claude/spell-epic/transcript-index.json.
  • A transcript is read again only when its size or modified time changed. So a run reads the few sessions that are active and none of the rest.
  • Sessions.named() asks the index first, and still reads a transcript in full only when it can match, as before. Which worktree a folder is in is asked fresh every run, so a config change is never stale.
  • It is best effort: a missing, damaged or old-version file is an empty index, and a failed write is skipped.
  • The output of worktree status and session find is unchanged.

Checked:

  • yarn ts and yarn lint in spell-epic: 0 errors, 0 warnings.
  • yarn vp test run: 149 files, 1565 passed, 2 skipped (was 148 files and 1555: one new test file with 9 tests, one new test in the sessions file).
  • New tests: what a scan finds, an unchanged transcript not read again (also by a later run), a grown or rewritten one read again, a deleted one dropped, a damaged index file, a write that fails. And in the sessions tests: a rename made after the index was built is still found.
  • epic worktree status and epic session find take about 0.3 seconds, however many sessions there are, after one slower run (3 seconds) that builds the index.
