P3 adds a migration step for the docs pages, components-not-markup (in src/tools/to-components.js, listed in migrate.js STEPS, dated 2026-10-19). It turns content written by hand into the components the templates use. The main session runs it after the merge; nothing in the shared content was touched here.

  • A bare <table> gets the house comparison wrapper, <ui-table celled compact striped unstackable>. The table inside is unchanged, its id too.
  • A <details> with a <summary> becomes the house aside, <ui-accordion class="spell-aside" styled> (spell-code when it holds just one code block). Its id and classes are kept. It starts folded, as every aside does: an open one is named in the report. The alternative was keeping it open as open="0"; I went with the house rule ("default to closed").
  • Left alone and listed in the report, "LEFT for a person": a table with its own class, style or role (which look it should get is a call), a <details> that is not a plain summary and body, either one inside an <epic-*> element that reads its children, and everything on a page that runs its own script or styles tables itself.
  • Not the step's job: a page's own buttons (its script wires them), headings outside <ui-section> (where the section ends is a call), and the markup our tools draw (the Epics list, the commands tables). The other P3 agents turn that last group into elements.
  • The survey found nothing for it in spell-app's content today. Every table in guides, pages, details pages and templates is already in a <ui-table>, and there are no <details> asides. A dry run on the real content changes 0 pages, so the step is a safety net for pages written later, and for other repos' content.
