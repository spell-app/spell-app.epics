Found while checking P15 in a browser.

  • After a page server restart, a page's writes are refused (its token is old). ServerLink was meant to fetch the page again and take the new token from it.
  • But the server sends a script's fetch() of a page the file as it is on disk, without the token (so <ui-include> never sees it). So the refresh never found one, and every write after a restart said "reload the page": saves, marks, notes, the agents panel.
  • The unit tests didn't catch it: their fake server put the token in.
  • Fixed in P15: the page is read in a hidden frame with its scripts off, the way the browser loads a page, and the token taken from there. Checked in Chromium against the real epic server: a stale token, then the save goes through with no reload.
A page open across a page server restart now saves again by itself; before, nothing typed after the restart was saved until a reload.
