The image zoom (click a screenshot, see it full size) moves out of the epics pack into Spell UI. This decides what Spell UI calls it, and so what a page writes to get it.

  • Today it's <epic-zoom>: no page writes it; the docs runtime makes one per page.
  • The images people want full size are plain <img>: screenshots in epic pages, guides, details pages and Markdown.
  • One <ui-zoom> per page, plus the rule for which images open in it.
  • Every plain <img> on the page can open full size, as on an epic page today.
  • An option on <ui-image> can come later, opening the same zoom.
  • Cost: one more tag in Spell UI's list.
  • <ui-image zoom src="..."> opens full size.
  • Cost: it never reaches a plain <img>, so every screenshot in every page would have to be rewritten as a <ui-image>, Markdown ones included. 
<!-- A:  nothing new;  the screenshot opens full size -->
<img src="shots/toolbar.png" alt="The toolbar">

<!-- B:  each one rewritten -->
<ui-image zoom src="shots/toolbar.png" alt="The toolbar"></ui-image>
  • <epic-zoom> becomes <ui-zoom>, in Spell UI, with a components page
  • any page's screenshots can open full size, not only an epic page's
  • no page has to change how it writes its images
