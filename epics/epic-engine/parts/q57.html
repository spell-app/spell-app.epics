Choices

A · Written, by the same backfill (recommended)

  • The backfill that fills each phase's Commits list also adds a Log entry per commit it finds.
  • It runs where it runs today (phase done, merge), and epic commits --backfill by hand.
  • Works offline and with airplane mode, in any checkout, and after the worktree is gone.
  • A commit made mid-phase shows once the phase is done or the backfill runs.
  • Why recommended: one way commits reach the page, and the page stays a plain file.

B · Read from git when the page is served

  • The page server runs git over every repo when the Log opens, and draws the entries.
  • Always up to the minute, nothing stored.
  • Costs: a git walk of several repos per page load, nothing when the page is opened as a file, and a second way commits reach the page beside the stored Commits lists.
  • the backfill writes Log entries as well as Commits lists
  • the Log is current after each phase done and merge; epic commits <name> --backfill brings it up to date any time
