The Epics page (epics/index.html) is now one <epic-list> holding every epic as an <epic-card>, written flat by epic pages index (by group, then title).

  • The list draws the five group headings and their counts, the saga chips, and places each card under its heading from its own shadow root: a ::slotted() rule per card, with CSS order, and display: none for a hidden one.
  • So nothing moves the page's cards any more: starring one, a saga chip, the sort, a live update of the page, and the page server's running cards all just re-place them.
  • The page server no longer rebuilds the groups as text: it adds the running epics' cards before the end marker and marks each card running and favorite (RunningEpics.render()).
  • Each card draws its own state mark from its facts (phases, updated, urgent ...) as of now, by the one rule (EpicState).

The alternative: an <epic-card-group> element per group, with cards moved between groups on a star click (what the docs runtime did by hand). Rejected: an element moving the page's markup fights the live update (a moved card could show twice) and kept the server regrouping strings.
