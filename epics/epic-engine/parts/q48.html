For epic-engine's P49 · One Repo Tooling: how the epic tooling knows a repo is a PEER of the kit (beside ~/www/spell, not inside it), and where its main checkout is, now that repo-split's P20 · One Repo moves spell-brand out to ~/www/spell-brand (Q47).

  • Today every reader looks for a child repo at <kit>/<name>: EpicConfig.repoCheckouts(), the page server's childRepos(), the repos tool's isCloned(). spell-brand at ~/www/spell-brand is found by none of them, so an epic's worktree would get no spell-brand worktree and the page server no Brand tab.
  • ONE rule, read by all three, is what this asks for.
  • { "name": "spell-brand", "url": ..., "needs": [], "peer": true } in the kit's repos.json5: its main checkout is ../spell-brand from the kit's main checkout.
  • One list still: lowest first, needs across inside and peer repos alike.
  • EpicConfig gets peers beside repos; the repos tool and the page server read the same flag.
  • Cost: a fixed place, beside the kit; a peer somewhere else needs option B.
  • "peers": [{ "name": "spell-brand", "path": "../spell-brand", ... }], beside "repos".
  • A peer may live anywhere.
  • Cost: two lists to keep in order, and needs reaching across them; a path nobody needs yet.
  • The page server already falls back to <kit>/node_modules/<name>; the epic tooling would follow that link's real path.
  • Cost: nothing is known before yarn install has run, and the worktree hook makes the worktrees BEFORE the install: it couldn't know to make spell-brand's.

Example: with A, epic config repos prints the inside repos and epic config peers prints spell-brand /Users/owen/www/spell-brand; yarn clone spell-brand clones it to ~/www/spell-brand, not ~/www/spell/spell-brand.

  • one list says which repos there are and where each lives
  • the hook, merge-main, removal, yarn clone and the page server all find spell-brand by it
