Installing Spell will print no deprecated warnings, and the audit will show no critical or high problems but the ones listed as left open. The fixes

    • It was Owen's pick (J41) because it writes a whole value at a time and removes any key the value leaves out. The replacement keeps that behaviour.
    • The replacement will be a small JSON5 editor of our own that keeps comments, in src/util/node/json5.ts, with no new dependency.
    • DataFile's null workaround goes if it's no longer needed.
  2. vite-plus 1.0.0 to 1.5.1, with the catalog and resolutions together (Vite core 1.5.1, Vitest and @vitest/* 5.1.0; vp toolchain has the final list), then spell-brand's copy of .yarnrc.yml. It should also clear the 2 yuku warnings, which isn't confirmed yet.
  3. Solid 2.0.0-rc.17 to the latest next (rc.21 when checked), with every pinned @solidjs/* and resolutions, reading the Solid 2 rules in full first. This clears seroval.
  4. monaco-editor to a version without the vulnerable DOMPurify. 0.57.0 pins 3.4.15, the advisories run through 3.4.16, and 3.4.17 is clean. Whether such a Monaco exists hasn't been checked; if not, it goes on the known-open list.
  5. query-string ^6 to 10 in $fetch and abortableFetch, checking its ES-module and API changes.
  6. A lockfile refresh for tar 7.4.3, shell-quote 1.8.3, brace-expansion, minimatch, picomatch, glob, ip-address, lodash, source-map-js and the rest.
  7. Left open, each written into the code-debt log at build time:

    • deepmerge through @inkjs/ui

The check

  • A new spell deps check will be the one command. It fails on any deprecated package and any critical or high advisory that isn't on the known-open list.
  • The known-open list will be one file. Each entry names the package, the advisory and the reason, and an entry that no longer matches anything also fails, so the list can't go stale.
  • spell publish will fail, not just report. It runs the same rules on its scratch install: what npm install warns about, and npm audit. That's what an outside person gets, which the lockfile can't show.
  • Pushes to GitHub: recommended is a thin git pre-push hook that runs spell deps check only when a push updates main.
    • Why a hook: pushes here are typed by hand, so a line in a skill would get forgotten.
    • Cost: the audit measured 1.5 seconds, and branch pushes aren't touched. The build will time the whole hook; if it adds more than 5 seconds, the hook is dropped and the push steps in the skills call the command instead.
    • If the registry can't be reached, the hook says so and lets the push through, since the check couldn't run.
  • The command goes on the commands page (commands.json5, then spell commands check).

Worth knowing

  • Never run npm audit fix --force: its proposed fix downgrades spell to 0.8.1.
  • resolutions don't reach people installing from npm, so the real dependencies have to change.
  • Nothing goes to npm until Owen says so (push but don't update npm stands).
  • This phase's work and Split Epic's Dependencies must pass the new check before they're pushed.
