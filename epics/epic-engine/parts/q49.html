For epic-engine's P49 · One Repo Tooling, with spell-brand a peer at ~/www/spell-brand (Q47): how it joins the kit's checkout and its ONE install.

  • Today it's a workspace of the kit's install (the root's "workspaces": ["spell-*"]), so it shares the kit's one Solid, and the page server, the bundles (BUNDLES' spell-brand/src sources) and the Linker (ONE_PACKAGE_REPOS) find it at <kit>/spell-brand.
  • repo-split's P20 · One Repo leaves "how it finds the spell package outside the kit's install" to a judgement call of its own: this question answers it for both epics, so the two must agree.
  • The kit's repos.ts links (every yarn install) and the worktree hook write <kit>/spell-brand, a link: main's to ~/www/spell-brand, an epic worktree's to the epic's spell-brand worktree.
  • So it stays a workspace of the one install (one Solid), and the page server's settings parts, the bundles and the Linker find it as today, unchanged.
  • Cost: yarn taking a linked folder as a workspace is untested (checked first, in the plan's step 1); the kit's .gitignore line /spell-*/ doesn't match a link (git sees a file), so it gains /spell-brand; the folder is out on disk but still in the kit's tree through the link.
  • yarn install in ~/www/spell-brand, the kit as portal:../spell.
  • Truly separate: nothing of it in the kit's folder.
  • Cost: a second Solid copy (the kit's "one copy of each package" rule breaks, and pages mixing brand and Spell UI elements get two); a second install per worktree; the page server, bundles and Linker each learn the peer's path.
  • One install, no link.
  • Cost: right only in main: from an epic's worktree ../spell-brand is ~/www/spell.worktrees/spell-brand, so each worktree would rewrite package.json and yarn.lock, and merge-main fight over them.

Example: with A, ls -l ~/www/spell/spell-brand shows spell-brand -> ../spell-brand, and in debut's worktree spell-brand -> ~/www/spell-brand.worktrees/debut; the Brand tab is served from that, the worktree's own.

  • spell-brand lives in its own folder, and the kit sees it through one link
  • the install, page server, bundles and Linker change nothing; the epic tooling writes the link
