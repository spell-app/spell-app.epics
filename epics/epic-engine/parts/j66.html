The docs tools and the epic server now read the component sets from the settings of the checkout they work on (its root package.json's "pageServer" "componentSets", through componentSets(pageServerSettings(checkout))), as r8 asked, instead of spell-app's COMPONENT_SETS.

  • Epic UI stays a set even where the settings don't name it (spell-epic's own checkout, a repo epic init set up): the epic server serves it for every repo. ComponentSetFolders appends it; ServedFolders.under() adds it, found through the checkout's spell-epic link as the templates are.
  • Example: in spell-epic's own checkout, src/docs/epic-item.html is still components/epics/epic-item.html; packages/app/docs/x.html there is no set's page, since spell-epic names no App UI.
  • The home page's set cards (index.js) now name their set by id (epics, ui, app); a set the checkout doesn't name gets no card, as before.
  • The alternative: keep reading spell-app's settings through .spell-app for every checkout: the old behaviour, but every repo would take spell-app's sets.
