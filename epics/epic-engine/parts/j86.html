The fix for I61. The server tool's spec names a package now (package: "@spell-app/server", its src/page/cli.ts and tsconfig.json). It doesn't name a path inside the caller's checkout any more.

  • The caller's checkout is the nearest repo root (.git), and Node's resolver finds the package from there (packageDir()).
  • Whether a checkout has a page server is the same test pages.js' ensurePageServer() uses: its package.json has "pageServer" settings, and the package resolves.
  • The serve tool is unchanged: it's still the caller's own scripts/serve.mjs, which spell-app still has.
  • From spell-app, epic server status reaches spell-app's page server on 4747 again. Before this fix it fell through to the machine's epic server on 4848.
  • From spell-epic and from repos epic init set up, nothing changes: they still get the epic server.
