Fixed: removing a worktree now stops its page and vite servers first, and every session's start stops any left by a folder deleted another way, at most once an hour.

  • One class does both, CheckoutServers (spell-epic's src/command/). It finds servers with spell-app's own finder, prune.ts (what epic server prune runs), by process, not by pid file. So no spell-app change was needed.
  • Stopped first by: the WorktreeRemove hook (only once it's sure to remove), a new epic worktree remove <name> [--force], and epic worktree move. /isolate done (/epic done) and /worktrees' clean-up now run epic worktree remove instead of a bare git worktree remove. Parking never removes a worktree, so nothing changed there.
  • The safety net: a new SessionStart hook, hooks/server-prune.mjs. It's quiet, always exits 0, and runs only in a repo using epics. Its stamp is ~/.spell-epic/server-prune.stamp. It never stops a live checkout's server: only one whose checkout and working folder are both gone. It took 0.2s here.
  • Checked: tests/command/CheckoutServers.test.ts, 6 tests on scratch checkouts, each "server" a tiny node process run as spell-app's page server and vite are. They show: a removal stops its own servers and no one else's; the hook keeps a dirty worktree and its servers; the session-start prune stops a deleted checkout's servers and leaves a live one's; the hour's wait. The full suite passes (1461 tests), and yarn ts, yarn lint and yarn plugin:validate pass. I also ran epic worktree remove by hand on a scratch repo: "stopped 2 servers", then removed.
  • Docs: AGENTS.md, src/AGENTS.md, the README, and the isolate and worktrees skills.
