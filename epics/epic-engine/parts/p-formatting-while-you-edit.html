The edit box gets a bar of light icon buttons above it, and keys: bold, italic, headings, links, lists, strikethrough and clear formatting, each writing its markdown marks, so the file stays markdown.

A switch at the bar's end shows the text either with its markdown marks faded beside it, or formatted only, like a word processor; remembered in the browser.

  1. The formats, as text (Spell UI, plain code, tested first, ~1½h): a new MarkdownFormats beside MarkdownSource.
    • Toggle a wrap around a selection: bold **, italic *, strikethrough ~~; unwrapped when the selection is inside one already; a word with no selection takes the word.
    • A link: the selection becomes [text](address); on a link, its address changed or the link removed.
    • A heading: a paragraph's line gets ## ... #### , a heading its level changed or dropped (Paragraph). A table cell or list item can't be a heading: the menu is off there.
    • A list: a paragraph becomes one item (- or 1. ), an item goes back to a paragraph; the piece's kind changes, so the block draws anew after the keep.
    • Clear formatting: every mark in the selection dropped (**, *, ~~, a link's brackets and address).
    • Which formats the cursor is in, for the pressed buttons.
  2. The bar (~1½h): light icon <ui-button>s in a <ui-toolbar>, drawn by the element in its shadow root just above the open box (below it near the window's top), gone as the box closes; placed with CSS anchor positioning on the box, so it never moves the page.
    • Bold, italic, a heading menu (Paragraph, H2, H3, H4), link, bulleted list, numbered list, strikethrough, clear formatting; then the view switch, last.
    • Each its tooltip (title): its name and key; pressed while the cursor is in its format.
    • A click keeps the focus in the box (the bar's buttons don't take it), so the cursor and selection stay.
    • Its words in English and Spanish; the icons (bold, italic, heading, list, list-ol, strikethrough, eraser, eye) added to ICONS and the site's.
  3. The keys (~½h): in onBoxKey(), ⌘B, ⌘I, ⌘K, ⌘⇧X, each preventDefault()ed so VS Code never sees it; ⌘E is never taken. A link's address: a small field in the bar, Enter to keep it.
  4. The faded-marks view (A, the default, ~2h): the box stays plain text, as P60's; a copy of its text drawn behind it with the marks faint and the text bold, italic or struck as the marks say, kept in step with each key. What's saved is exactly what's seen.
  5. The formatted view (C, ~3h): the box is rich text: bold, italic, struck, links and headings drawn, no marks.
    • On each keep, its content is written back as markdown by MarkdownFormats, keeping the piece's own marks where they didn't change (* stays *, not _).
    • A piece holding what it can't write back exactly (raw HTML such as <nobr>, an escaped mark, an image) opens in the faded-marks view, and says so in the switch's tooltip.
    • Pasting is plain text.
  6. The switch (~½h): the bar's last button flips the open box between the two views, keeping the text and the cursor; the choice remembered in this browser (the kit's PrefStore, ui-markdown:edit-view), so every box opens in it (J195: the faded-marks view first).
