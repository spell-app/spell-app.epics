For I4, I chose to keep the phase's stable id in the request, rather than rewrite request.md every time phases are renumbered.

  • What it does: epic file seo#P7 r3 writes phase: p-retry-logic next to filed: P7 · Retry Logic. epic requests looks the id up on the page, so after an insert it says P8 · Retry Logic.
  • Why: this is the same rule as P15's stable phase ids. It stays right however the phases move (an insert, a rename, a future reorder), and add-phase never has to reach into the requests/ folders.
  • The cost: the filed: line in request.md keeps the number from when the request was filed. Anyone reading the raw file sees the old number; epic requests shows the current one.
  • No migration for older requests: their filed: is free text ("in P21 · JSON5 Data Files (moved down ...)"), and every one sits in an epic that is closed or finished. Guessing a phase from that text could pick the wrong one, so they show what they say, as before.
  • The other way: have add-phase --before rewrite the filed: line of each request that moves. The raw file would stay current, but the plan tool would then edit request files, and a text match on "P7" can hit the wrong number.
