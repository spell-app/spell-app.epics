Why it broke

  • VS Code reads a folder's own settings file (its .vscode folder's) only when that folder is one of the window's own folders.
  • Every window's first folder is the kit's root (a worktree's root, in an epic's window), and the kit's root has no settings file at all.
  • The settings that pin oxfmt and turn on format-on-save are app's own, app's VS Code settings: written when spell-app was its own repo and its own window's first folder.
    • Since the one repo (repo-split's P20 · One Repo), app/ is just a folder inside the root, so VS Code never reads them.
    • Spell UI's VS Code settings don't pin a formatter at all (only how the Markdown preview opens links), and are never read either.
  • So every file falls back to your user settings, which name the Prettier extension. It isn't installed, so nothing formats.
  • The same goes for everything else in app's settings: the Quick Open and Find exclusions the kit's guide points at ("Windows"), the .json5 files opening as JSON with comments, the people library's schemas, the Oxc linter's settings.

The fix: one settings file at the kit's root, tracked

  • App's settings move to the kit's root, as its own VS Code settings; Spell UI's one setting joins them.
    • the paths in them are from the root now (the people schemas are under app/)
    • the extension recommendations move too (the Oxc extension in, Prettier and ESLint "unwanted"), so a fresh machine is told what to install
    • app's and Spell UI's settings files go: nothing reads them
  • One change in them: the Oxc extension reads EACH folder's vite.config.ts again, not only the root's.
    • App's settings told it to read only the root's config ("disable nested config"); that was right when app's config WAS the root's.
    • The kit's root config now leaves the big folders out of its lint (each lints by its own config), and Spell UI's own config holds its pattern rules and its formatter's ignore list (its hand-laid-out docs pages).
    • Read only from the root, a save in a Spell UI docs page would reformat what yarn format leaves alone, and Spell UI's pattern rules would never show in the editor.
  • Every checkout gets it at once, not only when its branch merges main: a checkout patch (the kit's epic settings' checkoutPatches) copies main's file into each checkout that doesn't track it yet, git-excluded there.
  • The kit's guide ("Windows") and the window script's header name the root's file, not app's.

Why there, and not in the window files

  • The window files' own settings (windows.settings in the kit's epic settings, written by epic window init) were made for the settings a folder CAN'T give, ones that apply to the whole window, such as which TypeScript the editor runs (intellisense's P4 · HTML and CSS Data).
    • Which formatter runs, per language, is a folder's setting: it belongs in the folder.
  • Both aren't needed. For a per-file setting like these, a folder's own settings beat the window file's, so the window file's copy would only ever be a fallback.
  • A tracked file reaches everyone who opens the kit: a window opened on the plain folder, someone without the epic engine's windows, Codex's people. The window files are each machine's own, in the epic repo.
  • Open windows take it live: VS Code watches each window folder's settings file, so nothing reloads, and no window file is rewritten (no risk of a window's colours changing).
  • Another repo set up with epic init gets nothing from this, and that's right: which formatter a repo uses is its own choice, in its own VS Code settings. The engine only writes what's about windows.
