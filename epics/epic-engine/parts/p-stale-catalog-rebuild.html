  • Owen (r45, from debut): "can we make <ui-root> signal the page server somehow when something like that happens, so it can auto-regenerate?"
    • What happened: after <ui-menu choose> was added, every page logged "<ui-menu>: its root's catalog is stale (no choose)" until yarn gen:root and epic's bundle-spell-ui.js were run by hand (debut I90).
  • When a page finds its root catalog stale, it tells the page server it came from.
    • The check that throws is DOMElement.attach(); the page sends one request to a server route, through the live client the server already injects.
    • Only pages the page server serves: a published page, or one opened from disk, has no server to tell, and keeps today's console message.
  • The page server reruns the right generator, once, however many pages ask:
    • Spell UI's root catalog (yarn gen:root)
    • a component pack's catalog (spell-pack build)
    • then the bundles built from it: Spell UI's docs site bundle, and spell-epic's docs bundle (bundle-spell-ui.js)
  • It reuses what the server already has for bundles (Bundle, BundleBuild), rather than a second way to rebuild.
  • When the rebuild finishes, live reload brings the open pages back on their own: nobody runs anything by hand.

A page that hits a stale catalog tells the page server, which reruns the right generator and reloads the page.

Spell UI's root catalog and spell-epic's docs bundle join the stale-bundle machinery the page server already has.

  • src/element/DOMElement.ts: attach(), where the stale catalog is found
  • ui/src/components/ui-root/RootLoader.ts, UIRoot.tsx: where a family that didn't load is reported
  • src/server/liveClient.ts: the page's side, sending the signal
  • src/server/page/BundleBuild.ts, src/server/Bundle.ts, src/server/server.types.ts (BUNDLES): the rebuild
  • src/server/page/PageServer.ts: the new route
  • ui/scripts/gen-root.ts, src/element-tools/RootCatalog.ts: the catalog generators
  • epic/src/tools/bundle-spell-ui.js: spell-epic's docs bundle
  • src/server/AGENTS.md: the page server's bundles section
  • A test: a stale catalog on a served page makes one rebuild request, and two pages asking at once make one rebuild.
  • By hand: add an attribute to a component, open a docs page on the page server, and watch it come back by itself without running yarn gen:root.
