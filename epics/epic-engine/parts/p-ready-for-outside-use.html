The READMEs and screenshots now match the code.

The published npx spell@next epic init now works from start to finish.

A repo whose main takes only pull requests, or that uses npm rather than yarn, now works too.

You can now set epic up in another repo with one command, npx spell@next epic init. It is published as 0.8.8.

Still rough, or not tried:

  • No real outside person has run it yet. The test was a scratch home folder and a scratch repo on this machine.
  • After setup, epic runs from npm’s cache (~/.npm/_npx).

What was built:

  • Docs (I245): every epic README, the kit README’s install steps and all the screenshots checked against the code. Released as 0.8.7, then 0.8.8, on GitHub and on npm under next.
  • The epic server from npm (I246): one place, EngineFiles, knows the two layouts, a checkout and an npm install. The scratch check in spell publish now starts the server, where before it only ran epic --help.
  • A main that takes only pull requests (I247): set baseBranchProtected in the repo’s epic settings, and:
    • epic init puts its setup on an epic-setup branch and opens a pull request
    • epic merge refuses
    • /epic done offers only a pull request
    • worktrees start from an up-to-date main
  • An npm project needs no yarn (I247): package-lock.json is regenerated on merge, and snapshots are made with the repo’s own test runner.
