Fixed. The wake couldn't find outline-spell's session, so it opened a new one beside it. The notice was the cooldown repeating that first wake.

What happened, from outline-spell's inbox, transcript and VS Code logs:

  • 20:47:32: you pressed Do Now on J30 while nobody was listening. The page server looks for the ONE running session titled for the epic, to type /epic review outline-spell into.
  • outline-spell's session was running, mid-turn, and its tab said 🚧 outline-spell. But Claude Code's record of it (~/.claude/sessions/<pid>.json) had a name it made up, outline-spell-<2 hex digits>. It does that when a session is resumed in a new process, and this one was resumed when VS Code started at 17:27. Our prompt hook doesn't rename a session whose title is already right, so the record kept the made-up name.
  • The finder read only that record name, found no session, and moved to its next rule: a NEW session in outline-spell's window, with the command typed in.

  • Also seen: at 20:47:52 the outline-spell window's extensions restarted. VS Code's log says "Extension host terminating: received terminate message from renderer". That stopped the running turn, and the session was resumed again. The log doesn't say why. Our wake only opened a tab, 20 seconds before, and nothing of ours restarts a window's extensions: most likely a reload.

The fix: SessionFolders.recordTitle(). It takes a session's record name unless Claude Code made it up; then it takes the title from the session's transcript (its last custom-title). These now use it:
