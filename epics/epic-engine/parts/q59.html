How does `b` work for a session which is not e.g. visible in VSCode? Does it run an "invisible session" somewhere?

No invisible session: nothing runs in the background. A wake always lands in a VS Code tab, and in most cases it only TYPES /epic review epic-engine there; Claude starts when you press Enter.

What the page server does when Send (or, with B, the countdown) finds nobody listening, first match wins:

  1. The epic's session is running (one tab titled for the epic):
    • its inbox poller runs: it's told through the inbox and wakes by itself in a few seconds, nothing typed
    • no poller: the command is typed into its tab through the spell extension's window bridge; press Enter there. If that tab is already open, VS Code refuses to type into it, so nothing happens and the page says so
  2. No session, the epic's worktree window open: a NEW session tab in that window, the command typed in.
  3. The worktree window closed: the window is OPENED (epic window launch), the command typed in.
  4. No worktree: a new session tab in a main window.
  5. No VS Code window: nothing; the page shows the command to type.
  • It needs VS Code and the spell extension's window bridge; a terminal-only session can't be reached.
  • Limits: one wake per epic in 10 minutes, none in airplane mode, none when several sessions are titled for the epic, none for a Send with nothing new.
