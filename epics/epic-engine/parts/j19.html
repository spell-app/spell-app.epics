The three pages whose scripts draw their contents (the core reference, the spell syntax guide, the parked goal sets) now build everything with DOM calls into Spell UI elements, never HTML strings:

  • Core reference (core-reference.js): every file a light-DOM <ui-section> holding a <ui-table> round a real <table>, its kind a <ui-label>, the numbers <ui-statistic>s. The link to the file's source in the title row is now a round <ui-button href> (size tiny), not a bare icon in a link. The file sections REPLACE the [data-core-modules] placeholder instead of filling it (each marked data-core-module, which the filter now looks for). Inside that box they had been indented twice: at 1200px a table started at 352px and was only 496px wide, so it scrolled sideways. Now each one fills the column (848px).
  • Spell syntax guide (spell-syntax.js): it already built with el(). Its raw <button>s are now <ui-button>s: the pencil, the reset (made only the first time its box changes, not 750 up front), and Expand all / Collapse all in the toolbar. Those two are <ui-button basic>s styled like the toolbar's section buttons, and their words still hide when the section titles do.
  • Goal sets (goals-live.js): the pills and the round buttons are built as elements, each with a title tooltip in place of the <ui-popup> that came after it. Clicking still shows the parked "TODO" toast. The parked dialogs (thoughtModal() etc.) are unused until epic-goals and are left as they were.
  • Every button's title is also put on the button inside it (a local titleInside(), like spell-doc-helpers.js's), so VS Code's side bar shows the tooltip.

Left as they were: the syntax guide's boxes stay native <textarea>s. There are 750 of them, read as plain values, and a <ui-textarea> each would change how they are read and saved. Its bottom bar stays a small layout box around Spell UI parts (<ui-textarea>, <ui-button>, <ui-message>). <epic-choices-bar> would need ChoicesForm to read these boxes and the epics pack on guides. The other way would be to write new <epic-*> elements for the rows. That is not worth it while the runtime has to see the tables in the light DOM.

Checked: check-spell.js --base passes on both pages against an epic server running this worktree. Screenshots at 1200 and 390px, light and dark, before and after. In the browser, every icon-only button's icon sits at the exact centre (0,0 offset) and its inner button carries the title. The filter, pencil, reset, wand, Expand all, Collapse all and the goals toast all still work.
