What broke: in a worktree, spell server start all ran main's copy of the spell command, the one on the PATH. It started the worktree's page server on main's server code, so main's request router was handed the worktree's route files, and every /api request answered error 500, "handler is not a function".

Who hit it: editor's agent, on 2026-11-14 (request r69, from editor). The papercuts log had it twice before.

The fix (merged into main as 86a858e90): spell, run inside another copy of the kit, hands the command to that copy's own bin/spell.mjs, so all the code that runs is that copy's. It does so only once that copy is installed: a fresh worktree before yarn install keeps main's, so epic window still works there.

How it was checked: the worktree's servers started with the PATH's spell; /api answered 200, with no "handler is not a function" in the server's log.

Still to come: the reverse case, main's page server started with a worktree's code, broke Solitaire on 2026-11-15 at 13:42 (request r70, from language). That's I287, being fixed now.
