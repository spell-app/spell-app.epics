Can the `App` link go to a route on the spell epic server which starts the app server if necessary, then redirects?

Yes, built. The App tab's /editor/ is now a route on the epic server (4848). It sends you to the app when the app is running, and starts it first when it isn't.

  • The app answers: a redirect to it. spell-app's editor is found the way its own page server finds it, from the record .spell-server.editor.json, and only if that URL answers within a second.
  • It doesn't: the epic server runs the repo's start command in the background, from its main checkout. For spell-app that's node packages/cli/bin/spell.mjs dev server ensure: the page server, which starts the editor with it. The output goes to ~/.spell-epic/app-spell-app.log. You get a "Starting spell-app's app…" page at once, never a hung click. It asks every 0.7s and goes to the editor once it answers. A start that fails, or doesn't answer within 2 minutes, says so there and names the log.
  • A repo without an app: a page saying so, showing how to declare one. Not a 404.
  • Each repo declares its own, in its .epic/config.json5: "app": { "path": "/editor/", "urlFile": ".spell-server.editor.json", "start": "..." }, or a fixed "url". The default repo's is at /editor/, and each repo's at /r/<repo>/editor/. /api/app/<repo> says how it stands.

Code: RepoApp (spell-epic's src/server/RepoApp.ts), wired in by EpicServer; the app key in EpicConfig. spell-app's app key is in spell-app's epic-engine worktree. It counts once that is merged into spell-app's main. Until then, 4848 shows "spell-app has no app".
