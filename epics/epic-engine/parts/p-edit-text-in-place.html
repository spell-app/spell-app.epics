  • Owen's ask (r53, from the LOE table of the atmosphere guide "Spaces and Spell"): "How hard would it be to let me click in e.g. a table cell and edit the text there directly, auto-save immediately?"
    • Not hard: the saving is all there already. The page server writes one element of a page by its exact bytes, refuses a stale write, and the page updates in place on its own save, without reloading.
    • New: knowing which markdown text each drawn cell came from, the box itself, and writing an inline block back.
  • What Owen will get, on any docs page the page server can save (a guide, an epic's page, a details page), in the side bar as in a browser tab:
    • An ⌥-click on a table cell, a paragraph, a list item or a heading inside a <ui-markdown> block: it becomes editable where it is.
      • It shows its markdown while he types (**bold**, links, a <nobr>), so nothing is lost.
      • Holding ⌥ shows what he can edit: a faint dashed outline and a text cursor on each piece. Letting go of ⌥ takes them away.
      • The bullhorn's tooltip and the docs pages' help say ⌥-click edits: no pencil, no edit mode to turn on or off.
    • Enter, or a click elsewhere, saves it; Tab and Shift+Tab move to the next and previous cell, as in a spreadsheet; Escape puts the text back.
    • No Save button: it also saves after 5 seconds without typing. Saving never moves the page: the scroll and the box stay where they are.
    • Only that text changes in the file. The block's one-line tags and the formatter's ignore line above it stay as they are (r52), and so does every other byte.
    • Reading is as before: a plain click never edits, a link click still follows the link, and a drag still selects text for a comment (⌘ I).
    • An agent saved the page while he typed: his edit goes into the new version when its text is still there. Otherwise the box says the page changed, and keeps what he typed.
    • A comment on text he changed shows as moved, saying what it was on, as it does today for any changed block.
