You said: "have the type-in box in the same column as the original text. Show me an example of what that would look like before doing the full thing." How every row of a blank-box choice page looks, starting with repo-split's command names page.
  • A choice page is a table Claude fills in and you type over. r12's mode starts every box BLANK: blank means "no change", and only a box you type in counts as a change.
  • Both layouts below keep r12's rules:
    • the box starts blank
    • a click on the current text puts it in the box, the cursor at its end, so you edit from it
    • the section counts commands and changes ("3 commands · 1 changed")
  • The rows are three real ones from repo-split's command names page. Nothing here is saved: it's a mock.

The current text stays on top, always readable. The box is under it, in the same cell.

Draws the pony. It imports nothing, so it proves spell runs with nothing else installed.

One box per row: the current text shows in it, grey, until you type. A click on it fills it, so you edit from it. Once you've changed a row, the old text shows under the box ("was ...").
