The guide page shows the readme through Spell UI's markdown element, instead of a port of the original's own parser.

  • The original parses the readme with its own 30-line markdown subset, and inline styles.
    • Its subset: paragraphs, lists, headings 1-3, rules, inline code / bold / italic / links.
  • The copy: <ui-markdown source="readme.md">, styled by its tokens.
    • Full GitHub markdown, sanitized, with its own loader and error message.
  • The contents list: a plain list of links, built from the headings the markdown reports (ui-render).
    • Levels 1-2, as in the original.
  • The lede, eyebrow and headline are the brand's type roles.
  • The original's "Loading the guide…" line is now the markdown element's own loader.
  • Anything the readme gains (tables, code blocks, nested lists) renders, where the original's subset would drop it.
  • Headings look GitHub's, not the brand's serif, until the markdown element gets heading tokens (I26).
  • A contents click, or a #heading address, scrolls to the heading; the address updates.
