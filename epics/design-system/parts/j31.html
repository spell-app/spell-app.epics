The original parses readme.md with its own 30-line markdown subset (paragraphs, lists, #-###, rules, inline code / bold / italic / links) and inline styles. Chose <ui-markdown source="readme.md"> (full GitHub markdown, sanitized, its own loader and error message) styled by its tokens, over porting the parser. The contents list is built from the headings ui-render reports (levels 1-2, as the original), as a plain <ui-list> of links. The lede, eyebrow and headline are the brand's type roles. The original's 'Loading the guide…' line is <ui-markdown>'s own loader now.

  • anything the readme gains (tables, code blocks, nested lists) renders, where the original's subset would drop it
  • headings look GitHub's, not the brand's serif, until <ui-markdown> gets heading tokens (I26)
  • a contents click or a #heading address scrolls to the heading; the address updates
