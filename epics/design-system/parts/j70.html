Owen asked for a source option "like for <ui-section>". <ui-section source> is being built right now in epic claude-design (P2 "Section Sources", in its own worktree), so chose NOT to build source into UISection here (two branches editing the same code), over building a panel-only copy that would fork the behaviour.

Instead <ui-panel> takes every section attribute by construction: it subclasses UISection and its vocabulary is { ...sectionVocabulary, attributes: sectionVocabulary.attributes.map(...) }, so the day source lands in the section's vocabulary and class, the panel has it (a test pins that the panel's attribute, slot, part, event and state names equal the section's).

Net effect:

  • <ui-panel source> does nothing until claude-design merges
  • the panel's docs page (Usage, "Loading a band from a file"), its vocabulary and class comments say so
