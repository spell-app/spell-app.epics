A .spell.html page needs one script with Spell UI, the brand theme and the new elements (D7). The same script, published, is how Claude Design could use our widgets: that's a follow-up epic (D4, C13), not this one.

  • Docs pages load spell-ui.js: one classic script with everything, works from file://. But it also carries the docs page runtime (contents sidebar, rail), and can't compile new Solid elements.
  • So the brand pages get their own bundle, brand-ui.js. It's built with Spell UI's own Vite setup, which compiles Solid JSX and our decorators. It is an ES module with lazy chunks, its icons from Spell UI's own packs (J4).
  • Epic claude-design did the Claude Design half without npm: a one-file bundle uploaded into a private design system. The npm path, not taken: Claude Design builds static HTML that can load scripts from public CDNs (jsDelivr, unpkg). Once ui is on npm, the brand bundle (or a twin of it) is a single <script src="https://cdn.jsdelivr.net/npm/@spell-app/ui/..."> line.
    • Blocker: solid-element is private, so it must be published too, or bundled into ui.
