The colour picker READS any colour it's given as an upper-case hex, but its host keeps the text as it was set, until the user edits the colour.

  • E.g. <ui-brand-color-picker value="#abc">; or an OKLCH colour, or 142 150 181.
  • It reads as #AABBCC everywhere the picker reports it:
    • the readout, the fields
    • the form value
    • every event's detail.value
  • The host's value property and attribute keep the text as it was set.
    • Once the user edits the colour, they're the hex that edit made.
  • Why not rewrite the host:
    • it would be a write with no event, which the page didn't ask for
    • it would fight a framework that controls value
  • When the colour must be normalised, read it from ui-change, or the form.
