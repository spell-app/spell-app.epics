Every page the page server serves opens an EventSource (/_server/live.js, src/server/liveClient.ts), and Chrome allows 6 HTTP/1.1 connections per host. Design System's eleven live thumbnails (<iframe>s of the copies, as the original's) took them all: the page's own lazy chunks never loaded, every <ui-*> stayed undefined. The original has the same problem (its lower thumbnails never load; yarn compare "Design System" times out waiting for networkidle on it).

Fix it needs: liveClient() skips live reload in a frame whose parent is same-origin (window.frameElement non-null: a thumbnail; VS Code's doc view frame is cross-origin, so it keeps it), or shares the parent's connection. Then the page drops its workaround for plain <iframe src loading="lazy">.

Workaround in the page: the script fetches each copy, strips the server's SPELL_SERVER + live.js tags, and document.write()s it into the frame (same origin, so it follows light / dark; location is the index's, same folder, so pages resolving files against location.href still work, which srcdoc broke).
