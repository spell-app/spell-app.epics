In a selectable <ui-brand-color-set>, each <ui-brand-color> host becomes the radio: the set writes BrandColorHost.choice (a Cell on the host), and the chip sets its own internals.role = radio, ariaChecked from selected, and ariaLabel (name + colour). The set owns the roving tabindex on the hosts and is itself the radiogroup (internals), so its own aria-label names it. A chip that is a choice draws a plain <span>: no <button>, and copy is ignored.

Chose this over the set wrapping each slotted chip in its own role=radio box in its shadow root (manual slot assignment, as <ui-accordion>): far less machinery, and the chips stay the light-DOM children people style.

Net effect:

  • No nested interactive content: a copy button can't sit inside a radio.
  • axe-core can't see ARIA set through ElementInternals, so the tests check internals.role / ariaChecked directly.
  • A chip that leaves a set gets its choice and tabindex back.
