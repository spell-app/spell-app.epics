In a selectable colour set, each colour chip is itself a radio button, and the set is the radio group.

  • The set (<ui-brand-color-set>):
    • marks each chip a choice: it writes BrandColorHost.choice, a Cell on the chip's host
    • is the radiogroup, through its element internals, so its own aria-label names it
    • owns the roving tabindex on the chips
  • Each chip (<ui-brand-color>), through its element internals:
    • role radio
    • checked when it's selected
    • its label: its name plus its colour
    • draws a plain <span> rather than a button, and ignores copy
  • Chosen over the set wrapping each chip in its own radio box in its shadow root (manual slot assignment, as <ui-accordion> does):
    • far less machinery
    • the chips stay the light-DOM children people style
  • No nested interactive content: a copy button can't sit inside a radio.
  • axe-core can't see ARIA set through element internals, so the tests check the chip's role and checked state directly (internals.role, ariaChecked).
  • A chip that leaves a set gets its choice and tabindex back.
