I5 / I21 / I35 asked that each variation read the GENERIC public token in front of its own value (--_ui-menu-icon-float: var(--ui-menu-icon-float, right)). Not done that way: themes set the generic tokens on :root for the PLAIN menu (Chubby's --ui-menu-active-background: var(--ui-primary) and --ui-menu-item-padding: 1.25em 2em, GitHub, Material, spell / spell-brand's lavender active fill), so every tabular tab, text link and secondary pointing underline would have filled primary or grown padding.

Instead, as docs/theming.md "Variations" already says (and as Fomantic's own @secondaryItemPadding, @textMenuItemColor ... variables are), each value a variation swaps is a public token of its own, --ui-menu-<variation>-<token>, read through its alias in the variation's block. Done for vertical, secondary, text and segmented; pointing, tabular and inverted still swap privately (same pattern when a page needs them).

Net effect:

  • a page restyles its side nav with --ui-menu-secondary-item-padding / -item-radius / -active-background / -active-color, --ui-menu-vertical-icon-float: none ..., not ::part()
  • a theme's plain-menu look never leaks into a variation; the generic tokens still reach whatever a variation leaves alone
  • new: --ui-menu-vertical-item-display / -active-radius / -icon-float / -icon-margin; --ui-menu-secondary-item-padding / -item-margin / -vertical-item-margin / -item-radius / -item-color / -hover-background / -active-background / -active-color; --ui-menu-text-margin / -item-padding / -item-color / -hover-color; plus base --ui-menu-margin, -min-height, -gap, -font-family, -item-min-height, -item-transform, -item-letter-spacing, -active-shadow
  • NOTE: secondary is also a hue word, so a secondary menu's active text was always the secondary hue's, never --ui-menu-active-color: --ui-menu-secondary-active-color overrides it
  • no default look changed (visual tests)
