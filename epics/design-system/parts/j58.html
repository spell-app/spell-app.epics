Each value a menu variation swaps is now a public token of its own, not the generic menu token read in front of the variation's value.

  • The issues (I5, I21, I35) asked that each variation read the GENERIC public token first.
    • E.g. --_ui-menu-icon-float: var(--ui-menu-icon-float, right).
  • Not done that way: themes set the generic tokens at the root, for the PLAIN menu.
    • Chubby: --ui-menu-active-background: var(--ui-primary), and --ui-menu-item-padding: 1.25em 2em.
    • GitHub, Material.
    • The Spell and Spell Brand themes: a lavender active fill.
    • So every tabular tab, text link and secondary pointing underline would have filled primary, or grown padding.
  • Instead, each swapped value is a token named --ui-menu-<variation>-<token>, read through its alias in the variation's block.
    • As ui's theming guide (theming.md) already says, in "Variations".
    • And as Fomantic's own variables are (@secondaryItemPadding, @textMenuItemColor ...).
  • Done for vertical, secondary, text and segmented menus.
  • Pointing, tabular and inverted still swap privately; the same pattern applies when a page needs them.
  • A page restyles its side nav with variation tokens, not ::part().
    • E.g. --ui-menu-secondary-item-padding, and its item radius, active background and active colour.
    • Or --ui-menu-vertical-icon-float: none ...
  • A theme's plain-menu look never leaks into a variation; the generic tokens still reach whatever a variation leaves alone.
  • New tokens:
    • vertical (--ui-menu-vertical-*): item display, active radius, icon float, icon margin
    • secondary (--ui-menu-secondary-*): item padding, item margin, vertical item margin, item radius, item colour, hover background, active background, active colour
    • text (--ui-menu-text-*): margin, item padding, item colour, hover colour
    • the base menu (--ui-menu-*): margin, min height, gap, font family, item min height, item transform, item letter spacing, active shadow
  • NOTE: "secondary" is also a hue word, so a secondary menu's active text was always the secondary hue's.
    • Never --ui-menu-active-color; --ui-menu-secondary-active-color overrides it.
  • No default look changed (visual tests).
