Chose the plain tag <ui-panel> over keeping a brand prefix (<ui-brand-panel>) or a variation of the section (<ui-section panel>), because Owen asked for ui-panel, a panel is a generic widget (decision D2: generic elements move into Spell UI), and a tag of its own keeps the inspector look out of every plain section's sheet.

It is still a UISection subclass, now with its OWN vocabulary built on the section's (ui-panel.vocabulary.en.ts: ...sectionVocabulary, tag, topics, aka, two descriptions), instead of the brand's trick of defining the section's vocabulary under another tag, so UIPanel.describe(), the docs' API table and <ui-root>'s catalog all say ui-panel.

  • page authors write <ui-panel>; same attributes, slots, parts, events and look as before
  • class words in the shadow root: ui ... section panel (+ sub), was section brand panel
  • layers ui.components.panel.*; lib entry @spell-app/ui/ui-panel; a PanelFallback (the section's, in the panel's class grammar)
  • docs page /ui/components/ui-panel.html; the brand's own page is gone, and the Brand index's row links Spell UI's
  • a types example + visual baselines (chromium / firefox / webkit, local); 15 tests (element + fallback)
  • fixed on the way, Safari / WebKit: the outer content clipped always, and WebKit has no overflow-clip-margin, so sub-head bands stopped short of the box's edges and a folded last band was cut off; it now clips only while the section animates (as the section does), which WebKit never does. Chromium unchanged
  • <ui-brand-field>'s tests now import $/ui themselves: they had passed only because <ui-brand-panel> imported the whole barrel as a side effect
