The composer's value works as the textarea's does: the attribute is the starting text, the property the live text.

  • The ATTRIBUTE is the starting value, and what a form reset goes back to.
  • The PROPERTY is the live text; typing never writes the attribute.
  • Why: a spell is long, multi-line text, and Spell UI's text controls all work this way.
  • ui-input fires per keystroke; a handler that re-sets value wins.
  • ui-change fires on leaving the box edited.
  • With blank text (empty, or only spaces):
    • the Cast button is dimmed to 50%, and aria-disabled, but stays focusable
    • :state(empty) is set
    • the originals never dim it: they start with text in the box
  • el.value is always the current text; getAttribute('value') is the starting text.
  • An empty box shows a faded arrow until you type.
