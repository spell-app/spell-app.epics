value works as <ui-textarea>'s: the ATTRIBUTE is the starting value (and what form reset goes back to), the PROPERTY is the live text; typing never writes the attribute. Why: a spell is long, multi-line text, and Spell UI's text controls all work this way. ui-input per keystroke (a handler that re-sets value wins), ui-change on leaving the box edited.

With blank text (empty, or only spaces) the Cast button is dimmed to 50% and aria-disabled, but stays focusable, and :state(empty) is set. The originals never dim it (they start with text in the box).

  • el.value is always the current text; getAttribute('value') is the starting text
  • an empty box shows a faded arrow until you type
