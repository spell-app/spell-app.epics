The markdown element gained public tokens for its headings and a few other looks, and the brand theme sets them to the Design Guide's look.

  • Each is read through a private alias in its sheet (ui-markdown.css).
  • The defaults are GitHub's look, as before.

The tokens, each --ui-markdown-*:

  • The headings:
    • heading-font-family: the article's
    • heading-weight: 600
    • heading-line-height: 1.25
    • heading-margin: 1.5em 1em, as a block margin
  • The rule under h1 and h2:
    • heading-rule: 1px solid, in the rule colour; none drops it
    • heading-rule-gap: 0.3em; without it, a dropped rule would still leave its padding
  • The sizes of h1-h3, each h<n>-size: 2 / 1.5 / 1.25em.
    • h4-h6 stay fixed.
  • hr-height: 0.25em.
  • strong-color and code-color: the text's.
  • heading-scroll-margin: 0.
    • Added beyond the issue, so a reveal or a #id lands below a sticky header.

The brand theme (spell-brand.css) sets them to the Design Guide's look:

  • serif bold, no rule
  • h2 at calc(28em / 15), h3 at calc(19em / 15)
  • a margin of 1.1em 0.43em
  • a 1px horizontal rule
  • strong and code in the brand's strong text colour
  • plus the heading colour, rule colour and code background, which the guide page had set itself
  • not taken: the guide's -0.012em heading tracking (no token)

The editable preview draws Spell UI headers, which these tokens don't reach.

  • Every markdown element under the Spell Brand theme reads like the Design Guide; other themes are unchanged.
  • The Design Guide page can drop its block of markdown colour tokens: the theme has it.
