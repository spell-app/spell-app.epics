2026-10-06, after P2: the keybindings never fired, so the keys still did nothing.

  • Why: they were bound when: focusedView == spell.docView. VS Code draws a side-bar webview in an overlay outside its pane, and never tells the pane when focus goes into the page, so focusedView is empty there.
  • What VS Code does instead (read in its own source): Copy, Cut, Paste, Select All, Undo and Redo, by key or menu, with a webview focused, become document.execCommand("copy") ... on the view's OWN document: our side-bar wrapper, not the docs page framed inside it. So they landed on an empty page.
  • Fix: the wrapper's script (packages/vscode/src/DocView.ts, html()) replaces document.execCommand for those six, and sends each to the extension as { spell: "edit", command }. From there it's P2's path: the extension reads the clipboard for a paste and hands the command into the page (liveClient.ts edit()). The keybindings and their command are gone.
