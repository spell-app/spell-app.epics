StaticCatalog stays its own file, and its banner says why.

  • It's one class with one static, classes: 93 component classes, from about 92 imports.
  • WWOD §8 › "One exported class per file" warns against micro-modules of one constant. I kept it anyway.
  • Folding it into the engine (StaticRender.catalog) would make the ENGINE import every family.
    • Today StaticRender.ts imports only the elements barrel and its peers.
    • It renders whatever it's given (define()).
  • It changes for a different reason than the engine: a family becoming server-ready edits the catalog, never StaticRender.
  • It's an exported class with a test of its own.
    • StaticCatalog.ssr.test.ts, in step with StaticFamilies.ts.
    • And spell ssr names it, in StaticDocument.ts.
  • NOT changed: the barrel still exports it.
    • So import { StaticRender } from "spell-ui/server" loads every family too; the barrel's header notes it.
    • Splitting it out of the barrel would change StaticDocument and three tests, for a load cost in node only.

No code change; the banner records the rejected fold.
