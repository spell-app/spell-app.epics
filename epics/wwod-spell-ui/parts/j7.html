StaticCatalog.ts is one class with one static (classes, 93 controller classes) and ~92 imports. WWOD §8 › "One exported class per file" warns against one-constant micro-modules; I kept it anyway, and wrote why into its banner.

  • Folding it into StaticRender (StaticRender.catalog) would make the ENGINE import every family: today StaticRender.ts imports $/ui/elements and its peers only, and renders whatever it's given (define())
  • It changes for a different reason than the engine: a family becoming server-ready edits the catalog, never StaticRender
  • It's an exported class with a test of its own (StaticCatalog.ssr.test.ts, in step with tools/visual/StaticFamilies.ts), and spell static (tools/StaticDocument.ts) names it
  • NOT changed: the barrel still exports it, so import { StaticRender } from "$/ui/server" loads every family too (noted in the barrel's header); splitting it out of the barrel would change StaticDocument and three tests for a node-only load cost

no code change; the banner records the rejected fold.
