A component's attribute getters (this.size) are typed by an interface that each concrete class merges with itself. The lint rule against that merging is off.

  • How it works: UIElement.register() installs the getters on each component class's prototype. It skips any name the class already has.
  • For TypeScript, a concrete class declares them: 
    export interface UIButton extends E.AttributeValues<typeof buttonVocabulary> {}
  • Rejected: re-typing UIElement as a constructor that returns its instance plus the attribute values.
    • Concrete classes would be typed for free.
    • But every GENERIC base fails with TS2509: a mapped type over a type parameter isn't "statically known".
    • Each would need the same cast of its own.
    • The generic bases: 
      FormElement, SourceElement, ContentPart, CheckControl, TextControl,
DialogElement, PartElement, PlaceholderShape, GridPart
  • A plus: a member that clashes with an attribute's type is a compile error, once the class merges the interface.
  • The lint rule typescript/no-unsafe-declaration-merging is off in vite.lint.ts, with the reason.
  • Generic bases declare what they read. For example, SourceElement declares read-only source and load.
  • Step 2 adds one line per family class; no family declares it yet.
