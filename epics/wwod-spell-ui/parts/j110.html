Skeleton text has ONE parser, SkeletonText, and every vocabulary now writes its skeleton as text. The parser is kept OUT of ui's core.

  • It has two methods: parse(text) and format(spec).
  • A vocabulary's skeleton is typed as a plain string.
  • The parser stays out of the vocabulary barrel.
  • Rejected: a template-literal type, or exporting the parser through the core.
skeleton  := "none" | ["inline"] size | ["inline"] [size ":"] parts
size      := <w> "x" <h> | <h> "tall" | <w> "wide"          (em)
parts     := part ("," part)*                              (top to bottom)
part      := "paragraph" | <n> "line paragraph" | "header" | "header with image"
           | "image" | "square image" | "rectangular image" | "line" | <length> "line"
length    := "full" | "very long" | "long" | "medium" | "short" | "very short"
  • Every skeleton in the 104 English vocabulary files is text now.
    • For example "inline 6 x 2.5", or "18 wide: square image, header, 3 line paragraph".
    • The old false is "none".
    • A script converted them, and checked each one round-trips.
  • yarn gen:root parses them. ui-root.catalog.ts came out BYTE-IDENTICAL, checked with git diff before the new tag was added.
  • Bad text throws a TypeError that names it. For example: 
    SkeletonText.parse(): can't read "18 by 15"; write e.g. ...
"hedaer" in "header, hedaer" isn't a part; write one of: ...
  • vocabularies.test.ts parses every vocabulary's skeleton. It also checks that the catalog holds what each parses to; if not, run yarn gen:root.
  • A template-literal type can't spell this grammar, so the plain string plus the test is the guard.
  • Why NOT in the barrel: the core re-exports the vocabulary barrel, and only <ui-components> parses skeletons at runtime.
    • It's imported by path, spell-ui/vocabulary/SkeletonText, with a comment at the import.
    • package.config.ts counts it as ui-root's. So yarn measure's check for core code outside the core stays clean.
  • Vocabularies and packs write skeletons the same way.
  • SkeletonSpec stays the parsed shape, which the catalog and PlaceholderSkeleton read.
  • core.js: 113,028 B, 33,299 gzipped (was 113,020 and 33,299).
  • Three tools read the vocabulary files through one new helper, VocabularyFiles.ts.
    • They're gen-root, SiteDataBuilder and site-bundle.
    • It was a loop copied in two places.
