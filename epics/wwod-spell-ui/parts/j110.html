Chose ONE parser, SkeletonText (src/vocabulary/SkeletonText.ts: parse(text) / format(spec)), with ComponentVocabulary.skeleton typed plain string, and the parser kept OUT of $/ui/vocabulary's barrel, over a template-literal type or exporting it through core. 

skeleton  := "none" | ["inline"] size | ["inline"] [size ":"] parts
size      := <w> "x" <h> | <h> "tall" | <w> "wide"          (em)
parts     := part ("," part)*                              (top to bottom)
part      := "paragraph" | <n> "line paragraph" | "header" | "header with image"
           | "image" | "square image" | "rectangular image" | "line" | <length> "line"
length    := "full" | "very long" | "long" | "medium" | "short" | "very short"
  • every skeleton: in the 104 *.vocabulary.en.ts files is text now ("inline 6 x 2.5", "18 wide: square image, header, 3 line paragraph", "none" for the old false); converted by a script that checked each round trip
  • yarn gen:root parses them: ui-root.catalog.ts came out BYTE-IDENTICAL (checked with git diff before the new tag was added)
  • a bad text throws a TypeError naming it (SkeletonText.parse(): can't read "18 by 15"; write e.g. ..., or "hedaer" in "header, hedaer" isn't a part; write one of: ...); test/vocabularies.test.ts parses every vocabulary's and also checks the catalog holds what it parses to (else yarn gen:root)
  • a template-literal type can't spell the grammar; string + the test is the guard
  • NOT in the barrel: core re-exports $/ui/vocabulary, and only <ui-components> parses at runtime. Reached by path ($/ui/vocabulary/SkeletonText, a comment at the import); tools/package.config.ts buckets it as ui-root's, so yarn measure's coreOutsideCore stays clean

  • vocabularies and packs write skeletons the same way; SkeletonSpec stays the parsed shape the catalog and PlaceholderSkeleton read
