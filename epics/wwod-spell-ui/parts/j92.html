A run of 3 or more expects became one whole-value check (toEqual, or toMatchObject), but only where the run reads ONE subject. The rest were left as they are.

  • One subject: a row, a host's chrome, a computed style, or a part's attributes.
  • Most of the audit's runs were left, because they:
    • read different things off one big value, e.g. the components, docs and topics of the site data in SiteDataBuilder.test.ts
    • or call one method with different inputs: a table, not one value
  • Merged: about 25 runs. For example:
    • the basic row in ui-docs-api.test.tsx
    • every fallback's section class and part
    • the combobox's 5 attributes in ui-docs-search.test.tsx
    • IconPackBuilder's index
    • the github theme, and the Spell colours, in DesignExport.test.ts
    • the brand chips, fields and phone
  • No test written for these, since they're bound to the DOM or to I/O, and covered through their element tests:
    • NavPreferences: localStorage
    • SearchData: fetch
    • ExampleSource: its snapshot and keep methods stay in the element test, since they need live elements
    • DocsFamilies: a glob
    • the brand's *Host classes
