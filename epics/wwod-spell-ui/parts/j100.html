Chose to control time in ui-grid .. ui-progress rather than keep any real wait: every sleep there was waiting on a timer the element sets, or on an event / lazy load that can be awaited.

Net effect:

  • ui-popup.test.tsx: settle(ms)'s setTimeout sleep is gone; the hover / focus tests that waited 20-120 ms call fakeTimers() (vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout"] }), so pointer, focus and popover events still come from the browser) and advance(ms); settle(10) after hidePopover() now awaits the popover's real toggle event (nextToggle())
  • ui-markdown.test.tsx: nextRender()'s 2 s fallback setTimeout is gone (no test ever reached it: the slowest took < 400 ms; a render that never ends now fails at Vitest's timeout); the two 300 ms sleeps before axe are drawn(root): customElements.whenDefined() for every ui-* tag in the body (the families MarkdownRenderer.loadMD() imports lazily), then ElementFixture.settle()
  • ui-nag.test.tsx: display-time="40" ran on the real clock; now fake timers + vi.advanceTimersByTimeAsync(40)
  • flakiness: every changed file ran green twice in full, popup / nag / markdown 4 more times
