<ui-input>'s inputmode attribute keeps the platform's own property name, inputMode, even though that hides HTMLElement's own. And the checkbox, radio and toggle get readOnly too.

  • Rejected: a name the platform doesn't use, like dividerHidden.
  • Why keep the platform's name: the meaning is the same.
    • Both read and write the host's inputmode attribute.
    • Ours also passes it on to the native input.
  • Why hidden did become dividerHidden: Fomantic's word means something else there.
  • The element layer lets a renamed property hide a platform one (upgrade.ts).
  • Also renamed, beyond the 6 tags queued: the shared readonly spec in ui-checkbox.types.ts. So the checkbox, radio and toggle say readOnly, like a native checkbox.
  • el.inputMode on a <ui-input> is ours: it reflects, and passes the value on. It's the same value the native getter would give.
  • readOnly is on 9 tags, not 6.
  • Attributes are unchanged everywhere, and no caller used the old property names.
