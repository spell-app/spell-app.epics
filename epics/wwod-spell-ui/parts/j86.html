The site's three hand-rolled fetches (SiteData.ts, ui-docs-search/SearchData.ts, site/_src/SiteShell.ts) checked response.ok and threw a plain Error. They now share ONE helper, SiteData.request(url, { method, fix }), which throws a load E.SourceError (P3's shape: cause: { kind, status }, or the network error as cause.error) with a house message, e.g. SiteData.load(): …/components.json answered 404 Not Found; run `yarn site:data` in packages/ui, or check `SiteData.url`.

  • Chosen over UI.sources.load(), which (1) refuses data: URLs as cross-origin, and the docs tests point SiteData.url at one; (2) needs the runtime chunk, which the layout fetch (SiteShell.mount(), before <ui-root>) must not wait for; (3) caches the 780 KB text beside the parsed JSON.
  • $fetch / ResponseError live in $/util/spell, which ui must not import.
  • SiteData.ts now imports E from $/ui/core: every bundle that loads it (the site entry, brand-docs.js) already had the core through ExampleSource.
  • same failures, typed and worded the house way; a layout that has no .site-content is a render SourceError; SiteRouter's swap failures (no main#main, an include ui-error, the 10 s timeout) are SourceErrors too
  • every site warning goes through E.Warnings.warn("Spell UI site", …) (was 3 bare console.warns: SiteShell, SiteRouter, site.ts); UIDocsSearch's was already Warnings (P2)
