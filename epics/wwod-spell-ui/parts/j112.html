Chose to wire the docs site to a pack AND keep DocsFamilies.add() in site.ts, over swapping one for the other.

  • yarn site:bundle writes docs.components.json: the seven <ui-docs-*> tags, each with its family chunk (stable names: ui-docs-example.js, not hashed) and its vocabulary's skeleton text; it fails if a family has no chunk
  • the shared layout, layout.html, gets <ui-components source="../_assets/docs.components.json"> before its <ui-root> (the shell makes the URL absolute)
  • site.ts still calls DocsFamilies.add(): a page that mounts no layout (no bare main) still loads the docs families. Both import the SAME chunk URLs, so nothing loads twice; the pack's entries win
  • no visible change on the site (its root is display="when-ready", so the pack's skeletons don't show there)
  • the pack is exercised on every site page; yarn site:check --all runs over it
