Two getters stay plain until step 2, though the table says @derived: the root classes, and a form element's validation. And :state(invalid) stays in the validity effect.

  • Why: @derived is a cache that tracks reads of the record (the coordinator's design correction).
    • It can't see a Cell or a memo change.
    • The family hooks these two read still read Cells: classValue(), extraClasses, rules, validationValue ...
  • UIElement.rootClasses and FormElement.validation are PLAIN getters for now. Step 2 makes them @derived, once every override reads record members.
  • UIRadio and TextControl keep their own memoized validation, as before (groupValidation, mergedValidation).
    • With a plain getter, a radio group's effects read every member's selected, and framed a stale membership.
    • That's EFFECT_RELAY_TEAR, pinned by ui-checkbox.test.tsx.
  • :state(invalid) is set by onValidationChanged(), the validity effect.
    • NOT by @cssState, the table's choice.
    • In the one render effect for :state(), it would also read a radio's own selected, and tear the same way.
  • Only IconGlyph.svg is @derived in the core: it clones, and reads only its SVG template.
  • No behaviour change.
  • The class string is rebuilt on each read, instead of shared; nearly every family has one reader.
