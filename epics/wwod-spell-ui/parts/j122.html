@derived is a self-tracking cache over the record (coordinator's design correction): it can't see a Cell or a memo change. The family hooks these two read (classValue(), extraClasses, rules, validationValue ...) still read Cells, so:

  • UIElement.rootClasses and FormElement.validation are PLAIN getters for now (the rows say @derived); step 2 makes them @derived once every override reads record members.
  • UIRadio / TextControl keep their own validation memoized (groupValidation, mergedValidation), as before: a plain getter made a radio group's effects read every member's selected and frame a stale membership (EFFECT_RELAY_TEAR, pinned by ui-checkbox.test.tsx).
  • :state(invalid) is set by onValidationChanged() (the validity effect), NOT @cssState (the rows' choice): in the one :state() render effect it also reads a radio's own selected, and tears the same way.
  • Only IconGlyph.svg is @derived in the core (it clones; it reads only svgTemplate).

Net effect:

  • no behaviour change; the class string is rebuilt per read instead of shared (one reader in nearly every family)
