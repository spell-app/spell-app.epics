Two typing rules for a component's attribute getters, plus one private accessor:

  • Generic base classes declare their getters themselves.
    • They can't merge E.AttributeValues<V>, since V isn't known there.
    • CheckControl<V> extends CommonAttributes: the getters checkbox and radio share. CommonAttributes lost type.
    • TextControl<V> extends it too; it gains rules: unknown in step 3.
    • DialogElement declares closable, closedby, header and content, with explicit types.
    • SourceElement declares source and load.
  • Concrete classes leave out of their interface what their own member owns.
    • The select and the dropdown leave out value: theirs is a string list too.
    • The input and the textarea leave out value, and the common attributes.
    • These share the attribute's name, with a compatible type: 
      UICalendar.value, UISlider.value / end, UITabs.value, UIDocsNav.view,
UITable.sortColumn / sortDirection
  • CheckControl.isSelected is a getter and setter over a private accessor. 
    @controlled("selected") accessor selectedProperty
    • A server host (linkedom) has no property setter.
    • So a plain controlled isSelected lost the static <ui-checkbox checked>.
    • choose() calls E.Reactive.requestChange() directly. The member's own request-change leaves out private members (it's typed keyof this).
  • Types only, plus one private accessor.
