What the house-style recipe changed in the docs nav, search and toc families and the site glue, beyond imports and docstrings. Every caller is in ui, and all are fixed.

  • Where:
    • ui-docs-nav
    • ui-docs-search
    • ui-docs-toc
    • the site's source folder, site/_src/
  • The kinds of change, each with its full list in the folded block below:
    • Sets of words became const arrays, each with its type.
    • Constructors take one props object.
    • Booleans passed by position became named options, or named values.
    • Functions with 4 or more parameters take one object.
    • Functions that draw a piece are bare nouns; lookups end in For.
    • Public boolean fields gained is. Nothing outside the class read them; the host STATES keep their names.
    • Constants only one class uses moved below it, as module consts (Q18).
    • Class words in the shadow DOM became constants; the shared ones live in the types files.
    • null became undefined.
  • TocIndex checks a tag's name, not instanceof Element: node scripts run it on linkedom.
    • A new FollowedContent type.
    • UIDocsToc.followedContent() replaces three copies of the same call.
  • scrollerFor() now uses ui's E.flatParentFor(), which climbs the same way. So the private flatParent(), and its null, are gone.
  • The docs fallbacks read their English texts through VocabularyTexts.english(), the other agent's new helper. That's nav, search and toc; the toc's label used to be the first text.
  • ThemePreference, site.ts and SiteRouter now import from $/ui/core. They used the runtime and icons entries; the site entry loads the core anyway.
  • The full list: 
    Sets as const arrays:
  DocsSchemes        was DOCS_SCHEMES + an inline union;  DocsShownScheme = Exclude<DocsScheme, "system">
  SearchKinds        was SearchKind + KIND_ORDER, listing the same strings
  NavViews, NavGroups
Props objects:
  new SearchIndex({ data, search })        was (data, search?);  2 test calls
  new SiteRouter({ siteRoot, content })
No positional booleans:
  SiteRouter.land(url, { scrollY, isFirst })   was land(url, undefined, true)
  SiteSections.show(main, { isFirst })         was show(main, first)
  restoreFolds(main, { isInstant })
  UIDocsToc.schedule("rescan" | "follow"),  reveal("page load" | "hash change")
  UIDocsSearch.clear(event, true)  -> onClearClick()
  showCard(shown)                  -> openCard() / closeCard()
  UIDocsNav.flip(set, item, present) -> copyWith(set, item, "add" | "delete")
4+ params:
  UIDocsNav.group({ group, title, body, extra }),  SearchIndex.match({ entry, key, query, words, bonus }),
  toggleFavorite({ tag, star, event })
Pieces and lookups:
  renderOption -> option (its lookup -> optionFor);  renderSection / renderEntries -> section / entries
  optionIdFor, indexFor, dataTargetFor, scrollerFor, reservedIdsFor
is / has:
  nav:     searching / autoClosed / settled                    -> isX
  search:  open / preparing / searching / shown / loading      -> isX
  UIDocsSearch.segments() pieces:  mark -> isMarked  (TitleSegment, in the types file)
Constants below the class (Q18):
  PageOutline.SECTIONS / NOT_PAGE / PANES,  SearchIndex.PAGE_BOOST / HERE_BOOST / LENGTH_COST,
  UIDocsSearch.EMPTY / LISTBOX,  DocsSearchFallback.LIST,  UIDocsNav.SEARCHED,
  every SiteRouter / SiteShell / SiteSections static constant
  shared class words:  nav ROWS / ROW / HEADING / BAND,  search FIELD
null -> undefined:
  PageOutline.read(root?: Element)  (the search passes querySelector() ?? undefined;  1 test), its pane lookup
  SiteSections' climbs (sectionAround())
TocIndex:
  UIDocsToc.followedContent() replaces 3 copies of TocIndex.followed(…, this.attrs.for || undefined)
Imports:
  ThemePreference, site.ts, SiteRouter:  E / UI from $/ui/core   (were $/ui/runtime / $/ui/icons)

Small behaviour changes:

  • NavPreferences.closedGroups() drops names that aren't a nav group, and is typed NavGroup[]. Before, it kept them; the element only ever asked about its own groups.
  • A click on a nav group or view value that isn't a real one is ignored. Before, it was cast to one.
  • No public API changed outside the site bundle and the doc-only families.
  • site.js grew 2.2 kB minified, 1.2 kB gzipped.
    • Most of it is the house messages and E.Warnings.
    • The rest is the other agent's VocabularyTexts and HeadingLevels, landing in the entry, in the module ThemePreference also reads.
