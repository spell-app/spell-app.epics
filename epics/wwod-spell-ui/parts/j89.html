What the recipe changed in ui-docs-nav, ui-docs-search, ui-docs-toc and site/_src/, beyond imports (E / UI / UIT) and docstrings. Every caller is in packages/ui, all fixed.

  • Sets as const arrays: DocsSchemes (was DOCS_SCHEMES + an inline union; DocsShownScheme is Exclude<DocsScheme, "system">), SearchKinds (was SearchKind + KIND_ORDER listing the same strings), NavViews, NavGroups
  • Constructors take one props object: new SearchIndex({ data, search }) (was (data, search?); 2 test calls), new SiteRouter({ siteRoot, content })
  • Positional booleans gone: SiteRouter.land(url, { scrollY, isFirst }) and SiteSections.show(main, { isFirst }) (were land(url, undefined, true) / show(main, first)); restoreFolds(main, { isInstant }); UIDocsToc.schedule("rescan" | "follow") and reveal("page load" | "hash change"); UIDocsSearch.clear(event, true) became onClearClick(); showCard(shown) became openCard() / closeCard(); UIDocsNav.flip(set, item, present) became copyWith(set, item, "add" | "delete")
  • 4+ params: UIDocsNav.group({ group, title, body, extra }), SearchIndex.match({ entry, key, query, words, bonus }); toggleFavorite({ tag, star, event })
  • Render pieces as bare nouns: renderOption -> option (its lookup -> optionFor), renderSection / renderEntries -> section / entries; lookups xFor: optionIdFor, indexFor, dataTargetFor, scrollerFor (now on E.flatParentFor(): the same climb, so the private flatParent() and its null went), reservedIdsFor
  • Booleans is / has: public controller fields searching / autoClosed / settled (nav), open / preparing / searching / shown / loading (search) -> isX; nothing outside the class read them. The host STATES keep their names. UIDocsSearch.segments() pieces: mark -> isMarked (TitleSegment, in the types file)
  • One-class constants -> module consts below the class (Q18): PageOutline.SECTIONS / NOT_PAGE / PANES, SearchIndex.PAGE_BOOST / HERE_BOOST / LENGTH_COST, UIDocsSearch.EMPTY / LISTBOX, DocsSearchFallback.LIST, UIDocsNav.SEARCHED, every SiteRouter / SiteShell / SiteSections static constant; shadow class words -> constants (shared ones in the types files: nav ROWS / ROW / HEADING / BAND, search FIELD)
  • null -> undefined: PageOutline.read(root?: Element) (the search passes querySelector() ?? undefined; 1 test), its pane lookup; SiteSections' climbs (sectionAround())
  • TocIndex: instanceof Element -> localName (node scripts run it on linkedom); FollowedContent type; UIDocsToc.followedContent() replaces three copies of the TocIndex.followed(…, this.attrs.for || undefined) call
  • The docs fallbacks read their English texts through the other agent's new VocabularyTexts.english() (nav, search, toc; the toc's label was texts[0])
  • ThemePreference, site.ts, SiteRouter import E / UI from $/ui/core (were $/ui/runtime / $/ui/icons): the site entry loads the core anyway

Behaviour changes, small:

  • NavPreferences.closedGroups() drops names that aren't a NavGroup (it kept them; the element only asked about its own), and is typed NavGroup[]
  • a click on a data-nav-group / data-nav-view value that isn't one is ignored (was cast)

Net effect: no public API outside the site bundle and the doc-only families changed; site.js +2.2 kB min / +1.2 kB gz, most of it the house messages, E.Warnings and the other agent's VocabularyTexts / HeadingLevels landing in the entry (the module ThemePreference also reads).
