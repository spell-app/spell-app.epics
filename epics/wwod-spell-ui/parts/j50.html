In components.types.ts (UIT), the six value SETS took Q2's shape, and every caller moved (one-line edits):

  • STACK_WITH_VALUES -> StackWithValues (8 callers), MENU_APPEARANCES -> MenuAppearances + MenuAppearance (tabs, menu, docs/grammar.md), ITEM_ALIGNMENTS -> ItemAlignments + ItemAlignment, SOURCE_LOAD_MODES -> SourceLoadModes, FORM_STATES -> FormStates + FormState (form, input), SHAPE_FLIPS -> ShapeFlips (and ShapeFlip is now derived from it, not a second copy of the list)

Chose to leave two other shapes as they are:

  • const OBJECTS and vocabulary tables keep ALL-CAPS (PART_OWNER_TOKENS, TOGGLE_COMMANDS, SOURCE_ATTRIBUTES ...): ~150 call sites in other families for casing alone; Q2's option B (everything into const objects) was rejected for the same churn
  • unions with NO runtime reader stay plain types (ModalCloseReason, DimmerCloseReason, ItemRole ...): a const array would add bytes to core.js that nothing reads; callers write the typed literal (requestClose("escape")), which Q2 says is then type-checked

Net effect:

  • six renamed sets, every caller fixed; no behaviour change
