The code that makes decorators work is now bundled ONCE, shared by every file (I26). ui's core went from 29.48 to 26.30 kB gzipped.

  • Why there were copies: esbuild has no option to import its helpers.
    • So every decorated file carried its own copy, about 2.6 kB minified.
    • They're __decorateElement, __runInitializers ...
    • The core had 12 copies, and every family file one more.
  • The fix, in the root's vite.decorators.ts: it swaps a file's helpers for an import of ONE virtual module.
    • That's virtual:esbuild-decorator-helpers, built from a probe class that uses every decorator kind.
    • It swaps only when each helper the file declares matches it word for word.
    • Otherwise the file keeps its own: test files that import it, where esbuild renames a local.
    • The swap keeps the line count, so source maps still line up.
  • yarn measure, in kB gzipped: 
    core                    29.27 (step 1) / 29.48 (step 2 + fixes) -> 26.30
forms                   8.02   -> 6.39
a page with one button  71.93  -> 65.94
all families            590.75 -> 481.63
    • Every check is clean. The helper module lands in the core, so there's no new chunk.
  • It applies to every package built with the plugin: the brand, app and docs bundles.
  • Also looked at:
    • Controlled (0.29 kB) and Cell (0.11 kB) can't go yet. Brand's components use them, with UIElement.controlled() and attrs.
    • HostAttribute is already gone (step 1).
    • Reactive.ts is 2.35 kB gzipped on its own.
  • The core is 1.09 kB over its size before P14 (25.21), inside the 1.5 kB budget.
  • I26 can close.
