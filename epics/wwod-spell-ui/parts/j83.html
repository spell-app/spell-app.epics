The site data builder now takes its value lists from ui's own ValueSets.setFor(), as T2 asked. Two differences are kept on purpose, and written into its docstring.

  • Where: DEFAULT_SETS, in SiteDataBuilder.ts. It goes through a private SiteDataBuilder.valueSetFor(spec).
  • Kept: a width attribute lists the widths set.
    • That's a SITE choice, not added to KIND_VALUES.
    • To ValueSets, a width is free-form: 1/4, 25% ...
    • But the docs and editors list the column words.
  • Kept: a boolean attribute lists no set.
    • setFor() gives booleans, which lists yes, no ...
    • That would add them to 73 attribute rows that already say "boolean".
  • Not taken: adding width: "widths" to KIND_VALUES. That would change what ValueSets accepts as valid.
  • <ui-table>'s two alignment attributes now list their values.
    • text-align: alignments
    • vertical-align: verticalAlignments
    • In components.json, and the editors' html-custom-data.json.
  • Nothing else changed. Counted: every other alignment attribute already named its set.
