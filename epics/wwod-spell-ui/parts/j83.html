T2 asked whether DEFAULT_SETS (tools/SiteDataBuilder.ts) should read ValueSets.setFor(). Chose: it does now, through a private SiteDataBuilder.valueSetFor(spec), with two differences kept on purpose and written into its docstring.

  • width => widths stays a SITE choice, not added to KIND_VALUES: to ValueSets a width is free-form (1/4, 25%), but the docs and editors list the column words
  • boolean => none: setFor() gives booleans, which would add yes / no ... to 73 attribute rows that already say boolean
  • Option not taken: add width: "widths" to KIND_VALUES; that would change what ValueSets validates
  • <ui-table>'s text-align and vertical-align now list their values (alignments, verticalAlignments) in site/_data/components.json and the editors' html-custom-data.json; nothing else changed (counted: every other textAlign / verticalAlign attribute already named its set)
