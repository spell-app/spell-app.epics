Every phase from P3 to P9 takes one slice of ui, and walks each file through the same steps, in this order.

  • Agents (up to 5 per phase) each take a disjoint set of families, with this list.
  • Every rename is grepped across the whole repo first (WWOD §1).
  1. Imports:
    • one statement per module, in WWOD §4's order, the CSS import last
    • shared constants as UIT.X
    • no ../
    • the namespace form waits on Q4
  2. Layout:
    • the banner (one line, then bullets) and //// groups, members ordered outside-in
    • statics and constants AFTER the main methods; @proto static defaults stay on top (Q11)
    • a backing field right after its getter
    • module constants move into the folder's types file, or a private static
    • page-wide registries become private static readonly, with a static reset() (Q10)
  3. Types:
    • a set of values becomes a const array plus a type (Q2)
    • duplicates of UIT constants go
    • null becomes undefined, except at platform boundaries (Q9)
    • a positional boolean becomes a sentinel or a named option
    • 4+ parameters become a params object
    • constructors take one props object
  4. Names (every caller in the repo fixed, Q1):
    • xForY() for lookups
    • is / has / can for booleans
    • no abbreviations, and honest names
  5. Errors:
    • the message reads "Method(): problem; fix"
    • TypeError for bad caller input
    • a typed cause
    • the name on the prototype, X.prototype.name
  6. Docstrings:
    • where the base doesn't already say it (Q3)
    • "why static" on statics
    • the module's place in the import graph
    • comments that drifted, fixed
  7. Warnings through UI.logger (Q5, built in P2).

Each phase ends with yarn review green in every package it touched, one commit, and a stop for review.
