Each types file now holds only what 2+ files of its folder read; the rest moved below the one class that uses it (Q18). Where a family word has a UIT twin:

  • same name, same value, same meaning => UIT.X: step's COLOR_CLASS_PREFIX, every key name (UIT.Key.*: table's SPACE, slider's five arrow / page keys, rating's Backspace / Delete / arrows), UIT.CONTENT / DESCRIPTION for step's shorthand parts
  • same text, different meaning => a family name that says what it is: step's TITLE_PART (the .title part, not UIT.TITLE, the tooltip attribute), TableSort's HEADER_CELL = "th" (was HEADER, beside UIT.HEADER = "header"), tabs' NO_VALUE = "\u0000" (was NONE, beside UIT.NONE = "none"), step's CURRENT_STEP (was STEP)
  • tab's duplicate values merged: MENU_NOUN / MENU / MENU_PART => MENU; TAB / TAB_PART => TAB; ACTIVE_ITEM / SEGMENT_ACTIVE built from the words
  • the tab and step types files no longer value-import their vocabularies: PANE_NOUN is tabVocabulary.noun read in UITabs; step's IN_STEP / CONTENT / TITLE / DESCRIPTION class strings became UIStep.staticPart(noun) (as UICard's) and the fallback's part(noun, text); COMPLETED moved into the fallback
  • I14: UIT.STATIC_ROOT = "data-ui", beside STATIC_CONTROL; static.types.server.ts now value-imports UIT (import * as UIT from "$/ui/components/components.types", pure data, as types files may) so ROOT_ATTRIBUTE = UIT.STATIC_ROOT; its module docstring says so

Net effect:

  • ui-tab, ui-slider, ui-rating and ui-step types files import nothing; ui-table's only import type { UIT }
  • no published spelling changed (data-ui, class words, parts)
