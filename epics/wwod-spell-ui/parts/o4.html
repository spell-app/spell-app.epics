The proposal for P13 (Boolean Names): which true / false names in our code start with is / has / can (isOpen), and which are a bare word, like "open".

  • Nothing is renamed yet. You pick on the page, in five questions (Q22 to Q26), and a later phase does the renames.
  • You'd notice the problem reading any controller: three kinds of "open" can all sit in one class.
    • this.attrs.open: what the page author wrote
    • this.isOpen(): what we worked out
    • this.open.get(): a cell

Already settled

  • Public element API stays bare, like the platform (you, 2026-10-06, J13; WWOD §3's exception): attributes, element properties, :state(), event detail. el.open, nag.dismissed, el.readOnly.
  • Earlier renames already went toward is / has:
    • J12a: UIElement.isLoaded / isConnected / isFormDisabled, PartContextProps.isDirect
    • J12b (commit c9b6aaa8): the controller's word matches the public word, prefixed (isVisible, isCollapsed, isVeiled ...)
    • J30: UI.browser.isReducedMotion / isDark
  • So this section is about everything else: the names only our own code sees.

How the numbers were counted

  • A one-off script (not committed) ran TypeScript 6's type checker over every package with a tsconfig.json (all 14, util to vscode) and listed every declaration whose type is boolean (or boolean | undefined): 2,170 in all, 1,971 outside test files.
  • Each name is sorted by its shape:
    • is / has / can: isOpen, hasIcon, canAdd
    • other verb: should / was / did / needs / uses / shows ... (wasCancelled, showToolbar)
    • bare: everything else (open, scrolls, ignoreCase)
    • CONST: ISOLATE_ERRORS
  • Sites = the declaration plus every reference TypeScript's findReferences finds, in every package that compiles the file (tests included), each counted once even when overrides share them. So a site is one identifier a rename would change.
  • Not counted: mentions in .md docs and comments, and names reached through a string (setState("isLoaded")). The rename phase greps for those.
  • Why not git grep: words like open, active and selected match thousands of unrelated lines; the checker knows which open is a boolean.

Counter-examples, where the other form reads better or is forced:

  • A verb: scrolls() asks "is the content its own scroll box?"; isScrolling() would mean "is it moving right now". holdsShapes(), like the platform's matches(), needs no prefix.

DX:

  • Page author: unaffected; these never reach the page (J13).
  • Reader: in a controller, this.attrs.open is what the author wrote and this.isOpen() is what we worked out. The prefix marks the line between public and ours.
  • Autocomplete: typing this.is lists every yes / no a controller knows, in one place.

With every recommended option (A on Q22 to Q26), WWOD §3's boolean rule would read: 

- **A boolean's name reads as a yes / no question:**
  - What a class holds or works out, and the records we read back:  `is` / `has` / `can` (or `was` / `did` /
    `should` / `needs`):  `isOpen`, `hasIcon`, `canAdd`, `state.isBound`;  or a third-person verb that already
    asks it:  `scrolls()`, `matches(x)`, `supports.popover`.  NEVER a bare adjective or participle (`open`,
    `dirty`, `saving`).
  - Settings are bare, the platform's way:  options objects, constructor and component props, `@proto static`
    switches (`{ once: true }`, `{ optional: true }`, `static parenthesize = true`).  The field a setting is
    copied into keeps its name (`new Event(type, { bubbles })` -> `event.bubbles`).
  - A noun is never bare, anywhere:  `isAlias`, `isPart`, `isFirst`, not `alias`, `part`, `first`.
  - Yes / no functions:  `isX(value)` / `hasX` / `canX`, or a verb (`contains`, `covers`);  `isSameX(a, b)`,
    never `sameX`.  An action that reports success stays a verb (`requestClose(): boolean`).
  - Locals and parameters:  free, within the noun rule (`if (applied)`, `let found`).
  - EXCEPT names copied from outside, which keep their shape:  a custom element's PUBLIC API (bare, J13), platform
    members (`formAssociated`, `headersSent`), protocols (LSP modifiers), JSON on disk, Fomantic's published
    names, upstream ports.
- In a Solid controller, a tracked read is a call (`isOpen()`, a method or a memo);  elsewhere a getter
  (WWOD §12;  SEE:  §17).
