The inverted block wrote literal colours straight into private aliases (--_ui-flyout-background: oklch(0 0 0) ...) and the close icon's color: oklch(1 0 0). The rule (a literal colour only as a token's default) is met with three new public tokens, declared through their aliases in the token block, whose defaults ARE the old literals: 

--_ui-flyout-inverted-background: var(--ui-flyout-inverted-background, oklch(0 0 0));\n--_ui-flyout-inverted-color: var(--ui-flyout-inverted-color, oklch(1 0 0));\n--_ui-flyout-inverted-actions-background: var(--ui-flyout-inverted-actions-background, oklch(0.2 0 0));
  • the inverted block now writes --_ui-flyout-background: var(--_ui-flyout-inverted-background) ... (header colour and close icon read --_ui-flyout-inverted-color)
  • options: A) these tokens (taken: zero pixel change, and a theme can now restyle the dark flyout); B) the global --ui-ink-on-dark / --ui-black, which moves pixels (0.99 0.005 260, not pure white)
  • <ui-modal inverted> (P6) sets no colours of its own, so nothing to match there

Net effect:

  • no pixel should move (same computed values); P10's yarn test:visual confirms
  • the flyout's token table on the site grows by three rows after yarn site:data
