Seen in P1's baseline (2026-10-05), before any change:

  • entriesMissingCore: ui-flyout, ui-panel
  • runtimeChunks: one Rolldown runtime chunk (rolldown-runtime-*.js)
  • coreOutsideCore: 71 modules, e.g. $/util's decorators.ts, ValueSets.ts, every docs-components file

Looked at in P10 (or earlier if a phase makes it worse).

Root cause: four lazy chunks that core's own code can't reach each shared modules with core.js, and Rolldown only folds shared modules (and its __name helpers) into core.js when every lazy chunk using them is reachable from core or already loads it. Each one broke that rule in its own way, in three commits:

  • <ui-docs-*> families (8c2c785d): RootLoader's second glob, import.meta.glob("../../docs-components/*/index.ts"), made seven lazy chunks of the LIB build that import $/ui/core and other families. So every core module carried them in its "who needs me" set. The ones UIRuntime also uses (ValueSets, Vocabulary, BuiltInPacks, IconName, decorators / dom / string) then had a set Rolldown wouldn't merge into core.js, because ui-root reaches those chunks and core doesn't. So they went to a shared BuiltInPacks-<hash>.js.
  • Themes (8c2c785d): ThemeSheets.pageStyles() did import("$/ui/runtime"). That barrel isn't an entry, so the call made a new lazy chunk out of runtime/index.ts + load.ts + runtime.types.ts. The chain is UIRuntime → $/ui/styles → themes.ts → import() → load.ts → import("./UIRuntime"), so load-*.js and runtime.types-*.js split out too.
  • MDEngine (28e0ebde, after the bisect's first bad commit): its static import "$/ui/components/ui-table" (and five more families) made a lazy chunk that imports the core through those families. It's the same mechanism as the docs families, and it's enough by itself to bring BuiltInPacks-*.js back.
  • MarkdownSanitizer (364f93a8, I6): DOMPurify alone, no core import. Under keepNames every chunk depends on Rolldown's runtime module, and Rolldown hosts that module only in a chunk every user reaches statically. This chunk reaches nothing, so the helpers went to rolldown-runtime-<hash>.js. CodeEngine, MarkdownEngine and TemporalPolyfill already avoid this with a real SourceError / TEMPORAL_POLYFILL import, and their headers explain it; the sanitizer was written later without one.
  • ui-flyout / ui-panel in entriesMissingCore: a symptom only. Those two use only modules that had moved to BuiltInPacks-*.js, so their chunks stopped importing core.js.

How I checked: in a frozen export of HEAD, I removed each cause on its own. Every one of the four, removed alone, made its own chunk go away, and removing all four brings back 93abde40's layout (core.js, forms.js, families, lazy engines, nothing else).

Fix (import paths and entry structure only, no Rolldown option):

  • RootLoader globs only the library's families. It gains RootLoader.add(barrels), and a new src/docs-components/DocsFamilies.ts holds the docs glob. The site's site.ts calls DocsFamilies.add() before <ui-root> is defined. So dist/ no longer carries the doc-only families, and neither does the docs' single-file bundle built from it.
  • ThemeSheets.pageStyles(): import("$/ui/core"), the core ENTRY, which UIRuntime's chunk loads anyway.
  • MDEngine imports no family. MarkdownRenderer.loadMD() imports the six families beside it (mdFamilies()); an import() of a family is its own lib entry, so it adds no chunk.
  • MarkdownSanitizer imports SourceError from runtime.types and uses it. It now fails closed: where DOMPurify.isSupported is false it throws instead of returning markup it didn't clean.
  • tools/package.config.ts: docs-components/ gets a bucket of its own, docs, no longer core. A new check, docsBundled, fails if one ever shows up in the lib build again.
  • yarn measure: every check is empty (it was runtimeChunks 1, coreOutsideCore 71, entriesMissingCore 2).
  • core.js 90.95 → 107.19 kB min (26.39 → 31.25 gz): the 16.6 kB of BuiltInPacks + runtime.types + load + Rolldown's helpers are back where they belong. Reported core 73.11 → 23.00 kB gz, because docs modules no longer count as core.
  • A page with one button: 7 files / 46.49 kB gz → 3 files / 44.23 kB gz (dist files, Solid excluded). Dropdown 10 → 6 files, 68.08 → 65.70 kB.
  • Family chunks the same or smaller (ui-root 9.04 → 8.92, ui-modal 9.22 → 9.17 kB gz). ui-markdown.js is +0.12 kB min (gzip the same): the six import()s moved there from MDEngine.
  • The real yarn build still has ONE extra chunk, rolldown-runtime-<hash>.js (1.2 kB), and every family imports it. Before this fix it had four: BuiltInPacks, SiteData, runtime, rolldown-runtime. The cause is the styles entry, which yarn measure doesn't build: ThemeSheets' lazy glob needs Rolldown's helpers, and styles.js doesn't load core. A new issue has the options.
  • Tests: RootLoader.test.ts (4) and MarkdownSanitizer.test.ts (2) are new.
