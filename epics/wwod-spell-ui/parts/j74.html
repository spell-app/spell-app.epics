ui's environment variables now all start SPELL_UI_, and the old names no longer work at all: no period of reading them with a warning (what the CODE-DEBT.md entry suggested).

  • Why a clean break is safe: every variable is set by our own scripts or CLI, or typed by hand.
    • yarn test:all sets SPELL_UI_TEST_ALL.
    • VisualRunner sets the six SPELL_UI_VISUAL_* for its Playwright child.
    • SPELL_UI_SOLID_PROD and SPELL_UI_FA_PACKAGE_DIR are typed by hand.
  • The renames: 
    UI_TEST_ALL                                       -> SPELL_UI_TEST_ALL
UI_SOLID_PROD                                     -> SPELL_UI_SOLID_PROD
FA_PACKAGE_DIR                                    -> SPELL_UI_FA_PACKAGE_DIR
UI_VISUAL_OS / BASE_URL / WS / PARITY / STATIC / WORKERS -> SPELL_UI_VISUAL_*
  • ONE place reads them: environment.ts, which exports environment.
    • Its fields: 
      isAllBrowsers, isSolidProduction, fontAwesomeDir, isCI, invocationDir, visual.{os, baseUrl, ws, isParity, isStatic, workers}
    • Below it, unexported helpers that read one variable each, by type: a string, boolean, path, choice, or count or percent.
    • They aren't promoted to a shared package: no second package uses them yet.
  • The configs import it.
    • vite.config.ts and vitest.config.ts: Vite bundles relative imports into the config.
    • playwright.config.ts: Playwright transpiles it.
    • No process.env read is left outside it, except VisualRunner forwarding the variables to its child.
  • VisualSettings.ENV is gone. The variable names are now VisualVariables, beside environment.
  • A boolean variable is false when unset or empty, or set to 0, false, no or off.
    • ANY other value is true (CI=woodpecker), rather than an error for an unknown word.
    • Why: CI is set by other people's services.
  • A shell that still exports UI_SOLID_PROD=1 now silently gets the dev runtime: set SPELL_UI_SOLID_PROD=1 instead.

      • visual-testing.md
