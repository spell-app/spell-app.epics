ONE rule for member names: a base class gives way to a vocabulary. A member named like an attribute hides that attribute's getter.

  • This closes the base-class half of T26.
  • A BASE class never takes a name any vocabulary uses.
    • The bases: UIElement, FormElement, SourceElement ...
    • When a vocabulary does use one, the base member is renamed.
  • Applied, twice:
    • UIElement.definition became elementDefinition, because of the table's definition attribute. Fixed in ui, the demo, the element fixture and brand's composer.
    • FormElement's rules hook became validationRules, because of the rules attribute of input, textarea and form. It matches validationValue, validationLabel and validationAnchor.
  • So two workarounds are gone:
    • UITable's Omit<..., "definition">
    • TextControl's use of E.Reactive.attributeValue(). Its rules member is the attribute again.
  • A concrete class names members for what they are (isOpen).
    • A @controlled member that IS the attribute keeps its name: value, view, sortColumn.
    • Where its type is wider, the interface line leaves it out, with a line saying why. That's the value of the dropdown, select, input and textarea.
  • Guarded: Reactive.test.tsx checks every vocabulary's attributes against the base classes' members, instance fields too.
  • Written into UIElement's doc ("Member names"), and ui's AGENTS.md.
  • Rejected: an Omit per class. Every future family would need to know the base's names.
  • T26 stays OPEN, for brand only.
