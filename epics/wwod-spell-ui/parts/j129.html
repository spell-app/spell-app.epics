A member named like an attribute hides its getter. The rule:

  • A BASE class (UIElement, FormElement, SourceElement ...) never takes a name any vocabulary uses; when one does, the base member is renamed. Applied: UIElement.definition -> elementDefinition (<ui-table definition>; ui, the demo, ElementFixture, brand's composer), FormElement's rules hook -> validationRules (the rules attribute of input / textarea / form; matches validationValue / validationLabel / validationAnchor).
  • So UITable's Omit<..., "definition"> and TextControl's E.Reactive.attributeValue() work-around are gone (this.rules is the attribute again).
  • A concrete class names members for what they are (isOpen); a @controlled member that IS the attribute keeps its name (value, view, sortColumn), and where its type is wider the interface line omits it (UIDropdown, UISelect, UIInput / UITextarea's value), with a line saying why.
  • Guarded: Reactive.test.tsx checks every vocabulary's attributes against UIElement's and FormElement's members (instance fields too). Written into UIElement's doc ("Member names") and packages/ui/AGENTS.md.
  • Rejected: an Omit per class -- every future family would need to know the base's names.
  • T26 stays OPEN for brand only: a census of every controller's chain finds no ui collision left but the intended @controlled ones; brand's controllers (UIBrandCheck state / font, UIBrandChecklist step, UIBrandColorPicker / UIBrandComposer value, UIBrandColorSet columns, UIBrandComposer rows / hint) still collide, as they're still on the compat layer (see the brand issue)
