The themes switcher's hard-coded colours became three public tokens, with the SAME values as their defaults. So nothing moves on screen, and a theme can now change them.

  • Before: the sheet drew the switch's knob and the inverted buttons in literal oklch()s.
  • Chose tokens whose defaults are those literals, as J39 did for <ui-flyout inverted>. Mapping them to foundation tokens instead would have moved pixels.
  • The knob's tokens:
    • --ui-docs-themes-knob-color: white, oklch(1 0 0)
    • --ui-docs-themes-knob-shadow: 0 1px 2px oklch(0 0 0 / 0.25)
  • --ui-docs-themes-inverted-ink is white too, and the inverted buttons draw everything from it.
    • The fill, ring and icon are that colour at 0.08, 0.16 and 0.8 opacity.
    • On hover: 0.14, 0.28 and 1.
    • So it's one token, not six, through oklch(from var(...) l c h / a).
  • The dropdown's value for our own look, DEFAULT_VALUE, is deleted.
    • It was the same word, with the same meaning, as DOCS_PLAIN_THEME.
    • That's what the theme key stores for it; it's used instead.
  • Same pixels, by construction.
  • The three tokens show in the family's token table (yarn site:data rerun).
  • Also: ui-docs-example.css uses @media (--ui-mobile) for its width under 768px, the same range.
