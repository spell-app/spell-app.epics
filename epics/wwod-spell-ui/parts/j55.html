What ui-search became, where a choice was open:

  • Public: SearchMatcher.groups() -> SearchMatcher.groupsFor() (a pure lookup, WWOD §3); its response takes undefined, no longer null. Callers: UISearch and ui-search.test.tsx (4 lines, updated). SearchMatcherOptions -> SearchMatcherProps, moved from the types file to below the class (props live with their class); the constructor destructures it with inline defaults.
  • Private: enough / shown / busy -> isLongEnough / isShowing / isFetching; resultsElement() / categoryElement() / messageElement() / marked() / resultId() -> results() / category() / messageBox() (the message memo has the bare noun) / markedText() / idFor(); controller (an AbortController) -> abortController; SearchMatcher.fuzzy() -> isFuzzyMatch(); the min-characters check written 3x is isLongEnoughQuery(text).
  • RemoteAnswer.status and SearchMessage.kind are const objects (RemoteStatus.idle, SearchMessageKind.empty) in ui-search.types.ts, NOT module constants below UISearch (Q18): the types file's RemoteAnswer / SearchMessage types need them, and a types file never imports a class file.
  • location.assign(url) -> this.host.ownerDocument.location.assign(url): the host's own document, not the global (same page in practice).
  • DEFAULT_FIELDS_TEXT deleted: an absent search-fields passes undefined and SearchMatcher's own default applies.
  • The types file no longer value-imports the vocabulary: the fallback's CHANGE_EVENT / part name are module constants typed E.EventName / E.PartName.
  • One public rename (groups -> groupsFor); behaviour unchanged; 310 browser + 11 ssr tests of the four families pass.
