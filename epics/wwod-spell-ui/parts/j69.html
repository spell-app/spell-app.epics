UIToast, UINag and DialogElement created their appear / show effects inside render(). They now create them in mount() (ui's AGENTS.md "Eager memos and overridables"; DialogElement's call isOpen(), which a subclass may override).

  • Each compute adds this.loaded() (connected && loaded, as UICalendar's does): render() only runs once the runtime has loaded, and the applies animate / showModal() the rendered box, so without it an early connect would skip the entry animation
  • DialogElement's naming effect reads loaded() too, so it re-applies once the <dialog> exists
  • <ui-transition>'s visible effect stays in render(), with a comment: it calls nothing overridable, and moving it would let a visible change before the first render announce events
