A component pack file is a bare JSON ARRAY of entries, checked strictly. Rejected: an object with a version, or a looser shape. 

[
  { "tag": "x-chart",  "source": "chart.js", "skeleton": "20 x 12" },
  { "tag": "x-legend", "source": "chart.js", "load": "eager", "skeleton": "none" }
]
  • tag: any custom-element name, not only ui-*. That's lowercase, a letter first, and a hyphen inside.
  • source: the module to import, relative to the PACK file. It's made absolute as it's read.
  • load: when to import it.
    • on-demand, the default: a root imports it when it meets the tag.
    • eager: imported as soon as the pack is read.
  • skeleton: skeleton text; the default is none.
  • Anything wrong fails the pack as a whole.
    • That's an unknown key ("lod"), a bad tag, no source, an unknown load, or bad skeleton text.
    • It's a "render" SourceError, naming the pack, the entry's number and its tag.
  • The pack file is fetched through UI.sources: cached, and from the same origin only, as <ui-include> does. The modules it names may be anywhere, as a module script's may.
  • A pack's word on a tag WINS over the catalog's: its module, and its skeleton. The docs pack names <ui-docs-*> tags the catalog also lists.
  • Tags are added, never removed: a new source on the element reads that pack too.
  • ComponentPack.load(source) is the JS way, and what the element calls.
  • ComponentPack.entries(text, url) checks a pack without a server.
  • New types, in ui-root.types.ts:
    • ComponentPackEntry: an entry as written
    • RootPackTag: as RootLoader takes it
    • ComponentLoadPolicies
  • The element:
    • Its states: :state(loading | loaded | error).
    • It sends ui-load { source, tags }.
    • On failure it sends ui-error { kind, source, error }, which can be canceled; then a Warnings line.
