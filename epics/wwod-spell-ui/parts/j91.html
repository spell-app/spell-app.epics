Three sleeps in ui's tests are gone, and none kept: each test now awaits the same promise the code itself is waiting on, not a timer.

  • The api and tokens fallback tests dropped a setTimeout(resolve) after SiteData.load().
    • The files: ui-docs-api.fallback.test.ts and ui-docs-tokens.fallback.test.ts.
    • The fallback attaches its own .then to the SAME cached promise first, when it connects. So it has filled the section by the time the test's await resumes.
    • A comment in render() says so.
  • The color picker's "a refused clipboard write" test: the 20 ms sleep is now an await on that rejected write.
    • It's await write.mock.results[0].value.catch(...).
    • The picker's own await on the write runs its catch first.
  • The brand colour's copy test advances fake timers with the async form (advanceTimersByTimeAsync).
    • vi.useRealTimers() is added to afterEach, so a failing test can't leak fake timers.
  • Kept, since they're real browser events, not sleeps:
    • one requestAnimationFrame in the toc's test: the toc scans a frame after it connects
    • the scroll test's frame(), in the api family's test
  • Also kept: polls (vi.waitFor, expect.poll) for the nav folds, theme sheets and the flourish's resize. They wait on a condition, never a guessed time.
