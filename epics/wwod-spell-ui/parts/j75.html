ui's hot-reload test, hmr.e2e.ts, stays on node's own test runner, not Vitest: an exception to WWOD §20 › "Test APIs come from Vite+".

  • Why: yarn test:hmr runs the file with tsx, as a plain script.
    • Node runs a node:test suite that way.
    • Vitest's describe() only works inside Vitest's own runner.
  • Moving it would need a third Vitest project (or config) for one file.
    • That file owns a dev server, a browser, and real edits to source files.
    • It must never run alongside the other tests.
    • Not worth it; the reason is in the file's docstring.
  • Its free functions, over module-level variables for the server, browser and page, became two classes:
    • HmrPage: the page, and what the scenarios do to it
    • SourceFiles: the edits on disk. It can restore them all, and assert that they were (restoreAll(), assertRestored()).
    • The in-page arrow helpers became functions at the bottom.
  • Its sleeps became real waits, all but one:
    • the button's size change: 50 ms became a wait for its large class
    • the segment's 50 ms: recolorSegment() now waits for its class
    • update()'s 100 ms became two animation frames (SETTLE_FRAMES)
    • the 400 ms after a syntax error stays, named ERROR_GUARD: Solid's Vite plugin drops updates for 200 ms after an error, and fires no event
  • yarn test:hmr: 8 / 8, four runs in a row, about 3 s
