Below are the four changes to MenuOptions, the class behind the option list of <ui-dropdown>, <ui-select> and <ui-search>. Each one shows the code on main (Before) and on this branch (After). Only the first change affects code outside the class.

1. One props object for the constructor

A caller now names what it passes, so it no longer fills a skipped position with undefined.

  addition?: MenuAddition,
  keys = new WeakMap<MenuOption, SearchKeys>()
) {
 
private readonly keys = new WeakMap() as NonNullable<ConstructorParameters<typeof MenuOptions>[2]>

// in visible():
return new MenuOptions(this.all(), undefined, this.keys)
 
constructor({ options = [], addition, keys = new WeakMap() }: MenuOptionsProps = {}) {

/** Constructor props of `MenuOptions`. */
export type MenuOptionsProps = {
  options?: readonly (E.MenuOption | E.MenuAddition)[]
  addition?: E.MenuAddition
  keys?: WeakMap<E.MenuOption, MenuSearchKeys>
}
 
private readonly keys = new WeakMap() as NonNullable<F.MenuOptionsProps["keys"]>

// in visible():
return new F.MenuOptions({ options: this.all(), keys: this.keys })
  • UISearch passes nothing (new F.MenuOptions()), so it reads the same before and after.
  • The test file's lists change the same way: new MenuOptions(OPTIONS) becomes new MenuOptions({ options: OPTIONS }).

2. One Folding object instead of two booleans

Callers outside the class see no change. Inside it, the two switches travel together as one object, so a bare (true, true) now has a name. 

private normalize(query: string, ignoreCase: boolean, ignoreDiacritics: boolean)
private fold(text: string, ignoreCase: boolean, ignoreDiacritics: boolean)
private key(option: MenuOption, field: "text" | "value", ignoreCase: boolean, ignoreDiacritics: boolean)

// in selectionForKey() (type-ahead):
let term = this.normalize(prefix, true, true)
if (!option.disabled && this.key(option, "text", true, true).startsWith(term)) return index
 
private normalize(query: string, { ignoreCase, ignoreDiacritics }: Folding)
private fold(text: string, { ignoreCase, ignoreDiacritics }: Folding)
private key(option: E.MenuOption, field: E.MenuSearchField, { ignoreCase, ignoreDiacritics }: Folding)

// in selectionForKey() (type-ahead):
let term = this.normalize(prefix, TYPE_AHEAD)
if (!option.disabled && this.key(option, "text", TYPE_AHEAD).startsWith(term)) return index

// below the class:
const TYPE_AHEAD: Folding = { ignoreCase: true, ignoreDiacritics: true }
  • filter() and highlights() build theirs once from their options: const folding = { ignoreCase, ignoreDiacritics }.
  • A correction to the details above: TYPE_AHEAD is a module const below the class, not a private static. That follows ui's rule for constants only one class uses (Q18: a module const minifies to one letter).

3. keysOf() renamed to keysFor()

This is a rename of a private method, so callers see no change. The new name reads as "the search keys for this option". 

private keysOf(option: MenuOption): SearchKeys

// in withAdditions():
const keys = this.keysOf(option)
 
private keysFor(option: E.MenuOption): MenuSearchKeys

// in withAdditions():
const keys = this.keysFor(option)
  • Its return type, the private SearchKeys, is now the exported MenuSearchKeys, because MenuOptionsProps.keys names it.

4. "text" | "value" becomes MenuSearchFields

A caller still writes search: "text", "value" or "both". Only the type has a name now, and filter() loops over the fields instead of spelling out each one. 

// elements.types.ts
search?: "text" | "value" | "both" | MenuSearchFunction

// MenuOptions.ts, in filter():
const matchText = search !== "value"
const matchValue = search !== "text"
const results: MenuOption[] = []
for (const option of this.options) {
  const text = this.key(option, "text", ignoreCase, ignoreDiacritics)
  const value = this.key(option, "value", ignoreCase, ignoreDiacritics)
  if (
    (matchText && MenuOptions.matches(text, term, fullTextSearch)) ||
    (matchValue && MenuOptions.matches(value, term, fullTextSearch))
  ) {
    results.push(option)
  }
}
return this.derive(results)
 
// elements.types.ts
export const MenuSearchFields = ["text", "value"] as const
export type MenuSearchField = (typeof MenuSearchFields)[number]
search?: MenuSearchField | "both" | MenuSearchFunction

// MenuOptions.ts, in filter():
// `"both"` (or anything else) matches every field
const fields: readonly E.MenuSearchField[] = search === "text" || search === "value" ? [search] : E.MenuSearchFields
return this.derive(
  this.options.filter((option) =>
    fields.some((field) => MenuOptions.matches(this.key(option, field, folding), term, fullTextSearch))
  )
)
  • The matches are the same as before. "both", or any other string, still matches the text or the value.
  • One small saving: the old loop computed the value key even when search: "text" would never use it. The new one computes only the keys it compares.
  • A caller that passes options writes new MenuOptions({ options }), not new MenuOptions(options). That means 2 lines in UIDropdown and 5 in MenuOptions.test.ts. No page or doc in the repo builds its own MenuOptions.
  • new MenuOptions() with no argument (UISearch) is unchanged.
  • Three new exports: MenuOptionsProps, MenuSearchKeys (previously the private SearchKeys), and MenuSearchFields + MenuSearchField.
  • Private only, so no caller sees them: Folding, TYPE_AHEAD and keysFor().
  • Behaviour is unchanged: filtering, type-ahead and highlighting give the same results.
