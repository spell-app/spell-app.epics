P3 made the shared bundles every page loads a little bigger, and the rule that caused most of it would do the same to every family in P5-P7. You said in P2 you don't want the component bundles to grow (Q5), so this needs your call before P4.

What grew, P2 -> P3 (yarn measure, bytes):

Chunk min gzip Loaded by
core.js 108,891 -> 111,055 (+2,164) 31,833 -> 32,412 (+579) every page
forms.js 20,967 -> 21,983 (+1,016) 7,679 -> 7,949 (+270) pages with a form control
family chunks unchanged unchanged (P3 didn't restyle them)

Why: the rule in ui's AGENTS.md "Classes" (decision Q10, from WWOD §12) moves a constant one class uses from a module-level const into a private static. The minifier shrinks a module const's name to one letter, but a static's name is a property, kept in full: 

// module-level const:  minified to
const a = /[\s,]+/;  ... x.split(a)
// private static:  minified to
static LIST_SEPARATOR = /[\s,]+/;  ... x.split(t.LIST_SEPARATOR)
  • the forms agent measured it per file: Validator +374 B, MenuOptions +399 B, ControlLabels + LabelWatch +679 B, almost all from constants turned into statics
  • core.js's +2.2 kB mixes three things: statics' names, the longer house-style error messages (WWOD §5: "Method(): problem; fix"), and new reset() methods for tests
  • P5-P7 would do the same to ~60 family chunks, which hold ~700 more constants
  • P3's one-class constants go back to module consts below their class; core.js / forms.js shrink back toward P2's size (measured before you review P3)
  • ui's AGENTS.md "Classes" changes: "a constant one class uses: a module const below the class (it minifies); never a private static"
  • P5-P7 move nothing into statics
  • ui exception to WWOD §12: a constant ONE class uses is a module-level const BELOW the class (with its helpers, WWOD §8 › "Class first"), never a private static
  • page-wide registries stay private static + reset() (few, and tests need the reset)
  • P3's constant moves are put back: most of the growth goes; error messages stay house-style (they're worth their bytes)
  • WWOD to the letter; P3's +0.85 kB gzip stays
  • families grow too in P5-P7 (a guess: 1-3% each), every page pays
  • keep the WWOD shape and get the bytes back: a build option that mangles marked property names (e.g. esbuild / Oxc mangleProps on a name pattern)
  • needs a naming mark for "private, mangle me" (a prefix WWOD doesn't have), and mangling can break HMR, debugging and anything reading names; a spike first
