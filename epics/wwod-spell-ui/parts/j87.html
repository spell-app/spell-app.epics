The twin loaders disagreed (I10): SiteData.reset() kept its URL, SearchData.reset() cleared it, so tests wrote SiteData.reset(); SiteData.url = undefined. Both now take SearchData's rule: reset(url?) forgets the fetch and SETS url, so reset() is back to the page's own default (the <meta> / SITE_DATA_PATH; beside the data file).

  • Chosen because reset() reads as "back to the start", and no shipped code calls it (only tests, which always want a clean slate).
  • One shape, not one class: both keep the same static surface (url, load(), reset(url?)) and fetch through the same SiteData.request().
  • Rejected: a shared SiteFile<T> base. Statics on a base are shared by its subclasses (one loading for both files) unless each redeclares them, and instance singletons (SiteData.file.url) would change SiteData.url for site.ts, brand-docs.ts and ~40 test lines, for two 30-line classes.

Net effect:

  • the tests' SiteData.url = undefined after reset() is now redundant (left for P8, which restyles tests)
  • a caller that wanted reset-but-keep-the-URL passes it: SiteData.reset(SiteData.url) (none does)
