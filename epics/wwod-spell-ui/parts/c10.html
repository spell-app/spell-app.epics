A file of ui's element core can no longer be the first module loaded. The core's files now import the core back, so the folder is one cycle.

  • Entering it at a file the core reads while it loads throws.
    • For example, importing $/ui/elements/UIElement first loads the core.
    • The core loads ContentPart, which extends UIElement.
    • UIElement is still mid-load, so that's a ReferenceError (TDZ).
  • Nothing does that.
    • Only the core and forms.ts import those files by path.
    • Tests and the static renderer enter through the elements barrel. Its first class file, ClassBuilder, isn't read by anything at load time.
    • Both routes pass: 4695 browser tests plus 1 todo, and 255 server-render tests.
  • Also: the pieces that don't depend on a library now load the whole core, and Solid, when imported.
    • ClassBuilder, Validator, MenuOptions, Shorthand, StickyWatch ...
    • Their CODE still uses no Solid.
    • No node script imports them alone.
  • ui's AGENTS.md says NEVER import one of the element core's files by path.
  • barrel.test.ts documents why.
