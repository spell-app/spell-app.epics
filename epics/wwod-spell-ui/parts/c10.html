Now that the element-core files import $/ui/core back, the folder is one cycle. Entering it at a leaf that the core reads while it evaluates throws: e.g. import "$/ui/elements/UIElement" first would load the core, which loads ContentPart, whose extends UIElement meets a module still mid-load (a TDZ ReferenceError).

  • Nothing does that: only core.ts / forms.ts import the leaves by path; tests and $/ui/static enter through $/ui/elements, whose first class file (ClassBuilder) nothing reads at load time. Both routes pass (browser 4695 + 1 todo, ssr 255).
  • Also: the library-neutral pieces (ClassBuilder, Validator, MenuOptions, Shorthand, StickyWatch ...) now load the whole core (and Solid) when imported; their CODE still uses no Solid. No node script imports them alone.

packages/ui/AGENTS.md says NEVER import an element-core leaf by path; barrel.test.ts documents why.
