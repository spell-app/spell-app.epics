Some of the gaps aren't ui breaking a rule. WWOD (written for app code) and ui's AGENTS.md (written for a library of custom elements) say different things, or WWOD's own ui examples break WWOD.

  • Each needs a ruling before code moves.
  • The big ones are the open questions (Q1-Q5); the rest are proposed in the plan.

Where they disagree:

  • Namespaces (Q4):
    • WWOD §4 wants ONE namespace, qualified at the use site (P.Match)
    • ui exports three namespaces (E, V, SSR), but no file uses them
    • ui's AGENTS.md says two things:
      • "plain named imports from components.types"
      • "UIT.<NAME>, never bare"
  • Constants (Q2):
    • WWOD §9 wants a set of values as a const array or object
    • ui is built on one loose ALL-CAPS constant per word
  • Logging (Q5): WWOD §19's Logger lives in $/util/spell. It imports chalk, which ui must never load.
  • WWOD examples that break WWOD:
    • SourceError (§5)
    • CodeLines.TOKENS and CalendarDates.MINUTE_STEP: §12 says "after the main methods", but both sit at the top
    • FormFields and CalendarDates: §12 cites them, but they take positional constructors
    • ExampleSource.format(html, live): a positional boolean
  • WWOD §17 (Solid components) and §18 (CSS naming) were written for the app's function components and sheets.
    • ui's controller classes draw their pieces as private methods
    • its shadow sheets use Fomantic's class grammar (.ui.small.button)

Settled so far:

  • Q1-Q3 and Q5 answered
  • the rest proposed as decisions (Q6-Q16)
