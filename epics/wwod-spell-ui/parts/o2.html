Some of the gaps aren't ui breaking a rule: WWOD (written for app code) and packages/ui/AGENTS.md (written for a library of custom elements) say different things, or WWOD's own ui examples break WWOD. Each needs a ruling before code moves; the big ones are the open questions (Q1-Q5), the rest are proposed in the plan.

  • Namespaces: WWOD §4 wants ONE namespace qualified at the use site (P.Match); ui exports E, V, SSR but no file uses them, and ui's AGENTS.md says both "plain named imports from components.types" and "UIT.<NAME>, never bare" (Q4)
  • Constants: WWOD §9 wants sets of values as a const array or object; ui is built on one loose ALL-CAPS constant per word (Q2)
  • Logging: WWOD §19's Logger lives in $/util/spell and imports chalk, which ui must never load (Q5)
  • WWOD examples that break WWOD: SourceError (§5), CodeLines.TOKENS and CalendarDates.MINUTE_STEP (§12 says "after the main methods"; both sit at the top), FormFields / CalendarDates (§12 cites them, but they take positional constructors), ExampleSource.format(html, live) (a positional boolean)
  • WWOD §17 (Solid components) and §18 (CSS naming) were written for the app's function components and sheets; ui's controller classes render pieces as private methods, and its shadow sheets use Fomantic's class grammar (.ui.small.button)

Settled so far: Q1-Q3 and Q5 answered, the rest proposed as decisions (Q6-Q16); Q4 waits on P1's spike.
