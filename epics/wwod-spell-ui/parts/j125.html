@derived takes an equals option now, so the decorator keeps a list's identity, not hand code.

  • Before: it took no options, so three groups kept list identity by hand.
  • Now, with @derived({ equals }), an equal result keeps the OLD value. So readers see no change: an outer @derived, or an @onChange.
  • E.isSameList is exported for it: same items, in the same order.
  • UIDropdown:
    • Gone: the private stableList() (marked REFACTOR), its map of last lists, three name constants, and its own isSameList.
    • Its three lists use @E.derived({ equals: E.isSameList }): all options, chosen values and menu rows.
  • UISelect.chosenValues and UITabs.tabs do the same, as their old memos did.
  • UIMenu.ownItemContext uses @E.derived({ equals: isSameContext }).
    • Its lastItemContext is gone.
    • isSameContext moved above the class: a decorator's argument reads it while the class is defined.
  • Test: "@derived({ equals })", in Reactive.test.tsx.
  • The same identities as the step-0 memos.
  • No hand-kept caches left.
