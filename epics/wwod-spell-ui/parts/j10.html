Three methods RETURNED a SourceError for the caller to test (WWOD §5: never return error unions). They now throw it; behaviour is the same, since every caller already turned the returned error into a failure.

  • SourceElement.refuseSource(source): SourceError | undefined -> checkSource(source), which throws; default does nothing. schedule() catches it into loadFailed(). Only override: UIInclude
  • SourceMarkup.refusal(host, source, counts): SourceError | undefined -> SourceMarkup.checkNesting(...), which throws (callers: UIInclude.checkSource(), SourceBody.fetch())
  • SourceMarkup.parse(): DocumentFragment | SourceError and UIInclude.parse() -> DocumentFragment, throwing a render error; UIInclude.insert() catches it into loadFailed(error, "render")
  • Named check...: a method named refuse... that usually doesn't refuse wasn't honest (WWOD §3)

Also SourceError.kindFor(error, otherwise), replacing four copies of error instanceof SourceError ? error.kind : "load" (SourceElement x2, SourceBody, UICode): kind is now a getter over an optional cause, so each copy would have needed a ?? too.

Net effect:

  • one small change: a non-SourceError thrown while <ui-include> parses (DOMParser, URL rewriting) now shows as a render failure instead of escaping the effect
  • no caller outside ui
