Close its Claude tab, open a new session in this worktree's window, then run /epic wwod-spell-ui and pick "Reuse": it plans again from the kickoff prompt. This note goes once the plan has its first phase.

Bring packages/ui (about 120,000 lines, 62 component families) in line with WWOD, the house style, folder by folder: the shapes WWOD asks for (constants, errors, constructors, statics, names), not just comments. Where WWOD and ui's own AGENTS.md disagree, we settle the rule first, write it down, then change the code to match.

Kickoff prompt

`packages/ui` project was completely written by you before the WWOD rules landed.
It doesn't match my preferred coding style.

Five agents read ui against every WWOD rule (2026-10-05), one slice each: the element core and static render, the runtime and vocabulary, families ui-accordion to ui-loader, families ui-markdown to ui-visibility, and the docs components, tests, tools and scripts. Nothing was changed.

The surface style is already close. Across all ~900 files:

  • no interface (outside module augmentation), no TS enum, no #private
  • no jsdoc @param, no unicode em-dash, two spaces after every period
  • //////////////// group headers well formed; most element classes carry the /**** banner
  • no test file mixes it() and test(); every test imports from vite-plus/test
  • CSS: no rem, no live !important, no :host-context, public tokens read through private aliases

Some of the gaps aren't ui breaking a rule: WWOD (written for app code) and packages/ui/AGENTS.md (written for a library of custom elements) say different things, or WWOD's own ui examples break WWOD. Each needs a ruling before code moves; the big ones are the open questions (Q1-Q5), the rest are proposed in the plan.

  • Namespaces: WWOD §4 wants ONE namespace qualified at the use site (P.Match); ui exports E, V, SSR but no file uses them, and ui's AGENTS.md says both "plain named imports from components.types" and "UIT.<NAME>, never bare" (Q4)
  • Constants: WWOD §9 wants sets of values as a const array or object; ui is built on one loose ALL-CAPS constant per word (Q2)
  • Logging: WWOD §19's Logger lives in $/util/spell and imports chalk, which ui must never load (Q5)
  • WWOD examples that break WWOD: SourceError (§5), CodeLines.TOKENS and CalendarDates.MINUTE_STEP (§12 says "after the main methods"; both sit at the top), FormFields / CalendarDates (§12 cites them, but they take positional constructors), ExampleSource.format(html, live) (a positional boolean)
  • WWOD §17 (Solid components) and §18 (CSS naming) were written for the app's function components and sheets; ui's controller classes render pieces as private methods, and its shadow sheets use Fomantic's class grammar (.ui.small.button)
