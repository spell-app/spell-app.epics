Bring packages/ui (about 120,000 lines, 62 component families) in line with WWOD, the house style, folder by folder: the shapes WWOD asks for (constants, errors, constructors, statics, names), not just comments. Where WWOD and ui's own AGENTS.md disagree, we settle the rule first, write it down, then change the code to match.

Kickoff prompt

`packages/ui` project was completely written by you before the WWOD rules landed.
It doesn't match my preferred coding style.
Read WWOD rules deeply and reformulate `ui`, asking yourself "What Would Owen Do"???

Estimate: 25h-37h in all, 25h-37h left

Five agents read ui against every WWOD rule (2026-10-05), one slice each: the element core and static render, the runtime and vocabulary, families ui-accordion to ui-loader, families ui-markdown to ui-visibility, and the docs components, tests, tools and scripts. Nothing was changed.

The surface style is already close. Across all ~900 files:

  • no interface (outside module augmentation), no TS enum, no #private
  • no jsdoc @param, no unicode em-dash, two spaces after every period
  • //////////////// group headers well formed; most element classes carry the /**** banner
  • no test file mixes it() and test(); every test imports from vite-plus/test
  • CSS: no rem, no live !important, no :host-context, public tokens read through private aliases

Q2 Loose ALL-CAPS constants (~700): turn sets into const arrays + types, keep single words?

ui's types files hold about 700 loose ALL-CAPS constants, one per word: a class word, a part name, a key name, a mode. WWOD §9 › "Avoid TS enums, and loose constants" says a SET of related values is a const array (plural) plus a type (singular), or a const object, never loose constants.

ui-toast.types.ts · today 
export const TIMEOUT = "timeout"
export const ESCAPE = "escape"
export const APPROVE = "approve"
export const DENY = "deny"
// ... 11 class words under one comment
export const POSITIONS = ["top right", "top left", ...]   // not `as const`, no type
export const DEFAULT_POSITION = "top right"
 ui-toast.types.ts · option A 
////////////////
// ## Close reasons
////////////////

/** Why a toast closed, in `ui-hide`'s `detail.reason`. */
export const ToastCloseReasons = ["timeout", "escape", "approve", "deny", ...] as const
/** One of `ToastCloseReasons`. */
export type ToastCloseReason = (typeof ToastCloseReasons)[number]

////////////////
// ## Class words
////////////////

/** Class word of the close button. */
export const CLOSE_CLASS = "close icon"
 A · Sets become const arrays; single words stay (recommended)
  • a SET (close reasons, key names, positions, modes, trigger kinds) becomes Xs + type X, used as plain strings: reason === "timeout" is then type-checked
  • a single vocabulary word (CLOSE_CLASS, TITLE) stays a named constant: it isn't a set, and WWOD §3 › "Magic strings become named constants" asks for exactly that
  • every types file gets group headers; the ~18 family constants that re-declare a UIT one go; shared key names become ONE set in components.types.ts
B · Everything into const objects
  • ToastClasses.close, Keys.enter: one object per family per kind
  • about 700 constants and every call site renamed; a much bigger diff, little gained for single words

Net effect (A):

  • about 60 sets become const arrays + types
  • their values become English where they're only ours ("file protocol", not "file-protocol"); values a page or CSS reads (event detail, data-ui-animation) stay as they are
  • single-word constants stay, grouped and deduplicated
  • a line in ui's AGENTS.md says which is which
Q3 Docstrings: must every override of a documented base hook, and every @proto static line, carry its own?

WWOD §6 › "Docstrings on every declaration" says every member gets a docstring. About 400 of the ~1,000 missing ones are the same few members, repeated in every family:

  • overrides of hooks the base class documents: render() (46), hostStates() (46), build() in fallbacks (42), isDisabled() (17), classValue(), the form hooks (formValue, validationAnchor ...)
  • the @proto static lines every element has: vocabulary, styles, Fallback, degraded, delegatesFocus (about 280); WWOD §12 › "Every static member's docstring says WHY it's static" asks for more on each
UIButton.tsx · today 
export class UIButton extends UIElement<typeof buttonVocabulary> {
  @proto static vocabulary = buttonVocabulary
  @proto static styles = { button: buttonCSS }
  @proto static Fallback = ButtonFallback
  ...
  isDisabled(): boolean {
    return this.attrs.disabled || this.formDisabled.get()
  }
 A · Document what the base doesn't say (recommended)
  • the base classes (UIElement, NativeFallback) document each hook and each @proto static once, with why it's static
  • an override gets its own docstring only when it adds to the base's contract: /** Disabled by its attribute, or by a disabled fieldset. */
  • a plain render() or @proto static vocabulary = buttonVocabulary stays bare; one line in ui's AGENTS.md records the rule
B · Every declaration
  • ~400 more docstrings, most of them /** The vocabulary. */ and /** Renders. */
  • matches WWOD to the letter, but adds the noise WWOD §6 › "Explain why" warns against

Net effect (A):

  • about 600 docstrings written (new members, types, type members, exported constants); about 400 overrides stay bare where they only fill the base contract
  • a rule in ui's AGENTS.md: "As WWOD §6, plus: an override that only fills a documented base hook needs no docstring"
Q4 Namespaces: keep named imports from $/ui/core (a recorded exception), or qualify through one namespace (E.UIElement)?

WWOD §4 › "ONE namespace per sub-system" says code imports ONE namespace per package and qualifies at the use site: import { P } from "$/parser", then P.Match. ui does it differently, partly on purpose:

  • component files import named exports from $/ui/core / $/ui/forms, which ARE the lib bundles (dist/core.js): import { Cell, proto, UIElement, UIT } from "$/ui/core"
  • ui exports E, V and SSR namespaces, but no file in ui uses E or SSR
  • folder peers import their types file by name: import { DEFAULT_TYPE, FORM_ATTRIBUTES, ... } from "./ui-button.types" (up to 12 names)
  • ui's AGENTS.md contradicts itself on UIT: "plain named imports from components.types" in one place, "UIT.<NAME>, never bare" in another; today 26 files use bare names, 24 use UIT.X, 15 mix both
A · Named imports from the entries; UIT.X everywhere (recommended)
  • ui's AGENTS.md records the exception, with why: the entries are the bundles, and every name is already unique (UIButton, MenuOptions), so WWOD's "one name per type" holds
  • shared constants always UIT.NAME; one import statement per module (fixes the ~25 split ones)
  • delete the unused E and SSR namespaces (WWOD §2 › "Delete a field, option or export nothing reads")
B · Full WWOD: one namespace
  • import { E, UIT } from "$/ui/core", then E.UIElement, E.Cell, E.proto in ~600 files
  • risk: a namespace through core.ts may pin every export into each family's chunk (yarn measure would show it); the biggest diff of the epic

Net effect (A):

  • imports change only where they're split, bare where they should be UIT., or out of order
  • E and SSR namespaces removed; V stays (the api entry uses it)
  • one rule in ui's AGENTS.md "Imports" instead of two that disagree
Q5 Logging: promote a browser-safe Logger and debounce() into $/util for ui, or a ui-only devWarn()?

WWOD §19 › "Log through a Logger, not bare console.*", and WWOD §12 › "Debounced write-backs are xSoon members" leans on $/util's debounce(). ui can't reach either: Logger lives in $/util's spell-only folder (packages/util/src/spell/Logger.ts) and imports chalk; debounce() doesn't exist yet.

Today in ui:

  • 14 console.warn in browser code, with 5 different prefixes ([@spell-app/ui] ..., <ui-root>: ... ...); Converters.warn exists, with a REFACTOR: note asking for a devWarn()
  • 89 console.* in tools/ and scripts/, used as CLI output
  • two hand-rolled debounces (AppStylesheet.schedule(), VisibilityWatch.schedule())
A · Promote a browser-safe Logger + debounce() to $/util (recommended)
  • WWOD §8 › "Promotion path": Logger moves to packages/util/src/Logger.ts without chalk; debounce() beside it
  • ui's runtime gets ONE UI.logger (prefix ui, level WARN), every warning through it, one message format (WWOD §19 › "Message format")
  • tools/ and scripts/ write CLI output to process.stdout / stderr, as packages/cli does
  • cost: touches util (and parser's one import); a few hundred bytes in core
B · A ui-only devWarn()
  • $/ui/util gets devWarn(source, message, ...data); every runtime warning goes through it
  • tools keep console.*; no util change
  • leaves ui outside WWOD §19 for good: a CODE-DEBT entry

Net effect (A):

  • $/util gains a generic Logger and debounce(); $/util/spell's Logger path re-exports it
  • every ui warning goes through UI.logger; tools/ stop using console.*
  • WWOD §19's "TODO: epic logger-everywhere" moves one package forward
