Some of the gaps aren't ui breaking a rule: WWOD (written for app code) and packages/ui/AGENTS.md (written for a library of custom elements) say different things, or WWOD's own ui examples break WWOD. Each needs a ruling before code moves; the big ones are the open questions (Q1-Q5), the rest are proposed in the plan.

  • Namespaces: WWOD §4 wants ONE namespace qualified at the use site (P.Match); ui exports E, V, SSR but no file uses them, and ui's AGENTS.md says both "plain named imports from components.types" and "UIT.<NAME>, never bare" (Q4)
  • Constants: WWOD §9 wants sets of values as a const array or object; ui is built on one loose ALL-CAPS constant per word (Q2)
  • Logging: WWOD §19's Logger lives in $/util/spell and imports chalk, which ui must never load (Q5)
  • WWOD examples that break WWOD: SourceError (§5), CodeLines.TOKENS and CalendarDates.MINUTE_STEP (§12 says "after the main methods"; both sit at the top), FormFields / CalendarDates (§12 cites them, but they take positional constructors), ExampleSource.format(html, live) (a positional boolean)
  • WWOD §17 (Solid components) and §18 (CSS naming) were written for the app's function components and sheets; ui's controller classes render pieces as private methods, and its shadow sheets use Fomantic's class grammar (.ui.small.button)

Settled so far: Q1-Q3 and Q5 answered, the rest proposed as decisions (Q6-Q16); Q4 waits on P1's spike.

Every phase from P3 to P9 takes one slice of ui and walks each file through the same steps, in this order. Agents (up to 5 per phase) each take a disjoint set of families, with this list; every rename is grepped across the whole repo first (WWOD §1).

  1. Imports: one statement per module, WWOD §4's order, the CSS import last, shared constants as UIT.X, no ../; the namespace form waits on Q4
  2. Layout:
    • the banner (one line, then bullets) and //// groups, members ordered outside-in
    • statics and constants AFTER the main methods; @proto static defaults stay on top (Q11)
    • a backing field right after its getter
    • module constants into <folder>.types.ts or a private static; page-wide registries private static readonly + static reset() (Q10)
  3. Types:
    • a set of values becomes a const array + type (Q2); duplicates of UIT constants go
    • null becomes undefined, except at platform boundaries (Q9)
    • a positional boolean becomes a sentinel or a named option; 4+ parameters become a params object; constructors take one props object
  4. Names: xForY() for lookups, is / has / can for booleans, no abbreviations, honest names; every caller in the repo fixed (Q1)
  5. Errors: "Method(): problem; fix", TypeError for bad caller input, a typed cause, X.prototype.name
  6. Docstrings where the base doesn't already say it (Q3), "why static" on statics, the module's place in the import graph, comments that drifted
  7. Warnings through UI.logger (Q5, built in P2)
