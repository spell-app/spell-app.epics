Two sentences: what this plan does, and why.

I'm getting on an airplane in 36 hours. I'd like to work on epics while I'm offline (or only intermittently online with crappy wifi). Specifcally, I'd like to be able to through the existing epics/docs and mark/comment on things, queuing up things for you to work on while I'm offline. What do we need to change to make this work?

Five gaps, found by three explore agents on 2026-10-09. Each says what Owen would hit on the plane.

  1. Flaky wifi can stall every page. Every docs page and plan doc (121 files, all 30 plan docs) loads highlight.js from cdnjs with a plain blocking tag, just before spell-ui.js: 
    <script src="https://cdnjs.cloudflare.com/ajax/libs/highlight.js/11.9.0/highlight.min.js"></script>
    • Fully offline: the request fails at once; code blocks lose their colours, nothing else changes.
    • Plane wifi with a "pay first" page: the request hangs, so spell-ui.js waits too. The page shows raw, unstyled markup with no review buttons until it gives up (tens of seconds).
  2. Guides, durable docs and the docs index take no notes at all. No button, no route. Only plan-doc items, goals pages and details pages with questions do.
  3. In a plan doc, only items and Overview sub-sections take marks.
    • Not the summary, not a phase (its Goal, Changes, Files ...).
    • No way to add a NEW todo or question from the page: a new idea has to ride along as a note on some other item.
  4. Getting around the Review tab needs a terminal. It has no home page: each plan doc is opened with spell dev docs open epics/<name>/<name>.plan.html --review. (The Spell Docs tab has its Docs Index command, and the review buttons work there too.)
  5. After landing, nothing gathers what he left.
    • No command lists marks across every epic: he would have to remember which docs he marked, and run /epic review <name> on each.
    • Marks he never Sent never wake /epic review.
    • Text typed in a note box but never submitted stays a draft forever: one from 10/6 still sits in outline-spell's inbox.
    • Details answers, goals thoughts and the new page notes live in three more places.

Two skill calls bracket the flight. In between, Owen works on the pages alone, and everything he does lands in files on disk.

  1. /airplane, before the flight (online):
    • a pre-flight check: page server up, extension current, no page loading anything remote, no session mid-work
    • airplane mode ON: the pages stop saying "start /epic review", and say "queued for when you land" instead
  2. On the plane (no Claude):
    • open any plan doc or guide in the side bar
    • mark items, write notes on any section or phase, add new todos and questions
    • all of it saves through the local page server
  3. /airplane land, after (online again):
    • one list of everything left, across every epic and page: marks (sent or not), drafts, Do Now requests, page notes, new items, details answers, goals thoughts
    • works through it in background agents, the way /bedtime does: each answer written INTO its item or page, nothing merged
    • then /epic review, for Owen to go through what came back
  • What Owen leaves is only files: the epic inboxes (epics/<name>/<name>.inbox.json) and the new notes files.
  • So only the CAPTURE side (the pages, the buttons, the files' shape) must be built before he flies.
  • The processing (/airplane land) only reads those files: it can be built after he lands, as long as their shape is fixed first.
