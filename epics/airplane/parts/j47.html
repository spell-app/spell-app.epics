Owen asked for "the normal browser menu" on right-click in the Review / Spell Docs views. Right-click showed NOTHING: VS Code's webview host listens for contextmenu on the view's own page only (pre/index.html, hookupOnLoadHandlers()), and our page is a cross-origin frame inside it, so the click never reached it. A browser-style menu (Back, Reload, Inspect Element ...) can't be had: VS Code is Electron, and "Electron doesn't have a built-in context menu. You're supposed to handle that yourself" (github.com/sindresorhus/electron-context-menu); an extension can't reach Electron to build one. What a webview CAN show: VS Code's webview/context menu (code.visualstudio.com/api/extension-guides/webview, "Context menus").

So the page forwards its right-click to the view's wrapper, which right-clicks again at the same place (the host's listener checks no isTrusted), and VS Code shows the menu there: Cut (in a field, with a selection), Copy (with a selection), Paste (in a field), Select All; Back, Forward (greyed when there's nowhere to go), Reload; Open in Browser; Inspect (Developer Tools). A right-click the page handles itself (preventDefault()) stays the page's.

  • Right-click in either side-bar docs view shows a VS Code menu with those items, at the pointer
  • Inspect toggles the window's developer tools (as the title-bar button): it can't jump to the element clicked (Electron's inspectElement(x, y) isn't open to extensions); Cmd + Shift + C there, then click
  • No Back / Reload of the browser's own, no Look Up, no spelling suggestions: those are Chrome's, not Electron's
