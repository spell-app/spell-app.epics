Where should a note on a guide, a durable doc or the docs index be saved? A plan doc already has its inbox, epics/<name>/<name>.inbox.json. Other pages have nothing yet.

For example, Owen reads guides/solid/solid-2.html, section 3.2, and writes "this contradicts the cheatsheet".

  • The note is saved in guides/solid/solid-2.notes.json, next to the page. It isn't committed (git-ignored), the same as the inbox files.
  • The page can show its own notes again, and they are easy to find from the page.
  • The landing finds them all with one file scan (**/*.notes.json).
  • Every note goes into a single file, ~/.spell/airplane/notes.jsonl, one line per note: page, section id, text, time.
  • Easiest for the landing to read.
  • But a page has to search the whole file to show its own notes, and the file only exists on this machine.
  • The note is written into the page's HTML, the way goals thoughts are.
  • It's committed with the shared content repo, so the note travels with the page.
  • But it changes Owen's docs while he only meant to comment, and every page kind needs its own markup for it.
  • A new /api/notes route on the page server writes <page>.notes.json.
  • The shared repo's ignore list gets *.notes.json.
