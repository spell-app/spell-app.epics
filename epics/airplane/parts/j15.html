How the Epics page decides "errors" and "running".

  • Urgent means an item whose chip is red or orange. Both wait on Owen.
    • red (attention): an open question, or a judgement call or issue not reviewed
    • orange (replied): Claude's options wait on Owen's pick
    • todos, tests and caveats never count
  • A session is running when its record (in ~/.claude/sessions) has a live process, and either:
    • its folder is the epic's worktree
    • or its title, minus the icon, is the epic's name
  • The page server re-marks every card on each load, so "paused" and "in progress" follow the clock and the sessions.
    • The docs index writes each card's facts as attributes (data-phases, data-updated, data-urgent, data-future).
    • RunningEpics.render() reads them on each request.
  • In a plan doc's own header, "running" means a session is listening to its review.
  • Planning (no phases yet) is now "in progress" or "paused", with no yellow bubble.
  • 17 old, finished epics now show red errors: their judgement calls were never reviewed (claude-design has 49).
    • That's the rule doing its job, but expect a lot of red until they're reviewed or marked calm.
  • Session titles: 😴 is gone. The new icons are 🚨 errors and ⏸️ paused; bareTitle() still strips an old 😴.
  • Opened from disk, the Epics page shows the states as of the last docs index run.
