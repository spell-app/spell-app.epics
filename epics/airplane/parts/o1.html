Most of what Owen wants already worked with no network and no Claude, before this epic. Marking a plan doc in the side bar only needs the local page server.

  • The review buttons stay on with nobody listening. These all save to the epic's inbox file, epics/<name>/<name>.inbox.json:
    • Approve, Revisit (with a note), Make Todo, Do Now and Choose, on each item
    • Send, in the page header
    What happens with no session listening:
    • The page only warns: "No Claude session is reviewing this doc: this waits for the next /epic review".
    • Do Now stays dashed ("queued") instead of spinning.
    • The file survives server restarts and days; /epic review <name> picks up what was Sent.
  • Overview sub-sections take notes too (Revisit, Make Todo, Do Now), not only items.
  • Details pages and goals pages save on their own. The page server writes a details answer to <slug>.answer.json, and a goals thought into the goals page itself, with no Claude waiting.
  • Nothing else reaches the internet.
    • Fonts and icons are built into spell-ui.js; the plan-doc elements come from the committed epics.pack.js.
    • The VS Code side bar only frames 127.0.0.1: no auth, no telemetry, no claude.ai.
    • The page server's start-up bundle builds are local vite runs; yarn has its own committed release and a warm cache.
  • Page side: packages/epics/src/review/ReviewClient.ts, buttons in packages/epics/components/epic-item/ReviewControls.tsx.
  • Routes: packages/epics/src/tool/reviewRoutes.ts (/api/review/mark, now, send, draft ...), under a file lock.
  • The file: packages/epics/src/tool/ReviewInbox.ts; Claude's side: InboxCommands.ts (listen, wait, apply).
