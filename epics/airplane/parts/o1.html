Most of what Owen wants already worked with no network and no Claude, before this epic. Marking a plan doc in the side bar only needs the local page server.

  • The review buttons stay on with nobody listening. These all save to the epic's inbox file, <name>.inbox.json, beside its plan doc:
    • Approve, Revisit (with a note), Make Todo, Do Now and Choose, on each item
    • Send, in the page header
    What happens with no session listening:
    • The page only warns: "No Claude session is reviewing this doc: this waits for the next /epic review".
    • Do Now stays dashed ("queued") instead of spinning.
    • The file survives server restarts and days; /epic review <name> picks up what was Sent.
  • Overview sub-sections take notes too (Revisit, Make Todo, Do Now), not only items.
  • Details pages and goals pages save on their own, with no Claude waiting. The page server writes:
    • a details answer to a file beside its page, <slug>.answer.json
    • a goals thought into the goals page itself
  • Nothing else reaches the internet.
    • Fonts and icons are built into the docs script, spell-ui.js.
    • The plan-doc elements come from a committed script, epics.pack.js.
    • The VS Code side bar only shows pages from this laptop (127.0.0.1): no sign-in, no telemetry, no claude.ai.
    • The page server builds its bundles when it starts, on the laptop.
    • Yarn has its own committed copy and a warm cache.

Four pieces, from the page to Claude:

  • The page side: ReviewClient.
  • The buttons: ReviewControls.
  • The page server's routes, under a file lock: reviewRoutes. 
    /api/review/mark
/api/review/now
/api/review/send
/api/review/draft
...
  • The inbox file itself: ReviewInbox.
  • Claude's side, the commands that listen, wait and apply: InboxCommands.
