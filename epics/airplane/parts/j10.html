An item folds once Owen chooses an action for it, and only then.

  • It folds after:
    • the line's buttons: Approve, Make Todo, Do Now, a todo's plane and x
    • every note box button: Later, Make Todo, the plane, the x
    • a Choose pill's pick
  • It doesn't fold after:
    • Revisit: it opens the note box, so nothing is chosen yet
    • typing
    • a button pressed again, to clear its mark
    • a running request called off
    • an un-pick

How it's told:

  • The page's review client decides what a click did, so it also says whether it chose something: ReviewClient.press() now answers "open-box", "chosen" or nothing.
  • The buttons (ReviewButtons) call onChosen, the note box its onUsed, and an option card its item's foldAfterAction().
  • The fold goes through the item's usual toggle, so the stuck line stays put (I5's fix).

Only items fold.

  • An Overview part, a phase and the summary keep their review buttons open, as Owen asked only about items (their onChosen is unset).

Not handled: folding near the very end of the page.

  • There the browser clamps the scroll, because too little is left below.
  • The line then moves DOWN by what's missing, still on screen.
  • A spacer at the page's end could hold it; left out as rare, since the folded sections below usually give room.
  • Owen picks an action, the item folds, its line stays where it was, and the next item is right under it.
  • Browser tests: an action CHOSEN folds the item; Revisit, typing, a cleared mark or a request called off don't.
