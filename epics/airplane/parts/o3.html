Two skill calls bracket the flight. In between, Owen works on the pages alone, and everything he does lands in files on disk.

  1. /airplane, before the flight (online, from the main checkout):
    • spell dev airplane check --fix, the pre-flight check, names what isn't ready:
      • run from the main checkout, not a worktree
      • the page server is up (--fix starts it, or restarts one older than its code)
      • no page loads anything from the internet (--fix points every page's highlight.js at the repo's copy)
      • the VS Code extension is current (if not: spell dev vscode from main, then reload)
      • which epics already have marks waiting: they will be gathered at landing too (J9)
    • any Claude session still mid-work is listed, and Owen picks which to /park
    • spell dev airplane on: the switch, ~/.spell/airplane.json. The page server tells every page as it serves it, and a plan doc then says "Airplane mode: queued for when you land" instead of "start /epic review"
  2. On the plane (no Claude):
    • open a plan doc from the Review tab's list button ("Review: Open Epic..."), or any page from "Review: Docs Index"
    • in a plan doc: mark items, leave a note on the summary or a phase, add a new todo or question with the +
    • on any other docs page: a note on a section (the bubble on its title), or on the whole page (the Note pill)
    • all of it saves through the local page server; Send isn't needed
    • a plan doc's marks go to its inbox file; a note on a guide or other page is written into the page itself, the way goals thoughts are, and travels with it in the shared content repo
  3. /airplane land, after (online again):
    • spell dev airplane inbox first: one list of everything left, across every epic and page, while the switch still says when the flight began
      • each epic's marks, sent or not, and its new items, drafts and Do Now requests
      • page notes not yet answered
      • details answers since the flight, and goals thoughts
    • then spell dev airplane off
    • spell dev plan-doc inbox <name> apply --all on each epic: approvals, picks, todos and new items land in the doc, sent or not (Q3)
    • the rest goes to background agents, up to 5 at once: each Do Now, revisit and page note, the answer written INTO its item or under its note; nothing is decided for Owen
    • drafts (text typed and never submitted) are asked about, never acted on
    • then /epic review on the epic with the most waiting, for Owen to go through what came back
  • What Owen leaves is only files: the epic inboxes (epics/<name>/<name>.inbox.json) and the notes written into the pages.
  • /airplane land (P5) only reads them. It was built before the flight anyway, in bedtime mode with the rest (Q8, Q9), but it didn't have to be merged before Owen flies.
