  • A bullhorn icon beside each major block of a guide: sections, tables, asides, code, lists.
    • Clicking it opens a comment field.
    • The comment saves to an inbox beside the guide (<guide>.inbox.json), and is queued in airplane mode.
    • It shows in a box under that block, like a plan doc question's.
  • The comment box is a small floating pane (Owen, 2026-10-10).
    • It opens just below the selected text, or below the bullhorn that was clicked.
    • Owen can move it by dragging its top band.
    • The page never scrolls when it opens or saves, so he keeps his place.
  • Clicking highlighted quoted text on the page opens that comment in the pane again.
    • While it is still waiting, Owen can edit it.
    • Once Claude has taken or answered it, it is read-only and shows Claude's answers.
  • Owen can clear any comment, whatever its state: new, taken or answered.
    • It leaves the inbox and its highlight goes.
    • Delete stays as it was, allowed only while a comment is new.
  • One guide-changes epic gathers the comments, one phase per doc.
    • It runs on landing, or on demand, for one doc or all.
  • Where the comments are kept (Owen asked):
    • A docs page's (a guide, the docs home, an epic's own pages): in its own inbox file, beside the page. The Solid 2 guide's, for example, is solid-2.inbox.json.
    • A plan doc's: in the epic's existing review inbox (<name>.inbox.json), under comments, beside the marks.
    • Both are git-ignored in the shared repo: waiting work on this laptop, never the record, as review marks are.
    • The page server writes them, so no Claude and no network are needed.
    • At landing, /airplane land runs spell dev comments gather:
      • it puts every docs page's waiting comments into epic guide-changes, one phase per page, and marks them taken
      • a plan doc's comments are answered into the doc like a revisit's note (/epic review 7.3, step 3b), then marked done (plan-doc inbox <name> done cm3)
  • How to see a comment was recorded: its card under the block, by the fill rule.
    • dashed while typed and not saved: "Not saved yet"
    • outlined once saved: "Saved 14:02 · waiting for Claude"
    • solid once Claude has it: "Taken by Claude · guide-changes P3", or "Answered"
    • a toast on save, and the block's bullhorn shows the count
  • A bullhorn beside every major block: quiet until hovered, and always shown, with a count, once the block has comments.
    • on docs pages: sections (in the title), tables, asides, code, messages, cards, steps, top-level lists, the page header
    • in plan docs: items, phase fields, the summary, Overview prose, tables, asides, code
    • its tooltips are the browser's own (title)
  • Comment on selected text: ⌘ / Ctrl I, or the bullhorn floating beside the selection.
    • The quote is kept, with where it sits in the block's text.
    • It shows at the top of the box and the card, and is highlighted softly on the page.
  • How a comment finds its block again (BlockAnchors, shared by the page and the tools):
    • the block's id, if it has one
    • else its section's (or plan part's) id, its kind and its number: memory#table-2

    <section or plan part id>#<kind>-<n>
