A new note is spliced straight into the page's text, instead of re-writing the whole page.

  • A small tag scanner finds where the note's lines go (PageNotes.js).
  • Then the formatter (oxfmt) runs in memory, but only when the page was already formatted before (SRV.formatHTML()).

Chose it over the way goals pages do it, because that way is noisy and slow:

  • Goals pages parse the page with linkedom, write it back out, then tidy it (tidy()).
  • A guide written back out by linkedom changes bytes all over the page.
  • Tidying runs the formatter (yarn vp fmt) and the link fixer on every note: seconds each time, on the plane.
  • A note's diff in the shared repo is the note alone.
  • A page that wasn't formatted gets the note pre-indented, and is NOT reformatted.
    • Today that's two pages: the Solid 2 guide (solid-2.html) and the CLI guide (cli.html).
    • The next docs update, or a finishing pass, formats it.

Chose to insert the note's lines straight into the page's text (a small tag scanner, PageNotes.js) and to run oxfmt (in memory, AS.formatHTML()) after only when the page was formatted before, over the goals way (linkedom parse, serialize, tidy()), because a guide re-serialized by linkedom changes bytes all over the page, and tidy() spawns yarn vp fmt and doc-links on every note (seconds, on the plane).

  • A note's diff in the shared repo is the note alone
  • A page that wasn't oxfmt-clean (today: guides/solid/solid-2.html, guides/cli.html) gets the note pre-indented and NOT reformatted; the next docs update / finishing pass formats it
