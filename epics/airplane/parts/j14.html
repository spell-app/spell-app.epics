Owen asked for one place to work out an epic's state. It's one file with no imports, EpicState, in the server package's site folder.

Why there, and not in the plan-doc tool:

  • The plan-doc tool (tool/) is node-only, and must never go into the epics pack; but the page header lives in that pack.
  • The page server is a leaf, and may not import epics.
  • The docs index runs under plain node, which has no import aliases.
  • The one home every reader may import is the server's site folder (site/), which already holds browser code.
  • The file has no imports, so plain node loads it by its path, with its types stripped.

Four readers import that one file: the docs index, RunningEpics, the epic-page header, and the CLI's session icons.

  • ONE rule, and no copies to keep in step.
  • The old pair, in the docs index and RunningEpics, had drifted into "SAME as" comments.
  • The docs index (index.js) imports the file by its path, and plain node strips the types: 
    ../../server/src/site/EpicState.ts
