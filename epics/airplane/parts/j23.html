The docs index reads all three: the epic-page updated stamp, the newest epic-event time in the doc or parts/log.html, and the epic's branch's last commit (one git for-each-ref for every branch, so cheap). A merged epic with its branch deleted goes by the doc alone.

The page server's live cards for an epic running in a worktree read the doc's two dates (no git per request), and keep the docs index's date when that is later (it may hold the branch's commit).

Shown as month/day without the year (10/9), its title the full date and time in the plan docs' style (10/9/26 22:17).
