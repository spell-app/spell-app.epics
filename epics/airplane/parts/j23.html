An epic was "last worked on" at the latest of three dates.

  • the plan doc's "updated" day (on <epic-page>)
  • the newest log line, in the doc or its log part (log.html)
  • its branch's last commit
    • one git call (git for-each-ref) covers every branch, so it's cheap
    • a merged epic, its branch deleted, goes by the doc alone

Who reads them:

  • The docs index reads all three.
  • The page server's live cards, for an epic running in a worktree, read only the doc's two dates: no git on each request.
    • They keep the docs index's date when that is later, since it may hold the branch's commit.

Shown as month/day without the year (10/9). Its tooltip is the full date and time, in the plan docs' style (10/9/26 22:17).

  • Each Epics card's bottom-right corner says when it was last touched, by Claude or by a commit.

The page server's live cards for an epic running in a worktree read the doc's two dates (no git per request), and keep the docs index's date when that is later (it may hold the branch's commit).
