Handlers would get an event with a real type, which clears 12 of the 13 unknowns in Solitaire's TypeScript and gives Rust what it needs. This asks how to do that better than HTML does.

HTML's way: there's one family of event classes grouped by device (MouseEvent, KeyboardEvent, DragEvent), and a handler that hears several has to check which one it got. Fields it wants may or may not be there.

Spell is already most of the way past this.

  • What comes with an event is read by name: send flipped with side = 1 is read as side in the handler.
  • The mouse and keys can be read anywhere: the shift key is down.
  • A template can already declare an event: it sends "flipped" with side as a direction.

So in the compiled code, the event argument is plumbing that no Spell author sees, and only its type is missing. 

// Spell
- it sends "flipped" with side as a direction
- when flipped:
    show side

// TypeScript:  the name of the handler settles the type, so nothing to check
type Flipped = SpellEvent & { side: Direction }
onFlipped(event: Flipped) { ... }

// Rust
pub struct Flipped { pub side: Direction, pub target: Handle, /* ... */ }
fn on_flipped(&self, event: Flipped) { ... }
  • The handler's name settles what it holds. Nothing to check, and no field that might be missing.
  • click has only the basics, key down adds key, and a card is dropped on it adds the card.
  • Every event shares the same basics: target, the original target and sender.
  • Events a template declares get their types from that declaration. An event only triggered (card-click) gets them from its with properties, as properties already get theirs from what the program gives them.
  • An event sent with nothing declaring it may be unclear, and falls back to Value.
  • Simplest: every handler gets the same type, with its extras looked up by name.
  • Clears the unknowns on paper, but side still has no type. That's HTML's problem turned inside out, and Rust would need Value at each lookup.
  • A new phase in this epic, after the type knowledge moves to the shared base. It helps TypeScript and Python at once, so it's worth doing even if Rust stops at FizzBuzz.
  • That makes about 6 phases. You can defer it at Accept Phases, since FizzBuzz itself has no events.
  • Spell source doesn't change. Only compiled code gets types.
