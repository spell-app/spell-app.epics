JavaScript runs a top-level step that waits beside the next step, while Python finishes it first. So a top-level close the door whose event can be canceled, followed by a print, prints in a different order. This was so before sending was added.

  • The new test project wraps its steps in one function, so it doesn't hit this.
  • A property's change is heard at the next wait, so its exact place can differ in the same case.
  • Worth a look before Rust adopts either behaviour.
