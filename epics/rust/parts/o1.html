A Rust target would turn a Spell program into a small Rust project that a person could read, and that prints exactly what the JavaScript prints.

  • You'd type spell run fizzbuzz --target rs and see the same lines, after a compile.
  • It would sit beside the other targets, named rs to match js, ts and py. It would be a Cargo project, Rust's normal build tool.
  • Its model is Python, the only target with a runtime of its own. There is no WebAssembly target yet: that epic has made decisions and written no code, so it offers ideas but nothing to reuse. 
// Spell:   its "rank" is one of ace, 2 ... 10, jack, queen, king
//            it "is a (rank)"

// Python, from Solitaire's snapshot:
//   RANKS = ("ace", 2, 3, 4, 5, 6, 7, 8, 9, 10, "jack", "queen", "king")
//   rank = prop(one_of=RANKS)
//   def is_a_rank(self, rank: Any) -> bool:
//       return self.rank == rank

// Rust:
#[derive(Clone, Copy, PartialEq)]
pub enum Rank { Ace, N2, N3, N4, N5, N6, N7, N8, N9, N10, Jack, Queen, King }

impl Card {
    pub fn is_a_rank(&self, rank: Rank) -> bool {
        self.rank() == rank
    }
}

What this means, and what it doesn't:

  • Rust is the output. It doesn't rewrite Spell's compiler in Rust, which would be a different epic.
  • No browser at first. Drawing starts as HTML text with no browser, as Python's did. A web app is left for later.
  • Rust compiled to WebAssembly could be a later variant. It wouldn't replace the WebAssembly epic's plan, which writes WebAssembly directly.
