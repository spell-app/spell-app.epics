Spell's things point at each other: a card knows its pile, and the pile knows its cards. Rust wants one owner per value, so compiled programs need a way around that. Every line of compiled code shows the choice. 

// A:  shared pointers, with a check at run time
let pile = card.borrow().pile.upgrade().unwrap();
if Rc::ptr_eq(&pile, &solitaire.borrow().stock) { ... }

// B:  a handle is a small id into one store of things
if card.pile() == solitaire.stock() { ... }
  • What most people meet first, with no extra machinery.
  • Noisy at every read, and needs "weak" pointers for owners so memory is ever freed.
  • Reading a thing while it's being changed crashes at run time, and Spell programs can easily do that. So can holding one across a wait.
  • Each thing is a small copyable id, and the runtime holds the things. Spell's saving and references already work by id (Tableau#1).
  • The cleanest compiled code, and no borrow crashes, since nothing stays borrowed.
  • The store is hidden state, which is less "pure" Rust. Things are freed only when the program ends, or by a clean-up we'd add.
  • Closest to how JavaScript and Python behave.
  • A new dependency, in a corner of Rust with no settled standard. Reads unlike most Rust.
  • The hand-written card and pile are tried this way first, and with A beside it if B reads badly.
  • The runtime gets a store of things.
  • Compiled Rust reads close to compiled Python.
