Four things Spell does freely are hard in Rust, the first by far the hardest.

Things that point at each other

  • A card knows its pile, and the pile knows its cards. Compiled programs freely read self.pile == solitaire.stock.
  • Rust wants each value to have one owner, so nearly every program would be fighting that rule.
  • So each thing is a small id, and the runtime keeps the things in one store. Nothing stays borrowed, so reading a thing while it's changing can't crash. The hand-written card and pile try this in real Rust first.

Types the compiler doesn't know

  • Python can say "any type" and run anyway. Solitaire's Python mentions Any on 23 of its 1133 lines.
  • Rust needs a type for everything, and some of what the compiler does know is locked inside the TypeScript writer. Solitaire's TypeScript has only 13 unknowns, 12 of them the event a handler is given. Its is_a_rank already knows its argument is a Rank, where Python writes Any.
  • So that knowledge moves to the shared base, which also helps every other target. What's still unknown is a question: Q3.

Waiting

  • Rust's standard library has no way to run code that waits, unlike Python's. So the Rust runtime uses tokio, the library most Rust programs use, on a single thread. It's the one outside dependency, and compiled programs say only async and .await.
  • Holding a borrowed value across a wait would crash at run time, and handles avoid that: nothing stays borrowed.

Build time

  • Python runs at once; every Rust run is a compile first. The contract test allows 60 seconds a program, across 30 programs.
  • A shared build folder and a prebuilt runtime should help, but nobody has measured it. It's the first thing to measure, with tokio in the build, since it slows every first compile.
