spell-epic's six pages: the method and the tool, for a developer who runs a project with an AI pair and wants the plan, the work and the review in one place. Claude Code only today. Facts: research/explore-4-ui-brand-epic.md C and D; explore-5-app-dev-wiki.md E.

README.md: epics and sagas

  • Lead: spell-epic is a way of building software with a coding agent where the plan is a living page: you ask for an epic, the agent plans it on the page, builds it phase by phase in its own worktree, and you review on the page itself, in VS Code, while it works. A Claude Code plugin today (Q10: other agents coming).
  • Second paragraph: how it changes your workflow, and what you get (the owner's M26): you stop reading chat scrollback and start reading a page that stays true; every question comes with its options and a recommendation, so you decide from the page alone; judgement calls the agent made without you are listed for you to approve or revisit, in one colour scheme; review happens when you have time, not when the agent asks; the agent's work is isolated in a worktree and window of its own, so three epics can run at once; each epic ends with a guide and a changelog entry, so the project remembers why. The benefits in one table: for you, for the agent, for the project.
  • HERO PICTURE: an epic's life: the nine steps from explore-4 D.2 (name → worktree and window → plan → the page fills → phases, each committed → review rounds any time → doc review and the guide → merge). Caption: "The page is the memory: every decision, call, issue and test lives there."
  • The words: epic, saga (an epic of epics), epic page, phase, the item kinds (question, judgement call, caveat, todo, issue, test) with their ids; one table.
  • What the pages do: review marks (Approve, Revisit with a note, Make Todo, Do Now), picks on option cards, Send and Review Now, comments and bullhorns on any block of any docs page, threads, test runs, requests between epics, the colours (one meaning each); each a line, linking README-pages.
  • In VS Code: the Review tab and Epic Docs, windows per epic with a look, the Claude session titled for its epic; link to README-vscode.
  • Built from Spell UI and Epic UI: the pages are plain HTML on `ui-*` elements plus the `epic-*` pack; a page holds data and prose, the elements draw; the tool writes the same markup through the same definitions.
  • Beyond Spell: what it takes to adopt it (four commands, a config file, a content folder, the extension), and the honest label: it ran once outside Spell; rough edges listed on README-adopting.
  • The commands: `epic` in one paragraph and a link to README-cli; the skills in one line and a link to README-skills.
  • Working on it: the layout (`src/`, `skills/`, `hooks/`, `templates/`, `vscode/`, `bin/epic`), the checks, "an edit is live at once; a skill's text after `/reload-plugins`".
  • Expands: the page kinds (epic page, saga page, details page, choice page, guide, home page); standing, future, bedtime and airplane modes, one line each; the history (lifted out of spell-app in October).
  • Sources: explore-4 C.1, C.2, D.2; today's README (its install and config sections move to README-adopting; its "switching over" and "not run yet" sections are history and go).

README-cli.md: the `epic` command

  • Lead: `epic` edits the one shared epic page from any checkout, runs the review inbox, and drives worktrees, windows and the servers; no build step, on every session's PATH while the plugin is on.
  • Addressing: `<epic>#<id>` and the short saga address.
  • The groups, one table each from explore-4 C.3 (requests; making and reading pages; phases; items; the inbox; log and upkeep; sagas; worktrees, sessions, parked work; shared content; windows and servers; settings; answer pages, agents, airplane). Every row's description clear by itself.
  • Old spellings: `spell dev plan-doc ...`, `spell epic ...`, still run.
  • Expands: the cheat sheet from the epic skill, verbatim; exit codes.
  • Sources: explore-4 C.3; `epic --help`; the epic skill's cheat sheet.
