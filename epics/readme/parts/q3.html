The brief wants the READMEs densely linked, and the deepest explanations of Spell live in the guides and epic pages of the content folder, spell.epics. That folder is a local git repo: nothing clones it, it isn't on GitHub, and a reader on GitHub (or a fresh checkout) can't follow a link into it.

  • What's there: about 40 guides (the page server, custom elements, rulex, markdown, Solid 2, the targets ...), every epic page, the sagas, the three logs, WWOD's copy, the brand pages.
  • What a README can link today without a dead end: files in the six repos, and GitHub itself.
  • The six repos are public on GitHub (checked 2026-10-21: spell-kit, spell-lang, spell-ui, spell-brand, spell-epic, spell-app).
  • Every README explains its subject fully enough on its own, with its own pictures.
  • At the end of a page, an expand "More in the docs site" names the guides by title with their served path (/guides/rulex/rulex.html) and says in one line that the docs site needs a checkout with the content folder and the page server running.
  • No dead links on GitHub; a developer with the full setup still finds everything.
  • Simplest to write; works in VS Code for people who have the content folder.
  • Cost: every such link is dead on GitHub and in a fresh checkout; the link checker in P8 would have to skip them.
  • The richest result: READMEs link straight into the guides and epic pages.
  • Cost: the content repo holds every epic page, review inboxes, window files and personal notes; publishing it is a decision bigger than this epic, and its pages only render through the page server anyway.
  • The writers' brief (1.2) gets the rule: "no relative link into spell.epics; guides go in the 'More in the docs site' expand, by served path".
  • The P8 link checker treats any link into the content folder as an error.
