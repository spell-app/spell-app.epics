In a type's body, a bare line like - score is 0 is the type's getter, not a variable. Before P9 the same line set a variable beside the class.

  • How: a getter with its subject left out gets declaration priority once its body parsed, so it outranks setting a variable, which reads the same words.
  • "Once its body parsed": - color is red if ... otherwise it is black is still the either-getter's, not a getter of the words red if ....
  • Unchanged elsewhere:
    • inside a getter or method in the body, total is 2 still sets a local
    • at the top level, score is 0 still sets a variable
    • in a body, a variable is set with - set x to 1
  • This is what P9's plan asked for (the bare-name decision in T8, option A).
  • - score is 0 in a body compiles to get score() { return 0 } on the class, and warns
  • a test pins it: "a bare name with a value is a getter, not a variable, and warns"
