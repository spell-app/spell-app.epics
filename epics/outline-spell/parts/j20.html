The "always the same" warning fires only when a getter's body is a plain value: a number, text, or yes / no. P9's plan said "a getter that never reads it warns", which is wider.

  • What warns:
    • - score is 0: score is always 0: to give it a type, write "score is a number"
    • - label is "card": label is always "card": to give it a type, write "label is text"
    • its score is 0 too: any getter in an outline body, not only bare names
  • What doesn't: - total is 1 + 2, or - name is the name of the game. They never read it either, but may well be meant.
  • Why narrower: a plain value is the one case that's almost surely a type written wrong. "Never reads it" would also flag constants and getters that read other things.
  • Only in an outline body: the sentence style, the score of a card is 0, doesn't warn.
  • a getter that's just a number, text or yes / no warns, in an outline body only
  • other getters that never read it don't warn
