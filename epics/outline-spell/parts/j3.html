In P1 · Bullets And Bodies, quotes around a NEW name ("quotes teach a new word") were made to work in exactly two places: a type's name in the line that declares it, with or without a body, and a property's name after its, inside an outline body. You'd notice it when a quoted name works in one line and gives "Don't understand" in another.

  • In short: a "card" is a thing works with or without a body; its "suit" is ... works only inside one.
  • "Outline body": the indented, bulleted lines under a type's heading, e.g. under a card is a thing where:, where it / its mean a card.
  • "Sentence style": today's way, one fact per line, each naming its type again: a card has a suit as one of ....
  • Every line below was run through the parser on this branch (2026-10-06), in a throwaway test, since deleted.

Why it went this way

  • Your rule (from Q3, curly quotes): "something in quotes means I'm teaching you new language". A type's declaration is always where its word is taught, body or not, so a quoted type name means the same thing in both.
    • It also lets you write the quotes first and add the body later, without the line breaking in between.
  • A quoted property name needs a word in front saying WHOSE property it is. In the outline that word is its, and its means the type only in a body (subject_its in types.ts, which looks for the body's P.SubjectScope). At the top level there's no type for its to mean.
  • The sentence style already frames a property's name with fixed words: a card has ... as, the ... of a card is. The words in between are read up to as / of, so quotes there would tell a reader nothing new.
  • Smallest change: only the rules the outline needs got a quoted form.

The other ways it could have gone

  • quoted type names in every a ... is a ... declaration, body or not
  • quoted property names only as its "x", in a body
  • why recommended: quotes mean "a new word" wherever a word is taught, and nothing else changes
  • cost: each type declaration tries 4 syntaxes (with or without a body, quoted or not): part of P1's +5% on the speed test (caveat C5)
  • a "card" is a thing where: works; a "card" is a thing alone is an error
  • gain: quotes would mean "outline style" and nothing else; 1 fewer syntax per type rule
  • cost: an error while you're typing a heading whose body isn't written yet; a test in outline.test.ts ("a list type's body, a quoted type name ...") changes
  • a card has a "suit" as one of ..., the "short name" of a card is: ...
  • takes: a {property:quoted_member} syntax beside each {property:member_words} one: define_property_has (a card has, cards have), the_property_of_a_thing (feeds property_value_either), property_value_getter's the "x" of a card is. About 4 more registrations, their tests, the ui highlighter bundle rebuilt
  • collides with nothing found: today those lines are just "Don't understand"
  • cost: one more syntax tried on every sentence-style property line; two spellings for the same line

What a declaration shows

The editor's outline (its symbol list) and the Type Explorer name things WITHOUT their quotes: card, suit.

  • Both ask the line's rule getDeclaration(match), which names the thing with declaredText() (packages/parser/src/rules/Rule.ts).
  • The default is the source text. quoted_type and quoted_member override it to give the name without quotes; subject_it / subject_its override it to give the type, card, never it.

What a quoted name may hold

  • A type: ONE word, starting with a letter, then letters, digits, _ or -, and not a reserved word. The same word an unquoted a card is takes. The unit tests on quoted_type (in types.ts):
    • "card" is Card
    • "bank-account" is Bank_Account
    • "playing card" is refused: two words
    • "if" is refused: a reserved word
  • A property: the words a property name takes without quotes (member_words), EVERY word inside the quotes. No structural word (of, the, is, as ...), except that the FIRST word may be one of with, for, from, in, on, by, at, into. The unit tests on quoted_member (in properties.ts):
    • "rank" is rank
    • "short rank" is short_rank
    • "short-rank" is short_rank too
    • "with jokers" is with_jokers
    • "rank of" is refused: of is structural
  • So its "short rank" and a card has a short rank name the same property. One difference: unquoted words just stop at a structural word (jokers with reads as jokers), while a quoted name is refused whole. 
// types.ts:  quoted_type
const QUOTED_TYPE_NAME = /^[A-Za-z][\w-]*$/
const name = token.innerText
if (!QUOTED_TYPE_NAME.test(name) || blacklist?.[name.toLowerCase()]) return undefined

Found while checking (2026-10-06)

  1. A quoted type isn't known to the lines ABOVE it, so "works like the unquoted line" isn't fully true yet.
    • a deck "is good" if it is a card, above a "card" is a thing: "Don't understand is a card". Without the quotes it works.
    • Why: before a project parses, a quick scan finds every type it declares, so a line can name a type declared further down. The scan is a pattern, SpellParser.TYPE_DECLARATION, and it doesn't allow a quote: an?[ \t]+([\w-]+)[ \t]+is\b.
    • Not hit by a pile is a list of cards above a "card" is a thing: that slot takes any type word. It shows wherever a line needs a KNOWN type, like is a card.
    • Fix: let the pattern take an optional quote on each side of the name. Small; not done.
  2. its "short rank" is text fails, though a card has a short rank as text works: the two styles don't mean the same yet (Q1, both styles with the same meaning).
    • The outline's specifier, outline_specifier_datatype, needs the article: (a|an) {datatype:singular_type}. The sentence style's makes it optional: as (a|an)? {datatype:singular_type}.
    • Without the article, text is read as the value of a getter: a junk get short_rank() {} and an error.
    • Likely why: after is, a bare word can be a value (its "color" is red), so the article tells a type from a value. P2 · Value Types already reworks what follows is (is up or down without either), so it fits there.
  3. Not about quotes, but the sketch's first line won't parse as written: A “card” is a two sided thing.
    • A capital A fails, quoted or not: A card is a thing is "Don't understand".
    • Curly quotes aren't quotes yet: Q3's answer deferred them out of this epic.
  • a "deck" is a list of cards compiles as a deck is a list of cards; the same for a "card" is a thing, with or without a body
  • create a type called "hand" ... stays unquoted only
  • quoted property names: only its "x" ... in a body; the sentence style stays unquoted (a card has a suit as ...)
  • the editor's outline and the Type Explorer show names without quotes: card, short rank
  • P2 (todo T3) adds unquoted its rank is a number in a body, so quotes become optional there
  • two gaps to fix, not done: the type scan should see a "card" is, and its "x" is text should work like as text
