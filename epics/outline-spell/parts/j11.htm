How I read it. There are two kinds of phrase, and they collide in different ways. J11's text described the bug with a placeholder phrase (a card's is (color)), but what P5 actually hit was a literal one (is a face card). You're asking whether the owner check covers both kinds, and what is different about each.

  • "Literal phrase": fixed words, one method, e.g. - it "is face up" if its direction is up. Its rule matches those words and nothing else.
  • "Placeholder phrase": a phrase with a slot filled from a list of values, e.g. - it "is a (suit)", or - it "is a suit" in the outline Solitaire, where spell works out the slot itself.
  • "Embed": the placeholder's rule spells out every value in the list, so is a (suit) becomes is (a|an) (club|diamond|heart|spade).
  • Every line below was run through the parser on this branch (2026-10-06, at 6adf06e1), in a throwaway test since deleted. The rule shapes come from the SPELL: DECLARES comments in the compiled output.

What each phrase's rule matches

The phrase Its rule (syntax) What it matches
a card's it "is face up" if ... {operator:is} face up, rule method_postfix, of Card only is face up / isn't face up
a rank's a rank "is a face card" if ... (Deck.spell) {operator:is} a face card, of Rank the SAME words for both owners. Only the owner can tell them apart: this was P5's collision

the same, the deck's suits declared BELOW (a "kind declared further down", P3) {operator:is} (a|an) (expression:{constant}|{number}), with kinds: { suit: "Suit" } and values: { suit: [] } any known value or number while parsing; then checked against the suits where the phrase is USED (kindValue()): the card is a red is refused

The owner check covers both kinds

  • Both rules start with the same line: a literal phrase is a MethodPostfixRule (or MethodInfixRule), a placeholder phrase a QuotedPropertyRule, and each one refuses an operand KNOWN not to be its owner (thisType).
  • For a literal phrase, the owner is the only thing that can tell two phrases apart. For a placeholder phrase, the values filter first, and the owner matters when two kinds share a value (red as a color and as a team).
methods.ts, classes.ts, expressions.ts · the owner check · 12 lines 
// MethodPostfixRule.parse() and MethodInfixRule.parse(), methods.ts:  a literal phrase
if (!SuffixLeft.couldBeA(scope, this.thisType)) return undefined

// QuotedPropertyRule.parse(), classes.ts:  a placeholder phrase
if (!SuffixLeft.couldBeA(scope, this.thisType)) return undefined

// SuffixLeft, expressions.ts:  set by compound_expression for the FIRST suffix after an operand only
couldBeA(scope: P.Scope, type: P.Datatype | undefined): boolean {
  return !SuffixLeft.current || scope.couldBeA(SuffixLeft.current.datatype, type)
}
