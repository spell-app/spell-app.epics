A drop is an event the program answers, not a move the page makes on its own (P28, Dragging Cards).

  • When a card is dropped on a pile, the program hears card drop, with the card and the pile: 
    on card drop with a card and a pile
  put the card on the pile
  • So the game's own rules run on a drop, just as on a click: its scoring, and turning the tableau's next card up.
  • A program with no handler still works: the page moves the card there itself, by the lists' own rules (core.move()).
  • The other way, the page moving cards by itself, would have skipped the game's score and turn-over.

Later the same day (J48, J49):

  • only what the program says can be dragged drags
  • Solitaire answers a drop in the pile's own body, - when a card is dropped on it: put the card on it, which takes the place of the event
  • Any drawable thing a list will give up can be dragged; the program decides what a drop does.
  • Solitaire and Solitario answer it with put the card on the pile.
