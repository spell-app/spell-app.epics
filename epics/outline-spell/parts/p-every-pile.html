The Solitaire keeps a list of its own, all-piles, and adds each pile to it by hand as it's made, only so its state, its deal and a card's play can go through every pile.

A new expression, every pile, is every pile the program has made, of any kind, in the order made. The Solitaire's all-piles goes.

Owen, 2026-10-19: "do we need all-piles, or is there a way we can get the list of piles created at runtime without it?" He picked a new expression, every pile, read from core's registry of things.

  • every pile is a list of every pile the running program has made.
    • sub-types too: every stock pile, discard pile, foundation and tableau
    • in the order they were made
    • made fresh each time it's read, so a pile made later is in the next read
  • It's typed as a list of piles, so the editor knows each item is a pile: hover, completions, and the usual warning for a member a pile doesn't have.
  • A test's own things aren't in it: a pile a to test ... method makes isn't one of the program's piles.
  • In the Solitaire, before and after: 
    // before:  every pile added by hand
set all-piles to a new list of piles
set the stock to a new stock pile with name = "stock", droppable = no
add the stock to all-piles
...
	for each pile in all-piles
		add the state of the pile to state

// after:  no list to keep
	for each pile in every pile
		add the state of the pile to state
