Found answering T8. In a loop over a value kind's list, such as the deck's ranks, each item has no type. So reading a member it doesn't have is neither an error nor a warning, and gives nothing when it runs.

  • e.g. in the deck's to set up a deck, for each rank in its ranks, then for each suit in its suits inside it
    • inside the first loop its is the rank, so its suits compiles to rank.suits
    • the inner loop never runs, the deck stays empty, and the deck test fails with no message saying why
  • the same loop over a typed list warns: for each card in it, then its zork, says "A card never says it has a zork"
  • likely fix: a value kind's list (the deck's ranks) is a list of that kind (ranks), so the loop's item has a type and the usual warning fires
