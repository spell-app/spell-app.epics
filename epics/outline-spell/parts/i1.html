The scan that finds a project's types before it parses doesn't allow quotes, so a "card" is a thing isn't found ahead. Found while writing J3's details (2026-10-06).

  • the scan, SpellParser.TYPE_DECLARATION, is what lets a line name a type declared further down
  • fails: it is a card on a line ABOVE a "card" is a thing: "Don't understand"
  • works: the same with a card is a thing
  • fix: let the scan's pattern take "card" (and 'card'); one regex, plus a test
  • a quoted type name behaves exactly like an unquoted one, wherever it's used
