A re-opened type's bullets compile exactly as the same lines in the sentence style would. The a game: line itself compiles to nothing: it has no class of its own.

  • So in the same file, a game: + - score is a number gives the same JavaScript as a game has a score as a number there.
  • In a later file of the project, it gives the same JavaScript as a game has a score as a number in that file: it adds onto the game's class the way a sentence there already does.
  • The tests compare the two outputs, line for line, in the same file and across two files.
  • Why: the type is declared once, where it's declared. A second class, even an empty one, is what broke the program in the declared-twice issue (I13).
  • The other way, collecting the bullets into the first declaration's class, would have needed the second file to reach back into the first one's output. The sentence style already solves "add to a type from elsewhere", so the outline style reuses it. 
a game is an app
a game:
	- score is a number
	- state is: its score * 2
// compiles as:
a game has a score as a number
the state of a game is: its score * 2
  • a game: adds no class; its bullets land in the game's class wherever the game was declared
  • nothing new to learn about where the code goes: it's where the sentence style's goes
