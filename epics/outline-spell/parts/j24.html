Declaring a type a second time is an error on the second line, in the same file or in another file of the project. The message names where the first one is, and says how to add to it.

  • Same file: There's a game already, on line 1: to add to it, write "a game:"
  • Another file: There's a game already, on line 1 of /Game.spell: to add to it, write "a game:"
  • It uses the line's own article: an account is a thing twice says There's an account already.
  • It's checked after the existing short-name checks (a name another type goes by), so those messages win when both apply.
  • Not refused: a type only mentioned before it's declared, an imported type, a built-in type (a list, an app ...), or the editor re-reading the same line.
  • Why across files too: JavaScript refuses two classes of one name wherever they are, so a project with the game declared in two files never loads (I13).
  • I13 is fixed: the second a game is an app is red, naming the first
  • the message's wording is the one above; changing it is one line, and the tests that quote it
