In a type's body, a bare name can't be one of the 23 words a spell statement starts with. Those lines stay the statement, so a property with one of those names keeps its quotes. You may well want - type is ... to work as a property.

  • Why a guard at all: without it, - return x is 1 in a body would read as a getter named return x.
  • Where the words come from: the statement rules themselves, each one's first fixed word, worked out once per statement rule (BodyMemberWords).
    • so a statement added later guards its own word, with no list to keep up
    • but it also takes words that make good property names, because some statement starts with them
  • it and its are refused too: - its rank is ... names its subject, and the property is rank. 
return  print  set  draw  add  move  type  wait  expect  start  stop  on
to  for  repeat  each  get  let  create  remove  alert  notify  test
 
a card is a thing where:
	- return x is 1               // a return, as before
	- set x to 1                  // sets the variable x
	- type is one of a or b       // NOT a property:  "Don't understand"
	- "type" is one of a or b     // a property, with its quotes
  • safe and automatic: no statement is ever read as a property
  • cost: type, start, stop, test, each, get need quotes
  • - type is text becomes a property, since it isn't a valid type statement
  • cost: a line that's a broken statement turns quietly into a property instead of an error
  • cost: each refused word means a second parse: slower (the parser-speed caveat, C5)
  • e.g. type, start, stop, test: allowed as bare names when followed by is / are
  • cost: a hand-kept list beside the automatic one
  • no change: a property named after a statement word keeps its quotes, - "type" is ...
  • the outline guide says so, in "Leaving out it / its"
