In a type's body, a bare name can't be one of the 23 words a spell statement starts with.

  • those lines stay the statement, so a property with one of those names keeps its quotes
  • you may well want - type is ... to work as a property
  • Why a guard at all: without it, - return x is 1 in a body would read as a getter named return x.
  • Where the words come from: the statement rules themselves, each one's first fixed word, worked out once per statement rule (BodyMemberWords).
    • so a statement added later guards its own word, with no list to keep up
    • but it also takes words that make good property names, because some statement starts with them
  • it and its are refused too: - its rank is ... names its subject, and the property is rank. 
return  print  set  draw  add  move  type  wait  expect  start  stop  on
to  for  repeat  each  get  let  create  remove  alert  notify  test
 
a card is a thing where:
	- return x is 1               // a return, as before
	- set x to 1                  // sets the variable x
	- type is one of a or b       // NOT a property:  "Don't understand"
	- "type" is one of a or b     // a property, with its quotes
  • safe and automatic: no statement is ever read as a property
  • cost: type, start, stop, test, each, get need quotes
  • - type is text becomes a property, since it isn't a valid type statement
  • cost: a line that's a broken statement turns quietly into a property instead of an error
  • cost: each refused word means a second parse: slower (the parser-speed caveat, C5)
  • e.g. type, start, stop, test: allowed as bare names when followed by is / are
  • cost: a hand-kept list beside the automatic one
  • no change: a property named after a statement word keeps its quotes, - "type" is ...
  • the outline guide says so, in "Leaving out it / its"

How does this relate to identifier blacklist?

They're separate lists, guarding different things, and they overlap in only five words.

  • The identifier blacklist: about 100 words, kept by hand, that can never be a ONE-word name of a variable, a type or a constant, anywhere.
    • verbs (is, has, repeat), control words (if, while), yes / no, the, prepositions, number words, ordinals
    • its job: if or the is never read as a variable
  • A property's name (member_words) never used the blacklist on purpose: short and long are fine property names. It stops at structural words instead (of, is, if ...).
  • The 23 statement words (P9's body_member_words): only for a bare name STARTING a line of a type's outline body.
    • its job: - return x is 1 stays a return, not a property called "return x"
    • worked out from the statements themselves, so a statement added later guards its word too
  • The overlap: repeat, each, for, on, to are in both. The other 18 (type, start, stop, return, print, set ...) are fine variable names today, and fine property names anywhere else, e.g. its type is ... or a card has a type as text. 
identifier blacklist   ~100 words, by hand     a one-word variable / type / constant name, anywhere
member stop words      ~30 words, by hand      where a property's name ends:  of, is, if, the ...
statement words        23 words, worked out    a bare name starting a line of an outline body
overlap (blacklist ∩ statement words):  repeat, each, for, on, to
  • A, as you picked: the guard stays its own list, and only an outline body's bare names feel it
  • the blacklist doesn't change, and nothing outside an outline body does
  • - "type" is one of ... (quotes) or - its type is one of ... both still work
