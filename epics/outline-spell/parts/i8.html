A card's own phrase, e.g. it "is (color)", wins over a plain comparison on one of the card's properties. The program compiles with no error, and crashes when it runs.

  • the line: set b to the team of the card is red
  • compiles to: card.team.isColor("red"), a card's method called on the text "blue"
  • runs: TypeError: card.team.isColor is not a function (spell run on a scratch project)
  • the same in the sentence style, and with its team is red inside a method
  • why: the phrase refuses only a thing KNOWN to be another type (SuffixLeft.couldBeA() in expressions.shared.ts); a property with a list of values (is red or blue) has no type the scope knows, so it "could be" a card
  • matters for C2's quick fix: the team of the card is red is the long form it would write
