In a type's outline body, - its clubs is a new foundation with ... didn't parse: only the long form gave a property its starting value.

Such a body line gives the property its starting value, compiled as the long form is; and with name T1 means name = "T1".

  • Each new thing gets its own starting value, made with the thing, before its create(); a new list is still made on its first read.
  • The property's type is the new thing's, a foundation, not "New".
  • A bare capitalized name after a property's name is its value as text: - its T1 is a new tableau with name T1.
  • Python compiles it the same way.

Fixed 2026-10-20, found while rewriting the outline Solitaire (P24): a starting value was made LAZILY, on its first read, not when its thing was made.

  • So the solitaire's piles didn't exist until something read them, and every pile missed them.
  • That went against this phase's own goal: "made for each new solitaire, as the long form's is".

Now:

  • A starting value that's a THING is made with its thing, before its create() (spell's to set up).
    • unless the props it was made with gave one
  • A new LIST, as a new list of tasks, is still made on its first read: a saved thing never gets an empty list.
  • Compiled, a thing's starting value says so, the long form's too:
    • javascript and TypeScript: { init: () => new Foundation({...}), early: true }
    • Python: prop(init=lambda: Foundation(...), early=True)
  • How:
    • PropInfo.early and Schema.earlyProps(): which properties are made with the thing
    • Thing's constructor makes them, before create()
    • ProgramWriter.madeEarly() writes early for a new thing, not for a new list
    • Python: prop(early=) and SpellObject.__init__
