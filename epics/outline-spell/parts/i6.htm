Revisit (2026-10-06): should a phrase with no body mean "always true"?

Your note: - it "can move" could be read as get can_move() { return true }, "nice magic, but might be surprising". A phrase with nothing after it would then be a fact about every card.

What I found while checking: spell can already say this, out loud, with one word.

Line Today, on this branch
- it "can move" always get can_move() { return true }, no error
- it "can move" never get can_move() { return false }, no error
- it "can move": yes get can_move() { return true }, no error
- it "can move" an error: "can move" has no body: write "can move" if ..., or end it with ":" and ...

always and never are spell's words for yes and no, so they read as the phrase's body. No new grammar is needed.

The ways to go

A · Keep the error, and point to always (recommended)
  • a phrase with nothing after it stays an error
  • its message offers always first: "can move" has no body: write "can move" always, or "can move" if ...
  • gain: the "always true" fact is one word away, and you can see it on the line
  • gain: a forgotten if ... is still caught, not silently always true
  • cost: a one-line change to the message, plus its tests
a joker is a card where:
	- it "is wild" always
 B · Nothing after it means always true
  • - it "can move" compiles to get can_move() { return true }
  • gain: the shortest way to state a fact about every card
  • cost: a line where you forgot the if ... (or it went onto the next line by mistake) is always true, with no error. That's the kind of silent wrong answer J9 and I6 just removed.
  • cost: the hover's Reads as would have to say "always", so you could spot it
a joker is a card where:
	- it "is wild"

Net effect (A, recommended):

  • - it "can move" always is how to say a phrase is true for every one of the type; it already works
  • - it "can move" on its own stays an error, and the error names always first
  • nothing else changes
