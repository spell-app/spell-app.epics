With the kinds of pile moved to the end of Solitaire.spell, the table above them makes a new stock pile before the stock pile's class exists, so the program stops as it loads; and a two-word name like stock pile wasn't read as a type at all.

The compiler moves a file's classes above its first running code, so a file can put its types last. A type's name may be several words, a stock pile is a pile, and a method on it compiles inside its class.

Owen, 2026-10-19, asked how the table can make piles declared below it: "Hoist classes. Move the set the stock lines to properties of the solitaire class" (the second half is P18's).

  • A file can declare its types at the end and use them above, as it loads.
    • e.g. Solitaire.spell's table says set the stock to a new stock pile ..., and the kinds of pile come last, under "The piles"
    • in the compiled JavaScript, each class moves up above the file's first running code, in its own order
    • banners, headings and the code under them stay where they are, so the Thing Explorer's headings still fit
  • A type's name may be several words:
    • a stock pile is a pile
    • a bank account aka account is a thing
    • read as one name only before is a, is an or aka
  • A method on such a type, - to draw a stock pile:, is the stock pile's own method, compiled inside its class.
