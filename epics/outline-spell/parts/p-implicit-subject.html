In a type's outline body every bullet must start with it or its.

  • - "suit" is a suit of its deck is "Don't understand"
  • - "is face up" if its direction is up compiles, with no error, to a stray return outside the class

Each line that starts with it or its gets a twin without them.

  • first, the stray-return misreading is fixed (I9)
  • the 12 twins match only directly in a type's body, when the line starts with a quoted name or a verb
  • the list guards (can take, can give up) get body forms too
  • In a type's body, these work without it / its, and compile exactly as their it / its forms do (T8, option A of its first reply):
    • a quoted name:
      • - "suit" is a suit of its deck
      • - "short name" is: its rank
    • a phrase:
      • - "is a (suit)"
      • - "is face up" if its direction is up
    • a verb first:
      • - has a name as text
      • - belongs to a pile
      • - is saved inline
  • The guards, which have no it form today, work in a body:
    • - can take a card if: ...
    • - can give up a card if: ...
    • - can never let go of a card
  • it / its keep working: both styles give the same output.
  • Outside a body nothing changes: "suit" is ... at the top level stays an error.
  • A value if condition line outside a getter's body is an error, not a return at the file's top level (I9).
  • The hover's "Reads as" line puts the subject back: - "suit" is a suit reads as the "suit" of a card is a suit.
  • The property-shape decision (Q4) moves from "always its" to "its optional".
  • Folded in, since this phase works on the same getter lines: the colour-style getter (red if ... otherwise it is black) written once, on the value_if lines (T6).
