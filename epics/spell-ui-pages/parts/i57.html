Fomantic lets a theme brand checked checkboxes with variables alone. Ours paints the checked box through private variables, so a theme can't.

  • Fomantic's example: the theming page, Component Defaults. In checkbox.variables:
    • @checkboxActiveBackground: @primaryColor
    • @checkboxActiveBorderColor
    • @radioActiveBorderColor
    • @radioActiveBulletColor
  • Ours paints the checked box's background, border and mark through PRIVATE switches. 
    --_checkbox-background, --_checkbox-border, --_checkbox-mark
    • only the mark's colour, the slider's line and the toggle's lane have public tokens
    • the colored theme reaches the rest with class-grammar overrides
  • What the page does instead: theming.html's Component defaults playground offers:
    • --ui-checkbox-mark-color
    • -border-color
    • -radius
    • -toggle-lane-on
    • -slider-line-on
  • The fix: public --ui-checkbox-background-selected / -border-color-selected (plus the radio bullet), read through aliases.
  • color= on a single element already works.
  • once fixed: a theme can brand checked checkboxes with tokens, and the playground offers them
