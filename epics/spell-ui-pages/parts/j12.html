stack-with reuses the mechanism tables already use, proven to work, rather than a new host state.

  • The pieces:
    • a private class on the element's root: stack-with-page or stack-with-container
    • an inherited token, --ui-stack-with, read with @container style()
    • the rules on the root written four times: (@container or @media) times (token or class), each copy guarded so exactly one of them matches
  • Parts read a flag the root works out once:
    • --_grid-range
    • --_items-narrow
    • --_ui-form-stack-with
  • <ui-root stack-with> writes the token into its own constructed sheet (RootBox, beside --ui-scale), not as a state either.
  • The other option: a host :state() switch. It would have halved the duplication, but WebKit leaves viewport media queries stale there (agents/PAPERCUTS.md, 2026-10-01).

Net effect:

  • each stacking rule exists in four guarded copies in the sheets
  • the layout updates correctly in WebKit when the window is resized
