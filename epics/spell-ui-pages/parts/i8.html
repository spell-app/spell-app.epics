<ui-header href level> renders a link with a heading role, which axe (the accessibility checker) reports as aria-allowed-role.

  • The markup it renders: <a role="heading" aria-level> (UIHeader.tsx). That's deliberate: the link carries the class grammar.
  • Where it bit: <ui-docs-api family>'s tag headers link to themselves (e.g. #ui-or).
  • What was done instead: <ui-header level dividing><a href="#ui-or">...</a></ui-header>, plus two lines in its sheet keeping the link in the header colour.
  • The fix: a header with both a link and a level draws a real heading around its link (<hN class="ui header"><a>). Not a 15-minute local fix, since it touches:
    • ui-parts.css's a.ui.header rules
    • the tests
    • the visual baselines
  • once fixed: a linked header is a real heading holding a link, and passes axe
