Tables already had a way to choose what they stack by, so they kept it instead of getting a second attribute that means the same thing.

  • Unchanged: <ui-table stack-by="viewport|container"> and the token --ui-table-stack-by, viewport by default (as Fomantic).
  • New: a table with no stack-by falls back to the page-wide --ui-stack-with (page ~== viewport).
  • <ui-docs-tokens> no longer hard-codes stack-by="container". Its host sets: The host's rule · 1 line 
    --ui-table-stack-by: var(--ui-stack-with, container);
     so its tables stay container-based unless the page says page.
  • That fixed the tokens tables issue (I58) on the site.
  • The other option: a stack-with attribute on tables too.

Net effect:

  • tables follow --ui-stack-with only when they have no stack-by
