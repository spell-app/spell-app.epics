Every epic page is drawn by Solid web components from the spell-epic package (the epics package then, its own repo since epic-eject) (<epic-page>, <epic-item> and 23 more), loaded by Spell UI's root element as a component pack, so a doc holds only its data and prose. The plan-doc tool is TypeScript in that package, and all 29 docs moved over (P12, P14), with one colour scheme, status cards for the review loop, and a guide with a page per element.

Plan docs (epic pages) as Solid web components, instead of HTML that carries its own layout:

- no need to tell other epics' docs to update when the format changes
- components used inside the pages can be components too: <epic-choices>, <epic-item-instructions> ...
- dogfood for <ui-root> and the @spell-app/ui components
