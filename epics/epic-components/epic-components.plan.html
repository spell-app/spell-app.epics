Plan doc for /epic epic-components, branch epic-components Worktree: /Users/owen/www/spell-app/spell-app/.claude/worktrees/epic-components Started 2026-10-07, updated 2026-10-07

Plan docs drawn by Solid web components (<epic-page>, <epic-item> ...) in a new package, packages/epics, loaded by <ui-root> as a component pack, so a doc holds only its data and prose. The plan-doc tool moves into the package as TypeScript, and all 26 docs switch over at once at the end: a layout change becomes an element change, never a rewrite of every doc.

Kickoff prompt

Plan docs (epic pages) as Solid web components, instead of HTML that carries its own layout:

<epic-page epic="windows-and-review" title="xxx">
<epic-header/>
<epic-overview />
<epic-section phases>
<epic-phase id="p1" title="Saved Replies" estimate="2h" />
</epic-section>
<epic-section questions>
<epic-item id="q1" title="Which four colours for the actions?" answered state="old"
changed="2026-10-06T09:28:23-04:00" status="decided"></epic-item>
</epic-section>
</epic-page>

Advantages (Owen, 2026-10-06):
- much easier/faster for Claude to read and write the file
- the components can be versioned individually
- no need to tell other epics' docs to update when the format changes
- components used inside the pages can be components too: <epic-choices>, <epic-item-instructions> ...
- dogfood for <ui-root> and the @spell-app/ui components

Decided on the details page epics/windows-and-review/details/epic-components.html (2026-10-06):
- Q1 whose code draws a doc: A, main's, always: every plan doc link goes to main's page server; a branch previews its components on its own server
- Q2 old docs: C, rewrite the docs (a converter script), no per-element versions. Owen: "I assume there will be shared code for reading/changing these files, correct? DRY?"
- Q3 where the code lives: A, a package of its own (packages/epics, @spell-app/epics). Owen: "Should this always be edited on the main branch as well?"
- Q4 rollout: A, convert the 25 docs once, then move the review runtime into the components in steps
- Q5 when: A, after windows-and-review
