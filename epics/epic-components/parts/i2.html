linkedom (0.18) escapes only " when it writes an attribute. Titles are attributes now, so a title whose TEXT is &lt;ui-input&gt; is written title="&lt;ui-input&gt;" and read back as <ui-input>.

  • real cases: design-system I37, I40; epic-review Q16; spell-ui-pages Q31; ui-component-creation Q53 (the proof caught all five)
  • the converter escapes every & in attribute values just before it writes (escapeAmpersands() in packages/epics/src/convert/domEdits.ts)
  • PlanMarkup.serialize() (the tool, P8) writes through linkedom the same way: once it writes <epic-item title>, each edit of such an item would turn its title's &lt; into <

Net effect:

  • P8: escape & in attribute values in PlanMarkup.serialize() (or use the converter's helper)
