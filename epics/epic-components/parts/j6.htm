The contract puts a pack catalog INSIDE its script, so the root learns its skeletons only when the script runs and registers, and define() runs in the same call. Chose to redraw the skeletons at that moment, so they cover the time until the pack elements are READY (their own loads, a slow first render), over changing the contract.

  • Option A (chosen): skeletons from the moment the pack registers until the root is ready; before that, the pack tags are hidden the when-ready way (space kept), or covered by Spell UI skeletons drawn around them.
  • Option B: a separate catalog the root can read before the script (a catalog attribute on <ui-components>, or a small JSON file beside the pack): skeletons during the download too, at the cost of a second file per pack and a contract change for P2.

Net effect:

  • The test checks the skeleton from the pack catalog while <x-card> is defined but not ready, not before define().
  • Easy to add option B later without breaking packs.
