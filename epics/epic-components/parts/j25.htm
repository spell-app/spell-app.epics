Chose to move every piece of page data into <epic-page> attributes and drop what it draws, over keeping copies on <body> for older code.

  • <body>'s data-plan, data-recent-since, data-bedtime, data-future become epic, recent-since, bedtime, future; <body> keeps its class and data-spell-needs-server
  • dropped, as drawn by <epic-page>: the sticky h1 and step label, the meta lines (branch, worktree, dates: their ids #plan-started / #plan-updated go too), the Plan hung? and future-epic notices. The durable doc's link is kept, slot="durable"
  • repo is read from the commit links, so each <epic-commit sha> draws its GitHub link
  • the breadcrumb stays in <main>, before <epic-page> (the page doesn't draw one)
  • a split host gets source, part-ids, commits and NO placeholder line: a <p> isn't allowed in a phase or the log
  • the body goes inside <ui-root><ui-components source="../../packages/epics/pack/epics.pack.js">; the scripts stay after it

Net effect:

  • a converted page shows no header, meta lines or hung notice until P5 draws them
  • code reading body[data-plan] must read epic-page[epic]
