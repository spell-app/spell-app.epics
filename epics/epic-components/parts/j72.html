To let <epic-choices> sit on ANY item (a judgement call's text, a reply, More Details) and <epic-field label> sit in an item's prose, both are now flow elements (they count as prose wherever prose is allowed), rather than new places listed in each parent's content model.

  • why: the old grids sit in the middle of prose ("The options:", the grid, then a Net effect and more text), and inside replies; a listed place would make the text after them "out of order"
  • cost: the item's "at most one Choices" rule is gone, and details --append now puts new prose at the end of the item's text, AFTER a question's option cards (it went before them)
  • a phase still takes only its named fields: a labelled block in a phase is refused

Net effect:

  • the converter's second pass can put both anywhere prose goes; nothing else changes for a reader
