Two answers: (a) yes, prose may use <ui-markdown>, with three catches; (b) why parts are .htm today, and what renaming them to .html takes. (b) needs your pick, below.

(a) <ui-markdown> in a plan doc's prose

It already works on every docs page: the docs bundle loads every Spell UI family, and points <ui-markdown>'s engine at its lazy script. Where it helps: a long stretch of plain prose in a part (an Overview sub-section, a long issue write-up), written as markdown instead of <p> / <ul> / <li>.

 ...
 *   - then `spell-ui:lazy`, pointing `<ui-code>` / `<ui-markdown>`'s engine loaders at their lazy scripts

The catches, all because it renders into its OWN shadow root:

  1. Links into it: a page link #d7 can't reach an id inside it. It handles #id links to its own HEADINGS only (reveal(), and on hashchange). So an answer card, an h4 another item links to, or anything listed in a host's part-ids must stay HTML.
  2. Relative links in a part: a part's links are written relative to parts/ and rebased when it loads, but the rebase rewrites ATTRIBUTES only (PlanParts.rebase()). A markdown link is text, so [x](../../../guides/x.html) in a part would be one ../ off once shown.
  3. The tools don't see inside it: doc-links.js names each source link's tab (target="src-..."), and check checks #id links; both read <a href> markup. A markdown link gets no tab name, so in VS Code's doc preview a link to a .ts file opens IN the preview instead of in the editor (liveClient.ts followInFrame() sends only src- targets to the editor).

static rebase(element: Element, change: (url: string) => string): void {
  for (const node of [element, ...element.querySelectorAll("*")])
    for (const name of URL_ATTRIBUTES) {
      const value = node.getAttribute(name)
      if (value === null || !isRelative(value)) continue
      node.setAttribute(name, change(value))
    }
}

So: markdown for plain prose with no links to source files and nothing linked INTO it; HTML for the rest. Find-in-page should be fine: Chrome's searches text in open shadow roots (not checked in VS Code's doc preview).
