<ui-root> can only load Spell UI's own ui-* elements, from a list fixed when Spell UI is built.Added component packs to Spell UI: <ui-components source> inside a <ui-root> registers another package's elements, loaded on demand like Spell UI's own, from file:// too, with the page's own Spell UI and Solid.
  • A pack is a classic script calling registerPack(); ComponentPacks is the page's one registry, and SpellUI.packModules hands a pack the shared modules
  • The root takes catalogs added at run time, and any tag prefix
  • A pack that fails to load doesn't hang the page; its skeletons show once its script has run
  • <ui-components> has its own docs page
  • Where to see it: a page can now load another package's elements. Put <ui-components source="…/x.pack.js"></ui-components> inside <ui-root>, and that pack's elements work on the page.
    • Seen working in Chromium, opened from file://, with the epics pack: pack-smoke.html.
    • <epic-page> was defined and drawn, the root got ready, and the console showed no errors.
  • What changed in Spell UI:
    • <ui-components> is a new, invisible Spell UI element.
    • It has its own docs page, ui-components.html, which still holds the generated stub text.
    • ComponentPacks is the page's one registry of packs.
    • registerPack is exported from spell-ui, and also set on the page's SpellUI global.
    • window.SpellUI.packModules hands a pack the shared modules: Solid, its web layer, and Spell UI's core and forms. 
      solid-js, @solidjs/web, spell-ui/core, spell-ui/forms
  • A pack that fails to load does not hang the page: the root still gets ready, and the error names the pack's file.
  • Rough edge: a pack's skeletons show only once its script has run, because the pack's catalog lives inside that script (the late-skeletons judgement call, J6).
