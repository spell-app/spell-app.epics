Chose classes over a line-for-line port of the free functions, because WWOD lists free functions that all take the same object as an anti-pattern, and nothing outside the tool imported those names.

  • ReviewInbox: an instance IS the inbox file's JSON (its own fields are the file's keys, in the file's order), so setMark(inbox, ...) is now inbox.setMark(...), and updateInbox(file, fn) is ReviewInbox.update(file, fn)
  • PlanParts: one per parsed document (new PlanParts(doc).split(), .assemble(reader), .hosts); file helpers are statics
  • ReviewBackfill: holds the transcripts folder (tests pass a fixture); findEvidence() and projectSlug() are statics
  • the option not taken: keep the free functions, so inbox.js etc. could forward the very same names
  • the inbox file, the routes' answers and every command's output are byte-identical (checked)
  • spell-epic/src/tools/inbox.js, plan-parts.js, review-backfill.js are one-line forwarders to the classes; anything still calling the old function names breaks (nothing in the repo does)
