The 4,625-line plan-doc.js's model half (the PlanDoc class, its tables and helpers) is now TypeScript in packages/epics/src/tool/. Chose a split by job over one 2,700-line file, because WWOD wants one class per file and helpers as statics on small classes.

  • PlanDoc.ts: the class, every public method the command line calls, same names and arguments
  • PlanMigration.ts: the 20 old-doc conversion steps (mergeDecisions(), migrateItems() ...), made by PlanDoc.migrate(); they are no longer PlanDoc methods (nothing outside migrate called them). orderSections() and estimatesToBadges() stay on PlanDoc: other code and the tests call them
  • helpers as statics: PlanMarkup (escaping, serializing), PlanSections (sections either markup, phase fields, title, prompt), PlanItem (title, kind, options, recommendation, pickAsks()), PlanTime (dates, estimates), PlanCommits (subjects, GitHub base)
  • the types file is planDoc.types.ts, not plan-doc.types.ts as the brief said: WWOD forbids kebab-case file names outside scripts. PlanDocError lives there, now with prototype.name set (WWOD §5)

Options: one big PlanDoc.ts (closest to the JS); a split by job (chosen); a finer split (phases / items / review classes, with PlanDoc delegating every method: much more code for the same behaviour).

Net effect:

  • the command layer imports PlanDoc plus the helper class it needs (PlanItem.titleOf(), PlanTime.isoDate() ...) instead of free functions
  • plan.mergeDecisions() and the other migration steps are reached only through plan.migrate()
