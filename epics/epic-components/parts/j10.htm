Two calls about what spell dev pack build writes.

  • define(): the generated entry is registerPack({ name, prefix, catalog, define: () => Promise.all([import(family) ...]) }). Rolldown inlines the families into the ONE script but wraps each in a lazy init, so nothing is defined until define() runs; the tags are defined a microtask later, and the promise says when. The alternative (static imports, so every tag is defined as the script loads, before registerPack) is simpler but ignores the contract's order
  • check: a sha-256 of every file in components/ and src/ (tests and snapshots left out), the pack's name and prefix, recorded in the catalog's 2nd line and the script's banner; check compares it and the catalog's text. Chosen over rebuilding and diffing: a build takes ~1s and pulls in Vite, and every pack's yarn test runs the check

Net effect:

  • a formatter run (yarn format in review) that changes a component file makes the pack stale: yarn pack:build, then review again
  • pack/ holds three committed files: <pack>.catalog.ts, <pack>.entry.ts, <pack>.pack.js (minified IIFE)
