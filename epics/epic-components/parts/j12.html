Built the 17 tags from the Overview's list, and filled each gap today's markup has, so the converter (P6) can carry everything over.

  • <epic-item> also takes deferred, work, working, bedtime (today's data-* review marks), part-ids and commits (today's data-part-ids / data-commits); phases and sections take part-ids too
  • <epic-page> also takes recent-since (today on <body>) and repo: each <epic-commit sha> builds its GitHub link from it, rather than every commit carrying its own link
  • the durable doc is a child, <a slot="durable" href=...>Title</a>, not an attribute: so doc-links.js still fills in its target and checks it, and its title stays
  • <epic-answer> takes a title (the Answer · Named palette line)
  • <epic-updated at phase> is one dated line each, not one block holding a list
  • a section's tooltip (data-tip) goes: it's fixed per kind, so P5 draws it from the vocabulary
  • families: sub-tags live in their owner's folder (epic-phase/ holds epic-field, epic-updated; epic-choices/ holds epic-option; epic-answer/ holds epic-reply, epic-more; epic-original/ holds epic-version)
  • nothing a doc says today is lost in the new markup
  • a leftover data-status on an epic-* element is reported by Markup.validate(): data lives only in the listed attributes
