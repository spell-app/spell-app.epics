Claude's status card is a new element, <epic-status state="underway|done" at done-at>, in a family of its own (components/epic-status/), NOT an <epic-reply> with a state.

  • Why: a reply is a message; a status card changes state in place and carries a summary slot, and its header text (Claude • Underway / Claude • Done) is drawn from its state, not from from / re
  • It shares the reply card's sheet (epic-answer.css, adopted first: the box and the dated band, .header.dated); only its two fills are its own (epic-status.css)
  • Where it goes: slot="status", drawn LAST in the item's details, between Owen's marked note and the note box, so it sits literally under his input even while his note is still in the inbox (before inbox done turns it into an <epic-reply from="Owen">). The phase asked for 'after the replies' in the child order; a slotted child is never ordered, so the tool writes it at the end of the item, and a part file never holds it (it stays in the skeleton, with the title)
  • The same slot on an Overview sub-section, above its note box
  • state isn't required in the vocabulary (absent reads as underway): a key required on one tag and optional on another (<epic-item state>) makes Markup.set()'s untyped data never
