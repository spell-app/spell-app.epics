Chose, where an epic-* element's children can't be patched one by one (its own text changed, or they don't line up), to swap its children and keep the element, over replacing it as other elements are, because the element holds its fold, its loaded part and its controller.

  • what's typed in a replaced light-DOM field still carries over by id, as before; P9's note boxes are in shadow roots, so a patch never touches them
  • component pack scripts (x.pack.js) no longer make a page reload instead of patch
  • a part re-fetch now re-focuses a box inside a shadow root (an epic-item's note box), which the item hides for a moment while its part reloads
  • the check: the page server doesn't watch preview-epics/, so the script calls the page's own live client hook (window.__spellLiveChange) after writing a file; everything after that is the real path. It answers the review routes itself, so the page is reviewed

Net effect:

  • node packages/epics/demo/check-live-epics.mjs [epic] --bundle passes on windows-and-review (q2) and epic-components (q11); against today's spell-ui.js it fails (the page reloads)
