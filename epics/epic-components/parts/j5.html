Chose namespace imports in packages/docs/tools/_assets/spell-ui.entry.js over an explicit list of named exports kept in ui. The ui rule against import * as a Solid package keeps a LIBRARY bundle from pinning all of Solid; this map exists so a pack may use ANY export, which no tree-shaker can know ahead, and a hand-kept list would break a pack silently (an unlisted import is undefined at run time).

  • Option A (chosen): namespaces, in the docs entry only; ui itself never holds the map.
  • Option B: an explicit named-export object in ui: smaller, but must grow with every pack, and the failure is silent.
  • All of solid-js and @solidjs/web stays in spell-ui.js (a few kB more, not measured yet: the orchestrator rebuilds it).
  • Keys are the exact specifiers: solid-js, @solidjs/web, $/ui/core, $/ui/forms. A new one goes in the entry AND the pack build externals.
  • The exception is written down in the entry header and in packages/ui/AGENTS.md "Component packs".
