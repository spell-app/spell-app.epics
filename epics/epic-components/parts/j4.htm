Chose to put ComponentPacks (the page registry and script loader) and registerPack() in src/components/ui-components/, exported from $/ui (@spell-app/ui) and the family barrel, over adding them to the shared core entry. Loading packs is the root job, and the root barrel now imports the ui-components family (as it does ui-loader and ui-placeholder), so every page with a root has exactly one registry.

  • Option A (chosen): the ui-components family; core bytes unchanged.
  • Option B: $/ui/core, so a pack built against core could also import registerPack from the module it already shares. Not needed: packs call SpellUI.registerPack (the contract).

Net effect:

  • ES code: import { registerPack } from "@spell-app/ui" (or @spell-app/ui/ui-components once it is a lib entry).
  • The docs bundle: window.SpellUI.registerPack.
  • A page with a root but no packs carries the small family anyway (an invisible element plus the registry).
