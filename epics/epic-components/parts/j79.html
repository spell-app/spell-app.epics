I8 lets one item hold several <epic-choices> (its text's, a reply's, More Details'), so a pick must say which. The mark carries choices: the set's position among the item's sets in page order, its Original Discussion's never counted (PlanItem.choiceSets(), and EpicChoices.setOf() on the page, the same rule). A mark without it (from before I8) means the item's own set, the first that's its child.

Why not an id on each <epic-choices>: every writer (the converter, agents' HTML, IncomingHtml) would have to mint and keep one. Positions only shift when the item's text is rewritten (its old cards go into the Original Discussion), and a pick waits minutes, not days, for inbox apply; a stale one names a set or letter that isn't there and is left, not misapplied, unless the new set has the same letter.
