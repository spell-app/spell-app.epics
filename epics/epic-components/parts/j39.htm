The brief said to make a new goals.css, but goals pages already had one (their own look) and link spell-doc.css, plan-doc.css and goals.css. So I added a section to that goals.css with the plan-doc.css rules goals pages use, instead of making a second sheet.

  • Found the rules by loading all 20 goals and template pages in a browser and testing every plan-doc.css selector: 8 matched (item lists, id chips, the folded-details indent, empty list text, the first-shown-item divider, heading icon margin). Copied as they were, except one.
  • The one: plan-doc's heading-icon rule gave h3 icons 4px, beating goals.css's 6px. It is now a plain .spell-doc-main h3 > ui-icon rule with 4px, so the look is unchanged.
  • Also copied: a done item's title turns grey once the runtime marks item states. That only happens after a live update, so the browser check could not see it.
  • No tool writes a goals page's head (the templates do), and there is no command that regenerates every page. So page.js gets GoalsPage.restyle() (drops the plan-doc.css link), with tests, and nothing calls it until P12 (T16). If editPage called it, a thought added through this worktree's page server would strip the link from a shared page while main still needs it.
  • Fixed a wrong comment in passing: goals.css said done items are struck through. They are not.

Net effect:

  • Restyled copies of all 20 pages matched the originals pixel for pixel at 900px light, folded and unfolded
  • Shared goals pages and templates are unchanged tonight
