Two rules the content model forces on the tool.

  • Checked writes: PlanDocFiles.edit() runs Markup.validate() (with ids and links) before and after the change; a NEW problem refuses the edit, nothing written. Problems the doc already had don't block it
  • Append: an item's prose must come before its Choices and answer, so details --append with plain prose adds it at the end of the item's text (before, it went after the answer); an epic-reply (or an old div.plan-reply) goes after the other replies, as before
  • Overview sub-sections (Q14) have no review attributes yet: approve on one is only logged, todo makes a todo linking #o3, Owen's kept note is a paragraph at its end
  • the tool can't write markup the elements would refuse
  • an agent's appended paragraph on an answered question lands above the answer, not below
