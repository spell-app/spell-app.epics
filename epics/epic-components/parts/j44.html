On a converted doc the contents list was EMPTY (the runtime only knew ui-section and h2 markup), so check-spell couldn't pass. Chose to teach the runtime the blocks, with the blocks saying what to list, over copying their numbering and titles into the runtime.

  • each block's host has contentsEntry (EpicFoldHost): its label as drawn (1. Overview, 1.2 Why, P3 · Converter, 4. Judgement calls), its icon (a phase's status icon in its colour), a section's open/all count; read from the page as it is now, so a live update's change shows at once
  • the runtime waits up to 5s for the pack to define and draw before building the outline
  • folds: a block the reader opened stays open on reload (the same spell-folds key as before, so a fold left on a doc before the switch holds); restored before the blocks draw, so nothing animates
  • a contents link or #id link opens the blocks and items around its target (and loads a part by part-ids), then lands below the stuck titles, read from --epic-stack
  • the contents list and rail of a converted doc match today's: same entries, icons and counts
