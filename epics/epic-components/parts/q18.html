Owen's pick (2026-10-07, after a merge full of noise): stop committing packages/brand/_assets/ui/ (266 files) and packages/ui/site/_assets/ (195 files); the page server builds them when it starts, if stale.

  • Why: their chunk names carry content hashes ([name]-[hash].js), so any Spell UI change deleted and re-added nearly all of them in every diff and merge. Only the page server serves them (ES modules, never file://), so nothing else needs them committed.
  • How: $/assembler Bundle knows each bundle (its package script, output folder and sources) and records the sources' hash in <output>/.bundle.json; spell dev bundles build [name...] [--stale] / spell dev bundles check run it; the page server's BundleBuild spawns the checkout's own spell dev bundles build --stale at startup, logs it, and a request for a missing bundle file waits for it (up to 2 minutes). Live reload reloads open pages when it ends.

Net effect:

  • Both folders are git-ignored; their .gitattributes lines and GENERATORS entries are gone
  • Both builds take about 1.5 s each; a start with nothing changed builds nothing
  • spell dev worktree merge-main untracks any file the merged .gitignore ignores that main still commits (one side's tree lacks it), so merges across the change don't stop on them
