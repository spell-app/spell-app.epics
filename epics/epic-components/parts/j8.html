Chose template files with a .tmpl suffix (__Class__.tsx.tmpl, __tag__.vocabulary.en.ts.tmpl ...) over real .ts files with placeholders, or templates as strings in code.

  • real extensions: cli's tsc, type-aware lint and vitest would all read them (the template test would run in node and fail)
  • strings in code: hard to read and edit

Net effect:

  • no tool touches a template; editing one is editing a plain file
  • tokens: __pack__ __packCamel__ __prefix__ __solid__ __tag__ __Class__ __vocab__ __noun__ __nounCamel__; gitignore.tmpl becomes .gitignore
  • package.json is merged key by key (scripts, devDependencies, spellPack) rather than skipped, so a folder that already has one still becomes a pack

Hmm, can't we put this in JSON?

We can, but I'd keep the templates as files. Today spell dev pack new / pack element copy 18 small template files (393 lines in all) from packages/cli/templates/pack/, filling in each __token__. Most of them are TypeScript, CSS and markdown, so as JSON strings they'd lose their highlighting and gain escaping.

  • the files: element/ (7, one element family) and package/ (11, a new pack)
  • the tokens and how they're filled live in code, in packNew.ts (packTokens(), elementTokens(), fillTokens())
  • package.json.tmpl already IS JSON (with tokens), and is merged key by key, not copied

/** The tokens of element `tag` in pack `pack`. */
function elementTokens(root: string, pack: PackInfo, tag: string): PackTokens {
  const noun = tag.slice(pack.prefix.length)
  return {
    ...packTokens(root, pack),
    tag,
    Class: pascalCase(tag),
    vocab: camelCase(tag.replace(/^ui-/, "")),
    noun,
    nounCamel: camelCase(noun)
  }
}

/** `text` with each `__token__` of `tokens` filled in;  any other `__word__` stays. */
function fillTokens(text: string, tokens: PackTokens): string {
  const names = Object.keys(tokens).sort((a, b) => b.length - a.length)
  return text.replace(new RegExp(`__(${names.join("|")})__`, "g"), (_, name: string) => tokens[name]!)
}

 A · Keep one file per template (recommended)
  • as today: each template a real file, named like what it writes
  • an editor highlights it, a diff shows a one-line change as one line, and you edit it like the file it becomes
  • cost: none; the token list stays in packNew.ts

Net effect:

  • no change
 B · One JSON file holding every template
  • templates/pack/templates.json: path => text, 18 entries
  • cost: every quote and newline escaped (the sketch above); no highlighting; a one-line change is a diff of one very long line; a hand edit easily breaks the JSON
  • gain: one file to find

Net effect:

  • 18 .tmpl files become one templates.json; packNew.ts reads it
C · JSON for the token list and file map; templates stay files
  • templates/pack/pack.json says what's now in code: each token with what it means and an example ("Class": "EpicPage"), which files are merged rather than copied (NOT_COPIED), the gitignore => .gitignore rename
  • cost: ~30 min; how a token is COMPUTED (pascalCase(tag)) still has to be code, so the JSON only names and documents them
  • gain: you see every token and file rule in one data file beside the templates
