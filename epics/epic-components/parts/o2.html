An epic page's markup says WHAT is there (an item, its status, its title) and the elements draw HOW it looks. The prose stays plain HTML.

  • data goes in attributes: status="decided", state="old", dates, the phase
  • prose goes in children: paragraphs, lists, code, as today, so it stays searchable and diffable
  • the chrome (id chip, review label, fold button, option cards, answer card) is drawn by the element: no doc ever writes it again
  • no v="1" on elements: you picked "the converter rewrites the docs" over per-element versions (analysis Q2)

The first elements, from your sketch and the old markup; every "later" in the table was built in P9 and P10:

Element Attributes Draws
epic-page epic, title, branch, worktree, started, updated, future, bedtime the sticky page header, step label, meta lines; later Send and Review Now
epic-overview (summary, prompt and sub-sections as children) the folded Kickoff prompt, the estimate total
epic-section kind: phases, questions, judgements, caveats, todos, issues, tests, log its numbered title, icon, open / all count; later the state filter
epic-phase id, title, status, estimate, source status icon, estimate badge; its fields as children: epic-field (symptom, changes, goal, done, files, verify), epic-updated, epic-commit
epic-item id, title, status, state, changed, phase, answered, reviewed, review-as, queued, source the id chip in its state's colour, the line, the fold; later the review buttons and note box
epic-choices, epic-option chosen; letter, title, recommended option cards, folded under "Choices" once answered; later the Choose pills
epic-answer, epic-reply, epic-more id; from, at, re the answer card, reply cards, the More Details card
epic-original, epic-version as-of the folded Original Discussion
epic-commit, epic-event, epic-update sha; at, icon; phase commit links, log lines, the UPDATE marker

The item's KIND (question, judgement call, issue ...) stays what its id says (q, j, i ...): one <epic-item> for all of them, as in your sketch (Q11).
