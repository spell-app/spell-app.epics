A program that imports another project, or has no app, still runs again on every edit, so it redraws.
  • From I9: Owen, 2026-11-03, 'later phase, after data lands'.
  • An edit to a program that imports another project keeps its state and redraws only what changed, as Edit Without Redraw does for one program.
  • A new property's attribute shows without Restart, if it can.
Edits are taken live across imports too, once the data epic has landed.
  1. Remember each imported project as it runs. The run that links a program's imports keeps, per project, the text it ran, the URL it ran at and what it exports, beside the program's own (lastProgram in runCompiled.ts).
  2. Take an edit with imports live. On a recompile, each import's new text is read again (loadImport) and compared as the program is (LiveEdit.between()), deepest first:
    • unchanged: its running module stays, at its old URL
    • changed inside its types: its live text loads over its running variables, and its running things take the new classes (core.loadOverRunning(), core.takeNewClasses()), as the program's do
    • anything a program can't take (a new type, a top-level line): Restart, saying which project
    Then the program itself, its imports pointing at the running (or new) modules. Only the views of what changed, in any project, draw again.
  3. A program with no app keeps running again on every edit, as I9 says is right: nothing is drawn to keep.
  4. A new property's attribute without Restart. The tag's attribute list is fixed when the browser defines it, so: a property added by an edit is added to the tag's own list of properties, and each element of the tag on the page starts writing it as an attribute (thing to element); the page writing that attribute back (element to thing) is watched per element. If the platform blocks either half, the half that works ships and the other is recorded.
  5. Checked by: a browser test on the frozen counter-app (it imports counter): click to change the count, edit the app's code, then a library edit taken through the runner; the count kept, the same elements. A test that a new property's attribute shows on an element without Restart. The app's full run, failures rerun alone.
  6. Left out: editing an imported project from inside the app's own editor window (the editor runs one project at a time); imports in the public preview.
