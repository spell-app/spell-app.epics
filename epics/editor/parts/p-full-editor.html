All of the editor is in Spell. It opens as a project, and edits itself.
  1. The editor as a project group. The editor's own Spell pieces (layout, bar, menus, file tabs) move from the app's source into the built-in projects, as a group of their own, @spell/editor, one project per piece. The editor imports them from there, so the files you open and the files it runs are the same files. The group shows only on your own machine (like the test projects), never in the public preview.
  2. Can't lock you out. Each piece's last good compile is kept. A piece that stops compiling falls back to it while the editor runs locally, and the editor says so in plain words, naming the piece and the error; a build still stops, so nothing broken ships. A piece that compiles but fails to draw already falls back to its plain stand-in.
  3. Save and see. With drafts (P24), saving writes your draft and the running editor keeps the published piece; Publish writes the file, and the running editor reloads with it. Checked by changing a pane's setting in the editor-layout project, publishing, and seeing the running editor change; then breaking it on purpose and seeing the fallback.
  4. Two editors on a page, proved first. Try your draft of the editor in a frame of its own, the theme editor's way: a second editor page in an iframe, which compiles the pieces from your drafts in the browser, while the outer editor stays on the published ones. Built only if the proof holds; otherwise recorded with what blocked it.
  5. Left out: visitors shipping their own editors; the public preview; editing the editor's TypeScript (what each action does) from inside it.
  6. Checked by: a browser test for each of the first three, headless pictures in Glass light and Fruity dark, and the app's full tests.
  • Where to see it: on your own machine, the home page has a group, The editor, of four projects: editor-layout, editor-bar, app-menus, file-tabs. They are the editor's own Spell pieces, which the editor imports from there, so the files you open are the files it runs. The public preview never lists them.
  • Opening one shows the editor itself, built from your drafts, in a frame in the app pane; a draft changes the frame only, never the editor you're using, and Publish makes it the real editor (J73).
  • A piece that stops compiling can't lock you out: the editor keeps its last good compile and says which piece broke, and why.
  • Rough: the frame is narrow, so its bar's middle group runs into the menus (T47); what each action does is still TypeScript, not editable from inside (T48).
  • Not tried: Publish through the File menu itself, a real save in the editor, a real Mac, Spanish. M17 is Owen's.
