The editor is one bundled Solid program, so it can't be edited in itself.
  • Stage 1 of turtles: the editor's layout pieces are written in .spellml, with custom TypeScript backing where Spell would make it too hard.
  • One pane proves it first: it builds, shares the page's one Solid, and reaches the single editor object.
  • What the proof finds decides whether the rest goes ahead now, or waits until after the preview.
  • The editor looks and works the same when it's done.
  • It's the first thing to pull if it runs long, since the preview doesn't strictly need it.
One pane is proved in .spellml first. Then the layout pieces follow, with TypeScript behind them where Spell would make it too hard.
  1. Prove it on the file tabs. They are small, sit in plain view, and read the single editor object, so they test everything that could go wrong. It runs after One Header Row, so it rewrites the finished header, once.
  2. Compile Spell while the editor builds. A small Vite step wraps spell compile, which the preview build already runs, and turns a .spellml file into a module the editor imports.
  3. Answer the three unknowns, with the pane running:
    • Does it share the page's one Solid? The running app's own copy of the runtime must stay separate.
    • How does it reach editor? Through a small TypeScript backing, which is what you described.
    • What does it add to the first load? Measured before and after.
  4. Where the proof ends. It passes if the tabs look and work the same, in the dev server and the static build, on one Solid, with a small size change. If it needs a second Solid, or adds a lot to the first load, I stop and bring you what was found, with the phase rewritten.
  5. Then the other layout pieces, one commit each: the top bar's groups, the panes' headers, then how the panes are arranged. Monaco, the Inspector's cards and the theme editor stay TypeScript behind them.

Checked by: the existing editor tests, a screenshot compared before and after each piece, the static build, and yarn review in app.

Left out: rewriting the backing in Spell (Backing In Spell), editing the editor inside itself, and the Inspector working on its own panes.
