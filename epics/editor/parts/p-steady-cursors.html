A page with it starts with the arrow and no text selection, so nothing is left to the browser's guess. Docs pages stay as they are, and text meant to be selected opts back in.
  2. One setting for controls: a theme value, the cursor every control uses, replacing the separate pointer rules in the reset, menu, item, icon and dropdown styles. Glass and Fruity set it to your choice below.
  3. Controls that have no rule get one: bar menus, file tabs, plain menu items, and icon buttons such as the hide-eye and the Inspector's toggle.
  4. Dragging and selecting: while a drag runs, the whole page shows the closed hand. While Inspect app is on, the app's area shows a crosshair over everything. Both replace the forced !important rule on a drawn thing's insides.
  5. Cleanup: the editor's own one-off cursor rules go, in the Inspector, the explorers, the console and the top bar. Only the split bars and the code keep their own.

How it's checked: the same walk runs again, and may find an I-beam only in the code and in fields you can type in, and one cursor per control. It's kept as a test. Then a manual test for you: move the mouse across everything.

Left out: the code editor's gutter and caret, which it draws itself. Other themes keep the hand on controls.
