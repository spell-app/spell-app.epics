For P38 · Side By Side And Sizes: Design's side-by-side sheet shows a view in several settings at once (face up and down, each suit). You also want to tweak a card's settings there and save them as a named entry, which then shows in the sheet.

Where do the sheet's entries come from, and where does a saved one get written?

  • Today a view's settings are written only in its tests, e.g. Card.spell's to test card setup: get a new card whose rank is queen, suit is spades and direction is down.
  • Its property editor is already a file of its own beside it, Card.editor.spell.
  • Saved entries go in Card.<word>.spell, beside Card.editor.spell.
  • Each is a name and the Spell you already write in tests: "queen of spades, face down" is a new card whose rank is queen ...
  • With none saved yet, the sheet makes its own from the view's choices, one change at a time: each suit, face up and down.
  • The view's own file stays as it is.
  • Cost: one new way to name an entry in Spell, which you would see and OK first.
  • A block in Card.spell, after its drawing, listing the named entries in the same Spell.
  • Everything about a card in one file.
  • Cost: the view's file grows with entries that are only for designing, and the same new Spell wording as A.
  • A JSON5 file beside the view: each entry a name and its values ({ rank: "queen", suit: "spades" }).
  • No new Spell wording.
  • Cost: not readable as Spell; the values aren't checked by the language server.
  • Each card a test makes (a new card whose ...) becomes an entry.
  • Cost: no Save button; Card's tests make only two cards.
  • saved entries live in a Spell file beside the view, as its property editor does
  • a view with none saved still shows a sheet, made from its choices
