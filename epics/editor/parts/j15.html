This is about which kind of side-bar edit gets built first. Both still get built, in the same phase.

Take a Solitaire card. There are 52 on the screen, but the program never writes 52 tags. One line makes them all, in a loop: 

add a new card with rank = the rank ...

So if you select the ace of spades and change something, there's no "ace of spades" in the code to change. The only place to write it is Card itself, which changes every card.

I counted this across 20 built-in examples and guides. Of the values with something in them, 64% are like that: they belong to something made in a loop.

  • Built first: edits that change the type, such as what every Card does.
  • Built second: edits to one tag written in the code, such as one button in a toolbar.
  • Only the order changes, inside the Sidebar Writes Source phase. Nothing is dropped.
