Proposed fix

When you open the editor's own project (@spell/editor/spell-editor), its app pane shows each part of SpellEditor.spell in a zone of its own, drawn from the code as you type. It no longer shows a second whole editor in a frame.

  • Which zones, in which order: each view the app holds, in the order spell editor is an app lists them: the editor bar, the editor layout, the file tab bar, the project menu, File, Edit, View, Run, the home row, the About box and the Versions box. The list is read from the running app's views, so a view you add shows up by itself. Each zone is headed with the view's name in words.
  • How each one is drawn: by the program the app pane already runs, on the programs' copy of the runtime, never the copy the editor itself runs on. The app is run as a layout (layout), so it doesn't try to draw itself. Each zone draws its view in place (core.drawOwn()), inside an error boundary of its own, so a drawing that throws shows its error in its zone and the other zones keep drawing.
  • What the editor would draw in a view's place for it (a pane, the Spell menu's projects, a menu's Undo row): a labelled grey stand-in naming that part.
  • A view that is a modal (About Spell, Versions): its zone holds a Show button. A modal open all the time would cover the page and lock it, so it opens only when asked, and goes again when it closes. It's filled with sample data: the editor's version, and two sample versions with the Versions box's own words.
  • As you type: an edit that compiles is taken by the running program (live edit), so the zones redraw where they are. An edit that doesn't compile leaves them as they were, and the editor shows the compile error as usual.
  • The draft-editor frame goes (?pieces=draft, <DraftEditorFrame>, isDraftEditor): nothing else uses it.
  • The lock-up (I122): the frame's address carried editor.edits, so every keystroke reloaded a whole second editor (its code editor, its compile, its saves) in the frame, the next load starting before the last had finished. It's gone with the frame.
  • Saving is unchanged: at test.spell.app, a save of a built-in project becomes your draft (savesInPlace()), so edits there stay drafts until you Publish.
