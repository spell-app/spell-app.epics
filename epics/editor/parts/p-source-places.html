First, count what has a home across the examples. Then the compiler marks each drawn element with its place in the source.
  1. Count first, with a small headless script. It runs each built-in example, English and Spanish, picks every part, and sorts every field by its home:
    • written on its own tag
    • its tag is in the source, but this field isn't written yet
    • made in a loop: its tag is shared, or it has none
    • the type's default
    • worked out by the program
    • an expression, {...}
    • set while running
    The table goes into this phase's Done.
  2. What the count could change:
    • Most things loop-made: This Or All starts on "All", and Sidebar Writes Source builds default edits before tag edits.
    • Most editable values are expressions: the side bar can't edit much as it stands, so I stop and bring you the numbers, because that changes the promise of editing without code.
    • Otherwise both go ahead as written.
  3. Mark what's drawn. While the editor compiles, each drawn tag's h() call gets its place in the source, from SourceMarks. Each thing made by add a new card gets that statement's place.
  4. Published output stays the same. The marks are on only in the editor's runs, so compiled code and the snapshots don't change. A test says so.
  5. After a recompile: the marks are simply made again. A pick is found again as it is today, and reads its new place.
  6. The Inspector reads the mark, and the best guess in InspectorSource goes. Rows of one list all point at their one tag, as they should.

Checked by: a test picking elements in Solitaire and Solitario, and finding the right tag; the parser speed test on the diff and on HEAD.

Left out: changing anything in the source, which is the next phase; reading the maps back for code mode (Code Follows Along).
