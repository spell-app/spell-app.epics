The cursor itself always moved in under 1ms. The pause is the Inspector drawing its card again, in the same task as the key, before the frame that shows the caret. Where the time went, Inspector showing (Solitaire, a CPU profile):

  • ~60ms a line: the Code band makes a new code editor for each event and action of the new selection, and a new editor measures every line of its file, the whole of Solitaire.spell, for its careful wrapping (I33).
  • ~17ms: the Views tree scrolls its selected row into sight, which makes the page lay itself out early.
  • ~11ms: the outline's ants find their box; ~10ms: the property editor's fields.
  • The arrow keys' follow waits until the cursor has rested 120ms on a line, then updates the Inspector once: a run of presses, or a held key, is one update, and never in the key's task. A click follows at once, as now.
  • Another line of the same tag changes nothing (no new selection).
  • The Code band's slices keep their code editors for the next selection, so a new selection no longer makes and measures new ones.

Fixed: the caret moves at once whether or not the Inspector shows. The Inspector catches up once the cursor rests.
