Why it misses: the editor's Enter rules know only a line ending in :.

  • Two more Enter rules, in the language's settings (Monaco's and VS Code's, kept the same by a test), not a new typing help:
  • a line ending in an opening tag (<content>, <toolbar class="x">): the new line one tab in. Not after <x/>, <br> or a closing tag.
  • Enter between <x> and </x> (or </>): the caret a level in, the closing tag on its own line at the tag's indent.
onEnterRules: [ { beforeText: OPENS_TAG, afterText: CLOSES_TAG, action: { indentAction: IndentAction.IndentOutdent } }, { beforeText: OPENS_TAG, action: { indentAction: IndentAction.Indent } }, { beforeText: /:\s*$/, action: { indentAction: IndentAction.Indent } } ]
  • Enter after <content> starts its first child a level in
  • Enter in <x>|</x> opens it up, caret inside
  • the same in VS Code
 Enter after an opening tag goes in a level; between <x> and </x>, the caret a level in and the closing tag on its own line (Spell's Enter rules, Monaco's and VS Code's)
