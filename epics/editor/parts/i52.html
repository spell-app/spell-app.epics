Found: a click in a drawing's markup selects its element only in one case, the line its tag starts on, and only for a tag drawn on the page itself.

  • Lines inside a tag select nothing. The app knows where each element's tag STARTS (line and column), and a click matches that line only. In Tic-Tac-Toe, clicking {the label of the square}, inside the board's <button>, selects nothing; </content> and {draw its board} leave the old selection.
  • Tags inside a drawn thing's own drawing are never found. A pile's placeholder, a card's face: these are drawn inside the thing's own element, and the search only walks the parts tree, which doesn't go in there. In Solitaire, clicking the stock pile's <text part="placeholder"> selects nothing.
  • What works today: clicking the first line of <container>, <card>, <header> or a button selects it. 
static selectWrittenAt(path: string, line: number): void {
  const area = appArea
  if (!area) return
  const written = Inspector.partsIn(area)       // the parts tree:  not inside a drawn thing
    .map((row) => row.element)
    .filter((element) => {
      const place = placeOfPart(element)
      return place?.path === path && place.line === line   // the tag's first line only
    })
  if (written.length) Inspector.selectAll(written)
}
  • A click anywhere in a tag, its content and closing tag included, selects the innermost element drawn from it.
  • That works inside a drawn thing's own drawing too: a pile's placeholder, a card's face.
