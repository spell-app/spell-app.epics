The Inspector treats a thing as one of a kind, and drops its This | All switch, when either holds:

  • the parse says so: its thing is a variable of kind only in the project's scope, of its type. That's what create_one_of_a_kind declares (solitaire is an app, leaderboard is a page, klondike is a card game), and a site (CreateSite) and a place (family cookbook is a web server at ...) the same way.
  • it's the running program's app (core.RUNTIME.app), however it's declared: a program has one app (App.rememberedKeyFor() says so too). So it holds before the editor's first parse, while the program runs from a kept compile.

Not one of a kind: a type declared with an article (a home is a page, a card is a view), even when the program happens to make only one, e.g. Counter's "counter" is a new counter: another could be made.

Then its changes go to its type without asking (the switch's All), its type's Events / Actions / Tests cards show as All Cards' do, and no notice says All Solitaires or each solitaire; a change it can't keep still says why.

The code: Inspector.isOneOfAKind().

a one of a kind (the app, `solitaire is an app`) gets no This | All switch: its changes go to its type without asking, and nothing says All Solitaires
