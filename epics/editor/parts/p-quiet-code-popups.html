Nothing pops up by itself. When asked for, a popup speaks plainly and wears the app's look.
  1. Nothing shows by itself: the parameter popup is off by default, and so are the pinned lines at the top of the code. Both can still be switched on in the code settings.
  2. The ⌥ hover speaks plainly: the plain sentence and its description. The heading stops being a rule's name such as bare_type_arg.
  3. The compiler's words (what it matches, what it compiles to, the compiled code) move behind a new code setting, off by default.
  4. VS Code's extension uses the same language server and keeps the fuller hover, since its people are programmers. It's one option on the one hover, not a second way of building it.
  5. The look: the code editor's popups take the surface, type and radius of a Spell UI popup, from the theme. They stop being Monaco's dark box, using the --ui-popup-* values in the code editor's one stylesheet.
  6. Words: any new label goes in the language server's texts, in English and Spanish.

How it's checked: a headless script types put in Solitaire and sees no popup, then holds ⌥ over a word and sees only plain words, with pictures in Glass and Fruity. The hover's tests are updated.

Left out: the suggestion list on Ctrl+Space keeps its behaviour, and gets only the shared look.
