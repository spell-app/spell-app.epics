Proposed fix: the cause is traced.

  • On a reload the compile behind (editor.compileBehind()) runs the project's parse. If a parse was started again while it ran, the step the old run left over moved the new run on one step too many, and skipped one.
  • The compile behind then threw (reading 'parser' in devtools), so nothing was parsed till an edit.
  • That step-skipping is what I134 fixed in TaskList, this afternoon: with it, the compile behind parses every time.
