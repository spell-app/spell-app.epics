Found by I66: the editor's own Spell and the running program each mount an app, and each registers the undo keys (UI.keyboard: "Meta+z" registered twice in scope "page").

You asked: "What's the fix for this?"

Looked closer: it isn't a wrong-history bug, only a warning about something done on purpose.

  • The editor puts ⌘Z on the page's keyboard first (editorHotkeys()); the running program puts its own on after it, as every Spell app does (core's listenForUndoKeys()).
  • The newer one, the program's, is asked first, and it asks the editor before its own history (core.pageUndoKey): in Edit the editor's undo wins (the side bar's change, the code), in Run the program's. A key it doesn't take goes on to the editor's.
  • Spell UI's keyboard warns whenever two registrations claim one key in one scope, so this layering shows as "registered twice".
  • Spell UI's UI.keyboard.register() takes an option saying a registration goes over an earlier one on purpose (over: true): no warning for it; a handler returning false still passes the key on, as now.
  • The program's undo keys register with it. Two registrations that don't say so still warn.
  • A test: the editor and a running app both registered, ⌘Z in Edit undoes the editor's change, in Run the program's, and the console stays quiet.
  • Nothing changes in what ⌘Z does; the two warnings go. Press Do this to have it built.
