For P37 · Mermaid Drawings: the new <ui-mermaid-diagram> tag draws with Mermaid, a library Spell doesn't have yet. The house rules ask you before any runtime dependency is added, so this is that ask, and which of Mermaid's two builds to take.

Mermaid comes two ways. The main package has every diagram type, and since version 12 (September 2026) it includes ELK, the layout engine that now lays out flowcharts, state, class and ER diagrams by default, with tidier lines than the old one (Dagre). The "tiny" build is about half the size, and leaves out ELK, mindmaps, architecture diagrams, maths in labels, and Mermaid's own splitting into small files.

Either way it loads only when a page draws a diagram, in files of its own: a page with no drawing loads none of it. The cost is on pages that do draw, and in the size of the installed package.

  • Every diagram drawn the way Mermaid's own site and GitHub draw it today.
  • Mermaid splits itself by diagram type, so a page with one flowchart loads the flowchart's part, not all 37 types.
  • Cost: the biggest download on a page that draws, the first time (cached after); its exact size measured with Spell UI's bundle measure as the phase builds.
  • About half the size.
  • Cost: flowcharts fall back to the older Dagre layout; mindmaps and architecture diagrams don't draw at all, and show an error.
  • Cost: the tiny build is one file that sets a global, not a module, so it can't be split by diagram type.
  • Small for the simple diagrams, ELK only when it's wanted.
  • Cost: two packages to keep in step, and mindmaps and architecture diagrams still missing.
  • The phase is dropped; Mermaid stays only in the READMEs, drawn by GitHub.
  • mermaid (12.3 or later) added to the kit's one install, and to the published package's list of optional dependencies, so the spell and epic commands don't install it
  • every diagram type draws, laid out by ELK where Mermaid does so by default
  • pages without a drawing unchanged, checked with the bundle measure
