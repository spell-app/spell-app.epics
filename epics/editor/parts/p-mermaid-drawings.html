Spell UI has no way to draw a diagram from text: a flowchart, a sequence or a timeline written in Mermaid shows up only as code.

Your words (Owen, 2026-11-18):

"new spell-ui component: `mermaid` drawing which takes mermaid format input and draws in various styles. Check the latest features of mermaid and make the phase description but don't write it."

What you'll see once it's built:

  • A new Spell UI tag, <ui-mermaid>, that draws a diagram from Mermaid text.
    • The text goes inside the tag, or in a file it points to with source, as <ui-markdown> and <ui-code> already take theirs.
    • It redraws when the text changes: typing in the editor, a script setting it, or the file changing on disk.
    • Every diagram type Mermaid has today works, with nothing to turn on: flowcharts, sequence, class, state, ER, Gantt, pie, mindmaps, timelines, Git graphs, C4, quadrant, XY charts, Sankey, and the newer ones (below, "What Mermaid can do today").
  • It draws in Spell UI's own colours, and follows light and dark.
    • Its colours come from Spell UI's theme: the same purples and inks the rest of the page uses, read from the page, so a theme you edit in the theme editor reaches the diagram too.
    • Switching the page to dark redraws it dark; no second copy of the colours to keep in step.
    • The look matches the README pictures yarn mermaid:pretty already draws, because both read the one set of colours.
  • A look attribute picks the drawing style. Mermaid draws three ways: plain lines (classic), sketched by hand (hand-drawn), and a flatter, softer style (neo). All three are offered, classic by default (Q51, B).
  • A theme attribute picks the colours, beside the look.
    • spell, the default: Spell UI's own colours, read from the page, following light and dark.
    • Mermaid's own presets beside it: default, neutral, dark, forest, neo, neo-dark, redux, redux-color, redux-dark and redux-dark-color, the ones the aside below lists.
    • A preset with a dark twin follows the page too: default draws as dark on a dark page, neo as neo-dark, redux as redux-dark, and redux-color as redux-dark-color.
    • A preset with no twin, neutral or forest, draws the same in light and dark; so does a dark one named outright, such as neo-dark.
    • Mermaid's base isn't offered by name: it is what spell is built on.
    • A theme written into the diagram's own text still wins, as it does on GitHub.
  • A page without a drawing pays nothing. Mermaid is big (megabytes), so it loads only the first time a page draws one, in a file of its own, as the code highlighter and the Markdown engine do. Which Mermaid build, and whether the better layout engine (ELK) comes with it: Q50. Where it loads from, Spell UI's own files or a public CDN: Q53.
  • Bad text shows a readable error, not a blank box or Mermaid's bomb picture.
    • It says, in plain words, that the diagram couldn't be drawn, which line Mermaid stopped at, and what it expected.
    • The last good drawing stays underneath while you're typing, so a half-typed line doesn't make the diagram flash away.
  • Safe with text you didn't write. It draws in Mermaid's strict mode: any HTML in the labels is shown as text, and clicks that run code are off.
  • It's a real Spell UI component, in English and Spanish.
    • Its own docs page, with examples of each kind of diagram and each style, light and dark, and one diagram drawn in every theme, side by side.
    • Its vocabulary in English, and in Spanish as <es-mermaid> (a product name, kept as <es-markdown> keeps Markdown, with "sirena" and "diagrama" among the names it is found by), with its attributes, the look and theme names and the error's words.
    • A property editor layout, so it can be placed and set up from the editor's side bar like any other tag.
    • Whether a ```mermaid block in Markdown is drawn by it: Q52.
  • A new dependency, Mermaid itself: the house rules ask you before any runtime dependency is added, so this phase waits on your OK in Q50.

Mermaid went to version 12 in September 2026, and has had a release roughly every three weeks since. What matters for this tag:

  • Diagram types, 37 in its docs. Besides the long-standing ones, the newer ones:
    • architecture (cloud services and how they connect, with icons), block, packet (network packets, bit by bit), kanban, radar, treemap
    • from 11.13 on: Ishikawa (fishbone), Venn, Event Modeling, Wardley maps, a tree view of folders, Cynefin, railroad (syntax) diagrams, swimlanes
    • 12.0: UML use case diagrams, and "agentflow", for drawing AI agents' steps
    • many of the newest are still marked beta: their keyword ends -beta (venn-beta, swimlane-beta)
  • Themes: default, neutral, dark, forest, neo and neo-dark, the newer redux, redux-color, redux-dark and redux-dark-color, and base, the only one whose colours you can change, through themeVariables (primaryColor, lineColor, fontFamily and dozens more).
    • Since 12.0, flowcharts, sequence, class, state, ER and a few more default to redux-color and the neo look; everything else to default and classic.
    • Since 12.0, theme, look and layout can be set per diagram type.
  • Looks: classic, handDrawn (sketchy lines, drawn with Rough.js; a seed keeps it the same each draw) and neo.
  • Layout engines: since 12.0 ELK is built into the main package and is the DEFAULT for flowcharts, state, class, ER and more; Dagre (the old default), a grid, cose-bilkent (mindmaps), a new layered one (beta) and tidy-tree (a separate package).
    • The "tiny" build is about half the size, and leaves out ELK, mindmaps, architecture diagrams, maths (KaTeX) and lazy loading; ELK can be added back to it as a separate package.
  • Icons: icon packs from Iconify (registerIconPacks()), each loaded only when a diagram uses it; architecture diagrams and flowchart icon shapes use them.
  • Settings in the text itself: a front-matter block at the top (---, config:, theme, look, layout, themeVariables), or the older %%{init: ...}%% line, which yarn mermaid:pretty writes today.
  • The calls a tag needs: mermaid.initialize() once, with startOnLoad: false; await mermaid.render(id, text), which gives back the SVG as text; await mermaid.parse(text), which checks the text without drawing and throws a readable error; mermaid.detectType(text).
  • Security: securityLevel is strict by default (HTML in labels shown as text, clicks off); antiscript, loose and sandbox (drawn in an iframe) loosen or wall it off.
  • Also new in 12.x: flowchart edges can carry a step number and animate a dot along them in order (12.3, hidden for reduced motion); mindmaps coloured by depth (12.2); a collapsed view for subgraphs (11.17).
  • Needs: since 12.0, ES2024 and Safari 17.4 or later, which every browser Spell supports already meets.
