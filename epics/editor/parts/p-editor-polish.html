  • I50: the selection outline never shows while the loading screen is up.
  • I51: moving the code cursor to another line, by click or arrow keys, moves the outline with it, and it goes away on a line that draws nothing.
  • I52: clicking anywhere in a to draw block's markup outlines that element in the app, inside a drawn thing's own drawing too.
  • I53: pasted code matches the indent where it lands.
  • I54: typing <act offers action by itself.
  • I55: typing a property of a thing, or an attribute of a tag, shows what fits and what each one is, as you type; hovering a tag or attribute says what it is.

The outline follows the code cursor and waits for the page. A paste takes the indent where it lands. Tags, attributes and properties offer help as they're typed.

  • By themselves only for a tag after <, an attribute inside a tag, and a property after its / 's / of, each row with its description.
  • Everywhere else still quiet: Ctrl+Space, as P4 chose.
  • Why: it's the help your notes ask for, without the "annoying" popups P4 took away.
  • Turn on Monaco's own as-you-type list as the default: every word typed shows a list.
  • Simplest (a default changes), but undoes P4's quiet code.

2. The cursor lands on a line that draws nothing (I51): what happens to what's selected?

  • The outline goes, and the properties card shows nothing selected, as a click on the app's empty space does.
  • Why: one selection everywhere (P11); what the card shows always matches the outline.
  • The properties card keeps what was selected; only the ants hide until the cursor is on a drawing line again.
  • Keeps the card for editing while reading code, but the card and the app disagree.
