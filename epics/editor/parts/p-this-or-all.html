A "This card | All cards" switch in the row that names the thing. Each field shows where its value comes from.

Source Places counted the built-in projects: in Solitaire, 61 of 80 parts are loop-made. A loop-made thing starts on "All cards", as already planned. Now that each part knows how many share its place, that check is Inspector.writtenPlaceOf().

  1. The switch. A small This card | All cards beside the name in the properties card's first row, worded from the thing's type. It's a segmented <ui-menu>, the same widget as every other choice; it collapses when the card is narrow, and adds no row.
  2. Which side it starts on: "This" for a thing with its own tag, otherwise "All". The count from Source Places may move this default.
  3. All cards edits the type's default through the source edit, and every card follows on screen.
  4. A thing made in a loop starts on "All cards", and "This card" stays open to play around. Its fields edit this one running thing and write nothing, under one quiet note in the card: "Changes to this card can't be saved." They go when the program restarts. No separate try-out control.
  5. Where each value comes from. <ui-property-editor> learns this, so any property editor can use it, and the editor adds no CSS of its own:
    • set here: a dot, and a Reset that removes it from the source
    • inherited: quieter, its tooltip naming the type
    • worked out: read only
    Today it compares a value with the default only, so the Inspector tells it the home.
  6. A template's own <property-editor> works the same way, since these are its fields.

Checked by: in Solitaire, a card's suit edit goes to the template, and the try-out writes nothing; a tag in the source keeps its own value on "This"; a component test of the three looks; the designer review.

Left out: making a new type from one thing's changes, and many selected at once (One Selection).

  • Where to see it: select a card in Solitaire: a This card | All cards switch sits in the row naming it, with no new row.
  • This, made in a loop: fields edit the running card and write nothing, under one note, "Changes to this card can't be saved."
  • All, made in a loop: read only where the code gives no value to change, saying where each comes from, with a button to the line. So cards start on "This", not "All" as planned (J25).
  • This, with its own line: a value on the line is edited there, one not on it is added, a dot marks what's set here, and a reset takes it off, as its own undo step.
  • All, with a literal default: set its count to 0 changes in place, and things still holding the old value follow.
  • New in Spell UI: <ui-property-editor origins>, so any property editor can say where a value comes from.
  • Fixed: pressing Run keeps a game in progress going, unless the program changed (I6). Read-only button rows no longer take presses.
  • Not tried: a slider drag, the static build, a real Mac, and Spanish text in the running editor.
