Found by I66: SpellProject.writeTitleWords() asks for Solitaire.es.names.json5 and spell-editor.es.names.json5, which don't exist.

Ask only for names dictionaries the project has: the project's index says which.

  • Why it asks today: each compile's last step looks for a titles dictionary in every language the program isn't written in (writeTitleWords()), by loading <Project>.<lang>.names.json5 blind. Most projects have none, so the browser shows a 404 for each.
  • The fix: the project's index, which every reader of a project already loads (the page server, the static build's copy, the disk reader under the spell command and VS Code, all from spaces' getIndex()), gains a list of the languages it has a names dictionary in, namesLanguages, found beside its project file.
  • The compile loops over that list, not every language: no list, no request. A project with a dictionary still gets its title words.
  • Not chosen: an "optional" read the server answers 204. It still sends a request per language on every compile, and needs the same change in the static build's and the disk reader's answers.
  • Tests: a project with namesLanguages: ["es"] and a dictionary gets its Spanish title words; one without asks for no names file. getIndex() lists a dictionary beside the project.
