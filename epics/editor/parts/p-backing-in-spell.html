That TypeScript gets rewritten in Spell, piece by piece.

The TypeScript behind the editor's pieces in Spell, smallest and least tangled first:

  1. The Run menu: seven fixed rows, two greyed by whether you're inspecting. Moves to Spell as File did: the rows, their order, keys and greying in Spell, what each does and says in TypeScript, by name.
  2. The Edit menu: fixed rows, plus the selection's part actions as one named row the editor fills in. Moves the same way.
  3. The View menu: rows ticked by what's showing, plus the Inspector's cards as one named row. Moves the same way. (J50: these three were left in TypeScript in P16.)
  4. A file tab's right-click menu: Duplicate, Rename, Delete. Moves into the file tabs' Spell as a menu.
  5. The Program panel's tabs: which tabs, their icons and order. Could move; their titles have the same gap as below.
  6. The panes' sizes for each mode: which columns show in Run, Edit, with compiled code or the Inspector, and the remembered sizes. Tied to the browser's storage and the page's width: stays.
  7. Which files there are, and what's showing: the editor's state, which Spell can't read: stays.
  8. What fills each pane: the code editor, the running app, the Inspector, the Program panel's output: Monaco and the runner, stays.

What Spell can't say yet (sent to the language epic):

  • An action's title, apart from its name, in each language: "Compile and Run", "Duplicate Solitaire…". So every menu's titles stay TypeScript, read by the action's name.
  • A menu of menus: a menu bar is one menu of actions, so File · Edit · View · Run · Help as a bar, and a sub-menu like More Examples ›, can't be written.

  5. Likely to stay in TypeScript longest: the code editor's wiring, the compile and run machinery, and anything that runs before Spell has loaded.

  7. Left out: opening the editor inside itself (P22).
