Each action's frame ends however it ends (a try / finally in the debugging build), so stepping over or out of an action's last line stops on the next line of the action that ran it. When nothing ran it (a click's handler), the game simply plays on, as VS Code's does.

Which actions ran which is worked out as they're called (the last line that ran, until the browser's turn ends): a line that calls two actions while another action runs beside it, with a pause between, could show the wrong caller. None of the examples do.
