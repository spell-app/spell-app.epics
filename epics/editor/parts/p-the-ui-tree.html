Three hand-built trees exist, with no filter, no arrow keys, placeholder icons and rows that read as raw markup.
  • A new <ui-tree> in Spell UI, with many selected, arrow keys and rows that open and close, for Spell apps to use too.
  • A filter behind a search icon in the header: no new row until you ask for it.
  • An icon for each kind of thing: each component's vocabulary gets one, and a type can name its own.
  • Rows in plain words: "Moves: 0", not <ui-item "Moves: 0" />.
  • Things and Templates fold in, and stay available in the Program panel for developers.
  • The Inspector's tree has no tabs on it.
A new <ui-tree> replaces them. Things and Templates fold into it.
  1. The widget. A new <ui-tree> with its vocabulary, docs page and tests: rows that open and close, on Disclosure (the open attribute, and ui-opening and ui-opened), many selected through P11's rule with the menu's own choose="many", and tree keys built on RovingTabindex (arrows, Home, End, left and right to close and open). Rows take an icon, a label and actions on the right.
  2. Icons. Each component's vocabulary gets an icon field (vocabulary.types.ts; every *.en.ts), and a spell type can name its own. P13's palette uses the same icons.
  3. Plain rows. A row says what a person would: "Moves: 0", "Card · ace of spades". The raw tag stays in the tooltip.
  4. Filter. A search icon in the header's right slot opens a field in that same row. Matches keep their parents. No new row at rest.
  5. One tree in the Inspector. Views and undrawn Things share it, the things in a group of their own. Its tabs go, which leaves the header for the filter and actions.
  6. Developers keep theirs. Things and Templates move to the Program panel, off by default, on the new tree. So the three hand-built trees go, and their CSS shrinks.
  7. Checked by: component tests with keys; a headless script for filter and many selected in Solitaire; yarn measure in ui; the designer review.
  8. Left out: rethinking Things and Templates (P19); dragging rows in the tree, which Add And Move adds, on the lifted drag.
  • Where to see it: the Views card: one tree, no tabs, rows in plain words ("Menu", "Moves: 0"), an icon per kind of thing, and a magnifying glass that opens a filter in the same row.
  • How a row is written, such as <ui-item "Moves: 0" />, is in its tooltip.
  • What the program made but doesn't draw is a group of its own, closed to start. Things and Templates are tabs in the Program panel now, for developers.
  • New in Spell UI: <ui-tree> and <ui-tree-item>, with tree keys, many selected, and a filter. Every component names an icon in its vocabulary.
  • The filter took 0.4ms on Solitaire's 82 rows.
  • Rough: a row for a thing no drawn part reaches does nothing on click. The filter finds only rows already drawn (T24).
  • Not tried: a real Mac, a screen reader, the Program panel's tabs by eye, and the selected row's look.
