  1. Where it is today. The Events band lists a part's events and abilities, found by reading the source text (eventsInSource()). Their code sits in a growing text box, and what's typed is only remembered in the editor's preferences, never written to the file. Actions have their own band, of run buttons (InspectorActions).
  2. A slice of the real file. Each row's code is a small Monaco editor on the SAME model as the file's code editor (SpellModels), showing only that handler's lines, the rest hidden. So the language service sees the whole file: completions, hovers and errors are the file's. Reuses MonacoEditor; nothing in the app hides lines yet, so the slice is new, kept in one place for the notebook to use later.
  3. Where each row's lines are. From the parser's source places (P7, P.SourceMarks), not from reading the text with patterns: the handler's first and last lines, kept right as the file changes. eventsInSource()'s text reading goes once the places cover what it finds.
  4. Typing. An edit is an edit to the file: one undo history with the code pane and the side bar (EditorHistory), compile after the usual 10 seconds or at once with ⌘Enter, and Edit Without Redraw keeps the app running. Clicking a row follows along (editor.followed).
  5. New handlers. The band's "+" writes an empty on click in its place through the side bar's source edits (SourceEdits, P9), then opens its slice with the cursor inside. The remembered-code preference and its migration of what was typed go.
  6. Actions. The type's actions are listed in the band with their code, edited the same way: see the choice below for where. Spanish programs get their own words (al hacer clic).
