Asked epic data on 2026-10-31 for sample swapping, where a value came from, and the write path.

Epic data answered in its Overview's "What the editor needs" (o9), a proposal with nothing built yet:

  • A sample is one more place, swapped in while designing, with the declaring line untouched.
  • Places.originOf(thing, property) answers the place, whether it can be written, and where it's declared.
  • A side-bar edit of a data value is a plain property set in one undoable step, sent when the edit is committed, not a source edit.
  • No Spell program can declare a place until its words land, after epic language's waiting work, so P15 waits for that.

Correction from epic data, its Q16: a saved thing's identity is its id, and a key means a secret. So Places.originOf() returns id: "r-12".

Epic data built this, on main, in its Samples And Origin phase. The real names, replacing the proposal's:

  • Samples: useSample(places, name) and useRealPlace(places, name). The declaring line doesn't change.
  • Made-up rows: pass rowsFromType, using rowsMadeFrom() and things.classNamed().
  • Where a value came from: places.originOf(thing, property, { identity }), on the instance. A saved value answers its place, kind, collection, id, canWrite, whyNot, isSample and declaredAt; a worked-out one { workedOut: true, canWrite: false, readsFrom, declaredAt }; a value from no place undefined.
  • Editing: things.startEdit(thing, property, { title, history }), then .set(value) per keystroke, then .commit() on Enter or leaving the field, or .cancel(). Pass the editor's own UndoStack as history, so the program's history records nothing.
  • Commit on leaving the field: an edit left open across a sample swap writes to whatever is behind the name by then.
