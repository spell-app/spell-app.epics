Owen, on the edit scope page's Q3 (2026-11-04): "I'm thinking that there is utility in maintaining the compiler data (maybe even the AST) semi-persistently. E.g. if you are loading a library, not having to compile the library code each time will make changing the app's or page's code run faster, no? As part of this, we could keep track of what types/files a given file actually uses ... What are the rules for what can modify something else? E.g. I'd think it is not possible for Solitaire to make changes to card's compile path without explicitly saying a card:... and extending it. Is this the case?"

  • Keeping compile data: yes, and some of it is kept already.
    • Within one project, each file's parse is memoized and an edit re-parses incrementally; a library imported as compiled isn't parsed at all: its <Project>.declarations.json5 is read instead.
    • What isn't kept: a library imported as source parses again with the app, and nothing survives a page reload. Keeping parses on disk, keyed by each file's text, would make an app's edit faster when it imports source libraries.
  • What each file uses: not tracked today. The compiler knows it as it resolves each name, so the declaration marks this phase builds can record, per declaration, the file it's in and the types it reads: card uses nothing, deck and pile use card, solitaire uses all. That's the graph a smart cache, or "what does this edit redraw", needs.
  • What may change a type: no, today it's looser than that.
    • Any file of the project may add to a type: to move a card to a pile: in Pile.spell becomes a method of Card (the compiler moves it into Card's body, hoistClassMembers()).
    • A project importing another may add members to the imported type too: they're patched onto it (Card.prototype.play = ...), with no a card: needed.
    • Only the project's own types are re-built; an import's type is changed only by what's added onto it.
 The editor's marks phase records the graph as it goes (little extra work). Keeping compiles between runs, and whether adding to another file's or project's type needs an explicit a card:, are language decisions: sent to the language epic as a request. Faster edits sooner, but the editor epic would own parser internals it doesn't otherwise touch. Smallest now; the graph is recomputed when someone needs it.
  • The declaration marks phase records, for each declaration, its file and the types it uses.
  • language gets a request: compile caching across reloads, and the rule for adding to a type from another file or project.
