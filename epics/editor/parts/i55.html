Your note here (an attribute written color="|", its words shown at once) is built in I70, with the tags: choosing color after <segment writes color="|" and lists its colours; fluid or disabled, which take no value, are written by their name alone; nothing is doubled when =" is already there. VS Code gets the same through the language server (M27).

Found: help for a thing's property exists, but only in places you don't see while typing; help for a tag's attributes doesn't exist at all.

  • A thing's properties: hovering turn in set its turn to says "property turn of TicTacToe · a text, Whose turn it is: X or O". But hover needs ⌥ held, and the suggestion list (Ctrl+Space only, I54) gives each property just "property of Square", with its description hidden (details off by default).
  • A tag's attributes: nothing. <button col offers the program's names (tic-tac-toe, it ...), not color; hovering color or fluid on a button shows nothing.
  • What's there to use: Spell UI already writes every tag's attributes, values and descriptions for VS Code (its HTML custom data, made from the components' vocabularies), and the parser knows each Spell tag's ui-* name in English and Spanish. 
<button col             -> tic-tac-toe, it, square, tictactoe, object ...
set its tu              -> mark, color, label, board, turn ...  ("property of Square")
hover color (on <button>) -> nothing
hover turn              -> property **turn** of TicTacToe · a text
                           Whose turn it is:  X or O
  • Typing a property (its tu) or an attribute (<button col) shows a list of what fits, each with a line saying what it is.
  • Hovering a tag or an attribute says what it is, like a property does.
