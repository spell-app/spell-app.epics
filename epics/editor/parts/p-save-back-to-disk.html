An app can read a file you pick or drop, but can't save back to it: a browser refuses a file place with no server side.
  • Your words (Owen, 2026-11-19, from epic 's File Upload In Spell, sent as r6): "Ah, we'll want to think about storing file handles for apps that save to the disk."
  • An app whose data is a file on your computer opens it once, picked or dropped, and every later save goes back to that same file: no download, no second copy in your Downloads folder.
  • The app remembers which file it was, for each app and each of its files, so after a reload or the next day it still saves back to it.
  • After a reload the browser asks again whether the app may use the file: you see one short line with a button, never a surprise prompt, and your data shows from the copy kept on this device meanwhile.
  • In Safari and Firefox, which can't save back to a file, the app still works: your changes are kept on this device, and saving hands you the file to download, with the same name.
  • Spell has words for it, once you've agreed them (the words question below): a place that is a file on your computer, and the actions to open one and save back to it.
  • It's one more kind of place, beside a web server, a sheet and a data folder: the same reading, saving, pending changes and copy on this device every place has.
  • A file you pick or drop keeps its handle, remembered for each app and file in the browser's database, so a save goes back to that file, after a reload too (Chrome and Edge).
  • Elsewhere the changes stay on this device, and a save downloads the file.
  • A new kind of place, with Spell words you agree first.
