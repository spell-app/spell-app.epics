Proposed fix

  • The words list stays, with ONE row on top for an attribute that has a picker: Pick a color… on color="|", Pick an icon… on icon="|" (Spanish: Elegir un color…, Elegir un icono…).
    • Why the row, not the picker by itself: the list already opens there (I70), so a picker opening too would fight it for the keys; a row is one more choice in the list people are already looking at, and typing still filters the words.
  • Choosing it opens the picker at the cursor: the color palette (Spell UI's hues, each a chip) or Spell UI's icon picker, searching.
  • Picking writes the value between the quotes, as one undo step, the caret after the closing quote; Esc, or a click outside, closes it and changes nothing.
  • Which attribute takes which picker comes from Spell UI's vocabularies, through the help the language service reads (ComponentAttributeHelp.picker): an attribute whose values are the hues takes the palette, one of kind icon the icon picker. No tag is named. Spanish (color, icono) the same way.
a colour or an icon attribute's value is picked at the caret: its words list starts with 'Pick a color…' / 'Pick an icon…' ('Elegir un color…' / 'Elegir un icono…'), which opens the colour palette or Spell UI's icon picker; a pick writes the value as one undo stepthe Pick a color / icon row is built where the value's words are, not in the statement completions (a temporary-index commit had put it in the wrong function); Inspector's docstring shows I108's trail words
