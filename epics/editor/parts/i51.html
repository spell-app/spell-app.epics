Found: two rules from Code Follows Along keep the outline where it was.

  • Only a CLICK on a line moves what's selected. Arrow keys and other cursor moves don't (that was J43).
  • A click on a line that draws nothing leaves the selection as it was, on purpose: "most lines draw nothing".
  • So a newly added item, selected once it's drawn, keeps its outline while the cursor goes anywhere else.

Seen headless in Tic-Tac-Toe: after clicking the New game button's line, arrowing down six lines, and clicking a comment, a for line and set its turn, the button kept its outline every time. 

// editor.ts:  only the mouse follows
inputEditor.onDidChangeCursorSelection((event) => {
  editor.onInputCursor("cursor")
  if (event.source === "mouse" && event.selection.isEmpty())
    editor.followCodeLine(event.selection.positionLineNumber)
})

// Inspector.tsx, selectWrittenAt():  a line that draws nothing changes nothing
if (written.length) Inspector.selectAll(written)

What should happen to the selection when the cursor lands on a line that draws nothing is a choice for you: it's in the phase's Choices.

  • The selection follows the cursor, by click or arrow keys, but not while you type.
  • On a line that draws nothing, the outline goes away (recommended).
