P30 · CodeMirror Test: what it showed

Solitaire's Spell in CodeMirror 6, beside today's Monaco, on one page.
A test, not a switch: Monaco is still the editor, and only the test page reaches the new code.

  • The page: /demo/codemirror.html on the worktree's editor (its address is in .spell-server.editor.json).
  • Its bar: Edit, Diff (Publish's two sides), Compiled (the javascript); Solitaire.spell or Card.spell; English or Español; light or dark.
  • Nothing is saved: the page answers every write itself.
  • The code: spell/app/app/ui/codemirror, 2,217 lines with its CSS and the test page.

The verdict first

Move the editor to CodeMirror 6, everywhere, as an epic of its own.
The bubbly look became real elements in the lines, with no layer to keep lined up.
It is a sixth of Monaco's size, draws sooner, and types a little faster.
Monaco gives the compiled TS / JS / Python views only colouring today, which CodeMirror gives too: keep it nowhere.

What was easy

  • The look. The page's own bubbly.css rules work on CodeMirror's marks as they are:
    white pills, curly quote marks, bold names, italic values, dotted underlines, inverted code pills.
  • Padding round a pill is the pill's own padding: CodeMirror measures what the browser drew, so the caret still lands on the letters.
  • Bands are a mark round a head's words; rails are a stripe per enclosing block on each line's background;
    a foot is a thin block widget under the last line. No layer behind the text, no injected text, no view zones.
  • The layout code is 342 lines (CodeMirrorBubbly), from the same SP.BubblyLayout and SP.BubblyStretches Monaco reads.
    Monaco's side of the same job: SpellBubbly, BubblyMarks, MarkupMarks, TextMarks, FoldArrows, about 2,300 lines.
  • The language service, in-process, as Monaco and VS Code use it: suggestions, hover, problems, folding, go to definition (F12, ⌘-click), code actions. 378 lines.
  • Find and replace, folding and the merge view come with CodeMirror; each change in the merge view is taken by its arrow, and ⌘Z puts yours back.
  • CodeMirror has no right-click menu of its own, so Spell UI's is the only one: Cut, Copy, Paste, Go to Definition, "Make it text", Find.
  • Typing helps reuse Monaco's own line readers: Enter keeps the indent and goes in after a : or an opening tag; <action writes <action "|" />; its opens a name's quotes.

What was hard

  • An editor made in an element that isn't in the page yet put its style sheet in that detached element:
    the editor drew with none of CodeMirror's CSS. Fixed by giving it its root once it's in the page.
  • Two marks over exactly the same stretch nest in no set order: a quoted name's pill came out inside or outside its marks at random. Fixed by one mark per stretch.
  • A found word or a problem cut a pill in two, until the look's marks were given the lowest precedence: CodeMirror draws a lower source's marks outside a higher's.
  • A foot (a block widget) can't come from a view plugin: the layout lives in the editor's state.
  • bubbly.css's "laid out as the editor" section zooms a page's drawing; it had to leave this editor out (J127).
  • The selection is drawn behind the text, so the bands hid it: it's drawn over the text now, see-through.
  • Left for a real move: tags with pointed ends as Monaco draws them, a head's description at its band's right end, HTML files drawn bubbly, five of the nine typing helps, rename, signature help, the value picker and choices, link clicks, a file per editor state.

Translatability

  • CodeMirror asks for every word it shows through one setting, EditorState.phrases:
    about 30 phrases for find and replace, folds, suggestions, problems and the merge view.
  • The test hands it a Spanish table (CodeMirrorTexts), swapped in live by the bar's Español.
  • Monaco's words are English unless its translated bundles are swapped in when the app is built:
    "3 hidden lines" and T75's "Revert Change" stay English in a Spanish page, beside CodeMirror's "10 líneas sin cambios".
  • Our own words (the right-click menu) are AppTexts' in both.
  • Pictures: find panel in Spanish, merge view in Spanish beside Monaco's, menu in Spanish.

"Seems like we should keep Monaco for TS/JS/Python views?"

No: Monaco gives those views nothing CodeMirror can't, and keeping it costs a second editor.

  • Where the editor shows TS, JS or Python: only the compiled-code pane (CodeOutput), and it's read only (readOnly: true), for js/solid, ts/solid and py.
  • No project has a hand-written .ts, .js or .py file: none in @spell's projects nor in your spaces.
    What's beside a source is written by Spell (.lib.ts, .app.py), and edited, if ever, in VS Code.
  • What Monaco gives them today: colouring only. monaco.ts registers TypeScript and Python as Monarch colouring, "none of them needs a language worker":
    no TypeScript worker, so no types and no IntelliSense. CodeMirror's lang-javascript (TypeScript too) and lang-python colour the same, for 45 KB.
  • Keeping both would mean: 4.6 MB more to load, two looks to keep in step (Monaco's themes and CodeMirror's CSS), two find panels, two right-click menus, two sets of keys, and Monaco's words in English.
  • On the test page, Compiled shows Card's javascript in both: light, dark.
  • If people ever edit hand-written TypeScript in the editor and want its types, load Monaco then, lazily, for that file alone.

What moving over would take (a rough phase list)

  1. The core: a CodeMirror twin of SpellModels (a state per file, its undo, parses as typing pauses, problems), the code pane on it behind a setting.
  2. The look whole: tags as Monaco draws them, descriptions at the band's end, HTML files (MarkupMarks), the look turned off, page files coloured.
  3. Typing: all nine helps and "make it code / text", on the pure helpers lifted out of SpellTyping.
  4. Language features: rename, signature help, highlights, the value picker and choices, link clicks, error hover, accent fixes.
  5. Every place Monaco is: the Inspector's Code card, Publish's diff, the compiled-code pane, notebooks, <spell-editor>, CSS, markdown and HTML files.
  6. Keys, menus and words: EDITOR_HOTKEYS, the code pane's "..." settings, the find panel's look, Spanish.
  7. Tests and clean-up: 15 of the 35 page tests reach into Monaco; then Monaco, its worker and CodeThemes go, and the build tests change.
