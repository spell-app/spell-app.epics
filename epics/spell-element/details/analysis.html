The long version, with every file, flow and test, is in the plan doc: 1.3, solid-element: how it works now, and folded in. This is the short one.

  • A custom element is a tag a page defines itself: a class extending HTMLElement, registered with customElements.define("ui-button", Class) (MDN).
    • The browser then calls the class's callbacks at set moments: added to the page (connectedCallback), removed, an attribute changed, a form reset ...
  • Every <ui-*> tag is one. But ui doesn't write those callbacks itself: a separate package does, packages/solid-element.
    • It began as a copy of Solid's own custom-element library (@solidjs/element, plus the older component-register), merged and then fixed in 11 places.
    • The plan was to send the 11 fixes back to Solid (its UPSTREAM.md). None was ever sent.
  • What that costs today:
    • to understand one <ui-button>, you read two layers, in two packages
    • ui reaches into solid-element's private record (the STATE symbol) for fresh attribute values
    • most of solid-element's options are choices ui never makes
    • a package of its own: its build, 146 tests, scripts (yarn fork), an import-map entry
  • The idea: write the custom-element code in ui, plainly, and only what ui needs.
  • ui makes every tag through ONE call into solid-element, UIComponent.defineTag(). Almost every option it passes is fixed.
  • Components hear "connected" and the form callbacks by handing solid-element functions: 11 calls in 7 files.

DOMElement.ts · a SKETCH of the shape, not built · 24 lines 
export class DOMElement extends BaseElement {
  readonly internals: ElementInternals = this.attachInternals()

  /** The attribute values, converted:  read fresh by the component's getters. */
  readonly attributeValues: Record<string, unknown>

  connectedCallback() {
    this.restoreUpgradeProperties()
    if (!this.component) this.definition.Component.mount(this)
    this.component?.onConnected()
  }

  disconnectedCallback() {
    this.component?.onDisconnected()
  }

  attributeChangedCallback(name: string, _old: string | null, text: string | null) {
    const attribute = this.definition.attributeNamed(name)
    if (!attribute || this.reflecting === name || this.upgrade?.has(attribute.property)) return
    this.setValue(attribute, attribute.fromAttribute(text), "attribute")
  }
  // ... the form callbacks, renderRoot, dispose()
}

How button.size = "large" and setAttribute("size", ...) reach each other. These are the rules page authors and frameworks see:

  • a getter and setter per attribute, on the class
  • a property write is copied back to its attribute at once ("reflection"); defaults never are
  • a property a framework sets BEFORE the tag is defined is kept, and wins
  • an attribute whose property would hide a member of the DOM element is refused

owner.ts · lookupOwner(), the whole rule · 10 lines 
export function lookupOwner(element: Element): Owner | undefined {
  let next: Stamped | null = element as Stamped
  while (next) {
    const owner = next._$owner
    if (owner && !isDisposed(owner)) return owner
    // a ShadowRoot continues at its host
    next = (next.parentNode ?? (next.nodeType === 11 ? next.host : null) ?? null) as Stamped | null
  }
  return undefined
}
