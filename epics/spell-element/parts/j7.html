When a tag is defined, DOMElement stops with one clear error if an attribute’s property would hide one of the element’s own members (the properties decision, Q6). The error lists only ACCIDENTAL clashes; a property the vocabulary names on purpose may take over a member.

  • an accidental clash: the property is just the attribute’s name camelCased, e.g. hidden or title; the error names each one
  • on purpose: the vocabulary says property: "…" itself, to mirror the browser’s own member, as solid-element allowed:
    • property: "inputMode" on <ui-input> (UIInput.en.ts), forwarded to the native input
    • readOnly, commandFor, closedBy
  • why: with every clash an error, <ui-input> failed to define
  • a new attribute named like a DOM member (title) fails at define time, with its name in the error
  • writing property: "<member>" in the vocabulary takes that member over on purpose
