2026-10-09: <spell-app> and <spell-editor> become a COMPONENT PACK, Owen's bedtime answer (Q22), not the recommended "in packages/app, written like a ui family".

  • built by spell dev pack build, as packages/epics builds its elements
  • a page loads it with <ui-components source="...">
  • tags, attributes and properties stay as they are
  • Where to see it: the two demo pages, which now load the elements as a component pack.
    • The pages: spell-app.html and spell-editor.html, in the app's demo folder.
    • Each is a <ui-root> holding <ui-components source="/element/spell.pack.js">.
    • spell run, and any other page that embeds an app, works as before: it loads /element/spell-app.js directly, with no <ui-root> (J37).
  • Not quite what was planned: Owen picked "a component pack" (Q22), but a pack built by spell pack build could NOT carry these two elements (I4).
    • That tool makes ONE classic script, with no code splitting. So every page would load Monaco (4.2 MB) and the parser: about 1.3 MB gzipped, against 29 kB today.
    • Monaco's worker can't be found from a classic script.
    • <spell-app> loads spell-runtime.js once per app, and shares React with it.
    • The committed output would change by megabytes on every change.
    • Its "is it stale?" check ignores the parser.
  • What was built instead: both tags are Spell UI components, written the way a pack writes its families (J38).
    • spell-app, in the app's components folder, has four parts:
      • a vocabulary (SpellApp.en.ts)
      • the DOM element class, DOMSpellAppElement, with run() and restart()
      • a UIComponent
      • index.ts, which defines the tag
    • spell-editor has the same four parts.
      • Its DOMSpellEditorElement carries compile(), save(), compiled and COMPILE_DELAY.
    • The tag names don't change.
    • A new import alias: spell-app/app/components/*.
    • Gone: SpellAppElement.tsx, SpellEditorElement.tsx, and both element.ts files.
  • The pack itself: yarn build:element, in the app package, writes spell.pack.js.
    • It's a classic script that calls SpellUI.registerPack(); its catalog is made by Spell UI's RootCatalog.
    • Its define() imports spell-app.js and spell-editor.js, which sit beside it.
  • Small differences from before, for someone using the tags (J39):
    • el.assets returns the attribute's text, not a resolved URL
    • an unknown debug value warns, in development
    • both elements use delegatesFocus: false
    • the status messages are vocabulary texts
  • Still rough, or not tried by Owen:
    • The VS Code extension was built (spell app vscode build) but NOT installed. This branch is behind main until P1 + P2 land there and main merges back.
    • spell.pack.js works only where Solid and Spell UI come from dist-element/. A docs page embedding <spell-app> through it would load a second Solid (C9).
    • A page using the pack downloads both elements, the editor's parser too: 236 kB gzipped.
  • spell-solid.js no longer holds solid-element: just Solid and spell-ui/core, 18.8 kB gzipped.
  • Two Spell UI fixes the pack needed (J40):
    • ComponentPacks waits for a pack's define(), when it returns a promise.
    • Vocabulary keeps event names that don't start with ui-.
      • Before, spell-compiled went out as ui-compiled.
      • So <spell-app editor> never heard it.
