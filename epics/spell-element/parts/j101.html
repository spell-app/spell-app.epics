A small generated module, spell-solid-shared.js, picks the page's own Solid and Spell UI core when the page has them, else ours.

  • Every other bundle imports it in place of spell-solid.js.
    • The page has all four module names it needs (SpellUI.packModules): it re-exports every name from them.
    • Else it loads spell-solid.js (await import()).
    • It's written by sharedPage(), in the Solid build.
  • Why: ES imports can't be conditional, and this keeps the choice in ONE file.
  • The docs bundle's packModules gains the root's module, since <spell-app> extends the root.
    • The module: $/ui/components/ui-root.
    • NOT added to the pack builder's list (PACK_MODULES): no pack imports it.
  • A page missing one of the four (an older docs bundle) gets ours, whole.
  • It reads them as the module runs: a docs page's classic bundle, at the end of body, runs before any module script.
  • a docs page embedding <spell-app> loads ONE Solid
    • checked in a browser: spell-solid.js never fetched
    • the component is an instance of the page's UIRoot
  • spell.pack.js now works on a docs page too
