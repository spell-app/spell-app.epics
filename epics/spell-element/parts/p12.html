Four words say "this element is on screen" (open, active, two kinds of visible), hidden and visible behave differently, and only a family can change how an element animates.hidden and visible become one fact with two names, both animated; open and active go from the overlays (a breaking rename, with a new elementSetup.visible for what starts hidden); every element takes a shared animation, its own value overriding its family's, and none or reduced motion turning it off.
  • What this phase is: the redesign Owen asked for in his review of 2026-10-09 (the replies in J57, J58 and J59, all option A), built together, since each leans on the others; it replaces how P8 answered Q28, before any of it reaches main, so main sees one change, not two
  • J57 (A): hidden and visible are perfectly symmetrical: one fact, two names
    • el.hidden is always the opposite of el.visible; writing either one, as an attribute or a property, sets the fact
    • the hidden attribute is where the fact is kept: the browser, CSS and a page before its scripts load all read it
    • the element writes a visible attribute back only if the page wrote one, so a page that only uses hidden never sees visible appear
    • both animate the same way (the element's animation, below); both are instant before the element first draws
    • both written in markup and disagreeing: hidden wins; after that, the latest write wins
    • hidden="until-found" stays the browser's: it counts as hidden, and never animates
    • two breaking renames, for attributes whose old meaning clashes:
      • <ui-divider hidden> (Fomantic's divider with its spacing but no line) gets a new name, e.g. spacer
      • <ui-reveal visible> ("don't clip what overflows") gets a new name, e.g. unclipped
  • J58 (A): one word for "this element is on screen": visible / hidden
    • BREAKING, no alias: open goes from <ui-modal>, <ui-popup> and <ui-flyout>; active from <ui-dimmer> and <ui-loader>; <ui-sidebar>'s and <ui-transition>'s own visible become the shared one
    • <ui-modal visible>, modal.visible = true; the <dialog> and the popover inside still open with showModal() / showPopover(), now when visible changes
    • a new elementSetup.visible: "shown" | "hidden": what an element shows when the page writes neither name; "hidden" for the modal, flyout, popup, sidebar, dimmer, loader and transition, which write hidden on themselves when they connect
    • the base class holds the one controlled isVisible for everyone
    • open stays only where a PART of an element still on screen unfolds: <ui-dropdown>'s menu, <ui-calendar>'s grid, <ui-search>'s results, <ui-accordion open="0 2">'s panels
    • active stays where it means selected or pressed (<ui-button active> ...)
    • events keep their names (ui-open / ui-close before, cancelable; ui-show / ui-hide after the animation); their detail is { visible } everywhere
    • every caller follows: UI.modals, the app's Chooser.tsx and its test, the docs themes picker, the example files, Spell UI's docs pages (modal, popup, flyout, dimmer, loader, sidebar, menu, the kitchen sink), then the site data regenerated
  • J59 (A): a shared animation attribute on every element, the fourth after disabled, loading and visible
    • it names how the element animates when it shows or hides: <ui-transition>'s names (fade, fade up, scale ...) or none
    • an element's own value ALWAYS overrides its family's default (Owen: "Component instances must be able to override their default animation setting!"). Which one wins, first one set:
      1. the element's own animation="slide down" (or el.animation = ...)
      2. none from around it (<ui-root animation="none">, a parent with animation="none"), or the person's reduced-motion setting
      3. the family's default, elementSetup.animation (P8's visibleAnimation, renamed); the overlays keep the look they have now
      4. fade
    • none spreads down through a CSS custom property, --ui-motion: none, so a page turns all motion off with <ui-root animation="none"> or one CSS line; reduced motion is the same switch
    • motion that shows progress is exempt: a loader keeps spinning
    • <ui-transition> drops its own animation spec for the shared one (its markup unchanged)
    • BREAKING: <ui-visibility transition> becomes animation; <ui-sidebar transition> (over, push, uncover) keeps its name
    • a test for each step of the order above
