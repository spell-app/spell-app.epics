@protoMerged (P3) merges each class's elementSetup down the class chain as the class is defined. The agent made four calls in how it landed.

  1. setup is deleted, not kept as an alias:
    • this.elementSetup IS the merged value, so one name is enough
    • every reader now says this.elementSetup, e.g. this.elementSetup.styleSheets
  2. no static setupFor():
    • code outside an instance (the server render, the docs tools) reads SomeClass.prototype.elementSetup
    • why: the merged value already sits on the prototype; a helper would only wrap that read
  3. styleSheets comes first in each elementSetup literal, so it reads the same everywhere
  4. keys merge one level deep:
    • a subclass's styleSheets REPLACE its base's whole
    • to add to them, spread the base's: styleSheets: [...Base.prototype.elementSetup.styleSheets, mine]
    • why: the same as the static it replaced, so no component changed behaviour
  • setup gone, no setupFor(), shallow merge
  • two names for one thing; a deep merge would ADD style sheets where a subclass meant to replace them
  • this.setup no longer exists: read this.elementSetup
  • outside an instance: Class.prototype.elementSetup
  • style sheets inherit as before: replaced unless spread
