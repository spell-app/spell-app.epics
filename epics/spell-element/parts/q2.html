packages/app defines its two page elements, <spell-app> and <spell-editor>, with solid-element’s customElement() directly (a function component, a base class of its own, string / boolean attributes), and its shared Solid file spell-solid.js re-exports all of solid-element (~4.9 kB gzipped). The fold as first written (1.2) only counts what ui uses. The whole write-up: 1.3.9.

Net effect (A):

  • packages/app gains one small base class (~100 lines) for both elements
  • spell-solid.js stops carrying solid-element; element.build.test.ts follows
  • the fold touches packages/app too
  • plain custom-element code: attributes as signals, a property each, properties set before the upgrade kept, render on connect, dispose a microtask after leaving, an error boundary in its JSX
  • loses owner adoption (two page-level elements: nothing provides context around them) and, for their own shadow roots, the event re-targeting fix (their ui-* children keep theirs)
  • one copy of everything: each gets a vocabulary and a DOMElement subclass
  • <spell-editor>, which draws no ui-*, would load ui’s core (~33 kB gzipped) and wait for its runtime and sheets before showing
  • defineSolidElement(tag, attributes, Component) in ui, which UIComponent.defineTag() sits on too: one copy of the plumbing
  • but a generic layer stays in ui: close to solid-element under another name
  • ui stops using it; two copies of the plumbing
  • the package, its tests and yarn fork stay
