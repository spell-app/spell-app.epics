  • Not quite what was planned: Owen picked "a component pack" (Q22), but a pack built by spell dev pack build could NOT carry these two elements (I4).
    • that tool makes ONE classic script with no code splitting, so every page would load Monaco (4.2 MB) and the parser: about 1.3 MB gzipped, against 29 kB today
    • Monaco's worker can't be found from a classic script
    • <spell-app> loads spell-runtime.js once per app, and shares React with it
    • the committed output would change by megabytes on every change
    • its "is it stale?" check ignores the parser
  • What was built instead: both tags are Spell UI components, written the way a pack writes its families (J38).
    • packages/app/components/spell-app/: a vocabulary, SpellApp.en.ts; the DOM element class DOMSpellAppElement, with run() and restart(); a UIComponent; and index.ts, which defines the tag
    • packages/app/components/spell-editor/: the same four parts, with DOMSpellEditorElement carrying compile(), save(), compiled and COMPILE_DELAY
    • the tag names don't change
    • a new import alias, $/app/components/*
    • gone: src/runner/SpellAppElement.tsx, src/spellEditor/SpellEditorElement.tsx, and both element.ts files
  • The pack itself: yarn build:element (in packages/app) writes dist-element/spell.pack.js.
    • a classic script that calls SpellUI.registerPack(), its catalog made by Spell UI's RootCatalog
    • its define() imports spell-app.js and spell-editor.js, which sit beside it
  • Small differences from before, for someone using the tags (J39):
    • el.assets returns the attribute's text, not a resolved URL
    • an unknown debug value warns in development
