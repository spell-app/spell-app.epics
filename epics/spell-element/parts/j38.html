Agreed, and the app's pack can take more families today, without the "spellPack" key. The key and the pack are two different things:

  • "spellPack": { "prefix": "epic-" } in packages/epics/package.json (the only package with it) tells spell dev pack build to build that package the STOCK way:
    • ONE classic script, pack/epics.pack.js, committed, sharing only Solid and Spell UI's core with the page
    • that's what can't carry Monaco and the parser (the issue I4)
  • The app's pack, spell.pack.js, is built by Vite instead (componentPack() in vite.element.config.ts):
    • it lists every family folder in packages/app/components/: a new folder there joins the pack, nothing to register
    • the pack script itself is tiny (the list of tags, and an import() per family)
    • each family is its own module beside it, and Monaco and the parser are lazy chunks those modules load
  • So "light families in the pack, heavy ones as modules" is already how it works. What's missing is J37's point: define() loads every family at once, so each new family makes every page heavier until a pack can load tag by tag.
