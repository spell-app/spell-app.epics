chose a free forget(owner, name) (E.forget(SiteData, "load") in a static reset()) over a reset the decorator registers, because it is one line at the reset site and needs no per-class registry.

  • options: a forget() helper (picked); the decorator registering a resetLazy() on the class; a @lazy({ resettable }) option; keeping the backing field where there is a reset
  • values live in a module WeakMap (object => name => value), not on the object: works on frozen objects and statics alike, no hidden fields
  • forget is typed keyof Owner: a typo is a compile error, but a PRIVATE member can't be forgotten from outside (none needs to today)
  • SiteData / SearchData lose their backing field; reset() says E.forget(X, "load")
  • kept per object it is read on: each instance, or the class a static is called on; a detached call (const f = X.load) would throw
  • undefined is kept (unlike ??=); a throw keeps nothing; a rejected promise is kept until forget(), as before

e.g. in `SiteData`, the `forget` logic belongs in `static url`, not in `reset()`. That way `SiteData.url = xxx` or `= undefined` just work everywhere. so `@resets("load") static url: string | undefined`

Agreed: setting url is the reset. One wrinkle: it has to be static accessor url, not a plain field. A decorator on a plain field only sets its starting value; it never sees a later write. accessor gives it a setter to wrap, as @E.state accessor does.

  • Same story as J15 / J25: a setting that says what it does where it's declared, not in a separate method.

/** The data file, fetched once per page (until `url` is set). */

/**
 * `@resets("load") static accessor url`:  setting the member forgets what `@lazy` / `@once` members `names` kept,
 * so the next read or call makes it anew.
 * - Needs `accessor`:  a plain field's decorator never sees a write.
 * - Every write resets, even of the same value:  `X.url = X.url` fetches again.
 */
export function resets<This extends object, Value>(...names: (keyof This)[]) {
  return function (target: ClassAccessorDecoratorTarget<This, Value>, _context: ClassAccessorDecoratorContext<This, Value>) {
    return {
      set(this: This, value: Value) {
        for (const name of names) forget(this, name)
        target.set.call(this, value)
      }
    }
  }
}
  • "load" is checked: keyof This is the class's statics here, so a typo is a compile error
  • every write resets, even of the same URL, on purpose: tests set the same URL again to start over after a fetch that failed (beforeEach(() => SiteData.reset(DATA_URL)) today)
  • SiteData.url ??= ... in site.ts and brand-docs.ts keeps working: a set before the first load forgets nothing
  • forget() stays: the decorator uses it, and so do @lazy's own tests
