The lint guard against old patterns is ONE oxlint plugin of our own, plus a test of its allowed exceptions, not oxlint's built-in no-restricted-imports plus a grep test.

  • The plugin, the patterns plugin, at the repo root, has six rules:
    • no-solid-effect
    • no-mutation-observer
    • no-dom-element-listener
    • no-untrack
    • no-raw-timer
    • no-function-component
  • The lint settings (patternLint()) turn it on over the component folders (PATTERN_FOLDERS):
    • ui's components and docs components
    • epics' components
    • brand's components
  • Why a plugin: oxlint has no no-restricted-syntax.
    • Only a plugin can spot new MutationObserver, a listener added on the DOM element, a raw timer, or an exported function that draws JSX.
    • One plugin keeps every rule in one place, and the decorator each message names.
  • A kept exception takes two things, the same reason in both:
    • a comment on the line above: // oxlint-disable-next-line spell-ui/<rule> -- <why>
    • a line on the allow-list in LintPatterns.test.ts, which fails on an unlisted one, so each exception is seen in review
  • The test lives in ui's node tools tests: the root has no test project.
