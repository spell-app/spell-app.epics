So it is asked again, as 4 smaller questions, on a new details page: visible and hidden (2026-10-09). What it found first:

  • visible is an attribute on <ui-sidebar> and <ui-dimmer>: they start hidden and animate in
  • <ui-popup>, <ui-modal> and <ui-flyout> say open instead, which means more than shown: focus moves in, Escape closes, ui-open / ui-close can veto
  • the platform's hidden can fail on a ui-* element today: its own :host { display: ... } beats the browser's [hidden] { display: none }, so <ui-segment hidden> may still show. P8 fixes that whatever the answers are

The 4 questions on that page (the recommended option first):

  1. visible and hidden together:
    • A · Two words, two jobs (recommended): hidden is instant and works before scripts load; visible="false" is an animated hide on any element; both set, hidden wins

    • C · visible only; hidden left to the platform, never animated
  2. elements that say open (popup, modal, flyout):
    • A · Keep open; visible works there too (recommended): visible="false" hides the whole element, even while open; nothing breaks
