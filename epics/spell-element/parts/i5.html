An @E.aria getter that throws never applies, and nothing says so: the ARIA property stays empty for good.

  • Found writing the docs inspector (<ui-docs-inspector>, P6).
    • Its @E.aria("ariaLabel") get label() called this.translationForKey(), which reads UI.i18n.
    • UI throws until UI.load() resolves.
  • What happened: internals.ariaLabel stayed null for good.
    • Even after the members the getter read (title) changed.
    • The element drew normally: no :state(errored), no fallback, nothing in the test's output.
  • Where: Reactive.startAriaEffect(), in the decorators' file (Reactive.ts).
    • It's createEffect(createMemo(compute, ...), apply).
    • A throw in compute seems to stop the memo for good, outside the element's error net.
    • @E.onChange members likely share it: same shape.
  • Worked around in the inspector: the getter returns undefined until isReady. The guide's @E.aria section says so.
  • Fix to weigh: route these effects' errors to the error net, as the :state() render effect does, or warn once.
