<spell-app> should be a root like <ui-root> and <ui-page> -- it enables all of the UI widgets and the spell pack

Yes. "A root" would mean <spell-app> IS a <ui-root>: its class, SpellApp, extends UIRoot instead of UIComponent. A page with only a <spell-app> on it then gets everything a <ui-root> gives, with nothing written around it.

What a page would get from it:

  • Spell UI's widgets, on demand: every ui-* tag inside it loads its family the first time it appears, as inside a <ui-root>
    • today <spell-app> loads ALL of Spell UI at once instead (loadUI.ts imports the whole $/ui barrel)
    • a widget a program draws later loads when it's drawn
  • The spell pack: it knows the spell pack's tags without a <ui-components source>, so a spell tag inside it loads when one appears (today <spell-editor>; later the panels of T12, such as <spell-console>)
  • The root's settings for what's inside it: icons, emoji, the theme, the size, appContext
    • its icons default to fomantic, the names the runner uses; today that's a second <ui-root icons="fomantic"> it draws inside its own shadow root, which goes
    • the host page's own ui-* outside it keep their icons, as now
  • Inside another <ui-root> (a docs page, the editor demo), it's a nested root, as nested <ui-root>s are today: it takes the outer root's settings it doesn't set, and the outer root waits for it to be ready

What it takes in Spell UI's core: "is this element a root?" is asked by TAG today, so a subclass with another tag isn't found. That becomes a setting, elementSetup.root, which UIRoot sets and SpellApp inherits. 

/** Is `localName` `<ui-root>`, or a translated alias of it? */
private static isRootTag(localName: string): boolean {
  return localName === ROOT_TAG || UIComponent.registry.definitions.get(localName)?.vocabulary.tag === ROOT_TAG
}

How it meets the earlier reply on this item (packs that load one tag at a time):

  • That reply's problem: the spell pack's define() loads BOTH elements, so a page with only a <spell-app> would also download the editor and the parser (236 kB gzipped)
  • As a root, <spell-app> doesn't need the pack to define itself: spell-app.js has already done that. The pack matters only for the OTHER spell tags
  • so the root loads each of those by itself, the first time it appears: spell-editor → spell-editor.js, beside its own script. A page with no editor never downloads one
  • that's the "tag by tag" loading the earlier reply asked of Spell UI's pack format, but only for spell's own tags, so Spell UI's packs don't change. The general version, for any pack, stays what T12 waits on
  • <ui-page> isn't needed for any of this: it stays an idea, with no item of its own

How it meets the pack issue (I4: Monaco and the parser can't go in a stock pack): it doesn't touch it. Nothing here uses the stock pack build; the editor's module, with Monaco and the parser as lazy chunks, still loads only when an editor appears, and each app still gets its own spell-runtime.js.
