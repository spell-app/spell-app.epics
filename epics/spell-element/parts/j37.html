<ui-page> which subclasses <ui-root>?

Yes, a <ui-page> fits. But on its own it doesn't make spell run's page load the way the demos do: the reason it doesn't is in the pack, not in the root.

  • Why spell run's page skipped the pack: the pack's define() loads BOTH elements.
    • so a page with only a <spell-app> would also download the editor and the parser (236 kB gzipped)
  • Spell UI itself would cost that page nothing extra: <spell-app> already loads all of Spell UI (spell-ui.js) on any page it's on.
  • So what makes every page load one way is a pack that loads each tag's code only when the page uses that tag (the third option in this call's text).
    • Spell UI's own ui-* tags already load tag by tag; packs don't yet

What <ui-page> would add over <ui-root>, as a small subclass:

  • it IS the page: the whole window, its background painted, the body's margin gone (each page writes that itself today)
  • a theme with no theme set: it follows the system's light / dark setting (a bare <ui-root> paints nothing)
  • one per page: a second one is reported in the console; <ui-root>s inside it work as today
  • everything else (loading, skeletons, packs, icons, size) stays <ui-root>'s, unchanged
