Chose two ways to load the elements, by page:

  • the demo pages (/demo/spell-app.html, /demo/spell-editor.html) load /element/spell-ui.js, and put everything in a <ui-root><ui-components source="/element/spell.pack.js">
  • spell run's page (packages/cli/src/runInBrowser.ts) and any other embedding page still load /element/spell-app.js as a module, with no <ui-root>: unchanged
  • Why: the pack's define() loads BOTH elements.
    • so a spell run page (only <spell-app>) would also download the editor and the parser (236 kB gzipped) for nothing
    • each family's module still defines its own tag, as a ui family's barrel does
  • VS Code's Run Project webview never used either tag (it mounts VSCodeRunner into #runner-root): unchanged, except that its spell-solid.js now holds Spell UI's core instead of solid-element.
  • No docs page embeds the tags; one couldn't use the pack (a second Solid): see the issue.
  • Options:
    • every page through the pack: the simplest story, but it costs the editor's bytes everywhere
    • two packs, one per tag
    • a per-tag lazy define in Spell UI's pack format (a ui change)
  • two ways to load the elements, both tested in a browser (no console errors)
