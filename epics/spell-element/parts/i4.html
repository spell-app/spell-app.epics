Owen picked "as a component pack" (bedtime page, 2026-10-09). The app's elements ARE a pack now, but the stock pack build (spell pack build) can't make their script.

  • They're a pack because they have its parts:
    • vocabularies, UIComponent subclasses, DOM element classes
    • loaded by <ui-components source>, under a <ui-root>

Why the stock build can't make their script, for real reasons:

  1. It writes ONE classic script (an IIFE), with no code splitting.
    • Monaco (4.2 MB) and the parser (0.9 MB) would sit in it. Every page with only a <spell-app> would download all of it: about 1.3 MB gzipped, against 29 kB today.
    • Monaco's worker can't be found from a classic script either.
  2. <spell-app> loads spell-runtime.js afresh per app, by URL, and shares React with it.
    • That's a Vite ES build (dist-element/), whatever the pack is.
  3. A pack's pack/ is committed: megabytes of minified churn, on every app, spell, parser or lsp change.
  4. Its staleness hash follows only the pack's own components/ and src/ folders.
    • A parser change would never mark it stale.
  5. It shares only Solid and Spell UI's core, from SpellUI.packModules, which only the docs bundle sets.

Built instead: a pack script of their own, built by Vite.

  • It's spell.pack.js, written by componentPack() in the element build.
  • It's a classic script calling SpellUI.registerPack(), with a catalog read by Spell UI's own RootCatalog.
  • Its define() imports the two elements' scripts, beside it: spell-app.js, spell-editor.js.
  • /element/spell-ui.js gives the page SpellUI.registerPack.
  • Spell UI's ComponentPacks now waits for a define() that returns a promise.

Limit: it works only where Solid and Spell UI come from dist-element/, never on a docs page, whose bundle brings a second Solid.

  • Where it works: the demos, and any page loading /element/spell-ui.js.

Since P11 (2026-10-10): the limit above is gone.

  • The pack's two scripts now take Solid and Spell UI's core from a docs page when it has them, so a docs page loads one Solid (T3, J101).
  • A page with only apps on it needs no pack at all (J37, J100).
    • <spell-app> is a root itself.
    • It loads the editor's script only when an editor appears inside it.
  • What stays true: the stock pack build still can't make this pack's script, for the reasons above, so yarn build:element keeps building it. Closed as accepted: Owen approved it on 2026-10-09.
