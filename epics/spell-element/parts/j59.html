Yes. The proposal is a shared animation attribute on every element, the fourth shared one after disabled, loading and visible. It names how the element animates when it shows or hides (J57), and animation="none" turns that off for the element and everything inside it.

Today the animation is a setting only the family can change:

this.isHiding = !show
const name = this.elementSetup.visibleAnimation
const direction = show ? UIT.IN : UIT.OUT
await Promise.all(
  boxes.map((element) => UI.transitions.animate({ element: element as HTMLElement, name, direction }))

<ui-transition> already has exactly this attribute, with Fomantic's names:

{
  name: "animation",
  kind: "enum",
  values: TransitionAnimations,
  default: DEFAULT_ANIMATION,
  description:
    "Animation for showing / hiding (Fomantic's names:  `fade up`, `scale`, `horizontal flip` ...);  an " +
    "attention one (`shake`, `pulse` ...) shows / hides at once, and runs through `transition()`."
}

The rules:

  1. animation takes <ui-transition>'s names (fade, fade up, scale ...) or none. So <ui-transition> drops its own spec and uses the shared one.
  2. Not written: the family's default, elementSetup.animation (P8's visibleAnimation, renamed). fade for most; the overlays keep the look they have now (a modal scales, a flyout slides in from its side).
  3. none spreads down: an element animates only if neither it nor anything around it says none. An element inside can't turn motion back on.
    • how: animation="none" sets a CSS custom property, --ui-motion: none. Custom properties pass into shadow roots, so every element below sees it
    • the page-wide switch is then <ui-root animation="none">, or :root { --ui-motion: none } in a page's CSS
  4. Reduced motion is the same switch: prefers-reduced-motion counts as none everywhere. reset.css and UI.transitions already honour it; they would read the one switch instead.
  5. Motion that shows progress is exempt, as now: a loader keeps spinning (WCAG 2.3.3), because animation covers only showing and hiding.

Where it overlaps attributes that exist today:

  • <ui-sidebar transition="push"> says how the sidebar shares the page: over it, pushing it, or uncovering it. Those aren't animation names, so it keeps its name. animation="none" makes the push happen at once.
  • <ui-visibility type="image" transition="fade"> IS an animation name (how a lazy image appears), so it becomes the shared animation. That rename is breaking.
  • <ui-transition duration> stays that element's own, for now.
<ui-message animation="fade down">...</ui-message>
<ui-modal animation="none" visible>...</ui-modal>
<ui-root animation="none">  <!-- nothing inside animates -->
  • one switch for a part of a page or the whole of it, and reduced motion feeds the same switch
  • every family's own motion has to check it, including the overlays' CSS transitions
  • animation="none" affects that one element
  • page-wide: UI.motion = "none" in script; it can't be written in markup
  • every element takes animation; elementSetup.visibleAnimation becomes elementSetup.animation
  • <ui-transition> loses its own animation spec; the markup is unchanged
  • breaking: <ui-visibility transition> becomes animation
  • <ui-sidebar transition> unchanged
  • one switch for none, reduced motion and the page; built in the same new phase as J57 and J58
