The timer helpers in spell-ui/util (timing.ts, P3) needed four small calls the plan didn't make. Each is listed with what was chosen and why.

  1. after()'s cancel():
    • it marks the promise as handled before rejecting it, so a cancelled fire-and-forget timer never reports an unhandled rejection
    • an await on it still gets the AbortError
    • once fn has started, cancel() does nothing
    • why: most callers start a timer and forget it; an error in the console every time one is cancelled would be noise
  2. constants stay in milliseconds:
    • a call reads after(COPIED_MS / 1000, ...), not a new COPIED_SECONDS constant
    • the constants keep their names and values; the conversion happens once, at the call
  3. Reactive.ts imports afterSolidUpdate from spell-ui/util directly:
    • not through the E namespace
    • why: Reactive.ts is a leaf, one of the files E is built from, so it takes no value import of E
  4. every() has no callers yet:
    • the only setInterval is in ServerLink.ts, outside the components, and was left as it is
    • every() is built and tested, ready for the first caller
  • quiet cancel, ms constants, a direct import, every() waiting for a caller
  • cancel rejects loudly; constants rewritten in seconds; ServerLink.ts moved onto every()
  • more churn, and epics taking a ui helper outside a component
  • cancelling an after() nobody awaits is silent; one being awaited throws AbortError
  • timing constants stay named ..._MS, divided by 1000 at the call
  • every() exists, unused until something needs it
