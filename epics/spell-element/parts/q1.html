Owen's answer, given on the analysis page as analysis Q3 (2026-10-08): A · Methods on the component.

  • each lifecycle event becomes a method on the component, with an empty default: onConnect(), onDisconnect(), onFormAssociated(form), onFormDisabled(disabled), onFormStateRestore(state, mode), beside today's onFormReset()
  • a component overrides only the ones it needs, and calls super
  • DOMElement calls them on its component
  • the hook registry and the element given as Solid context (current.ts, 83 lines, about 0.7 kB gzipped) go
  • the 11 calls in 7 files become overridden methods
  • PartContext follows its component's isConnected instead
  • onConnect(), onDisconnect(), onFormAssociated(form), onFormDisabled(disabled), onFormStateRestore(state, mode), beside the existing onFormReset()
  • the DOM element calls them on its component; an override calls super
  • reads like the rest of a component: moment callbacks are on... methods
  • E.onConnect(fn) and the rest: nothing changes but the import
  • keeps the registry, its replay of form state to late hooks, and the element provided as Solid context (~80 lines)

  • works for helpers as well as components; longer calls; no Solid context needed
