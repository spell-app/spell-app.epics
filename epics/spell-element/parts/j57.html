hidden and visible should be perfectly symmetrical

Read this way: shown-or-hidden is ONE fact about an element, and hidden and visible are two names for it, opposites. They behave the same (both animate), and writing either one changes what the other says. This reply is the core of one redesign; the rename of open (J58) and the shared animation (J59) build on it.

Today (P8) they are two different things:

{
  name: "visible",
  kind: "boolean",
  default: true,
  description:
    '`visible="false"` hides it with a short animation (a fade);  `visible` (or `="true"`) brings it back.  ' +
    "Shared by every element.  The platform's `hidden` hides at once, and wins when both are set."
}
 
:host([hidden]),
:host(:state(hidden)) {
  display: none;
}
  • el.hidden = true hides at once; el.visible still says true
  • el.visible = false fades out; el.hidden still says false

The rules I propose:

  1. Every element is shown or hidden. el.hidden is always the opposite of el.visible.
  2. The hidden attribute is where the fact is kept, because the browser, CSS and a page before its scripts load all read it.
  3. Writing either name, as an attribute or a property, sets the fact. The element then puts hidden right. It puts the visible attribute right too, but only if the page wrote one, so a page that only uses hidden never sees a visible attribute appear.
  4. Both animate the same way: the element's animation (J59). Both are instant before the element first draws, and with animation="none" or the person's reduced-motion setting.
  5. Where neither is written, the family decides (J58). Most start shown. A modal, popup, flyout, sidebar, dimmer, loader or transition starts hidden, and writes hidden on itself when it connects.
  6. Both written in markup, and disagreeing: hidden wins. The browser already hid the element before scripts loaded, so showing it then would flash it in.

Markup as written, what the element makes of it, and what shows:

written after it draws shows el.visible
<ui-message> unchanged yes true
<ui-message hidden> unchanged no false
<ui-message visible="false"> visible="false" hidden no false
<ui-message hidden visible> hidden visible="false" no (hidden wins) false
<ui-modal> hidden (its family's default) no false
<ui-modal visible> unchanged yes, open true

What a script sees, on a <ui-message> that is showing:

script writes the element attributes after reads after
el.hidden = true animates out hidden el.visible === false
el.visible = false animates out hidden el.hidden === true
setAttribute("visible", "false") animates out visible="false" hidden el.hidden === true
then removeAttribute("hidden") animates in visible el.visible === true

What this costs:

  • <ui-divider hidden> means something else today. In Fomantic it is a divider that keeps its spacing but has no line, and it would be hidden instead. It needs a new name (e.g. spacer), and that rename breaks pages that use it.
  • <ui-reveal visible> means "don't clip what overflows". It needs a new name too (e.g. unclipped).
  • While an element animates out, hidden is already set. One CSS rule keeps it on screen until the animation ends: :host([hidden]:not(:state(hiding))) { display: none }.
  • hidden="until-found" stays the browser's (find-in-page shows it). It counts as hidden, and is never animated.
  • the rules and tables above
  • hidden works everywhere, before scripts load, and with any framework that sets el.hidden
  • visible reads naturally on things that start hidden: <ui-modal visible>
  • hidden animates; el.visible is a read-only opposite of it
  • simplest, and the most like the platform
  • no family default: a <ui-modal> written without hidden opens at once, so every page writes <ui-modal hidden>. J58's rename would be open → no hidden
  • hidden and visible="false" do the same thing: an animated hide, instant before the element first draws
  • el.hidden and el.visible always read as opposites
  • P8's "both set, hidden wins" holds only for markup; after that, the latest write wins
  • breaking renames: <ui-divider hidden> and <ui-reveal visible>
  • built in a new phase together with J58 and J59 (the choice is in J58's reply)
