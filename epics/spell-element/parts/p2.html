Each element is two layers: the copied customElement() class, and DOMElement / UIComponent on top of it.DOMElement becomes a plain HTMLElement subclass that does the work itself. The component hears each lifecycle event (added to the page, removed, its form reset ...) through a method of its own. Names marked “DOM API:” are the browser’s, from HTMLElement and custom elements, not ours.
  • on DOMElement, the browser’s side (Q4):
    • DOM API: connectedCallback() (added to the page), disconnectedCallback() (removed)
    • DOM API: attributeChangedCallback(), static observedAttributes
    • DOM API: internals, from attachInternals() (custom states, the form value)
    • DOM API: the shadow root, from attachShadow()
  • on UIComponent, Solid’s side: render, its Solid root, effects (Q4)
  • lifecycle events become component methods with empty defaults, onConnect(), onDisconnect(), onFormReset() ...; a component overrides only the ones it needs (Q1)
  • properties, reflection and early properties: the same rules, tidied definitions (Q6):
    • one converter per kind of value
    • a property that would hide a DOM member is ONE clear error when the tag is defined
  • forms (Q7):
    • DOM API: formAssociatedCallback(), formResetCallback(), formDisabledCallback(), formStateRestoreCallback(), on DOMElement, each calling its component method (onFormReset() ...)
    • DOM API: static formAssociated, set per tag from elementSetup.isAFormControl, so the browser calls them only on form controls; <ui-section> and the other non-controls unchanged
  • errors: the safety net (<Errored>, :state(errored), ui-error, the fallback) stays, always on; the ISOLATE_ERRORS switch and its measuring test go (Q8)
    • why it can’t be optional (Owen asked, 2026-10-08): each element draws in a Solid root of its own, and once the owner lookup goes (Q9) that root has NO parent, so an error can’t climb to a container’s <Errored>; without its own net, one failing element freezes the whole page
    • it couldn’t climb for elements written in HTML even today: the owner was the JSX that CREATED an element, never the element it sits in
    • a test proves it: a failing element inside a container that has a net still gets :state(errored), and its siblings keep updating
  • context: the owner lookup and Solid’s compiler stamp go; app context comes from the nearest <ui-root>; tools/frameworks/solid/identity.js sets it there (Q9)
  • the event re-targeting fix moved as is, into ShadowEvents.ts (Q10)
  • hot reload into HotDefinitions.ts, its Vite plugin into ui/tools/HotElements.ts; the server stand-in into ServerDOMElement.ssr.ts (Q11)
  • the moved code carries a one-line MIT notice per file (Q12)
  • Each ui-* element is now one layer: a plain HTMLElement subclass, with a Solid component drawing inside it. Where to look:

    • app context is the appContext property of the nearest <ui-root>, no longer a Solid context (J9)
    • a property that would hide a DOM member is caught when the tag is defined: one error listing every clash (J7)
