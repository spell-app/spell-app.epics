Owen's answer to analysis Q2, "Where does the code land, and how is it laid out?" (2026-10-08): A · Platform on DOMElement, Solid on UIComponent.

No new class joins the chain.

  • DOMElement (the tag in the page) gets the browser's callbacks, the attribute record, the property accessors, the upgrade step, the internals and the shadow root
  • UIComponent (the class that draws it) gets "define the tag", "mount under Solid" and "catch errors"
  • the three big jobs keep files of their own beside them:
    • the event fix: ShadowEvents.ts (Q10)
    • hot reload: HotDefinitions.ts, its Vite plugin in HotElements.ts
    • the server stand-in: ServerDOMElement.ssr.ts
  • the full table: 1.3.7
  • not chosen: B (a plain base class under DOMElement), C (everything in the two classes, no files beside)
  • DOMElement.ts grows from 91 lines to about 400
  • a component author sees almost nothing change: define(), render() and the decorators all stay
