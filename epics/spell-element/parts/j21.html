The rule this adds, for packages/ui/AGENTS.md ("Reactive members"):

  • made once and kept: @E.lazy (getter) or @E.once (method)
  • changes later: @E.state, even when nothing reactive reads it
  • NOT state: handles to things the class started (a timer, an observer, an AbortController), such as UIDocsToc.queuedUpdate or ControlLabels.labelObserver. They stay plain fields: a decorator there would say "watch this", which nobody should.
  • Only where E can be imported: the runtime services (src/runtime/) sit below core and can't use it.
  • On a field or getter, the decorator says what the member IS: @E.state, @E.controlled, @E.derived, @E.lazy, @E.cssState("open"), @E.aria("busy"), @E.fromContent(...).
  • On a method, it says WHEN the method runs, and starts with on: @E.on("command"), @E.onChange("isOpen"), @E.onConnected, @E.onContentChange(...). Every one of these runs its method untracked.
  • Two say HOW a method runs: @E.once, @E.untracked.
  • A decorator with no arguments has no parentheses: @E.state, @E.onConnected.
  • @E.state private static accessor current; look stays a read-only getter
  • Storage is still read on first use, not when the module loads
  • @E.state static accessor look: DocsLook = ThemePreference.read(): no getter, no backing field
  • But anyone may then write ThemePreference.look = ..., skipping storage and the listeners
  • Storage is read when the module loads
  • ThemePreference.ts: its field state becomes @E.state private static accessor current; the "Not a @lazy" docstring goes
  • One rule added to packages/ui/AGENTS.md: made once is @E.lazy / @E.once, changes later is @E.state, handles stay plain
  • No other site changes: the rest of the "left as is" list above are handles, memo tables or element-core plumbing, and UIDocsSearch.dataWasRequested is already @E.state
