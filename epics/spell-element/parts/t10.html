The fix is one loop in the code that works out a translated tag's names. Today it renames only the attributes the tag's own vocabulary lists; the shared ones (disabled, loading, visible) are added afterwards, under their English names. Let it walk the shared ones too, and a dictionary names them like any other attribute.

How a translation names attributes today:

  • a translation is ONE object per language, a Dictionary, for every tag at once; there's no file per tag (no UIButton.es.ts). The only one so far is the test's, packages/ui/test/dictionary.es.ts
  • its attributes map is keyed by the English name, for every tag: { primary: "primario" }; components["ui-button"] overrides a name for one tag only
  • Vocabulary.resolve() builds a tag's translated names from vocabulary.attributes: the tag's OWN list, which has no shared attributes in it
  • then ElementDefinition adds the shared ones (SharedVocabulary.attributesFor()), looks each up in those names, doesn't find it, and keeps the English
  • so a dictionary that says disabled: "desactivado" has no effect: <ie-boton desactivado> is not disabled, and only <ie-boton disabled> works
