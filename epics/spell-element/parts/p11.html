  • How elementSetup is inherited and named:
    • J15 (A): @protoMerged chains instead of copying.
      • Each class's own elementSetup object gets its parent's as its prototype, so a key it doesn't state is read from the parent's.
      • One object per class: the class's setup and its prototype's (UICheckbox.prototype.elementSetup) are the same.
      • Nested values (styleSheets, aria) keep the spread, since code walks over their keys.
      • The three test helpers chain too.
      • The "the static keeps only what this class stated" lines go, from UIComponent's doc and ui's rules (AGENTS.md).
    • J25 (B): the CSS states that mirror an attribute move back INTO elementSetup, under the key cssStates.
      • Written cssStates: ["loading", "fluid"]. A subclass that adds states spreads its base's list, as styleSheets does.
      • The @E.cssStates(...) class decorator goes (24 classes).
      • A typo is caught when the tag is defined (define() throws, naming it), no longer by TypeScript.
      • The key and the cssStates() hook method share a name: both docstrings say which is which.
      • While moving them: drop "loading" from the dropdown's and the text control's lists, if the shared states already set it.

      • DOMElementBaseClass is renamed AnyDOMElementClass.

    • J24 (A): ARIA by short name.

    • A getter or method that follows the element's own content is marked @E.watches(...), the new name of @E.fromContent.
