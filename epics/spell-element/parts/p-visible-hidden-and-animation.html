  • J57 (A): hidden and visible are perfectly symmetrical: one fact, two names
    • el.hidden is always the opposite of el.visible; writing either one, as an attribute or a property, sets the fact
    • the hidden attribute is where the fact is kept: the browser, CSS and a page before its scripts load all read it
    • the element writes a visible attribute back only if the page wrote one, so a page that only uses hidden never sees visible appear
    • both animate the same way (the element's animation, below); both are instant before the element first draws
    • both written in markup and disagreeing: hidden wins; after that, the latest write wins
    • hidden="until-found" stays the browser's: it counts as hidden, and never animates
    • two breaking renames, for attributes whose old meaning clashes:
      • <ui-divider hidden> (Fomantic's divider with its spacing but no line) gets a new name, e.g. spacer
      • <ui-reveal visible> ("don't clip what overflows") gets a new name, e.g. unclipped
  • J58 (A): one word for "this element is on screen": visible / hidden
    • BREAKING, no alias:
      • open goes from the modal, popup and flyout
      • active goes from the dimmer and loader
      • the sidebar's and transition's own visible become the shared one
    • <ui-modal visible>, or modal.visible = true.
      • The <dialog> and the popover inside still open with showModal() / showPopover(), now when visible changes.
    • a new family setting, elementSetup.visible: "shown" | "hidden": what an element shows when the page writes neither name
      • "hidden" for the modal, flyout, popup, sidebar, dimmer, loader and transition, which write hidden on themselves when they connect
    • the base class holds the one controlled isVisible for everyone
    • open stays only where a PART of an element still on screen unfolds: a dropdown's menu, a calendar's grid, a search's results, an accordion's panels (<ui-accordion open="0 2">)
    • active stays where it means selected or pressed (<ui-button active> ...)
    • events keep their names; their detail is { visible } everywhere
      • before: ui-open / ui-close, cancelable
      • after the animation: ui-show / ui-hide
    • every caller follows, then the site data is regenerated:
      • UI.modals; the app's chooser (Chooser.tsx) and its test
      • the docs themes picker, the example files
      • Spell UI's docs pages: modal, popup, flyout, dimmer, loader, sidebar, menu, the kitchen sink
  • J59 (A): a shared animation attribute on every element, the fourth after disabled, loading and visible
    • it names how the element animates when it shows or hides: <ui-transition>'s names (fade, fade up, scale ...), or none
    • an element's own value ALWAYS overrides its family's default (Owen: "Component instances must be able to override their default animation setting!"). Which one wins, first one set:
      1. the element's own animation="slide down" (or el.animation = ...)
      2. none from around it, or the person's reduced-motion setting
        • from around it: <ui-root animation="none">, or any parent with animation="none"
      3. the family's default, elementSetup.animation (P8's visibleAnimation, renamed); the overlays keep the look they have now
      4. fade
    • none spreads down through a CSS custom property, --ui-motion: none
      • so a page turns all motion off with <ui-root animation="none">, or one CSS line
      • reduced motion is the same switch
    • motion that shows progress is exempt: a loader keeps spinning
    • <ui-transition> drops its own animation spec for the shared one (its markup unchanged)
    • BREAKING: <ui-visibility transition> becomes animation
    • the sidebar's own transition (over, push, uncover) keeps its name
    • a test for each step of the order above

  • Visible and hidden are one fact with two names, on every element (J57):
    • Hidden is always the opposite of visible; writing either one, as an attribute or a property, sets it.
    • The hidden attribute is where it's kept, so CSS, and a page before its scripts load, read it.
    • Both animate the same way; both are instant before the element first draws.
    • Both written in markup and disagreeing: hidden wins. After that, the latest write wins.
    • Removing visible hands the choice back to the family: a modal hides, a message stays shown (J108).
    • The browser's hidden="until-found" stays the browser's: it counts as hidden, and never animates.
    • A hidden sidebar is out of the page now, not laid out unseen (J110).
    • A hidden hover dimmer stays laid out, so Tab still reaches its buttons (J104).
  • Every element takes a shared animation, the fourth shared attribute after disabled, loading and visible (J59):
    • its value: one of Fomantic's transition names (fade, fade up, scale, fly right ...), or none
    • Which one wins, first one set (J107):
      1. motion off: the element's own none, none from around it, or the person's reduced-motion setting
      2. the element's own value
      3. its family's default
      4. fade
      • J59's list put the element's own value first, but its reply also said nothing overrides a page-wide none; both can't hold, so motion off comes first.
    • <ui-root animation="none">, or one CSS line, --ui-motion: none, turns all motion off. A loader keeps spinning.
    • The overlays look as before: each keeps its own style sheet's transition as its default, and any other name runs as keyframes (J103).
      • The flyout's default is "fly right", whatever side it comes in from.
  • What changed in how a component is written:
    • elementSetup.visible: "hidden" says a family starts hidden: the modal, flyout, popup, sidebar, dimmer, loader and transition.
    • elementSetup.animation names a family's default animation (P8's visibleAnimation, renamed).
    • A family reacts to showing and hiding in onVisibleChange(). The default one leaves a family's own hidden boxes alone (I10).
    • New CSS states on every element:
      • :state(hidden): hidden, and done hiding
      • :state(hiding): animating out
      • :state(still): its own animation is none
    • Family style sheets lost their own :host([hidden]) (J109).
      • One rule in the shared reset sheet hides, and keeps an element on screen while it animates out.
      • A family that wants a hidden look of its own uses :state(hidden).
    • The animation names moved into the shared component types, and the transitions helper's reveal() is public (J113).
    • In Spanish, animation is animacion (J111).
  • Docs: the custom-elements guide and ui's rules (AGENTS.md) describe the new rules; P8's "both set, hidden wins" text is gone.
