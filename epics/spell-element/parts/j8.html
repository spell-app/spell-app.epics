Everything the browser’s callbacks share inside DOMElement lives in ONE private field, bookkeeping, so an attribute can clash with as few names as possible.

  • WWOD forbids #private fields
  • a TypeScript private field is still a real property on the element, so an attribute could clash with it: state, say, is a <ui-message> attribute
  • so the mounted flag, the release and property-changed callbacks, the attribute being reflected and the values set before the upgrade are all in bookkeeping
  • the define-time clash check (Q6) lists the instance fields too: internals, attributeValues, component, ready, bookkeeping
  • no attribute may be called one of those five names; the clash check says so at define time
  • a new field on DOMElement goes into bookkeeping, or into the check’s list
