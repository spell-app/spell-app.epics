Smaller choices made in the rename from open / active to visible, on the five overlay tags.

  • Fomantic's shown class word now comes from the element, just before the noun.
    • It's an extraClass while visible; the loader's, while shown or fading out.
    • A modal: ui tiny basic top aligned active modal. A popup: ui top left visible popup, after the position, so a phrase rule's words stay side by side.
    • It was a vocabulary key of open / active, earlier in the string.
    • No CSS reads the order; visual tests unchanged (66 local).
  • Page scripts write the visible property: el.visible = true / false.
    • The scripts: goals-live.js, spell-doc-runtime.js, the brand picker pages, the docs pages' examples.
    • The drawer code in Spell UI's docs reads and writes el.hidden, which works for a flyout and a sidebar alike: UIDocsSearch, SiteRouter, SiteCheck.
  • The themes picker (<ui-docs-themes>) mutes its palette tooltip with a muted class, not hidden.
    • It hid the tooltip while its overlay is open; on a popup, hidden now means "not shown".
  • The event-detail types keep their names, their field renamed to visible.
    • They are ModalOpenDetail, PopupOpenDetail, DimmerOpenDetail ...
    • Not merged into one shared type with the sidebar's: that's another share's.
  • UIPopup.requestOpen(open) became requestVisible(visible).
    • The dialogs' and dimmer's requestOpen() / requestClose() keep their names: they match the ui-open / ui-close events.
  • no open or active left on the five tags
  • CSS unchanged in look
