When a @cssState member and the family's state list (elementSetup.cssStates) name the same state, the member wins, wherever either sits in the class chain.

  • Over the decorator's old rule, "the most-derived class wins": the list is one merged setting now, with no class of its own to rank.
  • The typo check is in define(), not register().
    • It runs after register(), which puts each attribute's getter on the class.
    • So the server render, which calls register() alone, never throws over it.
    • The other option: check in register() too, so the static render throws on a typo as well.
  • Why it matters today: only the shared loading overlapped (UIComponent's isMarkedLoading).
    • The reply on J25 dropped it from UIDropdown's and TextControl's lists.
    • The test subclass that names loading with its own member still wins, as before.
  • no element shows a different :state()
  • a misspelt name throws when the page defines the tag: 
    UIComponent.define(): <x>'s elementSetup.cssStates names nope, which it has no attribute or member for
