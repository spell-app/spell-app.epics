Chose a new exported type DOMElementBaseClass = typeof DOMElement<E.UIComponent<any>> (an instantiation expression) for ElementSetup.DOMElement, subclassForTag()'s Base, DOMElementClass and HotDefinitions, over keeping typeof DOMElement, because typeof DOMElement keeps C open, and DOMNagElement (component: UINag) doesn't fit 'any C': every family failed TS2417 / TS2322.

  • Other option: typeof DOMElement<any> inline at each use (4 places) -- no name, but any repeated.
  • One new type in DOMElement.ts, exported through E; no run-time change.

Confusing

The type exists to say "DOMElement, or any family's subclass of it". The obvious way of saying that, typeof DOMElement, doesn't work, because DOMElement takes a type parameter. The clearer fix is to drop that parameter, so the obvious type works and the extra name goes.

  • Part of the same story as J15 and J25: this is the type of one key of elementSetup.

Why it exists, in plain words:

  • every tag's DOM element is made from a class that elementSetup.DOMElement names: usually DOMElement, sometimes a family's own subclass that adds script API (DOMNagElement, for nag.close())
  • DOMElement is generic: DOMElement<C>, where C is the component class, so DOMNagElement extends E.DOMElement<UINag> knows this.component is a UINag
  • so typeof DOMElement means "a class that can make a DOM element for ANY component class you name"; DOMNagElement can only make one for UINag, and TypeScript refuses it
  • DOMElementBaseClass = typeof DOMElement<UIComponent<any>> pins C to "some component", which every family's subclass fits 
error TS2322: Type 'typeof DOMNag' is not assignable to type 'typeof DOMEl'.
  Type 'DOMNag' is not assignable to type 'DOMEl<C>'.
    Type 'Nag' is not assignable to type 'C'.
      'Nag' is assignable to the constraint of type 'C', but 'C' could be instantiated with a different subtype of constraint 'Comp<any>'.

The clearer shape: no type parameter. A family's DOM element narrows its component with one declare line, the same way a component already narrows its DOM element (declare readonly domElement: DOMNagElement). Checked in a scratch file: it compiles, and typeof DOMElement then takes DOMNagElement. 

export class DOMNagElement extends E.DOMElement<UINag> {
  close() { return this.component?.close() ?? false }
}
 
export class DOMNagElement extends E.DOMElement {
  declare component?: UINag

  close() { return this.component?.close() ?? false }
}
