default:

/** A primitive as attribute / class text;  anything else as JSON (never `[object Object]`). */
private static text(value: unknown): string {
  if (typeof value === "string") return value
  if (typeof value === "number" || typeof value === "boolean") return String(value)
  return JSON.stringify(value)
}

  • Does today's code still do it? Yes. Nothing in ShadowEvents.ts is specific to click:
    • bridge() wraps Solid's listener for every event type Solid delegates (DelegatedEvents.has(type)). In @solidjs/web rc.13 that set holds input, keydown and focusin, among 22 types
    • after() then deletes the event's own target / currentTarget, whatever event.type is, so the browser's own retargeting (target = the host) shows through again
  • What's tested today:
    • ShadowEvents.test.tsx: its page-listener test checks click only. Its test field has an onInput, but no test listens for input from the page
    • events.test.tsx (real ui-* elements): "<ui-input>: input, keydown, focusin, click see the host" types into a <ui-input> and checks all four types. Its inner <input> has Solid onInput and onKeyDown handlers (UIInput.tsx), so Solid's walk really runs for those two: input and keydown ARE covered
    • focusin is NOT, really. No ui-* element hands Solid an onFocusIn:
      • the two that listen for focusin (RovingTabindex, <ui-toast>) use addEventListener() / @E.on("focusin"), which Solid never walks
      • Solid adds its listener for a type only once some code asks for that type, so for focusin nothing overwrites target in the first place
      • so the focusin row in events.test.tsx would pass with ShadowEvents switched off
  • So: a missing TEST again, not a missing behaviour. input and keydown only lack a test in ShadowEvents's own file; focusin lacks one anywhere.

      onKeyDown={() => log.push("keydown")}

  for (const type of types) {
    const record = (event: Event) => (seen[type] ??= []).push(see(event))
    host.addEventListener(type, record)
    document.addEventListener(type, record)

    expect(seen[type]![0]).toEqual({ target: "host", currentTarget: "host", path0: "input" })
    expect(seen[type]![1]).toEqual({ target: "host", currentTarget: "#document", path0: "input" })

})
