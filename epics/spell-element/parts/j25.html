Chose @E.cssStates("loading", "fluid") on the class over an elementSetup.attributeStates list, because @protoMerged merges key by key: a subclass stating its own list would REPLACE its base's states, while the decorator's entries add up down the class chain like @E.cssState's. It also reads as the getter version's sibling, and TypeScript flags a name the class has no member for.

  • Kept a getter (with @E.cssState) wherever something else reads it: every isDisabled (9), UICheckbox.isIndeterminate (overrides CheckControl's, caught by a test), UIProgress isIndeterminate, UIRoot isFixed, UISteps isCircular, UITabs isVertical, UICard / UISegment's stacked with @E.aria
  • A disabled that is only a look carries one comment line above the decorator
  • 38 getters (about 230 lines) gone in 30 classes
  • name clash to know: the decorator E.cssStates and the hook method cssStates() share a name (documented on both)
