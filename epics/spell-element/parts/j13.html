When brand's this.attrs.x became this.x (One Attribute Store, P3), eight members of brand components had the same name as one of their attributes. The agent renamed the MEMBERS, so each attribute keeps its name and the member says what it is.

  • the eight renames:
    • font → shownFont
    • state → shownState
    • step → currentStep
    • the colour picker's value() → hex()
    • the composer's value() → text()
    • rows() → rowCount()
    • hint() → shownHint()
    • columns() → columnCount()
  • in brand's components: ui-brand-checklist (its <ui-brand-check> too), ui-brand-color-picker, ui-brand-color-set and ui-brand-composer
  • why: members are named for what they are (the rule in ui's AGENTS.md's "Reactive members", with the base classes' list under "Base classes" in UIComponent's doc); this.step is the attribute, the member is the step being shown
  • attributes keep their names: no page markup changes
  • this.x is always the attribute; the member has its own, clearer name
  • ui's precedent: UIInput, UISelect and UIDropdown declare Omit<E.AttributeValues<...>, "value">, so their own value member wins
  • no renames, but this.font would not be the font attribute: easy to misread
  • eight brand members have new names; every attribute, and so every page, is unchanged
  • in brand, this.x always means the attribute x

Let's dive into this one

All eight sit in four brand elements. In each, a member worked something out FROM an attribute and had the attribute's own name. Once this.font became the font attribute (P3), the member and the attribute couldn't share the name, so the member got a new one.

Element Attribute Old member New member What the member is Better name?
<ui-brand-check> font font shownFont the face the text is drawn in: its own font, else its list's, else sans keep
<ui-brand-check> state state shownState how the check looks (done, active or pending), worked out from checkable, the list's step, selected and its own state keep: <ui-brand-field> already had a shownState
<ui-brand-checklist> step step currentStep step as a whole number, 0 or more, or nothing when unset activeIndex: it is the position of the active check (the ones before it are done)
<ui-brand-color-picker> value value() hex() the colour as #RRGGBB, whatever form value was written in keep: <ui-brand-color> already had a hex()
<ui-brand-composer> value value() text() what's in the box now: the page's value, or what was typed; "" when empty keep, or the ui way (option C)
<ui-brand-composer> rows rows() rowCount() rows rounded, at least 1, else 3 keep
<ui-brand-composer> hint hint() shownHint() the hint under the box: hint, else the Mac or PC shortcut text keep
<ui-brand-color-set> columns columns() columnCount() chips per row, or nothing for one long row keep
  • The pattern: shown… for "what the element actually shows, after defaults and the parent's say", …Count for a cleaned-up number. Two of them match names brand already used.
  • A small fix the item text needs: it lists ui-brand-color and ui-brand-field among the renamed; neither was. Theirs were already good names.

  • Why it fits ui and not the picker: in <ui-input>, the member IS the value (what the page set, or what was typed). The picker's member is a different thing: with value="oklch(0.7 0.1 250)" on the page, this.value() would hand back the same colour as a #RRGGBB hex. Same name, two meanings.
  • The composer is the one place it would fit: text() is exactly the value. ui's shape there is a decorated member, as in <ui-input>:
