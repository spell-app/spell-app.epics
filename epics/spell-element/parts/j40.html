Chose to fix both in `ui`, over working around them in `packages/app`:

  1. `ComponentPacks.register()`: a `define()` returning a promise resolves the pack's load once it settles (rejects it on failure; logs when there is no load), so a `<ui-root>` waits for the tags. `ComponentPack.define` is typed `void | Promise<unknown>`. The `load` / `error` events of the script no longer fail a load that already registered. `epics`' `define()` already returned one (inlined `import()`s), so it now waits for real. Test: `later.pack.js` fixture.
  2. `Vocabulary.resolve()`: an event NOT named `ui-*` keeps its name unless a dictionary translates it. Before, every event took the tag's prefix, so `<spell-editor>`'s `spell-compiled` went out as `ui-compiled` and `<spell-app editor>` never heard it (found in the demo). `epics`' `ui-open` / `ui-close` are unchanged. Tests in `Vocabulary.test.ts`; `docs/translation.md` says so.
  • any component pack can name its events as it likes and load its families lazily
