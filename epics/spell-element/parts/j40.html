Chose to fix both in ui, over working around them in app:

  1. A pack's define() may return a promise (ComponentPacks.register()):
    • the pack's load resolves once that promise settles, so a <ui-root> waits for the tags
    • it rejects the load on failure, and logs when there is no load
    • ComponentPack.define is typed void | Promise<unknown>
    • the script's load / error events no longer fail a load that already registered
    • epics' define() already returned one (inlined import()s), so it now waits for real
    • test: the later.pack.js fixture
  2. A pack's own event names stay (Vocabulary.resolve()): an event NOT named ui-* keeps its name, unless a dictionary translates it.
    • before, every event took the tag's prefix: <spell-editor>'s spell-compiled went out as ui-compiled, so <spell-app editor> never heard it (found in the demo)
    • epics' ui-open / ui-close are unchanged
    • tests in Vocabulary.test.ts; translation.md says so
  • any component pack can name its events as it likes and load its families lazily
