Agreed, and it goes wider than the modal. Today four different words say "this element is on screen", so a reader has to learn which one each element uses:

  • open: <ui-modal>, <ui-flyout>, <ui-popup>
  • active: <ui-dimmer>, <ui-loader> (Fomantic's word for these)
  • a visible of their own, starting hidden: <ui-sidebar>, <ui-transition>
  • the shared visible, starting shown: every other element (P8)

The proposal is one rule: visible / hidden say whether the element itself is on screen (J57's rules). open stays only where a PART of an element that is still on screen unfolds:

  • <ui-dropdown open>: its menu
  • <ui-calendar open>: its pop-up grid
  • <ui-search open>: its results
  • <ui-accordion open="0 2">: which of its panels

active stays where it means selected or pressed (<ui-button active>, <ui-label active> ...).

The modal's open today:

/** `open`:  shown.  The DOM element's `open` property when set, else kept here. */
@E.cssState("open")
@E.controlled("open")
accessor isOpen = false

It would become your ElementSetup setting: what an element shows when neither visible nor hidden is written. The base class holds the one controlled isVisible for everyone. 

@E.protoMerged static elementSetup = {
  // nothing written:  hidden (`<ui-modal>` gets `hidden`)
  visible: "hidden"
} satisfies Partial<E.ElementSetup>

// the base class:  `isVisible`, controlled, `:state(hidden)`
// this class only acts on it:  showModal() / close()
 
/**
 * What the element shows when the page writes neither `visible` nor `hidden`.
 * - `"shown"` (the default):  a message, a segment, a menu ...
 * - `"hidden"`:  a modal, flyout, popup, sidebar, dimmer, loader, transition
 */
visible: "shown" | "hidden"

What becomes what:

today becomes
attribute open (3 elements), active (2), their own visible (2) the shared visible / hidden
property el.open, el.active el.visible, el.hidden
CSS state :state(open), :state(active), :state(visible) :state(hidden), or :not(:state(hidden))
Fomantic class word active on the root box while shown unchanged
events ui-open / ui-close before (a person's action; can veto), ui-show / ui-hide after the animation the same names. The sidebar already pairs them with visible
event detail { open }, { active }, { visible } { visible } everywhere
<dialog> and popover inside the shadow root: showModal() / close(), showPopover() / hidePopover() unchanged; now called when visible changes
button commands --show, --close, --toggle unchanged
UI.modals modal.open = true modal.visible = true

This is a breaking rename. Every page that writes <ui-modal open>, <ui-popup open>, <ui-flyout open>, <ui-dimmer active> or <ui-loader active> breaks, and so does every script that reads .open, .active or event.detail.open on them. The sites I counted (rough counts of lines that mention the word):
