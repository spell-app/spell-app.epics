Four pieces of work, in nine phases.

  • Each phase left everything green, so it could be reviewed, and stopped after, on its own (Q14).
  • the fold: solid-element is now Spell UI's own code, and the package is gone (P1 to P5)
  • the guide, "Custom Elements in Spell" (P6)
  • epic-components' elements, moved onto the folded element core (P7)
  • shared states on every element: disabled, loading and visible (P8)
  1. P1 · Bring It In: the element layer copied into Spell UI's element folder (elements) unchanged, its 91 tests with it.
    • sizes and speed measured before and after
    • nothing on a page changed
    • yarn fork went from ui
  2. P2 · Fold Into Elements: each ui-* element became one layer.
    • DOMElement is a plain HTMLElement subclass doing the browser's side: the callbacks, attributes, properties, reflection, the shadow root, forms
    • UIComponent draws inside it with Solid. Each lifecycle event is a method on it: onConnect(), onFormReset() ...
    • the event fix, hot reload and the server render's stand-in were moved in as they were
    • app context is a property of the nearest <ui-root> (J9)
  3. P3 · One Attribute Store: one converted value per attribute, read as this.x (this.attrs is gone), and a set of new decorators.
    • @E.protoMerged elementSetup, merged down the class chain, with styleSheets as one of its keys
    • listeners and watchers:
      • @E.on, @E.untracked
      • @E.fromContent (since renamed @E.watches), @E.whileConnected
    • ARIA, states and caching:
      • @E.aria, @E.cssStates
      • @lazy, @once
    • timing helpers named for when they run: afterSolidUpdate(), after(seconds) ...
    • form controls' shared code in FormComponent
    • an element's extra classes go before the noun, as Fomantic writes them
  4. P4 · App Elements: <spell-app> and <spell-editor> became Spell UI components, in the app's components folder (components).
    • Also a component pack, spell.pack.js, built by yarn build:element: the stock pack build couldn't carry them (I4).
  5. P5 · Package Goes: the solid-element package (solid-element) and ui's copy of it deleted.
    • the docs, CI and tools brought up to date
    • the "after" numbers: no slowdown, and a page with one button the same size
  6. P6 · Custom Elements Guide: "Custom Elements in Spell", the durable doc.
    • diagrams, a teaching element (<ui-counter>), live elements
    • a new docs widget, <ui-docs-inspector>, beside each live element
  7. P7 · Move Epic Components: main merged in, and epic-components' new elements (its P14) moved onto the folded element core.
    • Owen's request (Q17).
  8. P8 · Disabled And Visible: added after the plan, at Owen's request.
    • every element takes disabled, loading and visible
    • what each means is a family setting, in elementSetup:
      • disabled: "unusable" (the default) or "its own"
      • loading: "loader" or "its own"
    • the platform's hidden now always wins
    • readonly on every form control
    • how visible and hidden fit together is still Owen's call (Q28): built on the recommended answers
  9. P9 · Doc Review: this doc pruned; the guide made the durable doc; the changelog.

The guide (was P19 · Custom Elements Guide, estimated 2-3h)

  • A guide, "Custom Elements in Spell" (guides/), for someone NOT familiar with custom elements: each custom-element feature in a sentence or two, with a link to MDN.
  • Near the top: what each decorator does, in detail; the @controlled idea explained.
  • A section per hook and what it does (render(), onMount(), extraClasses, classValue(), cssStates(), styleSheetNames, isDisabled ...); a section on events: on() / send().
  • Lots of pictures: diagrams of the component / DOM element pair, the life of an element, how an attribute reaches the view, how a part finds its owner.
  • <ui-button> as the running example; then the patterns that repeat: <ui-select> for form controls, <ui-include> for loading, and a few more.
  • Written after the fold, so it describes the folded design.
  • Files: custom-elements.html (shared), the docs index. Checks: spell dev docs link checks, check-spell.js (look at the screenshots).
