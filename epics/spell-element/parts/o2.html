  • P10 to P13 were added after the first Doc Review (P9), from Owen's review of 2026-10-09; so the epic has two Doc Reviews.

  • Owen's review follow-ups: the element core's names and set-up as he picked them, and <spell-app> a root (P11)

  1. P1 · Bring It In: the element layer copied into Spell UI's element folder (elements) unchanged, its 91 tests with it.
    • sizes and speed measured before and after
    • nothing on a page changed
    • yarn fork went from ui
  2. P2 · Fold Into Elements: each ui-* element became one layer.
    • DOMElement is a plain HTMLElement subclass doing the browser's side: the callbacks, attributes, properties, reflection, the shadow root, forms
    • UIComponent draws inside it with Solid. Each lifecycle event is a method on it: onConnect(), onFormReset() ...
    • the event fix, hot reload and the server render's stand-in were moved in as they were
    • app context is a property of the nearest <ui-root> (J9)
  3. P3 · One Attribute Store: one converted value per attribute, read as this.x, and a set of new decorators.
    • this.attrs is gone.
    • @E.protoMerged elementSetup, merged down the class chain, with styleSheets as one of its keys (since P11, chained to the parent's instead of copied)
    • listeners and watchers:
      • @E.on, @E.untracked
      • @E.fromContent, since renamed @E.watches
      • @E.whileConnected
    • ARIA, states and caching:
      • @E.aria
      • @E.cssStates: since P11, a list in the setup instead
      • @lazy, @once
    • timing helpers named for when they run: afterSolidUpdate(), after(seconds) ...
    • form controls' shared code in FormComponent
    • an element's extra classes go before the noun, as Fomantic writes them
  4. P4 · App Elements: <spell-app> and <spell-editor> became Spell UI components.
    • They live in the app's components folder.
    • Also a component pack, spell.pack.js, built by yarn build:element: the stock pack build couldn't carry them (I4).
  5. P5 · Package Goes: the solid-element package (solid-element) and ui's copy of it deleted.
    • the docs, CI and tools brought up to date
    • the "after" numbers: no slowdown, and a page with one button the same size
  6. P6 · Custom Elements Guide: "Custom Elements in Spell", the durable doc.
    • diagrams, a teaching element (<ui-counter>), live elements
    • a new docs widget, <ui-docs-inspector>, beside each live element
  7. P7 · Move Epic Components: main merged in, and epic-components' new elements (its P14) moved onto the folded element core.
    • Owen's request (Q17).
  8. P8 · Disabled And Visible: added after the plan, at Owen's request.
    • every element takes disabled, loading and visible
    • what each means is a family setting, in elementSetup:
      • disabled: "unusable" (the default) or "its own"
      • loading: "loader" or "its own"
    • readonly on every form control
    • how visible and hidden fit together was built on the recommended answers to Q28 ("hidden always wins"); P12 replaced it, before any of it reached main
  9. P9 · Doc Review: this doc pruned; the guide made the durable doc; the changelog.
  10. P10 · Spell UI Patterns Everywhere: every element outside the app is a Spell UI family, its reactive parts written by decorator, not by hand.
    • Owen's ask: "Everything other than app components should use spell-ui pattern." The app is untouched.
    • epics' and brand's elements moved: 83 hand-written effects, observers, listeners and timers were found; what is left is on an allow-list, each with its reason.
    • epics' plain function components became families, or private render methods:
      • the review controls: <epic-review>
      • the Add button and its form: <epic-new-item>
      • the agents panel: <epic-agents>
    • A lint guard: yarn lint flags a hand-written effect in a component file of ui, epics or brand.
      • A use that has to stay carries a disable comment with its reason, and is listed in a test.
  11. P11 · Review Follow-ups: everything Owen picked or OK'd in his review of 2026-10-09, but the visible / hidden redesign.
    • The element core's set-up and names:
      • each class's elementSetup chained to its parent's, nothing copied
      • the CSS states that mirror an attribute listed in the setup, as cssStates
      • ARIA written by its short name (busy, label ...)
      • @E.fromContent renamed @E.watches
      • a new decorator, @E.resets, so writing a value makes the next load fetch again
    • <spell-app> is a root, a kind of <ui-root>.
      • It loads only the widgets it draws, so a page with only apps never downloads the editor.
      • On a docs page it uses the page's Solid: one Solid per page.
    • Smaller ones:
      • 17 families take the shared "unusable" disabled
      • brand's composer and colour picker take readonly and required
      • a translated tag names the shared attributes too
      • the guides that still described solid-element rewritten
  12. P12 · Visible, Hidden And Animation: one word for "this element is on screen", and one shared animation.
    • visible and hidden are one fact with two names, on every element; both animate.
    • BREAKING: the modal, popup and flyout lost open; the dimmer and loader lost active.
    • A family says it starts hidden with elementSetup.visible; its default animation is elementSetup.animation.
    • Every element takes an animation; motion off (the element's own none, a page-wide none, or reduced motion) wins over it.
  13. P13 · Doc Review: the second text pass, this doc pruned, the guide and the changelog brought up to date; then the merge.

The guide (was P19 · Custom Elements Guide, estimated 2-3h)

  • A guide, "Custom Elements in Spell" (guides/), for someone NOT familiar with custom elements: each custom-element feature in a sentence or two, with a link to MDN.
  • Near the top: what each decorator does, in detail; the @controlled idea explained.
  • A section per hook and what it does (render(), onMount(), extraClasses, classValue(), cssStates(), styleSheetNames, isDisabled ...); a section on events: on() / send().
  • Lots of pictures: diagrams of the component / DOM element pair, the life of an element, how an attribute reaches the view, how a part finds its owner.
  • <ui-button> as the running example; then the patterns that repeat: <ui-select> for form controls, <ui-include> for loading, and a few more.
  • Written after the fold, so it describes the folded design.
  • Files: custom-elements.html (shared), the docs index. Checks: spell dev docs link checks, check-spell.js (look at the screenshots).
