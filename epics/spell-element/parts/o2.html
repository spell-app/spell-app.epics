Two pieces of work, in eight phases: fold solid-element into ui's own DOMElement / UIComponent in stages that each leave everything green (Q14), then write the guide. Each phase can be reviewed, and stopped after, on its own.

  1. P1 · Bring It In: measure size and speed first, then copy the code ui uses into packages/ui/src/elements/ unchanged; only imports switch.
  2. P2 · Fold Into Elements: DOMElement becomes a plain HTMLElement subclass doing the browser's side itself; UIComponent does Solid's side; each lifecycle event is a component method. The big one.
  3. P3 · One Attribute Store: one converted value per attribute on DOMElement, one change signal each; attrs goes, and brand's 89 this.attrs.x become this.x.
  4. P4 · App Elements: <spell-app> and <spell-editor> become ui components.
  5. P5 · Package Goes: packages/solid-element deleted; the docs follow; the "after" numbers.
  6. P6 · Custom Elements Guide: "Custom Elements in Spell", a contributor guide in guides/, with diagrams, a teaching element and live examples.
  7. P7 · Move Epic Components: epic-components' elements checked and fixed on the new core (Owen's request, Q17).
  8. P9 · Doc Review: prune; the guide becomes the durable doc; the changelog.
