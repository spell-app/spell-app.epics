Coherence is a reviewer, the way the designer is one: an agent that reads, holds what it reads up against a set of rules, and returns ranked findings, changing nothing itself.

  • Where the designer asks "does this page look right?", coherence asks "is this the ONE way we do it?"
    • a mechanism written twice, where one shared mechanism, handed what differs, would serve both
    • new code that rebuilds something the repos already have
    • two words for one idea (fold, expand, toggle, collapse, where we decided open / close)
  • It is a standing epic, like epic-engine: each sweep or review is a phase, and each phase merges on its own.

Its parts

  • The coherence agent, registered in spell-epic's plugin beside the designer's: coherence-agent.md.
    • read-only tools, as the designer has: it finds and ranks, the session that asked decides
  • The skill, /coherence, in spell-epic's skills: its steps, what it reads, how findings are reported, and how they land in an epic page.
  • The catalog: the mechanisms we already have, each with a "use it when" line.
    • e.g. "a new syntax to read: a tokenizer subclass plus rules, as the markdown and rulex tokenizers do", or "remember a UI preference: PrefStore"
    • It's what a plan-time review checks a new plan against: without it, the agent can't know what to look for.
  • The word list: the one word we use for each idea, the platform's word first, and the words it replaces.
    • e.g. open / close, as <details open> says it, never fold, expand or toggle
    • seeded from what's already decided: elemental-spell's event names (its Q65 and Q68)
  • Learning, as the designer's last step does: Owen's verdict on a finding becomes a catalog entry, a word, or a rule saying "this is fine, stop flagging it".

Where the catalog and the word list live (with the agent in spell-epic, or beside WWOD in the kit) is Q1; how the catalog is made is Q2.
