The app's change requests live in one file, rewritten whole by two processes with no lock between them:

  • the editor's server adds a request (ChangeRequests.add())
  • spell app changes takes the next one (takeNext())

Each reads the file, changes its copy and writes it back (to a temporary file, then renamed). When both run at once, the second write drops the first one's change: a request added while another is taken can vanish. Probable from the code, not seen in a run.

The fix: the kit's file lock (SRV.FileLock) around each read-change-write, or a locked DataFile, as ReviewInbox.update() does for the epic inbox.
