spell-epic's node tools write their own copies of what the kit (or spell-epic itself) already has: running git, finding a checkout, a real path, a running process, a file lock, a package's folder, opening Chrome, and the page server's settings.

  • A race: one of the three file-lock copies checks that the lock file is missing, then writes it. Two runs at once can both take the lock.
  • The root cause of the lock copies: the kit's FileLock imports the server's whole barrel, so plain node can't load it.

open a page in a Chrome tab openInChromeTab, in the kit 1, line for line about 40 lines
the page server's pieces the kit's page server 3, in the epic server a hard-coded swap the settings already declare
  • Git moves into the kit (node's built-ins only, with its own entry so plain node can load it): run, out, lines, mustRun
  • RealPath moves into the kit
  • FileLock imports its error class directly, gets its own entry for plain node, and a try-once mode
  • checkoutOf(), isProcessAlive and packageRootFor are used as they are
  • openInChromeTab gains a { front } option, the only thing the copy adds
  • the kit's page server exports its unwatched list and its overlay of component sets; the epic server reads localCopies from the settings
  • the spell-epic hook that must stay on node's built-ins keeps its own process check, on purpose
