Seven small text helpers are written by hand again and again, 7 to 16 times each, and some copies already disagree: an accented title gets a different id depending on which copy made it.

  • The seven:
    • a slug from a title: 8 or more copies, following 4 different rules
    • escaping text for a regular expression: 16 copies
    • escaping HTML: 7 or more copies, one of which forgets >
    • removing accents: 9 copies
    • removing or adding indentation (dedent, indent): 9 copies
    • a size in kilobytes: 7 copies, in two different units (1000 and 1024)
    • clamping a number between two others: 14 hand-written copies
  • Drift in the slugs (inferred from the code, not run):
    • the epic tools' phase ids strip accents, their addresses don't: finding phase "p-cafe" misses a phase called "Café"
    • Spell UI's table of contents strips accents, its site index doesn't: the two disagree on an accented title
    • the code map's docs reader keeps only plain letters: an accented heading gets a different anchor than GitHub's
  • Drift in the accents: the language server's keyword list removes only the acute accent, so it keeps ñ and ü; that may be on purpose for Spanish.
  • all seven in the kit's spell/util/string, each taking what differs as an option (slug(text, { fallback }), withoutAccents(text, { keep }))
  • the slug follows the phase ids' rules, which strip accents
  • clamp() and slug() live in a generic file Spell UI may import one by one, since it can't import the kit's Spell-specific util files
  • later, the regex escaper becomes the platform's RegExp.escape()
  • spell/util/string gains slug(), escapeRegExp(), escapeHTML(), withoutAccents(), dedent() / indented(), kb() and clamp()
  • about 70 copies call them instead
  • every slug strips accents the same way, so ids agree between the epic tools, Spell UI's site and the code map
  • every size is shown in one unit

About 70 copies become seven helpers; the slugs and accent rules agree everywhere.
