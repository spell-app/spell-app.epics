graphify can't follow our package-name imports, so spell map links them itself: the code map now knows which file uses which class from another repo.

  • graphify leaves an import like spell/util/node/json5 unresolved, so nothing linked a file to the code it imports from another repo.
  • The merge reads each file's imports and adds three kinds of link:
    • imports_from: the file it imports
    • uses: each name it takes, a barrel's members too (P.Tokenizer)
    • inherits: a class extending an imported one (extends P.Tokenizer)
  • About 14,000 links in all, 475 of them subclass links.
  • Without them, "who uses Tokenizer" missed MarkdownTokenizer: the exact case behind elemental-spell's hand-written spellx reader.
  • the code map links files across repos by their imports, not only by graphify's guesses
  • spell map uses <name> finds subclasses in other repos
  • our import rules (package name plus path) are read by our own code, so a change to them means a change here
