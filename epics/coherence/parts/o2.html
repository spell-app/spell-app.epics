Coherence runs two ways: a sweep over code that's already written, and a review of a plan before it's built.

1. The sweep: /coherence sweep [area]

  • It reads one area of the code, or all of it, looking for the same mechanism done more than one way.
  • All of it is about 450,000 lines of our own code, so it splits into five areas, an agent each:
    1. Spell UI's components
    2. Spell UI's docs and tools
    3. the epic elements and the docs pages' runtime
    4. spell-epic's tools and command line, with the kit
    5. the parser and the app
  • Each finding names every place it's in, what they share, what differs, and the one mechanism that would replace them.
  • Findings are ranked: most code saved, and most likely to be copied again, first.
  • Where they land is Q4.

2. The plan review: /coherence epic <name>

  • It reads a new epic's kickoff prompt and Overview, and asks: what in the repos already does part of this?
  • It checks the plan against the catalog and the word list, then searches the code for the nouns the plan names.
  • Each finding goes into THAT epic as a question, before Owen accepts its Overview.
    • e.g. for elemental-spell: "The spellx reader (Q10, option A) writes a parser by hand. The markdown and rulex tokenizers show the tokenizer can be subclassed; would a spellx tokenizer plus rules do it?"
  • It runs by itself from /epic, so nobody has to remember it: when, and how often, is Q3.
  • It also runs by hand, on an epic already under way.
