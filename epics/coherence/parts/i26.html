Measured 2026-11-04 (agent coherence-hook-speed): the hook tests' slow steps are the ones that start the epic command (epic shared link, every create once an epic folder sits beside the repo), and that start is slower here only through tsx's cache.

  • The cache folder holds about 107,000 files (953 MB, every checkout's and worktree's compiled files from the last 8 days).
  • tsx looks each file up by scanning that whole list (cacheFiles.find()), so a checkout whose entries sit later in the folder's order starts slower.
  • The epic command's start, epic --help, 6 runs each: shared cache main 0.71s, coherence 0.94s; a fresh cache main 0.50s, coherence 0.46s.
  • One hook create with an epic folder beside, interleaved, 6 each: shared cache main 1.90s, coherence 2.53s; a fresh cache main 1.04s, coherence 0.92s.
  • The modules loaded differ by 5 small files (Heartbeat, FolderWatch, findUp, the two timing files); the resolves are the same.

Nothing to change in the branch. Emptying the cache folder ($TMPDIR/tsx-501) puts every checkout back to the fast start; it refills as files are run.
