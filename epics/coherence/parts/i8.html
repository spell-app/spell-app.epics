The epic pages talk to the page server in about a dozen hand-written ways, and each handles a stale token, a missing file and "am I served?" differently.

  • Writes carry the page's token, and each handles a stale token its own way:
    • the review link asks the server again
    • the docs helpers reread the page
    • the syntax page throws "reload"
    • the parked goals page reloads the page
  • The pattern that reads the token from the page is written twice.
  • Ten or so reads check the response themselves and answer nothing on a failure: the work $fetch() already does.
  • The test "is this page on the page server?" is written about ten times.
  • Polling while the page is visible exists: ServerLink.watch() polls, pauses while hidden and hears the server's file notices. Five places write it again.
  • ServerLink for every read and write: given an isServed test and a get(api) built on $fetch(), with default contents for a missing file
  • ServerLink.watch() for every poll, given a test for which paths it cares about
  • today only the agents and review clients use it

About 130 lines for the calls, about 60 for the polling.
