Two sentences: what this plan does, and why.

So we're writing a shit ton of code, and I'm worried that we're not taking advantage of code that is already there.

Goal: new skill / agent / whatever that looks over the code base and finds places where we are essentially doing the same thing in multiple places, but not sharing code. e.g. where two things are using the same pattern, and we could have one mechanism with dependency injection.

One example is elemental-spell -- it wrote a new hard-coded parser by hand, rather than saying `if we changed tokenizer, we could do this with existing tokenizer/parser/rules`.

Another example: we were figuring out event names for different components. Many many things are opening/closing, but we ended up with "folding", "expanding", "toggling" rather than "opening / closing."

At least two modes:
- analysis of current code to find any efficiencies
- when a new plan comes in, have it run by coherence agent to see if there are any advantages.

This is a standing epic, like epic-engine.
