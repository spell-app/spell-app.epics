Each turn commits the plans locally and stops there: nobody else ever sees them, and two people's new items would clash.

  • Every turn's commit pulls (rebasing) before and pushes after, on its own; epic shared sync by hand; a conflict it can't settle stops the sync and says so; offline, it commits and pushes later. (Q5)
  • After each pull, two items, comments or change marks with one id are told apart: the LOCAL one gets the next free number, its part file and every link following, with a log line. (Q6)
  • The log keeps both people's lines (git's union merge) and is re-sorted by time.
  • The page's "updated" date merges as the later of the two.

The end-of-turn commit pulls before it and pushes after, whenever the content repo has a remote; epic shared sync does the same by hand. After each pull it fixes what a merge leaves: duplicate ids, the log's order, the page's date.

  1. Pull and push. Shared gains sync(): commit as today, then git pull --rebase, the fixes below, and git push. Only when the content repo has a remote; inside the commit lock that's there already.
  2. Every turn. epic shared commit runs the sync when there's a remote, still detached from the turn (the end-of-turn hook); epic shared sync runs it by hand, and prints what it did.
  3. When it can't. Offline: the commits stay, and the next sync pushes them. A conflict the fixes can't settle: the rebase is aborted, and the sync names the files, in its log and the next time epic shared status runs.
  4. The merge settings. The content repo's attributes file gets merge=union for every parts/log.html; Shared.init() writes it, and a sync adds it to a repo without it.
  5. After the pull, for each epic page the pull changed:
    • the log's lines re-sorted by their time
    • the page's updated date the later of the two
    • duplicate ids (items, comments, change marks): the one only this machine had gets the next free number, its part file and links following, through ItemRenames.renumber(), with a log line
  6. Checked: tests with two clones of one bare repo, both adding T22, a log line and a date; a real conflict; offline. yarn review in epic/.
