From epic repo-split (2026-10-29), Owen's ask: "add a section for setting all of this up (or maybe a new README 'working with npm'?)". "All of this" is how Spell publishes to npm, as repo-split's P22 did it; its epic page has the record.

  • spell publish [--dry-run] [--tag next]: builds and packs three packages into dist-packs/ (spell, spell-ui, spell-epic), checks each, installs them in a scratch project, then publishes. --tag defaults to next, so a plain publish never moves latest (npm keeps the coming-soon placeholder, spell@0.8.1, until the real release; npm dist-tag add spell@<v> latest then).
  • Logging in: npm login sessions expire in about 2 hours. Instead a granular access token (npmjs.com → Access Tokens → Granular: read and write, ALL packages, since the names are unscoped and new packages can't be picked before they exist; bypass 2FA; 30 days) in ~/.npmrc as //registry.npmjs.org/:_authToken=npm_..., replacing the old session line, never two. npm whoami checks it. npm warns bypass-2FA tokens lose direct publishing in January 2027: then trusted publishing from a GitHub Actions workflow (repo-split T62).
  • zsh gotchas: no # comments in pasted commands; a tarball path needs ./ (npm publish ./dist-packs/x.tgz), or npm reads it as a GitHub repo.
  • Claude can't publish in auto mode unless Bash(npm publish:*) is allowed in ~/.claude/settings.json.
  • A version can never be reused, not even one only staged; publish spell FIRST, the others depend on it.
