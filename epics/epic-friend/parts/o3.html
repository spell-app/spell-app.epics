Each person runs their own epic server on their own machine. So the server knows who its person is, with no login, and stamps their name on what they write.

  • Where the name comes from: git's own user.name to start with, which the person can change. epic init asks "What do you want to be called?", suggesting "Ana Lima", and they can answer "Ana". The answer is kept per machine, in the epic home folder; epic whoami [name] shows or changes it. Then, Q12: the short name defaults to the person's GitHub login (owenoak), git's user.name is the full name, and epic whoami Owen keeps another. Spell's people app reads git's name the same way, for a person's starter profile.
  • How a page learns it: the server hands it to every page it serves, beside the other server settings. Airplane mode already reaches the pages this way (airplaneRoutes).
  • What gets a name:
    • a comment, and each reply on its thread
    • a note kept as a reply in the epic page (<epic-reply from="Ana">)
    • a pick ("Ana picked B"), and a test result ("passed in Ana's run")
    • the log line an action writes
  • One test, "is this Claude's?": about 12 places test a reply's author against the literal "Owen", in three styles (a constant, a string, a pattern). They become one check: anything not Claude's is a person's. The pages already store a name on every reply, so the old "Owen" replies stay valid.
  • A developer named Claude (O3): an agent's replies are told apart by what they ARE, not by the name. Each reply says which agent wrote it in an attribute of its own (agent="claude", agent="codex"), so a person who calls themselves "Claude" is still a person.
  • Whose Claude: Claude's replies and status cards name the person whose session wrote them, "Claude (Ana)", so the team can tell Ana's Claude at work from Ben's. Shown as just "Claude" when it's your own. Another agent is named the same way: "Codex (Bob)" (P10).
  • On the page: your own replies say "You", and everyone else's show their name. The two voices' colours are theme tokens (T11): people's violet, Claude's terracotta, comment threads included (Q16). A repo can give each person and agent a colour of its own, in .epic/config.json5's colors (P10).
  • The word that replaces "Owen" (Q7): "you" on pages and in the help, "the person" in code and the skills (P3).
