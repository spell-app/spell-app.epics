Codex's docs (learn.chatgpt.com/docs/hooks, developers.openai.com/plugins/build/plugins, read 2026-10-29) say:

  • hooks load from ~/.codex/hooks.json, <repo>/.codex/hooks.json or [hooks] in config.toml; a repo's only when the project is trusted
  • a plugin's hooks run for a plugin "installed manually in Codex desktop"; nothing says the CLI runs them, and installing a local plugin is described only through the desktop app
  • every hook runs only once the person trusts it (/hooks), again after it changes; a Stop hook's stdout must be JSON or nothing

So epic plugin install --codex writes the three hooks into ~/.codex/hooks.json ($CODEX_HOME) by the kit's full path, the person's own hooks kept, an older install's replaced. The plugin manifest epic/.codex-plugin/plugin.json names the same file (hooks: ./hooks/codex-hooks.json) for P12 to extend; not added to spellPublish files yet. If P12 installs the plugin too, the user-file hooks must come out, or they run twice.

The Stop hook runs the same hooks/shared-commit.mjs as Claude's, which starts epic turn end detached: the turn never waits for a push, and it prints nothing (Codex reads plain text as a mistake).
