The code changes, roughly in the order they'd be built. The phases come after the Overview is accepted.

  1. Who you are: a small helper on the kit's git runner (Git) reads git's name. The people app's private copy of it moves there too. The epic server hands the name to its pages.
  2. Names on what people write: the one "is this Claude's?" check, a by on comments and marks, and the writers that hard-code "Owen" take the person's name instead (CommentList, PlanDoc, the inbox commands).
    • A migration step brings older pages along.
    • The page bundles are rebuilt.
  3. Sharing the content repo: a remote in the config, a clone in epic init, a pull and push around each turn's commit, the union merge setting for logs, and a fix for duplicate ids (Q6).
  4. Outside-repo rough edges the friend hits first (from the adopting README's list of nine):
    • The worktree hook runs in every repo on the machine with Spell's settings, which breaks Claude Code's worktrees in repos without epic init.
    • Settings left out of the config fall back to Spell's values, for example a content folder of ../spell-app-dev.
    • The docs name the epic server's home folder ~/.epic, but the code uses ~/.spell-epic.
  5. The words: "Owen" out of the text other people read (Q7).
