ContentMerge runs only on files a rebase stopped on (both people changed them):

  • the later date wins for updated and recent-since (the latter is per machine, so it clashed too)
  • both people ADDED at one place: both kept, the remote's first. Done by characters, not lines: the formatter folds a closing > onto the next line, so adding an item at a section's end changes the line before it too.
  • anything else: the rebase is undone, kept in .git/spell-shared-sync.json5, and the next session start says which files

A merge driver would need each clone's .git/config set up, and would run outside the sync's lock.
