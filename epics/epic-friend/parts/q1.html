Where should a team's epic pages live in git? Today they're in a content repo beside the code, for example my-app.epics, which nobody can share.

  • Keeps today's design: the plans stay off the code branches, so an epic page never conflicts in a code merge.
  • The team makes one more repo (my-app-epics on GitHub), and the config names it so epic init clones it.
  • Spell's own content repo already has a remote: it would just start pushing.
  • One clone brings everything: nothing more to set up.
  • But each epic's edits ride on its code branch, and the tool rewrites epic pages heavily: every merge into main would merge epic pages too, the conflict the shared design was built to avoid.
  • Every worktree would see its own copy, not one shared page.
  • a new config setting for the content repo's remote
  • epic init clones it when the folder is missing
  • the README tells a team to make one more repo
