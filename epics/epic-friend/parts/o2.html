The plans stay in their own content repo, now with a remote that everyone pulls from and pushes to. Comments are shared too, one file per person; marks stay on each machine.

  • Where the plans live: the content repo gets a remote, and the config names it so epic init can clone it. The other way, keeping the plans inside the code repo, is Q1.
  • Keeping in step: the end-of-turn commit (epic shared commit) gained a pull before it and a push after, on its own, every turn, whenever the content repo has a remote. epic shared sync does the same by hand. A conflict it can't settle stops the sync and says so; offline, it commits and pushes later.
  • What conflicts when two people change one epic page, and how the sync settles it:
    • The page's updated date, which nearly every command rewrites. A merge can take the later of the two.
    • New item ids: each is the highest number plus one, so two people both make T22. Git merges them cleanly, and the page then has two items with one id. So the sync looks for duplicate ids after each pull, and gives the LOCAL one the next free number (T22 becomes T23), its part file and every link following, with a log line saying so.
    • The log: both sides add lines at the end. Git's "union" merge setting keeps both, in the content repo's attributes file. The log is a file of its own (parts/log.html), and the sync then sorts its lines by time, so a merged log reads in order (O2). A page not split into parts keeps its log as merged (T15).
    • Each item's and each phase's body is a file of its own, so edits to different items don't touch each other.
  • Comments are shared, marks stay local (P9 · Shared Comments). Each person's comments go in a file of their own beside the page, <page>.comments.<person>.json5, synced with the plans. The inbox keeps only what's this machine's: marks, Send, which session is listening.
    • The inbox is rewritten whole on every change, and holds a heartbeat that updates every 30 seconds: so it stays off git.
    • Each person's Send hands their own agent only their own threads; a claim says whose agent took one ("Claude (Ana): thinking…"). Only a comment's writer edits or deletes it, and two people's same comment id is renumbered at sync.
    • So a comment thread reaches the rest of the team only once it's answered, for now. A later phase shares comments through git before they're answered: the inbox split into a shared part (comments and marks, by person) and a local part (who's listening, the heartbeat), and a rule for whose Claude answers. P9 then did that, with comments only: marks stay on each machine (J26).
  • Spell's own content repo syncs every turn too: the kit's config names spell-app/spell-app.epics as its remote (J18). It must be private before the merge (M2).
