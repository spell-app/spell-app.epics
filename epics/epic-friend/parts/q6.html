How should duplicate item ids be avoided when two people add items to one epic page?

  • Today a new id is the highest number plus one: Ana and Ben both add a todo, both get T22, and git merges both lines cleanly into one page with two T22s.
  • The same happens to comments (C4) and change marks.
  • The sync finds a duplicate id after it pulls, and gives the LOCAL one the next free number (T22 becomes T23), its links and part file following.
  • Ids stay short, so they're easy to say in chat.
  • An id said in chat before the sync can change: the log says so.
  • T22a for Ana, T22b for Ben: never collides, never changes.
  • Every id gets longer, and the id rules, the lint and the links all change.
  • a renumbering step in the sync; ids unchanged otherwise
