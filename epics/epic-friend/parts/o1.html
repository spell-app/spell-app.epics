Most of the setup for one person is already built and documented. This epic adds what's needed for a team.

  • Today, one person can adopt epics in their own repo. The adopting README covers it in three steps, and it has run end to end outside Spell, in a throwaway repo: 
    node ~/www/spell/epic/bin/epic plugin install   # once per machine:  skills, hooks, `epic` on the PATH
cd ~/www/my-app && epic init                    # once per repo:  .epic/config.json5, the content repo beside it
epic repo add && epic hub ensure                # the epic server, port 4848, shows the pages
# then the VS Code extension, built and installed by hand
  • What's missing for a team:
    • The plans live in a content repo beside the code, for example my-app.epics. It's committed after every turn, but nothing clones, pulls or pushes it. So a second person has no way to get the plans.
    • Everything a person writes is filed under "Owen", whoever wrote it.
    • The install needs a Spell checkout: the plugin isn't on npm yet, and its hooks need Spell's code to run.
  • The goal, for a second person joining: 
    git clone git@github.com:friend/my-app.git && cd my-app
epic plugin install       # once per machine (Q3 decides where it comes from)
epic init                 # finds the committed config, CLONES the team's content repo beside it
epic hub ensure           # this person's own epic server
# from then on:  each turn's commit is pulled and pushed, and pages name who wrote what
    • There's no new "join" command: epic init already skips the steps that are done, and keeps a config it finds. It learns to clone the content repo when the folder is missing.
