Setup for one person was already built and documented. This epic added what a team needs.

  • Before this epic, one person could adopt epics in their own repo. The adopting README covered it in three steps, run end to end outside Spell, in a throwaway repo: 
    node ~/www/spell/epic/bin/epic plugin install   # once per machine:  skills, hooks, `epic` on the PATH
cd ~/www/my-app && epic init                    # once per repo:  .epic/config.json5, the content repo beside it
epic repo add && epic hub ensure                # the epic server, port 4848, shows the pages
# then the VS Code extension, built and installed by hand
  • What was missing for a team, and what fixed it:
    • The plans live in a content repo beside the code, for example my-app.epics. It was committed after every turn, but nothing cloned, pulled or pushed it. Now epic init makes or clones it, and every turn pulls and pushes it (P4, P5).
    • Everything a person wrote was filed under "Owen", whoever wrote it. Now each person, and each agent, is named (P1, P2, P10).
    • The install needs a Spell checkout: the plugin isn't on npm yet, and its hooks need Spell's code to run. Still true (Q3); README/npm.md says how publishing will go.
  • As built, a second person joining: 
    git clone git@github.com:friend/my-app.git && cd my-app
node ~/www/spell/epic/bin/epic plugin install   # once per machine, from a clone of Spell for now (Q3)
epic init                 # finds the committed config, CLONES the team's content repo beside it
epic server start         # this person's own epic server (O1:  the same server `epic hub` starts)
# from then on:  each turn's commit is pulled and pushed, comments too, and pages name who wrote what
# with Codex:  epic plugin install --codex, once per machine (below, "Other agents (Codex)")
    • There's no new "join" command: epic init already skips the steps that are done, and keeps a config it finds. It clones the content repo when the folder is missing.
    • The FIRST person's epic init sets the shared repo up itself: it asks what to call it, suggesting my-app-epics, makes it on GitHub with gh, pushes, and writes its address into the config. It prints a few lines of what it did, with a link to the epics README for the rest. It asks private or public first, private by default (T19).
    • The plugin comes from a clone of Spell for now. Epic repo-split is publishing it to the plugin marketplace soon; the README then switches to /plugin install epic@spell.
    • epic hub ensure is out of the README: in a repo set up by epic init, epic server start already starts the machine's one epic server, so that's the command people see (O1).
