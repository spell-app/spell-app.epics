The plugin acts as if every repo were Spell: its worktree hook breaks Claude Code's worktrees in repos without epic init, and settings left out fall back to Spell's values.

  • In a repo with no epic settings, a Claude Code worktree is made exactly as Claude Code would make it.
  • No default names spell-app, ../spell-app-dev or yarn install; Spell's own config spells those out.
  • The docs and comments name ~/.spell-epic, the folder the code uses (T1).

The worktree hook does Claude Code's own plain worktree in a repo without epic settings. A missing setting falls back to a neutral default, never Spell's. The docs name the real home folder.

  1. One "is this repo set up?" check (coherence). EpicConfig.ofSetUp(cwd): the config when the repo has one, else nothing. Used by the end-of-turn hook, the left-worktree and behind-main hooks, the worktree guard and the worktree hook, which each check their own way today.
  2. The worktree hook in a repo that isn't set up does what Claude Code does by itself: git worktree add under .claude/worktrees/<name>, on a new branch, and prints the path. No links, no install.
  3. Defaults from the repo, not from Spell (coherence). RepoInit.settingsFor(main), what epic init writes, moves into EpicConfig, and a setting left out takes its value from there: ../<repo>.epics, the repo's own install command, its own window names. DEFAULTS keeps only the keys with no per-repo value. First: the kit's own config spells out every Spell value it relied on.
  4. The home folder (T1): the adopting README and the two comments say ~/.spell-epic.
  5. Checked: a hook test in a throwaway repo with no config; a config with keys left out gets the repo's values; epic config in the kit prints the same before and after; yarn review at the kit's root and in epic/.
  6. Left out: the other rough edges of the adopting README's nine (VS Code on macOS, the extension built by hand: T3).
