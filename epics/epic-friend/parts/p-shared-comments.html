A comment or mark reaches the rest of the team only once its own Claude has answered it, since the review inboxes stay on each machine.

  • Comments and marks are shared through git before they're answered: the inbox split into a shared part by person, and a local part (listening, heartbeat, working). (Q4, its later step)
  • Each person's Claude answers that person's comments; others see them, and the answers, after a sync.
  • Old inboxes are read as before, and moved over once.

The inbox splits in two: a shared part, the comments and marks, kept by person and synced with the plans; and a local part, who is listening and the heartbeat. A rule says whose Claude answers what.

  1. Split the inbox. Each epic page's inbox becomes two files: a shared comments file per person, committed and synced, holding that person's comments, marks and their threads; and the local inbox, never committed, holding who is listening and the heartbeat. Its name is keyed by the person's id or name, per Q10. ReviewInbox, CommentList and GuideInbox read both.
  2. One writer per file. Each person writes only their own comments file, so a pull never conflicts there. Claude's answers go into the file of the person it answers, with Claude's marker (Q9).
  3. Whose Claude answers (coherence). The claim is the inbox's existing taken / working state, now with the name of whose Claude took it. The rule: a session takes only its own person's comments, unless nobody has taken one.
  4. Committed with the plans, through the content repo's marked .gitignore block from the Sync Every Turn phase (coherence): the local part kept out, the comments files let in.
  5. Old inboxes are read as before, and moved over once, into the person's file.
