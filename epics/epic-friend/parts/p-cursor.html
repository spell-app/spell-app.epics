Everything that opens, moves or reloads a window calls VS Code's code, and the extension is installed only into VS Code: in Cursor the Review tab and the window moves don't work.

Owen's comment C10 on the guide: "phase to get working in Cursor on other machines".

What's known (sources below):

  • Cursor is built on VS Code: it runs VS Code extensions, and its command, cursor, takes VS Code's flags, --install-extension <file.vsix> among them.
  • Its catalog is Open VSX, not Microsoft's; a .vsix installs by file, which is how ours ships anyway.
  • Claude Code installs in Cursor as the same extension (anthropic.claude-code). Since Cursor 3.15.6 its panel opens as an editor tab, and the right side bar is kept for Cursor's own agent: our Review tab, in VS Code's right side bar, needs another home there.

Outcomes:

  • Which editor: one Editor helper, read by everything that runs code today (the window script, the plugin install, the openers); editor in the settings, else the window's own (TERM_PROGRAM, VSCODE_* / CURSOR_* in the environment), else code.
  • The extension in Cursor: epic init installs it with the right command (after P15's install step).
  • The Review tab in Cursor: the extension's view registered where Cursor shows it (the primary side bar, or "View: Move View" said in the docs), checked in a real Cursor.
  • Window files: the .code-workspace files open in Cursor as they are; the window settings the extension writes go to Cursor's settings folder where they differ.
  • Docs: the guide's limit becomes "VS Code or Cursor", README-epics says how to set editor.
