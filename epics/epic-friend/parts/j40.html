What Codex's docs say (read 2026-10-29), and what P12 did with each:

  • Codex: build skills: a skill is a folder with a SKILL.md (name, description), the format ours already are; the Codex CLI lists the person's skills from ~/.agents/skills/ in every repo, following links; agents/openai.yaml's policy.allow_implicit_invocation: false stops Codex picking a skill by itself, while $name still calls it; the skills list takes at most 2% of the context, 8,000 characters when Codex can't tell.
  • Codex: build plugins: .codex-plugin/plugin.json takes skills and hooks paths (we set both: the SAME skills/ folder, and Codex's own hooks file); but a local plugin is installed only through Codex's desktop app, and nothing says the CLI runs a plugin's hooks.
  • Codex: sub-agents: a custom agent is a TOML file in ~/.codex/agents/ with name, description, developer_instructions; the parent waits for its sub-agents.

So epic plugin install --codex LINKS each skill into ~/.agents/skills/ (the same files) and writes the designer and coherence as ~/.codex/agents/epic-<name>.toml, generated from their Claude Code agent files. The plan said it would add the kit's marketplace to Codex and turn the plugin on for the repo: the CLI has no way to install a local plugin, so the manifest is there for the desktop app and the published package, and the links are what the CLI reads.
