The content repo, where the plans live, exists only on the first person's machine: nothing creates a remote, and nothing clones it.

  • The first epic init sets the shared repo up itself: it asks for a name, suggesting my-app-epics, makes it with gh, pushes, and writes the address into the config. (Q1)
  • It prints a few lines of what it did, and a link to the epics README.
  • A second person runs the same epic init: it finds the address and clones the plans beside their checkout. No "join" command.
  • Without gh, or offline, it says what to run by hand, and the rest of init still works.

The first person's epic init asks what to call the shared repo, makes it on GitHub, pushes and writes its address into the config. A later person's epic init clones it when the folder is missing.

  1. The setting. EpicConfig gains contentRemote: the shared repo's address, empty when there is none; epic init writes it, with its comment.
  2. Check gh first. Before making the shared repo, epic init checks that GitHub's command, gh, is installed (gh --version) and logged in (gh auth status). If not, it prints the two commands, brew install gh and gh auth login, the page for other systems (https://cli.github.com) and the epics README's link, then carries on with the rest of init: never an obscure failure.
  3. The first person. When there's no address and no remote: epic init asks "What should the shared epics repo be called?" through Phase 1's CLI.ask (coherence), suggesting <repo>-epics; --content-repo <name> answers it without a terminal. It makes the repo private, with gh repo create, under the code repo's owner, adds the remote, pushes, and writes the address.
    • --remote <address> uses a repo that already exists; --no-remote skips it, as today.
    • GitHub only, for now.
  4. Later people. The address is in the config, the folder missing: epic init clones it there, then links as today. Cloning needs only git, not gh.
  5. What it prints: a few lines of what it did, then "next" steps and a link to the epics README (written in the README phase).
  6. Checked: tests with a local bare repo as the remote and a stubbed gh: first init pushes, a second clone's init clones; gh missing, and not logged in, each print the two commands and the link. One real run in a throwaway GitHub repo by hand. yarn review in epic/.
  7. Left out: pulling and pushing each turn (the next phase); hosts other than GitHub.
