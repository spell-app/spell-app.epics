The editor ignores Spell UI's themes: its colours are hard-coded, and the code is always Monaco's plain light theme.

  • The editor applies a Spell UI theme at start-up, picked from a menu and remembered in the browser.
  • Its hard-coded colours become theme tokens.
  • The code gets Shades of Purple in dark mode, and a matching light theme.
  • A theme menu in the editor, reusing the docs site's ThemePreference and its theme menu.
  • The editor's own colours (the menu bars, the dark page background, the panels) and the Things and Types explorers' colours all come from --ui-* / --spell-* tokens, so every theme reaches them.
  • Shades of Purple, ported from its VS Code theme file, with rules for Spell's own token names (headings, keywords, types).
  • The code theme follows light and dark with the rest of the page.
  • The editor starts in a Spell UI theme, Fruity by default, and remembers the one picked: a palette button in the top bar of the editor and of the landing page (Spell UI's own docs palette: Light, Dark, Auto, and every theme).
  • The editor keeps its own theme, apart from the docs site's; light / dark is one choice for every Spell site.
  • The editor's own colours (the page behind the panes, the panes, the console, the tree, the Things and Types explorers, the syntax colours) are Spell UI tokens now, so every theme and dark mode reach them. With Fruity, the wallpaper shows behind the panes.
  • The code is Shades of Purple, ported from its VS Code theme, with a matching light version; it follows the page's light / dark, under any page theme. Rules for Spell's own words: headings, keywords, types, properties, actions, constants.
