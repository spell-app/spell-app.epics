A theme is a long CSS sheet, hard to read and change as values.

  • Glass is 525 lines and Spell 763: most of it values, each colour written as light-dark(light, dark), with real CSS rules mixed in below.
  • The themes to come, the tints, the Full Theme Builder and saved themes all need a theme as values, and could get them today only by reading CSS.

mark

  • ONE file per theme, <name>.theme.json5, in Spell UI's themes folder:
    • what it builds on (Fruity on Glass), the palette it borrows (Apple's), the rules sheets it adds
    • its values in NESTED groups, groups inside groups (surfaces > page, panel, bar), the same tree the Full Theme Builder shows as folds
    • each value one for both schemes, or a light and a dark one
  • The theme's CSS sheet generated from it, committed, by yarn gen:styles, as the foundation's sheets are: nothing that loads a theme changes.
  • What values can't say stays real CSS: a rules sheet the file names.
  • Spell, Glass, Fruity and Merlot converted, and they look exactly the same.
  • A type and a JSON schema, so VS Code completes and checks a theme file.
  • ONE shape for a theme, which the later phases use: the facelift and the new themes are written in it, the tints and the builder edit it, saving writes it.

  1. When: right after P17 · One Theme Set, before P19 · Spell Facelift and P20 · Four New Themes (Owen: "Do this before P18", Spell Facelift's number then), so they write their themes as data from the start.
  2. The file: <name>.theme.json5, beside its sheet in Spell UI's themes folder.
    • extends: the theme it builds on (Fruity: "glass"); palette: the hues it borrows ("apple"); rules: its rules sheets (below); title, only for a theme a person names (a saved theme, P25): Spell's take their file's name.
    • Its values in NESTED groups (Owen: "grouping should be nested!"): typography > size, family > body, heading; radii > s, m, l; surfaces > page, panel, inset, bar; text > body, strong, muted, light; borders; brand > primary > color, on ..., links, focus; semantic > positive ...; shadows; palette > red > base, on, text ...
    • Each leaf one value for both schemes, or { "light": ..., "dark": ... }, written out as light-dark(). A value is CSS text; "{surfaces.panel}" points at another leaf, the way the design tokens file already writes one.
    • Two open groups: components, a family's own tokens under its name (menu > segmented-active-background), and own, the theme's private values (glass-blur, glass-wallpaper). 
    {
  "$schema": "./theme.schema.json",
  // Merlot:  a code studio in wine reds, flat panels a step off the page
  "palette": "apple",
  "typography": { "size": "15px" },
  "radii": { "s": "6px", "m": "8px", "l": "12px" },
  "surfaces": {
    "page": { "light": "#e8dade", "dark": "#1a0c13" },
    "panel": { "light": "#fefcfd", "dark": "#3d1f2d" },
    "inset": { "light": "#f4ecef", "dark": "#2b1520" },
    "bar": "{surfaces.panel}"
  },
  "text": {
    "body": { "light": "#3a1824", "dark": "#f3e3e9" },
    "muted": { "light": "#6d4555", "dark": "#cfacb9" }
  },
  "brand": {
    "primary": {
      "color": { "light": "#8c1d40", "dark": "#f4a65f" },

    }
  },
  "components": {
    "menu": { "segmented-active-background": "{brand.primary.color}" }
  }
}
  3. The tree, written ONCE, as data: themeTree in styles.en.ts, beside the foundation's other scales.
    • Each leaf names the token it sets: surfaces > page is --ui-background.
    • The generator, the schema and the Full Theme Builder (P24, its folds) all read it: a token added to the tree shows up in all three.
    • (coherence) Its top groups are the theming page's token tables' groups, by the same names (typography, radii, text, surfaces, brand, semantic ...): one list, the tables read it too.
  4. What stays CSS: rules sheets in themes/rules/, a folder, so no theme menu lists them (as palettes/ today).
    • glass.css: the blur behind every glass surface, the inverted segment, the flyout.
    • spell.css: its fonts, its headings, the brand's own components, the accent colour's class.
    • modern.css (coherence): the rules Glass and Spell each copy today, about 70 lines: anchors below the sticky header, tabular numbers, link underlines, the image outline, the button press, no animation while the scheme switches. One copy, which the four new themes name too.
    • A page setting that isn't a token (font smoothing) goes there too.
  5. The writer: ThemeFile (new), beside StyleGenerator.
    • It merges a theme's palette and what it extends, checks every name against the tree (a wrong one fails, naming the group it belongs in), and writes the sheet: the values on :root in @layer ui.theme, then its rules sheets.
    • Fruity's sheet still imports Glass's, as today: no copy of the glass.
    • Pure, text in and text out, as StyleGenerator is: it runs in node and in the browser.
    • yarn gen:styles writes the theme sheets too: one command for every generated sheet, no new script. Each sheet's first line says it's generated, from which file.
    • The test that keeps the generated sheets current covers them; spell-ui's merge list marks them generated, so a merge of main makes them again.
  6. At build time, not in the page (recommended):
    • Nothing that loads a theme changes: UI.themes still reads the folder's CSS, so no JSON5 reader and no writer ship in a page, and the contrast test, the design tokens tool and the editor read the same sheets.

    • In the page only where it's needed: the builder (P24) and saved themes (P25) run the same ThemeFile for the theme being made, reading a theme's file as text with the kit's parseJSON5(), loaded only there.
