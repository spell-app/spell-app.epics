The Inspector shows what a thing is, but not what can be done to it: only a right-click menu or the Things view's ▶ does an action.

  • Pick a Solitaire card: an Actions section lists what can be done to it (turn it over, turn it face up, play it, put it on a pile), each with a play button.
  • Press one: it's done to that card, and the game redraws.
  • An action that needs something picks it in a field: "put it on a pile" shows a select of the game's piles (Foundation 1, Tableau 3 ...); one taking text or a number, an input.
  • An action that isn't enabled now (its enabled when says no) is dimmed, and can't be pressed.
  • Where it sits: Q45; how it meets Thing Inspector's action rows (P26): Q46.
  • An Actions section in the properties card: each action pressable, done to the picked thing.
  • An action's parameters as fields: a select of the game's piles, an input for text or a number.
  1. A thing's actions, with what they take: the runtime's list (ThingRegistry.actionsOf()) knows each action's name and how many arguments it takes, not their types.
    • The compiler records each action's parameters, name and type (a pile, text, a number), in the words file beside the headings P26 records there (coherence: one record of a type's members, not a second).
    • Whether each is enabled now, and its title: what the menus already read (acting.ts's isEnabled, the MenuItem shape ActionMenus draws), so a right-click menu and the Inspector agree.
    • Doing one with arguments: perform() takes them, and hands back its wait (as P26 plans), so the button shows it's busy while put it on a pile pauses.
  2. The section, in the properties card (PropertiesCard), a folding band titled Actions:
    • one row per action, its words from the words file, in the file's order, then a play button
    • its parameters as fields on the row, under its title when it has more than one
    • dimmed while not enabled, following the thing live
    • an error goes to the Console, as the program's own would
  3. A parameter's field, by its type:
    • a type of the program's (a pile): a <ui-select> of the running program's things of that type, by their names (from core.things, as the Things view lists them), sub-types included (tableaux and foundations are piles)
    • text: an input; a number: a number input, right-aligned
    • yes or no: a checkbox; one of a list (one-of): a select of its values
    • anything else: an input read as spell would read a value, e.g. a quoted text
    • The play button is off until every field has a value.
  4. Thing Inspector's rows (P26): as Q46 decides; recommended, P26's action rows go and the Actions section is the one place, ⚡ for events, ▶ for actions. P26's plan gets the change mark then.
  5. Checked:

    • the Inspector's browser test: a Solitaire card's Actions; "turn it over" turns it; "put it on a pile" with a foundation picked moves an ace there; a disabled one can't be pressed
    • yarn review in parser and app; the parser's speed test on this branch and on main
  6. Left out:
    • picking a pile by clicking it in the app, instead of in the select
    • questions (is a (rank)) and drawing (to draw it): not actions, not shown
