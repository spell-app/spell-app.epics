The editor is one page in three columns: the spell you type (Monaco) over a console, then the running program, its compiled JavaScript and its parse tree. It's Solid 2 and Spell UI, but it ignores Spell UI's themes: its colours are hard-coded.

  • The chrome is two purple menu bars (AppMenu, PanelMenu), on a fixed dark grey (#343a40).
  • The code theme is Monaco's plain light vs, in a proportional font (Lato). There's no way to pick another, and no theme of ours is registered.
  • The landing page (ProjectChooser) is a plain grid: Projects, Examples, an empty Guides column, and "Create new ..." buttons.
  • The brand pages already show what it could look like: the Spell App, Spell Docs and Spell Marketing pages in the Brand tab. Lavender on near-white, aubergine in dark mode, Palatino headings with an italic lede, pill buttons, soft violet shadows, blobs and flourishes.

The Things and Types explorers

  • In code they're ThingExplorer (the running program's things, live) and TypeExplorer (every type the program knows, with details).
  • Already shared: VS Code's runner panel and the <spell-app> element both show them, in a tabbed pane.
  • The web editor has everything they need in the page already: the language service it runs for Monaco gives the types, and the running program gives the things. So it's a new tab, and a refresh after each compile.
  • Their CSS hard-codes colours: those become theme tokens, or a theme can't reach them.

Rough edges a visitor would see

  • the console's test buttons (an alert saying "Yo!", a prompt for "Bob" ...)
  • About, Docs, Help and Publish buttons that do nothing yet
  • disabled "..." menus on every panel
  • the Projects column (yours, on your disk), the empty Guides column, and the "You" panel
