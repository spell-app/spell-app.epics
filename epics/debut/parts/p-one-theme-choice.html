  2. How each place reads and writes it
    • Every place through ONE ThemePreference, on the kit's PrefStore with the page server as its place (ServerPlace, /api/prefs), which the person's space answers.

  3. A change reaches open pages live
    • Saving spell-site through /api/prefs tells every open page over the page server's live channel (LiveReload.send("prefs", { store, key, value }), the socket every served page already keeps).
    • The page's live client hands it on; ThemePreference applies it and its menus follow (subscribe()).
    • The editor: its /api forwarding carries the socket too (ws: true, checked); and every page also asks again when it comes back into view, so a missed message is never stale for long.
  4. The browser's copy: first paint only
    • localStorage keeps the last value seen, so the head script and restore() draw the right theme before the space answers; the space's value always wins, and replaces the copy.
    • It is never the source of truth while a space answers.
  5. The read-only public build (P9): no server
    • The visitor's browser keeps the choice, the same way it keeps their edits: the browser's database (DatabasePlace), as the build's StaticFiles does.

  6. The old keys, moved once
