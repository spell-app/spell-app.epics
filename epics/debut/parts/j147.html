The plan said the class's flag would NAME its getter, as an action's enabledWhen does. Built instead: the flag stays true / false, and a condition is a getter of a fixed name, <ability>When (clickableWhen), which core.isAble() reads.

  • Why: the getter's name differs per target (draggableWhen in JavaScript, draggable_when in Python), so a string naming it would need a writer-aware literal; a fixed name needs none.
  • An event implies its ability only when no type below the core's says the word: a joker is not draggable beats its - on drag:.
