spell-app's monaco.ts loads Monaco's features through register.all, which holds only the viewport semantic tokens, not the document ones (only Monaco's editor.main has those). So SpellLanguageFeatures' semantic tokens provider was never called: keywords, types and properties stayed plain, with only strings, numbers and comments coloured by the instant tokenizer. Fixed in P3 by importing documentSemanticTokens beside register.all; found while porting Purple.
