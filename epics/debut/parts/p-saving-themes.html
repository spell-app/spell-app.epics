A theme made in the theme editor can be kept only once, and never becomes one of Spell's.

  • Use this theme keeps ONE theme per browser (SavedTheme): keeping another replaces it, and it has no name.
  • It shows in no theme menu: only the editor puts it back.
  • Nothing carries it to another browser or computer but Copy CSS.
  • Making it one of Spell's own themes means copying that CSS into a sheet and the theme list by hand.
  • The builder (P21) saves NAMED themes, any number, where SavedTheme keeps one today: save, save as, rename, delete.
  • Saved themes show in the theme menu in every place, in a "Yours" group beside Spell's, each with its tint; picking one wears it, and it's remembered like any theme.
  • Export a saved theme to a file; import one back, in any browser.
  • In development (the page server), "Save into Spell UI" writes the theme as a real theme file in Spell UI's themes folder and adds it to the theme list: the builder is how Spell's own themes get made.
  • A theme kept before this phase (Use this theme) opens as the first of Yours.

  • The builder saves themes by name, as many as you like; rename and delete them.
  • They show in the theme menu, in a "Yours" group beside Spell's, each with its tint.
  • Export one to a file, and import it again, on another computer.
  • While working on Spell (served by the page server): "Save into Spell UI" writes the theme as a real theme file and adds it to the theme list, so the builder is how Spell's own themes get made.
  1. A saved theme: a name, an id, and what the builder made (UIT.ThemeChoices: its base theme, its tint, its colours) with its sheet's text.
    • Kept by SavedTheme, grown from one theme to a list, in this browser, as today (PrefStore).
    • (coherence) SavedTheme stays the one home: no second store for the menu, the builder or the files.
    • The id is made once, when it's first saved, and never changes: a rename changes only its name (WWOD §3, names aren't ids), so a menu that remembered it still finds it.
    • The one theme kept today becomes the first of the list, named after its base ("My Fruity").
  2. In the builder: Save (asks a name the first time), Save as, Rename, Delete (asks first).
    • Start from lists Yours under Spell's themes; opening one edits it, and Save writes it back.
    • Use this theme stays: it saves, then wears it.
  3. In the theme menu (<ui-docs-themes>), in every place: a "Yours" group after Spell's, only when there is one.
    • Each with its tint's swatch beside its name; P20's tint row doesn't show for it (its colours are its own).
    • Picking one wears it the way SavedTheme puts a kept theme on today: its base theme, then its sheet.
    • Remembered (ThemePreference) by its id, stored yours:<id>; one deleted since: the place's default.
  4. Export and import, in the builder.
    • Export: a <name>.theme.json file, the name and choices (the sheet is made again from them, so a file from an older Spell still opens); downloaded through the button's own download link.
    • Import: a file picker (Spell UI's file input); the theme joins Yours, a name already there gets " 2". A file that isn't a theme says so, and nothing is added.
  5. Save into Spell UI: in development only, where the page server answers.
    • A route of Spell UI's own, declared in its package's page server settings ("pageServer": { "routes" }), as spell-epic's and the editor's are: the builder shows the button only when that route answers, so a published site never has it.
    • It writes spell-ui/src/styles/themes/<name>.css: the builder's sheet as a whole theme, its header comment saying what it is and that the builder made it, light and dark; a name already there asks before it overwrites.
    • It adds the name to the theme list (UI.themes.own): the list gets start and end markers, and the route splices the new name in with the kit's spliceGenerated(), which Spell UI's generators already share.
    • The page server rebuilds what's stale, so the new theme is in the menu on the next reload; the contrast test checks it by itself, since it runs over own (P17).
    • It's then a file in Spell UI's repo, to review and commit like any other.
