• A thing's starting values (what it's made with, and its create it) aren't changes: its handler hears changes from when it's made on.
  • Nor is setting the same value again, nor what a recompile carries over.
  • Each change sends one event, just after it lands (a microtask): set twice in a row, the handler runs twice, both reading the newest value, each event carrying its own value and was.
  • Only to the thing itself: a card's change never reaches its pile or the app.
  • Python's core doesn't send them yet: its compiled handler is there, nothing calls it.
  • Solitaire's game says when its score changes: all 52 cards on the foundations puts " -- You won!" after the score. Solitario (Spanish) is unchanged.
