No theme looks like today's macOS.

  • A new Spell UI theme, fruity, with frosted glass done in CSS alone.
  • Light and dark, pickable in the docs site and the editor.
  • The system font, rounder corners, soft shadows.
  • Translucent cards, menus, popups, panels and dialogs, with a blur behind them for the glass (not gone too far).
  • Listed as one of Spell UI's own themes, not a Fomantic port.
  • A test, beside the other themes'.

Owen looked at fruity on Spell UI's docs (test V1), with a screenshot (v1-owen-1.png): 'Spacing problems. Header bars backgrounds should go all the way to the edges. Merge day/night buttons into the theme picker. Lower opacity slightly in headers and bubbles around the button groups etc to simulate glass.' So P2 reopens for a follow-up: the spacing, edge-to-edge header bars, one theme picker with light / dark in it, and thinner glass on headers and the bubbles around button groups.

Owen's second look (v1-owen-2.png, v1-owen-3.png): 'Tighten up top bar so it doesn't wrap. Move hamburger left a bit, move search to right side. Theme picker and owners/variables bars don't match theme. Scrolling overlaps the Spell Docs header.' And: 'Agent: You are a graphic designer, very familiar with the MacOS look. Look at the page and point out visual consistencies and ugliness. DO NOT go too crazy and add tons of padding around elements. Use the buttons page as an example.'

Owen's third look (v1-owen-6.png): 'still overlapping top bar poorly, increase opacity on sticky things. I like the way that header bars in the first theme example are white, helps distinguish toolbars from content underneath them. flyout sidebar: doesn't slide back when dismissed, just disappears. Keep the page active when it's visible (no background scrim). Clicking a component doesn't dismiss sidebar.'

Owen's fourth look (v1-owen-7.png, v1-owen-8.png): 'Still overlap with examples/etc tabs. Add more horizontal padding for tabs, including types/groups/etc. Add vertical padding when sticky so things don't run together. Less opacity around pill bar. Pill bar hover is bad. Can we do the slidey-pull bar selected thing like Apple does? Why does types have the T? Make that look like a pill button bar as well. Types / Button headers need some visual differentiation, break when sticky. Would be cool if the top Spell UI bar was transparent-ish when not pinned. Sidebar -- click on the page should make the sidebar hide. Animation should be quicker, especially on hide. When the window is narrow, we should see some of the buttons with < and > buttons when there is more to scroll. Consider <ui-toolbar> which has this behavior, subclass of ui-menu.'
