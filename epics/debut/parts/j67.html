How P16 step 2 makes ui-table scroll sideways for every table that doesn't stack.

  • Whether a table stacks is decided by the table sheet's own rules: the viewport, its own width, stack-by, the page's tokens.
  • The box that scrolls is inside the element's shadow root, and can't read that decision.
  • So UITable watches its width and the table's (isTooWide), and while the table is wider, its box scrolls sideways (sideways), height uncapped.
  • A stacked table always fits, so it never scrolls.
  • That box is then a focusable, named region, as a scrolling table's is.
  • Its name: the element's aria-label, else the caption, else the table's own aria-label (new), else "Table". Several API tables on one page each need a name of their own.
  • Before JavaScript runs (a static page), a wide table still spills, as before.
