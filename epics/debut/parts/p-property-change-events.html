A program can't say when its score changes:: Spell has no event for a property changing (J152).
  • when (its) <property> changes: and on <property> change:, in the outline and as a tag, run each time that property's value changes.
  • Built on the reactive store the things already have, so the event fires once per change, after it lands.
  • The Inspector lists them in its Events band like any other event.

Owen picked this on (Q47's examples: <when (its) score changes>), and said "start on the other phases" (2026-10-29): written accepted.

  1. What a program says, in a template's outline and as a tag, every Q47 form:
    • - when (its) score changes:, - on (its) score change:, changed too; the small word (its, the) and the colon optional; a one-line form, - when score changes show "You won!"
    • tags: <when its score changes>...</>, <on score change(:) ... />
    • Spanish: - cuando (su) puntuación cambia:, - al cambiar (su) puntuación:
    • The property is one its type (or a type it inherits from) declares, read through its words (high score); anything else stays the event it reads as today.
  2. What it compiles to: the thing's handler for event score-change, onScoreChange(event), as - on score change: already compiles; a new word rule finds the property, changed_property, so when ... changes names the same event.
  3. When it runs: the core hears every property write in one place already (noteSetting(), the undo history's and the while handlers' hook).
    • A real change (a new value, not the same one) to a thing that has a handler for it sends score-change to that thing, with value and was, once per change, just after the write lands (a microtask), through core.send(), as every event goes.
    • Not while the thing is being made (its starting values), nor while a recompile carries the game over.
  4. The Inspector: its Events band lists them as written, ⚡ when its score changes with its code under it, from the program's text (InspectorSource's reader), outline and tag forms.
  5. The example: Solitaire's game says - when its score changes: ... if the foundations hold all 52 cards, "You won!" in its hint. (Or a smaller line, if that reads wrong in the game.)
  6. Checked: rule tests (English, Spanish, tags), the core's change events (once per change, after it lands, none while made), the Inspector's source reader; yarn review in parser and app; the parser's speed test on this branch and on main.
  7. Left out: a change of a list's items (a pile gaining a card) isn't a property change; Python's core doesn't send them yet.
  • - when (its) score changes:, - on (its) score change: (also changed, has changed), one line or nested, and as tags: <when its score changes>...</>, <on score change: ... />; in Spanish - cuando (su) puntuación cambia: and - al cambiar (su) puntuación:.
  • Each is the thing's handler of score-change; the core sends it each time the property changes, once per change, just after it lands, to that thing only; never for its starting values, the same value again, or a game a recompile carries over (J161).
  • The Inspector's Events band lists them as written, ⚡ when its score changes with its code, from the outline or the tag.
  • Solitaire's game: once all 52 cards are on the foundations, its score line reads "Score: … -- You won!".
  • Checked: every form (outline, tags, Spanish) compiles the same; the core's change events; the Inspector's reader; live in the editor, light and dark, desktop and phone. Python's core doesn't send them yet.
