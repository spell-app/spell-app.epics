Owen, 2026-10-25: yes to all four.

  1. name is what a value is called: a form field, a property, a thing's name. It's what data is keyed by.
  2. id is what finds one element on the page: anchors, <label for>, the page's getElementById. It's never a data key.
  3. Since layout tags use id="T1" to mean "the thing named T1" (epic drawable-thing Q9), either make them use name="T1", or accept id as an alias for it.
  4. Forms stop falling back to id for validation, so a field without a name is flagged rather than half-working.

Where things stand today:

  • A form (<ui-form value>) binds its fields by name (property, then attribute), but its rules and messages find a field by name, else by id (FormFields.identifierFor()).
  • Spell things have a generated id and their own name; drawable-thing Q9 picked "by id or name" for layout tags.
