The editor needs the page server for every file, list and save.

  • A static build of the editor: plain files, edits kept in the visitor's browser.
  • A command that builds it, and serves it the way a host would.
  • A browser version of the editor's one file hook (LoadableFile.fetch): project lists from files written at build time, edits saved in the browser, a "Reset example" button (Q2).
  • The few calls that skip the hook (create, rename and delete a project, the You panel) go through it, or are hidden.
  • Hidden in the public build: the Projects column, the You panel, the console's test buttons, the About / Docs / Help / Publish buttons that do nothing yet, the disabled "..." menus, the debug globals, the test fixtures.
  • A build script: the examples and guides compiled, their scope packs, the lists, and a rule sending every unknown path to the page.
  • A spell command, suggested before it's built (commands guide first): spell app site build | serve; the commands page kept true.
  • No deploy yet (Q6): a todo.
  • spell app preview build writes the editor as plain files into app/dist-static/:
    • the editor itself, built by Vite as static files
    • the examples and the guides, compiled, with each group's list and each project's index as JSON files beside them
    • a fallback that sends every unknown page to the editor (404.html, _redirects)
  • spell app preview serve shows the build as a host would, with no page server (port 4848, --headless).
  • In the browser, every file is read and saved through one hook, LoadableFile.fetch, answered by StaticFiles:
    • files come from the build's copies
    • a visitor's edits are kept in their browser as they type
    • "Reset Example", beside Run, asks first, then forgets them
  • Creating, renaming and deleting projects and files, and the You panel, go through the same hook: the preview refuses them.
  • One flag hides what needs a server: isStaticBuild in code, :root.spell-static in CSS. Gone in the preview: the Projects section, the You panel, About, Help, Publish, Settings, the console's test buttons, the "..." menus, the debug globals.
  • The commands page lists both commands; README-cli too.
