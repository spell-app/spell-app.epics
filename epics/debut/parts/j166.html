The buttons kind is now a segmented <ui-menu name>, which <ui-form> reads and writes like a select. It isn't a form-associated element, so a NATIVE <form> (its FormData, form.elements) doesn't see it; <ui-form> and the property editor's binding do.

  • Nothing changes for the editor, the Inspector or the theme editor.
  • A page posting a native form with a buttons property would miss that value; as="radios" keeps the old radios.

Make <ui-menu> a form element! Or should we make a subclass of <ui-menu> which works as an element? What do you think?

Owen: "Make <ui-menu> a form element!" It's form-associated, as <ui-button> is (elementSetup.isAFormControl, the vocabulary's formControl, the root catalog regenerated): a named segmented menu choosing one submits its value (FormData, form.elements), and a form's reset chooses its starting value again; any other menu (and <ui-toolbar>, which extends it) submits nothing.
