- on drag cancelled show "x": with no colon, an event's name of several words can't be told from its code by position alone. The parser (event_words) takes the fewest words (at least two) whose rest parses as a whole statement, read as the handler's body would be (it the thing); none does, the most words, as with a colon. A line with a colon is read as before.

  • Costs a statement parse per word for an on / when line with no colon.
  • The Inspector reads a thing's events as written, by text (eventsInSource()): it splits a one-line event only for the page's own events (click, double click, drag, drag cancelled, mouse ...), a regex; J145 stays open for asking the parser.
