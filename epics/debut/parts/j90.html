The coherence review of P20's plan found the switch that applies themes is the place to apply a tint, and the theme editor's sheet slot the wrong one.

  • Kind: rebuilt.
  • Where: P20 step 2, "the theme editor's own colour settings ... laid over the theme"; step 4, "Stored as glass:rose".
  • The one: UI.themes.apply(), the one switch that applies a theme (its slots, its "last call wins" count), learning a tint: a slot of its own after the theme's, holding ThemeSheet's text for the two choices.
    • Not ThemeSheet.applyToPage(): it puts its sheet in the one slot the kept theme and the live theme editor share, so a tint there would replace a kept theme, or be replaced by it.
    • In memory the theme and the tint are two fields; only the stored text joins them (glass:rose). So whatever reads the theme (the theme list, SavedTheme.follow(), the editor's chrome) still gets a sheet name: today an unknown name like glass:rose is forgotten, back to the default.
  • Net effect: a theme and a tint picked in a row land in order, and a kept theme's colours still win; no second path applying sheets in the menu or the editor.
  • Saves: a second applier and its race guard (about 25 lines); a pick that would forget itself.
