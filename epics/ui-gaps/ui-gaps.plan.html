Two sentences: what this plan does, and why.

Build the Spell UI components that spellx needs now that it has no native HTML elements (epic elemental-spell, Q46, Q50 A: "Build the gaps as Spell UI components, in a sibling epic"). Saga: Spell UI.

In a .spellx drawing every tag is a Spell word, a template, or a pack's component (`<button>` is always Spell UI's `ui-button`). So whatever HTML can draw that Spell UI can't is a gap. The full table, HTML group by group, and the clash list are in elemental-spell's Q50: epics/elemental-spell/elemental-spell.plan.html#q50.

The 10 significant gaps (5 small, 4 medium, 1 large), ranked:
1. Table rows and cells: `ui-table` only dresses a native table written inside it, so with no native HTML it has nothing to dress (`ui-row` / `ui-column` already belong to the grid).
2. A plain layout box for rows and columns, with gaps and alignment.
3. A link in running text (today `href` only works on buttons, cards, images, items ...).
4. A paragraph.
5. Inline styles: bold, italic, inline code, key caps (needed to show actions' shortcuts), a highlight.
6. A page frame (the never-built `<ui-page>`; a Page template draws inside it).
7. A drawing surface (canvas and shapes).
8. Video and audio files.
9. A term-and-value list.
10. A figure with a caption.
Minor: quotes, sub- and superscript.

Shared words to settle with elemental-spell (Q50's table): description, comment, event, property and action are decided by context; `section` stays Spell UI's folding block; `ui-label` is a badge, so lint points HTML habits at a field's `label=`; row / column decided with the table gap.

elemental-spell's P6 (drawings) uses what exists until each gap lands. About 20-30h.
