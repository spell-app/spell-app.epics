How long an old attribute name keeps working once it's renamed. Owen, in r1: "keep the old names working as aliases for a while (ask Owen how long)".

  • An ALIAS here is the old spelling, still accepted: <ui-button primary> draws the same as <ui-button color="primary">.
  • Old names are everywhere: every repo's pages and components, Spell UI's own docs, and about 2400 pages in the content repo (epic pages, guides) that use ui-* tags.
  • The plan has a sweep phase: a script that rewrites old names to new in any folder, run over every repo and the content repo.
  • While an alias lasts, the page prints a console note once per old name, so a page someone writes by hand still finds out.
  • The sweep rewrites every repo and page; the same phase deletes the aliases.
  • One set of words afterwards: the docs, the editor's inspector and the JSX types list only the new ones.
  • Cost: a page outside the repos, written with old names, stops looking right with no warning.
  • The sweep runs, the aliases stay a month, each printing its note once per page.
  • Then a todo deletes them.
  • Cost: a month of two spellings in the code, and a todo to remember.
  • Old names always work, as English muscle memory (as checked works for selected on a checkbox today).
  • Cost: two names for most attributes, for ever; the inspector and the docs must hide one.
  • The sweep phase ends by deleting every alias.
  • Until then, each old name prints a console note once per page.
  • The breadcrumb rename has no alias period at all (its caveat).
