r1's concept 2 gathers seventeen look words into one attribute: "basic, tertiary, circular, raised ... -> style="<that word>"". But style is already HTML's own attribute, on every element.

  • style holds inline CSS: style="color: red". The browser reads it on every element, ours included, and tries to read style="basic" as CSS.
  • In code, element.style is the browser's CSS object, so a component can't have a style property of its own.
  • Authors could no longer give one element a bit of inline CSS: style="basic; margin: 0" is neither.
  • A site with a strict content-security policy reports every inline style as a violation.
  • Web Awesome, which Spell UI's layout utilities follow, has the same idea as appearance: <wa-button appearance="outlined">. 
<ui-button style="basic">Cancel</ui-button>            <!-- r1:  the browser reads "basic" as CSS -->
<ui-button style="basic; margin: 0">Cancel</ui-button>  <!-- neither a look nor CSS -->
<ui-button appearance="basic">Cancel</ui-button>       <!-- A -->
  • Web Awesome's word for the same thing, so people coming from it know it.
  • CSS has an appearance property too, meaning much the same: how a control is drawn.
  • Cost: long to type; Spanish apariencia.
  • Short and plain: <button look="basic"> in a drawing.
  • Cost: no other library uses it; Spanish aspecto.
  • Material UI's and Shoelace's word for a button's look.
  • Cost: Web Awesome uses variant for the COLOUR (brand, success, danger), the other way round.
  • r1's concept 2 becomes appearance="<word>", the old switches its aliases.
  • The old link look (looks clickable) becomes appearance="link".
  • style stays HTML's inline CSS, on every tag.
