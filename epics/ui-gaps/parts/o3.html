Every new tag goes through the same steps, so each phase below says "the usual steps" and lists only what's different.

  • The steps are Spell UI's own, from its components guide ("Adding a family, step by step") and its rules for a family's files.
  • Every component draws in its own shadow root; none is plain light DOM.
  • One small family is about 6 source files, 1 to 3 test files and a docs page, plus a line in each of 5 registration files and a few thousand lines of regenerated data.
  • That's why even an "S" gap takes an hour or two: the Spanish words, the docs page and the tests come with every tag. 
1. spell-ui/src/components/ui-<name>/
     UI<Name>.tsx      the component:  vocabulary, element setup, render()
     UI<Name>.css      its look, Fomantic's class grammar, private --_ui-* tokens
     UI<Name>.en.ts    tag, topics, aka, description, skeleton, attributes, events, slots, parts
     UI<Name>.es.ts    its Spanish words:  the tag's name, its own attributes and texts
     index.ts          define() and re-export
     examples/elements/types.html    read by the kitchen sink, axe and visual tests
2. components.es.ts:  the Spanish dictionary listed
3. vite.config.ts COMPONENTS, package.json exports, src/index.ts:  one line each
4. yarn gen:root  +  yarn site:build      the root catalog, JSX types, docs data, kitchen sink
5. docs/__data/pages.json5:  title, summary, status
6. yarn site:new ui-<name>  then  yarn site:check ui-<name>.html      the docs page and its screenshots
7. tests/components/ui-<name>/        component, CSS and server-render tests
8. yarn readme:components;  a row in the status list (guides/ui/notes/status.md)
9. yarn review, then the designer review of its docs page
  • Before any of it: the Solid 2 rules, read in full, as every Spell UI change needs.
  • The visual baselines need Docker; a family without them shows "local" in the status list, as ui-toolbar does today.
