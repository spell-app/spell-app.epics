How a drawing shows a thing's details at a glance, as term and value: "Suit: hearts".

  • HTML's is a description list: <dl>, each term a <dt>, each value a <dd>.
  • Nearest today: a form's field with a value shown (ui-field), and a statistic (ui-statistic), a big number under an uppercase label. Neither reads as plain details.
  • Owen's comment on 1.2's table: "yes, should allow for slotted content": a value that's more than text (a label, an icon, a link).
  • The terms line up in two columns, the terms' widths matched, so the values start at the same place.
  • The catch: a <dt> and <dd> must sit right inside one <dl>, and each Spell UI tag draws inside its own box (its shadow root), so the list can't be HTML's own. Screen readers get the same through ARIA roles instead: term and definition.
  • <terms> around <term>s.
  • A term's name is label (r1's word for a tag's words); its value is value, or whatever's inside it.
  • A label slot too, for a term with markup.
  • direction="horizontal" on the list puts the pairs side by side, in a row.
  • Cost: about 2-3h.
<terms>
  <term label="Suit" value="hearts"/>
  <term label="Owner">
    <text link="…">Ann</text></term>
</terms>
  • <list definition> with <item label="Suit">hearts</item>: Spell UI's rule of one item for every list.
  • Cost: a list's item is a bullet-list row today; its look and its screen-reader role change by an attribute on its parent.
  • New: ui-terms, ui-term; in a drawing <terms>, <term>.
  • label and value, or slotted content for either.
