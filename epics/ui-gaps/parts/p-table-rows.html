  1. Read ui-table's code (its native-table dressing, its list mode, TableSort) and the grid's parts.
  2. ui-row learns its parent: inside a ui-grid it's the grid row it is today; inside a ui-table it's a table row, with the row role (Q5). A test proves both.
  3. A new ui-cell: a cell, or a header cell with header; colspan; a row with header is the header row, one with footer the footer row.
  4. ui-table gains caption (attribute and slot), and takes the table role when it holds rows rather than a native table.
  5. Layout: the table a CSS grid, each row a subgrid, so columns line up; the phone stacking kept.
  6. The look: ui-table's sheet taught the new tags beside the native ones (celled, striped, selectable, compact ...), in the new words from P4.
  7. Sorting: TableSort reads header cells and moves row elements, not only native rows.
  8. Docs: "Rows and cells" first in ui-table's Usage; the generated data and Spanish words as usual.
  9. Checked: ui-table's tests plus new ones (roles, sort, spans, the grid's rows unchanged); axe; site:check; a test for Owen: VoiceOver's table navigation.

  • Layout: the scroller a CSS grid of the widest row's columns, each row a subgrid of them, so columns line up; span covers columns (J27). Stacks into blocks at phone width, as a native table does.
  • <ui-row> learns its parent (Q5): in a table it's a table row (header, footer, :state(in-table)), in a grid the grid row it was. A row is a size container in the grid's sheet, which stops a subgrid: the table's sheet turns that off.

  • Sorting: header cells sort as a native table's headers do (TableRows, beside TableSort); client-sort moves the row elements, header rows first, footer rows last.
