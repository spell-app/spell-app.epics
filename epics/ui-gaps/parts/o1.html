A .spellx drawing can only draw what Spell UI has: it holds no native HTML at all, so what HTML can draw and Spell UI can't, a spellx author can't draw either.

  • Every tag in a drawing is a Spell word, one of the app's own templates, or a component from a pack the project lists ().
  • <button> there is always Spell UI's ui-button, never the browser's own.
  • So the gaps become new Spell UI components, in this epic of their own (, option A).
  • elemental-spell's drawings use what Spell UI has until each gap lands.

The ten gaps, most needed first

From elemental-spell's survey of HTML, group by group (its Q50 has the full tables).

# What's missing Closest thing today Why that isn't enough
1 Table rows and cells ui-table It only dresses a native table written inside it; with no native HTML there's nothing to dress
2 A plain layout box ui-grid, ui-segment, ui-container A 16-column grid, a box with a look, a page-width column: nothing just lays out a row or a column
3 A link in running text href on a button, card, image, item, label, header, step No link inside a sentence
4 A paragraph ui-text, ui-markdown ui-text is inline, with a line height of 1; markdown can't hold a drawing's values
5 Inline styles: bold, italic, inline code, key caps, a highlight ui-text's size and colour No weight, no slant, no code look; nothing draws key caps for an action's shortcut
6 A page frame ui-root, ui-sidebar Nothing frames a whole page into header, main, side and footer, the regions screen readers jump between
7 A drawing surface ui-tree-diagram, ui-icon One diagram and glyphs; no shapes of your own, no canvas, for games and charts
8 Video and audio ui-embed YouTube and Vimeo only; no file of the app's own, no sound for a game
9 A term-and-value list ui-field, ui-statistic One is a form's field, the other a big number; nothing shows "Suit: hearts" at a glance
10 A figure with a caption ui-image No caption under an image
minor Quotes, sub- and superscript markdown only Rare in apps, but cheap once the inline styles exist
