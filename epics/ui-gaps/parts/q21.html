r1, "still open": "source means different things (where content loads from, vs a component pack's link); type (a field's kind vs an item's kind); speed (the loader's spin vs progress's fill)". What each word means in each family today, and whether to split it.

source: four meanings, not two

Family source is
include, code, markdown, section, accordion a file to show: source="notes.md", loaded and drawn
property-editor its layout page, a file too
components a component pack's link: <ui-components source="epics.pack.js">
search the results to search, as data (a property)
embed the video's host: source="youtube"

Choices

A · Keep it for files; the other three get their own word (recommended)

  • source: a file to show, as today, in six families.
  • <ui-components pack="epics.pack.js">.
  • <ui-search results="...">.
  • <ui-embed host="youtube">.
  • Cost: three renames, each an alias for a while.

B · Keep source everywhere

  • "Where it comes from" covers all four, loosely.
  • Cost: the inspector shows one word that takes a file here, a site name there.
  • source always names a file to show; pack, results and host are new, source their old name.

type: five meanings

Family type is
input what's typed in, as HTML's <input type>: text, number, email ...
calendar what it picks: date, time, datetime, month, year
item item, a group header, or a divider line
checkbox, radio a LOOK: toggle or slider
button form behaviour (submit, reset): r1 drops it

Choices

A · type for a field's kind only (recommended)

  • Input and calendar keep type: what the field takes, as HTML says it.
  • Item: <ui-item kind="divider">.
  • Checkbox and radio: the look word, appearance="toggle" (whatever the style question picks).
  • Cost: two renames.

B · Keep type everywhere

  • "What kind of one" covers all of them, loosely.
  • Cost: a checkbox's look hides under a word that means a field's kind everywhere else.
  • type stays on input and calendar; item's becomes kind; the checkbox and radio look joins the look word.

speed: one meaning after all

  • ui-loader speed="slow | fast": how fast it spins.
  • ui-progress speed="slow | fast": with indeterminate, how fast its animation runs (not how fast it fills: the fill follows the value).
  • Both are how fast the motion goes, with the same two values.

Choices

A · Keep speed (recommended)

  • One word, one idea: how fast its motion runs.

B · Split it

  • spin-speed and pulse-speed.
  • Cost: two words for the same idea.
  • speed stays on loader and progress, described as "how fast its motion runs".
