Nothing frames a whole page into the regions screen readers jump between.
  • ui-page (Q11): header, nav, aside, footer slots and the main content, as landmarks
  • Skip to content; its background; system light or dark; one per page
ui-page, a ui-root that is the whole window.
  1. Read how SpellApp subclasses UIRoot (its content(), elementSetup.root): ui-page follows the same pattern.
  2. UIPage extends UIRoot in a new ui-page folder: content() draws header, nav, main (the unnamed slot), aside and footer, each the HTML landmark screen readers jump between, laid out in a CSS grid.
  3. A Skip to content link first, hidden until focused, its words from the vocabulary (English and Spanish).
  4. The whole window: paints its background, clears the body's margin (a page sheet, as ui-table registers one), follows the system's light or dark setting when no theme is set.
  5. One per page: a second reports itself in the console and still draws.
  6. Narrow screens: nav and aside stack above and below the main content (stack-with, as the root has); a drawer is left for later.
  7. The usual steps: vocabulary with the new words (label, appearance), Spanish (es-pagina), registration, gen:root + site:build, a docs page whose examples sit in a resizable box, tests (landmark roles, one-per-page note, skip link), the designer review.
  8. Checked: yarn review; axe on every example; a landmarks check by hand goes to Owen as a test.
  9. Left out: the nav-as-drawer on phones; sticky header (an attribute later if drawings need it).
