How a drawing writes a table's rows and cells, now that tables are built from tags (Q2, answered: rows and cells as tags, a list filling them with for each).

  • Owen's names (his comments on 1.2's table): <ui-row> and <ui-cell>, written <row> and <cell> in a drawing, with header on either.
  • The rest of the table's parts:
    • <row header>: the header row, its cells column headers
    • <cell header>: a row's own header cell, the first cell that names the row
    • <row footer>: a footer row, totals and the like
    • caption="..." on the table, or a caption slot for a caption with markup
  • The catch: ui-row is taken today. It's one of the grid's two parts, ui-row and ui-column, Fomantic's 16-column grid. ui-cell is free. 
<table celled sortable caption="Scores">
  <row header>
    <cell>Player</cell>
    <cell>Score</cell>
  </row>
  <row>
    <cell header>Ann</cell>
    <cell>12</cell>
  </row>
</table>
  • Owen's names, everywhere.
  • Inside <table> a row is a table row (a row for screen readers, its cells lined up in columns); inside <grid> it's the grid's row, as today.
  • The same rule elemental-spell settled for description and event: the tag's owner decides ().
  • Cost: one tag with two shapes, chosen once it's placed; a row moved from a grid into a table redraws.
<table><row><cell>…
</cell></row></table>
<grid><row><column>…
</column></row></grid>
  • <row> means a table row only; the grid's is <grid-row>.
  • ui-row inside a grid keeps working as an old name until the sweep.
  • Cost: every grid on every page changes; the grid's column stays <column>, so its two parts no longer match.
  • No clash: each family names its own parts, as ui-breadcrumb-section does.
  • Cost: <table-row>, <table-cell> in a drawing: longer, and not the names Owen asked for.
  • New: ui-cell; ui-row draws a table row inside a table.
  • header on a row or a cell; footer on a row; caption on the table.
  • The grid's ui-row is unchanged.
