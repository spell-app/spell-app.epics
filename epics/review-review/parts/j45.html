Each spell dev pass-through (plan-doc, goals, docs, details, server, window, vscode) starts the tool as a separate node process, the way spell plan-doc already did, rather than loading the tool's script into the spell process itself.

  • Measured, window which, 3 warm runs each, two rounds: in the same process 0.12-0.15s, as a child 0.14-0.16s. So about 0.02s, inside the noise.
  • Tools that need tsx (plan-doc, docs link, the page server) CAN'T run in-process correctly: spell is linked to the MAIN checkout, and its tsx maps $/server into main's files, while a worktree's tool must get the worktree's. A child gets the tool's own tsconfig.json.
  • In-process would also mean rewriting process.argv, changing folder, and sharing exit handling with each tool.

Example: spell dev plan-doc summary review-review from a worktree runs node --import <main's tsx> <worktree>/packages/docs/tools/plan-doc.js with the worktree's packages/docs/tsconfig.json.

Net effect

  • One way to run every tool (runTool(), packages/cli/src/dev/passThrough.ts), correct across checkouts.
  • Costs ~0.02-0.04s per call over the fastest possible.
