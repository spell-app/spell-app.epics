Each spell dev pass-through starts its tool as a separate node process, rather than loading the tool into the spell process itself.

  • The pass-throughs: plan-doc, goals, docs, details, server, window, vscode.
  • It's the way spell plan-doc already worked.

Why:

  • It costs almost nothing: about 0.02s, inside the noise.
    • Measured on window which, 3 warm runs each, two rounds.
    • In the same process: 0.12-0.15s. As a child: 0.14-0.16s.
  • Tools that need tsx CAN'T run in-process correctly: plan-doc, docs link, the page server.
    • spell is linked to the MAIN checkout, so its tsx maps spell-kit/server to main's files.
    • A worktree's tool must get the worktree's files.
    • A child gets the tool's own tsconfig.json.
  • In-process would also mean rewriting the command line (process.argv), changing folder, and sharing exit handling with each tool.

An example: spell dev plan-doc summary review-review, run from a worktree, starts the worktree's tool with main's tsx and the worktree's settings (tsconfig.json): 

node --import <main's tsx> <worktree>/packages/docs/tools/plan-doc.js
  • One way to run every tool, correct across checkouts: runTool().
  • It costs about 0.02-0.04s per call, over the fastest possible.
