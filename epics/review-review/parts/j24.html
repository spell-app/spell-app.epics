Three small rules for the inbox file (scripts/inbox.js) the contract left open.

  • The file is deleted once nothing is in it (no marks, no now requests, no agents at work, nobody listening): "absent until the first mark" holds both ways.
  • Clicking Add Details (or revisit now) twice on one item queues ONE request: the second replaces the first, with its newer note.
  • Changing an item's immediate mark to one that waits for a send (revisit now, then revisit soon), or clearing it, drops its queued request: you changed your mind before Claude took it.
  • Marks may only name items of that plan doc: <ui-item>s with an id and a status, read from the doc on each request (a phase like p1 is a 400).

Example: revisit now on T1 with "what else?", then Clear before Claude starts: the mark and the queued request both go, and with nothing else marked the file is deleted.

  • No stale empty inbox files beside plan docs; no duplicate agents from a double click.
