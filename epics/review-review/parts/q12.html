When something asks a side bar tab to show the page it ALREADY shows (same path, whatever its ?t= stamp), the view no longer reloads it. It reveals the tab and, if a #hash was asked for, posts { spell: "go", hash } into the page's frame (hash without the #).

  • The page's live client (packages/server/src/liveClient.ts, agent B) must handle it: scroll to that id, the way a link to it lands. Until it does, a repeated yarn plan-doc open --hash ... on the same page only reveals the tab.
  • Only a DIFFERENT page changes the frame's src. The reload button and "Restart page server" still reload.
  • Between the extension and the view's own script there is also { spell: "navigate", url }, which points the existing frame at a new page; the page never sees it.
  • The page's own messages (place, open, history) are unchanged.
