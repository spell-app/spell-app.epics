spell is a link to the main checkout's packages/cli/bin/spell.mjs. That's why spell dev window open now works in a fresh worktree before its yarn install (AGENTS.md and the isolate skill say so now, replacing the old 'node, not yarn window' reason). The other side of it: in a worktree, spell dev plan-doc / docs / details run MAIN's tools, not the branch's.

Net effect

  • A branch that changes those tools has to test them with node packages/cli/bin/spell.mjs dev ... from its own root.
  • The new commands have to act on the checkout of the folder they're run in (servers, docs open, window stay-check), not the checkout the CLI lives in. That's for the CLI work to make sure of.
  • Code that starts the page server (scripts/serve.mjs, ui's site-dev.ts and SiteCheck.ts, the VS Code 'Restart server' button) runs its OWN checkout's node packages/cli/bin/spell.mjs dev server ensure, never the spell on PATH.
