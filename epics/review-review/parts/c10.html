spell is a link to the main checkout's CLI (spell.mjs), which cuts both ways.

  • The good side: epic window open now works in a fresh worktree, before its yarn install.
    • AGENTS.md and the isolate skill say so now, replacing the old "node, not yarn window" reason.
  • The other side: in a worktree, spell dev plan-doc, docs and details run MAIN's tools, not the branch's.
  • A branch that changes those tools has to test them from its own root, with node bin/spell.mjs dev ....
  • The new commands have to act on the checkout of the folder they're run in, not the checkout the CLI lives in.
    • For example: servers, docs open, window stay-check.
    • That's for the CLI work to make sure of.
  • Code that starts the page server runs its OWN checkout's CLI, never the spell on PATH.
    • That code: serve.mjs, ui's site-dev.ts and SiteCheck.ts, and the VS Code "Restart server" button.
    • What it runs: node bin/spell.mjs dev server ensure.
