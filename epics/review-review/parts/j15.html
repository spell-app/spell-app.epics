The script writes two attributes the plan didn't name. Neither shows on the page; they let commands tell things apart later.

  • data-answered on a question that has an answer (decide, or add ... decision): so reopen after close knows to put it back as decided, not as a question waiting on you. A born-answered question has no answer block to look for, so the status alone can't tell.
  • data-sha (the full hash) on each commit entry's <li>: so commit replaces an entry instead of adding a second, and commits --backfill skips what's listed, even with no GitHub link to read the hash from.
  • Also: review labels follow the new colors: "to do" orange (was blue), "reviewed 10-02" green while recent, then grey; the review picker's state icon takes the item's page color.

Example: <li data-sha="cd6a9d76..."><a class="plan-commit" ...>cd6a9d7</a> Spell Docs + Review tabs ...</li>

  • re-running commits --backfill adds nothing (tried: 0 commits added)
