yarn plan-doc inbox review-review wait, the background command that wakes the review session, prints a send only once, and remembers it did (a handedOver time in the inbox file).

  • Why: the session runs wait again after every wake. Without the memory, the same send would wake it again at once, in a loop.
  • A send prints EVERY mark it covers that is still in the inbox. So a revisit Claude has not finished talking over comes back with the next send, flagged "(sent before)".
  • A send with no marks left (everything already applied) is taken quietly: no wake for nothing.
  • Add Details and revisit now never wait for a send: wait takes them off the queue as soon as they arrive, and marks each item working (its spinner).

Example: Owen sends J9 approve and a revisit on J28. Claude applies J9 and starts talking about J28. Owen marks C1 todo and sends again: the next wake prints J28 "(sent before)" and C1.

Net effect:

  • one wake per send; a still-open mark is never lost, only repeated
  • the inbox file gains a handedOver field
