The pull request offer is a new step 4 in /isolate's Finish, written as skill prose with two git commands.

  • When: after the branch has main merged in, before leaving the worktree, and before main moves.
  • It checks whether GitHub's main is behind the local one. If it is, there's no offer, just one line saying why (Q16, answer C). 
    git fetch origin main
git rev-list --count origin/main..main     # not 0: GitHub's main is behind
  • Chosen over a spell dev worktree verb.
    • A verb needs CLI options, tests and a commands page row (held back in the pending folder until merge).
    • That's more than the two git commands it would wrap.

Examples:

  • GitHub's main 62 commits behind: "No pull request: GitHub's main is 62 commits behind local main, so a PR would list all 62 as well as this branch's. Push main first if you want one."
  • Up to date: a modal, "Open a pull request for review-review on GitHub?", with "Push and open a PR" and "No PR".
  • Nothing is pushed without the modal's yes; main is never pushed from /isolate.
  • The PR's title: the changelog entry's header, without its date.
  • Its body: the entry's bullets as plain text, since their links point into shared docs, which aren't on GitHub.
  • A PR already open: the offer just pushes the branch, which updates it.
  • Steps 4-7 of Finish became 5-8.
