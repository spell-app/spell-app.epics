Each plan-doc edit rewrites <body data-recent-since> (the commit time green items count from). After a commit that value changes, and the in-place update falls back to a full reload whenever anything outside main changed.

  • Example: you're reading the doc in the side bar; Claude commits a phase, then logs a line: the page reloads once (a short flash, your scroll kept) instead of patching quietly.
  • Also breaks check-review.js / check-live.js on a doc whose stamp is behind (PAPERCUTS).
  • Fix: let the in-place update copy changed <body> attributes instead of reloading.

Net effect (once fixed):

  • no reload after a commit; the checks pass on any doc
