Whether a listening session is gone is decided in one place, the inbox code.

  • The inbox code (inbox.js) answers listening: null once the session's heartbeat is over 90 seconds old.
  • So the page needs no clock rule of its own.
  • The two times are named once each, there: 
    LISTEN_HEARTBEAT_MS   30s
LISTEN_STALE_MS       90s
  • The stale listening entry stays in the file until the next listen or unlisten.

Beyond the ask: more commands stamp the heartbeat, so a session busy between waits still counts.

  • wait (every 30s) and listen, as asked
  • and the session's inbox apply, done, clear and working

Still a gap:

  • A session talking a revisit over with you for more than 90s, running none of those, shows "nobody is reviewing" until it runs wait again.
  • Marks you make then do wait for that wait, so the warning is roughly true.

An example: you close the review tab mid-wait. 90s later:

  • the send button's tooltip says "No Claude session is reviewing this doc"
  • "revisit now" shows the notice
  • yarn plan-doc inbox review-review prints: 
    listening: nobody (session ... last seen ..., over 90s ago: gone without unlisten)
  • After a crash, the warning comes back within 90 seconds, with no page change needed.
  • A long chat with no inbox command can show the warning while the session is still there.
