A pick waits for the send, so choosing a card on an item already asked "revisit now" turns its mark into a revisit soon with the note and the new pick; inbox done then keeps it.

  • Why: an immediate mark counts as sent the moment it is made, so a pick added to it would never reach Claude.
  • inbox done used to drop whatever mark the item had; it now drops only immediate marks (finishMarks()), so a mark you changed while the agent worked stays for the next send. clear still drops anything.
  • Unchanged: Approve, Add to todo or Add Details on a picked question replaces the pick (one mark per item, the latest wins).
  • Example: you ask "revisit now" on Q7 ("why not reuse it?"); while the agent answers, you choose B. Q7 turns filled orange with a B, the send button turns blue; the agent finishes, done Q7 prints "changed since, kept for the next send: Q7"; your next send hands over "picks B, asks: why not reuse it?".

Net effect:

  • a pick made during a "revisit now" is never lost
  • the alternative, keeping it "now": the pick would ride on a request Claude may already have taken
