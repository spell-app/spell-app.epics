Inside <ui-sections collapsing> every section folds by default; one that must not fold says so with the attribute it already has, set to "false", not with a new word.

  • Why: the library reads "false" / "no" as false on every boolean (Vue writes open="false"), and <ui-modal closable="false" already turns off a default this way. A new word (static, fixed) would be one more name to learn for one case.
  • The section tells "absent" (take the group default) from "false" (off) by reading the raw attribute; a section without the attribute takes the NEAREST group default, at any depth.
  • Sub-sections of an opted-out section still follow the group: the opt-out is for that one section, not its subtree.
  • Catch: from code, section.collapsible = false REMOVES the attribute (booleans never reflect as "false"), which brings the group default back; use setAttribute("collapsible", "false"). Noted in the code. 
<ui-sections collapsing>
  <ui-section header="Install">...</ui-section>                          <!-- folds -->
  <ui-section header="Changelog" collapsible="false">...</ui-section>  <!-- never folds -->
</ui-sections>
  • No new attribute name; collapsible means the same everywhere.
  • Opting out from JS needs setAttribute, not the property.
