Each pass-through runs its tool in the folder its old yarn script did, so its output and path handling don't change.

  • spell dev docs (update, index, new, open, link) and spell dev details: in the docs package (packages/docs), as yarn workspace @spell-app/docs ran them.
    • For example, docs new prints the new page's path relative to the docs package, as before.
  • spell dev plan-doc: in the current folder, as spell plan-doc always ran it.
    • The root yarn plan-doc used to run it in the docs package.
    • So, called through yarn, the paths it prints are now relative to the root.
  • spell dev window: in the current folder. Its script (window.mjs) reads it, to tell which VS Code window it's in.
  • spell dev server: in the current folder.
    • url <file> reads the file from there, or from INIT_CWD when yarn ran it.
  • Skills switching from yarn X to spell dev X see the same output.
  • Changing a docs tool to print paths relative to where you are would be a separate, small change.
