Each pass-through runs its tool in the folder its old yarn script did, so its output and path handling don't change.

  • spell dev docs update|index|new|open|link and spell dev details: in packages/docs, as yarn workspace @spell-app/docs ran them. E.g. docs new prints the new page's path relative to packages/docs, as before.
  • spell dev plan-doc: in the current folder, as spell plan-doc always ran it (root yarn plan-doc used to run it in packages/docs, so paths it prints are now relative to the root when called through yarn).
  • spell dev window: in the current folder: window.mjs reads it to tell which VS Code window it's in.
  • spell dev server: in the current folder; url <file> reads file from there (or from INIT_CWD when yarn ran it).

Net effect

  • Skills switching from yarn X to spell dev X see the same output.
  • Changing a docs tool to print paths relative to where you are would be a separate, small change.
