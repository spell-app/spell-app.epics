The one hard limit, found while exploring:

  • Nothing outside a Claude Code session can push a message into it. A session wakes only when you type, or when a background command it started finishes.
  • The VS Code Claude extension can type a prompt into a session's tab, but only when it opens that tab fresh; into a tab that's already open, it refuses ("Your prompt was not applied").

So the page and the session meet in a file, the way details pages already work:

  • The page saves your marks through the page server's review routes into an inbox file beside the epic page, git-ignored, e.g. wwod.inbox.json5 (D1).
  • The /epic review session keeps a background command waiting on that file. Sending, Add Details or "revisit now" makes it finish, which wakes the session.
  • A busy session (mid-answer) gets the wake as soon as its turn ends: that's the "queue it up to happen ASAP" you asked for, for free.
  • Each send is handed to the session once; marks you change while Claude works wait for the next round.
  • No session listening (it was closed): the marks stay in the inbox until the next /epic review, and a notice on the page says so (D6).
