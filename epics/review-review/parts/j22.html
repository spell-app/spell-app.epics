Each plan doc's inbox (epics/<name>/<name>.inbox.json, where your page marks wait for Claude) is ignored by git (.gitignore: epics/*/*.inbox.json*, its lock and temp file too).

  • It is hand-off state, not the record: what Claude makes of a mark (an approval, a todo, a picked option) is written into the plan doc, which is committed.
  • It changes on every click (marks, sent, working, listening): committed, every click would show in Source Control and conflict on merges.
  • Same call as scratch details pages and their answers (ignored).
  • Rejected: committing it, so pending marks travel with the branch. They rarely outlive a session: P6 deletes marks as it applies them.

Example: you approve J3 and pick B on Q8, then close VS Code. The marks stay in review-review.inbox.json on this machine for the next /epic review; git status never shows the file.

Net effect:

  • No inbox noise in commits or Source Control.
  • Marks not yet applied are lost if the worktree is removed: P6's clean-up (/isolate done, worktree remove) should check yarn plan-doc inbox <name> first.

Update, shared content (2026-10-04): still true, but the rule moved and the inbox is now shared.

  • the ignore line lives in spell-app-dev's own .gitignore: spell-app ignores the whole packages/docs/content link
  • one inbox per epic for the whole machine: a mark sent from any window reaches whichever session is listening, worktree or main
  • the plan doc itself is auto-committed to spell-app-dev every turn, so "the plan doc, which is committed" still holds

Net effect

  • No change to the decision; only where its rule lives.
