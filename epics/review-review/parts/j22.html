Each plan doc's inbox, where your page marks wait for Claude, is ignored by git.

  • The file: <name>.inbox.json, beside the plan doc.
  • The rule is in .gitignore, and covers its lock and temp file too: epics/*/*.inbox.json*.

Why:

  • It is hand-off state, not the record. What Claude makes of a mark (an approval, a todo, a picked option) is written into the plan doc, which is committed.
  • It changes on every click: the marks, and what's sent, being worked on, or listening.
    • Committed, every click would show in Source Control, and conflict on merges.
  • It's the same call as for scratch details pages and their answers (ignored).
  • Rejected: committing it, so pending marks travel with the branch.
    • They rarely outlive a session: P6 deletes marks as it applies them.

An example:

  • You approve J3 and pick B on Q8, then close VS Code.
  • The marks stay in review-review.inbox.json on this machine, for the next /epic review.
  • git status never shows the file.
  • No inbox noise in commits or Source Control.
  • Marks not yet applied are lost if the worktree is removed.
    • P6's clean-up (/isolate done, worktree remove) should check yarn plan-doc inbox <name> first.

Update, shared content (2026-10-04): still true, but the rule moved, and the inbox is now shared.

  • The ignore line lives in the shared content repo's own .gitignore.
    • spell-app ignores the whole link to it (packages/docs/content).
  • One inbox per epic, for the whole machine: a mark sent from any window reaches whichever session is listening, worktree or main.
  • The plan doc itself is auto-committed to the shared content repo every turn, so "the plan doc, which is committed" still holds.
  • No change to the decision; only where its rule lives.
