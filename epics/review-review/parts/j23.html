The send button counts only marks that wait for "send to Claude". An immediate request (Add Details, revisit now) is handed over the moment you click it (the inbox's now queue), so it never counts as unsent, even though its mark is newer than the last send.

  • The contract said "marks newer than sent are unsent", with no exception. Taken literally, clicking Add Details would turn the send button blue ("Send 1 mark to Claude") for a request Claude already has.
  • One helper decides it: inbox.js unsentMarks() (and isImmediate()); yarn plan-doc inbox uses it. The page should count the same way.
  • Times in the inbox (at, sent, since) carry milliseconds: 2026-10-04T17:07:20.473-04:00. To the second, a mark made in the same second as a send would pass for sent.

Example: you approve J3, click Add Details on I2, then pick B on Q8. The send button says "Send 2 marks" (J3, Q8); I2 shows its spinner instead.

  • The send button turns blue only for marks a send would actually deliver.
  • Times are still ISO with an offset: Date.parse() reads them as before.
