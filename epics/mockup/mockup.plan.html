I have a web site that I am redesigning for my day job. I have laid out a figma file with cards for the old screens, linked to screen shots, and cards for the new screens with nothing linked to them. Taking the figma file as input, I want to make a mockup of the new site. Ideally, we'd be able to turn that into actual code!

So, new things to think about:
- site / sitemap: links to pages with URL routes/parameters, both for the static cards and the new cards
- sidebar navigation: we probably have all of the pieces for this, but it may want to be its own <ui-component> to make things simpler
- ERDs and NERDS: I want to turn the spell data ingestor loose on the current API surface and create ERDs from it. a "NERD" is "not an entity relationship diagram" which shows less detail -- e.g. rather than showing `analasys_id` or `analasys_ids` column, it would show `analaysis` or `analyses` links between the tables. It would also show a subset of the properties. Clicking the a node in the NERD opens that up as a flipping card animation to show the full ERD in its place. The ERD / NERD should be laid out in columns, and I should be able to move things around. I have claude instructions for making the NERD diagram which I can feed in.
- we'd start with faked data (we can scrape from the current site in this case, we'll eventually want them to be able to add/edit rows) and then make things live later on.
- for the new site, once we have the sitemap running, I want to be able to start by writing out the functions the card should have, then lay out the sections on a "mockup" theme (sketchy look, e.g. basalmiq style). This should be a click-through prototype, allowing e.g. a button to open up a related modal or show data in a slide-out sidebar.
- I'm thinking that the site editing functionality will be a new editor mode, where I can create/delete/arrange pages, then dive in to edit a particular page. This doesn't necessarily have to be in the same editor although it could be if it doesn't complicate the base editor too much.
- Once we have the site map / page layout and mockups, we'd turn them into real running code still in the mockup style. I can do user testing with this.
- Once user testing phase is done, I'd start tweaking the actual page layouts with a "real" theme etc.
- Goal is that this will turn into a fully functional site which can be published for the company. You can assume that we have a node-based back-end, although for this site in particular some functionality might come from Python (e.g. rendering charts and sheets).
