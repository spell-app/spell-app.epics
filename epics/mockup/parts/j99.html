Theme › and the ☰ menu's File ›, Edit ›, View ›, Run ›, Help › all name their fly-out by id, a <FlyoutMenu> beside the items, rather than holding their items inside the <ui-submenu>.

  • Inside, <ui-submenu> draws them in a <ui-menu> of its own shadow root: its width fixed at a vertical menu's 15em, so Theme's Light | Dark | Auto read "Li…" and each theme's line wrapped; its ticks copied from the row's menu, so the ☰ menu's File and View lost their ticks; and no sheet of the page reaches it (the bar's row padding, the Glass blur).
  • Named, each is the page's own element: ticked or not by itself, styled by MenuBar.css, opaque and blurred like its popup.
  • No Spell UI attribute added, no Spell UI change.
  • Opened by keyboard (→), Theme ›'s focus goes to Edit theme…, not the chosen theme: <ui-submenu> focuses its fly-out's first item, and the theme menu's rows aren't items (its focusChosen() is for a host to call). The old hand-made sub-menus had no keyboard at all.
  • Sub-menus open on hover, a click, Enter or →, as Spell UI's do everywhere
  • Theme › draws as before, 240px wide; File and View tick in the ☰ menu as in the bar

Fixed in <ui-submenu> itself, no new attribute; the editor now writes its items inside.

  • Width: the fly-out is as wide as its widest item (no more 15em), at most the window's width less a margin; a short window scrolls inside it.
  • Ticks: it ticks when its row's menu has ticks, OR an item inside says whether it's on or off (selected or active written, "false" too). The editor's menu rows now write selected="false" while off, so View › and File › tick in the ☰ menu.
  • Styling: the box's look is in its own sheet now, not inline, so a page's ui-submenu::part(flyout) wins (background, blur, padding, min-width); its background follows --ui-popup-background, so inside the bar's popup it's the popup's near-opaque surface by itself.
  • Keyboard: → focuses the chosen item; with none, the first thing in it -- Theme › hands focus to the theme menu's chosen theme (its focusChosen()).
  • Gone from the editor: FlyoutMenu, the flyouts prop, the .BarFlyout CSS. An action clicked in a fly-out still closes the whole menu; a sub-menu row leaves it open.
<ui-submenu>'s items-inside form fits its widest item, shows ticks when its items say on or off, takes ::part(flyout) styling and focuses the chosen item on →; the editor's sub-menus write their items inside (Owen)
