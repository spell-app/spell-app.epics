Spell learns to keep a program's own JSON file the way it already keeps its own CSV file; the shopping list prints.

C1 · Where the two files sit in git. A program's own data folder is inside its project folder. For an example, that's inside the kit's repo: so every tick on the shopping list would show as a changed file in git, unless the folder is ignored.

  • the root .gitignore leaves out every example's __data/
  • an empty file: the app adds a few items and three recipes when it starts, as Recipe Box does
  • your shopping list and recipes stay yours on your Mac, never committed; a fresh checkout starts with the samples
  • why: it's the only one that keeps git clean without new Spell work
  • __data/shopping.csv and recipes.json committed with the samples in them
  • you can open them in the repo before running anything
  • cost: every use of the example leaves changed files to undo or commit

C2 · How a program prints. Spell's print writes to the console today, and nothing in Spell opens the browser's Print dialog. The app runs inside the editor, so the browser's own ⌘P would print the whole editor.

  1. Where each one saves, in plain words. Both files go in the example's own data folder, on the computer the page server runs on:

    • Shopping List: shopping list is a sheet at "shopping.csv", already in Spell: the example's folder, then __data/shopping.csv.
    • Recipe Cards: recipe file is a json file at "recipes.json", the same shape, new: __data/recipes.json, plain JSON, { "recipes": [...] }, each recipe with its ingredients and steps inside it.
    • Everyone using that page server shares one list and one set of recipes. In git, every example's __data/ is left out (the root .gitignore): each app fills in a few samples when its file is empty, so your list and recipes stay yours, never committed (C1 A).

  2. A program's own JSON file, built the way its own CSV file was (epic language T65):

    • the compiler turns a .json file's name alone into the page server's address, as csvAddressFor() does for .csv
    • the page server answers it with the kit's FilePlace, written whole as plain JSON (SpaceFolders, beside csvFileAt())
    • tests beside the CSV ones; the places line's docstring and the core's notes say it

  3. Shopping List (@spell/examples/ShoppingList), split into files so Recipe Cards can use its parts:

    • its API file: the one shopping.csv place, and an item (name, amount, unit, aisle, got it, from which recipe)
    • the item's view, and the list's view (grouped by aisle, what's still to get first): files of their own
    • the app: add one (name, amount, unit, aisle); tick it off; "Clear what I got"; undo; a few items to start with when the file is empty

  4. Recipe Cards (@spell/examples/RecipeCards): a real recipe app, not Recipe Box again.

    • a recipe: its title, how many it serves, a picture, its ingredients (amount, unit, name, aisle) and numbered steps, kept INSIDE the recipe's row
    • three real recipes to start with, each with 6-10 ingredients and 4-6 steps, each with a free-licensed picture committed in the example (or one you pick)
    • pick a recipe, read it; edit it on a draft (add, remove and reorder ingredients and steps), Save or Cancel
    • Scaling: "Cooking for" a number of people; every amount times diners over servings, shown sensibly (grams and counts whole, cups and spoons to the nearest quarter)
    • Converting units: show a recipe in metric (grams, ml) or in cups and spoons, and back, with Spell's measures where they fit
    • Choosing what to buy: tick ingredients, "Add 4 to shopping list", the scaled amounts; the same item in the same unit adds up
    • Reuses Shopping List's own parts: imports its API file AND its list view, so it shows the SAME shopping list, not a copy, and both name ONE shopping.csv, Shopping List's. First: check an imported project's place keeps its own project's address, and fix it if not

  5. A printable shopping list: a new Spell step, open printing (HyperTalk's words; Spanish abrir impresión), opens the browser's Print dialog for the app alone, in the editor and in a tab of its own (C2 A):

    • a Print button on Shopping List: on paper, only the items still to get, by aisle, a box to tick beside each, the toolbar and inputs left off
    • the print styles in the example's own CSS file, small; a line in Spell's syntax guide
