Spell UI has no --ui-primary-25 (no steps of a colour), so the panel fill is color-mix(in oklab, var(--ui-primary) 5%, var(--spell-code-paper)), in the app's shared sheet beside --spell-code-paper; a theme can set its own. Measured light: Glass #f6f6fe, Spell #f6f6fd, Merlot #faf4f5, Midnight #f3f7f7.

The menu-bar token is the app menu's own fill (the same tokens <ui-menu appearance=header> reads, in the same order) laid over the page colour, since the top bar is see-through on the page while these headers sit on a panel. Matches the app menu pixel for pixel in Spell, Merlot and Midnight, light and dark; in Glass about 1-2 levels off (#f9f7fd vs #faf6ff), as the real bar's blur also saturates. The new <ui-app-menu> (mockup-app-menu) must keep reading those tokens, or this one follows it.

The panels now take the fill in every theme, not only while the code is drawn bubbly; the page's spell-bubbly class, read by nothing after that, is gone. The site editor's form pane has no header bar, so only the board's bar was coloured.

The Inspector's card headers, the file tabs bar and the site board's bar match the top bar; the Inspector cards and both site panes sit on a pale primary tint. Change the tint in one place, --spell-panel-background.
