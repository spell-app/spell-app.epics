I4: <table rows={every review}/> and <text>{every review}</text> now compile as a property that reads a place does: core.waitedValue(), so the page needs no its reviews property.

  • A new core call, core.waitedValueKeyFor(this, film): a read that names a loop's item is another read for each item. Without it every row would have shown the first row's answer, since a waited value is keyed by its words.
  • The same read in there are ... and the number of ... gets this too.
  • Other choice: refuse a read naming a loop's item in an attribute, and ask for a property on the item's view. I kept it working instead.
  • A loop's own function in a drawing (core.drawEach(), core.drawRead()) now never waits, as a drawing never does. Before, a loop body reading anything that waits became an async function, which never drew.
