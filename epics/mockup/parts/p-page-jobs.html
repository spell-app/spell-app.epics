A new page has nowhere to say what it must let people do, before anything is laid out.

  • A page file starts with its jobs: "see an analysis's runs", "start a new run".
  • A job may be an Agile story instead: "As a lab manager, I want to compare two runs, so that I can see which settings changed", with its "done when" checks under it.
  • The jobs are saved with the page for good: they stay in the file when the page is mocked, then built; the running page never draws them.
  • In the site editor, each card shows how many jobs its page has; the page form lists them, to add, edit, reorder and tick off.
  • The example site's pages each get a few jobs, so there's something to look at.

A page's JOBS are written in its own file, as plain lines or as Agile stories with their "done when" checks.

The site editor shows and edits them on each page's card.

  1. Where jobs live: in the PAGE's file, at its top, as a <jobs> block of markdown, on the same path as a template's description (MarkdownDescription, its raw-text tags), compiled to a static description: no new syntax. 
    <jobs>
  - [ ] see an analysis's runs
  - [x] As a lab manager, I want to compare two runs, so that I can see which settings changed
    - done when:  both runs' settings show side by side
</jobs>
     Stories are markdown lines; a task list's box ticks a job off.
  2. The running page draws nothing for them.
  3. The site editor reads them: a count on each card, the list in the page form, to add, edit, reorder and tick; each change written into the page's file through the same source edits as P4's, one history step.
  4. The example site's pages each get two or three jobs.
  5. Checked by: tests that the description carries them; an app test edits one in the site editor.
  6. Left out: checking a mockup against its jobs by itself.
  • Jobs go first in a page's own declaration, as a markdown list.
    • in spellx: <spell-jobs>
    • in code Spell: <jobs>
    • in Spanish: <encanto-tareas>
    • compiled to the page's static jobs through the markdown description rule: no new syntax, nothing drawn
    • - [x] ticks one off; the lines under it are its checks
  • The site editor lists them under a page's form: tick, words, details, move, delete, Add a job, Add a story (As a …, I want …, so that …, done when …); each change one undo step in the page's file; each card counts them ("0 of 3 jobs")
