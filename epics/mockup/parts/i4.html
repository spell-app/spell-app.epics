In a drawing, a read in an attribute, like <table rows={every review}/>, compiles to a syntax error, so the page doesn't load.

  • It compiles to an await inside a plain arrow function (below).
  • A <for> over the same read compiles right.
  • So does a page property holding it.
  • Found in P9; meanwhile, the Star Wars reviews page uses a property, its reviews.
  • Fix: an attribute's read in a drawing compiles as a property's does.
// <table rows={every review}/>:  a syntax error
"prop:rows": () => await core.savedThings(Review)

// a <for> over the same read:  right
core.drawRead(() => core.everyThing(...))

// a page property holding it:  right
core.waitedValue()

 <table rows={every review}/> compiled to () => await ..., a syntax error; an attribute's or child value's read is now a waited value (readableInDrawing()), one per loop item (core.waitedValueKeyFor()), a loop's function in a drawing never waits, and the Star Wars reviews page reads every review itself
