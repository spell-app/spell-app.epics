A page declared further down the file isn't known yet when a handler above it says go to the about page. It's taken by its word page; a wrong name shows only when it runs (SiteBase.show() throws, naming it).

You asked: "can we check the site spell for the name?"

Yes. The site file lists every page by name, and P1 keeps that list in the program's scope (TypeScope.sitePages). So go to the about page is checked against the site's list, not against the types declared so far:

  • a name the site lists is fine wherever the line is, above or below the page's own declaration
  • a name it doesn't list is an error at that line, naming the pages it does have, in the editor as you type, not when it runs
  • done in P3, at its start
  • a misspelled page name in go to, show or a link shows red in the editor
