On Spell UI's docs page for the page layout, the Theming tab's live example is squeezed to nothing: the page layout inside it is drawn 0 pixels wide, so its page text runs down the left edge one letter a line.

  • Where: the Spell UI docs site, the page layout's page, its Theming tab, the Tokens section.
  • The example sits in the playground: the shaded box above the token tables, where you edit a token and watch the example change.
  • What you see: an empty, tall box, a lone arrow (the drawer's navigation, with no room), then "The page goes here" one letter under another.
  • Measured headlessly at 1280 × 900: the page layout is 0 wide and about 1,586 pixels tall.

Why it happens: two things that are each fine on their own meet in the playground.

  • The playground's preview box is a flex row that wraps: it lays its children side by side, each only as wide as its own contents, and moves one to the next line when the row is full. That suits a row of buttons, which the playground mostly shows.
  • The page layout uses inline-size containment: it measures its own width to decide when to go narrow (one column, the drawer sliding over the page, under 40em). To do that safely, the browser makes it refuse to take its width from what's inside it.
    • Put in a box that fills the line (a page, a normal block), that costs nothing: it's as wide as the box.
    • Put in a box that asks each child "how wide are your contents?" (a flex row like the preview), its answer is "nothing", so it gets 0.
  • The page text then wraps inside 0 pixels, which is one letter a line.
/* Playground:  the preview fills the bar, the reset button sits at its end (wrapping below on a narrow column). */
.playground {
  --ui-segment-margin: 0;
}
.bar {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 0.75em;
}
.preview {
  display: flex;
  flex: 1 1 12em;
  flex-wrap: wrap;
  align-items: center;
  gap: 0.5em;
  min-width: 0;
}
 
:host {
  /* its own width decides narrow:  a site drawn in a narrow box is narrow */
  container-type: inline-size;
  display: flex;
  flex-direction: column;
  min-block-size: 100%;
}

The preview box itself is fine: it is 523 pixels wide. It's only its child that gets nothing, because the child's slot is a plain <slot> inside that flex row.

The same example in Spell's own guides works, because it was patched there by hand.

  • When the page layout's guide pages were written for the Spell guides (todo T41), its example got width: 100% on the page layout, which overrides the contents-sized width.
  • Spell UI's docs page has no such patch: its example sets only a minimum height.
  • So the fix belongs in one of the two pieces themselves, the preview in <ui-docs-tokens> or the layout's own outer box (its :host), and the hand patch then comes out. 
<ui-docs-tokens family="ui-page-layout" playground>
	<ui-page-layout style="width: 100%; min-height: 18em">
 
<ui-docs-tokens family="ui-page-layout" playground>
  <ui-page-layout style="min-height: 18em">

It isn't only the page layout. Four more components measure their own width the same way, and each one's Theming playground is 0 wide too (measured headlessly, the same way, today):

  • the form, <ui-form>
  • the table, <ui-table>
  • the theme editor, <ui-theme-editor>
  • the page, <ui-page>: its example sits in a resizable box, which starts at 0 wide for the same reason, until you drag it
  • The playground's preview, in <ui-docs-tokens>, notices a child that sizes itself by its own width, and gives it the whole line.
  • One change fixes all five playgrounds: the page layout, form, table, theme editor and page.
  • A row of buttons stays as it is: only those children are widened.
  • T41's hand patch in the Spell guide comes out.
  • Cost: a few lines of script, as CSS can't ask whether an element uses containment.
/* set by script when a slotted
   child's container-type isn't
   "normal" */
:host(:state(wide)) ::slotted(*) {
  flex: 1 1 100%;
}
  • The page layout's own outer box takes the full width itself, so it fills whatever it's put in.
  • Fixes the page layout's playground, and anyone else's flex row or grid it lands in.
  • The other four playgrounds stay 0 wide: each would need the same line, one by one.
  • Also changes: beside other things in a row, the layout always takes a line of its own. That's what a page layout is for, so it's mild.
  • T41's hand patch comes out.
:host {
  container-type: inline-size;
  inline-size: 100%;
}

A is recommended: the preview is the one place all five broken examples share, so one fix covers them, and any new component that measures its own width will just work there. B is still worth doing on top, if you want the page layout to fill a flex row on real pages too.
