The sitemap (pages, addresses, nesting, states) has to be written down somewhere the site editor writes and the running site reads. The example in 1.3 shows the data either way.

  • Site.spell: the site has a page "Analysis" at "/analyses/:analysis", showing an analysis
  • the language reads it, so links to pages and parameter types are checked (a link to a page that's gone is an error)
  • the site editor writes it as it writes other Spell, through source edits
  • why: pages and their parameters become things Spell knows about, the same way places and types are
  • quicker to start: no language work
  • nothing checks a link or a parameter's type; a page is a name in a file
  • a site and page in the language (parser work), its runtime choosing a page by address
  • more work up front than B (about a phase more)
