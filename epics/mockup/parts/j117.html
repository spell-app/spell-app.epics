Every vocabulary lists attach in its replaces, as align lists alignment, with "Its old names were attach and attached" in the description. Like every old name since epic ui-gaps P13, it does nothing on a page: spell ui rename --write rewrites markup still in it.

  • A page or .spell file still writing attach="top" draws unattached until it's renamed
  • every one in the kit, app spaces and the epic repo's guides is renamed already

The call: when Spell UI's attach attribute became attach-to (Spanish unir-a), the old name was written down, but NOT kept working.

  • It's the attribute that joins a box to the one above or below it, so the two read as one piece (a header segment sitting on its table, a button group on a form).
  • It changed on 15 components, each one's vocabulary in English and Spanish.
  • Each of those vocabularies lists attach as an old name of attach-to, with "Its old names were attach and attached" in the description.
    • The buttons also list the older switch attached, which stands for attach-to="both".

What "recorded, not kept working" means: the old name is a note for the rename tool and the docs, and the elements themselves ignore it.

  • This is how every old name in Spell UI has worked since the ui-gaps epic's P13: align lists alignment the same way.
  • The docs' API tables show the old name beside the new one, so someone still writing the old word finds it.
  • A page that still writes the old name gets no error and no warning: the attribute is simply unknown.

For example, a page written before the rename:

<ui-segment attach="top">Monthly totals</ui-segment>
<ui-table>...</ui-table>
  • It now draws the segment as a separate box, with its own rounded corners and a gap, instead of joined to the table under it.
  • Nothing else on the page changes, so it's easy to miss.

How to fix one: run the rename tool over it.

  • spell ui rename --write rewrites the old names in HTML pages, Markdown, and the markup inside code, straight from what the vocabularies list: attach="top" becomes attach-to="top".
  • Without --write, it only lists what it would change.
  • A branch merging main gets it for free: epic worktree merge-main runs it over the branch's own files.
  • About 140 files were rewritten in the kit and the app's spaces, plus 5 guides in the epic repo and the docs' shared stylesheet; all of it is merged into main.

The alternative: keep attach working as a second name for attach-to.

  • The elements would read either name, so an old page would keep drawing joined.
  • Why not:
    • It would be the one old name in Spell UI that still works, against the rule every other rename follows since ui-gaps P13.
    • Every one of the 15 components would read two names, and decide which wins when a page writes both.
    • Old pages would never get renamed, so the old word would live on in examples people copy.
    • Every page Spell itself owns was already rewritten, so the only pages it would help are ones written outside this repo.
