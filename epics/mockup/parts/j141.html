A <ui-site-tabs> with no pages of its own finds the nearest box around it (across shadow roots) that has a <ui-site-nav> of its own, and shows that navigation's pages and current, kept up while connected. No new attribute, event or core API: the site already hands its navigation everything. The site's own handler of ui-navigating on the tabs is gone: the tab is a real link, and the site's link following (followLink()) goes there without leaving the page.

  • Its own pages win: the docs examples that set them by hand are unchanged.
  • It reads the navigation's attributes, what a Spell site writes, not a pages property set from a script.
  • Rejected: a Solid context (an element's root isn't owned by the page drawing it), a compiled core call for the tag (core API, Python's core too), and an event the site answers (a new public event).
  • A page with tabs now has them as its first block: its <ui-header> is no longer the first child, so it keeps its top margin, 16px further down than before.
The site draws no tabs by itself. A page that wants its family as tabs writes <site-tabs/>: all 378 Spell UI site pages in a family have it; Star Wars never drew any. <site-tabs/> an element a page includes; the site draws no tabs by itself
