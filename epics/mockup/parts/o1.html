Owen is redesigning a website for his day job. This epic gives Spell what it takes to go from his Figma board to a site people can click through, test and, later, use for real.

The steps, in the order the work happens:

  1. Read the Figma board. Each card becomes a page in a SITEMAP:
    • an old screen keeps its screenshot, as a picture of what's there today
    • a new screen starts empty
    • each page gets an address with its parameters, e.g. /analyses/:analysis
  2. Read the current site's data, and draw it as two diagrams. Spell's ingester (spell place ingest) looks at the current API and writes down its collections, fields and links:
    • a NERD ("not an entity relationship diagram"): each collection with a few fields, and the links between them by name (analysis, analyses), never the id columns
    • an ERD: every field. Clicking a NERD box flips it over to its ERD box.
  3. Sample data for every page, copied from the current site, so the mockups show real-looking rows.
  4. Each new page: its jobs first. A short list of what the page must let people do ("see an analysis's runs", "start a new run"), written before anything is laid out.
  5. Then its mockup: sections laid out in a sketchy, hand-drawn theme, and wired so a click does something: a button opens a modal, a row opens a slide-out panel, a link goes to another page.
  6. Testing with people, on the mockup running as real code, still in the sketchy theme.
  7. Then a real theme, live data, and a published site.

This epic covers steps 1 to 5: it stops at the click-through prototype, which runs in Spell's own Run view. Testing with people and step 7 are later epics, written down as future ones before this one ends. Testing with people and step 7 are LATER PHASES of this epic, added when Owen is ready, not future epics.
