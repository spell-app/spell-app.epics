  • The sitemap is a Spell file the language reads: a link to a page that's gone, or a parameter of the wrong kind, is an error in the editor, as a misspelled type is.
  • The site holds each page's address, name and parameters; the page file holds only what the page shows and does, so a page moves to another address, or gets a name in another language, without its file changing.

A site file in Spell lists the site's pages: each one's address, its name and its parameters, nested as the side navigation nests them.

The first example is Spell UI's component pages, a few components' notebooks gathered into ONE site.

  1. A site is a built-in TEMPLATE written in Spell, beside the notebook's (Notebook.spell), compiled into the core by yarn core:gen:templates: no hand-written core class, no new rule module. a home is a page already exists, and stays the page side.
  2. The site says WHERE it lives, the way a place does: spell ui is a site at owen@spell/spell-ui, or ... is a site in the cloud; its first line reuses the place-creating rule (CreatePlace).
  3. Its parts are written the way any thing's are, with it has, one detail line each (PlaceDetail's shape), nested lines for the pages under a page: 
    spell ui is a site at owen@spell/spell-ui
  - it has a button page at "/button", named "Button"
    - it has a button api page at "/button/api", named "API"
  - it has an analysis page at "/analyses/:analysis", new
  - it has a settings dialog
  - it has a syntax sidebar
     The exact words settle while building; the syntax table shows the final ones.
  4. Besides PAGES, a site holds its DIALOGS and SIDEBARS (it has a settings dialog, it has a syntax sidebar): named once, opened from any page, with no address of their own; a dialog is drawn as <ui-modal>, a sidebar as <ui-flyout>.
  5. A parameter's TYPE belongs to the page: the analysis page says - it has an analysis, and the site file names :analysis without typing it again. A :name the page has no property for is an error; so is a part name that isn't one, and two pages at one address.
  6. The tag form: <spell-site> with a <page>, <dialog> or <sidebar> per part, as the notebooks' templates are written.
  7. A part's name is a plain text in the site file, so spell translate translates it as every text; the page file has no name or address.
  8. TWO example sites from the start:
    • Spell UI's: a new example project importing three or four of the component notebook projects (Button, Action, Tree, Modal), their tabs as pages; nothing copied (request r1: epic notebook moves the rest)
    • Star Wars: a small site over the Star Wars sample data (films, people, planets, with :film and :person pages, a settings dialog and a person sidebar); the click-through phase builds its mockups on it
  9. Checked by: the place-detail rules' tests with the new lines, the templates regenerated, the syntax table, and both examples opening in the editor with no errors.
