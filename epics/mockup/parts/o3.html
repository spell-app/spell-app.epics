A SITE is a Spell project holding many pages, and its SITEMAP says which pages there are, where each lives, and how they nest. Today a Spell project is one app drawn into one root: there is no "site" yet.

Each page in the sitemap has:

  • a title, and where it sits in the side navigation (its parent, its place among its siblings)
  • an address pattern, the router's grammar: /analyses/:analysis/runs
  • its state:
    • old: a screenshot of today's screen, from the Figma card
    • new: its jobs and mockup still to write
    • mocked, built, later
  • the data it shows: which collection a parameter names (:analysis is an analysis)

The running site reads the sitemap to draw its side navigation and to show the right page for an address, with its parameters filled in. How the sitemap is written down is Q3. 

pages: [
  { title: "Home", address: "/", state: "old" },
  { title: "Analyses", address: "/analyses", state: "new",
    pages: [
      { title: "Analysis", address: "/analyses/:analysis",
        params: { analysis: "analysis" }, state: "new" },
      { title: "Runs", address: "/analyses/:analysis/runs",
        state: "old", screenshot: "figma/runs.png" }
    ] },
  { title: "Settings", address: "/settings", state: "old" }
]
