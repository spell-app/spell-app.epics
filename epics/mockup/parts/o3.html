A SITE is a Spell project holding many pages, and its SITEMAP says which pages there are, where each lives, and how they nest. Today a Spell project is one app drawn into one root: there is no "site" yet.

Each page in the sitemap has:

  • a title, and where it sits in the side navigation (its parent, its place among its siblings)
  • an address pattern, the router's grammar: /analyses/:analysis/runs
  • its state:
    • old: a screenshot of today's screen, from the Figma card
    • new: its jobs and mockup still to write
    • mocked, built, later
  • the data it shows: which collection a parameter names (:analysis is an analysis)

The running site reads the sitemap to draw its side navigation and to show the right page for an address, with its parameters filled in. How the sitemap is written down is Q3. 

pages: [
  { title: "Home", address: "/", state: "old" },
  { title: "Analyses", address: "/analyses", state: "new",
    pages: [
      { title: "Analysis", address: "/analyses/:analysis",
        params: { analysis: "analysis" }, state: "new" },
      { title: "Runs", address: "/analyses/:analysis/runs",
        state: "old", screenshot: "figma/runs.png" }
    ] },
  { title: "Settings", address: "/settings", state: "old" }
]

A site is one unit, and each page says its own address

From Owen's request r1 (sent from epic ):

  • a site is ONE thing, seen whole, with its pages inside it, not many separate pages
  • the SITE holds each page's address and name, not the page: so a page can be moved to another address, or its name translated, without touching the page itself; links between pages name the page, and the site turns that into its address
  • the second site after the company's: Spell UI's component pages
    • today they're 94 separate notebook projects, one per component, each tab its own page file, linked by a copied tab bar pointing at editor addresses
    • as a site: one project, the side navigation listing the components, each component's tabs pages at addresses like /button/usage
    • the core has no pages-by-address yet (its page class says moving page to page isn't built): this epic builds it, and epic notebook's content rewrite turns those files into one site once it exists

So in Q3's Spell form, the site file lists its pages, each with its address, its name (in each language) and its parameters; a page file holds only what the page shows and does.
