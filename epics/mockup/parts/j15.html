A new page is a new type, which a running program can't take as it runs (Edit Without Redraw). So the not found page's Create it button makes the edit as one undo step, then restarts the run, which opens at the new page's address. The game-in-progress kind of state a site has is lost by that restart.

You asked: "how can we fix this?"

Why it restarts: the editor keeps a program running through an edit only when the edit stays INSIDE types it already has (LiveEdit). A type added, removed or renamed restarts it, and a new page is a new type. The site's own list of pages is inside the site's type, so adding the line alone could go live; the new page's file is what forces the restart.

  • nothing running can be using a type that didn't exist, so adding one is safe: load its class and register it, keep everything else running
  • removing or renaming a type still restarts (running things may be one)
  • helps every edit that adds a type, not just Create it: a new view, a new kind of thing
  • cost: about a phase's worth, in the live-edit reader and the runner; its test runs over every built-in example as today
  • before restarting, save what the running program holds (its things, the page it's on, form fields); restore it after
  • helps every restart, but matching old things to new ones after a type changes is hard, and some state can't come back
  • a site's data lives in its places, which a restart keeps; only what's held in memory goes (a half-filled form)
  • nothing to build
  • Create it adds the page with no restart; the running site goes to the new page as it is
  • a new phase after P2, or folded into P4 · Site Editor, where adding pages is most common
