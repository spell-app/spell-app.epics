No saved edit looks lost any more, and the editor's menus were reworked around drafts.

Saving, and your draft

  • In a checkout, saving a built-in example's file writes the file itself, so git sees it, and drops your old draft of it.
    • The built-ins are the examples and the library (@spell/examples, @spell/library), never the test projects.
    • The setting is editsBuiltins: on where the built-ins are the checkout's own source; SPELL_EDITS_BUILTINS overrides it.
  • Through the house-network site, Caddy marks every request it passes on, and a marked save stays a draft.
  • Your build (J86): while you have drafts, what the editor compiles is saved in your own build folder and served to you; everyone else gets the shared build. Publishing or discarding your last draft drops it.
  • "Your draft", with Discard, sits under the file tabs while the file showing is your draft, in English and Spanish. The tab's ring keeps no tooltip (J87).
  • Draft | Publish moved into the Run | Edit group, right of Edit, its words the modes' size.
  • AutoSave is on by default: each file is kept once typing pauses for 0.8 seconds, and as the page goes (J88).

The file tabs

  • Drag a file tab along the row to reorder the project's files; the order is saved in its project file. It needs the right to rename files, a project's Manager (J88).
  • A drag inside a Spell element's drawing no longer counts as the element's own drag.

The File and project menus, split

  • File holds what's about the open file: New Spell File (⌥⌘N, J90), New CSS File, Save (every unsaved file), AutoSave, Duplicate File, and Revert Changes to the file.
    • Revert goes to the last save with AutoSave off, to what's published with it on; one undo step.
  • The project's own menu, under its name before File, holds what's about the whole project: Rename, Delete, Duplicate, Reset to Saved, Publish, Versions, Delete Draft, Project Settings, Export, Import, Theme and Home.
  • Delete Draft puts every drafted file back as published, after asking, as one undo step. It throws away edits not saved yet in those files too (J93).
  • New Example moved to the Spell menu, at its foot above Home (J91).
  • Versions says plainly what restoring does. Its Save Current Changes keeps your draft as a list entry of its own, which only you see (J92).

Export and Import, as a .zip

  • Export downloads the whole project as a .zip, its pictures and project file included.
  • Import reads one back (or an old .spell.json) as a new project of your own. Every page and source file arrives as your draft; the project file and pictures are real files, and an archive with no project file gets an empty one (J100, T33).
  • The browser writes and reads the zips itself; the server's zip uses the same layout.

Project Settings

  • A heading, a narrower dialog, two fields to a row (title and version, lists start and also compiles to).
  • The languages' dropdown is as wide as its column; the title's hint is gone.

Sub-menus, in Spell UI

  • A new tag, <ui-submenu> (Q19): a menu row with a fly-out of the items inside it, or of a menu named by its id. Spanish <es-submenu>.
    • Its row's words are label= (J94).
    • It opens on hover at once, on a click, Enter or →; ↓ opens one in a sideways menu (J97).
    • It fits its widest item, and ticks when an item inside says it's on or off (J101).
  • SubMenuAim keeps a sub-menu open while the pointer heads for it: an angle check with 15° slack, which gives up after two misses or 0.4 seconds at rest, mouse only.
  • The editor's sub-menus use it: Theme, and the folded menu's File, Edit, View, Run and Help (J99).

Spell UI fixes found on the way

  • A toolbar's center slot centres what's in it, in the room between the title and the right.
  • A segmented menu's thumb is measured without a transform above it: it drew small as a dialog zoomed in.
  • A multiple dropdown's placeholder is centred top to bottom.
  • A field's info tip hides on a click elsewhere, and on a dialog's empty space.
  • The part under a dialog's heading has no rounded corners.
  • The bar menus have no extra space at the bottom, through the editor's own menu margin token (J89).
