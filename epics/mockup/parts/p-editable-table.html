Rows are edited one value at a time in the Inspector; nothing edits a whole table the way a spreadsheet does.

  • Click or arrow to a cell, type to replace it, Enter or Tab to move on, Escape to put it back.
  • Each cell is edited by its field's type: text, number, date, yes / no, and a link as a dropdown of the rows it can point at (a film's planet).
  • Add and delete rows; paste a block copied from Excel or Google Sheets.
  • Each change goes to the place the table shows (the samples now, the live API later), and ⌘Z undoes it, as the Inspector's edits undo.
  • Screen readers announce cells (the accessible grid pattern).
  • The Star Wars mockup gets an editable table of its sample rows.

<ui-table editable>: a cell cursor, typed cell editors, adding and deleting rows, pasting blocks of cells.

The table reads a place's collection itself, and writes each change through the place, undoable.

  1. The cell cursor: one cell is current; arrows, Tab, Enter, Home / End move it; the accessible grid pattern, so screen readers announce cells.
  2. Editing: typing starts an editor in the cell; Enter or Tab keeps it, Escape puts it back. An editor per field type: text, number, date, yes / no, a choice, a link as a dropdown of the rows it can point at. Worked-out cells are read only (Places.originOf() says which).
  3. Rows: a last empty row adds one; a key and the row's menu delete. Paste: tab-separated cells, as Excel and Google Sheets copy, fill from the current cell, adding rows.
  4. Spell UI never writes a place: the table sends <ui-property-editor>'s change event, and the host's bridge, the Inspector's pattern (InspectorData), writes it: startEdit() then set, commit or cancel, remove() for a row (PlaceThings), each one undo step.
  5. Long tables draw only the rows in view, through the core's drawnInWindow().
  6. Reading: columns from the collection's fields and types, so a page writes one <ui-table editable> over runs.
  7. Its docs page grows an editable example; the Star Wars mockup gets one.
  8. Checked by: the table's tests (keys, editors, paste, the change events); an app test for the bridge's writes and undo; screenshots; a manual paste test for Owen.
  9. Left out: formulas, frozen columns.
