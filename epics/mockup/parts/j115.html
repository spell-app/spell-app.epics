FizzBuzz's project file lists FizzBuzz.spell first (moved there, likely by dragging its tab). Its play fizzbuzz ran before Console.spell's on fizz listened and before Explainer.spell's page was made, so nothing printed and every count was 0. The compiler now cuts each file where its running code starts (a call, a loop, an if, a trigger, a set, a start) and writes every file's setting-up part first, then every file's running part, each in file order. Each file's own lines keep their order; nothing moves when no later file sets anything up.

  • FizzBuzz prints 1 to 100 again, and its page counts 27 fizz, 14 buzz, 6 fizzbuzz, 53 plain numbers, whatever order its files are listed in.
  • Star Wars' start line now runs after its last file's Portrait class, not before it.
  • A file's steps that move start with their heading's call again, so the Thing Explorer still names them by their heading.
  • A line the compiler can't tell is a step counts as setting up, and runs where it always did.
