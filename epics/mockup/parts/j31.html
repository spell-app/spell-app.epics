Chose one cancelable ui-editing event, over sending the property editor's change event (<ui-property-editor>), as the plan said.

  • Its detail is every change one keystroke, paste or click made: { edits }, each a set, an add or a remove.
  • Why: a paste or a row's delete is several changes at once, which a one-value change event can't carry as one undo step.
  • Not cancelled, the table shows the change in new rows of its own (a docs page, plain data).
  • A Spell program's core cancels it and writes its things, and the table follows them.
  • The table never changes a row in place.
