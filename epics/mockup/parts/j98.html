The menu a <ui-submenu> draws round its items is always an English <ui-menu>, so a choice in it is ui-choosing, not <es-menu>'s translated name.

  • Fixing it means drawing the row's menu's own tag, with its translated attribute names.
  • A named (by-id) <es-menu> is fine: its own event is sent again from the row.
  • A Spanish page listening for the translated choice event misses choices made inside a submenu, until this is fixed.

The editor's menus don't care (2026-11-13, the bar menus moved onto <ui-submenu>):

  • They close on a click on an action, not on ui-choosing, so the event's name doesn't matter to them.
  • Their fly-outs are named menus (<ui-submenu menu="...">), not items written inside the row: the row listens for the named menu's own event name, so the always-English menu it draws round inside items never comes into it.
  • And the editor writes English tags in every language: only its words are translated (appTexts).

So J98 stays a Spell UI matter, for a Spanish page that writes items inside an <es-submenu>.
