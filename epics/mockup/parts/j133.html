Built ON the menu, as <ui-toolbar> is: one new hook in UIMenu, boxContent(), lets the app menu put three section boxes where the menu's one slot was; its bar look is the menu's own window bar (class header), not a copy. No new attribute: the sections are slots (slot="start", none for the middle, slot="end"). Spanish: <es-barra-aplicacion>, slots inicio / fin.

appearance="header" is NOT retired: segmented header (a pane's bar row) still uses the word, and a value can't be renamed alone in the vocabulary; bare header keeps drawing the same bar, for anyone still writing it.

What stayed in the app's CSS: the editor's spacing (tight items, the bar's end padding, thirds' max-content), and its sub-menus' items' padding-block: 0 -- a sub-menu's items adopt the sub-menu's sheets, so the app menu's own rule reaches only its direct items.

The editor and Projects page draw their top bar with <ui-app-menu> (Spell's <app-menu>), pixel for pixel the same; the site's bar can use it next.
