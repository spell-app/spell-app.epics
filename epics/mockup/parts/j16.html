P3's plan said the docs nav would draw a site nav inside, and look EXACTLY as before. Those two can't both hold.

  • The docs nav: <ui-docs-nav>.
  • Inside it, a <ui-site-nav>, its rows a <ui-tree>.

Why not:

  • the docs nav's rows are the brand's panel rows: a star on each component, a status badge, a count on each topic band, topic bands as <h3>, Favourites, the A-Z / Topics switch
  • a <ui-tree-item> row is the tree's own look (its triangle, its indent, its selected fill), with no star or badge
  • so moving the docs nav onto it changes how the docs site looks, or needs the tree restyled to the brand's rows and given an actions slot per row first

Built: <ui-site-nav> as a component of its own (its docs page, its tests), drawn by every running Spell site; the docs nav untouched.
