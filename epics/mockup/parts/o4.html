The data comes from the ingester, run over the current site's API. It writes what it found to two files beside the site: the place and its types in Spell, and a description of every collection and field. The diagrams read that description; nothing reads the API a second time.

The NERD

A NERD is a picture of the data for people who don't care about columns:

  • a box per collection, with only its few fields that matter (a title, a status, a date)
  • a line per LINK, named for what it points at: analysis for one, analyses for many, never analysis_id
  • boxes in COLUMNS (e.g. projects, then analyses, then runs, left to right), which Owen drags about; the page remembers where he put them
  • Owen's own instructions for drawing a NERD (which fields to keep, how to name links) are fed in as its rules: T1

The ERD

  • the same box, every field, with its type; the id fields shown as links
  • clicking a NERD box FLIPS it, like a card turned over, to its ERD box, in the same place; clicking again flips it back

Sample data

  • the ingester already reads a few rows of each collection; Spell's samples (useSample()) keep up to five rows a collection, or rows copied whole (PlaceCopy)
  • rows the API doesn't serve (a page that's only drawn from HTML) are read off the current site's pages with a headless browser
  • later, the same pages switch to the live API with useInstead() / backToDeclared(): the page's code doesn't change
  • adding and editing rows: the Inspector already edits a place's rows

How the ingester reaches the current site (sign-in, network) is Q2.
