A running Spell program draws one page: the core's page class says moving from page to page isn't built.

  • Open the example site in Run: its first page shows; change the address to /button/api and that page shows.
  • Links between pages name the page, and the site makes the address: a program writes go to the analysis page for this analysis, or a link naming the page, and never writes /analyses/42 itself.
  • A page reads its parameters as properties: the analysis page's its analysis is the analysis the address named.
  • An address no page has shows a plain "no such page" page, not a blank one.
  • Address patterns are matched the way the page server's router matches its routes (:name, :rest*): one matcher for both.

The running site shows the page its address names, with the parameters filled in, and a link or a statement goes to a page by its NAME.

Run shows a site at a page's address, and the browser's back and forward work.

  1. One matcher for addresses: the page server's router already matches /analyses/:analysis (compilePattern()). It moves into util, browser-safe, and the router imports it from there; the router's own tests prove nothing changed.
  2. A Site class in the core, compiled from the site file: its pages, nested, each with its address pattern and parameters.
    • pageFor(address): the page and its parameters, or none
    • addressOf(page, parameters): the other way round, for links
  3. The Page class learns its address from the site, and its parameters become its properties: the analysis page's its analysis is looked up from the id in the address (from its place, or the samples).
  4. Going to a page: a statement (go to the analysis page for this analysis), and a link that names a page instead of an address; both turn into the address through the site. An address no page has draws a plain "no such page" page.
  5. Run: a site's page address follows the project's own in Run's address, e.g. the button's API tab at /run/@spell/examples/SpellUISite/button/api. The browser's back and forward move between pages; the editor's own routes are untouched.
  6. Checked by: core tests (each address to its page, nesting, no match, a link's address); an app test running the example site, following a link and going back.
  7. Left out: the side navigation (next phase); a site served outside Spell (the publishing epic).
