  • Open the example site in Run: its first page shows; change the address to /button/api and that page shows.
  • Links between pages name the page, and the site makes the address: a program writes go to the analysis page for this analysis, or a link naming the page, and never writes /analyses/42 itself.
  • A page reads its parameters as properties: the analysis page's its analysis is the analysis the address named.
  • An address no page has shows a plain "no such page" page, not a blank one.
  • Address patterns are matched the way the page server's router matches its routes (:name, :rest*): one matcher for both.

The running site shows the page its address names, with the parameters filled in, and a link or a statement goes to a page by its NAME.
