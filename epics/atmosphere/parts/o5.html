All 16 of AT Protocol's design proposals were read on 2026-11-04. These are the parts that bear on Spell hosting accounts and spaces.

  • A Spaces host is big: 27 server calls, three kinds of access, keys and signed summaries per space, on a full account server. Realistic only as Bluesky's own server, once Spaces ships, which its proposal calls "very much a work in progress" (0016).
  • A group can own a space: a group gets its own id as the space's owner, which can always read and write. No one can write another person's record, and nothing merges rows from two people: a shared row is ours to build (0016). Spell writes every record as the group's account, so a shared row is simply the group's record.
  • Reads are whole-space: a member reads all of a space or none of it, and access control isn't encryption: the host can read everything (0016). So something private is its own space, its own project data folder.
  • Spell owns the sign-in screen: it runs the sign-in server, so an emailed code is its choice.
    • Its own app can stay signed in with no consent screen (0010, 0011).
    • Making accounts is in no proposal.
    • T4 is the snag with emailed links.
  • A host answers for what it holds: takedowns, an abuse contact, signed abuse notices (0012), and reports and appeals (0009, 0005). All of it is about public data: Spell starts with a takedown path and an abuse contact, and adds reports and appeals later (Q7).
  • Leaving is half-specified: a space can be copied out and in, but how a group id whose keys the host holds leaves is not said: T5.
  • Useful shapes: lists with join, leave and admins for a group's members (0001, T6); records of 1 MB at most, about 10 KB advised, 200 changes a commit (0006); change streams a page can read as plain JSON (0015).
