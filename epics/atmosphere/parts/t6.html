A group's member list should follow the shape of AT Protocol's lists (proposal 0001): people join, leave, and some are admins.

  • That proposal's lists have exactly the moves a group needs: join, leave, and admins who manage the list.
  • Same shape, so a Spaces member list can be made from ours, or ours read from one.
  • Where the list lives is Q4's choice (a plain list in the folder's own file is recommended); this is only its shape.
  • Each member still has a read and a write flag, as a Spaces member space does.

A note from your answer to Q6 (reads direct, writes through Spell), 2026-11-04.

  • The read flag now means "holds a credential for the space": it opens the whole space, nothing finer.
  • The write flag is checked by Spell's server, on every write it makes as the group.
  • So a member who should see only part of a group's data needs a second space, not a narrower flag.
