Several waiting plans say a failed server write "goes into the retry queue", but Spell's server has no retry queue. The only one is the page's own save queue, which keeps a person's unsaved changes in their browser.

  • Projections (P25): a view Spell writes into a public space after each change to its source.
  • Inboxes And Messages (P28): copies of a message written into each person's inbox.
  • Write Server And Proxy (P14): a write handed on to a real Space host, which may be down.
  • Email And Subscriptions (P29) and Phone Alerts (P37): mail and alerts sent after a write.

What happens without one: the host is down for a minute, and that message never reaches Bo's inbox.

  • SaveQueue, the page's queue, gets a store on the server's disk, a DataFile, beside the browser's.
  • Every phase above puts its failed writes there: one queue, one way to retry, one place to look.
  • Cost: the queue learns to hold a send (mail, an alert) as well as a write.
  • A projection is rebuilt from its source, so a missed write is fixed by the next rebuild.
  • Inbox copies, mail and alerts share one new outbox on the server, retried by the daily round.
  • Cost: a second queue beside the page's, with its own retry rules.
  • one retry queue in Spell, the save queue, on the page and on the server
  • P14, P25, P28, P29 and P37's plans say "the save queue on the server's disk"
