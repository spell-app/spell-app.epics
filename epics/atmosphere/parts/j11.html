A room's websocket carries no token in its address any more.

  • A page can't set a header on a websocket.
  • Signed in, the cookie rides by itself and no token goes at all.
  • Not signed in, on this machine, the page still needs this run's token, so it goes as the socket's sub-protocol (spell-token.<token>), which the browser sends as a header.
    • Nothing is in the address, so nothing lands in a log.
  • The room's old ?token= is refused now.
