Spell's cloud can write a space's folder on its own disk, but not into a real Space as the org.

  • The recipe box, signed in as Ana, saves through Spell's cloud into a real Space, written as the test org.
  • Reading goes through a small proxy that holds no data: it passes Ana's own credential, and the host decides.
  • A person taken off the org's list is refused by the host, not by Spell (Spell never gates a read).
  • The trial for one person is done, with the same steps an org will use; the report to AT Protocol is drafted.

Spell's cloud learns to keep one test org's space in a real Space: it writes as the org, and passes each person's own credential through to the host for reads.

  1. First, the rooms' writes reach the space's checks (T38, from I8; moved here from P27 · The Sign-Up Sheet): today a room's Referee writes its place with an empty context, so a space's member, role, takedown and limit checks never see who is writing.
    • Each room's Referee is handed the space's own FolderPlace, from SpaceFolders.
    • The socket's signed-in person (request.person) is passed through as the write's identity.
    • Checked by: a room write refused for someone not on the space's list.
    • No separate write-server path for rooms: P27, P32 and P36 rely on this fix.
  2. One space, two stores: a space's settings may name a real Space to keep it in. SpaceFolders then hands its writes to AtProtoSpacePlace, signed in as the org, instead of to files. Every other space stays on files.
  3. The org's id: the test org from the trial, with its own AT Protocol id, as Q10 allows for a trial. Spell's own orgs keep their @ ids.
  4. Writes: the same one route, the same checks (role, owner, limits, takedowns), then a write as the org, each record's written-by field naming the person.
    • A write the host refuses for a moment (it's down) is retried by the ONE retry queue for the server's writes, mail and alerts: the save queue, kept on the server's disk (Q19 A).
  5. The read proxy: one more backend of DirectReads, not a new reader. For a real Space it takes the person's own Space credential and passes the read to the host, keeping nothing; the page's reads keep going through DirectReads as now.
  6. Member lists: adding or removing a member of that space also puts or removes them on the real Space's list.
  7. The report: a draft of what we found (the four file answers, the member side, single-writer spaces), for AT Protocol's alpha feedback.
  8. Needs you: posting the report yourself, where AT Protocol asks for alpha feedback.
  9. Checked by: headless tests against the host from P13, and the stand-in host.
  10. Left out: moving existing spaces; it's one test org, until Spaces leaves its alpha.
