Nobody knows yet whether a file (a picture, a program's source) can be uploaded into an AT Protocol Space.

  • A file uploaded into a Space, with one record naming it (name, type, size) and pointing to it, read back by a member.
  • We know whether publishing can copy a file from a private Space to a public one, and whether a replaced file is cleared away.
  • We know whether the host refuses a change made from an out-of-date copy, inside a Space.
  • If uploading can't work yet, the fallback is written down: a file's text goes in its record, with the same name and steps.

Spell's side of Spaces learns to upload a file into a space, and the trial answers the four unknowns about files, first on the stand-in host, then on the alpha.

  1. Read first: the Spaces proposal and the alpha's change list for how a blob goes into a space (its own upload call, or the account's usual one with a space named); write what it says into the Spaces guide.
  2. Spell's side: AtProtoSpace gains an upload and a read of a file, and a record shape for a file (name, type, size, pointer), as the guide's "A Document or Spell file is a real file" says.
  3. The stand-in host: FakeSpaces answers uploads as the proposal says, so the tests need no network.
  4. The trial's new steps: upload a picture into the org's private space; copy it to a public one; replace it and ask for the old one; write one record twice from the same old copy and see whether the second is refused.
  5. Needs you: the two alpha accounts again (the same environment variables as P11 · Spaces Trial), and your go-ahead before the real run; nothing real is kept, and the space is deleted at the end.
  6. Afterwards: the guide's unknowns and the fit table updated from the log; a fallback written into the guide if uploads don't work.
  7. Checked by: the stand-in tests, then the real run's log.
  8. Left out: the editor saving files this way (P23 · Files In Spaces does that, on Spell's own server first).
