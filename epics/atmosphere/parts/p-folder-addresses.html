A project data folder only ever lives on a test server, and every reader shares the same one.

  • A program saves to a real folder by its address: family cookbook is a data folder at "owen@spell/recipes" keeps its rows in that space's folder on disk, through one route on the page server. Addresses inside a folder stay as they are.
  • "recipes" is the program's own shared folder; personal "recipes" is one per person, in each person's space.
  • Until sign-in, owen@spell means the same person on every machine, and the page says so.
  • A server can say how often it may be asked at most: check it every can't go below that, and the line says why.
  • A row's version comes from its content, with the same hash CSV places use, shared rather than written again.
  • A project data folder's rows have an owner, written as a membership with the owner's role, in that folder's __members.
  • The recipe box moves both ways, between a project data folder and an atmosphere account.
  • This is data's old The Cloud phase, moved here: T1.

A full address, such as owen@spell/recipes, names a real folder in a space; personal gives each person their own; a folder's owner is a membership.

  1. The address: a data folder's at that reads owen@spell/recipes (no scheme) turns into the page server's one places route for that space's folder, instead of a plain web folder. The address is worked out by the same code that names projects (SP.SpellUrls), not a second parser. Files: placeKinds.ts, the app's route module, which serves FolderPlace over PlaceServer at that route.
  2. Shared or personal: "recipes" alone is the program's own folder, under its project's __data/; personal "recipes" is under each person's space. One new word in the place rules, beside the existing personal atmosphere account, in English and Spanish.
  3. Who is owen@spell: until P3's sign-in, the person is this machine's (SPACES.LOCAL_PERSON), and the side bar says "same on every machine until you sign in".
  4. Slowest polling: a place states its minimum in what it can do (beside its rate limit); check it every below it is raised to it, with a note at the line. Files: polling.ts, places.types.ts.
  5. Versions from content: CSV's hash moves into one shared helper, used by FolderPlace and CsvPlace.
  6. The owner: a new project data folder gets a membership, the person with the owner's role, in its __members/ (the people library's Membership, an "owner" role added); a write by anyone else is refused with "only the owner", as it is today on atmosphere accounts.
  7. Moving the recipe box: a copy from a project data folder to an atmosphere account and back, using the copy the rooms already have (RoomCopy) if it fits, else a small copy of its own, recorded why.
  8. Checked by: tests of each step (the parser's, the kit's places tests, the app's route tests); the recipe box headless, saving to owen@spell/recipes, reloaded, and moved both ways.
  9. Left out: sign-in, hosting, sharing with named people.
