A project data folder only ever lives on a test server, and every reader shares the same one.

  • A program saves to a real folder by its address: family cookbook is a data folder at "owen@spell/recipes" keeps its rows in that space's folder on disk, through one route on the page server. Addresses inside a folder stay as they are.
  • "recipes" is the program's own shared folder; personal "recipes" is one per person, in each person's space.
  • Until sign-in, owen@spell means the same person on every machine, and the page says so.
  • A server can say how often it may be asked at most: check it every can't go below that, and the line says why.
  • A row's version comes from its content, with the same hash CSV places use, shared rather than written again.
  • A project data folder's rows have an owner, written as a membership with the owner's role, in that folder's __members, when the folder has one: it's optional, and without one the folder's people are its org's members, as today.
  • The recipe box moves both ways, between a project data folder and an atmosphere account.
  • This is data's old The Cloud phase, moved here: T1.

A full address, such as owen@spell/recipes, names a real folder in a space; personal gives each person their own; a folder's owner is a membership.

  1. The address: a data folder's at that reads owen@spell/recipes is recognised by the one test Spell already has for addresses (SpellLocation.isAddress()), not a new one; today it falls through to a plain web folder. It becomes the page server's places route for that space's folder.
  2. The server side: no new server: PlaceServer serving a FolderPlace on the app's space storage, mounted in the app's route module the way the Airtable routes are.
  3. Shared or personal: "recipes" alone is the program's own folder, under its project's __data/; personal "recipes" is under each person's space. One new word in the place rules, beside the existing personal atmosphere account, in English and Spanish.
  4. Who is owen@spell: until P3's sign-in, this machine's person, and the side bar says "same on every machine until you sign in".
  5. Slowest polling: a place states its minimum in what it can do, beside its rate limit; check it every below it is raised to it, with a note at the line.
  6. Versions from content: CSV's row hash (csvRowVersion()) moves into one shared helper, used by FolderPlace too.
  7. The owner: each row's owner in the field the atmosphere account already uses (owner), refused to anyone else with the existing "only the owner". Who that owner is follows Q9: the person or org whose space it is; a folder MAY have its own __members, read when it's there, and without one its people are the org's members, through the people store's rolesOf().
  8. Moving the recipe box: a copy from a project data folder to an atmosphere account and back, using the rooms' copy (RoomCopy) if it fits, else a small one, recorded why.
  9. Checked by: tests of each step (parser, the kit's places tests, the app's route tests); the recipe box headless, saving to owen@spell/recipes, reloaded, and moved both ways.
  10. Left out: sign-in, hosting, sharing with named people.
