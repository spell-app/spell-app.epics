AT Protocol Spaces matches a project data folder with a list of people, but it can't hold real data yet, and someone with no account needs one made for her, which Spell now does.

A Space is a private group of records, shared by a list of accounts, each person's writes kept on their own host.

  • Everything here comes from reading docs, proposals and forums on 2026-10-31. Then it was tried for real on the Spaces alpha on 2026-11-05, with two accounts there, and the table says what was seen: Spaces gets tried for real once it reaches its beta, not now.
  • Read first: the alpha's announcement, its proposal, its running change list.
What we want Fit Why
One list of people per folder Fits A "member space" lists accounts, each with a read and a write flag: one project data folder, one Space. Spell's list is made from the membership records and roles kept for that folder in its people library, so each role gives a read and a write flag. On the alpha: a member added with a read and a write flag read the org's record and wrote its own
Finer rules later Partly Read is all or nothing across a Space: anyone holding a space's credential sees all of it, so something private is its own space, its own project data folder. Finer rules for writing are Spell's own, as every write goes through it
People hold their own data Not used Each person's writes sit on their host, which for the groups we're after is Spell (Q1). It isn't encrypted: the host can read it. On the alpha, a member's own host must run Spaces too: an ordinary bsky.social account could be listed, but its host answered "not implemented" when it asked to read (T35). Spell doesn't use this: its server writes every record as the group's own account, with a "written by" field naming the person
Ana, with no account anywhere No Members are listed by account, so Spell makes her one and hosts it
Sign in with an email link Not found The standard host documents passwords; but Spell runs the sign-in server, so the sign-in screen, an emailed code, is ours (T4). The alpha took a session signed in with an app password for every Spaces call, though its proposal says sign-ins are OAuth only (T33)
owen@spell/recipes Fits As Spell's own name for a longer at:// address, stored by account id, since handles change
Taking someone out Partly Removed, a member leaves the list of writers at once, and is refused a new read credential. But the one it holds still reads until it ends, 10 minutes later (T32)
Someone not in the space Fits Asking for a credential, they're told the space isn't found (SpaceNotFound): it doesn't say a space is there. A member trying to add members is refused (NotSpaceOwner): only the space's owner manages it
Ana and Bo editing one recipe Fits, through Spell Every record belongs to the account that wrote it. Spell writes them all as the group's account, so a shared recipe is one record, and Spell's server settles who changed what
Many small rows Fits A program reads the group's space directly, all on one host; write limits are unconfirmed
Large files Badly, for now How to upload one into a Space, and its size limit, are unclear
Working offline, or on one machine No Readers and the list's owner need hosts they can reach, so a project data folder stays the local copy
Live rooms No It says "something changed", then you fetch: rooms stay as they are
Hearing about changes from a page Polling Being told needs a service that can be reached, and a page isn't one

Why not to depend on it today:

  • Its own words: breaking changes are coming, data may be lost, no security review, not for production use.
  • Its hosted alpha server is invite only, and is deleted when the alpha ends.
  • Breaking releases came on October 22 and 29, and moving a Space to another host only became possible on the 29th.
  • The change list hopes for a beta at the end of November, and the announcement for a launch this year: no promised date.
  • A host that dies probably takes its Space data with it, as nothing mirrors it the way public records are mirrored.
  • Whether a page can reach a Space's addresses directly (the browser's cross-site rules). Programs read a space directly, so a real Space must allow it, as Spell's own server will.
  • How a page gets a space's credential, and keeps it safe.
  • Whether a local tool can get access to a Space through the local sign-in that public records allow.
  • How to upload a file into a Space, and how big it can be.
  • Which sign-ins today's host offers: the post we found is from 2025. The alpha takes an app password's session: whether the beta still does is unknown.
  • Real prices for a paid host: we found none published, and no independent security audit.
