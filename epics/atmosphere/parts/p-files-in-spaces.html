A space keeps rows of data, but not files: a page, a picture or a program's source has nowhere to go in it.

  • A picture added to the Events Team's public space shows on its page, and is listed by name, type and size.
  • A file has a name and can be replaced; nobody ever sees the hash it's kept under.
  • Changing several files at once: every file goes up first, then one change of their records, so nobody sees half of it.
  • Export gives the files as files, beside the rows as plain JSON.

A file in a space is a blob and one record naming it, as an AT Protocol Space keeps it, on Spell's own server first; several files change together in one go; plain export takes them too.

  1. The shape: the one P12 · Blobs In Spaces tried: a record (name, type, size, pointer) and the bytes, kept by their hash in the space's folder.
  2. What it's built from, nothing new:
    • the bytes written by saveBinaryFile(), as drafts' version zips are
    • one hash, contentVersion(); the drafts' own sha1 (in ProjectDrafts) folded into it first
    • the space's size limit through FolderPlace's own limits, not a second count
    • files out as a zip through the storage zip helper (zip.ts)
  3. One store for both: the same calls on Spell's own server and on a real Space, so a space can move later without programs noticing.
  4. Several files: bytes first, then one batch of records.
  5. Deleting: the bytes go when no record points at them any more.
  6. Limits and takedowns: a file counts against the space's 100 MB; a file can be taken down like a record.
  7. Export: files out as files.
  8. Checked by: tests; the drafts' tests unchanged after the hash is folded.
  9. Left out: drafts and publishing (P26 · Publish By Role).
  • A file in a space: its bytes and one record naming it, as an AT Protocol Space keeps one. A reader sees a name, a type and a size, never the hash the bytes are kept under.
  • One set of calls for both stores (SpaceFiles): FolderFiles on Spell's own server, AtProtoSpaceFiles on a real Space, so a space can move later without its programs noticing.
  • Every check holds: a file's record goes through the space's folder, so members and roles, the public settings, takedowns and the 100 MB limit apply. Its bytes count against the same limit, not a second count.
  • Several at once: every file's bytes are kept first, then their records change in one go, so nobody sees half. A refused write leaves no bytes behind.
  • Replacing and deleting: a name written again replaces the file; bytes go once no file points to them, but a taken-down file's are kept for its putting back. A takedown's delete takes them too.
  • On the page server: /api/files/spaces/<address>: read a picture by name for a page's <img>, list, add one, add several, remove.
  • Export: the files come out as files, files/<name>, with files.json listing them.
  • One hash: the drafts' own sha1 is now the kit's contentHash(), which contentVersion() uses too; the drafts' tests pass unchanged.
  • Checked: tests for adding, replacing, removing, several at once, export, a guest refused, a file over the limit refused, and a file taken down; the real-Space side against our own Spaces host.
