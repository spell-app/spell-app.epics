Sign-in mail goes out through Postmark from spell.app, with the steps only Owen can do (DNS, mailboxes, the service's account) written out one by one.

  1. The service: Postmark, of Q12's two (Q12 A, a mail service).
    • Its whole business is mail a person is waiting for (codes, links): it's the one comparisons name for arriving fast and out of spam.
    • It keeps sign-in mail apart from any newsletter-style mail, so one never spoils the other.
    • Cost: free for 100 mails a month (a trial, really), then $15 a month for 10,000. Resend's free tier is bigger (3,000 a month, 100 a day), so it's the fallback if the cost matters more than arrival.
    • No new package: Spell calls Postmark's web API itself, one request per mail.
  2. The sender: a PostmarkMailer beside the MailCatcher, the same Mailer shape, so sign-in, invites and later phases' mail all use it without change.
    • The server picks it when a Postmark key is set; with none, the mail catcher, as today (tests and this Mac stay as they are).
    • Settings: SPELL_MAIL_FROM (default Spell <sign-in@spell.app>) and the key, kept in a file only that machine's account can read, never in a repo or the page.
    • A failed send says so on the sign-in bar ("couldn't send the email, try again"), and is logged. Mail that isn't a sign-in (an invite, an update) is retried by the ONE retry queue for the server's writes, mail and alerts, the save queue kept on the server's disk (Q19 A); a sign-in code isn't queued, since a late code is no use.
  3. Putting the key on the machine: spell app cloud mail key asks for it (typing hidden) and saves it; spell app cloud mail test you@example.com sends one real mail. Both go on the commands page in the same change.
  4. The domains: spell.app sends; spell.social is set up the same way, ready for its pages. The abuse contact's default becomes abuse@spell.app (J25's guess, spell.spaces, settled). And a second address, abuse@spell.space, for what's hosted under spell.space (its spaces and handles, ana.rs.spell.space), both landing in one mailbox:
    • Spell shows abuse@spell.app by default (the setting, SPELL_ABUSE_CONTACT, as now); a refusal or takedown about something under spell.space shows abuse@spell.space (a second setting, SPELL_SPACE_ABUSE_CONTACT).
    • spell.space only receives: its MX, SPF and DMARC records, at Squarespace, and nothing of Postmark's unless it ever sends.
    • Read from Owen's "we'll want both", about abuse@spell.spaces: spell.spaces was never a domain, so the second address is at spell.space (Q27).
  5. A DNS check: spell app cloud mail check looks up each domain's records and says which are missing or wrong, in the words of the steps below.
  6. Needs you (about an hour, most of it waiting for DNS), every click and record in the guide Mail, Domains And Hosting:
    1. Both domains' DNS is at Squarespace: every record goes in its Custom Records.
    2. Mailboxes at Fastmail for both domains: owen@ at each, abuse@spell.app an alias.
    3. A Postmark account sending for both domains, approved to send to anyone; its key put on the machine with spell app cloud mail key, never in chat.
    4. One _dmarc record per domain, starting at p=none.
    5. spell.space too: its Fastmail records, SPF and DMARC, and an abuse@spell.space alias to your mailbox.
    6. Then tell me "mail's set up": I run the check and send a test mail to you.
  7. Checked by: tests of the sender against a stand-in Postmark (the request it sends, a refusal shown on the bar); the DNS check against made-up answers; then, once you've done the above, one real sign-in mail to you (a new manual test).
  8. Left out: newsletters and digests (Email And Subscriptions' phase uses this sender); receiving mail into Spell; moving DNS between companies.
