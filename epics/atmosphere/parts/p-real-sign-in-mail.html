Sign-in mail goes out through Postmark from spell.app, with the steps only Owen can do (DNS, mailboxes, the service's account) written out one by one.

  1. The service: Postmark, of Q12's two (Q12 A, a mail service).
    • Its whole business is mail a person is waiting for (codes, links): it's the one comparisons name for arriving fast and out of spam.
    • It keeps sign-in mail apart from any newsletter-style mail, so one never spoils the other.
    • Cost: free for 100 mails a month (a trial, really), then $15 a month for 10,000. Resend's free tier is bigger (3,000 a month, 100 a day), so it's the fallback if the cost matters more than arrival.
    • No new package: Spell calls Postmark's web API itself, one request per mail.
  2. The sender: a PostmarkMailer beside the MailCatcher, the same Mailer shape, so sign-in, invites and later phases' mail all use it without change.
    • The server picks it when a Postmark key is set; with none, the mail catcher, as today (tests and this Mac stay as they are).
    • Settings: SPELL_MAIL_FROM (default Spell <sign-in@spell.app>) and the key, kept in a file only that machine's account can read, never in a repo or the page.
    • A failed send says so on the sign-in bar ("couldn't send the email, try again"), and is logged.
  3. Putting the key on the machine: spell app cloud mail key asks for it (typing hidden) and saves it; spell app cloud mail test you@example.com sends one real mail. Both go on the commands page in the same change.
  4. The domains: spell.app sends; spell.social is set up the same way, ready for its pages. The abuse contact's default becomes abuse@spell.app (J25's guess, spell.spaces, settled).
  5. A DNS check: spell app cloud mail check looks up each domain's records and says which are missing or wrong, in the words of the steps below.
  6. Needs you, in this order (about an hour, most of it waiting for DNS):
    1. Find where each domain's DNS lives. In Terminal: dig NS spell.app +short, then the same for spell.social.
      • Names ending cloudflare.com: Cloudflare, at dash.cloudflare.com › the domain › DNS › Records › Add record.
      • registrar-servers.com: Namecheap, at Domain List › Manage › Advanced DNS › Add New Record.
      • domaincontrol.com: GoDaddy, at My Products › the domain › DNS › Add New Record.
      • porkbun.com: Porkbun, at Domain Management › the domain › DNS.
      • Anything else: whois spell.app | grep -i registrar names the company; its help page "add a DNS record" has the menu.
      • Both domains end in a place that takes a TXT, a CNAME and an MX record: every one above does.
    2. Mailboxes, at Fastmail (recommended; about $5-6 a person a month, check fastmail.com/pricing):
      1. Sign up at fastmail.com with a plan that allows your own domain.
      2. Settings › Domains › Add domain › spell.app › "I'll set up DNS myself". It lists the records; add each at your DNS place:
        • 2 MX records on the domain itself (name @): in1-smtp.messagingengine.com, priority 10, and in2-smtp.messagingengine.com, priority 20. Delete any other MX records first.
        • 3 CNAME records for its signature: names fm1._domainkey, fm2._domainkey, fm3._domainkey, values as Fastmail shows them.
        • 1 TXT record on @: v=spf1 include:spf.messagingengine.com ?all. ONE such record per domain: if one is there, add the include: to it rather than making a second.
      3. Back at Fastmail: Settings › Domains › Recheck DNS, until it's green.
      4. The same again for spell.social, in the same account (one account holds both domains).
      5. Make the addresses: owen@ at each, and abuse@spell.app as an alias to yours (Settings › Aliases).
      6. Free alternative: Cloudflare Email Routing forwards owen@spell.app to your Gmail. It only works when the domain's DNS is at Cloudflare, sends nothing itself, and its MX records replace Fastmail's: pick one or the other.
    3. Sending, at Postmark:
      1. Sign up at postmarkapp.com (your name and a card for the paid tier).
      2. Servers › Create Server, named Spell cloud.
      3. Sender Signatures › Add Domain › spell.app. Its DNS Settings page lists two records; add them:
        • a TXT record named like 20261105pm._domainkey, value k=rsa;p=... (copy it whole)
        • a CNAME named pm-bounces, value pm.mtasv.net (at Cloudflare: "DNS only", the grey cloud)
        Press Verify beside each; it can take up to 48 hours, usually minutes.
      4. The same for spell.social.
      5. Postmark lets a new account send only to its own addresses until it's approved: Account › Request approval, saying "sign-in codes and invites for spell.app".
      6. Servers › Spell cloud › API Tokens: copy the token. Don't paste it to me: on the cloud machine, run spell app cloud mail key and paste it there.
      No change to the SPF record above: Postmark's bounce address is pm-bounces.spell.app, which carries its own.
    4. One more TXT record per domain, which tells other mail servers what to do with mail pretending to be you: name _dmarc, value v=DMARC1; p=none; rua=mailto:owen@spell.app. After a few weeks of clean reports, p=quarantine.
    5. Then tell me "mail's set up": I run the check and send a test mail to you.
  7. Checked by: tests of the sender against a stand-in Postmark (the request it sends, a refusal shown on the bar); the DNS check against made-up answers; then, once you've done the above, one real sign-in mail to you (a new manual test).
  8. Left out: newsletters and digests (Email And Subscriptions' phase uses this sender); receiving mail into Spell; moving DNS between companies.
