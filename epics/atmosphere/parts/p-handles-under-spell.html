An account the org makes for someone has no AT Protocol name: other apps can't find ana@rs.

  • ana@rs and ana.rs.spell.space are two spellings of one person, worked out by one function both ways.
  • Other apps looking up ana.rs.spell.space find her account, once the host from P13 · A Spaces Host is reachable.
  • ana.spell.space stays free, for personal accounts later.
  • An org with its own domain gets ana.their-domain.org instead.

Each account an org makes gets a name like ana.rs.spell.space, which other AT Protocol apps can look up, while people still see ana@rs.

  1. First, one address reader: three files keep their own copy of the "id@org" pattern, and four places split an address at its @ by hand. Each is folded into SpellLocation (its isAddress()), the one place addresses are read:
    • the pattern: in the space command, the takedown command and Takedowns
    • the split: three in SpaceMembers, one in the preferences routes
  2. One function each way: a person-facing address to an AT Protocol name, and back, in SpellLocation beside it, with the org's own domain when it has one; the folder an address keeps stays SpellUrls.folderFor()'s.
  3. The look-up: Spell's cloud answers the standard name look-up (a small file at a well-known address) for names under spell.space, with the account's permanent id.
  4. Only accounts with an id: an account on the host from P13 has one; a Spell account on files has none, and its look-up says not found, as it should.
  5. Needs you: a wildcard DNS record for *.spell.space (or for each org, *.rs.spell.space) pointing at the cloud, when it has a real address. I'll write the record; you paste it in.
  6. Checked by: unit tests (the folded copies' own cases moved to SpellLocation's), and the look-up on this machine.
  7. Left out: handing out real accounts (P35 · Setting Up An Org); orgs' own ids (orgs stay @rs, Q10 A).
