An account the org makes for someone has no AT Protocol name: other apps can't find ana@rs.

  • ana@rs and ana.rs.spell.spaces are two spellings of one person, worked out by one function both ways.
  • Other apps looking up ana.rs.spell.spaces find her account, once the host from P13 · A Spaces Host is reachable.
  • ana.spell.spaces stays free, for personal accounts later.
  • An org with its own domain gets ana.their-domain.org instead.

Each account an org makes gets a name like ana.rs.spell.spaces, which other AT Protocol apps can look up, while people still see ana@rs.

  1. One function each way: a person-facing address to an AT Protocol name, and back, in the one place addresses are read; with the org's own domain when it has one.
  2. The look-up: Spell's cloud answers the standard name look-up (a small file at a well-known address) for names under spell.spaces, with the account's permanent id.
  3. Only accounts with an id: an account on the host from P13 has one; a Spell account on files has none, and its look-up says not found, as it should.
  4. Needs you: a wildcard DNS record for *.spell.spaces (or for each org, *.rs.spell.spaces) pointing at the cloud, when it has a real address. I'll write the record; you paste it in.
  5. Checked by: unit tests, and the look-up on this machine.
  6. Left out: handing out real accounts (P34 · Setting Up An Org); orgs' own ids (orgs stay @rs, Q10 A).
