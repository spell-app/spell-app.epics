An org is one space with one list: there's nowhere to keep the Finance Team's notes away from everyone else.

  • RS's ten spaces: the org's, the Admins', and the Membership, Events and Finance teams', each a shared one everyone in the org reads and a private one only its Leads reach.
  • A new project gets its two spaces when it's made.
  • Addresses people read: events_team@rs/2026-q4/welcome, finance_team@rs/__private/budget-notes.
  • Spell keeps each list right from the roles (Q9's memberships, worked out, never typed).
  • The page server on this machine answers the same addresses and roles as the cloud.

Each org, standing team and project gets a shared and a private space, made when needed, each with the member list its roles say, on Spell's own server and the local Spell host alike.

  1. Addresses: a team or project inside an org reads events_team@rs, with the space after it, the org-wide one by default and the private one named; a project's under its team (events_team@rs/2026-q4).
    • Read by SpellLocation, the one address reader P16 folded the copies into (isAddress()), and filed by SpellUrls.folderFor(); no new pattern or split.
    • The at:// form stays out of sight.
    • The private space's folder is __private (Q25 A), one of Spell's own names; pages show it as "private".
  2. Folders: each space a folder of its own under the org's, so export, backups and takedowns work on it as they do on a space today.
  3. Who's in each: SpaceMembers works a space's list out from the org's roles (P20 · Org Roles): the org-wide space, everyone in the org; a private one, its Leads and everyone above them.
    • The org-wide space is NOT built on publicRead, which means anyone on the internet; it's the "shared space" (Q22 A), and "public" means only publicRead, anyone at all.
  4. Made when needed: a space appears the first time it's written; nobody makes ten folders by hand.
  5. The Admin requests space: the Admins' org-wide space, where anyone in the org may ask them for something.
  6. Both servers: the page server (this machine) and the cloud share the same folders code, so both answer the same.
  7. Checked by: tests over RS on both servers, including that nobody outside the org reads the org-wide space.
  8. Left out: what each role may write there (next phase); a space per person (P28 · Members' Own Spaces).
