In a flex row or stack, a static checkbox or rating is a few pixels shorter than the live element, so the rows below it shift up.

  • Why, live: the host is display: inline-block; as a flex item it's blockified, and holds its inline-block root in a LINE BOX at least the strut's height (the line's minimum height).
  • Why, static: there's no host, so the root itself is the flex item, with no line box around it.
  • Example: a checkbox is 25.4px tall as an element, 19.4px static.
  • This drift alone accounts for these examples' parity differences:
    • ui-checkbox/variations 10%
    • ui-checkbox/types 4.3%
    • ui-checkbox/states 3.9%
    • ui-rating/variations 19%
  • A real fix needs a box with the host's display around the root, in the flattener; left for the lead to weigh.
  • Done per family instead, where the root would STRETCH: .ui.checkbox:not(.invisible) { inline-size: fit-content } (a no-op inside the host).
  • nothing changes: checkboxes and ratings sit a few pixels shorter on static pages
