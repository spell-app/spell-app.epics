Solid's compiler, compiling for the server, passed a TypeScript type parameter along as if it were a value. Every modal and flyout render threw V is not defined.

  • Where it hit, packages/ui/src/components/ui-modal/DialogElement.tsx, inside a <Show>: part={this.part(UIT.HEADER as PartName<V>)}
  • Why: @solidjs/compiler (rc.11, server output, with hoistProps on by default) hoists a component's children into a module-level constructor, and passes it every free name they use, the class's type parameter V too: new _P$(_self$, V).
  • Reproduced on a 1-line class; hoistProps: false avoids it.
  • Worked around with methods, dialogPart() and closeText(), which the file still uses (checked 2026-10-04).
  • Any generic class with an as X<V> cast in a component's children will hit it.
  • Not checked: whether rc.13, the version the repo is on now, still does it.
  • no as X<V> casts in a component's children: move them into a method
