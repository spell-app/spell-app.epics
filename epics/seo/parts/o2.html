What the server render must fix

What stood in the way of rendering Spell UI in node, and how each was fixed.

  • The old probe passed only because its stand-in element had no children, parent or internals (ssr.ssr.test.tsx).
    • now ServerHost wraps a real linkedom element
  • The element layer, solid-element, had no server path.
    • browser-only: customElements, attachInternals, attachShadow and insert
    • its hooks throw without an element in context
    • fixed by ServerElement, in @spell-app/solid-element/server (D9)
  • Hooks with no guard: they register, and never run under ServerElement.run() (D9).
    • PartContext's onConnect, in 34 tags
    • FormElement's onFormReset, in 8 families
  • SlotContent used the Element and Node globals, so it crashed on any element with children.
    • now it tests nodeType
  • The UI runtime won't construct in node: new CSSStyleSheet().
    • about 25 families use its services while rendering: text(), UI.ids, UI.i18n or UI.browser
    • ServerRuntime installs those services (D11)
  • isServer checks made the output EMPTY: accordion panels, tab buttons, a card's slotted parts, table rows.
    • each family got a server branch in P3
    • an element's own ARIA goes through hostEffect() (D10)
  • Icons came from async packs and DOMParser, so on the server they were empty boxes.
    • now the SVG is read from disk, inline (D23)
