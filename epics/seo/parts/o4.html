Without shadow DOM, CSS leaks two ways: from a component into one nested in it, and from the page into a component.

Component into nested component (D5)

  • The leak: .ui.menu .item would reach a nested dropdown's rows.
    • leaky selectors per sheet: menu 44, list 34, dropdown 34, form 22, message 21, breadcrumb 14, comment 9
  • The fix: each sheet is wrapped in @scope (D13, D34).
    • from its families' roots: [data-ui=kind], and class-grammar markup the page wrote
    • down to, not into, the author's content and other components
  • Every rewritten subject is anchored with :where(:scope, *) (D18).
    • why: inside @scope, a bare .ui.card means a DESCENDANT of the root
    • subjects from shadow markup also get :not([data-ui-slotted]), so they never land on the author's content (D42)
  • A sheet several families adopt is scoped to every kind seen adopting it (D19).
    • e.g. items take ui-list.css
    • sheets keep their adoption order
/* in the shadow root */
.ui.cards > .card,
:host(:state(in-cards)) > .ui.card { margin: ...; width: ...; }

/* static */
@layer ui.components.card.types {
  @scope (:is([data-ui="cards"], [data-ui="card"], .ui.cards:not([data-ui]):is(...), .ui.card:not([data-ui]):is(...)))
    to ([data-ui-slotted]:not([data-ui]) > *, :scope [data-ui] > *) {
    .ui.cards > .card:where(:scope, :not([data-ui-slotted])),
    .ui.cards > [data-ui-li] > .card:where(:scope, :not([data-ui-slotted])),
    :scope:where([data-ui]):is([data-state~="in-cards"]):is(.ui.card) { margin: ...; width: ...; }
  }
}

Page into component (D6, D58)

  • Page CSS never reached a component's own markup: the shadow boundary kept it out. Statically, every page subject gets REACH, so it still reaches only:
    • what's outside components
    • roots, which were the elements
    • the author's content
    :where(:not([data-ui] *), [data-ui], [data-ui-slotted], [data-ui-slotted] *)
  • Element names, parts and states in page CSS become attribute selectors (D22).
    • in <style>s, and in local linked sheets (D59)
    ui-card     =>  [data-ui="card"]
::part(p)   =>  [part~="p"]
:state(x)   =>  [data-state~="x"]
  • The stylesheet opens with its layer order, @layer ui-slotted, page, ui;, and is linked first (D52).
    • a page that layers its CSS as page loses to components
    • unlayered page CSS still wins on roots and the author's content, as it beat a shadow root's :host and ::slotted() rules in a browser

Rest of the rewrite

  • :host(X) > C becomes :scope:is(X):is(C).
    • the root replaced the element, so both land on one element
    • :state(x) becomes [data-state~="x"]
  • Rules for the element alone (token resets) move to @layer ui.reset, without display (D15).
  • ::slotted() and slot rules move to @layer ui-slotted, before page (D42).
    • they lost to the page in a shadow root too
  • In list groups (cards, list, feed, steps, items), each A > B also matches A > [data-ui-li] > B (D14).
  • Foundation sheets:
    • they keep only page selectors
    • reset.css is scoped to every component (D16)
    • typography and native get REACH
    • page sheets that families register while rendering are included (D35)
  • [hidden] { display: none }, unlayered: a component's display rules would beat the browser's.
  • Inherited properties already crossed shadow boundaries: no change.
