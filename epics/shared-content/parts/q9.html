  • packages/docs/ (tracked): package.json, AGENTS.md, tools/ (scripts, _assets, goals tooling)
  • packages/docs/content: a link to spell-app-dev/packages/docs/content, holding ALL docs content: index.html, changelog.html, guide pages, epics/, solid/, dev/, templates/, details/

Why tools can't live in the content repo: Node runs a linked script from its real path, where there's no node_modules and no $/ aliases (the tools import linkedom, playwright, esbuild, $/server, @spell-app/ui). Rejected: a link per content folder, which keeps most URLs but needs about 15 links and moves the 10 top-level pages anyway.

Net effect:

  • every docs URL gains /content/: /guides/solid/solid-2.html (C6)
  • links between pages don't change (they move together)
  • pages load assets from ../tools/_assets/ (depth-adjusted); the peer has a packages/docs/tools link back to spell-app's, so file:// still works
  • three links per checkout: packages/docs/content, goals, agents
