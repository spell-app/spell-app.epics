Claude Code already has /tasks, a built-in command: it lists everything running in the session's background and can stop any of it. Do we still build /bg list and /bg stop <name>?

Net effect (A):

  • /bg has one form, /bg [n] <task>
  • listing and stopping: Claude Code's /tasks, named in the skill and its reply
ChoicesA · Use /tasks, no list or stop (recommended)
  • /bg only starts tasks; its started: line ends "(/tasks to see or stop it)".
  • Why recommended: /tasks reads Claude Code's own record, so it's always right; a /bg list would rely on the session remembering what it started, which a compacted session can get wrong.
  • Less to keep up to date.
B · Build both
  • /bg list: the session's own list (names, age); /bg stop <name>: TaskStop, by the name it gave.
  • Wins: stop by the /bg name, in chat; one command to remember.
  • Cost: only works with Q1's option A, and the list can drift from the truth.
Answer · Build both: /bg ? lists, /bg stop <name> stops

Owen picked B in a modal (2026-10-07), and his plan comment renamed the list form: it is /bg ?, not /bg list.

  • /bg ?: the running agents, from the list file (spell dev agent list): name, task, status, age
  • /bg stop <name>: TaskStop by the entry’s taskId, then spell dev agent done

Net effect:

  • both forms are in the /bg skill (P2), reading the running-agents list (P1)
  • Claude Code’s own /tasks still works beside them
