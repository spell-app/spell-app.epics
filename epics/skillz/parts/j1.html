The running list of agents (P1) is built in the docs package, not in the CLI as the plan said: Owen would notice it when looking for the code, or when epic agents starts a little slower than other spell dev commands.

  • what the plan said: packages/cli/src/dev/agents.ts (the phase body, and the command-name decision, Q12)
  • what was built instead:
    • spell-epic/src/tools/AgentList.ts: the class; it finds the file’s place, prefixes the name, and does add / set / done, with locked, atomic writes like inbox.js
    • spell-epic/src/tools/agents.ts: the command line around it
    • epic agents is a lean pass-through to it, exactly as spell dev plan-doc is: packages/cli/src/commands/agentsCommand.ts, and TOOLS.agents in packages/cli/src/dev/passThrough.ts
  • why: the page route of P3 (spell-epic/src/tools/agentRoutes.ts, beside reviewRoutes.ts) must read and write the same file, and neither direction of import is allowed:
    • no other package may import the docs package’s code (root AGENTS.md: dependencies flow one way)
    • the docs package may not import a leaf file of $/cli such as $/cli/dev/agents (WWOD §4: imports go through barrels only)
  • option rejected: the class in spell-app/src/cli, with the route either
    • importing $/cli/dev/agents, which breaks the barrel rule, or
    • keeping its own copy, which means two writers’ code for one file
  • one class, AgentList, used by both the CLI and the page server
  • epic agents costs a child node start (about 0.3s), like spell dev plan-doc
  • the plan’s path packages/cli/src/dev/agents.ts does not exist; that name stays free
