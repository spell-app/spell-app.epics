When /bg starts a helper, it first writes the helper into the running-agents list (spell dev agents add), then makes the Agent call, then fills in the task id the call returns (spell dev agents set --task-id). The other order, start first and add after, would need one command fewer.

Why add first:

  • add refuses a name that is already running, so a name clash is caught BEFORE any agent exists: no orphan helper to stop
  • the entry is in the list even if the session is interrupted right after the helper starts, so /bg ? and spell dev agents still show it

The cost: one more command per start, the set --task-id.

Example, for /bg "aaa" 2 tidy the docs:

  1. spell dev agents add aaa "tidy the docs" prints skillz-aaa
  2. one Agent call, its description starting skillz-aaa:, returns a task id
  3. spell dev agents set aaa --task-id <id>

Net effect:

  • the skill’s “Start” steps are add, then Agent, then set --task-id
  • a clashing name is caught before anything runs: add exits 1 (“running already”), and /bg takes the name with a number instead (aaa-2)
  • an entry has no task id for a moment, between the Agent call and set --task-id
