Every agent Claude starts gets a name, whether /bg starts it or Claude does on its own (Owen's plan comments, 2026-10-07, Q8). The epic (or the checkout) keeps a list of the ones still running, so Claude can always tell what is in flight, and so can Owen, through /bg ? and the plan doc's panel.

Names

  • /bg "aaa" <task> names the agent aaa. With no name, Claude makes one up from the task: 1-3 words, kebab-case (string-docstrings).
  • The REAL name is prefixed with the epic’s name, else the worktree’s, else main:
    • /bg "aaa" in this epic is skillz-aaa
    • the same on main is main-aaa
    • agents Claude starts on its own are named the same way: this doc's Doc Review was done by skillz-plan-doc
    • an agent’s own helpers add to its name: skillz-aaa-tests
    • a name already running is refused (add exits 1), and Claude takes aaa-2
  • Claude Code’s Agent call has no name field (C2). So the name goes first in its description (skillz-aaa: docstrings in string.ts), and in the list.
  • A reply that relays an agent’s report opens with its name in bold: Agent skillz-aaa came back with:

The list, one file per place

Git-ignored, never committed: it is what is running NOW, and the file goes once the list is empty.

  • in an epic: agents.json, beside the plan doc in the shared repo
    • ignored by the shared repo's .gitignore, and by spell dev shared init’s template (epics/*/agents.json)
  • no epic: <checkout root>/.spell-agents.json, in spell-app’s .gitignore (Q5)

Format

Owen’s format, plus the fields the command needs:

  • started: for the age
  • taskId: Claude Code’s background task id, for /bg stop and redirects
  • redirects: Owen’s notes from the plan doc (1.5)
[
  {
    "name": "skillz-aaa",
    "task": "Add a docstring to every export in util/string.ts",
    "status": "active",
    "started": "2026-10-07T14:05:00-04:00",
    "taskId": "<background task id>",
    "redirects": [
      { "note": "only the exported ones", "at": "2026-10-07T14:07:12Z", "told": "2026-10-07T14:07:19Z" }
    ]
  },
  {
    "name": "skillz-bbb",
    "task": "Rename the string helpers' tests",
    "status": "blocked on skillz-aaa",
    "started": "2026-10-07T14:06:10-04:00",
    "taskId": ""
  }
]
  • status: active, or blocked on another agent, which it waits for
  • task: one sentence or less
  • an entry goes when its agent finishes (spell dev agents done)

Who updates it

Only spell dev agents (and the page server's redirect route), never Claude by hand (Q6). Several helpers may write at once, so every write is locked and atomic (AgentList.ts, on the same file lock as the review inbox).

  • add <name> "<task>" [--status ...] [--task-id ...]: adds the prefix, prints the full name
  • set <name> [--status ...] [--task-id ...]: changes only the fields given (I4)
  • done <name>: when its report arrives, or it is stopped
  • list [--json]: what /bg ? shows
  • --epic <name>, on any of them, picks the epic by hand
  • wait / told: redirects from the plan doc (1.5)

The standing rule

It's Claude-only, so it lives in the root CLAUDE.md, "Delegated work". It is short and points at the /bg skill for the steps (J4):

  • every agent Claude starts is named and listed
    • spell dev agents add before it starts, done when it's back
    • while any runs, a spell dev agents wait waits for redirects
  • the reply relaying it opens Agent <full name> came back with:
  • plan-doc work goes to a background agent, as if Owen had typed /bg "plan-doc" ... (Q9). /epic’s SKILL.md says so in its fill, phase-done and Doc Review steps.
