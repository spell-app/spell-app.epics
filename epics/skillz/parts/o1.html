/bg hands a task to a helper agent that works in the background, so the Claude panel is free again at once (the skill: SKILL.md).

Owen can keep talking to the session, or send more /bg tasks, while the helper works.

  • /bg ["name"] [n] <task>: start the task.
    • "name" (optional, a quoted first word) names the helper; with none, Claude makes one up from the task. Its real name gets the epic’s prefix: /bg "aaa" ... here is skillz-aaa.
    • n (optional, 1-5, default 1) is the most agents the task may use IN ALL, the helper included. /bg 3 <task> means the helper plus up to 2 of its own.
    • It's meant as a hard cap: unlike the root rule (up to 5 agents, unasked), the helper never goes over n. Only the helper's prompt holds it to that (C1).
  • /bg ?: the agents still running, from the list (spell dev agents list --json), each with its name, status, age and task.
  • /bg stop <name>: stop one (TaskStop by its task id), and take it off the list. Its staged changes stay.

What happens, in order:

  1. The same-files check, against the running agents' tasks. When one touches the files this task will:
    • the new task is listed as blocked on <other>, and doesn't start yet
    • the reply is one line, waiting: ...
  2. spell dev agents add lists the helper and prints its full name (why first: J3).
  3. ONE background Agent call: a fork of the session first (Q1), else general-purpose where the session has no fork agent (I3, 1.3). Its prompt is the skill's template:
    • the task, word for word
    • a Context line: what the conversation said that the task leans on, which a general-purpose helper can't see
    • the checkout, the epic and plan doc, and the budget n
    • the house rules: WWOD; stage, never commit unless told; shared files edited at their real path; plain shell commands in a worktree
    • no AskUserQuestion: a choice only Owen should make is taken and recorded as a judgement call (Q4)
  4. spell dev agents set --task-id: the id /bg stop and redirects need.
  5. A redirect waiter starts, if none runs yet (1.5).
  6. The session replies ONE line, started: skillz-aaa (1 agent), and ends its turn: the panel is free.
  7. When the helper finishes, its notice wakes the session, which:
    • runs spell dev agents done
    • writes a short report, opening with a bold line: Agent skillz-aaa came back with:
    • starts any task that was blocked on this one

Tried for real from the VS Code panel (P5):

  • a helper came back in 52s (V1)
  • /bg 3 stayed within 3 agents (V2)
  • a second task on the same file waited, then ran (V3)
  • /bg stop left nothing behind (V4)
