Decided (2026-10-07): the session starts it, as a background fork (Q1): Agent with subagent_type: "fork" and run_in_background: true.

Claude Code has two ways to send work to the background. Which one /bg uses is the first question (Q1).

  • The session starts it (the shape agreed in session wwod-spell-ui): /bg loads its instructions into the session, which makes one Agent call with run_in_background: true, says one line and ends its turn. A few seconds of the panel.
    • The helper can be a fork: a copy of the session that sees the whole conversation, so "fix the thing we just talked about" works without spelling it out.
  • The skill IS the helper: frontmatter context: fork (background is the default then). Typing /bg ... starts the forked copy straight away; the session itself never takes a turn.
    • The catch: EVERY /bg forks, /bg list and /bg stop too, so those can't be part of it. And nobody checks for two tasks touching the same files before starting.
  • Either way, the helper may start helpers of its own (Claude Code allows three levels), up to its budget n. A fork can't start another fork, only ordinary agents.
