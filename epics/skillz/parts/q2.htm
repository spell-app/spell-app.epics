Where does the helper make its changes: in the same checkout as the session, or in a worktree of its own? Owen notices this in Source Control: the helper's edits show up beside the session's, or under their own branch.

A · Same checkout (recommended)
  • The helper edits the files the session works on; its changes show at once, staged, never committed.
  • Cost: the session (or another /bg) editing the same file at the same time would collide; /bg says so and runs the second task after the first.
  • Why recommended: most /bg tasks are small and belong to the work under way; a worktree would need merging back each time.
B · A worktree each
  • Each helper gets .claude/worktrees/<session>-agent-<id> (isolation: "worktree"), commits there, and the session merges it in when it's done.
  • Cost: a merge per task, and the helper starts from committed work, so it can't see the session's uncommitted changes.
  • Could still be an opt-in flag later (/bg -w ...).

Net effect (A):

  • a /bg helper works in the session's own checkout, staging its changes
  • two tasks on the same files run one after the other, never side by side
