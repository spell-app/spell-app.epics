Redirecting an agent from the plan doc (P3) relies on SendMessage to a background agent that is still working. Whether that message lands while it works, or only once it has finished, is not checked yet.

  • P5 tries it with a real agent
  • the fallback, if it only lands at the end: stop the agent (/bg stop) and start it again with the redirect added to its task
  • P3 builds the route and the waiter either way; only the session’s last step (send, or stop and restart) depends on what P5 finds
