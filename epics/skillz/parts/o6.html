Two new /epic forms that act on the session's OWN epic, the plan doc of its worktree (Q11, P4). With no epic, they say so and stop. The skill sections are .claude/skills/epic/SKILL.md's "10. Add a phase" and "11. Start".

  • /epic phase [ids] [name]: a new phase. Owen's input goes on the lines after.
    • ids (J1 J5, t3: spaces or commas, any case): the phase's antecedents. Each one is linked in its goal and queued into it.
    • the other words: its name (add-phases becomes Add Phases). With no name, Claude makes one from the items.
    • no ids: a phase from scratch, from the text
    • a background <epic>-plan-doc agent drafts it and places it before Doc Review while Doc Review is still to do
  • /epic start P3 works a phase. /epic start J3 J4 T6 works those items as one block, each closed when done, in ONE commit, <epic> J3 + J4 + T6: ..., so commits --backfill files it under each item.
  • phase and start are reserved epic names. The prompt hook, .claude/hooks/prompt-gate.mjs, lets them through without renaming or blocking.
  • spell dev plan-doc add-phase ... --before N inserts the phase as PN:
    • the to-do phases from N on move down one, with their ids, part files, links and data-phase
    • it's refused once any phase it would move has started
    • prose without a link is left as written (J7)
    • the log says what moved, old numbers to new: P6 · Doc Review moved down to P7 (I6)
  • Tried live (V7 and V8): /epic phase t1 made P6 · Test Ids from a todo, and Owen then had it removed. There is no remove-phase command, so it was taken out by hand. /epic start then worked I6, and later I5, as blocks of their own.
