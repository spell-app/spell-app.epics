spell dev server ensure, which every opener calls, now restarts a page server that started before its code last changed.

  • its code: the server package's packages/server/src/, plus each route module's folder
    • PageServer.ensure() passes those folders as sources to SRV.PidFile.ensure()
    • newestChange() is their newest file time; a server that started before it is stopped and started again
    • so after a merge, the next page opened comes from a fresh server
  • why: found while trying the panel (I5). A page server loads its route modules only when it starts, and the main checkout's had started before P3 merged: it had no /api/agents route, so the plan doc showed no panel.
  • Owen picked this, option C, over two others (Q13):
    • the merge restarting the server: that misses a pull, or a merge done by hand
    • the server reloading its own routes: Node caches modules, and routes can't be removed
  • Until skillz merges, spell runs main's CLI, which doesn't have this yet (C6). After the merge, the hand check is V9.
