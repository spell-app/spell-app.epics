Each plan doc shows its epic's running agents in an "Agents running" panel above section 1, whenever the list isn't empty. Each agent has a note box, so Owen can steer it from the side bar without typing into a busy session (Q10, P3).

  • One row per agent: its name, a status label (active blue, blocked on ... orange), its age, its task, and the notes sent to it so far ("You · 12:52 PM · waiting for the session", then "told").
    • under the rows: a note box that grows with its text, and Send (Cmd/Ctrl+Enter too)
    • its look and wiring: J5, J6
  • The page server's route module, agentRoutes.ts (listed in the root package.json's pageServer.routes):
    • GET /api/agents?page=: the epic's list; the page polls it
    • POST /api/agents/redirect { page, name, note }: guarded like the review routes (token, same origin); the note lands in the agent's redirects, untold
  • The session hears it: while any agent it started runs, it keeps ONE spell dev agents wait going in the background.
    • that command exits with the untold notes (skillz-aaa: <note>)
    • the session then SendMessages each note to its agent, runs spell dev agents told <name>, and starts waiting again
    • its other exits: 3, nothing runs any more; 2, an hour passed
  • Tried live (P5, V5 and V6): two notes reached a RUNNING helper in about 7s each, and the second changed its course. So C4's fallback (stop and restart with the note) isn't needed.
  • On main since epic epic-components' P12, the panel is drawn by <epic-page> (AgentsPanel.tsx, over AgentsClient). The route and the list are unchanged.
