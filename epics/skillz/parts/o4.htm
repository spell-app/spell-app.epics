Every agent Claude starts, by /bg or on its own, gets a name, and the epic (or the checkout) keeps a list of the ones still running. So Claude, and Owen through /bg ?, can always tell what is in flight. Owen asked for this in his plan comments (2026-10-07; the names decision, Q8).

Names

  • /bg "aaa" <task> names the agent aaa. With no name, Claude makes one up from the task: 2-3 words, kebab-case (docstrings-string-ts).
  • The REAL name is prefixed with the epic’s name, else the worktree’s, else main:
    • /bg "aaa" in this epic is skillz-aaa
    • the same on main is main-aaa
    • agents Claude starts on its own are named the same way: this doc was filled by skillz-plan-doc
    • an agent’s own helpers add to its name: skillz-aaa-tests
  • Claude Code’s Agent call has no name field (C2), so the name goes first in its description (skillz-aaa: docstrings in string.ts), and in the list.
  • A reply that relays an agent’s report opens with its name in bold: Agent skillz-aaa came back with:

The list, one file per place

Git-ignored, never committed: it is what is running NOW.

  • in an epic: epics/<epic>/agents.json, beside the plan doc in the shared repo; epics/*/agents.json goes in spell-app-dev’s .gitignore (and in spell dev shared init’s template)
  • no epic: <checkout root>/.spell-agents.json, in spell-app’s .gitignore (the no-epic list decision, Q5)

Format

Owen’s format, plus two fields the command needs: started (for the age /bg ? shows) and taskId (Claude Code’s background task id, for /bg stop). P3 adds redirects, the notes Owen sends from the plan doc.

epics/skillz/agents.json · 16 lines 
[
  {
    "name": "skillz-aaa",
    "task": "Add a docstring to every export in util/string.ts",
    "status": "active",
    "started": "2026-10-07T14:05:00-04:00",
    "taskId": "<background task id>"
  },
  {
    "name": "skillz-bbb",
    "task": "Rename the string helpers' tests",
    "status": "blocked on skillz-aaa",
    "started": "2026-10-07T14:06:10-04:00",
    "taskId": ""
  }
]

The command is spell dev agents, not spell dev agent (2026-10-07): the WWOD citation check that had the name moves to spell dev wwod check (Q12).

  • status: active, or blocked on <name> (it waits for that one)
  • task: one sentence or less
  • an entry goes when its agent finishes (spell dev agents done): the list is only what is running

Who updates it

spell dev agents, not spell dev agent (2026-10-07, Q12).

Only the new spell dev agents command, never Claude by hand (Q6): several helpers may write at once, so every write is locked.

  • add <name> "<task>": when an agent starts; adds the prefix, prints the full name
  • set <name> --status ...: blocked, or active again
  • done <name>: when its report arrives, or it is stopped
  • list [--json]: what /bg ? shows
  • wait / told: redirects from the plan doc (P3)

spell dev agents add, not spell dev agent add (2026-10-07, Q12).
