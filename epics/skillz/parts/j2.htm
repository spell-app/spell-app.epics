The docs tools’ shared helper file, packages/docs/tools/pages.js, now holds one --key value argument parser, parseArgs(): Owen would notice it in the diff of P1, as a change to a file the phase did not plan to touch.

  • why: the new command line, packages/docs/tools/agents.ts, was about to get the 4th copy of the same parser
    • link.ts had one
    • design.js had one
    • details.js had one
  • who uses it now:
    • packages/docs/tools/agents.ts (new)
    • packages/docs/tools/link.ts, its own copy removed
  • design.js and details.js keep their own copies for now: left alone, since they are not this epic’s files
  • a departure from the house style: parseArgs() carries JSDoc @returns / @type tags, against WWOD §6 “Docstring format”
    • why: pages.js is JavaScript, and TypeScript reads a JS file’s types only from those tags
    • without them, flags is typed {} in agents.ts, and every flag read is an error

Net effect:

  • pages.js exports parseArgs(); link.ts and agents.ts import it
  • two copies remain, in design.js and details.js, until someone moves them over
  • one JSDoc type-tag exception to WWOD §6, in a JS file, for TypeScript’s sake
