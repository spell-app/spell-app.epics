Build a new Claude skill, `/bg`: run a task in the background so the Claude panel stays free. Use up to 4 agents in all
for this build.

What Owen asked (2026-10-07, from session wwod-spell-ui): "Is there a way I can tell you to do something in the
background? e.g. `/bg <task description>` so you don't lock up the UI while it is happening?" Then: "`/bg 4 <task>`
= build it and use up to 4 total agents to get it done."

Shape (agreed in that session; check against `guides/dev/commands/commands.md` FIRST, as the root AGENTS.md says for
any new skill, and say if it belongs elsewhere):
- A skill, `.claude/skills/bg/SKILL.md` (judgement and dialog, no tool): no `spell` command, no yarn script.
- `/bg [n] <task>`: `n` (optional, default 1) = the most agents the task may use IN ALL, the one started included
(it may start its own helpers up to that total). Unlike the root default (up to 5, unasked), `n` is a hard cap.
- What it does:
1. starts ONE background agent (`Agent`, `run_in_background: true`) with the task VERBATIM, plus this session's
context: checkout / worktree, epic and plan doc if any, the agent budget `n`, and the house rules that matter
(WWOD, stage don't commit unless told, edit shared files at their real path, record judgement calls in the plan
doc, plain shell commands in a worktree)
2. replies ONE line, "started: <short name> (<n> agents)", and ENDS THE TURN, so the panel is free at once
3. when the agent's notification arrives: a short report (what changed, where to look, anything that needs Owen),
links per the root rules (side bar + browser; plan docs in the Review tab)
- `/bg list`: the background tasks running, with their names and age; `/bg stop <name>`: stop one (TaskStop).
- Several `/bg` at once are fine; two touching the same files: say so, and run the second after the first.
- Keep `guides/dev/commands/commands.json` true (a skills row), then `spell dev commands check`.
- Record it in the changelog only if it ships on its own (root AGENTS.md "Changelog").
