Telling Spell's code from its tags

How should the editor show the English-like code between a .spellml file's tags, so the file's shape reads first and the code steps back?

session repo-split, while polishing the Solitaire example 2026-11-09
repo-split -- right now, Solitaire and Solitario playable on spell.app, with their code open to read and edit. You asked for a way to tell the code from the tags, so the structure is clearer and the code steps back. I looked at how other tools do it, and at what our two editors can draw. How every .spellml file looks in the Spell editor and in VS Code. The files themselves don't change.
  • A .spellml file mixes two things: tags, which say what's in the file, and the code between them, which says what each thing does.
  • Today both are coloured just as strongly, so the eye gets no first place to land. Here's the same sample today:
<action "deal the cards" title="Deal">
for rank in card ranks
add a new card with rank = the rank to the deck
shuffle the deck
</action>
<property "color" one-of="red, black">
red if it is a diamond or it is a heart
black otherwise
</property>
  • Every picture below is that same sample. They use the editor's real colours where it's given them.
  • The changes here are all in how the editor draws a file. The files themselves don't change.
  • Two editors have to show it: the one in Spell's pages (called Monaco) and VS Code. Each option says where it works.
  • The studies won't decide this. Results on colouring code are mixed: one small study found it speeds people up, less so with experience; an eye-tracking study found no difference between colour and black and white; one on coloured scope backgrounds found no change in gaze or scores. So this is about taste, and about what you can scan.
  • The nearest thing already out there: org-mode draws lines above and below its code blocks, which is option A's idea. Alabaster, a colour theme, colours only a few things and leaves keywords plain, which is option B's. VS Code fades unused code, option C's. Visual Studio has a background for Razor code, option D's. Indent Rainbow draws in the indentation, option E's.
  • Two limits shape the list. Neither editor can draw a background from a colour rule alone, so bands need extra drawing code. VS Code can't change a line's font or size; the Spell editor can.
  • Sources: org-mode, Alabaster, VS Code's theme colours, Razor's background, Indent Rainbow, Sarkar 2015, Beelders & du Plessis, ICER 2023.

In a .spellml file, how should the tags and the code differ, so the file's shape reads first? Pick the look you'd like to live with.

Each opening tag gets a faint band and a bold name; closing tags go quiet; the code is one calm grey. Structure is the only loud thing in the file.

<action "deal the cards" title="Deal">
for rank in card ranks
add a new card with rank = the rank to the deck
shuffle the deck
</action>
<property "color" one-of="red, black">
red if it is a diamond or it is a heart
black otherwise
</property>
  • Works in both editors.
  • Costs: a little drawing code in each editor; the code loses its colours, so a mistyped word is harder to spot by colour.
  • The grey stays dark enough to read comfortably (4.5 to 1 contrast, the usual floor).

No bands: tags keep their colours, and the code goes one calm grey. The smallest change.
