Nothing is built yet. This page shows the end, with all of it done. The plan runs in four stretches:

  • Phases 1-6, inside today's one repo: cut every import that points the wrong way (util trimmed, Spell UI's plugins, spell-solid renamed spell-element, the server split into a library and a page-server package, the pack build moved into Spell UI's tools, package names and a shared toolchain package).   • Phases 7-8, the cutover: the new top repo, spell, at ~/www/spell; then spell-app is cut into the eight child repos, each with its history. spell-epic, the content repo and your projects move under ~/www/spell.
  • Phase 9, the tooling: worktrees, merging main, /isolate done, the VS Code window, the extension and CI learn about several repos.
  • Phase 10, the doc review: every guide, rule and page brought in line with the new shape.

Words this page uses:

  • Repo: a git repository of its own: its own history, branches, pull requests and releases.
  • Top repo: spell, at ~/www/spell. It holds the others on disk and the ONE install for all of them, and nothing else: no package, no code anyone imports.
  • Child repo: a repo cloned INSIDE ~/www/spell (~/www/spell/spell-ui/ ...). It's still its own git repo; spell just holds it on disk.
  • Flat repo: a child repo that is ONE package, right at its root: its package.json is the package's (spell-ui, spell-brand, spell-element, and spell-epic as today). The other four (spell-util, spell-server, spell-lang, spell-app) hold several packages, a folder each.
  • Git-ignored: listed in spell's .gitignore, so spell's git never sees the child repo's files. git status at ~/www/spell shows only the glue; each child repo has its own git status.
  • Worktree: a second checkout of a repo on another branch, in its own folder. An epic gets one: a worktree of spell, with a worktree of each child repo inside it.
  • Lower and higher: a lower repo is one others use (spell-util, spell-element); a higher one uses others (spell-app). The rule: arrows only point down.

In the spell-app child repo: ~/www/spell/spell-app/app/, with its tests at ~/www/spell/spell-app/tests/app/. Beside it in spell-app: spaces, lsp, cli, vscode and the new page-server, the editor and its servers. Every other package leaves spell-app for a repo of its own; table 2.4 has every one.

Answered (your comment here): no more node scripts/.... It's yarn install, then yarn clone: the top repo's first install has no child repos to link, so it's quick, and after it yarn can run the clone command.

  • Set up once: clone spell to ~/www/spell, yarn install, yarn clone.
    • yarn clone reads repos.json5, clones every child repo that isn't there yet, then runs yarn install again: one install for all of them.
    • The first yarn install works with no child repos (no workspaces yet); phase 7 checks that before anything else.
    • The content repo and your projects aren't cloned: they're yours, local only. Someone new starts without them.
  • Checks: yarn review (or yarn ts, yarn test) at ~/www/spell covers every package of every repo, since they're one install. One repo's alone: its own scripts, from its folder.
  • A change across two repos is two commits, one in each repo, then two pull requests. No publish, no version bump: spell-app uses spell-ui's source straight from ~/www/spell/spell-ui/.
  • Day to day: yarn pull pulls every child repo; yarn status shows each one's git status. git status at ~/www/spell shows only the glue.
