Each repo publishes one package, named after the repo and with no @ scope in front: the packages that used to be separate become sub-paths of it. Owen would notice it in every import line: spell-kit/element where it said @spell-app/spell-element.

  • Owen, 2026-10-20: "What if we went with @spell-kit as the root, rather than @spell-app/kit?"
  • Then: "On the import paths, I'd prefer @spell-kit/element, @spell-epic, @spell-lang/spell etc but I'm not sure if that's bad juju to use the @ that way. $/spell/element, $/spell-lang/spell etc would work for me too if we can't use the @ that way."
  • He picked "Unscoped: spell-kit/element" once he'd heard why the @ forms don't work (the aside).
  • And: "I've opened up negotiations to try to take over the spell npm domain -- cross your fingers that I get it."

The six names, one per repo:

  • @spell-kit/element: on npm, @scope/name is always a package of its own. So @spell-kit/element, @spell-kit/util ... would be five packages again, the opposite of the one-package decision (Q35).
  • @spell-epic alone: a scope with no name after it isn't a valid npm package name.
  • $/spell-lang/spell: $/ names are only our own TypeScript paths. They can't be published, so a repo installed from npm couldn't be imported that way.
