Jarvis moves to your work GitLab: its two projects in a work epic repo (epics), beside a small app repo (jarvis-spell) that runs Spell and the epics over it. You check both out on the work computer and work there; the personal copies are unlinked.

Six steps, in this order. Two things on this machine block steps 1-4 until they're fixed:

  • the work GitLab only answers over the work VPN: without it, gitlab.psiquantum.com doesn't resolve
  • GitLab's command line tool, glab, isn't installed; plain git over ssh is enough to clone and push, as your older work repos do
  1. Clone both repos side by side.
    • into your work folder, ~/www/psiquantum/, as epics and jarvis-spell
    • over ssh (git@gitlab.psiquantum.com:software/quantum-os/...), with the VPN on
  2. Make the epics repo an epic repo and a Spell space.
    • the epic repo's folders, as epic init writes them
    • your space, spaces/@psiquantum/owen@/, with a __me.json5 saying who you are there
    • in it, plain copies of jarvis-new and jarvis-current: the files, not links, and none of the private repo's git history
    • NOT jarvis-new-t35: it came from a test epic, so it isn't copied
    • a short README saying the repo is private, and what's in it
    • then commit and push
  3. Make jarvis-spell a minimal app that runs Spell.
    • a package.json depending on spell@next (0.8.9 today), plus the optional packages the editor and page server need: npm's spell installs only what the spell and epic commands need
    • its epic settings, .epic/config.json5: the epic repo is ../epics, pulled and pushed to its GitLab address every turn, on branch main
    • a start script that runs the page server over ../epics/spaces
    • a README with the work computer's setup: Node 24.11 or later, VS Code, Claude Code, glab auth login for the work GitLab, clone both side by side, yarn install, install the epic plugin and the VS Code extension, yarn start
    • then commit and push
  4. Check it from a fresh clone of both, on this machine.
    • the editor opens both jarvis projects, and an edit saves into the epics repo
    • epic list sees the work epic repo
    • no requests that 404
    • the known risk: nobody has run the editor and the page server from an npm install outside the kit yet; what's missing gets fixed in the kit, on this branch
    • a fix that needs a new spell@next waits for your yes before it's published
  5. Clean up your personal space, after the push.
    • delete the three links in ~/www/spell.spaces/@spell/owen@/: jarvis-new, jarvis-current, jarvis-new-t35
    • the links only: jarvis-new-t35 points at the same folder as jarvis-new, so deleting what it points at would delete jarvis-new itself
    • the private ~/www/jarvis repo is left exactly as it is
  6. A manual test for you, on the work computer (an #M item): clone both, install, start, open jarvis-new, with every command spelled out.
