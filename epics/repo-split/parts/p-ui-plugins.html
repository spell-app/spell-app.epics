Spell UI commits two bundles built from the parser and the spell language, so it can't build or run without them.
  • Spell UI gets a plugin slot, for code languages and for the markdown engine, and imports nothing from the parser or the language.
  • spell-parser ships the markdown plugin, spell-app the spell-colouring one, each registered by whatever page loads it.
  • With no plugin, code shows uncoloured and markdown as plain text.
  • Spell UI builds and runs with no parser and no spell language beside it.
  • A page that wants markdown or spell colouring loads the plugin, and Spell UI uses it (Owen's comment on the plan, then his pick).
  • A page without the plugins still works: code is shown plain, markdown as plain text.
  • The two committed bundles leave Spell UI, and the merge tooling's list of generated files follows.
  • packages/ui/src/languages/, packages/ui/components/ui-markdown/
  • a new plugin registry in Spell UI's core
  • packages/markdown/src/browser.ts, packages/spell/src/highlight/browser.ts
  • the app's and spell-epic's page loaders
  • .epic/generators.json5, .gitattributes
  • Spell UI's docs site with no plugins shows plain code and plain markdown; with both, coloured code and drawn markdown (headless check-spell.js).
