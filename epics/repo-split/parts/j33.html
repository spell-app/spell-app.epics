The rule (vite.lint.imports.ts at the root, plugin spell) fails a ../ module path that lands in another package: packages/<a> or tests/<a> into packages/<b> or tests/<b>, a package and its own tests counting as one. It reads import, export-from, import(), import types, require(), vi.mock() and friends, and import.meta.glob(). Choices:

  • Its own plugin file, not vite.lint.patterns.ts: that plugin is Spell UI's component patterns (spell-ui/*), on in component folders only. oxlint has no built-in that fits (no import/no-relative-packages).
  • In lintBase, which both rootLint() and every packageLint() spread, rather than in rootLint()'s overrides: the root AGENTS.md's overrides advice is for a rule some packages get; this one holds everywhere.
  • Module paths only: a file path read or spawned (resolve(import.meta.dirname, ...)) has no alias to switch to.
  • Vite loads a config file with no alias table, so $/server fails there: configs and what they load reach another package by its npm name. spaces' environment.ts takes @spell-app/server/src/checkout.ts; the app's and the brand's configs @spell-app/ui/vite.config.ts and @spell-app/spaces/src/server/node/environment.ts; their setupFiles @spell-app/ui/test/setup.ts. Spell UI's package.json exports gained those two SOURCE files. A side effect: Vite now treats them as dependencies, so the brand's or the app's dev server no longer restarts by itself when ui's vite.config.ts changes.

Found and fixed: spaces' climb into server/src/checkout.ts; the app's and the brand's configs into ui and spaces; the pack template's vitest config. No cli import climbed into ui. Tests: tests/ui/tools/LintImports.test.ts, 21 cases. WWOD §4 says it.
