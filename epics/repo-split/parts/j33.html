The rule fails a ../ module path that lands in another package, a package and its own tests counting as one.

  • Where: vite.lint.imports.ts at the root, plugin spell
  • What fails: <a> into <b>, each a package's folder or its tests'
  • What it reads: import, export-from, import(), import types, and calls like require()

Choices:

  • Its own plugin file, not vite.lint.patterns.ts. That plugin is Spell UI's component patterns (spell-ui/*), on in component folders only. oxlint has no built-in that fits (no import/no-relative-packages).
  • In lintBase, which every config spreads, rather than in rootLint()'s overrides.
    • Every config: rootLint() and every packageLint().
    • The root AGENTS.md's overrides advice is for a rule some packages get; this one holds everywhere.
  • Module paths only: a file path read or spawned (resolve(import.meta.dirname, ...)) has no alias to switch to.
  • Vite loads a config file with no alias table, so $/server fails there: configs and what they load reach another package by its npm name.
    • spaces' environment.ts takes @spell-app/server/src/checkout.ts.
    • The app's and the brand's configs take Spell UI's Vite config and spaces' environment (by npm name).
    • Their setupFiles take @spell-app/ui/test/setup.ts.
    • Spell UI's package.json exports gained those two SOURCE files.
    • A side effect: Vite now treats them as dependencies. So the brand's or the app's dev server no longer restarts by itself when ui's vite.config.ts changes.

Found and fixed:

  • spaces' climb into checkout.ts
  • the app's and the brand's configs into ui and spaces
  • the pack template's vitest config
  • No cli import climbed into ui.

Tests: LintImports.test.ts, 21 cases. WWOD §4 says it.
