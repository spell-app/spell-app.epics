Some strings only NAME a module at run time: a page's SpellUI.packModules keys, PACK_MODULES, the app's SHARED_SPECIFIERS, SHARED_FAMILIES, and the brand design build's external names. spell-epic's bundles read these keys too, so they stay $/ui/core and so on. Source now imports @spell-app/ui/core, and packModuleKey() maps that back to the key (a family's @spell-app/ui/ui-code to $/ui/components/ui-code). The pack build, the app's sharedSolid() and the brand's vite.design.config.ts (output.paths) all use it.

It lives in a new file of its own with no imports, packages/ui/tools/packModules.ts, beside PACK_MODULES, which moved there from ComponentPack.ts. The app's and brand's Vite configs import it, and pulling in ComponentPack.ts would have dragged DOM types into their config builds. Result: the brand's and the epics' packs are byte for byte the same (199,662 bytes).

The run-time keys still keep their $/ names; the mapping moved and learned the new names.

  • packModuleKey() and PACK_MODULES are the kit's now, spell-kit/element/tools/packModules (J89).
  • It maps spell-kit/element and spell-ui/... imports to the old keys (J72, J102).
