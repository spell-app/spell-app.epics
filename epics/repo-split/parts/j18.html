The split, file by file:

  • Stays in packages/server/src/page/, made generic: PageServer, PageEditor, prune.ts, the CLI (cli.ts, spell dev server), the settings reader (settings.ts, now also componentSets() and engineRoutes()), the types (RouteModule ...).
  • Moves to the new packages/page-server ($/page-server, PS): BundleBuild and BUNDLE_WAIT_MS, the shared pages' bridges (movedFolderPath(), MOVED_FOLDERS, MOVED_OUT), the offline highlight.js swap (localHighlight()). All of it runs as ONE route module, pageServerRoutes.ts, listed first in the settings' routes.
  • Moves to settings (the root package.json's "pageServer"): componentSets and engineRoutes, as Q3 asked.

Why the class and its CLI stay: spell-epic uses them. Its route-module tests build a PageServer, airplane.ts calls PageServer.ensure(), and pages.js / EpicTools start packages/server/src/page/cli.ts by path. spell-epic may never import spell-app's page-server, and none of those name spell-app once the lists are settings. A route module needed no new hook: RouteContext already hands out the router, web.files.html and overlays, and onStop.
