The split, file by file:

  • Stays in the server's page folder, made generic:
    • PageServer, PageEditor
    • prune.ts
    • the CLI, spell dev server (cli.ts)
    • the settings reader (settings.ts), which now also reads the component sets and the engine routes (componentSets() ...)
    • the types (RouteModule ...)
  • Moves to the new page-server package, imported as $/page-server:
    • BundleBuild and BUNDLE_WAIT_MS
    • the shared pages' bridges: movedFolderPath() and its lists
    • the offline highlight.js swap (localHighlight())
    • All of it runs as ONE route module, pageServerRoutes.ts, listed first in the settings' routes.
  • Moves to settings, as Q3 asked: componentSets and engineRoutes. The settings are the root package.json's "pageServer".

Why the class and its CLI stay: spell-epic uses them.

  • Its route-module tests build a PageServer.
  • airplane.ts calls PageServer.ensure().
  • pages.js and EpicTools start the server's CLI by path, cli.ts.
  • spell-epic may never import spell-app's page-server, and none of those name spell-app once the lists are settings.

A route module needed no new hook: its context (RouteContext) already hands out what it needs. That's the router, the HTML overlays (overlays), and onStop.

The split itself holds, generic server and spell-app's route module on it, but both live elsewhere now.

  • The generic page server is the kit's server folder, imported as spell-kit/server/page (it was spell-server's repo in P8).
  • page-server is a folder of the one spell-app package (spell-app/page-server).
  • spell-epic now carries its own copy of the highlight.js addresses, so it no longer needs this package for them.
