The "meta repo" is the folder that holds every repo and installs them together, so they work as one while you develop (Q4). Owen's comments on the plan made spell-app itself that folder, rather than a new parent folder above it.

  • The child repos (spell-server, spell-element, spell-parser, spell-ui, spell-epic) are cloned INSIDE spell-app.
  • spell-app's .gitignore leaves them out, so spell-app's history never holds their files.
  • util and the shared toolchain are top-level folders of spell-app, beside packages/, not inside it.
  • So there is no spell-util repo: this replaces Q7's pick of B.

~/www/spell-app/spell-app.worktrees/<epic>/   an epic's worktree:  spell-app's, the children's inside it

A meta repo is NOT a monorepo again. What each one gives:

Today's monorepo spell-app as the meta repo
Git history one history for everything one history per repo: a fix to Spell UI is a commit in spell-ui alone
Install one yarn install still one yarn install, at spell-app's root, covering the child repos too
Using one repo alone not possible: you clone everything clone spell-ui by itself; it stands alone once util is on npm (the repo-loop caveat, C1)
Releasing everything together each repo on its own, to npm (Q4's later step)
  • six repos, not seven: util and the toolchain are folders of spell-app
  • the meta repo is spell-app's own root, so nothing new sits above it
