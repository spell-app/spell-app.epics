Spell UI's markdown element, <ui-markdown>, draws markdown with marked, a small outside library. spell has its own markdown engine, which the new <spell-markdown> uses (Q19). Once spell's markdown bundle is slimmed, should marked go, and every page use spell's engine?

  • Decided after the slimming, in P2: the numbers below are today's.
  • Both draw the same markdown: spell's engine has every feature marked's use here has.
  • spell's engine passes the GitHub markdown spec (670 of 670 cases, epic markdown's P5).
marked spell's markdown engine
Download, gzipped 15 KB 83 KB today; about 35 KB once slimmed
Time over the repo's 172 markdown files 58 ms 95 ms
Where it lives an npm package Spell UI depends on spell-lang (the parser and markdown packages)
  • The slimming: three known cuts, listed in . The HTML entity table through the browser, util's barrel (lodash and friends) left out, and the parser's syntax-tree file split out of its barrel.
  • The catch: most of Spell UI's docs pages use <ui-markdown> (85 of its 88 pages in the main checkout, counted 2026-10-20). With marked gone, Spell UI's own docs need spell-lang to draw, so yarn clone spell-ui would have to clone spell-lang too, or its docs show plain text.
  • <ui-markdown> stays on marked; spell's pages use <spell-markdown>.
  • Spell UI and its docs stand alone: yarn clone spell-ui stays four repos.
  • Two markdown engines in the family, one of them outside.
  • Why recommended: even slimmed, spell's engine is twice marked's size and slower, and Spell UI keeps no parser.
  • One markdown engine everywhere: spell's.
  • <ui-markdown> draws plain text unless <spell-markdown>'s engine is loaded.
  • Spell UI's docs need spell-lang: yarn clone spell-ui brings it too, or the docs pages switch to <spell-markdown>.
  • nothing changes for Spell UI's markdown: marked stays its dependency
  • spell's bundle is slimmed anyway, for the spell pages that load it
