The worktree hook's install timeout (installTimeout) stops only the shell the install runs in, not what that shell started.

  • What the shell started keeps running, and keeps the hook's error output open: so whatever ran the hook (Claude Code, or a test) waits until it ends anyway.
  • When it bites:
    • on Linux, every time: Ubuntu's sh (dash) runs even a lone command as a child (Ubuntu's own patch turns off the shortcut);
    • on your Mac, only for a command with more than one step (yarn install && ...): its sh hands a lone command like yarn install, the default, the whole process.
  • So it doesn't bite today. It made spell-epic's CI red: the hook's test timed a sleep 5 out after 1s, and waited the whole 5s (I65).
  • Not fixed in the hook: the test now runs exec sleep 5, so the sleep IS the shell. A real fix would stop the install's whole process group; the hook runs it with a blocking call that can only stop the one process.
