Not in I12's three options, found at the first run: tsx reads ONE tsconfig for every file it runs, so other repos' $/ imports failed.

  • spell-app's CLI, running spell-lang's and spell-server's source, failed on their own imports: Cannot find package '$'.
  • So did the page server, loading spell-epic's route modules.
  • Vite and Vitest are fine: they use the tsconfig nearest the importing file.
  • The fix: a node resolve hook (module.registerHooks(), in spell-util's aliases.ts).
    • It maps a $/ specifier through the alias table of the IMPORTING file's repo: the nearest tsconfig.base.json with paths.
    • Registered after tsx, it runs first.
  • Loaded by:
    • spell-app's spell.mjs, and its runner children (run, static, speed)
    • the language server
    • spell-server's background page server
    • spell-ui's spell-ui-pack
    • every tsx package script (tsx --import @spell-app/toolchain/aliases ...)
  • So @spell-app/toolchain is a runtime dependency of spell-server's server now (was dev).

The hook holds as decided; it is the kit's now, spell-kit/toolchain/aliases, not @spell-app/toolchain/aliases (Q35).
