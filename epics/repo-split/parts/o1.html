What goes where once the monorepo is split, and the order the work happens in. It follows your answers on the analysis page (Q1-Q5) and your comments on the plan (Q11). This part becomes the epic's guide in the last phase.

The repos, bottom to top

Six repos. spell-app is the top one, and it's also the meta repo: the folder the others are cloned into, so one install covers them all. 

spell-app      the meta repo:  util/, toolchain/, agents/, and core, py, spell, spaces, lsp, app, cli,
               vscode, brand, the page server's own layer
spell-epic     the epic engine and the docs tools (its own repo since epic-eject)
spell-ui       Spell UI, its site tools, and the pack build spell-epic borrows today
spell-parser   parser, markdown
spell-element  spell-solid, renamed
spell-server   the generic web server layer (~3,900 lines) and the assembler
  • Each package imports only packages in the repos below its own, so no package cycle (Q1).
  • util is not a repo: it's a top-level folder of spell-app, beside packages/, and so is the shared toolchain (Q11).
  • The catch: spell-parser, spell-element and spell-ui need util, which lives in the top repo. Inside the meta checkout that's invisible; a lower repo cloned on its own builds only once util is on npm (C1).
  • The house style and the three logs live in spell-app's own agents/ folder, which every child repo links (Q6, J1).

Spell UI's plugin slot

Spell UI imports nothing from the parser or the spell language. Pages that want markdown or coloured spell code load a plugin, and Spell UI uses it.

  • Spell UI has one slot for code languages and one for the markdown engine.
  • spell-parser ships the markdown plugin.
  • spell-app ships the spell-colouring plugin, since the spell language lives there.
  • With no plugin loaded, code shows uncoloured and markdown shows as plain text.
  • Built in UI Plugins (P2): it replaces the two bundles Spell UI commits today, built from the parser and the spell language.

The order of the work

  1. The seams, inside the monorepo (P1 to P6): cut every import that points the wrong way.
    • Each is an ordinary change with ordinary checks.
    • They merge into main before the cutover (Q12).
  2. The cutover, on main (P7, P8): spell-app becomes the meta repo, then each new repo is cut out of spell-app with its git history.
    • Other sessions' worktrees merge main first (C3).
  3. The tooling (P9): worktrees, merging main in, /isolate done, the VS Code extension and CI learn about several repos.
  4. The text pass and the guide (P10).

The meta repo

spell-app's own root holds every repo. Its package.json lists its own packages AND the child repos cloned inside it, so one yarn install links them all. 

~/www/spell-app/spell-app/        the spell-app repo, and the meta repo
  package.json  yarn.lock  .yarnrc.yml      the one install:  its own packages AND the child repos
  util/                           @spell-app/util:  generic + reactive helpers
  toolchain/                      @spell-app/toolchain:  lint config, decorators, base tsconfig, global types
  agents/                         WWOD and the three logs;  every child repo links agents/ here
  packages/                       core py spell spaces lsp app cli vscode brand page-server
  tests/
  spell-server/                   child repo, git-ignored:  server + assembler
  spell-element/                  child repo, git-ignored
  spell-parser/                   child repo, git-ignored:  parser + markdown
  spell-ui/                       child repo, git-ignored
  spell-epic/                     child repo, git-ignored (moved in from ~/www/spell-app/spell-epic)
~/www/spell-app/spell-app.epics/  the content repo, as today
~/www/spell-app/spell-app.worktrees/<epic>/   an epic's worktree:  spell-app's, the children's inside it
  • One lockfile: one Solid, one set of tool versions, nothing copied by hand.
  • It's not a monorepo again: each repo keeps its own history, and a fix to Spell UI is a commit in spell-ui alone (Q11).
  • An epic's worktree is a worktree of spell-app with a worktree of each child repo inside it, every one on the epic's branch; how that looks in VS Code is Q9, still open.
  • Every window's first folder stays spell-app's main root, so the Claude panel lists every session (Q10).
  • One repo names another's code by package name (@spell-app/ui); $/ stays inside a repo (Q8).
