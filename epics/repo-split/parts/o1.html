What goes where once the monorepo is split. This part becomes the epic's guide in the last phase. It follows your answers on the analysis page (Q1-Q5).

The repos, bottom to top

Every arrow points down, so each repo builds and tests with only the repos below it beside it.

spell-app      core, py, spell, spaces, lsp, app, cli, vscode, brand, the page server's own layer
spell-epic     the epic engine and the docs tools (its own repo since epic-eject)
spell-ui       ui, its site tools, and the pack build spell-epic borrows today
spell-parser   parser, markdown
spell-element  spell-solid, renamed
spell-server   the generic HTTP layer (~3,900 lines) and the assembler
spell-util     util's generic and reactive layers (and the few spell helpers the parser needs)
  • spell-ui may import spell-parser, for markdown (your note on Q1).
  • spell's highlighter is NOT imported by spell-ui: it's built from the spell language, which stays in spell-app. So spell-ui keeps a slot for it, and spell-app fills it.
  • Whether spell-util is its own repo, or a package inside spell-server's repo, is Q7.

The order of the work

  • First, inside the monorepo, on this branch: cut every arrow that points the wrong way. Each cut is a normal change with normal checks, and could merge into main on its own.
  • Then the cutover: a parent folder becomes the meta repo (Q4), and each new repo is cut out of spell-app with its git history.
  • Last, the tooling learns about several repos: worktrees, the page server's settings, the extension, CI.

The meta repo

~/www/spell-app/ already holds spell-app, spell-epic and the content folder side by side. It becomes the meta repo: a package.json whose workspaces are the repos, so one yarn install links them all. 

{
  "private": true,
  "workspaces": ["spell-util/packages/*", "spell-server/packages/*", "spell-element", "spell-parser/packages/*",
                 "spell-ui", "spell-epic", "spell-app/packages/*"]
}
  • One lockfile: one Solid, one set of tool versions, nothing copied by hand.
  • How a worktree fits in, when the repos are separate, is Q9.
  • How one repo names another's code ($/ui today) is Q8.
