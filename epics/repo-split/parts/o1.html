The kit, spell-kit

The repo at ~/www/spell is the kit: the bottom of every repo, and always there (Q31). It holds:

  • the code every repo stands on, under ONE src/: util, toolchain, server (with the assembler, Q43), element, element-tools, test-helpers and cli
  • all of it ONE npm package, spell-kit, with one version (Q35): every file imported by the package's name plus its path, spell-kit/server/page
  • the house style, WWOD, in its agents/ folder
  • the glue: the ONE install for every repo, the list of repos, and the commands over every repo (clone, pull, status, the checks)
  • It started as glue only, holding no package (Q15, P7). P9 merged spell-util, spell-server and spell-element into it, each with its history; P13 added the spell command's base.
  • The child repos are cloned inside it, git-ignored: each still its own git repo, with its own history.
  • The content repo and your projects live inside it too, as data folders, so one VS Code folder covers everything (J5).

Spell's code and markdown in Spell UI

Spell UI has no spell in it. It keeps its own code and markdown elements, and spell's elements subclass them (Q19).

  • <ui-code> stays on highlight.js, with its language registry, as before.
  • <ui-markdown> stays on marked: kept for now, and the slimming of spell's markdown bundle is a todo (Q21).
  • <spell-code>, in spell-app (Q24): loading it registers spell with Spell UI's code registry, so a spell block in any markdown is coloured.
  • <spell-markdown>, in spell-app too: spell's own markdown engine, plain and editable.
  • Docs pages get them from spell-app's page server, which adds them to the pages it serves; spell-epic imports nothing of spell-app (Q23).
  • No plugin system: that was the first plan for P2, replaced.

Setting up

Two yarn commands in the kit, and nothing else (Q17).

git clone <spell-kit's URL> ~/www/spell && cd ~/www/spell
yarn install            # the kit alone:  no child repos yet
yarn clone              # clones every child repo, then installs again:  one install for all
yarn clone spell-ui     # or just Spell UI and what it needs:  nothing but the kit, always there
yarn pull               # git pull in every child repo
yarn status             # each child repo's git status
  • The checks at ~/www/spell cover the kit, then every repo, lowest first; inside a repo, just its own.
  • A change across repos is a commit in each, merged lowest first (C5). No publish, no version bump while developing.
  • Once the packages are on npm (Q4's later step), a repo works with no kit checkout around it.

The order of the work

  1. The seams, inside the one repo (P1 to P6): cut every import that points the wrong way.
    • util stops reaching into spell, and takes JSON5 in.
    • Spell UI loses its spell bundles; <spell-code> and <spell-markdown> arrive.
    • spell-solid is renamed spell-element, and its tests stop needing Spell UI.
    • The server splits from its page layer (the site header stays with the server, C7).
    • The pack build moves into Spell UI's tools.
    • Imports across repos use package names, and the toolchain becomes a package.
    • Each is an ordinary change with ordinary checks, merged into main before the cutover (Q12).
  2. The cutover (P7, P8): the top repo spell, then spell-app cut into the child repos, each with its history; spell-epic, the content repo and your projects move in.
    • Every path moves once, so other sessions finish or park first (C3, C6).
  3. The kit (P9, P10): spell-util, spell-server and spell-element merge into the top repo, now spell-kit; the generic element tools and test helpers go with them.
  4. One package per repo (P11), named after the repo.
  5. The tooling (P12):
    • worktrees at ~/www/spell.worktrees
    • merging main, and /isolate done
    • the VS Code window, its folder 1 the kit
    • the extension, and CI
  6. The spell command's base moves to the kit's cli (P13).
  7. One import name (P14): one src/ per repo, every import by package name plus path, the assembler into the server.
  8. The text pass and the guide (P15).
