Chose to port the design tools to TypeScript, run by tsx as the brand's other scripts are:

  • design-bundle.ts and design-check.ts
  • design-paths.ts, for where both look: the one place they read process.env

Over keeping them plain JS, or putting them in a new tools/ folder:

  • spell-brand's tools are all TypeScript in its scripts folder
  • the port was cheap

Two files stay outside the type check:

  • The entry stays JS (design-bundle.entry.js): it imports a made-up module (spell-ui:icons) no type checker knows.
  • Claude Design's runtime went to dc-runtime.js in spell-brand's vendor folder, outside every lint, format and tsc path.

The bundle's default output didn't move: bundle.js in spell-ui's build folder; it never lived in spell-epic. These expect it there:

  • spell dev design build

  • spell dev design changed
  • yarn design:bundle / design:check in spell-brand
    • spell dev design bundle | check run them
  • the bundle is byte-identical to the old tool's
