  • App: what spell-app holds.

What every project command shares: the session

Every command runs inside one session object, CliSession, made for every command, even spell pony. It's where the app comes in.

  • It loads projects through the language server's disk workspace, SpellDiskWorkspace, which switches on spaces' disk reader the moment it's made.
  • Spaces does three jobs there:
    • reading a project's files: spell asks for web addresses, and spaces answers them from disk
    • addresses and groups: @spell/library/cards, owen@spell, a @local group for any other folder
    • where compiled output goes: a mirror of the project's path under spell-app's build/ folder
  • Each command's argument goes through resolveProject(), which needs spaces' groups for every address.
  • Proof the seam can move: spell-lang already reads a project folder by itself, for its own tests (parseSpellProject()). Its header says "spell never imports spaces".

The language server's brain is language code

  • The language service and the Type Explorer's builder (SpellLanguageService, ScopeExplorer) import only util, core's types, the parser, markdown and spell.
  • Only two files in lsp import spaces: the disk workspace, and the list of scope packs (which reads spaces' project groups).
  • So describe, explore, explain and format are language commands that borrow the app's package for code that isn't the app's.
