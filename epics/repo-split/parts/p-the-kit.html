Nine git repos, and four of them (spell-util, spell-server, spell-element and the top repo) are the one layer everything stands on, kept in step separately.
  • The top repo becomes spell-kit (Q31): util, toolchain, server, assembler and element move in as folders right at its root, with no packages/ folder (Q16), beside the house style.

Yes to one version and one place for everything the five share; no to literally one package. The recommendation (C below): the kit's own package.json holds the version and every shared setting, Yarn copies them into the five packages and fails a check when one drifts, and every import stays as it is.

What's there today:

  • Five packages, each with its own package.json: util, toolchain, server, assembler and spell-element.
  • Each says version 0.0.0, and each is private (none is published).
  • Each repeats the same ten scripts (review, ts, lint, format, test ...), and the same tools in its devDependencies.
  • Each has its own TypeScript settings, Vite config and Vitest config.
  • Spell UI, published later, needs two of them at run time: spell-element and util. So those two must be publishable too; server, assembler and toolchain are only its build tools.

const KIT = ["util", "toolchain", "server", "assembler", "element"]
const SHARED = ["version", "license", "engines", "type", "repository", "packageManager"]

module.exports = {
  async constraints({ Yarn }) {
    const kit = Yarn.workspace({ cwd: "." })
    for (const folder of KIT) {
      const pkg = Yarn.workspace({ cwd: folder })
      for (const field of SHARED) pkg.set(field, kit.manifest[field])
    }
  }
}
