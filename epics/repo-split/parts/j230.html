epic plugin install rewrites Claude Code's settings.json, its marketplace and plugin lists, the plugin cache, the skill links and the VS Code extension, for every project on the machine at once. Doing that from spell local on, and undoing it on off, is too much for a per-project switch.

Instead, spell local on and spell local status say which copy the plugin runs, from Claude Code's installed_plugins.json, which they only read. When it isn't the checkout, they print epic plugin install --kit <checkout>, then /reload-plugins. When the plugin runs a checkout and the project runs none, off and status print yarn spell epic plugin install to go back. That one is untested: it links Claude Code's cache into the project's node_modules, the same as the existing npx spell@next epic init does.
