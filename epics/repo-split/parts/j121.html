Two things in spell-app run spell as a child process: the page server's bundle build (BundleBuild, now spell bundle --stale) and its project build (ProjectBuild, spell compile ...). Both ran <spell-app>/cli/bin/spell.mjs.

  • Now they run the kit's cli/bin/spell.mjs, found as the checkout's own install resolves spell-kit (so a worktree runs its own kit, never the one on the PATH).
  • The two files each keep a small copy of that lookup (kitSpell()): the page server's folder may not import spaces.
  • spell-app's generators list and its people-library test say ../cli/bin/spell.mjs / resolve the kit by package the same way.
