Two things in spell-app run spell as a child process:

  • the page server's bundle build (BundleBuild), now spell bundle --stale
  • its project build (ProjectBuild), spell compile ...

Both ran spell-app's own spell.mjs.

  • Now they run the kit's spell.mjs, found as the checkout's own install resolves spell-kit. So a worktree runs its own kit, never the one on the PATH.
  • The two files each keep a small copy of that lookup (kitSpell()): the page server's folder may not import spaces.
  • spell-app's generators list and its people-library test say the kit's spell.mjs / resolve the kit by package the same way.
