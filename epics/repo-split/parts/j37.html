A sibling rule in the toolchain's lint.imports.ts. It's on everywhere, through lintBase, and it fails a $/ module path (import, export-from, import(), import types, vi.mock(), declare module ...) that names a package of another future repo. The list of repos is REPO_OF, beside the rule. Strings that only name a module aren't checked. P3's rule now uses the same visitor (it gains declare module). A lint rule rather than a script: the editor flags a new crossing as it's typed. The codemod's own rescan, a scratch script that isn't committed, also finds 0 crossings.
