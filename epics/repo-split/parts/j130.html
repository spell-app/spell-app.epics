The kit's new cli/ is the first of its folders to import another one whose files use the kit's own $/ names. E.g. spell-kit/server, spell-kit/assembler.

Building its declarations failed:

  • TypeScript reads an import of the package's own name back to the SOURCE, when its declaration sits in the output folder.
  • So cli's build got the server's source AND its declarations, and refused to write over them (TS5055).
  • Fixed in the toolchain's declarations build (Declarations.selfPaths()). In a package of several folders, every other folder's entry (spell-kit/server ...) is pointed straight at its declarations.
  • Nothing else changes: the other folders built the same before and after.
