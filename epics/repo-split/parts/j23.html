The CLI's packBuild.ts logic moved into a class, ComponentPack:

  • ComponentPack.read(folder)
  • then build()
  • check()
  • hash()
  • sources()
  • Run by path from any repo: spell-ui-pack.mjs. It's the spell-ui-pack bin of @spell-app/ui.
  • A pack is found by its FOLDER, not by name: its package.json's spellPack.
    • Finding packages/<name> is spell-app's layout, so it stays in the CLI's thin packBuild.ts.
    • With it: packNames() and the CliErrors.
  • The CLI calls it in-process, so spell dev pack build | check print exactly as before.
  • Errors are ComponentPackError. It sits beside IconPackError in the tools' types file, tools.types.ts.

Net effect: spell-epic and the brand build their packs with Spell UI's tool, no spell-app CLI.
