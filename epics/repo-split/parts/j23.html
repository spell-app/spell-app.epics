The CLI's packBuild.ts logic moved into packages/ui/tools/ComponentPack.ts, a class: ComponentPack.read(folder), then build(), check(), hash(), sources().

  • Run by path from any repo: packages/ui/bin/spell-ui-pack.mjs, the bin spell-ui-pack build | check [<folder>] of @spell-app/ui.
  • A pack is found by its FOLDER (its package.json's spellPack), not by name: finding packages/<name> is spell-app's layout, so it stays in the CLI's thin packBuild.ts, with packNames() and the CliErrors.
  • The CLI calls it in-process, so spell dev pack build | check print exactly as before.
  • Errors are ComponentPackError (in tools.types.ts, beside IconPackError).

Net effect: spell-epic and the brand build their packs with Spell UI's tool, no spell-app CLI.
