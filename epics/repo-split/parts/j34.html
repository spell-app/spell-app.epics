Every package's exports now points at source .ts files, so tsc, Vite, tsx and plain node all read the same files. Spell UI was the one with a build: its published entries (., /core, /forms, /api, a family's /ui-<name>, /styles, /icons/*) pointed at dist/. They now point at source too, and the built shape moved, unchanged, to publishConfig.exports (with main and types). I tried yarn pack: it writes publishConfig's version over the top-level one. yarn smoke's declaration check now reads publishConfig.

Why not a custom 'source' condition: every Vite config, tsc, tsx and spell-epic's esbuild would have to turn it on, and one that didn't would quietly read a stale dist/. Why not separate source subpaths: the barrel (@spell-app/ui) can't have two. The catch: npm publish ignores publishConfig.exports, so publish with yarn.
