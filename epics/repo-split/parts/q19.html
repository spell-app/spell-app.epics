Spell UI keeps its own code and markdown elements, as they are, and spell-lang adds two elements that subclass them for spell. There is no plugin system: Spell UI simply has no spell in it.

  • Owen, 2026-10-20 (the plan's round 3), replacing the plugin slot P2 first had.
  • Spell UI keeps <ui-code>, on highlight.js, with its language registry, UI.code.register(), as today.
  • Spell UI keeps <ui-markdown>, on marked.
  • Spell UI loses the spell highlighter bundle, the spell language's automatic registration, spell's markdown bundle, and the markdown engine switch.
  • spell-lang adds <spell-code>, a subclass of Spell UI's code element. Loading it registers spell in UI.code, so a spell block in any markdown is coloured too.
  • spell-lang adds <spell-markdown>, a subclass of Spell UI's markdown element, on spell's own engine, for plain and editable markdown.
  • Spell's own pages (the editor, the epic pages, the guides) use the two spell elements.
<script type="module" src="@spell-app/spell/spell-code.js"></script>   <!-- registers spell in UI.code -->

<ui-code language="spell">...</ui-code>        <!-- coloured once spell is registered -->
<spell-markdown editable>...</spell-markdown>  <!-- spell's engine, editable -->
