The toolchain's tsconfig.base.json now holds the settings every package's tsconfig.json repeated: module, moduleResolution, strict, noEmit and so on (12 of them). The root one held only paths.

  • A package now extends both, and keeps only what differs (target, lib, types, jsx, allowJs): ["@spell-app/toolchain/tsconfig.base.json", "../../tsconfig.base.json"].
  • Config tsconfigs (tsconfig.node.json) extend the toolchain's alone: configs reach other packages by npm name. That turned on noUnusedLocals there, which found one unused import.
  • spell's node config stays as it was: a composite project can't take noEmit.
  • vscode is its own yarn project and is untouched.

The global types became one file, index.d.ts, since lint forbids triple-slash path references.

  • A package that wants them names them in its types: "@spell-app/toolchain/types".
  • That's the same 10 packages that included ../../types.
  • spell's typecheck of compiled projects takes them the same way, with node_modules as a type root.

The 12 shared settings still live in the toolchain's base, now spell-kit/toolchain/tsconfig.base.json. A tsconfig no longer extends the pair: each repo's alias table extends the toolchain's base, and its folders extend only that table (J46).
