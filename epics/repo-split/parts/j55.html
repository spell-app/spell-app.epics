The toolchain's spell-types builds a package's declarations, with the aliases rewritten:

  • It's in spell-util: declarations.ts and its bin, spell-types.ts.
  • It runs tsc on a package's own tsconfig.json, incrementally, emitting declarations (and maps) into <package>/dist-types/.
  • Then it rewrites every $/ specifier in them to a relative path.
  • tsc never rewrites path aliases in .d.ts files, so without the rewrite a repo above would meet $/spell-element/... again.
  • A package's repo-mates come in through THEIR declarations: the alias table is re-pointed in the generated tsconfig.
    • So a package's output holds only its own files.
    • A repo builds its packages in dependency order (yarn workspaces foreach --topological-dev).
  • Each TS exports entry is { "types": "./dist-types/...d.ts", "default": "./src/...ts" }.
    • tsc takes the types, and Vite, Vitest, tsx and node the source, as before.
    • Not built: TypeScript falls back to the source.
  • It IS the type check: a package's yarn ts runs it in place of a bare tsc.
  • Not built: the toolchain (no aliases inside, read as source) and spell-app's packages (nothing above reads them).
  • Cost: the top yarn ts from nothing (11 dist-types deleted) 15s, up to date 14s; spell-ui's own 2s.

Declarations are still built into dist-types/ with the $/ names rewritten, but per repo now.

  • Each repo is one package with ONE dist-types/; its folders are built in the order its "spellTypes" lists, each on its own tsconfig (J79).
  • So the kit's five are no longer built package by package with foreach --topological-dev.
