The toolchain's spell-types (spell-util toolchain/src/declarations.ts, bin/spell-types.ts) runs tsc on a package's own tsconfig.json, emitting declarations (and maps) into <package>/dist-types/, incrementally, then rewrites every $/ specifier in them to a relative path. tsc never rewrites path aliases in .d.ts files, so without the rewrite a repo above would meet $/spell-element/... again.

  • A package's repo-mates come in through THEIR declarations (the alias table re-pointed in the generated tsconfig), so a package's output holds only its own files; a repo builds its packages in dependency order (yarn workspaces foreach --topological-dev).
  • Each TS exports entry is { "types": "./dist-types/...d.ts", "default": "./src/...ts" }: tsc takes types, Vite, Vitest, tsx and node the source, as before. Not built: TypeScript falls back to the source.
  • It IS the type check: a package's yarn ts runs spell-types in place of a bare tsc.
  • Not built: the toolchain (no aliases inside, read as source) and spell-app's packages (nothing above reads them).
  • Cost: the top yarn ts from nothing (11 dist-types deleted) 15s, up to date 14s; spell-ui's own 2s.
