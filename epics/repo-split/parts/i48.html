spell-lang's cli/ holds the language commands' list and their flags' types.

  • The commands themselves still run spell-app's code, through spell-app's language hook.
  • That code: its CliSession, its project lookup (resolveProject()), the Ink screens.

To move them down, spell-lang needs, as M1 found:

  • a loader that reads a project folder by itself (spell-lang's tests already do: parseSpellProject()), and hooks for what only the app knows: project addresses and groups, the "which project?" prompt, the build folder
  • the language service and the Type Explorer's builder, from spell-app's lsp (SpellLanguageService ...)
  • the status screens (Ink, React for terminals), or plain output in their place
  • app steps as hooks:
    • the editor pages after compile and lint
    • opening a UI project in a browser for run

Easiest first: parse, explain and speedtest. They use the parser only, but for their status screen and --in.
