The page server runs from spell-app: its settings (the route modules, the folders it serves and watches, the component sets, the site's tabs) are a block in spell-app's package.json that names spell-epic, spell-ui and spell-brand. So spell-app reaches sideways into spell-epic, the server needs spell-app installed, and it only works started with spell-app as its root.

  • Each repo declares its own part of the page server in its package.json, as it does its spell commands: spell-epic its route modules, assets, pack, templates and docs set; spell-ui its set and bundles; spell-brand its set and asset paths; spell-app the spaces routes, App UI and the script that colours spell.
  • The kit's settings reader merges the parts of every installed repo, each repo's paths from its own folder.
  • spell-app's page-server code (the bundle build at start, the local highlight.js) moves into the kit's server; the 'moved' bridge goes.
  • The site's tabs describe the content repo: they go in the kit (or the content repo).
  • The server runs from the kit's root: the --root spell-app workaround (I62), epic server ensure and the VS Code extension's settings follow.
  • The page server runs with any set of repos installed: the kit, spell-ui and spell-epic are enough for the epic pages.
  • spell-app no longer names spell-epic.
  • spell server behaves the same from any folder.

  • spell-app's src/page-server/ (moves), its tests
  • spell-epic's server ensure, the VS Code extension's settings

  • spell server start from the kit's root serves every page; with spell-app not installed (a yarn clone spell-epic checkout), the epic pages still work
