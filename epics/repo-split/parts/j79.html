Chose one declarations folder at the kit's root, each folder (util, server, assembler, element) built as its own TypeScript program into it, over one program for all five.

  • Why: one program would lose the browser-or-node check (element has no node types; assembler no DOM).
  • spell-types in the kit's root builds them all.
  • A child repo's spell-types --below finds the kit by its workspace: dependency, and builds them in that order.
  • The toolchain needs none: it's read as source.
  • util's index.d.ts ...; yarn kit:ts runs it, then the configs' and tests' tsc
