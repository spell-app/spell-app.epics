spell publish builds all five packages the same way (PackageBuild, in the kit's src/cli/publish/):

  • one .js per source file, at the same path under dist/, so every name the exports give still finds its file; not a bundle, which would copy shared code (two DOMElements)
  • esbuild strips types and lowers standard decorators (target: es2022, as the toolchain's decorator pre-pass does), names kept; Solid's JSX through Solid's own compiler (the one its Vite plugin runs); Ink's JSX in spell-app's cli/ as React's
  • imports rewritten so node runs them as written: own names and ./peer become relative .js paths; other packages' stay names (lodash/get gets its .js); x.css?inline, ?raw and .json become small modules; import.meta.glob() becomes the list it matched
  • declarations: the repo's existing spell-types output, copied in (the kit, spell-parser, Spell UI; spell-epic and spell-app have none)

Why not tsc's emit: it neither lowers our decorators nor compiles Solid's JSX. Why not a Vite build per package: Vite's library mode treats node code as browser code (asset URLs, env), and only Spell UI needs Vite's extras, which are a few lines here. Each repo says how it publishes in its own package.json, "spellPublish", so the kit names no child repo; spell-brand has none, so it never publishes. Not yet: source maps, and one shared copy of esbuild's decorator helpers (each decorated file has its own, about 2.6 kB).
