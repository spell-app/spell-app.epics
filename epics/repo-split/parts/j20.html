spell-epic reads spell-app's MAIN checkout through its link, so once P4 is on main its imports must still work:

  • The three old names are still exported, read from the settings of the checkout the server package is in.
    • the names:
      • COMPONENT_SETS
      • SITE_BUNDLE
      • SETS_BUNDLE
    • from $/server/page and page.types.ts
    settings.ts loads under plain node, since spell-epic's tools import page.types.ts by path.
  • A PageServer whose root's settings name no sets serves those sets. Why: spell-epic's commentsRoutes test serves /components/epics/ from a scratch checkout with no settings.
  • start({ bundles }) is kept and ignored, because spell-epic's AirplaneMode test passes it.
  • HIGHLIGHT_JS stays in $/server/page because spell-epic imports it. The swap itself moved to page-server's route module.
