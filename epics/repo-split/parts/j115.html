Owen picked: spell dev pack new is kept as spell pack create <name>, retargeted to the per-repo layout. What it now writes, and what it leaves alone:

  • It makes spell-<name>/ at the kit's root (the nearest kit from the current folder), a flat repo like spell-brand: a package.json named spell-<name> with "spellPack": { name, prefix } and the same scripts (pack:build, pack:check, ts, lint, format, test, review), its own alias table ($/<name>, $/<name>/components), tsconfig, Vite and Vitest configs, src/, components/, tests/, AGENTS.md, CLAUDE.md, README.md, .gitignore, .gitattributes and .epic/generators.json5 for its generated components/__pack/.
  • Its .yarnrc.yml is the kit's own, without yarnPath, as every child repo's is.
  • It wires nothing into the kit: the kit's spell-* workspaces take the new repo in at the next install, and the toolchain's lint already skips every components/__pack/. The old monorepo steps (root workspaces, root aliases, root Vitest, lint ignore) are gone.
  • It does NOT add the repo to repos.json5: it has no remote yet. Instead it prints the next steps: git init, add it to repos.json5 needing spell-ui, yarn install.
  • It still adds the new repo's yarn scripts to the commands page (the shared commands.json5), now as spell-<name> ts beside spell-brand ts, as before.
  • It refuses the kit's own repos' names (kit, lang, ui, app).
