Owen picked: spell dev pack new is kept as spell pack create <name>, retargeted to the per-repo layout. What it now writes, and what it leaves alone:

  • It makes spell-<name>/ at the kit's root (the nearest kit from the current folder), a flat repo like spell-brand, with:
    • a package.json named spell-<name>, with "spellPack": { name, prefix }
    • the same scripts: pack:build, pack:check, ts, lint, format, test, review
    • its own alias table:
      • $/<name>
      • $/<name>/components
    • tsconfig, Vite and Vitest configs
    • src/ and components/
    • tests/
    • AGENTS.md, CLAUDE.md, README.md
    • .gitignore and .gitattributes
    • generators.json5, for its generated components/__pack/
  • Its .yarnrc.yml is the kit's own, without yarnPath, as every child repo's is.
  • It wires nothing into the kit:
    • the kit's spell-* workspaces take the new repo in at the next install
    • the toolchain's lint already skips every components/__pack/
    • the old monorepo steps (root workspaces, root aliases, root Vitest, lint ignore) are gone
  • It does NOT add the repo to repos.json5: it has no remote yet. Instead it prints the next steps:
    1. git init
    2. add it to repos.json5, needing spell-ui
    3. yarn install
  • It still adds the new repo's yarn scripts to the commands page (the shared commands.json5), as before.
    • Now as spell-<name> ts, beside spell-brand ts.
  • It refuses the kit's own repos' names (kit, lang, ui, app).
