What it is: tools/one-repo/one-repo.ts does the scripted part of P20, each step its own commit, and spell rename branches carries an epic's child-repo branches across afterwards.

  • history: each child repo's main, cloned and rewritten into its folder by git filter-repo --to-subdirectory-filter, merged with --allow-unrelated-histories; its commit map (old SHA, new SHA) kept as tools/one-repo/commit-map-<folder>.txt, for epic-engine P49's 836 <epic-commit> links.
  • manifest: the folders' exports and dependencies folded into the kit's package.json; imports: spell rename imports over the result.
  • The same filter settings every run, with --preserve-commit-hashes: filter-repo otherwise shortens a SHA quoted in a message to the new one, as short as is unique among the objects THAT clone holds, so a clone with a branch's objects too could write a longer one, and every commit from there on would differ. Checked: a throwaway spell-ui branch of 2 commits came out on top of the merged history's own rewritten main commit (the same SHA), 2 commits of its own, no copies.
  • The carry-on renames the branch's imports BEFORE merging, then merges any file the merge stops on again against its base renamed too (mergeRenamed()): a line only the rename changed merges cleanly; a line the branch really changed keeps the branch's.
  • Replaying onto a newer main: the script's header (a fresh branch from main, the tools from this branch, the script, then the hand-made commits picked on top). Done twice in this build, the second onto the child repos' newer mains.
