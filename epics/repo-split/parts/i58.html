spell-epic's VS Code extension imports spell-kit/server for its own page server (WebServer, PidFile, mainServerUrl).

  • Since the assembler merged into the server (Q43), that barrel holds the Linker and formatHTML() too, so esbuild bundles linkedom, entities, htmlparser2 and css-select into out/extension.js: 758 KB in all.
  • formatHTML()'s import("vite-plus/fmt") pulled in oxfmt, whose optional prettier plugins esbuild can't find: the build failed. vite-plus/fmt is now external in vscode/build.mjs (only loaded on call, never by the extension).
  • It builds and type-checks; the extension just carries code it never runs. A fix is the kit's: a node-tooling entry apart from the server's barrel, or the extension importing leaf files that don't go through it.
