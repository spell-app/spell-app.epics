What it is: parser/, ui/, epic/ and app/ each keep a package.json, as a yarn workspace of the kit's install, but no longer a package anyone imports.

  • Kept in it: the folder's scripts (cd ui && yarn test still works: yarn runs a script only in a workspace, and links its bins from the workspace's own dependencies), its settings ("spell" commands and hooks, "pageServer", "spellPack", "spellTypes", "spellPublish", customElements), and its dependencies, each at the kit's version, plus spell itself (workspace:*) for spell-types and spell-pack.
  • Gone from it: its exports (the kit's package.json has them all now: ./ui/* to ./ui/src/* ...), its peer dependencies, its packageManager, and its copy of .yarnrc.yml.
  • The kit's package.json lists every folder's dependencies too: what spell publish packs as the ONE package's.
  • epic's keeps its exports: the spell-epic/... alias the plugin's hooks import, until epic-engine P49. A workspace named spell-epic is how a second name reaches the same files: the kit's own exports can only name spell/....
  • The kit finds them by its workspaces, lowest first (kitFolders(), spell/server/kitFolders), and names none in code.

Rejected: moving every script into the kit's package.json (about 140, with clashes, and every AGENTS.md's yarn x in a folder rewritten), and folder manifests under another name (yarn won't run a script outside a workspace).
