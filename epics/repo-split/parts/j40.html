Each package's package.json now lists the @spell-app/* packages it imports from other repos (workspace:*). Source imports go in dependencies, test, tool and config imports in devDependencies. Spell UI's are devDependencies: its build bundles util and spell-element, and their declarations ship inside it. The toolchain is a devDependency everywhere except the assembler, whose formatHTML() reads fmtConfig at run time. That one needs a yarn resolution in spell-epic (its T). Left out on purpose: spell's tests import spaces (C), and declaring it would make a dependency cycle.
