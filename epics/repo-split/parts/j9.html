Q23 says the page server adds the app's <spell-code> script. It adds /element/spell-language.js instead: the <spell-code> family's other half, which registers spell with the page's UI.code and defines no element.

  • Why: defining <spell-code> on a docs page means extending the PAGE's UICode, so the page's Spell UI must share its code family in SpellUI.packModules. spell-epic's docs bundle doesn't yet (listed for spell-epic), so spell-code.js would stop with an error on every epic page and guide.
  • spell-language.js needs only the page's core, which every docs bundle shares, and does nothing on a page with no Spell UI (no Solid or Spell UI loads for it).
  • The guides and epic pages write <ui-code language="spell">, which is exactly what it colours.
  • Once spell-epic shares the families, the setting can name spell-code.js (or both) and pages can use <spell-code> / <spell-markdown>.
