For the One Repo phase (P20): once every package is in one repo, how does TypeScript read the others?

  • Today it reads each other repo's BUILT declarations, which the toolchain's spell-types writes.
    • A stale one fails the type check until spell-types --below rebuilds it.
    • Each package's exports carry three conditions to make that work.
  • In one repo, TypeScript could read the source directly.
  • No stale-declaration failures, and no rebuild before yarn ts.
  • Cost: a check of the whole repo is one bigger program, so slower on a small change; each package's settings (its JSX, its decorators) must agree, or its files are checked under another's.
  • Only if it really drops the failures: tried first on one package.
  • Nothing changes; each package keeps its own settings.
  • The stale-declaration failures stay.
  • yarn ts no longer builds declarations first
  • each package's exports lose the types condition inside the repo (publishing keeps it)
  • if one package's settings won't fit, it keeps B
