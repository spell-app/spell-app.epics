<spell-code> and <spell-markdown> import UICode / UIMarkdown through a new shared file, spell-ui-shared.js (beside spell-solid-shared.js, written by vite.solid.config.ts).

  • The page's own families when the page has its own core (SpellUI.packModules must then name $/ui/components/ui-code and ui-markdown), else spell-ui.js's; a page with its own core but not the families gets a clear error.
  • The component sets' build shares them (SitePacks.ts, as a pack's define() starts), so App UI's pages extend the page's own.
  • spell.pack.js now lists all four app tags (its catalog is read from components/); its define() warns about a family that won't load and defines the rest, so <spell-app> keeps running on guides whose docs bundle doesn't share the families yet.
  • The families spell's engine draws with (ui-table ...) map to the same file as side effects: the page's Spell UI has them all.
