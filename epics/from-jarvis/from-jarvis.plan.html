In a built editor, an app's elements sometimes never get defined: Solitaire draws as empty space, and nothing is logged.

  • The paste's account matches the code here. loadRuntime() makes a copy of the runtime from its text, but points the copy's imports at the build's shared chunks, so every copy shares one core.
  • isViewClass() checks instanceof View, and each copy has its own View: the last copy loaded wins core.defineElement.
  • The two copies: the layout's (layoutRuntime()) and the Tests card's (editor.runTests()).
  • Where the code disagrees: the paste guessed the dev server shares core too. It doesn't: a plugin in the editor's Vite settings (runtimeCopyInDev()) follows a copy's imports through the core and runner folders, so dev copies have their own. Only the build is broken.

Phase: P13 · Runtime Copies Own Core. All Spell work.

A page can't read the Jarvis place, because its key (JARVIS_TOKEN) is only on the server, and nothing on the server answers for that place.

  • True here too: a web server place in a browser refuses when it needs a key (WebPlace), and only data folders and one Airtable base are served through PlaceServer today.
  • Where the code is ahead of the paste: Spell 0.8.9 was cut on 2026-11-09, and epic data's P49 landed on 2026-11-17 with two of the things the paste asks for.
    • Tokens that renew themselves: its token comes from "...", made with the secret "...", the paste's route C.
    • Dev and prod: a project's file lists each place's deployments (address, key name, read only), picked with SPELL_DEPLOYMENT. No re-running a converter to switch servers.
  • Still missing: serving a project's keyed places to its pages, and a check at startup that names a missing variable.

Phase: P14 · Keyed Places Served. Jarvis side: getting a token the Control System accepts (its issue I3), and saving the prod key.

The Jarvis Jobs page promises a deployments list it doesn't have. "Deployment" means two things in Jarvis, in two services.

  • Job deployments live in the Control System, which refuses the API-key tokens Spell can use today. Nothing here can change that: it's Jarvis-side.
  • System deployments are readable now, but two of their routes answer one record per instance, not a list.
  • Spell's own OpenAPI reader (PlaceSpec, spell place ingest --spec, also newer than 0.8.9) reads lists and things by id, and lists under a thing, but not one record under a thing. The Jarvis converter skips them too.

Phase: P16 · Per-Thing Records, if system deployments are wanted (Q5). Jarvis side: the Jobs page, and marking ingest-jarvis-api's P9 dropped.

The Netlist Viewer is plain HTML and TypeScript today; four gaps stop it being a Spell page.

  1. Picking or dropping a file and reading its text. Spell UI has a file input (<ui-input type="file">), so the gap is narrower than the paste says: no Spell words read the file it picks.
  2. Calling a TypeScript helper from Spell, and one copy of a project's classes.
  3. A project declaring an element that extends a <ui-*> one. The nearest thing today: compiled TypeScript hands the page its own element class (core.useElement()), but only for a Spell view.
  4. jarvis-spell runs a packed 0.8.9, which has neither the column view nor <ui-graph>.

Phases: P8, P9, P10 (one per gap), then P11 · Netlist Example And Pack. Jarvis side: the viewer's rewrite in the Netlists project, once Spell is packed again.

The netlists epic built a column mode for <ui-tree>, and asked for more: a breadcrumb, collapsing columns, sizing, a remembered path, a detail pane, outline helpers, windowing and a supported subclass.

  • Its branch, netlists, isn't on this machine: the tree phases are written as if it were merged (P1, Q1).
  • Where the code disagrees, and it matters: main ALREADY has a column view, <ui-tree appearance="columns">, from epic mockup's T37 (2026-11-15). It has Finder keys, column titles, and columns resized by dragging their edge, kept per level. The netlists branch's mode="columns" is a second one, built beside it.
  • Main also has a sticky path for the outline view (sticky-path), the start of a breadcrumb.

Phases: P2 to P7. All Spell work; <netlist-columns> itself is in the Jarvis repo.
