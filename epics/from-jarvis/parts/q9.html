This is for Calling TypeScript Helpers, the phase that lets Spell code call a helper file's functions, like the handoff's readNetlist(). You picked "listed in the project file, called by name", then asked how Spell knows the words to call each one by.

Existing code settles most of it: a function's words and its code name are already two fields, and an options object is already the with name = "x" shape. What's open is where each function's words come from. New words need your OK. 

A   in the helper's docstring, in Spell's own "to" line shape:
      /** Read `source` ... into a `Netlist`.
       * - spell:  read a netlist from (source) (with name)
       * - spell es:  leer una netlist de (fuente) (con nombre)
       */
    Spell:  set the netlist to read a netlist from the text with name = "ssx001"

B   in the project file, beside the helper's path:
      imports: [{ path: "/netlistReader.ts",
                  spell: { readNetlist: "read a netlist from (source) (with name)" } }]

C   made from the code name, no words written:
      readNetlist(source, options)       =>  read netlist (source) (with ...)
      otherEndOf(connection, port)       =>  other end of (connection) (port)   two inputs side by side
      no Spanish words

D   a "to" line with no body in a Spell file, naming the helper:
      to read a netlist from (source) (with name) -- netlistReader.ts
    (a new statement)
  • a helper function is callable from Spell once its docstring has a spell: line
  • the line is read by Spell's own to line rule, so its words, inputs and options work as for a Spell function
  • a spell es: line gives a Spanish project its words; a function with no line isn't callable, and the compile says which
  • the project file still lists the helper file, as you picked
  • The words live beside the code they call, in the shape a Spell author already writes.
  • A new docstring convention, but no new Spell statement.
  • Nothing in the helper changes; the words are far from the code, and drift when it's renamed.
  • No words to write; reads badly with two inputs, and gives a Spanish project nothing.
  • All in Spell; a new statement to design and translate.
