A reload loses where you were in the tree, and what you picked can only be shown somewhere else on the page.

  • A reload opens the tree where you left it
  • A detail pane at the end of the columns shows the picked item

The tree remembers its last path for the session, and opens it again when the page sets none; its last pane can be any view, which changes with what's picked, sizes to fit, and can stick to the side.

  1. path remembered: each pick stores the path for the session, keyed by the tree's id; a tree with no path set opens it again. A tree without an id remembers nothing, as main's widths do.
  2. Detail pane: a slot after the last column (slot="detail"), shown while something is picked; the tree sets the picked item on the slotted element (item property) and sends its usual ui-changed, so a Spell view or any element can draw it.
  3. The pane sizes to its content, and with sticky-detail stays in view while the columns scroll sideways.
  4. Docs: an example with a detail pane.
  5. Checked by: unit tests for the remembered path; a headless reload test; the pane checked at narrow and wide widths.
  6. Left out: a Spell view as the pane in a Spell page: that's P10's and P11's.
