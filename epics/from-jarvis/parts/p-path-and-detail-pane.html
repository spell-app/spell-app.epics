A reload loses where you were in the tree, and what you picked can only be shown somewhere else on the page.

  • A reload opens the tree where you left it
  • An optional detail pane at the end of the columns shows the picked item: drawn only when the page puts something in it, tight against the last column
  • You can drag the pane's edge to resize it, and the tree keeps its width across reloads

The tree remembers its last path, in its existing preferences store (coherence), and opens it again when the page sets none; its last pane can be any view, which changes with what's picked, sizes to fit, and can stick to the side.

  1. path remembered, in the tree's existing preferences store, not raw sessionStorage (coherence): UITree.columnWidthStore becomes one tree store, ui-tree, with keys widths:<id> and path:<id>; the old widths key is moved over once. It's kept where Column Sizing's choice puts widths.
  2. Each pick stores the path, keyed by the tree's id; a tree with no path set opens it again. A tree without an id remembers nothing, as main's widths do.
  3. Detail pane: a slot after the last column (slot="detail"), shown while something is picked; the tree sets the picked item on the slotted element (item property) and sends its usual ui-changed, so a Spell view, the JSON outline (Land JSON Viewer) or any element can draw it.
  4. The pane is optional:
    • it's drawn only when something is in the slot
    • a tree with nothing slotted there looks exactly as it does today, with no empty pane
  5. The pane sits tight against the last column:
    • no gap between them
    • it doesn't stretch to fill the rest of the box; the space left over stays after it
  6. The pane sizes to its content at first, and with sticky-detail stays in view while the columns scroll sideways.
  7. The pane is resizable by dragging its edge:
    • the same drag the columns use to resize (Column Sizing), not a second one
    • its width kept in the same tree store as the column widths, under the tree's id, so a reload keeps it; a tree without an id doesn't remember it
    • until it's dragged, it sizes to its content, as above
  8. Docs: an example with a detail pane, resized and reloaded.
  9. Checked by: unit tests for the remembered path, the moved widths key and the pane's kept width; a headless reload test; the pane checked at narrow and wide widths, with and without anything slotted.
  10. Left out: a Spell view as the pane in a Spell page: that's Subclass Elements In Spell's and Netlist Example And Pack's.
  • The column view remembers where a person left it: their picks (click, key, path line, filter match, Open/Close all) are kept as path:<id> in the same 'ui-tree' store as the widths, and opened again when the page sets no path (J53, J64). A path the page sets saves nothing. It's the browser's local storage, not sessionStorage as first asked, following the P5 pick (J51).
  • The detail pane, slot="detail": drawn only while something is slotted and picked, tight against the last column, sized to its content up to half the tree (J54). The tree hands it the picked item. Its edge drags with the columns' drag, a double-click fits it, and its width is kept (J52). sticky-detail pins it while the columns scroll; it has its own title cell and the columns' surface, opaque when stuck (J60, J65).
