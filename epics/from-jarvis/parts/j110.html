Only the editor fetches a project's files. VS Code's runner gets its program from the extension, and <spell-viewer> from a page. Each now says This program calls code from clipboard.ts, which this runner can't load yet. instead of failing on the import. Each needs only a loadNative handed to it, later.

Both runners hand the runner the same hook the editor's has (loadNative), so a program with a call native line runs there too. One way to get the javascript: esbuild on Spell's side (codeFileAsJavascript()), never in the page.

  • <spell-viewer>: it fetches each code file from the page server, /spaces/.../clipboard.ts?as=javascript, the route the editor uses. One function now builds that address for both, SpellUrls.codeFileUrl().
    • A src="..." viewer, which has no Spell server behind it, still says it can't load the code file.
  • VS Code's runner: it asks the extension for each code file (a loadNative message, as it asks for an imported project). The extension asks the language server (spell/codeFile), which reads the file (the open editor's text if it's open) and takes its types out with the same codeFileAsJavascript().
    • So the extension needs no page server and no esbuild of its own.
