The plan said the uploader holds a <ui-input type="file">. It holds an invisible native <input type="file"> instead, which nobody sees: its only job is opening the browser's file dialog.

  • <ui-input type="file"> can't open its dialog from script (its native input is in its own shadow root, and it has no showPicker()), and can't pick folders (webkitdirectory).
  • Everything people see is Spell UI: <ui-button>, <ui-input> (the input look), <ui-segment>, <ui-progress>, <ui-popup>, <ui-icon>.
  • Other way: give <ui-input> a showPicker() and a folder mode, then hold one of those.

Teach <ui-input type="file"> the two things it lacks, then have the uploader hold one, hidden, for every look.

  • <ui-input> gets showPicker() on its element, as a native input has: it opens its inner input's picker (a file's dialog, a date's calendar), so script can open it from a click elsewhere.
  • A new folder attribute (Spanish carpeta), the same word as the uploader's: a file input that picks whole folders, its files each with its path in the folder.
  • Its element also gets files, the files picked. Setting its value to empty forgets them, as a native input does, so the same file can be picked again.
  • It already has accept, multiple and ui-changed: the uploader passes its extensions as accept, and listens for ui-changed.
  • <ui-uploader> drops its native input for a hidden <ui-input type="file">, and every look's button opens it with showPicker().
