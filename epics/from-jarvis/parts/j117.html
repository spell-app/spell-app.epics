Found fixing I16. refresh() used to keep the tab stop's index: once the tree refreshed on every filter, a filter hiding rows above the tab stop would have moved it to another row.

  • Now it stays on its item while that item is still in the list; only when its item leaves does it fall back to the same index (or the last item), as before.
  • It's the shared runtime, so menus, tabs and listboxes get this too; they all refresh only after items change, where keeping the same item is what a person expects. Its tests and the tree's pass.
