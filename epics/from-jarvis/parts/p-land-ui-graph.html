Spell UI has no element for a graph of nodes and wires with nested parts: the handoff's <ui-graph> lives outside the kit.

  • <ui-graph> is a Spell UI tag, with its docs page in the components site
  • It shares the kit's text measuring with the diagrams, rather than its own copy
  • Unit tests for its layout and for opening a nested graph

<ui-graph> comes into Spell UI from the handoff, at its newest version: nodes with ports, wires between them, nested graphs opened in place, in a modal or by drilling in, with pan, zoom and fit. It's registered, documented and tested like every other tag.

  • <ui-diagram> already draws boxes and the links between them, as an SVG, laid out in columns (the NERD drawing).
  • One element for every boxes-and-lines picture; but ports, wires routed between them, nested graphs and pan / zoom are all new to it, and its NERD layout must stay rule for rule as it is.
  • Keep <ui-graph> as its own element, since its layout (layers left to right, ports on sides, nested graphs) is really different from the diagram's columns.
  • It measures text with TreeMeasure.widthOf(), as <ui-diagram> and <ui-tree-diagram> do, instead of its own canvas.
  • Each element's docstring says what the others are for, so nobody builds a fourth.

    • ui-graph.html and ui-graph.demo.ts: not copied as they are; they become the docs page and the examples (below)
  3. In the copied files: the docstrings that say "lives in the Netlists project for now" go; text is measured with TreeMeasure.widthOf() (coherence), its own canvas gone; imports checked against the kit's rules (spell/ui/... names, the family's barrel).
