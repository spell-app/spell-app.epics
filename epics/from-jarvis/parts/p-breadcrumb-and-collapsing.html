When the open path is deeper than the tree is wide, the first columns scroll out of view, and nothing says where you are.

  • You always see the whole path, and can click back to any column
  • Deep paths keep the last columns readable; the early ones are a strip with the picked row's name

A breadcrumb above the columns, each part a way back to its column, styled like the editor's sticky header; and the columns before the last few shrink to a narrow strip, widening on hover or focus.

  1. Breadcrumb: a part of the column view's own shadow root, above the columns, drawn from path: each part a button that picks that column's row and scrolls it into view.
  2. Reuse before writing: main's sticky-path already pins the path in the outline view, and Spell UI has <ui-breadcrumbs>. Draw the breadcrumb with the same parts and look as sticky-path (the editor's sticky header's style), so one attribute means "show the path" in both appearances.
  3. Collapsing: columns before the last N (a setting, default 2) get a collapsed state, a narrow strip showing the picked row's name or icon; hover, focus, or a breadcrumb click widens it again. A CSS width transition, none under reduced motion.
  4. Vocabulary: the new attribute and parts in UITree.en.ts, Spanish in UITree.es.ts; tokens for the strip's width.
  5. Docs: the tree's page gets a deep example.
  6. Checked by: unit tests for which columns collapse; a headless check of a 6-deep path at 600px and 1400px wide, light and dark.
  7. Left out: sizing (P3).
