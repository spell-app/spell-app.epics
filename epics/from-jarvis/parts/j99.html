The plan said each place would be served through PlaceServer, with RemotePlace in the page. Built instead: the page's RestPlace / GraphPlace stays as its lines make it, and only where it sends changes: to /api/places/projects/<project>/<place>. The page server (AuthenticatedPlaces) passes each request on to the place's own address with the secret, and scrubs the secret and that address from the answer.

  • Why: a web server's paths, paging, fields and searches are worked out from the program's own classes, which the page server doesn't have.
  • The same shape as DirectReads' read-through to a host: a pass-through that keeps nothing.
  • Airtable's base stays on its PlaceServer, one source of the same route module.
