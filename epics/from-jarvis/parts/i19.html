A project's declarations name the super-type UiTreeView, which another project doesn't have until one of its own lines names ui tree view.

As another project's declarations load, each super-type they name that is a Spell UI element's view is made in the importer's scope.

  • UiTreeView is read back to its element's words, tree, and found in the importer's packs, as its own ui tree view line would find it.
  • Its attributes are in the importer's language.
  • So a type below the imported one, a "port column" is a netlist column, is built on <ui-tree> and overrides its hooks.
  • Nothing new in the declarations file: each project makes its own, from its own packs.
