Found while building I12: in a markup column tree, right after filtering, calling row.focus() on a row did nothing, because it had no tabindex until the arrow keys moved onto it. The keys and clicks work; a page focusing a row by script doesn't. Maybe an existing gap in how the tree's roving focus picks up rows.

The tree gives its rows their tabindex only when rows are added or removed, or the focus moves. A row that comes on screen another way, in a column just opened or just filtered, has none, so focus() can't reach it.

  • The tree re-applies the tabindexes each time the rows on screen change: opened, closed or filtered.
  • The runtime's roving focus keeps the tab stop on the same row while it's still on screen, rather than the same position, so a filter doesn't quietly move it to another row.
  • A test that focuses a row by script in a column just opened, then just filtered.
