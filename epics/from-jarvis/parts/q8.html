This is for Asked For By Parameter, the phase that lets Spell read a list that needs a query parameter, like Jarvis's layer stacks (asked for by their system). Its plan is accepted; the coherence review found something it may not need to build.

What exists: RestPlace.paramsFor() already sends the fields a list is asked for by as the query, and takes the answer as the one for those values. The only gap is that "system" isn't a field of a layer stack.

  • AskedBy learns a new idea, a parameter of the list that isn't one of its fields.
  • The read's check (refusalWithoutQuery()) and the OpenAPI reader both learn it too.
  • AskedBy stays about fields, as today.
  • RestPlace writes the asked value onto each row it gets back, so every layer stack read for system "x" has system: "x".
  • The OpenAPI reader writes the field line from the query parameter.
  • Nothing new in the language, and a read's where its system is "x" works unchanged.
  • Asked For By Parameter's accepted plan is rewritten: steps 2 and 3 become "RestPlace writes the asked value onto each row; ingest writes the field line"
  • no new idea in AskedBy or in the read's check
  • its estimate drops from 2h to about 1h30m
