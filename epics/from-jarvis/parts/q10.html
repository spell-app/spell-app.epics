This is for Subclass Elements In Spell, the phase that lets a project declare an element built on a Spell UI one, like the netlist's column tree. You picked "a Spell declaration naming its base element", and asked if it reads is a ui tree view.

The nearest thing Spell has is a "card" is a draggable two sided view, a view on a built-in base. And plain Spell names Spell UI's elements without "ui": <text>, <tree>. The tree's vocabulary already lists "tree view" as another name for it ("vista de arbol" in Spanish). New words need your OK. 

A   a "netlist column" is a tree view            una "columna de netlist" es una vista de arbol
    a "wiring graph" is a graph view
    only for elements whose vocabulary lists "<noun> view" as another name

B   the same, for EVERY Spell UI element:  "<noun> view"
    a "big button" is a button view               reads oddly

C   a "netlist column" is a ui tree view          "ui" new to plain Spell;  no Spanish twin

D   a "netlist column" is a view on a tree        a new phrase, "view on"
    una "columna de netlist" es una vista sobre un arbol
  • a type line can end in a Spell UI element's "<noun> view" name, read as one name, as "two sided view" is
  • the elements it works for are the ones whose vocabulary lists that name: the tree and the graph to start
  • a program's own type named "tree view" warns, so the two never mix
  • if its appearance is columns doesn't already set an inherited default, that line is part of this answer too
