After the page server restarts, a page's next read of an authenticated place is refused (403, "bad token: reload the page") until it reloads; the page server's own reloads bring the new token. RemotePlace waits instead (GUARD_STATUS).

Make a read through the page server wait out a restart, the way other places on the page server already do, instead of failing as refused.

  • The page server marks its answer to an old write token as "stale token", so the page can tell it apart from a place that really said no.
  • The page treats that answer as no answer yet, and asks again later, as RemotePlace does.
  • Once the page server's own reload brings the new token, the next read goes through.
  • A real refusal still counts as refused: a place's own 403, a read-only place, a secret that isn't set.
