Likely places the old javascript is kept: the runner's live-edit path reuses the last run's code files (takeEdit(), last.natives) when the Spell program itself didn't change; or the extension or the language server keeps the file's javascript.

The code file IS read afresh on every Restart: the runner asks for it again, and the program runs the new code. The bug is in what VS Code's runner SHOWS.

  • Cause: the runner's two copies of the runtime (one for the program, one for its tests) share ONE core. The core's main module sits in a shared chunk, not in spell-runtime.js, because a sample-rows file the core loads lazily (placeSamples) imports one helper from the checker, which drags the core in with it.
  • So when the tests' copy loads, it puts its own console on that shared core. The Output pane still shows the program copy's old console: it never changes after the first run. HI! was printed, onto a console nobody shows.
  • It isn't about code files: any program's Output in VS Code's runner stops after its first run (built runners since about 2026-11-01 show it; the Oct 31 build doesn't).
  • Fix: move the checker's kindOf() into a small file of its own that needs no core, so the lazy chunk shares nothing of the core, and core is back in each runtime copy alone. Pin it in element.build.test.ts: the core's own module only in spell-runtime.js, not just resetRuntime.
