In a built editor, the layout's or the Tests card's copy of the runtime can take over the shared core, and an app's elements never get defined.

  • Solitaire draws with Solitaire as the root of the Views tree, on every load
  • A copy's core is never the main one's
  • The next mismatch logs a warning

Each copy gets its own core; a view class from a View core doesn't know warns instead of failing silently; a test pins it.

  • The runtime its own build entry, sharing no chunks; isViewClass() warns on a View it doesn't know.
  • Fixes the bug and the isolation the layout and tests assume.
  • loadRuntime() copies every chunk a copy imports into its own blob.
  • No build change, but each copy loads slower.
  • Elements get defined again, but copies still share all of core's state.
  • A quick unblock first, the real fix after.

The coherence review (sent to this phase's builder already): the self-contained build splits by the editor's existing dev rule (PER_COPY in app/app/vite.config.ts), not a new one.

  • Per copy: the core and the runner.
  • Shared by every copy: Solid, Spell UI and spell/util.

So the copy is its own runtime where it must be, and doesn't carry a second Solid or Spell UI.
