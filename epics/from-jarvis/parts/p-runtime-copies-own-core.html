In a built editor, the layout's or the Tests card's copy of the runtime can take over the shared core, and an app's elements never get defined.

  • Solitaire draws with Solitaire as the root of the Views tree, on every load
  • A copy's core is never the main one's
  • The next mismatch logs a warning

Each copy gets its own core; a view class from a View core doesn't know warns instead of failing silently; a test pins it.

  1. The fix is this phase's choice below (the paste's options).
  2. Option 1, the recommended one: build spell-runtime.js self-contained, its own build entry with no chunks shared with the editor (its lazy imports inlined), so a blob copy really is a separate runtime. Measure the bundle's size before and after.
  3. Option 3, with it: isViewClass() logs a warning when it sees a class extending a View it doesn't know, rather than quietly answering no; with a brand, when chosen.
  4. A regression test: load the main runtime and a copy (in a browser test, from a build), run a program declaring a view class; its tag is defined, and the copy's core isn't the main one.
  5. Dev is already right (runtimeCopyInDev()): a test pins that too.
  6. Checked by: the paste's three reproduction steps on a built editor, ten loads each.
