A use line records its names for its file's scope as it's committed (SP.NativeCode.useIn()). An incremental edit that removes it doesn't take the record away, so its calls still read that file until a full parse.

A use line's record goes into the parse journal, like every other change a line makes to what later lines see.

  • SP.NativeCode.useIn() records its change with an undo: an edit that rewinds past the line takes the record away, and one that keeps the line puts it back.
  • A use line already counts as changing what later lines see, so the lines below it parse again and look their names up afresh.
  • A test edits a project, deleting its use line, and checks the call then reads the project's other code file.
