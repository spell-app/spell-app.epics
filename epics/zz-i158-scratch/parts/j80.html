The worktree hook makes ~/www/spell.worktrees/<epic>/ as a git worktree of the top, then a git worktree of EVERY child repo cloned in ~/www/spell inside it, at the same folder names, all on branch <epic>, each from its own main. Then one install, at the top.

  • A child that isn't cloned (a yarn clone spell-ui setup) is skipped; one cloned later is added the next time the worktree is made or reused.
  • An agent's worktree (isolation: "worktree") gets the same whole layout, named <epic>-agent-<id>, and its own install: slower to start than a one-repo worktree, but the agent can edit and test any repo. The other way, an agent's worktree of one repo only, would have no install to run against (Q9's reason).
