READMEs in the Review tab: view first, comment, or edit in place? Which comes first?

  • Today a README in the page server is served as plain text: opened in the Review tab, it's raw Markdown.
  • Spell UI already has <ui-markdown>: it renders a Markdown file, and has Write / Preview tabs that save the file back.
  • Saving goes through the page server's writable folders, which today are content-repo folders only; READMEs live in the code repos (the kit, spell-ui ...), tracked by git on a branch.
  • Comments (the bullhorns) work on any docs page, block by block; a rendered README's paragraphs and list items would be blocks too.
  • A README page: epic pages open README-cli.md --review shows it rendered, with the site header, and a bullhorn on every block.
  • Comments go to the epic the README's checkout belongs to, as a guide's do today.
  • Editing next, as its own step: a write to a tracked file in a branch needs care (which worktree, the diff in Source Control).
  • Render, comment, and the Write tab, saving into the checkout the page server serves.
  • Cost: the page server writing tracked code files is new; a mistake edits main's README from a worktree's page.
  • Rendered, read-only. Comments by hand in chat. Cost: little better than opening the file in VS Code's Markdown preview.
  • the page server renders README*.md as a page (the site header, <ui-markdown>, the comments)
  • epic pages open and epic pages link take a README
  • editing in place is a later phase, with its own questions
