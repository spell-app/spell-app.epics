For I22, a page in the content folder is now linked from the checkout that SERVES that content: RepoList.linkRootOf(), the registered repo (~/.spell-epic/repos.json5) whose content folder it is. For spell-epic's own epics that's spell-app, so engine code links ../../../spell-epic/src/... through spell-app's spell-epic link.

  • spell-app and its worktrees are registered, so they keep linking from their own checkout, as before.
  • With no registered repo for that content (another machine, a test), it falls back to the checkout itself, which is the old behaviour.
  • The alternatives: a new config key naming the serving checkout (one more setting to keep in step), or leaving engine names as plain text in content pages (no links at all to the engine's code).
  • Limit: the link goes to the MAIN checkout's file, so a file new on a spell-epic branch stays plain text until it merges.
