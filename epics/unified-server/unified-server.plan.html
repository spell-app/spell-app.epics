Page Server A new leaf package, server ($/server, namespace SRV): one set of page-serving helpers replaces six hand-rolled copies, in goals, the VS Code preview, the CLI, ui's tools and the app's Express API. On it, ONE page server per checkout serves docs, plans, goals, Spell UI docs and finally the editor (spell serve) on one port, with live reload, a shared site header and an API that edits pages in place.

We now have a bunch of different things that are creating/"serving" pages
- the editor app
- general docs
- plan files
- spell/ui docs
- goals

I think we should centralize that base functionality into a `server` package.
