In the Docs And Preview phase (P4), the page server had to show the Astro site at /ui/. In dev, Astro serves its modules from the ROOT of the server, whatever its base says.

  • The paths it asks for: /@vite/client, /@fs/..., /src/...
  • None of those exists at the repo root, so the page server sent them on to astro dev while it ran.
  • Its hot-reload websocket went the same way, picked out by its vite-hmr subprotocol.
  • The options not taken:
    • Astro on its own port, in an iframe
    • a redirect to Astro's own port
  • Looks done or obsolete: the Astro site was retired on 2026-10-03 (commit fc83daab), and /ui/ is plain static pages now, so nothing is proxied (checked 2026-10-04).
  • while Astro ran: /ui/ pages hot-reloaded on the page server's own origin
