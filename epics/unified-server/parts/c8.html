The site header needs a root attribute: the relative path from its page up to the folder the header's links start from, so they work even when the page is opened from disk (file://). Each tool that makes pages from a template sets it its own way (settled in the Docs And Preview phase, P4).

  • docs:new (new-page.js): the same prefix it gives the page's asset paths, plus two more levels (../..). That's because the docs' content folder is two folders below the repo root.
  • goals new and goals new-set, and the goals home page, made from its template. fromTemplate() sets root to the path from the page up to goals' ROOT, the folder holding the goals folder. 
    const root = relative(dirname(dest), ROOT).split("\\").join("/") || "."
// ...
  .replace(/(<spell-site-header\b[^>]*?\broot=")[^"]*"/, `$1${root}"`)
  • plan-doc new: nothing to change.
    • its template, plan.html, sits at the same depth as the plan docs' own folders: a folder per epic, under plans then, under epics now
    • so its root="../.." is already right
    • so are its asset paths, which aren't rewritten either
  • The catch: goals is meant to be portable. In another project, the header's spell-specific properties would point nowhere (more on that: C2).
