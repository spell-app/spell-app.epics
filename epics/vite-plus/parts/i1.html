vp run --cache replayed a passing type check for a package that no longer type-checks. Its cache tracks which files a task reads, and it can't see TypeScript 7's reads.

  • How it was found: a type error planted in the parser's index.ts, then the parser's ts task run cached.
    • it said Cache hit - output replayed, and TSC PASSED
    const x: number = 'nope'                          // planted in spell-lang/src/parser/index.ts
yarn vp run --cache -F @spell-app/parser ts       // Cache hit - output replayed ... TSC PASSED
  • Why: inputs default to tracking which files the process reads. tsc here is TypeScript 7, written in Go, whose reads it doesn't see.
  • The fix: explicit input globs per task (run.tasks.<name>.cache.input).
    • including the packages a package's tsc reads through $/ aliases
  • NEVER --cache on plain scripts.
