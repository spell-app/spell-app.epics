Two choices in rendering and colouring docstrings.

  • Lazy: <Markdown> imports the markdown package on first use.
    • why: the VS Code runner and <spell-app> show docstrings too (the Type and Thing Explorers), and a runner page carries no parser
    • a static import would put the parser in every runner bundle
    • how: an async memo and <Loading>, plain text meanwhile
    • pinned by Markdown.browser.test.tsx
  • All comments: the language server colours markdown in every comment, not just docstrings.
    • spell's comments are markdown-styled already: # headings
    • telling a docstring from a comment needs the parse
    • a plain comment, with none of markdown's special characters, is untouched
    * _ ~ ` [ <
