Markdown isn't all grammar-shaped, so each part is built the way it fits.

  • parser rules (P rules) where it's grammar-shaped, hand-written code where it isn't
  • whether a rule is written in rulex syntax or built in code: decided rule by rule, from P1's rulex doc (D8)
Part How Why
Line kinds: ATX heading, fence, list marker, >, thematic break, table delimiter row P rules, one per kind, tried on each line's tokens Grammar-shaped; dogfoods Sequence / Choice / Pattern
Nesting: lists in quotes in lists, lazy continuation, list tightness Hand-written container stack CommonMark defines it as a line-by-line state machine, not a grammar
Code spans, links, images, autolinks, strikethrough, escapes, hard breaks P rules Grammar-shaped
* / _ emphasis Hand-written delimiter pass Spec's pairing algorithm: *a **b* c** isn't context-free
Output P.Markup + P.render Already plain data; any tag name works
