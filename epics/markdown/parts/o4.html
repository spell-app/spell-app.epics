How the parser is checked against GitHub markdown. The numbers (P9): every spec example passes, 670 of 670; 156 of the repo's 172 Markdown files draw the same as marked; 1.8 times marked's time.

  • The corpus: GitHub markdown's spec examples, about 670, from cmark-gfm's spec.txt.
    • vendored as JSON fixtures in spell-lang/src/markdown
  • A pass rate per spec section, pinned in a snapshot.
    • a regression fails the test; a gain updates the snapshot
    • no 100% target: the scope is a useful subset
  • A real-world check: render the repo's 169 or so Markdown files with both engines, and diff the HTML.
  • Speed:
    • against marked, on the same files
    • spell's speedTest() before and after any parser change
