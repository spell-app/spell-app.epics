The plan had MD.MarkdownDocument re-parsing only edited blocks. Measured first: MD.render() takes ~2.2 ms for packages/spell/PARSING.md (32 kB, the repo's biggest markdown file), well under a frame. So the preview renders everything each time and patchBody() keeps the unchanged lead and tail of top-level blocks (by their markup), swapping only the middle.

  • Why not the incremental parser: correct block-level re-parsing needs lazy continuation, list looseness and document-global reference definitions (C4) handled; all that complexity buys ~2 ms.
  • What the patch keeps: unchanged ui-* elements aren't re-created, so code blocks aren't re-highlighted, and a scrolled table keeps its scroll. Pinned by a test (the first and last block are the same nodes after an edit in the middle).
