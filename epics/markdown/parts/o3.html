Using the parser for something other than spell finds the places it assumes spell ("spell-isms"). Each is fixed in the parser, by the simplest change that works, through the review gate (D5, D7).

What P2 fixed in rulex, each through the gate: it reads syntax with its own plain tokenizer, throws on leftover syntax, keeps spacing as written ({space} / {spaces}), takes intervals ({n,m}) and /i; and the Tokenizer's arrow fields became methods.

Known before starting:

  1. The Tokenizer's methods are arrow-function FIELDS, so a subclass method of the same name is silently shadowed.
    • which: tokenize and matchWord
    • matchText and matchComment
    • matchJSXElement, and more
    • no subclass existed until now
  2. The default tokens misfire on markdown:
    • don't ... won't is read as one quoted string
    • http://x and --- start comments
    • so does #
    • <b> is read as JSX, so an unclosed <br> swallows the rest
    • 1. is a number
    • café splits in two
    • ¬ and ∆ are rewritten
  3. Literals.matchAtStart ignores whitespace.
    • so ** also matches * *
    • Symbols' docs say "no space in-between"
  4. No serializer to an HTML string: P.render.toText strips tags.
    • a toHTML is about 20 lines
  5. Choice tries every alternative and keeps the longest: it may be slow on inline text.
  6. The parser's P barrel loads all of it, which matters for Spell UI's bundle (1.5):
    • AST.ts, 2.7k lines that generate JavaScript
    • scopes, and incremental parsing
