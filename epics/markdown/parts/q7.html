Markdown needs "space required": - item is a list item, -item is text; # Title a heading, #Title text. With D13, symbol runs (**, ]() no longer allow spaces, but nothing can REQUIRE one.

Whitespace is already kept: with today's WhitespacePolicy.LEADING_ONLY, each token carries the spaces after it in token.whitespace. So a new policy wouldn't help by itself: the gap is that rulex has no way to SAY it.

What C changes in spell (guides/rulex/experiments/adjacency-impact.mts): 11 of 135 syntaxes have parts written touching. Each keeps today's behaviour by adding a space to the syntax.

For comparison, the decided Symbols fix (D13) changes ONE spell syntax: (operator:(<|>) =?) (math.ts:45) stops matching > =. Under C it would keep matching it, because that syntax has a space.
