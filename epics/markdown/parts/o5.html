Where the new parser could plug in, as things stood when the epic began.

  • <ui-markdown>: its engine loader, MarkdownRenderer.engineLoader, is already the place.
    • all the element needs is a render(text, options) that gives back a fragment and its headings
    • it draws no other Spell UI element than <ui-code> today
    • heading ids are GitHub's slugs
  • Size today:
    • marked and DOMPurify, one lazy chunk: about 25 kB gzipped
    • spell's pre-compiled highlighter (the whole parser, and spell): about 130 kB gzipped
    • an engine on the parser would land between them; DOMPurify stays either way
  • The app renders docstrings with marked 14, unsanitised, in ScopeDetailsPane (Markdown.tsx).
  • The language server turns spell's # comments into markdown for hover and completion (SpellLanguageService.docMarkdown()).
    • Monaco renders those itself
  • No markdown editor or live preview exists yet: Monaco only colours Markdown files.
