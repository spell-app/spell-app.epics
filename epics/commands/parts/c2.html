The spell command on your path runs from one checkout, but you often use it inside a worktree. Its dev commands must work on the files where you are, not on the checkout spell came from.

  • yarn cli:install links spell to one checkout, normally the main one.
  • So every spell dev command must find the nearest checkout from the current folder.
    • as spell plan-doc and spell goals do
  • Looks done or obsolete: findCheckout() does exactly this.
    • its docstring says every spell dev command uses it (checked 2026-10-04)
  • spell dev ... in a worktree reads and edits that worktree's files
