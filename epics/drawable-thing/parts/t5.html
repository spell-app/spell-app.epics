A <markdown> block in a spell file, its text kept exactly as written and drawn as formatted text, the way a <css> block keeps its CSS (Owen, reviewing J15: "we can do the same for e.g. <markdown>").

  • Spell reads it as raw text: the tokenizer's list of raw-text tags gains markdown beside css. So the markdown's own stars, hashes, angle brackets and braces are never taken for spell.
  • The common indent comes off, as it does for CSS, so the block can sit indented in an outline or a drawing.
  • It draws with Spell UI's markdown element, <ui-markdown>, which already renders GitHub-flavoured markdown.
  • Editors colour its inside as markdown: VS Code through spell's grammar (it already embeds CSS for <css>), and the spell editor in the web app. 
to draw a rules panel:
	return <div className="rules">
		<markdown>
			## Klondike
			Build each pile **down**, alternating colours.
		</markdown>
	</div>

Open questions, for when it's built:

  1. Where it may go: inside a drawing only, or also in a type's outline (as a description, say) or a layout.
  2. Whether {holes} in it show live values, as a layout's text does, or stay plain text.
  3. Whether the compiled output keeps the markdown as a string handed to <ui-markdown>, or renders it to HTML at compile time.
