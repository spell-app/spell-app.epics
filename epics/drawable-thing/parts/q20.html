The new phase, P12 · Spell Events Anywhere, lets a layout put an event handler straight on a tag, as an attribute. This asks how that attribute is spelled. Owen wants to explore it when the phase starts: "I'm unclear on the best syntax".

  • What exists today: one attribute, action, which runs its spell on a click (P9).
    • It takes no other event.
    • The new attribute takes any event: a click, a drag, a key press, a change.
  • The block form is settled: when clicked: play a song inside a <spell> block, with on drag: too.
  • Whatever is picked, a handler with spaces needs quotes, or the browser cuts it at the first space (C15). The phase looks at whether that can be avoided.
  • action stays either way, as the short form for a click.
 
<ui-button on-click="{play a song}">Play</ui-button>       ... A
<ui-button when-clicked="{play a song}">Play</ui-button>   ... B
<ui-button action="{play a song}">Play</ui-button>         ... today:  a click only
  • The name after on- is the browser's own event name: on-click, on-dblclick, on-dragstart, on-keydown.
  • Close to HTML's own onclick, and to Solid and Vue, so it reads as familiar to a web developer.
  • Every browser event works with no table of words: the name is passed through as written.
  • The cost: it doesn't match the block's words. The block says when clicked, the attribute on-click.
  • on-<event> attributes on any tag, the event's browser name after the dash.
  • The same words as the block's when clicked: when-clicked, when-double-clicked, when-hovered.
  • One way to name an event across the whole layout, in spell's voice.
  • Any other word is passed through as the browser's event name, as the block does today: when-keydown.
  • The cost: reads less like HTML; and spell's words for less common events (dragging, a key press) need deciding.
  • when-<word> attributes on any tag, read through the block's table of words.
  • on-click and when-clicked both work, and mean the same handler.
  • Matches the block, which takes on as well as when.
  • The cost: two spellings to document and to teach, and a tag could carry both by mistake.
  • Both prefixes read; each maps to the browser's event the same way.
  • The attribute form in P12 · Spell Events Anywhere is built in the chosen spelling.
  • action stays as the click shortcut.
  • The Klondike layout demo and Spell's docs on layouts show the chosen form.
