Six pieces, each small. Where each lives follows the packages' one-way rule: spell and core may not reach up into Solid or Spell UI, and Spell UI may not reach into spell.

  1. Grammar (spell): type names can be more than one word.
    • "a bank account aka account is a thing" declares one type, with a short name (O5)
    • "drawable thing" and "drawable list of cards" are built-in types, so "a card is a drawable thing" parses with no leftover word
  2. Two real base classes (core), each built on a class spell already has:
    • Drawable, a kind of Thing
    • DrawableList, a kind of List
    • they join the built-in classes, so compiled code can import them
  3. A hook (core): spellCore.defineElement(), empty in core and filled in by the page that runs the program.
    • why: core may not import Solid or Spell UI
    • the same trick core already uses to let the page register its elements
  4. The bridge (app, beside the runner's spellRuntime.ts): builds the element class at run time from the spell type, and defines its tag.
    • a Spell UI component class, its vocabulary made from the type's properties and methods
    • its drawing is the thing's own draw(), inside the thing's error net
    • compiled spell runs with no build step, so no decorators and no JSX: the class is put together with plain function calls
    • it uses the page's own Solid and Spell UI, never a second copy
  5. Styles: exactly as a ui-* element does it.
    • the shared runtime's theme and base sheets, adopted the same way Spell UI's own elements adopt them
    • plus the type's own sheet, written in a <css> block in the spell (P4)
  6. Drawing (core): draw the card puts the card's tag on the page with the card attached, instead of drawing its markup inline.
    • a drawable list draws its frame in its own shadow root
    • its items go in as its CHILD elements, shown through a slot in that frame
    • so a pile of cards is the same shape in a program and in hand-written HTML
<game-pile>                 <!-- the pile's frame:  its own to draw, in its shadow root -->
  <game-card …></game-card>  <!-- each card:  a child element, shown in the frame's <slot> -->
  <game-card …></game-card>
</game-pile>

The TypeScript writer writes the same element as a hand-written Spell UI class, in this epic too (Q6, P10).
