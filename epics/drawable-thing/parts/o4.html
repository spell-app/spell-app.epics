Five pieces, each small. Where each lives follows the packages' one-way rule.

  1. Grammar (spell): "a card is a drawable thing" reads as a type, a base type and the word "drawable"; no leftover word.
  2. A real base class (core): Drawable, a kind of Thing, joins the built-in classes, so compiled code imports it.
  3. A hook (core): spellCore.defineElement(), empty in core and filled in by the page that runs the program. Why: core may not import Solid or Spell UI.
  4. The bridge (app): builds the element class at run time from the spell type, on the page's own Solid and Spell UI, and defines its tag.
    • compiled spell runs with no build step, so no decorators and no JSX: the class is put together with plain function calls
  5. Drawing (core): draw the card puts the card's tag on the page with the card attached, instead of drawing its markup inline.
