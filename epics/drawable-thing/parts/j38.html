In a <spell-app> layout, the browser reads the <markdown> block before spell sees it. Chose to take its text (textContent) as the markdown, over its HTML.

  • Headings, **bold**, lists and > quotes all work as written.
  • But an HTML tag inside, e.g. <b>, becomes an element the browser keeps and the markdown loses: write &lt; for a <.
  • In a spell file the block is raw text, so this is only the layout's.
  • It is drawn by a new <ui-markdown> in its place, its holes live, the whole markdown drawn again when one changes.
  • Built.
  • Quotes (>) and code survive.
  • Inline HTML would survive.
  • But the browser writes > as &gt;, so every quote would break.
  • Exact text, as <ui-markdown> already allows.
  • More to type for the common case.
  • The layout's spell loads for a <markdown> block too (layoutHasSpell()).
