For J43, an element the program draws takes its thing's name as its id: <solitaire-card id="queen-of-spades">. Where two things share a name, the count lives with the PROGRAM, in the order it made its things, over counting per page or per tag.

  • Two decks: the first deck's queen of spades is queen-of-spades, the second's queen-of-spades-2, and a third deck's ends in -3.
    • Counted among every drawable thing the program made, of any type, since ids are the page's.
    • Each <spell-app> counts its own program's things.
  • Stable: a thing keeps its id while it keeps its name.
    • A card moved to another pile is drawn as a NEW element there: it gets the same id, never a new number.
    • A thing thrown away earlier doesn't renumber the ones after it.
  • It follows the name (point 3 of the task): card.rank = "king" makes the queen of spades king-of-spades, numbered afresh.
  • A thing with no name gets no id. A space in a name is a dash: discard pile is discard-pile.
  • The handed thing always wins: while the program has handed an element its thing, the id is never looked up, so the id can't make it draw another thing. An id the page wrote on the element itself is kept.
  • A layout's spell doesn't take a drawn element's id as a page name: only tags written by hand are names, e.g. T1.
  • Where: spellCore.elementIdFor(), written by SpellElement.nameAfterHandedThing().
  • As built: the same ids every run, whatever order the elements are drawn in.
  • A card moved to another pile is a new element, so it would take the next number: ids would drift to -2, -3 as the game plays.
  • A pile and a card that share a name would share an id on the page.
  • Every Drawable Solitaire card, tableau and pile shows its name as its id in the inspector.
  • Two <spell-app>s running the same game on one page each number their own things, so their layouts can repeat an id.
