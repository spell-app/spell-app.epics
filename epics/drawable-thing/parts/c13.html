A drawable element's attributes are set the first time its tag is defined: a property added to the type in a later run (an edit in the editor) gets no attribute until the page reloads.

  • Why: the browser reads a custom element's list of watched attributes ONCE, when its tag is defined, and a page can't define a tag twice.
  • A re-run keeps the tag and swaps what's behind it (the recompile swap, J20), but can't add to that list.
  • The same for methods: they're added when the tag is defined, so a method added by an edit isn't on the element either.
  • J20's aside saw this coming: a "redefine this tag" hook in Spell UI could fix it, if it matters.
// first run:   <solitaire-card rank="ace"> works
// edit, adding:  a card has a back as text
// re-run:      <solitaire-card back="blue"> ... back is ignored, until the page reloads
  • After an edit that adds a property or a method, reload the page to use it on the element.
  • Drawing still follows the edit at once: only the element's outside is fixed.
