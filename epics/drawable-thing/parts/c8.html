A type's outline (the indented lines under it) counts only when its line ends with a colon, so a <css> block under a type without one is an error.

  • The plan's own examples leave the colon out: the type examples (O1, O5) and the block's placement question (Q13).
  • Without the colon, the indented lines aren't the type's outline, so the block isn't in a type.
  • The error then says to put the block in a type's outline.
  • This is how outlines already worked, from the earlier epic outline-spell; this epic didn't change it. 
a card is a drawable thing:          ✓ the block is the card's
	- it has a rank as a number
	<css>
		.red { color: crimson }
	</css>

a card is a drawable thing           ✗ an error:  put it in a type's outline
	<css> ... </css>
  • Write the colon after a drawable type's line when it has a <css> block.
  • The plan's examples without it would fail as written.
