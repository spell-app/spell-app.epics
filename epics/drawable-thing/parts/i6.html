With types in snake_case, a type and a variable named for it are written the same, so the class's name is taken.

  • Solitaire in TypeScript, types in snake_case: const card = new card(), and tsc reports 14 errors (a name declared twice, a variable used before it's declared).
  • javascript and TypeScript don't hit it: their types are PascalCase.
  • It matters for the Python target (epic python-target), whose map is { all: "snake_case" }: Python would rebind the class's name the same way.
  • The naming test checks TypeScript with types in SCREAMING_SNAKE_CASE instead, which collides with nothing, so every place a type is named still has to agree.

When a language names a type and a variable the same way, rename one of them, e.g. a variable named for its type gets a suffix, or the language keeps PascalCase for types.

  • Python's naming map writes types in PascalCase (epic python-target P7), so a Python type and its variable differ: card = Card().
  • It would bite only a language whose map names types in snake_case or camelCase.
