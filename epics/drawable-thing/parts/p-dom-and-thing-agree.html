A drawable element passed its attributes on to its thing, but nothing came back: after ace.turnOver() the tag still said direction="up" (J22).

A drawable thing's properties and its element's attributes agree both ways, at once, for every drawable element, the program's too.

  • ace.turnOver() shows direction="down" on the tag; reading ace.rank asks the thing, so it's never stale (J34).
  • Text as written, a number as its digits, yes / no as the attribute there or gone, nothing as no attribute.
  • A hand-written tag's attributes win when it starts; a thing the program hands an element always wins instead.
  • A drawable element and its thing now agree both ways. ace.turnOver() changes direction="down" on the tag, so the browser's inspector shows the card as it is.
  • The page's changes still reach the thing, and now at once: ace.setAttribute("rank", "2") or ace.rank = 2 makes the thing's rank 2 before the next line runs, and the card redraws.
  • Reading ace.direction or ace.rank asks the thing, so it's never stale (judgement call J34). A number reads back as the number: rank="2" reads as 2.
  • How values show:
    • text as written
    • a number as its digits
    • yes / no as the attribute there or gone
    • nothing as no attribute; removing an attribute makes the thing's property nothing
    • a property holding a thing or a list stays a JavaScript property, with no attribute
  • Cards the program draws show their attributes too: in Drawable Solitaire every card shows its rank, suit and direction, every tableau its name, and a card played from the stock turns to direction="up" as it's played.
  • A tag written by hand keeps its attributes when it starts: the thing it makes takes them first. A thing the program hands an element always wins instead, so an element's empty values are never written into it (before, a program-drawn card with a yes / no property got a no written into its thing).
  • No loops: a value the other side already has is never written, and Spell UI's elements never hear their own attribute writes. The test counts it: one attribute change, and one write to the thing, per change.
  • Built on Spell UI's own reflection (a property write writes its attribute back) and its hook for every value change: nothing new in Spell UI.
  • The demo page, drawable-elements.html, shows the ace's tag live under its buttons, with a new setAttribute("rank", "2") button. Not opened by hand.
  • Checks: app's type check passes; app's node tests 118 pass; app's browser tests 170 pass (was 166: four new in SpellElement.browser.test.tsx, and the Drawable Solitaire runner test checks the attributes too).
