Nothing turns a spell type into a custom element.

A drawable class asks core's new hook to define its element; the app fills in that hook with a bridge that builds and defines the element. The tag is the singular project or library name, then the type (Q3), and it styles itself from the shared runtime, like any ui-* element.

  • Running a program with "a card is a drawable thing" defines the card's tag on the page:
    • <solitaire-card> in a solitaire app
    • <game-card> in a games library
  • The element looks like a Spell UI element: the same theme and base styles, from the shared runtime.
  • One copy of Solid and Spell UI on the page: the bridge uses the page's own.
  • The type's own styles come in P4, from <css> blocks in the spell.
  • drawing.ts: the defineElement hook, empty in core
  • JSWriter.ts: a drawable class calls the hook from its static block
  • spellElements.ts, new: the bridge
  • spellRuntime.ts: installs the bridge in the hook
  • tests
  • a browser test compiles a tiny project and finds its tag defined, customElements.get("test-card")
  • the shared sheets are adopted in its shadow root
