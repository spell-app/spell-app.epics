Every edit in the editor runs the program again from the top: Drawable Solitaire deals a new game, and any program loses what it was doing.

A recompile carries the program's things over to the new classes, matched by their type's name, and doesn't run the program's start again: the game in progress stays, drawn the new way.

  • In the editor, an edit to Drawable Solitaire keeps the game in progress.
    • Change a card's <css> or its to draw: the cards you dealt and turned stay where they were, drawn the new way.
    • No new deal: the program's start isn't run again.
  • It works for every spell program, drawable or not: a counter keeps its count, a list keeps its items.
  • How, on each recompile:
    1. the old program's things are written out, as saving does (each thing's JSON names its type)
    2. the new program is loaded, without running its start
    3. each thing is read back as the NEW class of the same name: an old card becomes a new card
    4. the program's top-level things point at the things read back, and the page draws them
  • The hard cases each do something Owen can predict:
    • a property added: the new thing's own starting value
    • a property removed: dropped
    • a property whose type changed, or a type renamed or removed: that thing starts afresh, and the console says so
    • a card held by two lists stays ONE card (saving's JSON keeps no identity today)
  • An escape hatch: a way to start afresh on purpose (a restart button, or an edit to the program's start), since sometimes a new deal is what you want.
