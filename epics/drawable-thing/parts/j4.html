A type named in several words compiles with an underscore between the words, Bank_Account, not BankAccount as the plan said (O5). This is a change from the plan.

  • Spell already writes a dashed name this way: a bank-account is a thing compiles as Bank_Account, through typeCase().
  • "bank account" and "bank-account" must name the SAME type, so they must compile the same.
  • Writing BankAccount for both would change how every existing dashed type compiles, and every fixture snapshot with one.
  • output-targets' P19 (the JavaScript writer's names) plans camelCase names, and may change how every class name is written. This follows whatever it does: both spellings go through the same function. 
a bank account aka account is a thing
set savings to a new account        -- compiled:  new Bank_Account()
set checking to a new bank-account  -- the same type:  new Bank_Account()

  • a dashed name and a spaced name are one type
