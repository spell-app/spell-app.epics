"a pile is a drawable list of cards" is read by its own grammar rule, create_drawable_list_type, rather than by the existing list rule learning a second phrase.

  • The new rule is a subclass of the plain list rule, create_list_type: it changes only the phrase ("drawable list of") and the class it extends.
  • Everything else is inherited: the item type, a short name after "aka", an indented body.
  • Visible side effect: the snapshot of spell's rule names gains one name.
  • The alternative, one rule that reads which kind of list from its words, would need a new small rule just to match "list" or "drawable list", and would make the list rule harder to read.
  • "a pile is a drawable list", with no "of cards", needs no new rule: the ordinary type rule reads "drawable list" as the parent type, and it compiles to extends DrawableList. 
export class CreateDrawableListType extends CreateListType {
  @proto static listType: P.Datatype = "drawable list"
}
classes.addRule(CreateDrawableListType, {
  syntax:
    "(a|an) {type:type_words} (aka {aka:singular_type})? is (a|an) drawable list of {instanceType:type} {with_nested_statements}?",
  ...
})
  • spell has one more rule, create_drawable_list_type, in its rule-names snapshot
  • create_list_type gains a listType setting, which its subclass overrides (a plain list by default)
