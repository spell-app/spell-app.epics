The TypeScript writer doesn't write a drawable thing's element class yet: P10 built the css tag part, and stopped before the element, because how the element class gets Spell UI is a real fork.

  • Today a drawable class names its element as it's declared (static elementTag = spellCore.defineElement(this, ...)), and the page running the program makes the element, from app's SpellElement. Core never imports Spell UI.
  • An element class written in the compiled TypeScript would have to get Spell UI from somewhere. Three things block it:
    • The type check sees only @spell/core, which is core's own code: it has no Spell UI types.
    • The page would make the same tag again (defineElement()), so one of the two has to step aside.
    • The core contract runs every fixture headless, with no page, and the TypeScript must print exactly what the javascript prints. Javascript makes no element there.
  • What's built and checked: the new fixture with drawable types (DrawableSolitaire) compiles to TypeScript that passes tsc with no errors, and runs in the core contract, printing what the javascript prints. Its card and pile are still plain classes there. 
import { SpellElement } from "@spell/elements"

export class CardElement extends SpellElement<Card> {
  static vocabulary = SpellElement.vocabularyFor("test-project-card", {
    rank: { kind: "json", values: RANKS },
    suit: { kind: "string", values: SUITS }
  })
  static elementSetup = { styleSheets: { "test-project-card": Card.css } }

  turnOver() {
    this.thing?.turnOver()
  }
}
