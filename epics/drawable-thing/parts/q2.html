What does the word "drawable" mean to spell? It decides what the grammar learns, and which types get an element. 

a card is a drawable thing     -- A:  a built-in type, "drawable thing"
a card is a thing              -- B:  any thing with its own "to draw" gets an element anyway
a card is a drawable, sortable thing   -- C:  "drawable" is one of many adjectives
  • Drawable is a kind of Thing, as App is
  • "a drawable thing" and "a drawable" both work; a type built on a drawable type is drawable too
  • only types that say so get an element: nothing changes for programs that don't
  • no new word: any type with a to draw becomes an element
  • cost: every existing program changes how it draws, at once; more elements than wanted (every card in a deck of 52)
  • a general slot for words before the base type: "drawable", later "sortable", "saved" ...
  • cost: a mixin system, much bigger than this epic
  • a new rule reads "a X is a drawable thing" ahead of today's type rule
  • core gains a Drawable class, a kind of Thing
  • existing programs draw as they do now

"drawable thing" makes a web component (Owen, 2026-10-10).

  • "drawable thing" and "drawable list" are built-in types, each two words long (the multi-word types section, O5).
  • Adjectives in general ("sortable", "saved" ...) are another topic: a future epic, mixins, written down separately.
