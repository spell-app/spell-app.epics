A spell author writes one line, and their type becomes a real web component: a tag any page can use, drawn with Spell UI. 

a card is a drawable thing
  - it has a rank as a number
  - it has a suit as text

to draw (a card):
  return <div class="card {its color}">{its rank} of {its suit}</div>
  • Today, every thing with a to draw is drawn as plain markup inside the program.
  • With this epic, a drawable thing also gets its own custom element:
    • the tag starts with the project's or library's name, made singular (Q3)
    • a card in a games library is <game-card>
    • a card in a solitaire app is <solitaire-card>
    • inside the program, draw the card puts that tag on the page, with the card itself attached
    • each card draws in its own shadow root, with its own styles and its own error net
  • The element shows the type on the outside:
    • its attributes and properties are the type's properties (rank, suit)
    • its methods are the type's methods: card.turnOver() on the element turns the card
    • all of them named by the type's vocabulary, the way Spell UI names its own elements' attributes
    • the names are English only, for now
  • A drawable list (a pile of cards) is an element too, and its tag holds its items' tags:
    • the list's to draw draws the outside of the pile
    • each card inside draws itself, as a child element of the pile
<game-pile>
  <game-card rank="1" suit="spades"></game-card>
  <game-card rank="12" suit="hearts"></game-card>
</game-pile>
  • The program draws that shape, and a plain HTML page can write it by hand (Q4).
  • The element is the same kind of thing as Spell UI's own ui-* elements, on the same engine.
