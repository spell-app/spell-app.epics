A spell author writes one line, and their type becomes a real web component: a tag any page can use, drawn with Spell UI. 

a card is a drawable thing:
	<css>
		.card.red { color: crimson; }
	</css>
cards have a suit as one of clubs, diamonds, hearts or spades
a card has a direction as either up or down

to draw a card:
	return <div className={"card " + its color}>{the short name of the card}</div>
  • Before this epic, every thing with a to draw was drawn as plain markup inside the program.
  • Now a drawable thing also gets its own custom element:
    • the tag starts with the project's or library's name, made singular (Q3)
    • a card in a games library is <game-card>
    • a card in a solitaire app is <solitaire-card>
    • inside the program, draw the card puts that tag on the page, with the card itself attached
    • each card draws in its own shadow root, with its own styles and its own error net
  • Its styles are a <css> block in the type's outline (P4).
    • The block is read exactly as written, the way a browser reads <style>.
    • VS Code and the spell editor colour it as CSS, and offer CSS completion, hover and errors inside it.
    • It compiles to a css-tagged template on the class, so editors colour the compiled CSS too (P10).
  • The element shows the type on the outside (P8, P13):
    • its attributes and properties are the type's properties (rank, suit)
    • its methods are the type's methods: card.turnOver() on the element turns the card
    • the two agree both ways: turning the card over shows direction="down" on its tag, and setting the tag's attribute changes the card
    • all of them named by the type's vocabulary, the way Spell UI names its own elements' attributes
    • the names are English only, for now
  • A drawable list (a pile of cards) is an element too, and its tag holds its items' tags (P6):
    • the list's to draw draws the outside of the pile
    • <children/> in it marks where the items show, and <children name="header"/> a second, named place (P15)
    • each card inside draws itself, as a child element of the pile
<game-pile>
  <game-card rank="1" suit="spades"></game-card>
  <game-card rank="12" suit="hearts"></game-card>
</game-pile>
  • The program draws that shape, and a plain HTML page can write it by hand (Q4).
  • The element is the same kind of thing as Spell UI's own ui-* elements, on the same engine.
  • A <markdown> block shows formatted text in a drawing, its {holes} live; in a type's outline, it's the type's description (P14).
  • An edit in the editor keeps the program's things: the game in progress stays, drawn the new way (P16).
  • Still to build: the TypeScript writer writing the element class itself (P10, J41). Today the page makes the element, for both output languages.
