A page has ONE element per drawable type's tag, and it draws with whichever program defined that tag last. Two <spell-app>s on one page running the same solitaire project share one <solitaire-card>.

  • The browser allows a tag to be defined only once per page, and every <spell-app> has its own copy of the runtime.
  • So the page keeps one shared table, on the page's global object: each tag, its class, and the runtime of the program that defined it last.
    • It's SPELL_ELEMENTS, in app's new SpellElement.
    • The first definition makes the tag's element; any later one just updates the table.
    • The element looks the table up each time it draws, so it always draws with the latest runtime.
  • The same thing happens when a program runs again: the tag stays, and its new run takes it over. That's the start of swapping on recompile (P7).
  • The catch: two different projects with the same name, on one page, would share a tag too. Their names would have to differ.
  • Chosen and built.
  • Tags stay the plain names Q3 chose.
  • Re-running a program needs no new tag.
  • Each app's cards stay its own.
  • But the tag is no longer predictable, so markup and CSS can't name it.
  • Every re-run would define yet another tag.
  • A tag defined twice on a page keeps working, and draws with the program defined last.
  • Two apps of the same project on one page share their elements.
