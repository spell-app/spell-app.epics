Chose to copy the last run's things straight onto the new classes, by type name, over writing them out as JSON and reading them back. The rules are saving's (a class by its name, props through their setters), but each old thing becomes exactly one new thing.

  • Why: JSON keeps no identity, and the goal asks that a card held by two lists stays ONE card (in Drawable Solitaire every card is in the deck AND a pile).
  • A property whose declared type changed, or a type renamed or gone: each top-level thing holding one starts afresh as a whole (keeps what the new run made), and the console says which and why, e.g. stock starts afresh: Card's rank changed its type. Over: making just that card blank, which would leave a pile of blank cards, and mix old and new cards across piles.
  • Which recompile counts as the same program: in <spell-app>, the same name from the same place; in the editor, the same project; in VS Code's runner, its panel's project. Restart starts afresh in all three (Q25).
  • A run that throws: the next recompile carries over the last good run's things, so a typo mid-edit doesn't lose the game.
