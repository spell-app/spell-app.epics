When a program runs again, its drawable types' tags keep their first definition, and app swaps the two things behind them; Spell UI needed nothing new for it.

  • A page can define a tag only once, so <drawable-solitaire-card> stays the element class the first run defined.
    • A program runs again after an edit in the editor, or when a second <spell-app> on the page runs the same project.
  • What it draws with: SpellElement.defineFor() records the new run's runtime and class for the tag, and the element looks them up whenever it draws.
  • How it looks: the type's own CSS (its <css>) is a style sheet named for the tag.
    • On a re-run, SpellElement.restyle() hands the new CSS to Spell UI's own UI.styles.register().
    • That replaces the sheet's rules in every element that uses it, at once, with nothing drawn again.
    • It's the same call Spell UI's hot reload makes when a component's CSS file changes (HotDefinitions.updateStyle()).
  • The sheet is never empty: register() takes an empty text to mean "unregister".
    • A type with no CSS gets a comment instead, so a type that gains CSS on a later run still restyles.
  • Why no hook: the element class is generic, one per tag. Nothing in it is about the type but its names (its vocabulary) and its sheet, so there is nothing to redefine.

const css = SpellElement.cssOf(Class) || `/* <${tag}>:  no styles of its own */`

  • Chosen and built.
  • No change to Spell UI: the call already exists, and its hot reload relies on it.
  • No redraw: only the CSS changes in the elements already on the page.
  • What the plan said (the recompile question, Q5, and P7's Files: HotDefinitions and UIComponent).
  • Not needed while the element class is generic: there's no new class to put behind the tag.
  • The cost: new code in Spell UI, and a test there, for nothing the swap uses.

One catch, for the Element API phase (P8), which turns each property into an attribute:

  • A custom element's watched attributes are read ONCE, when its tag is defined.
  • So a property a re-run adds would get no attribute.
  • If that matters, P8 may need option B after all.
  • Spell UI is unchanged by P7: HotDefinitions and UIComponent, named in P7's Files, weren't touched.
  • The swap lives in app's SpellElement: one sheet per tag, replaced in place.
  • P8 may still need a redefine hook, for attributes a re-run adds.
