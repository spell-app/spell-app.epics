The tag can't be written by hand, and its thing's properties and methods are hidden inside.

Each property becomes an attribute (simple values) and a JavaScript property; each method an element method; all named by the type's vocabulary, in English (Owen). A hand-written tag makes its own thing, and a library's tags load on a plain page (Q4).

  • A plain HTML page can write <game-card rank="1" suit="spades"> inside a <game-pile>, and an ace shows on a pile.
  • Calling card.turnOver() on the element turns the card.
  • Setting card.rank on the element redraws it.
  • The names come from the vocabulary, English only for now; translations are a todo.
  1. What you can try: a drawable type's tag now works on a plain page, written by hand.
    • The demo page, drawable-elements.html: Drawable Solitaire's cards and a pile, written by hand, and buttons calling the ace's methods. How to open it: the demo page test, V4; not yet tried by hand.
    • A hidden <spell-app> on the page runs the project, which defines its tags.
    • A tag written by hand, with no thing set, makes its own thing of its type once mounted, from its attributes.
    • The plain-page example the browser test runs: 
      <plain-stack2>
  <plain-ace2 rank="ace" suit="spades" face-up></plain-ace2>   ... draws "ace of spades"
</plain-stack2>
<script>
  card.rank = "2"     // the number 2, a legal rank:  draws "2 of spades"
  card.turnOver()     // calls the thing's turn_over():  draws "back"
</script>
  2. How names are made, in English only for now (translations: T2):
    • Each declared property is an attribute, kebab-cased, and an element property, camelCased. A property face_up is the attribute face-up and the property faceUp.
    • Each method is an element method, camelCased: turn_over is card.turnOver(), calling the thing's.
    • The attribute's kind comes from the declared type; a property holding a thing or a list has no attribute (J23).
    • Values go one way, from the element to its thing (J22).
    • A name the page or Spell UI already uses, like title or hidden, is left out (J24).
    • Where: SpellElement, when a tag is defined.
      • typePropertiesOf() names the attributes and properties.
      • addMethods() adds the methods.
  3. Core's new API: spellCore.elementApiOf() lists what a drawable class shows outside its element.
    • Its declared properties, its own and its super-types', each with its declared type and legal values.
    • Its methods, its own and its super-types', down to Drawable or DrawableList.
      • Not draw(), and not a method with values in its name, like "is a (suit)".
    • It differs from the plan: the plan named Thing.ts for making a thing from attributes; the element does it instead, in app.
