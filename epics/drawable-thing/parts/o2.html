Before this epic, the line parsed half-way, then failed quietly at run time. Now it parses whole, and compiles to a class on core's new Drawable. 

// before
statement › create_type  a card is a drawable
  superType: type  drawable
parse_error  thing

export class Card extends Drawable {}
/* PARSE ERROR: Don't understand "thing" */

// after (P1, P2)
export class Card extends Drawable {}
  • Then, the type rule, create_type, took ONE word after "is a", and never checked it: so "drawable" became the base class, and "thing" was left over.
    • Now a type's name may be several words (P1, O5).
    • "drawable thing" and "drawable list" are built-in types of two words (P2).
  • Then, nothing called Drawable existed when the program ran: only a TypeScript type meaning "has a draw()".
    • Now core has two real classes, Drawable (a kind of thing) and DrawableList (a kind of list).
  • The built-in base classes were three, and are five now:
    • Thing
    • List
    • App
    • Drawable
    • DrawableList
