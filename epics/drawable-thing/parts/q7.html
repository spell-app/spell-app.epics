The code that turns a spell type into a custom element lives in the app, and core reaches it through a hook.

  • Why, by the packages' one-way rule:
    • Spell UI may not import spell: it lives on its own
    • core may not import Solid or Spell UI
    • the app may import both, and it's what runs a program on a page
  • How:
    • core gets an empty spellCore.defineElement(), which a drawable class calls as it's defined
    • the app fills it in when it starts a program, beside the runner's spellRuntime.ts
    • the same way the app already hands core its elements
  • core gains one empty hook, and knows nothing about elements
  • the app gains the bridge (P3), on the page's own Solid and Spell UI
  • Spell UI gains only a spell-free hook, to swap a tag's class (P7)
