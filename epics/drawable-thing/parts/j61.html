Chose to tell which file an edit changed by comparing the last run's compiled javascript with the new one, file by file, over asking each runner (editor, VS Code, <spell-app>) to pass the changed spell file along.

  • Why: every runner has the compiled javascript, and its files are already separated by a // ----------- line. Only the editor knows the spell files themselves.
  • Several files: the file holding start the game changed, so it starts afresh, as Restart does. Card's or Pile's file, or the styles: the game carries over.
  • One file (start and types together): afresh only when the start's own lines change, e.g. start the game becomes start the board, or a test call is added. Any other edit carries over.
  • A file added or removed: afresh. No app started (a plain program): never afresh this way.
  • Known gaps:
    • A method one file declares on another file's type is compiled into that type's class, in its file. So an edit to Solitaire's to play a card counts as an edit to Card's file, and carries over.
    • An edit to Card's file that changes how Solitaire's code is written, e.g. a new ?., counts as a change to Solitaire's file: afresh.
