Every compiled program now imports the two new classes, whether it uses them or not. It's the same as Thing, List and App already are.

  • Simplest: the compiler doesn't need to know which classes a program uses.
  • An import a program doesn't use costs nothing when it runs.
  • The cost: every example program's saved output (its fixture snapshot) changed, in that one import line only. Each was checked by eye before it was accepted.
  • The app's runtime module had to export them too, or every program would fail to load: spellRuntime.ts. 
// before
import { spellCore, Thing, List, App } from "@spell/core"
// after
import { spellCore, Thing, List, App, Drawable, DrawableList } from "@spell/core"
  • every compiled program imports Drawable and DrawableList
  • every fixture snapshot changed once, in its import line
  • whatever page runs compiled spell must export both classes, as the app's runtime now does
