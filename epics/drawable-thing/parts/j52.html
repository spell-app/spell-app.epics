Each drawable type's element class (P10, J41 B) lists only what its own type declares, and the page fills in the rest when it builds the tag, as it does for javascript. Chose this over writing every attribute out in each class, because the list a card belongs to (a card belongs to one pile, its pile attribute) is only known when the program runs, so a class that wrote everything would still miss it.

  • CardElement lists the card's own properties: its rank, suit and direction. The page adds pile, from the pile that holds it.
  • TableauElement extends SpellElement<Tableau>, not PileElement: each class stands alone, as in J41's B sketch. A pile's name attribute and its methods reach the tableau's tag through the page.
  • An attribute the class names is used as written (its description, its kind); one it adds that is none of the type's properties is a plain attribute.
  • Its sheet: the type's own <css> (styleSheets: { "test-project-card": Card.css }), after its super-types', as for javascript. A type with no <css> of its own writes no sheet line.
