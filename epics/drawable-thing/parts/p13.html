A drawable element passes its attributes on to its thing, but nothing comes back: after ace.turnOver(), the tag still says direction="up", so the inspector shows the wrong card (J22).

A drawable thing's properties and its element's attributes stay the same, both ways: a change to the thing writes the element's attribute, and a change to the attribute writes the thing. Owen, reviewing J22: "The dom and the component need to agree."

  • Changing the thing shows on its tag, so the browser's inspector always tells the truth.
    • ace.turnOver(), or the program setting the card's direction, turns <solitaire-card direction="up"> into direction="down".
    • Reading ace.direction gives the thing's direction, never a stale one.
  • Changing the tag still changes the thing, as P8 built it: ace.setAttribute("rank", "2"), or ace.rank = 2, makes the thing's rank 2, and the card redraws.
  • It holds for every drawable element, not only hand-written ones: a card the program draws shows its rank, suit and direction as attributes too.
  • Which properties show: the type's own declared ones, the same list the element already turns into attributes (text, numbers, choices). A property holding a thing or a list stays a JavaScript property only, with no attribute.
  • How values are written:
    • text as written: suit="spades"
    • a number as its digits: rank="2", read back as the number 2
    • a yes / no as the attribute there or not: face-up present when it's yes, gone when it's no
    • nothing (no value yet): no attribute
  • No loops: a value the thing already has is never written back to it, and the element's own write to its attribute isn't read as the page changing it.
  • A hand-written tag's attributes win when it starts: the thing it makes takes them, then the two stay together.
  • J22 is closed once it works.
