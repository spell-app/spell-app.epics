A drawable element passes its attributes on to its thing, but nothing comes back: after ace.turnOver(), the tag still says direction="up", so the inspector shows the wrong card (J22).

A drawable thing's properties and its element's attributes stay the same, both ways: a change to the thing writes the element's attribute, and a change to the attribute writes the thing. Owen, reviewing J22: "The dom and the component need to agree."

  • Changing the thing shows on its tag, so the browser's inspector always tells the truth.
    • ace.turnOver(), or the program setting the card's direction, turns the tag's direction="up" into "down".
    • Reading ace.direction gives the thing's direction, never a stale one.
  • Changing the tag still changes the thing, as P8 built it: ace.setAttribute("rank", "2"), or ace.rank = 2, makes the thing's rank 2, and the card redraws.
  • It holds for every drawable element, not only hand-written ones: a card the program draws shows its rank, suit and direction as attributes too.
  • Which properties show: the type's own declared ones, the same list the element already turns into attributes (text, numbers, choices). A property holding a thing or a list stays a JavaScript property only, with no attribute.
  • How values are written:
    • text as written: suit="spades"
    • a number as its digits: rank="2", read back as the number 2
    • a yes / no as the attribute there or not: face-up present when it's yes, gone when it's no
    • nothing (no value yet): no attribute
  • No loops: a value the thing already has is never written back to it, and the element's own write to its attribute isn't read as the page changing it.
  • A hand-written tag's attributes win when it starts: the thing it makes takes them, then the two stay together.
  • J22 is closed once it works.
  • A drawable element and its thing now agree both ways. ace.turnOver() changes direction="down" on the tag, so the browser's inspector shows the card as it is.
  • The page's changes still reach the thing, and now at once: ace.setAttribute("rank", "2") or ace.rank = 2 makes the thing's rank 2 before the next line runs, and the card redraws.
  • Reading ace.direction or ace.rank asks the thing, so it's never stale (judgement call J34). A number reads back as the number: rank="2" reads as 2.
  • How values show:
    • text as written
    • a number as its digits
    • yes / no as the attribute there or gone
    • nothing as no attribute; removing an attribute makes the thing's property nothing
    • a property holding a thing or a list stays a JavaScript property, with no attribute
  • Cards the program draws show their attributes too: in Drawable Solitaire every card shows its rank, suit and direction, every tableau its name, and a card played from the stock turns to direction="up" as it's played.
  • A tag written by hand keeps its attributes when it starts: the thing it makes takes them first. A thing the program hands an element always wins instead, so an element's empty values are never written into it (before, a program-drawn card with a yes / no property got a no written into its thing).
  • No loops: a value the other side already has is never written, and Spell UI's elements never hear their own attribute writes. The test counts it: one attribute change, and one write to the thing, per change.
  • Built on Spell UI's own reflection (a property write writes its attribute back) and its hook for every value change: nothing new in Spell UI.
  • The demo page, drawable-elements.html, shows the ace's tag live under its buttons, with a new setAttribute("rank", "2") button. Not opened by hand.
