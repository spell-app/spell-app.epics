Owen (2026-10-12): "or, maybe, if a type file (card/etc) changes, just reload the objects. If the app-file itself changes, re-run again from the top?" Then, asked: both, with Q26.

  • Edit a type's file, e.g. Card.spell or Pile.spell: the objects carry over to the new classes. Only the tests and start the game are skipped (Q26).
  • Edit the app's own file (the one with start the game): the program runs again from the top, a fresh game, as Restart does.
  • Changing how a card looks keeps the game; changing how the game starts deals a new one.
