A drawable class now names its own tag the moment it's declared, but the page's definer only learns of the class a little later, once the class is complete.

  • Spell writes one extra line in each drawable class: a static field, elementTag, set by spellCore.defineElement().
    • It's written by TypeDeclaration.elementMember(), for a drawable type and a drawable list.
    • It returns the tag at once, so the class knows it: <drawable-solitaire-card> for the example below.
  • The page's definer (what turns the class into a real custom element) hears of the class later:
    • when one of its things is first drawn (spellCore.elementFor()),
    • or else in a microtask: the moment the code that's running now has finished.
  • Why not at once: a static field runs while the class is still being made.
    • The class's later statics, its css among them, aren't set yet.
    • Defined then, the element had no styles: the example's runner test caught it, its cards drawn without their CSS.
  • This replaces the Element Bridge phase's one line at the end of the module (J11, now canceled), and goes back to what the plan said: a static member per class.
    • That last line came too late: a program usually starts drawing before its module's last line runs.
    • So cards drew inline, as plain markup, not as their elements.
