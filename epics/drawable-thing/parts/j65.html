TypeScript reads a list's first or last item with ! when a guard found it's there, e.g. pile.lastItem!.color after the pile was checked for being empty. So the type check passes again.

  • Why: main's python-target P25 made the writers read such an item with ., not ?..
    • The writers decide it in mayBeNothing().
    • But TypeScript still types lastItem as Card | undefined.
    • So every Solitaire-like fixture had 2-7 tsc errors on main.
    • And on this branch, the SCREAMING_SNAKE_CASE naming test and DrawableSolitaire's 0-error tsc snapshot failed.
  • Now P.TSWriter.isFoundItem() writes such a read as pile.lastItem!:
    • when it's read off, set into a new variable, or passed
    • compared, it drops the !: card !== this.lastItem
  • Every fixture's TypeScript is back to 0 tsc errors, but CardsFromZero's one, which main's own snapshot has too: Property 'name' does not exist on type 'Pile'.
