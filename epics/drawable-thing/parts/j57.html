For J43, a tag written by hand finds its thing by its id on ANY page, as the thing attribute did, and the id reads as the part of a reference after its #. I chose that over keeping the id for layouts only.

  • <solitaire-tableau id="T1"> is Tableau#T1, in a <spell-app> layout or on a plain page beside a hidden app.
  • Digits are a place, as in a reference: <solitaire-tableau id="1"> is the first tableau made (J47).
  • A tag with an id never makes a thing of its own: until the program has the thing, it shows ⚠ no Tableau named "T9".
    • So a hand-written tag that should make its own thing has no id. The drawable elements demo's ace is found by its class now: <solitaire-card class="ace" rank="ace">.
  • The id is watched: a page changing it makes the tag draw the thing the new id names.
  • A thing="..." attribute written in markup is no longer read: the tag acts as one with no id.
  • As built: "the id IS the thing reference", everywhere.
  • A plain page could no longer show one of a hidden app's things: the drawable elements demo's tableau would lose it.
  • Tags mount before the program makes its things, so each would make one first: it takes the program's places (Tableau#1) and the tag switches things once the program's appears.
  • Both demos and the tests name things by id only; thing= is gone from markup.
