What happens when you edit the program and it recompiles? A page can define a tag only ONCE, so the second compile can't define <solitaire-card> again with the new draw.

  • The editor's runner and <spell-app> both recompile in the same page, many times a session.
  • Spell UI has a swap-in-place mechanism for its own development, but it's dev-only and not reachable from here.
  • the tag is defined once; its element asks the CURRENT program's class how to draw
  • a recompile swaps the class, and every element on the page redraws
  • needs a small hook in Spell UI's element base that knows nothing about spell
  • <solitaire-card-2>, -3 ...: nothing to swap
  • cost: the tag isn't stable, so use 2 (a hand-written tag) can't work; old definitions pile up
  • run each compile in a new iframe, which has its own tag list
  • cost: a big change to every runner, and slower
  • Spell UI's element base gains a spell-free "redefine this tag's class" hook
  • a recompile redraws the elements already on the page, keeping the things they hold
