The element class writes one method per method of its type, e.g. turnOver() { return this.currentThing?.turnOver() }, typed by the type's own parameters. The page's tag calls the class's method when it has one, so a method written there by hand wins; the type's other methods (its super-types') still call the thing, as for javascript.

  • SpellElement took a type parameter, SpellElement<Card>, so this.currentThing is a Card and the call type-checks.
  • A type's method with the name of one of the element's own members (send, on, render ...) would replace it and break the element: the writer leaves it out of the class. The page's tag still has it, calling the thing.
  • The writer's list of those names, TSWriter.ELEMENT_MEMBERS, is checked against a real element by a browser test: a member Spell UI adds later fails that test until it is listed.
