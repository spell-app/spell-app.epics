Inside a <css> block, the language server doesn't show spell's own parse errors, for now.

  • Spell's grammar has no rule for the block yet, so spell reads CSS as broken spell.
  • Without this, every CSS line would be underlined red until that rule lands.
  • The block's CSS errors still show: they come from the CSS checker, not from spell.
  • A TODO in SpellLanguageService.diagnostics() marks the filter for removal.
