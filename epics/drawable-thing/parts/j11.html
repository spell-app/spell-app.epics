A project's drawable types get their elements from ONE line at the end of its compiled module, not from a static block inside each drawable class, as the Element Bridge phase (P3) planned.

  • The plan's Files list had the JavaScript writer, JSWriter, emit a static block in each drawable class that asked core to define its element.
  • Built instead: the project writes one line after everything else, naming every drawable type it declares.
    • It's written by SpellProject.elementsFooterFor(), which combineCompiled() calls.
    • Sub-types of a drawable type count too: a joker that is a card gets its own tag.
    • A project with no drawable types ends exactly as before, so no test fixture changed.
    • Only the project's own types: a library it imports defines its own, as <game-card>.
  • Why:
    • The writers stay untouched. Epic output-targets is rewriting them tonight (its P19 and P20), so a change there would collide.
    • The project's name, which starts the tag, is known to the project, not to the writer of one class.
    • Defining last costs nothing: a tag drawn before it's defined is an unknown element until then, and the browser upgrades it the moment it is. 
class Card extends Drawable { ... }
class Joker extends Card { ... }
class Pile extends DrawableList<Card> { ... }
class Note extends Thing { ... }

spellCore.defineElements("Solitaire", { Card, Joker, Pile })
  • Chosen and built.
  • No change to any writer; the TypeScript target writes the same line, though nothing runs it yet.
  • The project's name is right there.
  • Each class defines itself as it's declared.
  • Every writer (JavaScript, TypeScript, Solid) changes, in the code output-targets is rewriting.
  • The writer would have to be handed the project's name for the tag.
  • No generated line at all.
  • But a class from a library can't tell which project it came from, so its tag can't be named (<game-card> or <solitaire-card>?).
  • And a tag written in markup before any drawing would never be defined.
  • P3's Files list is out of date: the writers are untouched, and spell's project file writes the line.
  • Every compiled project with drawable types ends with one spellCore.defineElements(...) line.
  • Projects without them compile exactly as before.
