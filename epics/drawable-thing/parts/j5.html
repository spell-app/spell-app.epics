A type with a name of several words can only be mentioned AFTER the line that declares it. Above that line, its words read as something else, or as an error.

  • A one-word type can be mentioned first: spell makes a placeholder for it (a "stub"), which the declaration claims later.
  • A multi-word one can't get a stub: spell would have to guess which runs of words are type names, and then ANY run of words could be one ("a big card" would become a type called "big card").
  • That greediness is what caveat C1 guards against (C1): only declared names match.
a bank account has a balance as a number   -- NOT found:  "bank account" isn't declared yet
a bank account aka account is a thing
a bank account has an owner as text        -- found
  • a multi-word type is declared before its first mention, in the same file or an imported project
  • a one-word type works in any order, as before
  • a later phase could add forward references by reading every declaration first (a pre-pass), if they matter
