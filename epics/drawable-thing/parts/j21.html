When you edit Drawable Solitaire in the editor, the game deals again: the cards don't keep their rank, suit, or face up or down across the edit, as P7's goal said they would.

  • Why: the editor's runner runs every program from the top on each compile.
    • runCompiled() resets the runtime, then runs the new code, drawable or not.
    • So the things are all new things, made from the new classes: a new deal.
  • What DOES carry over: the tags, and their CSS (J20).
    • The new deal draws with the new to draw and the new <css>, with no reload.
    • A card still on the page from an earlier run (a second <spell-app> of the same project) takes the new CSS too, but keeps its old drawing.
  • Keeping state would be a hot reload of program state: match each old thing to its new class, copy its properties, and not start the program again.
    • That's for every spell program, not something a drawable type can do alone.
    • No spell program keeps its state across an edit today.
