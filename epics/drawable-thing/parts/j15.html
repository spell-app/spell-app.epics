Spell reads everything between <css> and </css> as plain text, the way a browser reads a <style> tag, so the CSS's braces and angle brackets are never taken for spell.

  • Without it, spell's tokenizer (the step that cuts the text into words and symbols) would read { color: red } as a spell expression inside a tag, and < as the start of another tag.
  • The generic parser's tokenizer has a new setting, a list of raw-text tags: the whole contents of such a tag is ONE text token, up to its end tag.
  • Spell's parser turns it on for css only.
  • The same setting could carry a <spell> block later (P9), if that block needs its contents untouched. 
new Tokenizer({ rawTextTags: ["css"] })   // spell's parser
  • Chosen and built.
  • One small, general setting, tested in the parser package.
  • The CSS reaches the rule exactly as written.
  • No tokenizer change.
  • But fragile: any CSS spell can't read as an expression would fail before the rule ever sees it.
  • Any CSS can go in a <css> block, braces and all.
  • The parser package gains a raw-text tag setting, off unless a language asks for it.
