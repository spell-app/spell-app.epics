In a layout written as markup, how does a spell tag know WHICH of the program's things it draws? For P9 · Spell Inside Markup, and Owen's Klondike sketch (O6).

  • The program makes seven tableau piles; the layout has seven <solitaire-tableau> tags.
  • Each tag has to be bound to one of those piles, so it draws that pile's cards.
 
<solitaire-tableau id="T1"></solitaire-tableau>
<solitaire-tableau id="T2"></solitaire-tableau>

-- in the spell:
get a new tableau with name = "T1"
add it to the tableaus
  • the tag's id finds the program's thing of that type with that name, or a variable of that name
  • what Owen's sketch already writes: id="T1"
  • cost: names must be unique per type; a missing one shows an error in that tag
  • an attribute holds spell: <solitaire-tableau thing="tableau 1 of the tableaus">
  • says exactly which thing, for anything a name can't reach
  • cost: wordier; could come later, on top of A
  • the first <solitaire-tableau> gets the first tableau, and so on
  • cost: moving a tag in the layout silently swaps which pile it shows
  • a spell tag in a layout looks up its thing by its id, by type and name
  • a tag with no match draws an error in its place, not a blank
