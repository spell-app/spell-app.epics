Let a program you edit carry on where it was, rather than start again: in Drawable Solitaire, the cards you'd dealt and turned would still be there after you change a card's <css> or its to draw.

  • Today every compile runs the program from the top: the runtime is reset, and every thing is made again (the starting-afresh call, see the judgement below).
  • Keeping state means, on each recompile:
    • match each old thing to its new class, by its type's name (an old Card to the new Card)
    • copy its properties onto a thing of the new class
    • and NOT run the program's start again (no new deal)
  • It's a hot reload of program state, for every spell program, drawable or not: a possible future epic, not a phase of this one.
  • Hard parts: a type renamed or removed, a property added or retyped, things a list holds, a program's own variables.
  • none in this epic: written down for later, as a possible future epic
