The names a layout's spell can read from its program (the game, the deck) come from the RUNNING program, not from its compiled description of itself.

  • A project's declarations file lists its types and functions, and its rules, but not its top-level things.
    • So {the score of the game} couldn't find the game there.
  • The layout reads the program's module's exports instead, as it runs.
    • Each thing's type is its class, so score of reads a game's score.
    • They're live: the layout always sees the program's current thing.
  • Core's new spellCore.things.exported hands them over.
  • Types, functions and rules still come from the declarations.
  • Chosen and built.
  • No change to what spell writes into its declarations.
  • The cost: the layout's spell reads only once the program runs, which is when it's shown anyway.
  • Everything in one place, readable before the program runs.
  • The cost: a change to spell's declarations, shared with the editor and the language server.
  • Core gives the program's exports out, read-only.
  • A layout's spell knows the program's things, typed by their classes, as the program runs.
