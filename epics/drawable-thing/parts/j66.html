The Python writer reads a template's escapes before quoting it, so a <markdown> block's line breaks come out as line breaks.

  • Why: a template's text parts are kept as written, with javascript's escapes, e.g. \n.
    • The Python writer quoted them again.
    • So Klondike's <markdown> rules came out with a literal backslash-n.
  • Now PY.PyBaseWriter.ASTTemplateString() reads these first:
    • \n
    • \t
    • \r
    • \x, as x
  • No other Python fixture changed.
  • A drawable type's style sheet, javascript's css`...`, is written as its template: a plain string, with no new handling needed.
  • Listed as not ported yet in py's not_ported_yet.json:
    • thing references: thingNamed, thingAtPlace ...
    • the element hand-over: useElement and elementClassOf
    • the css tag
  • Klondike's rules panel shows its line breaks in Python too.
