A spell type's name can be more than one word, with a short name to call it by. Today a type name is one word, so "a bank account is a thing" can't be said. 

a bank account aka account is a thing
a bank account has a balance as a number
an account has an owner as text        -- the short name works too

set savings to a new bank account      -- compiled:  new BankAccount()
for each account in the accounts ...   -- plurals of either name
  • The line declares one type, compiled as the class BankAccount.
  • How each output language writes a name is its own naming map (P11): javascript and TypeScript write types in PascalCase, everything else in camelCase.
  • Afterwards it can be called by either name:
    • "the bank account" or "the bank accounts"
    • "the account" or "the accounts", the short name after aka
  • A drawable one's tag uses the whole name: <game-bank-account> in a games library.

The neat part: "drawable thing" and "drawable list" are themselves multi-word BUILT-IN types.

  • So "a card is a drawable thing" needs no special rule for the word "drawable".
  • It's just a type whose base type happens to have two words, compiled as Drawable (and DrawableList for a drawable list).
  • No adjective rule: adjectives in general ("sortable", "saved") are a future epic, mixins (Q2).

The catch: type mentions get greedier (C1).

  • "a big card" must not read as a type called "big card" unless someone declared one.
  • So only DECLARED names match, the longest first: "bank account" before "account".
  • Every existing example parses the same as before, and the parser is as fast (checked in P1).
