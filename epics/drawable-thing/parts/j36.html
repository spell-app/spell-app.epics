Chose to keep the program's things without changing the compiler: the recompiled program runs from the top as before, but while it loads every pause for ... never ends, and then the last run's things are put in place of what it made. Over: the compiler marking the program's start, so a runner can load the program without running it at all.

  • Why: the program's classes and top-level variables, like Drawable Solitaire's stock, tableaus and game, have to be made by running it.
    • Its functions point at those variables.
    • So the last run's state is copied INTO the new run's top-level things, and its variables keep pointing at them.
  • In Drawable Solitaire it does what the goal asks: the new deal stops at its first pause, the last run's cards are put back, and nothing moves on.
  • What still runs again: everything the start does before its first pause.
    • Its tests print to the console again.
    • A start with no pause runs to its end, then its things are replaced.
    • A start that shows a toast or an alert before any pause would show it again on each recompile.
  • A start that would have started its app only after a pause: the runner starts the app itself, as the last run had it.
