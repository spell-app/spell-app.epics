Owen's own example is unquoted: <ui-button on-click={play a song} />.

  • The browser ends an unquoted value at its first space (caveat C15).
  • So it arrives as three attributes: on-click="{play", then a, then song}.

Chose to rebuild it, in LayoutSpell.holeAttributes().

  • An attribute whose value starts with { takes the attribute names after it, up to the one ending in }.
  • The catch: the browser keeps only the FIRST of two attributes with the same name, so a word used twice is lost.
    • E.g. {the score of the game} unquoted becomes {the score of game}, which then shows ⚠.
    • The Klondike demo's comment says to quote.
Built. Owen's example works as written; repeated words need quotes.Simpler: an unquoted hole is an error that says to quote it. Owen's example would need quotes.

  • A hole with a repeated word needs quotes.
