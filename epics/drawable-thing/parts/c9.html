A drawable thing draws inside its own element, in a shadow root, so the page's own CSS doesn't reach what's drawn there.

  • What stops working inside a drawable thing:
    • Semantic UI's classes, such as ui button: the page's theme styles them, outside.
    • A project's styles.css rules that reach into the card, such as .Pile.stacked .Card.
  • What works instead:
    • Style the type with its own <css> block, in its outline (the CSS In Spell phase, P4).
    • Or style the element from outside, by its tag: .Pile drawable-solitaire-card. That reaches the element's box, not what's drawn inside.
  • This is why Drawable Solitaire is a new example, not a switched Solitaire (J17).
/* Solitaire:  reaches into each card -- not inside a drawable card's element */
.Pile.stacked .Card {
	position: absolute;
}

/* Drawable Solitaire:  the card's tag, from outside */
.Pile.stacked drawable-solitaire-card {
	position: absolute;
}
  • A project that makes a type drawable moves that type's look into its <css> block.
  • Page rules about the card's place on the page target its tag instead.
