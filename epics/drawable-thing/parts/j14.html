A type's <css> block becomes its class's style sheet text, but every line after the first gains two spaces in the compiled file.

  • The CSS is compiled to a static css member, as a backtick string (a template literal).
  • The code that writes a class indents every line of each member, to sit inside the class.
  • Inside a backtick string, those spaces become part of the text: lines 2 and on start two spaces further in.
  • CSS ignores whitespace between rules and declarations, so the styles are the same.
  • The one case it changes: a CSS string value that runs over several lines (rare) would gain the spaces in its value. 
// a card is a drawable thing:
// 	- it has a rank as a number
// 	<css> :host { display: inline-block }  .red { color: crimson } </css>
export class Card extends Drawable {
  ...
  static css = `:host { display: inline-block }
  .red { color: crimson }`
}
  • Chosen and built.
  • The compiled file reads like the CSS that was written.
  • The styles are the same; only a multi-line CSS string would differ.
  • The text is exactly what was written.
  • But the compiled file shows the whole sheet as one long, unreadable line.
  • A type's CSS works as written, and reads as CSS in the compiled file.
  • A CSS string value spread over several lines would gain two spaces per line.
