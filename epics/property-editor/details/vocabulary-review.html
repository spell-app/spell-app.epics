What each new or grown element is called, and the attributes, slots and events it takes. You asked to approve this before any element code is written.

property-editor: Spell UI elements that draw a property editor (a header, folding groups, one field per property) from a schema. You approved the plan, and said: review the vocabulary of every element before coding starts (T1 on the epic page). The names you'll write in pages: the tags, the attributes, their values. Renaming them after the first phase means touching every page that uses them.

Five elements, in this order of nesting:

Element New or grown What it is
<ui-property-editor> new The whole editor: a header, then groups of properties. A <ui-form> underneath.
<ui-property-group> new A folding band of properties ("Color", "Type"). A <ui-section> underneath.
<ui-property> new One property: reads its facts from the schema, picks a control, and draws it in a <ui-field>.
<ui-field> grown The field SHELL: label row (label, actions, readout, info tip), the control, hint, error. Takes over what <brand-field> draws.
<ui-form> grown Binds controls to a thing; grows apply, and editing many things at once.

A schema here means the grown component vocabulary you picked: each property's type, choices, default, label, tip and rules. The page says only how THIS form lays them out (groups, order, which control, hints, presets). 

<ui-property-editor header="Project settings" schema="ProjectSettings" apply="on save">
  <ui-property-group header="Project">
    <ui-property name="title"></ui-property>
    <ui-property name="id" on-leave hint="Renames the project's folder"></ui-property>
    <ui-property name="version" debounce="400"></ui-property>
  </ui-property-group>

  <ui-property-group header="Build" collapsed>
    <ui-property name="targets" as="buttons"></ui-property>
    <ui-property name="listsStartAt" as="buttons"></ui-property>
    <ui-property name="buildFolder">
      <ui-button slot="actions" size="mini" preset="build">Reset</ui-button>
    </ui-property>
  </ui-property-group>
</ui-property-editor>

Kept as today: state, inline, required, disabled, width, the :state(field) that <ui-form> finds it by. New (names in italics are asked about below):

Attribute Kind Default What it does
label text The label; slot="label" for a rich one. Names the control for screen readers.
info text The tip behind the "i" icon at the end of the label row; slot="info" for a rich one. The same word as <ui-section info>. (Q3)
hint text Text under the control; slot="hint" for a rich one. (Q3)
readout text A value shown at the end of the label row ("100%", "+8°"); slot="readout". (Q8)
error text An error under the control, and the error state. <ui-form>'s validation sets its own.
prompt label | text label How the error shows: Fomantic's pointing label (today's), or a plain line (brand-field's). (Q6)
debounce number (ms) bare: 300 Typing writes the value only after this pause. (Q4)
on-leave yes / no no Writes the value only when the cursor leaves the field (an id, say). (Q4)
mixed yes / no no The things being edited disagree: the control shows blank, with a "Mixed" placeholder. Set by the form; typing a value clears it.
Slot, part or state What it is
slot actions Small buttons at the end of the label row (Reset, Auto).
slots label, info, hint, readout Rich versions of the attributes.
parts field, row, label, actions, readout, info, tip, control, hint, prompt
states as today, plus mixed
texts info "More about {label}" (the icon's name), mixed "Mixed"

<brand-field> goes: the brand pages (Theme Creator, Color Set Chooser, the brand home page) switch to <ui-field>.

New Kind What it does
apply immediately | on save When edits reach the thing: at once (default), or all together on Save; Cancel drops them. (Q7)
value (grown) a thing, or a list of things A list edits them all: a field shows the value they agree on, else mixed; a write sets it on all. (Q5)
save(), cancel() methods On the element, for a page's own buttons (a modal's Apply).
ui-save event, cancelable { changes, value }: just before held edits land; preventDefault() keeps them held.
ui-cancel event Held edits were dropped.
:state(changed) state Edits are held, not saved yet.

header, icon, info As <ui-section>'s: title, its icon, its tip.

Attribute Kind What it does
name text, required The property it edits.

Both <ui-field> and <ui-property> draw one field. The difference: a property reads the schema and picks its control; a field holds whatever control you put in it.

Field is the shell, property is schema-driven: each has one job, and ordinary forms never see schema attributes.

<ui-field name="textSize" as="range"> in an editor draws its own control: one fewer tag, but <ui-field> grows the schema's attributes too.
