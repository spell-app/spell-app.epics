You asked: on <ui-section>, the editor and the group, should attached, basic, bordered, dividing, raised, styled become one appearance="basic attached"?

  • For it: they ARE one idea (the box's look), and one attribute groups them in docs and in a property editor (one multi-pick field instead of six checkboxes).
  • Against it, on these three alone: every other Spell UI element writes the same words as attributes of their own (<ui-segment raised attached>, <ui-button basic>). A section saying appearance="raised" beside a segment saying raised is two ways for one word.
  • Also: CSS and scripts test one look with [raised] today; in a list it's [appearance~="raised"]. attached takes a side (top attached), which fits a list fine.

My view: a good idea, but for all of Spell UI at once, not three elements.

These three keep the six attributes, like every other element; a future epic weighs appearance for the whole library (written down as a future epic).
