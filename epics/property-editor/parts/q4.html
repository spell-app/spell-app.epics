Do we write values through <ui-form>'s existing binding, or build the editor's own?

  • <ui-form> already binds named controls both ways to an object (Solid signals, Spell UI members, spell objects), and runs validation rules.
  • It has no debounce, no "on leave", no Apply mode and no "mixed" value for many things.
  • <ui-property-editor> is a <ui-form> underneath
  • the binding grows commit modes and a many-things source; every form gets them
  • one binding for every form; its tests already cover the hard parts (number controls, spell objects)
  • changes reach every form: more to test
  • free to fit the editor exactly
  • two bindings doing nearly the same job
  • FIELD properties, on <ui-field> (and so on each <ui-property>): debounce, on leave, mixed.
  • A FORM property: <ui-form apply="immediately | on save">; “on save” holds every change until Save, and Cancel drops them.
  • The binding carries both; no commit-mode list on the form (P3).
