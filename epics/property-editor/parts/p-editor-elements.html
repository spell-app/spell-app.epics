Nothing turns a vocabulary into fields.

Three new elements, each passing through the words of what it wraps:

  • <ui-property-editor>: most of ui-section's and ui-form's
  • <ui-property-group>: most of <ui-section>'s
  • <ui-property>: a <ui-field> that picks its control

The editor reads a layout page (source, select); control kinds come from a registry.

  • A name an element shares with what it wraps means the same there: it’s passed through, not a new word (Q8).
  • The editor (Q10):
    • schema: what it edits; value: the thing, or a list of things
    • source: the layout page, a spell path inside the spell editor, else a URL; select picks its first match
    • attributes: readonly, output, error
    • events: ui-change, ui-loading, ui-loaded
    • methods: save(), cancel(), validate()
  • The group has no layout page of its own: its select picks from the editor’s.
    • attributes: readonly, state, output, error
    • a changed state
    • events: ui-success, ui-invalid
  • readonly nests: a readonly editor or group passes it to every property inside it.
  • <ui-property> picks its control by type, or by as= (Q13):
    • input, text, number, select, checkbox, toggle, colour, a colour set
    • a slider with named steps (range), for an ordered scale
    • a segmented menu as a button group (buttons)
    • a whole editor, for a property whose value is a thing (editor)
    • any kind added through UI.propertyControls.add()
  • name may be a dotted path (font.size).
  • options names a registered source, or a list.
  • Presets as action buttons.
  • An empty editor shows every property, in vocabulary order, with default controls; “Other” holds what a layout doesn’t place.
  • Works in a side bar, a modal (apply="on save") and a popup.

The words Owen approved (Q8, Q10, Q13):

  • Each element passes through most of what it wraps: the editor, ui-section’s and ui-form’s words; the group, ui-section’s (so it sits on ui-section, not ui-panel: J1); the property, ui-field’s.
  • The editor’s source is its layout page, and select picks from it; the group has no source of its own.
  • Control kinds come from a registry, UI.propertyControls.add(); a property’s name may be a dotted path.
  • readonly on the editor or a group reaches every property inside, as disabled does.
  • Where to see it: Spell UI's new Property Editor page (/components/ui/ui-property-editor.html): From a schema, Laid out, Save and Cancel, Many things; all live, checked headlessly.
  • <ui-property-editor>: a form drawn from its schema.
    • The schema: a tag's vocabulary, a schema the page added, or an object.
    • Empty, it makes a property per attribute.
    • With a header, it draws a section around its properties, passing the section's attributes on.
    • Save and Cancel with apply="on save".
  • <ui-property-group>: a folding section.
    • While a property in it fails: :state(error) and ui-invalid.
    • While one holds an edit: :state(changed).
    • And ui-success.
  • <ui-property>: a field whose label, tip, choices and rules come from the schema.
    • It makes its own control: by as, else by its type's kind.
    • Its name may be dotted.
    • readonly nests (J8).
  • UI.propertyControls: control kinds, choice sources, on-change rules (run after a write), named schemas.
  • Rough:
    • as="buttons" draws radios (I3).
    • No visual baselines yet.
    • Layout pages (source / select) are P6.
