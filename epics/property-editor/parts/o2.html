Three new elements, each built on one Spell UI already has, and two existing ones grown.

  • Each new one PASSES THROUGH the names of the element it's built on: write collapsed on a group as on a <ui-section>.
  • Every name, in full: the vocabulary review's whole set.
Element Built on, and passes through Its own names
<ui-property-editor> most of <ui-section> and <ui-form>
  • schema
  • value: a thing, or a list of things
  • source: its layout page
  • select
  • readonly
  • output
  • error
  • events: ui-change
  • events: ui-loading, then ui-loaded
<ui-property-group> most of <ui-section>
  • select: picks its part of the editor's layout page
  • readonly
  • state
  • output
  • error
  • events: ui-success, ui-invalid
  • state: changed
<ui-property> most of <ui-field>
  • name: may be a dotted path
  • as: which control
  • options: where the choices come from
  • readonly
  • event: ui-change
  • state: changed
<ui-field>, grown the field shell; it replaced <brand-field>, which is gone
  • label
  • description: the tip behind an "i" icon
  • hint: under the control
  • output: a value at the end of the label row
  • error: a plain line under the control, on every form
  • apply
  • mixed
  • rules
  • readonly: nests like disabled
  • a slot for each, and actions
<ui-form>, grown itself
  • apply="immediately | on save"
  • value takes a list
  • validate="immediately | on leave | on save"
  • methods: save(), cancel()
  • events: ui-saving, then ui-saved
  • events: ui-cancelling, then ui-cancelled
  • state: changed
  • The controls are the ones Spell UI has, and as picks one:
    • <ui-input>
    • <ui-select>
    • <ui-slider>
    • a segmented <ui-menu>, as buttons
    • <ui-checkbox>
    • more kinds are added through a registry, UI.propertyControls.add(): the spell editor adds a multiple dropdown for a project's targets
  • A property whose value is itself a thing nests a whole editor inside it (as="editor").
  • <ui-section> takes the same words (Section Renames):
    • label, was header
    • hint, was subhead
    • description, was info
    • events in pairs: ui-opening / ui-opened
    • events in pairs: ui-closing / ui-closed
    • states: :state(nested), :state(in-group)
    • The old names keep working: this repo's pages are swept, the shared pages and spell-epic once the branch merges (C16).
  • The colour pickers come into Spell UI in another pass (C10).
<ui-property-editor label="Project" schema="ProjectSettings" apply="on save" validate="on leave">
  <ui-property name="title" apply="on leave" hint="Shown in the project list"></ui-property>
  <ui-property name="version" apply="delayed"></ui-property>

  <ui-property-group label="Compiling" collapsible>
    <ui-property name="targets" as="buttons"></ui-property>
    <ui-property name="listsStartAt" as="buttons">
      <ui-button slot="actions" size="mini" preset="1">Reset</ui-button>
    </ui-property>
    <ui-property name="build.folder" apply="on leave"></ui-property>
  </ui-property-group>

  <ui-property-group label="Sharing" collapsed readonly>
    <ui-property name="exports" options="declaredNames"></ui-property>
  </ui-property-group>
</ui-property-editor>

<!-- labels, tips, choices and rules come from the schema;
     apply on a property is when ITS edit is taken, apply on the editor is when edits land;
     the readonly group makes every property in it readonly;
     options="declaredNames" names an (async) choices source the page registers -->
