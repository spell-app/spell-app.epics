Three new elements and one grown, nested the way the Theme Creator's panel already is.

  • <ui-property-editor>: the whole editor, a <ui-form> underneath. It takes the thing (or things) to edit and its vocabulary. Its header is the panel's header ("Project").
  • <ui-property-group>: a folding band of fields ("Compiling", "Sharing"). A <ui-panel> underneath.
  • <ui-property>: one property. It's a grown <ui-field> that picks the control for the property's type.
  • <ui-field>, GROWN (Q1): Spell UI's own field becomes the field shell.
    • a label row: the label, an info tip, an actions slot for preset buttons
    • the control, a hint under it, and the error
    • <brand-field> is replaced by it on the brand pages, then deleted: no second field shell, and no new field element
  • The controls are the ones Spell UI has: <ui-input>, <ui-select>, <ui-slider>, a segmented <ui-menu> as a button group, <ui-checkbox>, the colour pickers. A property may ask for another control than its type's default (as="buttons").
  • A property whose value is itself a thing nests a whole editor inside it.
  • Every element's attributes, events and slots are written up for Owen's review before any element code (T1): the names below may change there. 
<ui-property-editor header="Project" vocabulary="ProjectSettings" apply="on save">
  <ui-property name="title" on-leave hint="Shown in the project list"></ui-property>
  <ui-property name="version" debounce></ui-property>

  <ui-property-group header="Compiling">
    <ui-property name="targets" as="checkboxes"></ui-property>
    <ui-property name="listsStartAt" as="buttons">
      <ui-button slot="actions" icon="rotate left" data-preset="1">Reset</ui-button>
    </ui-property>
    <ui-property name="buildFolder" on-leave></ui-property>
  </ui-property-group>

  <ui-property-group header="Sharing">
    <ui-property name="exports" options="declaredNames"></ui-property>
  </ui-property-group>
</ui-property-editor>

<!-- labels, tooltips, choices and validation come from the vocabulary;
     on-leave and debounce are the FIELD's, apply="on save" is the FORM's;
     options="declaredNames" names an (async) choices source the page registers -->
