The spell editor’s Project Settings form is a scaffold of placeholder fields.

A project’s settings get a vocabulary (title, version, targets, lists start at ...).

The page becomes one <ui-property-editor>.

  • The first real use of the editor (Q5).
  • Every setting a project file holds edits and saves.
  • The placeholder fields are gone.

Project Settings was a scaffold no route showed, and nothing could save a project's settings. So P5 also added the server route that writes them into the project file, the project group's saveSettings(), and the editor's Settings button opening the page as a dialog.

  • Where to see it: the editor's top bar, Settings: "<project> settings", a <ui-property-editor> with Save and Cancel (checked headlessly on Solitaire, not saved). Try it on your own project: V1.
  • It edits the project file's settings:
    • title
    • version: must look like 1.2.0, written on leave
    • also-compiles-to targets: a multiple dropdown, a control kind the app adds
    • lists-start-at: 1 or 0
  • A new server route, POST /api/projects/settings/project, writes them into the project file.
    • It keeps the file's imports and comments, and removes a setting left empty.
    • SPACES.SpellProjectRoot.saveSettings() calls it, and updates the loaded project.
  • Fixed: Save and submit now write a field still waiting (delayed, on leave) first.
  • Not editable yet: exports, a list of names.
