The editor writes changes through <ui-form>'s binding, grown. WHEN a value is written is split in two: each field says when it takes an edit, and the form says whether edits land at once or on Save.

<ui-field apply>, and so each <ui-property>'s:

  • immediately, the default: every change is taken at once
  • delayed: after a pause in typing, 300ms; delayed 100 for 100ms
  • on leave: only when the cursor leaves the field (a project's title, an id)

mixed: when the editor edits many things and they disagree, the field shows blank with a "Mixed" placeholder; typing into it sets that property on all of them.

  • apply="immediately", the default: each edit lands in the thing at once.
  • apply="on save": every edit is held until Save (a modal, Project Settings); Cancel drops them.
    • A page's own buttons call save() and cancel().
    • Around a save: ui-saving, then ui-saved.
    • Around a cancel: ui-cancelling, then ui-cancelled.
  • validate="immediately | on leave | on save": when fields check their values.
    • A field showing an error always checks again as it changes.
  • Errors show as a line under the control: from the property's type first, then the schema's rules, the form's rules and the field's own rules. A value that fails is not written.
  • "On change" rules run after a write: setting the font family can change the weights offered.
  • readonly nests like disabled: on the editor or a group, it reaches every property in it.
  • Every <ui-form> gets these, so its existing tests are the guard (C2).
