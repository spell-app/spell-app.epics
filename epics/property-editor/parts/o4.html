The editor writes changes through <ui-form>'s binding, grown (Q4). WHEN a value is written is split in two: each field says how it writes, and the form says whether writes land at once or on Save.

Properties of <ui-field>, and so of each <ui-property>:

  • debounce: a text field waits for a short pause before it writes
  • on leave: the field writes only when the cursor leaves it (a project's title, an id)
  • mixed: when the editor edits many things and they disagree, the field shows a blank "mixed" state; typing into it sets that property on all of them
  • <ui-form apply="immediately">, the default: each write lands in the thing at once.
  • <ui-form apply="on save">: every change is held until Save (a modal, Project Settings); Cancel drops them.
  • No list of commit modes on the form: the binding carries both.
  • Errors show as you type, from the property's type first, then any rule the vocabulary or the form adds. A value that fails is not written.
  • "On change" rules run after a write: setting the font family can change the weights offered.
  • Every <ui-form> gets these, so its existing tests are the guard (C2).
