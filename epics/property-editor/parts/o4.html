The editor writes changes straight into the thing it edits, as the Theme Creator does by hand today, unless it is told to wait for Apply.

  • Live (the default): each change lands at once. A text field waits for a short pause first (debounce); a field marked "on leave" (an id, say) lands only when the cursor leaves it.
  • In a modal: changes are kept in the editor, and land all at once on Apply. Cancel drops them.
  • Many things at once: a field shows the value when every thing agrees, and a blank "mixed" state when they don't. Typing into it sets that property on all of them.
  • Errors show as you type, from the property's type first, then any rule the schema or the form adds. A value that fails is not written.
  • "On change" rules run after a write: setting the font family can change the weights offered.
