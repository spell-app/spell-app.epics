A component vocabulary describes text attributes only; spell classes and JSON have no shape the editor reads.

The vocabulary’s attribute entry grows to describe a value of any type, with what a form needs.

An adapter turns a spell class or a JSON block into one; layout stays out of it.

  • The attribute entry grows:
    • values of any type: number, boolean, list, a nested thing
    • a label and a tooltip as translation keys, apart from the description
    • numeric limits: a lowest and highest value (min, max) and a step size
    • a regex pattern
    • an ordered scale, so “xs ... huge” can show as a slider with named steps
    • where its choices come from: its own list, a named (maybe async) source, or the form
    • validation and “on change” rules
  • Adapters INTO a vocabulary:
    • a spell class: its compiled property info, and its words file for the labels
    • a JSON block: its JSON Schema, else guessed from its values
  • Facts in the schema, layout in the page (Q3): groups, order, which control, hints and presets are NOT in it.
  • No new PropertySpec shape (Q2).

Owen picked a reader in the app for spell classes, for now (Q16): Spell UI never imports spell's packages. So core's jsonSchemaFor() is untouched; T6 weighs reading classes through their JSON Schema later. And the person's tip is its own field, tip (Q15).

  • A vocabulary's attribute can now say what a form needs. All of it is optional: every existing vocabulary is unchanged, and type-checks in spell-solid, ui, brand and app.
    • type: its value's type (text, number, boolean, date, choice, list, thing, data)
    • of: a list's item type
    • attributesOf: a nested thing's attributes
    • label, tip
    • limits: min / max
    • step
    • pattern
    • ordered
    • choicesFrom
    • rules, onChange
  • PropertySchema: what the editor reads, a name and attributes; a component's vocabulary is one already.
  • Spell UI's PropertySchemas reads a component's vocabulary, a JSON Schema, or a JSON block's values (guessing types); and gives any attribute's value type and label (listsStartAt => Lists start at). 6 tests.
  • The app's ClassSchemas.fromClass() reads a spell class's declared properties (types, legal values, defaults, list item types, superclasses first). 2 tests.
  • Not yet: labels from a class's words file (none exist yet; labels come from names); nothing draws a schema until P4.
