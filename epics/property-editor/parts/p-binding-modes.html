<ui-form>’s binding has no debounce, no “on leave”, no Save / Cancel, and no “mixed” value for many things.

On <ui-field>: apply="immediately | delayed [ms] | on leave" and mixed. On <ui-form>: apply="immediately | on save", and validate (was validate-on).

The binding carries both, edits many things at once, and runs the vocabulary’s validation and “on change” rules.

  • On each field (and so on each <ui-property>), apply:
    • immediately (the default): each change is written at once
    • delayed [ms]: a text field waits for a short pause before it writes (delayed 300ms)
    • on leave: writes only when the cursor leaves the field (an id, say)
  • mixed: a blank “Mixed” field when the things edited disagree; the form sets it.
  • On the form, apply:
    • immediately (the default)
    • on save: holds every change until Save; Cancel drops them
  • Save and Cancel: save() and cancel(); ui-saving (can be cancelled) then ui-saved; ui-cancelling (can be cancelled) then ui-cancelled; a changed state while edits are held.
  • validate="immediately | on leave | on save", the default on save, replaces validate-on.
    • A field showing an error always checks again as it changes.
  • No commit-mode list on the form.
  • Many things: the form’s value takes a list; a field shows the value they agree on, or mixed; a write sets it on all of them.
  • Validation comes from the vocabulary and the field’s rules; a value that fails is not written.
  • “On change” rules run after a write (setting A changes B, or B’s choices).
  • Where to see it: the form docs page's Usage tab, Binding: When a field writes, Save and Cancel, Many things (live examples, checked headlessly).
  • Each field says when it writes: <ui-field apply="immediately | delayed [ms] | on leave">; delayed is 300ms, and a committed change (leaving a text field) writes at once.
  • <ui-form apply="on save"> holds every edit (:state(changed)) until save(), which validates first; cancel() drops them and shows the thing again. Events: ui-saving (cancelable) / ui-saved, ui-cancelling (cancelable) / ui-cancelled, with the changes.
  • validate="immediately | on leave | on save" replaces validate-on outright (J3).
  • A list as the form's value edits every thing in it: the value they agree on, else blank, mixed and a Mixed placeholder; a write sets all of them (J4: placeholder on text controls only).
  • <ui-field rules> adds to the form's rules; a value that fails validation is never written.
  • Not yet: "on change" rules come with the schema in P4 (J5).
  • Tests: ui's review passes, 5023 browser tests (+17 across P2 and P3) and 297 server-side.

  • UIField.tsx, UIForm.tsx and their vocabularies
  • a mixed state on input, select, slider and menu
  • ui-form’s existing tests, with validate-on renamed
  • new tests for each field apply, each form apply, and Save and Cancel’s events
  • three things with one differing value: mixed shows, a write sets all three
