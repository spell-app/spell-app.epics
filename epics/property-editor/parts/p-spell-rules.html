  • The rule words, after must (Q21):
    • not be empty
    • match "<pattern>"
    • be at least N letters long, be at most N letters long
    • be between A and B
    • be at least N, be at most N
    • be an email, be a url
    • Then, optionally, with suggestion "..." or saying "..." (its own message).
  • Three places to write one:
    • a line of its own: - its title must not be empty
    • the property’s own line: - it has a title as text, which must not be empty
    • indented under the property: - it must not be empty
  • Two new kinds, as a url and as an email: text that brings its rule with it.
  • A pattern in quotes is read exactly as typed: [a-z] is a set of letters, not a fill-in.
  • Each rule compiles to Fomantic’s rule object, the shape Spell UI’s form checks read: { type: "minLength", value: "3", prompt: "..." }.
    • javascript: declareProp("title", { type: "text", rules: [...] }), or Card.declareRules("title", [...]) for a line of its own.
    • Python: prop(type="text", rules=[...]) and Card.declare_rules(...).
  • The declarations record them (rules on a property):
    • so the spell editor’s property editor checks them with no running program
    • a running class’s schema has them too
    • the JSON Schema for VS Code gets the matching keywords:
      • minLength
      • pattern, with VS Code’s patternErrorMessage
      • minimum / maximum
      • format
  • A program setting a value that breaks a rule: the value is set, and the console warns (title must not be empty, got: ), the same words in javascript and Python.
  • A rule written once on the type is checked everywhere the type is edited or set:
    • the property editor
    • VS Code
    • the running program, javascript and Python
