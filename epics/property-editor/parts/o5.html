The spell editor makes a default editor from a vocabulary, and saves it as a plain-markup page you can tweak by hand: ProjectSettings.editor.html, the first real one.

  • It holds only the markup in 1.2: groups, order, which control, hints, presets, and each field's apply. Everything else still comes from the vocabulary, so the page stays short.
  • <ui-property-editor source="ProjectSettings.editor.html"> loads it as it is, with no build: a spell path inside the spell editor, else a full URL. select picks part of it, and a group's select its own part.
  • A check-and-fix tool compares the page with the vocabulary as it is now:
    • a property the page names that the vocabulary dropped: flagged, or removed with a fix
    • a new property: added to the page, in an "Other" group
    • a control that no longer fits (a list of choices became free text): flagged
  • Validators and "on change" rules: TypeScript first. Written in spell later, in English (and other languages once spell reads them).
  • Compiled: the page and its rules become one TypeScript module defining a custom element (<project-settings-editor>), so it runs where neither the spell parser nor the loader is.
  • Project Settings shows no change landing live, so live editing is proven on the docs pages and the pony (C4).
