The editor reads ONE description of a property, whatever it came from. A small adapter per source turns what that source has into it.

  • A spell class: its compiled property info (type, one-of choices, default, list item type), and its words file for the labels.
  • A web component: its vocabulary (each attribute's kind, values, default, description).
  • A JSON block: JSON Schema if it has one, else guessed from the values it holds.

What the description adds that no source has today:

  • a label and a tooltip, apart from the description, each a translation key
  • numeric limits (min, max, step) and a regex pattern
  • where the choices come from: the schema's own list, an outside (maybe async) function such as "every font installed", or a list written in the form (rare)
  • an ordered scale, so "xs, sm, md, lg, xl, 2xl, huge" can show as a slider with named steps
  • validation rules, and "on change" rules (setting A changes B, or B's choices)
  • when a change applies: at once, after a pause (debounce), when the field is left, or on Apply
const textSize: PropertySpec = {
  name: "textSize",
  label: "theme.textSize",            // a translation key;  English default "Text size"
  tooltip: "theme.textSize.tip",
  type: "choice",
  options: ["xs", "sm", "md", "lg", "xl", "2xl", "huge"],
  ordered: true,                      // a scale:  may show as a slider
  default: "md",
  as: "range",
  commit: "live",
}
