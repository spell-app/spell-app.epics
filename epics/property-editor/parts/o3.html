The editor reads ONE description of a thing: a component vocabulary, the one every Spell UI element is already declared with, grown to describe a value of any type (Q2). No new PropertySpec shape.

  • A web component: its vocabulary as it is (each attribute's kind, values, default, description). describe() returns it at run time.
  • A spell class: an adapter turns its compiled property info (type, one-of choices, default, list item type) into a vocabulary, with its words file for the labels.
  • A JSON block: an adapter reads its JSON Schema if it has one, else guesses from the values it holds.

What the vocabulary's attribute entry grows, that no source has today:

  • values of any type: a number, a boolean, a list, a nested thing, not only text
  • a label and a tooltip, apart from the description, each a translation key
  • numeric limits (min, max, step) and a regex pattern
  • an ordered scale, so "xs, sm, md, lg, xl, 2xl, huge" can show as a slider with named steps
  • where the choices come from: its own list, a named outside (maybe async) source such as "every font installed", or a list written in the form (rare)
  • validation rules, and "on change" rules (setting A changes B, or B's choices)

What stays OUT of it is how one form shows it: groups, order, which control, hints, presets (Q3). And when a change is written is the field's and the form's (1.4). 

// today's fields
{
  name: "lists-start-at",
  kind: "enum",
  values: ["1", "0"],
  default: 1,
  description: "Where the project's lists start counting.",

  // grown (names settled in the vocabulary review, T1)
  type: "number",                 // the value's own type, not only text
  label: "listsStartAt",          // a translation key;  English "Lists start at"
  tooltip: "listsStartAt.tip",
  ordered: true,                  // a scale:  may show as a slider or buttons
  validate: ["oneOf"],
  onChange: ["recompile"],        // named rules, run after a write
}
  • The types: AttributeSpec, in spell-solid, read by Spell UI's $/ui/vocabulary.
  • The adapters: new, in Spell UI (P2).
  • Every element's docs page is the guard that nothing else changes (C1).
