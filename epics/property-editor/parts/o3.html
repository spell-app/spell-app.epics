The editor reads ONE description of a thing: a component vocabulary, the one every Spell UI element is already declared with, grown to describe a value of any type. No new PropertySpec shape.

  • A web component: its vocabulary as it is (each attribute's kind, values, default, description). describe() returns it at run time.
  • A spell class: the app's ClassSchemas.fromClass() reads its declared properties (type, legal values, default, list item type) into one; labels come from the names, since no class has a words file yet.
  • A JSON block: an adapter reads its JSON Schema if it has one, else guesses from the values it holds.

What the vocabulary's attribute entry now has, that no source had before:

  • values of any type: a number, a boolean, a list, a nested thing, not only text
  • a value type (type), a list's item type (of), a nested thing's attributes
  • a label and a person's tip, its own field tip, each a translation key
  • numeric limits: a lowest and highest value (min, max) and a step size
  • a regex pattern
  • an ordered scale, so "xs, sm, md, lg, xl, 2xl, huge" can show as a slider with named steps
  • where the choices come from: its own list, a named outside (maybe async) source such as "every font installed", or a list written in the form (rare)
  • validation rules, and "on change" rules (setting A changes B, or B's choices)

What stays OUT of it is how one form shows it: groups, order, which control, hints, presets. And when a change is written is the field's and the form's (1.4). 

// today's fields
{
  name: "lists-start-at",
  kind: "enum",
  values: ["1", "0"],
  default: 1,
  description: "Where the project's lists start counting.",

  // grown
  type: "number",                 // the value's own type, not only text
  label: "listsStartAt",          // a translation key;  English "Lists start at"
  tip: "listsStartAt.tip",          // the field shows it as its `description`
  ordered: true,                  // a scale:  may show as a slider or buttons
  rules: [...],                   // validation rules
  onChange: ["recompile"],        // named rules, run after a write
}
  • The types: AttributeSpec, in spell-solid, read by Spell UI's spell-ui/vocabulary.
  • The readers: Spell UI's PropertySchemas (a vocabulary, a JSON Schema, a JSON block's values), and the app's class reader (P2).
  • Every element's docs page is the guard that nothing else changes (C1).
