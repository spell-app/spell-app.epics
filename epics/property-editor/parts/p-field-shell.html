The only field with a hint, an info tip, actions and an error is <brand-field>, which Spell UI can’t use.

Spell UI’s own <ui-field> GROWS into the field shell, with the words Owen approved (Q11): label, description (the tip), hint, output, error, an actions slot, rules and readonly.

The brand pages switch to it, and <brand-field> is deleted.

  • Owen approved every element’s words first (T1).
  • <ui-field> draws:
    • a label row:
      • the label
      • the “i” tip (description)
      • an output value
      • an actions slot (Reset, Auto)
    • the control, then the hint under it
    • the error, a plain line under the control, shown as you type
  • Label, description, hint and output are each an attribute, or a slot for the rich version.
  • rules: validation rules for the field’s control, in <ui-form rules>’s shape, added to the form’s own.
  • readonly: shows the value, which can’t be changed.
    • It nests like disabled: a readonly form passes it to every field inside it (the group and the editor, in P4).
  • Errors look the same on every form: a plain line under the control (C5).
  • No new field element, and no naming question: the one Spell UI has grows.
  • Every form that uses <ui-field> today works as before; only its error line looks different.
  • The brand pages use it and look the same; <brand-field> is gone.
  • Where to see it: the form docs page's new Label Row, Actions and Error examples (/components/ui/ui-form.html), and the Theme Creator and Color Set Chooser brand pages, now on <ui-field>, pixel-identical to before.
