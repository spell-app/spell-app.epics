Kickoff prompt

I want to edit the pages in `spell-app-dev` with Claude Design.
I also want to be able to do design-ey things here in VSCode.

How do I do this?

Requirements:
- We want Claude to understand the spell/ui components, custom components built for the brand page, etc -- and have it modify pages / build new ones using the components for everything possible.
- Is there an easy/standard way to teach it about the vocabulary of those components? Can we take advantage of already having the names/attributes/etc sussed out, so it doesn't have to derive the component shape?

- It should only need to load `<ui-root>` and that will load all of the other bits. Will that mess things up?
- Where will it load the `<ui-root>` script and other scripts? Do I have to have that somewhere public for it to be able to find it? Would pushing a build of spell/ui components (and other components) statically in that folder. I want to be able to update components, then tell it to reload without a publish step.
- How do we handle the brand-specific components?

- I'm thinking that e.g. the plan docs should move to individual fragments for each phase, question, front matter, etc, and use <ui-include> to load the bits individually when they are displayed. That should fix flickering/scrolling problems in e.g. VSCode, and may be quicker for claude scripts to work with because they are self contained. We also won't be loading things that aren't visible.

Also, I want to be able to edit the spell/ui pages, which I think means moving them into `spell-app-dev`. ?

And I want to reorganize the folders in spell-app-dev to root level folders:

```
agents/
brand/
goals/
epics/
ui/ => spell/ui docs
templates/
guides/ => all pages which are currently in Guides section of the docs home page
```
And I want a pony.
