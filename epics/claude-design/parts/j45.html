Chose an OVERLAY in the page server over extra mounts or links, because it works the same for every checkout's own server and for worktrees on the main server, and no page link changes.

  • Overlay (chosen): StaticHandler.overlays, a new generic hook: a URL path served from another URL path when a file is there. The page server adds uiBuildPath(): /ui/_assets/x and /ui/_data/x come from packages/ui/site/, the same under /worktrees/<w>/ (that worktree's build). The rest of /ui/ is just the root's ui link, served by the / mount; the old UI_SITE mount is gone.
  • Extra mounts (/ui/_assets, /ui/_data): fine for one checkout, but each worktree on the main server would need its own pair.
  • Links inside the shared ui/ pointing at packages/ui/site/_assets: impossible, the shared folder is one copy for every checkout, so a link would pick one checkout's build.

Net effect:

  • every page's _assets/site.js, ../_assets/site.css, _data/... links work unchanged
  • a file the build lacks falls through to the pages: that's how ui/_data/search.json is served
  • old /packages/ui/site/<page> URLs redirect to /ui/<page> once the old file is gone (movedUiPage())
  • live reload: the build's changes are reported at /ui/... (LiveReload servedAt); before, a rebuilt bundle never reloaded /ui/ pages (its path was /packages/ui/site/_assets/..., the page loads /ui/_assets/...): fixed in passing
