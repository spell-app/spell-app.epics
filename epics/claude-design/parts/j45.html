Spell UI's built files reach its shared pages through an OVERLAY in the page server. It works the same for every checkout's own server, and for worktrees on the main server; no page link changes.

  • Overlay (chosen): a new generic hook, StaticHandler.overlays.
    • It serves a URL path from another URL path, when a file is there.
    • The page server adds one, uiBuildPath().
    • With it, the site's assets and data under /ui/ come from ui's site.
    • The same under /worktrees/<w>/, from that worktree's build.
    • The rest of /ui/ is just the root's ui link, served like any root folder.
    • The old UI_SITE mount is gone.
  • Extra mounts for /ui/_assets and /ui/_data: fine for one checkout, but each worktree on the main server would need its own pair.
  • Links inside the shared ui folder, pointing at ui's built assets: impossible.
    • The shared folder is one copy for every checkout, so a link would pick one checkout's build.
  • Every page's links to the site's script, styles and data work unchanged.
  • A file the build lacks falls through to the pages: that's how the shared search index is served (search.json).
  • Old page URLs under /packages/ui/site/ redirect to /ui/, once the old file is gone.
    • That's movedUiPage().
  • Live reload: the build's changes are reported at the URLs the pages load them from.
    • That's LiveReload's servedAt.
    • Before, a rebuilt bundle never reloaded /ui/ pages.
    • Its change came at its old path, but the page loads it from /ui/_assets/.
    • Fixed in passing.
