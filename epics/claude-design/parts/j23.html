The reorg's repair is one function that can be run again and again. The move ran it once, and spell dev shared repair and every shared commit run it after.

  • It lives in relocate.js, generalized with the reorg's path table.
    • REORG_MOVE
    • reorgPath()
    • reorgShared()
  • Why not a one-off script: older checkouts keep writing the old way until they merge (see C13).
  • spell dev shared repair runs, in order:
    1. the content move's repair
    2. then the reorg's (--shared)
    3. then it links the checkout
  • spell dev shared commit runs the reorg's repair first.
    • About 80 ms; quiet unless it changed something.
    • It uses the CLI's own copy of the tool, whatever the session's checkout runs.
    • Removed with the old-path links (T1).
  • Plan docs are rewritten under their .lock, as spell dev plan-doc takes it.
    • The move itself waited for every plan doc's lock.
  • A re-run only rewrites prose MENTIONS in files it moves just then.
    • A page left in place may name an old path on purpose.
  • A worktree cut before tonight can merge main and run spell dev shared repair: nothing to do by hand.
