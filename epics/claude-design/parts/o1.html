Claude Design builds on a design system: an artifact on claude.ai that holds a brand book, tokens, and a component library. Every design made "with" that system loads its library, so Claude draws with our real <ui-*> elements instead of inventing look-alikes.

  • What a design system holds: the claude.ai "Design System" artifact type, its files in a project folder.
    • a README: the brand book, which every reader starts from
    • the tokens: colors (light and dark), type scale, spacing, radius
    • ONE classic script, the bundle, that assigns a global namespace: no import, no network
    • the bundle's CSS, and its types, which Claude Design reads as docs
    • per component: a README of guidelines, and a live preview card
    project/
  README.md                      the brand book
  tokens.json                    colors, type scale, spacing, radius
  components/
    bundle.js                    one classic script:  window.<namespace> = ...
    bundle.css
    index.d.ts                   types, read as docs
    <Comp>/README.md             guidelines
    <Comp>/preview.html          a live card
  • Claude Code's own /design-sync handles React libraries only. We don't need it: a design system takes any single-script bundle, and custom elements register themselves when that script runs.
  • Ours is the Spell design system, a new private artifact (Q16, J7), not Owen's older Claude Design project, which is in the repo at spell-design-system/.
    • that one is React mock-ups drawn from reference images ("No codebase or Figma was provided")
    • the Spell system is built from the real elements instead, and reuses its brand book and tokens
  • Proven by the spike (P1): the real elements render in the system's cards and on a Design canvas; clicks work in the focused (Play) view only (C10).
