The design system has one card per family, named for its main tag, not one card per tag (97).

  • E.g. the Button card holds three tags:
    • ui-button
    • ui-buttons
    • ui-or
  • Why: the format's cards are components a reader picks from.
  • Sub-tags only make sense inside their family.
  • Seven groups, in order, with their card counts:
    • Actions 1, Forms 9, Navigation 5, Feedback 7
    • Overlays 4, Layout 10, Display 22
  • A family takes the group of its FIRST topic that maps, in its vocabulary's own topic order.
  • Card names come from the main tag: the Content parts family's card is Header.
  • Previews: the family's first 3 example sections.
    • types.html first.
    • Minus any that load a file (source=).
    • <ui-item> has no examples: it borrows the first section that uses it.
  • The types file (index.d.ts) still has a props type for all 97 tags.
