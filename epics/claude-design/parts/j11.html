The two editor files are written beside components.json and committed, not only into the design export.

  • Written by ElementManifests, which ui's site data script calls (gen-site-data.ts).
  • Why: editors need them with no build.
  • And a vocabulary change already means running yarn site:data.
  • custom-elements.json, the Custom Elements Manifest 2.1:
    • 58 modules, 97 tags
    • attributes, events, slots, parts, states, and each family's CSS tokens
    • the root package.json's customElements points at it
  • html-custom-data.json, VS Code's: every tag, attribute (and alias) and value, with markdown hover docs.
  • The repo's VS Code settings load it (settings.json, html.customData).
    • That file is tracked, and every package window's first folder is the repo root, so every window gets it.
    • Not the window files (workspaces/*.code-workspace): they're skip-worktree locally.
  • A test fails while they're stale (DesignExport.test.ts).
  • The formatter already skips their folder, site/_data/.
