Each body lives in epics/<name>/parts/<id>.htm: o3.htm is Overview 1.3, p2.htm phase 2's Goal / Done / Files / Verify, q7.htm Q7's details, log.htm the log. Chose this over numbered files or one file per top-level section, because an id is already unique in the doc, is what Owen and the agents say in chat, and never changes (the rules forbid changing ids).

  • why .htm, not .html: every page walker takes .html files only (the docs index, docs update, the link repairs). That includes checkouts on OLDER code, which would otherwise list hundreds of part files as pages in the shared docs home.
  • a part's relative links are relative to parts/ (one ../ more than the skeleton's), because the loader rewrites them against the file they came from. plan-doc.js rebases them both ways.
  • each part starts with a one-line comment saying whose body it is.

Net effect:

  • a split doc is a skeleton plus a parts/ folder of .htm fragments
  • agents edit a body's prose in its part file (the epic skill and plan-doc.md, "Parts", say so)
