A body that fails to load shows one plain error line, and the next open tries again. The section loads no ui-* families for its body, and has no ui-insert event.

  • On a failure:
    • it fires ui-error, which can be cancelled, with { kind, source, error }
    • the section gets :state(error), and el.load() rejects
    • unless the event is cancelled, one line goes above the placeholder: <p class="source error" part="error" role="alert">Couldn't load parts/p3.html.</p>
    • that line lives in the shadow content box; not a <ui-message>, which would pull in another family
    • a failure isn't remembered: fold and unfold again, and it fetches again
  • The section does NOT load the ui-* families a body uses.
    • The include does, through RootLoader.
    • A body is light DOM, the page's own: a <ui-root> (it watches its subtree) or the page's bundle defines its tags, as for any markup on the page.
    • Plan docs load the one-file spell-ui.js, which defines every tag.
  • Left out, since P3 doesn't need them:
    • ui-insert, to edit the fragment before it goes in
    • load="visible|idle" modes
    • to touch the body after it's in, listen for ui-load
