Spell UI's site data is split by what each file is built FROM. A shared file built from per-branch data, or the reverse, goes stale in every other checkout.

  • The search index (search.json, every page's sections) is built only from the pages: shared now.
    • It's search.json in the shared ui folder.
    • One yarn site:data, from any checkout, brings it up to date for all; no commit.
    • Kept tracked, every page edit would have left each branch's copy stale until that branch rebuilt and committed it. (SiteDataBuilder.test.ts would fail meanwhile.)
  • The per-family facts kept by hand (pages.json) stay tracked.
    • They feed components.json, which is per branch.
    • Shared, a summary edit would make every branch's committed components.json stale.
    • And a branch adding a family would seed entries main doesn't have.
  • Built from the vocabularies, tracked as before:
    • components.json, icons.json
    • custom-elements.json, html-custom-data.json
  • SiteDataBuilder.searchFile is the shared search index (new option pages). The tracked copy is deleted.
  • SiteDataBuilder.test.ts still checks it.
    • It fails in every checkout after a section edit, until someone runs yarn site:data, once.
