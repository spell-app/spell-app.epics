Chose to split _data/ by what each file is built FROM, because a shared file built from per-branch data (or the reverse) goes stale in every other checkout.

  • search.json (every page's sections) is built only from the pages: shared now (ui/_data/search.json), so one yarn site:data from any checkout brings it up to date for all, no commit. Kept tracked, every page edit would have left each branch's copy stale (SiteDataBuilder.test.ts failing) until that branch rebuilt and committed it.
  • pages.json (hand-kept per-family facts) feeds components.json, which is per branch: shared, a summary edit would make every branch's committed components.json stale, and a branch adding a family would seed entries main doesn't have. So it stays tracked.
  • components.json, icons.json, custom-elements.json, html-custom-data.json: built from the vocabularies, tracked as before.

Net effect:

  • SiteDataBuilder.searchFile is ui/_data/search.json (new option pages); the tracked copy is deleted
  • SiteDataBuilder.test.ts still checks it: it fails in every checkout after a section edit until someone runs yarn site:data, once
