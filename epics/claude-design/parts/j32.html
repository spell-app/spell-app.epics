Each part file is named for its block's id: o3.htm is Overview 1.3, q7.htm Q7's details. It lives in the epic's parts folder.

  • Examples:
    • p2.htm: phase 2's Goal, Done, Files and Verify
    • log.htm: the log
  • Not chosen: numbered files, or one file per top-level section.
  • Why the id:
    • it's already unique in the doc
    • it's what Owen and the agents say in chat
    • it never changes (the rules forbid changing ids)
  • Why .htm, not .html: every page walker takes only files ending in .html.
    • The docs index, docs update, the link repairs.
    • That includes checkouts on OLDER code, which would otherwise list hundreds of part files as pages in the shared docs home.
  • A part's relative links are relative to the parts folder: one ../ more than the skeleton's.
    • The loader rewrites them against the file they came from.
    • The plan-doc tool (plan-doc.js) rebases them both ways.
  • Each part starts with a one-line comment saying whose body it is.
  • A split doc is a skeleton, plus a parts folder of .htm fragments.
  • Agents edit a body's prose in its part file.
    • The epic skill says so, and so does plan-doc.md, "Parts".
