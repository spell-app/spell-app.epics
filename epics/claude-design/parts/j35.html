An edit used to write the file three times in about a second (the edit, then doc-links.js, then yarn vp fmt), and the page patched itself after each. Now links (linkText()) and formatting (format() from vite-plus/fmt, with the repo's own fmtConfig from vite.lint.ts) run in memory, and each file is written once, through a temp file and a rename, only when its text changed: parts first, then the skeleton. Chose the in-process formatter over vp fmt on temp files because it is ~0.5 s faster per edit; its output matched vp fmt byte for byte on this doc.

  • edit() is async now (the formatter is), under FileLock.runAsync: same lock as before

Net effect:

  • one change event per changed file per edit; a log line rewrites only parts/log.htm, closing an item only the skeleton
