A plan-doc edit now writes each changed file once, with links and formatting done in memory.

  • Before: an edit wrote the file three times in about a second, and the page patched itself after each.
    1. the edit
    2. then the link tool (doc-links.js)
    3. then yarn vp fmt
  • Now links and formatting run in memory:
    • links: linkText()
    • formatting: format(), from vite-plus/fmt
    • with the repo's own format settings (fmtConfig)
  • Each file is written once, and only when its text changed: parts first, then the skeleton.
    • Through a temp file and a rename.
  • Why the in-process formatter, over vp fmt on temp files: it's ~0.5 s faster per edit.
    • Its output matched vp fmt byte for byte on this doc.
  • edit() is async now, since the formatter is.
    • It runs under FileLock.runAsync: the same lock as before.
  • One change event per changed file, per edit.
  • A log line rewrites only the log's part (log.htm).
  • Closing an item rewrites only the skeleton.
