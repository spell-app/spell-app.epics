The design bundle is a --design flag on the docs' bundle script, not a script of its own. It writes into P7's design-system folder, and there's no bundle.css.

  • The script: bundle-spell-ui.js.
  • Why not a sibling script: that script runs its build on import.
    • So a sibling couldn't import its helpers without a refactor.
  • One esbuild config and one resolver serve both bundles; the docs build is byte-identical to before.
  • Where it writes: --out <dir>, else bundle.js.
    • That's inside what spell dev design build (P7) writes, and ignored by git.
    • Not ui's dist/, which ui's next build wipes.
  • No bundle.css:
    • every element adopts its own sheets
    • ThemeSheets.apply("spell") adopts the theme on the page
    • page typography is ui's opt-in class="ui-typography" on the body; the design system's README should tell Claude Design to use it
  • yarn design:bundle, in packages/docs, builds it.
    • It builds solid-element and ui first; --skip-ui-build reuses them.
  • A reader that expects a bundle.css finds none.
