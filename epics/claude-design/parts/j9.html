Chose primary, violet-500, space-m over the custom properties' own names (ui-primary, spell-violet-500), because the design system compiles tokens.json into UNLAYERED :root rules, which beat our @layer ui.tokens / ui.theme rules of the same name. Same names would freeze every --ui-* colour at the light theme's value (light-dark() gone) in every preview and Design.

Net effect:

  • every row's usage names the property it mirrors, e.g. primary: --ui-primary
  • the README tells a design to write var(--ui-primary) in page CSS; the prefix-less names are for the system's own Colors / Spacing views
  • a test fails if a colour token starts with ui- or spell-
