The design system's token names drop our ui- or spell- prefix. Same names would let the system's styles override the live elements.

  • E.g.:
    • primary
    • violet-500
    • space-m
  • Not the custom properties' own names, like ui-primary or spell-violet-500.
  • Why: the design system compiles tokens.json into UNLAYERED :root rules.
    • Those beat our layered token and theme rules of the same name.
    • Same names would freeze every --ui-* colour at the light theme's value (light-dark() gone), in every preview and Design.
  • Every row's usage names the property it mirrors.
    • E.g. primary: --ui-primary.
  • The README tells a design to write var(--ui-primary) in page CSS.
    • The prefix-less names are for the system's own Colors and Spacing views.
  • A test fails if a colour token starts with ui- or spell-.
