The design system is generated from the elements' vocabularies, so nothing is guessed: one command, spell design build (P3).

  • Each tag has a vocabulary file, <tag>.vocabulary.en.ts.
  • yarn site:data gathers all of them into one file, components.json.
  • That's 760 KB: 97 tags in 58 families, plus 391 foundation tokens and 27 themes.
export const buttonVocabulary = {
  tag: "ui-button", topics: ["buttons"], aka: ["btn"],
  attributes: [
    { name: "size", kind: "size", description: "Size, `mini` ... `massive`" },
    { name: "primary", kind: "keyOnly" },
    { name: "type", kind: "enum", values: ["button", "submit", "reset"], default: "button" },
  ],
  events: [{ name: "ui-toggle", detail: "{ active: boolean, originalEvent?: Event }" }],
  slots: [{ name: "" }, { name: "icon" }, { name: "label" }],
} as const satisfies ComponentVocabulary

The generator, in Spell UI (J8), turns them into every format a reader wants:

Output Read by From
components/index.d.ts Claude Design attributes, events, slots, as typed tag attributes
components/<Comp>/README.md Claude Design description, attribute table, slots, events, one example
components/<Comp>/preview.html Claude Design's cards the 181 example files in src/components/*/examples/elements/
tokens.json Claude Design foundation tokens and the spell-brand theme
custom-elements.json the web-components standard; tools and Claude in VS Code the same data
VS Code html.customData VS Code autocomplete and hover docs for <ui-*> in any .html the same data
  • What it writes: 70 cards (59 Spell UI, 11 brand), each a README and a live preview, a cover, the brand-book README with a Consuming section (plain markup, any Font Awesome Free icon), and every token: 451 colours, light and dark.
  • The Custom Elements Manifest (custom-elements.json) is the standard answer to "teach a tool our elements". Spell UI's never-run analyzer script couldn't read the vocabulary objects, so the generator writes it from components.json instead.
