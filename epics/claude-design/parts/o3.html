The bundle is uploaded INTO the design system as a file, so nothing has to be public, and nothing goes to npm. Claude Design can't reach your laptop (localhost is blocked; only a few CDNs and the system's own files load), so an update is one sync command, not zero steps.

  • <ui-root> is fine. It loads each family with import(), and the one-file build turns those into inline code.
    • the docs' spell-ui.js is a classic script: 2.7 MB, about 800 KB zipped
    • its build fails if any import() survives
    var SpellUI = (() => {...})()
  • The design bundle (P8) is that build minus the docs-only parts (the docs page runtime, the site header, the saver), with the Spell theme applied: about 5 MB, under Claude Design's 6 MB cap (C19).
    • icons: every Font Awesome Free icon is inlined, 2,159 SVGs under 2,889 names (J14)
    • the code and markdown engines and Spell's highlighter are inlined too (Q15); emoji names are left out, and draw nothing
    • every <!-- and </script is escaped; the build fails on one left, on an import(), or over 6 MB
    • fonts: the spell theme uses local Palatino only, so a design shows a fallback serif unless we ship a font file
  • The update loop (P10):
    1. change a component
    2. in Claude Code: /design push (builds, bundles, checks, then sends only the changed files)
    3. reload the design in Claude Design
  • Alternatives not taken: publish ui to npm and load it from jsDelivr (a real publish, and solid-element is private); host it on GitHub (jsDelivr's npm path is the allowed one, and its cache lags).
