A section's body loads through one small shared helper in the element core, SourceBody.

  • Not chosen: making the section a SourceElement.
    • That base is for elements that SHOW a text file: inline text, edits, save(), its own render.
  • Not chosen: having the section put a hidden <ui-include page-styles> inside itself.
    • That's an extra element between the section and its content.
    • It breaks ui-section > p-style selectors, and every reader that walks a section's children.
  • One fetch path: UI.sources.load(), the cache <ui-include> uses.
  • The include's markup handling moved out of UIInclude.tsx into SourceMarkup.ts, now used by both. It:
    • parses the <body>, or the select match
    • rewrites relative URLs
    • guards against cycles and nesting too deep
  • SourceBody loads the body once and inserts it.
    • It fires ui-load or ui-error.
    • It can load again: reload().
    • SourceBodyHost gives the element its own load and reload methods (el.load() ...).
  • Once loaded, the body sits DIRECTLY in the section: <ui-section source="parts/p3.html"><p>...</p></ui-section>.
  • The include's constants moved to the core, elements.types.ts:
    • the three:
      • URL_ATTRIBUTES
      • ORIGINAL_PREFIX
      • MAX_DEPTH
    • moved from ui-include.types.ts
    • the docs site's shell and ExampleSource.ts import them from the core now ($/ui/core)
