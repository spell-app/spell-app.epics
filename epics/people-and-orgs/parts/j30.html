Everything spell compiles for a project now lands in one folder that's never checked in, build/ at the repo root, at the path the project has under packages/.

  • e.g. Solitaire, in spaces' @spell/examples/solitaire/, builds into the same path under build/
    • when this call was made, both were under spell's old projects/system/examples/Solitaire/
  • Owen picked a build folder that mirrors the projects (the layout page, Q1). The call here is the exact rule: the path after packages/, so the build folder has no packages folder of its own.
  • The files that go there:
    • the program, Solitaire.spell.js
    • the TypeScript and Python programs
    • a Python program's page file
    • the scope pack
  • What stays beside the source, checked in: declarations, words, a library's .lib.ts, the Python web app
  • One function decides it, buildFolderFor(), inside the one mapping from a project to its files on disk, so every reader follows it
  • a fresh checkout or worktree has no compiled output until something compiles it: the page server as it starts, the app on demand, or spell compile
  • a compile leaves nothing new to commit
