The analysis wrote a file's type and version together, as "$schema": "spell:person@1" (Q3). Two of Owen's later notes pull it apart:

  • In a comment on the plan: schema references can come from any "spell address".
  • On upgrades (Q14): the version "is written into file as @version rather than file name".

Chose a spell address naming the type over keeping the analysis's form, because it then works for any type in any project, Owen's own included, and the version has a field of its own. 

{
  "$schema": "@spell:library/people/Person",
  "@version": 2,
  "nickname": "Owen",
  • VS Code can't read a spell address by itself: the spell extension turns it into JSON Schema (P5).
  • The address's exact form follows the address mapping question (Q15).
  • A file's "$schema" is the address of its type; its "@version" says which version
  • No version in a schema's name anywhere
