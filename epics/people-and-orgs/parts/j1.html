  • A drawn part: a thing of a kind declared a drawable thing or a drawable list. The page draws each one in an element of its own.
    • In the Solitaire test game: each card (<solitaire-card>) and each pile.
    • Not the game itself (an app), and not the deck (a plain list of cards).
  • Saved inline today means written whole, inside what holds it, with no id and no entry of its own: a person's dated events.
  • Every other thing is an ENTRY of its own, keyed by its id; what holds it writes a reference, {"@ref": "Card#card-a1b2c3d4"}.

Own entries, or own files? The saver makes entries, not files.

  • Where each entry goes is up to whoever stores it.
  • The only store planned, the people store (P9), writes one file per entry.
  • Nothing saves a game yet.
  • But a store that followed Q9's "things are in their own file" would write a whole game as 67 files: the game, the deck, 13 piles and 52 cards.

Why drawn parts were kept out of inline: one card, held in two places.

  • The test game deals each card into the stock without taking it out of the deck, so the deck and the stock hold the same 52 cards.
  • Each foundation sits in two lists too, the foundations and all the piles.
  • Written whole at every place, a save would read back with 104 cards, and two of each foundation. Turning a card over in the stock wouldn't turn over the deck's copy.
  • That's the bug this epic's saving phase (P2) fixed: "a card in two piles comes back as two cards."

/** Is `thing`'s kind saved inside what holds it (`static savedInline = true`)? */
function isSavedInline(thing: SpellObject): boolean {
  return (thing.constructor as { savedInline?: boolean }).savedInline === true
}
