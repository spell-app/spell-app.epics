How a title key would work:

  • Where it's written: the project file, one optional key: "title": "Todos - Form Based". Today that's project.json; JSON Five Everywhere (P12) renames it __project.json5, key and all.
  • The default, with no key: the title made from the folder name, as today: drawable-solitaire shows as Drawable Solitaire.
  • Read in two places on the server:
    • A project's index, which already copies the file's version, exports, targets and listsStartAt. SpellProject.title returns the key, or the made-up title.
    • A group's project list. This is the bigger half. Today the list is just addresses, and the editor's menus make each name from the address without loading the project. So the list would read each project's file as it lists, and send a title with each address.
    • That list's new shape reaches the group model, the answers to create, rename, duplicate and delete (they send the list back), the spell command's project list, and the API tests.
  • What shows it:
    • the editor's project menus (ProjectDropdown.tsx)
    • its notices, "Created app Todos - Form Based."
    • the spell command's picker, which today shows the kebab name and its group, cards @spell/library. It would add the title after the name: you still type the name, so the name stays first.
  • What writes it: creating or renaming a project in the editor. You type "Todos - Form Based"; the folder becomes todos-form-based, and the title is kept only when it differs from the one the folder name would make. Duplicating copies it.
  • What doesn't change: built files and the command's messages keep the kebab name (this item).
  • It survives saves already: when the server tidies a project file's file list, it writes back every key it read. Comments survive from P12 on. 
/** Its name for people, from its `projectName`:  `drawable-solitaire` => `Drawable Solitaire` (decision Q39). */
get title(): string {
  return SP.SpellLocation.titleFor(this.projectName ?? "")
}

// with the key:
get title(): string {
  return this.contents?.title ?? SP.SpellLocation.titleFor(this.projectName ?? "")
}

The key's name: you wrote $title. I'd write it "title", with no mark, but it's your call:

  • A project file's own settings are plain keys: imports, version, exports, targets, listsStartAt, and the spaces page's planned components and prefix.
  • A $ key is a saved thing's bookkeeping, not one of its fields: $schema, $type, $id, $ref. That's why those kept their $ (J50).
  • $title would be the only $ key in a project file.
  • Like the project file's other settings.
  • "title": "Todos - Form Based"
  • Marks it as spell's own key, not a field you made.
  • Cost: the one $ key among plain ones; the $ means something else elsewhere.
  • a project file may hold "title"; with none, the title is made from the folder name, as now
  • a group's project list sends each project's title with its address; the editor's menus and the command's picker show it

  • "Todos - Form Based" and "FizzBuzz" get their titles back in their project files
