Owen decided the first question of the judgement call on a file's schema and version (J3): every internal key of saved JSON starts with $. This phase makes the switch, and reads a version at the end of a type's address.

  • An internal key is one the JSON uses for itself, never a property of the thing:
    • @type becomes $type, a thing's kind
    • @items becomes $items, a list type's items
    • @ref becomes $ref, a reference in a saved file
    • @id becomes $id, a thing's number in a page's state
  • Why here, and not in the schema or versions phases:
    • No file is saved for real yet, so the switch is cheap now. The people store (P9) writes the first one.
    • This phase already changes both cores' savers and the address reader.
    • Every later phase writes these keys, so they should read $ from the start.
  • The address of one version, Person$v2, comes here too.
    • @ already means a space or a place in an address, so Person@2 would read as a place called "2".
    • $ appears in no address form, so $v2 at the end is unambiguous.
  • The version key itself, $version, waits for Versions And Upgrades (P6). Where a file writes its version is still open (Q19).
