Addresses use a slash now (Owen's round-7 note), so three kinds of address have one shape after the project.

  • The colon used to say "a file or a type in the project follows".
  • A slash said "a page of the running app follows".

Now these have one shape:

  • owen@spell/solitaire/rules: a page of the running app
  • owen@spell/solitaire/Card.spell: a file
  • @spell/library/people/Person: a type

Where the project ends is already found by a lookup (the longest project name that exists, as the address mapping decision says); only what comes after it is unclear. Asked on the spaces page, Q13, where Owen can answer.

So nothing is read from a name's case or its dot. Two slashes step from a place, a space or a project in it, to a thing inside that place; one slash stays for the parts of a place, and for a page of the running app.

A file and a type both follow the two slashes. Which one is meant comes from where the address is used: a "$schema" or a reference names a type; a URL or a project's file list names a file.
