ElementDefinition moved to $/spell-solid, as P17 says, but most of what it does is Spell UI's vocabulary layer. I kept that layer in Spell UI, and spell-solid reaches it through its settings.

  • the vocabulary layer:
    • the registry of translated names, Vocabulary
    • Fomantic's value sets, ValueSets: hues, sizes ...
    • the converters
    • the shared attributes: disabled, animation ...
    • the class words, ClassBuilder
  • the settings: SpellSolid.settings.words, which Spell UI hands it as Spell UI's core loads (SpellUISettings.ts)
  • The vocabulary's TYPES moved with it, since every set's elements are declared by one, and the component base is typed by it.
    • vocabulary.types.ts:
      • ComponentVocabulary
      • Dictionary ...
  • Their few Spell UI names (value sets, topics, animations) are "registries" Spell UI fills in, by augmenting spell-solid's interfaces (declare module).
    • so these still fail TypeScript in every set (checked): values: "huez", a wrong topic, a wrong elementSetup.animation
  • About 18 settings, as the spaces page guessed: runtime, words, styles, focus, motion, warn.
  • spell-solid holds no Fomantic words: value sets, class words and animations are Spell UI's
  • the vocabulary's types move, with three registries Spell UI fills in
  • about 1,450 more lines, Fomantic's value sets and the shared vocabulary's animations among them
  • spell-solid would hold Spell UI's words, and node's vocabulary tools would reach into it
  • simpler, but narrows P17's list: the element bases would ask Spell UI for each tag's definition
  • spell-solid imports only util's generic files and Solid (its barrel test pins it)
  • a set other than Spell UI would hand spell-solid its own vocabulary layer, through the same settings
