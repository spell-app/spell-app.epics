Owen's note on the __ names (Q33) is about files, but its reason reaches a type's version too: an address can be typed in a shell, and spell ... @spell/library/people//Person$v2 loses its $v2 there (bash and zsh read it as an empty variable).

Form In a shell What it costs
Person__v2 (picked) as it is a type's name may not end in __v and a number (the reader refuses one); spell's types are PascalCase, so none does
Person@v2 as it is goes against Owen's own reason for $v2 (J3): "so we don't conflict with @ in addresses"; a reference, Type#id@place, would read badly
Person+v2 as it is no spell name can hold a +, so nothing to refuse; but a new mark, used nowhere else
Person$v2 (as before) needs single quotes none
  • Picked __v2: the same swap as every other $, in Owen's words "use __ instead of $".
  • Not a dot (Person.v2): after // a dot reads as a file's extension, and Owen asked that nothing be read from a dot.
  • One Address Scheme's second half (P4) reads __v and a number at the end of a type's address; Schema From Spell (P5) serves Person__v2; Versions And Upgrades (P6) writes "$schema": "...Person__v2"
  • a type's name may not end in __v and a number

Addresses lost their two slashes (Q41, 2026-10-14). The version form, __v2, stands; only the slashes before the type change.

  • one version: @spell/library/people/Person__v2, not @spell/library/people//Person__v2
  • a type now looks like a page of the running app, and is read as a type only where one is expected: a "$schema", a reference
  • a dot now means a file, so Person.v2 stays ruled out, for that reason rather than the one above
  • One Address Scheme (P4) reads __v and a number at the end of a type's address, with no // before it
  • Versions And Upgrades (P6) writes "$schema": "@spell/library/people/Person__v2"
