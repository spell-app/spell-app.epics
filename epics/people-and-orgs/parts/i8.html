A project that doesn't compile clean never gets a scope pack, so every request for its scope pack starts a compile again.

  • Only a clean compile writes a scope pack (the Type Explorer's data, Name.scopes.js)
  • The app's API compiles a project when a built file it's asked for is missing (ProjectBuild), and nothing remembers that the last try failed
  • So a project with errors, open in the editor, costs a child spell compile (a second or more) each time its Type Explorer asks, and the request then answers 404 anyway
  • Not seen to hurt yet: the editor asks for the scope pack rarely

Net effect (once fixed):

  • a failed compile is remembered until one of the project's files changes; until then, the request answers at once
