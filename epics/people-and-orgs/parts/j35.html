As the page server starts, it compiles the built-in projects that are out of date, in the background: spell compile --stale --all @examples @library.

  • It's started by the app's route module (appRoutes.ts), the piece that adds the app's API to the page server, not by the page server itself
    • the page server's package imports no other package, so it knows nothing of spell projects
  • The phase plan said it would run beside the bundle step, as spell dev bundles build --stale: it runs at the same moment, but as its own command
  • The API server run alone (yarn start:server, port 3001) has no start-up build: it compiles a project only when a request finds a built file missing
  • Why only @examples and @library: the demo pages and App UI's live examples run them; any other project compiles when it's opened
  • on a fresh checkout, the page server's first minute or so compiles the examples, and an API request for one waits for it
  • spell compile --stale --all by hand does the same for every project
