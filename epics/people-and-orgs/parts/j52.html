Other tools already use __ names. None is in a space today, and none is one of ours (Q33), so nothing clashes now.

  • Python's __init__.py and __pycache__/
  • the tests' __snapshots__/: 28 folders under tests/
  • the pack templates' __Class__.tsx.template
  • To keep it so, spaces checks a name against the list it owns, not "starts with __". A project's file list then never hides a Python file or a snapshot folder someone keeps in a project.
    • the list: __me.json5, __org.json5
    • __project.json5, __members/
    • __settings/ ...
  • A rule of thumb that also holds: ours never END in __; Python's and the tests' do.
  • The other way: anything starting with __ is special. Simpler, but a project holding Python would lose its __init__.py from its file list.
  • Projects Into Spaces (P15) lists a project's files leaving out only spaces' own names
