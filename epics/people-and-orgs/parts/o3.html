The server must import compiled Person like any module. Today that can't work: loading compiled spell runs it.

  • Its headings, tests and top-level steps run on load (the cards library runs three tests when imported).
  • The core it imports loads Solid, for drawing.
  • Every thing made is added to one global list, the Thing Explorer's; a server holding many people would fill it.
  • Nothing compiles spell at build time for other code to import.

What changes:

  • A new LIBRARY target: the JavaScript writer, keeping only classes, exported functions and constants, in a .js file (Q11).
  • The Python side already has a writer that leaves out a program's top-level steps, to copy.
  • The file has no decorators, only plain JavaScript, so node and vite import it with no build step.
  • A .d.ts beside it gives TypeScript importers their types (J5).
  • Both are committed and marked generated, and a test fails while they're stale.
  • A model entry in the core package: things, lists and properties, with no drawing and no Solid.
  • Things made outside a runner aren't added to the global list.
  • Owen picked a committed, generated file, and asked for JavaScript so it imports directly (Q11).
  • So the JavaScript writer makes it, not the TypeScript one, with a .d.ts beside it.
