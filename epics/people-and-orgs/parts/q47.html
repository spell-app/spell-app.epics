Phase P19 (Output) renames the runtime object compiled javascript and TypeScript call, from spellCore to core. A program compiled BEFORE the rename imports spellCore, and stops loading if the runtime no longer has that name. Should the runtime keep the old name for those programs?

  • Where old compiled programs live:
    • each checkout's build folder, which is git-ignored
    • the build folders of Owen's own projects, in spell-spaces
    • any page or export someone saved
  • Nothing recompiles them by itself: the editor's API compiles a project only when its built file is MISSING, never when it's merely out of date (J36).
  • What a program compiled before does, first line: 
    import { spellCore, Thing, List, App } from "@spell/core"
spellCore.heading("Cards")
  • The precedent: when epic output-targets P16 renamed eight of the core's methods, it kept each old name as the same function, marked deprecated, "nothing recompiles a saved program". The contract test runs a program compiled before, to prove it.
  • The runtime exports both: core, and spellCore as the same object, marked deprecated, beside P16's old method names
  • Programs compiled before keep running; a recompile moves each to core
  • The contract test runs one compiled before, as it does for P16's names
  • Cost: one line, and one more name to drop someday
  • Why recommended: it's what P16 did, and stale builds are never rebuilt by themselves
  • import { spellCore } from "@spell/core" still works, marked deprecated
  • every new compile writes core
  • The runtime exports core only
  • The phase recompiles every program it can reach: build folders (every checkout), spell-spaces
  • A program compiled before that it missed fails to load, "does not provide an export named spellCore"
  • Cost: a stale build breaks until someone deletes it, since out-of-date builds aren't rebuilt (J36)
  • no spellCore anywhere in the runtime
  • every build folder recompiled by hand, once
  • the runtime's spellCore stays, deprecated, as the same object as core
