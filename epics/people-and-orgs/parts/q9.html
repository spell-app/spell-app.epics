How spell writes an id, a reference, and a value per member. These words go into every spell program, not only Person, so they're worth picking on purpose.

  • Id: a property no two things of a kind share (a person's owen).
  • Reference: a property that points at a thing instead of holding a copy of it.
  • Per member: one value for each item of a list (a note for each person in a friend list).

  • Each word says exactly what it does; "unique" also works for any property, an email say.
  • "per" is short, and reads well for roles: a role per member as one of admin or viewer.
  • The friendliest to read aloud.
  • "link" will clash with web links once addresses arrive; "known by" names only the one id.
  • An id is its own datatype; "by reference" is programmer's English.
  • Three new property specifiers in the grammar:
    • unique
    • references to
    • per
  • PARSING.md gains a section for each, with examples that are also tests

Owen's answer, in his words:

everything has an id, no need to declare. Can't create a property called id. a list of people -- array of type = either inline the objects or assume that it's references

His follow-up, which settles inline or reference:

assume that things are in their own file. Some sort of spell to override, not sure syntax. Drawable things are not inlined.

What that means for every spell program:

  • Ids: every thing has an id built in. No program declares one, and declaring a property named id is an error.
  • References by default: a property or list typed as a kind, such as a list of people, holds references. Each person is saved in its own file.
  • In the saved file, each reference is the other thing's address: {"@ref": "matt@spell"}.
  • Inline, by override: one sentence says a kind is saved inside its owner instead. Its words are a judgement call (J1).
  • Drawable kinds are never inlined: a card is always its own thing, so a card in two piles stays one card.
  • A value per member: Owen picked C in the session's question, "No new words". A membership is its own thing, holding a person, an org and a role.

This narrows the language decision (Q2): spell still learns ids and references, but gets no "per" syntax.

  • None of the table's words: no "unique", no "references to", no "per"
  • Every thing has an id property; declaring one is refused (P1)
  • A property or list of a kind saves references; one new sentence inlines a kind
  • An org's members are membership things, each with a role (P7)
