When this branch merges into main, the shared docs that still name a test at its old place, beside its code in packages/, are updated to its new place in tests/.

  • Why not now: these docs are shared content, one copy for every checkout.
    • main, and every other worktree, still has its tests in packages/.
    • Changed today, they'd be wrong everywhere but here until the merge.
  • How: each packages/<pkg>/...test... becomes tests/<pkg>/..., the same path after the package's name.
    • e.g. packages/core/src/saving.test.ts becomes tests/core/src/saving.test.ts
    • the same for snapshot folders and test data (core's three expected files go to tests/core/)

The house rules, which agents read before writing a test:

  • WWOD's tests spoke (tests.md):
    • the rule "Tests sit beside their module" becomes "Tests sit in tests/<package>/, at their module's path"
    • its examples, naming test files in ui, app and core
  • The Solid 2 rules (solid-2.md): one test path.

The three logs: their entries name test files as they were when written.

  • The code-debt log (CODE-DEBT.md): about lines 63, 94, 106, 348 and 625, e.g. parser's and lsp's barrel tests, cli's contract test.
  • The suspected-bugs log (SUSPECTED-BUGS.md): about lines 616, 631, 731 and 760.
  • The papercuts log (PAPERCUTS.md): its entries naming test files.
