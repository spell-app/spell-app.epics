This epic gave spell its first person and org: written in spell, compiled into code the server imports, and saved as readable files.

  • One person, no sign-in; spaces of projects, sign-in and sharing are later epics.
  • It also moved spell to one address scheme, which the scope decision (Q1) had left for later (Q12).

Where each piece lives, following the one-way imports in the root's AGENTS.md:

  • The language work (built-in ids, what a list holds, which kinds are saved in their own file, version steps) is in spell's grammar, and in the three writers that turn it into JavaScript, TypeScript and Python.
  • The runtime compiled spell runs on is the core, called core in compiled code (P19; it was spellCore). Its saving, loading and checking need no drawing, so the server can use them.
  • The addresses are read by SpellLocation and turned into URLs by SpellUrls.
  • Person and Org are a built-in library project, written in spell like any other: @spell/library/people, its People.spell compiled into a committed people.lib.ts.
  • The storage adapter and the people store are in the spaces package's node folder, beside the code that reads and writes projects (P14, P15).
  • The spaces routes read and write the current person; the app shows them in its You panel.
  • The repo's layout move ran as phases of this epic (P10, P11, P14 to P18). Epic repo-split has since split the packages into repos of their own; the names here are as this epic left them.
  • The page server package imports no other package, by rule: it's a leaf.
  • The storage needs the JSON5 editor, and the people store needs compiled spell.
  • So both live in spaces, which the app's server already imports for projects.
