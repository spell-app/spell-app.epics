This epic gives spell its first person and org: written in spell, compiled into code the server imports, and saved as readable files.

  • One person, no sign-in.
  • It also moves spell to one address scheme, which the scope decision (Q1) had left for later (Q12).
  • Spaces, sign-in and sharing are still later epics.

Where each piece lives, following the one-way imports in the root's AGENTS.md:

  • The language work (built-in ids, references, and the sentence that saves a kind inline) is in the spell package's grammar, and in the three writers that turn it into JavaScript, TypeScript and Python.
  • The runtime that compiled spell runs on is the core package. It gains a "model" entry: things, lists and properties, with no drawing and no Solid, so the server can import it.
  • The address parser is the spell package's, where today's project addresses are read.
  • Person and Org themselves are a built-in library project, written in spell like any other: @spell/library/people, its exact address per the address mapping question (Q15).
  • The storage adapter and the people store are in the spaces package, in its node folder, beside the code that reads and writes projects (J4 put them in the spell package first; the spaces package took them, with the projects, in P14 and P15).
  • The app's server gets routes to read and write a person; the app shows the current person in a small You panel.
  • The page server package imports no other package, by rule: it's a leaf.
  • The adapter needs the JSON5 editor library, and the people store needs compiled spell.
  • So both live in spell, which the app's server already imports for projects.

Files are JSON5 now (Q4), so the adapter needs a JSON5 editor, not a JSONC one (J41).
