This epic gives spell its first person and org, written in spell, compiled into code the server imports, and saved as readable files. One person, no sign-in: the decisions on scope (Q1) put spaces, addresses, sign-in and sharing in later epics.

Where each piece lives, following the one-way imports in the root's AGENTS.md:

  • The language work (ids, references, a value per member) is in the spell package's grammar, and in the three writers that turn it into JavaScript, TypeScript and Python.
  • The runtime that compiled spell runs on is the core package. It gains a "model" entry: things, lists and properties, with no drawing and no Solid, so the server can import it.
  • Person and Org themselves are a system library project, @library/people, written in spell like any other.
  • The storage adapter and the people store are in the spell package (the parts that touch the disk in its node folder, beside the code that reads and writes projects today).
  • The app's server gets routes to read and write a person; the app shows the current person.
  • The page server package imports no other package, by rule: it's a leaf.
  • The adapter needs the JSONC editor library, and the people store needs compiled spell.
  • So both live in spell, which the app's server already imports for projects.
