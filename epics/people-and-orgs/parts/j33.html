A project's index, what the app's API answers about a project, now carries buildFolder: where its built files are, from its own folder.

  • e.g. for Solitaire: ../../../../../../build/spell/projects/system/examples/Solitaire
  • Missing for a project whose built files sit beside its source
  • Who needs it: the Python web app, Solitaire.app.py, is checked in beside the source, but must load the compiled program and its page file from build/
  • So compiling writes the app with an OUTPUTS line, that folder from the app's own, and the app serves from there
  • Why a relative path: the app keeps working when the checkout moves, and in any worktree
  • Not taken: copying the compiled program next to the app, which would make it a checked-in copy again, what this phase removes
  • a Python web app compiled before this phase is rewritten with its OUTPUTS line on the next compile, unless it was edited by hand: then the line is added by hand
