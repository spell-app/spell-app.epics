Spell has two things every program can use, not only Person (Q2, narrowed by Q9).

  • An id, built in: every thing and every list has an id, made up the first time it's read (person-k3x9q2mf, from real randomness) unless it was set. No program declares one, and a property named id is refused.
  • Saved files use the id in place of the old numbers, which only lasted one save.
  • Lists say what they hold: - its "people" is a list of people in a type's outline, so saving knows a list of people holds people before it holds any.
  • Saved inside, by default: a thing is written whole inside what holds it the first time, and as a reference after, { "$ref": "Card#ace" }: a saved game is a handful of entries, never a file per card.
  • A card in two piles comes back from a saved file as one card; two friends load holding each other.
  • Its own file, by opting out: - it is saved in its own file gives a kind a file of its own: a person, an org.

No "per" syntax: a value per member, such as a role in an org, is a thing of its own, a membership. A friend list holds relationships, each with a kind, a person and notes (Q16). 

a person is a thing:
	- it is saved in its own file
	- it has names as text
	- it has a nickname as text
	- its "emails" is a list of text
	- its "dates" is a list of dated-events
	- its "friend-lists" is a list of friend-lists
	- its "notes" is a list of notes
a dated-event is a thing:
	- it has a label as text
	- it has a day as a date
	- its "notes" is a list of notes
a note is a thing where:
	- it has a title as text
	- it has a body as text
a relationship is a thing where:
	- it has a kind as text
	- it has a person as a person
	- its "notes" is a list of notes
a friend-list is a thing where:
	- it has a name as text
	- its "relationships" is a list of relationships
an org is a thing where:
	- it is saved in its own file
	- it has a name as text
	- its "members" is a list of memberships
a membership is a thing where:
	- it has a person as a person
	- its "role" is one of guest, member, admin, spell-admin

What's under the words, for a reader of the code later:

  • The grammar reads the saved-in-its-own-file and saved-inline sentences, and refuses a declared id, with tests and their PARSING.md sections.
  • Each property's runtime description (its type, its one-of list, its default) has the item type of a list; each kind's says whether it's saved in its own file.
  • All three writers emit them; TypeScript gets real types (List<Person>).
  • Saved JSON's own keys start with a dollar sign: $type, $ref, $version; a reference to a thing in another place reads Person#matt@three-degrees.
