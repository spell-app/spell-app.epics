Spell learns two things every program can use, not only Person (Q2, narrowed by Q9).

  • An id, built in: every thing has an id, made up when it's created unless set. No program declares one, and a property named id is refused.
  • Saved files use the id in place of today's numbers, which only last one save.
  • References by default: a property or list typed as a kind, such as a list of people, points at things saved in their own files, instead of holding copies.
  • Today a card in two piles comes back from a saved file as two cards; with references, it's one card.
  • Inline, by override: one sentence saves a kind inside its owner instead, a dated-event is saved inline. (J1).
  • Drawable kinds are never inlined: saying so of a card is an error.

No "per" syntax: a value per member, such as a role in an org, is a thing of its own, a membership. A friend list holds relationships, each with a type, a person and notes (Q16). 

a person is a thing with:
	- it has names as a new list of text
	- it has a nickname as text
	- it has emails as a new list of text
	- it has dates as a new list of dated-events
	- it has friend lists as a new list of friend-lists
	- it has notes as a new list of notes

a dated-event is a thing with:
	- it has a label as text          // birthday, anniversary ...
	- it has a day as a date
a dated-event is saved inline.

a friend-list is a thing with:
	- it has a name as text           // family, work ...
	- it has relationships as a new list of relationships

a relationship is a thing with:
	- it has a type as text           // father, colleague ...
	- it has a person as a person     // saved as a reference
	- it has notes as a new list of notes

a note is a thing with:
	- it has a body as text

an org is a thing with:
	- it has a name as text
	- its "visibility" is one of public or private

a membership is a thing with:
	- it has a person as a person
	- it has an org as an org
	- its "role" is one of admin, editor, viewer or guest

What changes under the words, for a reader of the code later:

  • The grammar gets the inline sentence, and refuses a declared id, with tests and their PARSING.md sections.
  • Each property's runtime description (today: its type, its one-of list, its default) gains the item type of a list.
  • Each kind's says whether it's saved inline.
  • All three writers emit them; TypeScript gets real types (List<Person>).
  • Saved JSON writes an id where today's mirror writes a counter, and a reference as {"@ref": "matt@spell"} (Owen's note on Q2).
  • Every thing has a built-in id: the sketch's "its id is unique text" lines are gone (Q9).
  • References are the default, and one sentence inlines a kind; no "references to" words.
  • No "per" syntax: an org's roles are memberships, and friend lists hold relationships (Q16).
  • The sketch gains relationships, notes and memberships.
