Spell learns three things every program can use, not only Person (Q2). Today none of them has any syntax; the exact words are open (Q9).

  • An id: a property that names a thing uniquely among its kind. A person's id is owen; saved files use it in place of today's numbers, which only last one save.
  • A reference: a property that points at another thing instead of holding a copy. A friend list points at people. Today a card in two piles comes back from a saved file as two cards.
  • A value per member: a note per person in a friend list, a role per member of an org.
a person is a thing with:
	- its id is unique text
	- it has names as a new list of text
	- it has a nickname as text
	- it has emails as a new list of text
	- it has dates as a new list of dated-events
	- it has friend lists as a new list of friend-lists

a dated-event is a thing with:
	- it has a label as text          // birthday, anniversary ...
	- it has a day as a date

a friend-list is a thing with:
	- it has a name as text           // family, work ...
	- it has people as a list of references to people
	- it has a note as text per person

an org is a thing with:
	- its id is unique text
	- it has a name as text
	- its "visibility" is one of public or private
	- it has members as a list of references to people
	- it has a role per member as one of admin, editor, viewer or guest

What changes under the words, for a reader of the code later:

  • The grammar gets new property specifiers, with tests and their PARSING.md sections.
  • Each property's runtime description (today: its type, its one-of list, its default) gains the item type of a list, "is an id", "is a reference" and "per member".
  • All three writers emit them; TypeScript gets real types (List<Person>, a map per member).
  • Saved JSON writes an id where today's mirror writes a counter, and a reference as {"@ref": "matt@spell"} (Owen's note on Q2).
