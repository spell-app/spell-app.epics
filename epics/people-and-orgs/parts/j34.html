When the app's API or the page server needs a project compiled, it starts the checkout's own spell compile as a separate process, rather than compiling inside the server.

  • It compiles exactly as spell compile does: every target, the scope pack, the type checks
  • The page server keeps serving pages while it runs, and a slow or crashing compile can't take it down
  • The checkout's OWN command (spell.mjs), never the spell on the shell's path, which is the main checkout's: a worktree compiles with its own compiler
  • Its output goes to the server's log, each line starting projects:
  • Cost: starting a process per compile, about half a second to load spell
  • The code: ProjectBuild
  • the page server's log shows each compile it started, and why
  • stopping the page server stops any compile still running
