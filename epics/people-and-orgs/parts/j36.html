A request for a project's compiled program, scope pack or other built file compiles the project first only when that file isn't there; a file that's there is served as it is, even if the sources changed since.

  • Why: the editor compiles and saves on its own as you type; a second compile started by a request could race it, and the older output could land last
  • Out-of-date output is caught elsewhere:
    • the page server's start-up run, with --stale, for the built-in projects
    • spell compile --stale by hand
    • opening a project in the editor, which compiles it
  • One compile per project at a time: a second request for it waits on the first's
  • A request waits at most 60 seconds; then it's answered as before (a 404), while the compile carries on
  • no race with the editor's own saves
  • a stale file can be served until something compiles the project again
  • always fresh
  • a check of every source's date on every request, and a compile that can race the editor's
  • after editing a project's spell outside the editor, run spell compile --stale (or reopen it) to see the change in the app
