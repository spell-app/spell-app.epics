Owen, in chat (2026-10-14), after asking why addresses need //: "use 'presence of dot means a file', 'trailing slash means a folder' and it's OK that 'types look like pages' because types will only be used when types are expected". It replaces the two slashes (Q32's answer, J47, J48, J86).

  • A project is its group's address and ONE more part; nested projects aren't supported, and nothing plans them.
  • @spell/examples/solitaire/Card.spell: a file (a dot). @spell/examples/solitaire/assets/: a folder (the slash at the end). owen@spell/__me.json5: the space's own file.
  • owen@spell/solitaire/rules: a page of the running app (no dot). @spell/library/people/Person: a type, read as one only where a type is expected (a "$schema", a reference).
  • So a file must have an extension, and a group's, project's or page's name may hold no dot.
  • P4's // comes out of the code, the tests and the docs; the app's router needs no shim
  • the editor's URLs are the address as it is: /edit/@spell/examples/solitaire/Card.spell
