How an address with two slashes travels in a URL (Q32). I checked it, and recommend keeping the two slashes in the URL as they are, so a file's URL is still its address under /spaces/. 

owen@spell/solitaire//Card.spell                       the address
/spaces/owen@spell/solitaire//Card.spell               reading it
/api/projects/file/owen@spell/solitaire//Card.spell    saving it
  • What keeps the two slashes:
    • the browser, and node's URL: the empty part between them stays in the path
    • the page server's router: it matches the path as it arrived, and a route's last part keeps them
    • vite's proxy, which passes the editor's /api/ calls on unchanged
  • What would lose them, and the rule for each:
    • Path functions (normalize, join, resolve), and the page server's own static-file lookup, squash // to /. Rule: spaces' routes split the address at its first // BEFORE they turn it into a path on disk.
    • A relative link with ../ climbs out of the two slashes. From /spaces/owen@spell/solitaire//Card.spell, ../x is /spaces/owen@spell/solitaire/x: a page address. A link to a file beside it, Deck.spell, stays inside. Rule: tools write a /spaces/ link whole, never ../ across the two slashes.
    • A link that STARTS with // names another web site: //Card.spell is the host card.spell. Rule: every URL starts /spaces/ or /api/, never with the address itself.
    • Encoding a whole address in one go turns // into %2F%2F, which the static lookup refuses. Rule: encode each part, never the address as one piece.
    • Python's web server (Werkzeug) merges double slashes only in a route's fixed parts, and it serves one app at its own routes, never an address: nothing to change there.
  • The other way, not recommended: write the two slashes as /~/ in URLs only, /spaces/owen@spell/solitaire/~/Card.spell. Safe from any tool that squashes slashes, but a URL's tail stops being its address, and nothing we run needs it.
  • /spaces/ and /api/projects/file/ URLs hold the address as it is, two slashes included
  • spaces' routes split at // first; one function turns an address into a URL and back
  • a test asks the page server for a two-slash URL, and checks that no tool writes ../ across one
