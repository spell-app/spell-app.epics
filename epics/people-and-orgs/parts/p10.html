Test files, snapshots and test data sit beside the code in every package, and crowd it.Every package's tests move to tests/<package>/, at the same path as the code they test, with their snapshots and test data. Each package's Vitest, tsc, lint and format still cover them, and its yarn test and yarn review still run them.
  • tests/ mirrors packages/: packages/core/src/saving.test.ts is tests/core/src/saving.test.ts (Owen's picks on the layout page: all of it, test data first, build/ and tests/ together; his note: started first, while the spaces plan is finished)
  • Each test reaches the code by its alias ($/core/saving), never a long relative path
  • A package's yarn test, yarn ts, lint and format cover its tests in tests/; the root's yarn review runs them all
  • The merge command's snapshot step finds snapshots under tests/
  • Test helpers ($/spell/test, $/ui/test ...) and the test projects move later: the projects with the spaces move, to tests/spaces/@spell/test/
  • The house rules (WWOD's tests spoke, the AGENTS.md files) say where tests live
