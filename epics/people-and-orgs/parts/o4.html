A person and an org are small JSONC files, one per thing, read and written through a storage adapter whose first version is the local disk. Where the folders live is open (Q10). 

people/
  owen/
    person.jsonc          who Owen is
    friend-lists/
      family.jsonc        one file per list:  two edits rarely touch the same file
orgs/
  three-degrees/
    org.jsonc
    members/
      matt.jsonc          matt's role here
    _index.jsonc          built from the folder, never edited by hand
 
{
  "$schema": "spell:person@1", // the type, and its version
  "id": "owen",
  "names": ["Owen Williams"],
  "nickname": "Owen",
  "emails": ["owen@example.com"],
  // comments survive when the app saves
  "dates": [{ "label": "birthday", "day": "1970-01-01" }],
}
  • JSONC (Q4): edited with Microsoft's jsonc-parser, which changes one value and keeps every comment. The app's own project files lose their comments on every save today.
  • The schema is the spell declaration (Q3): it compiles to a checker the store runs on every read and write, and to JSON Schema, so VS Code underlines a mistake in the file.
  • Versions: "$schema": "spell:person@2". An old file is upgraded step by step when read, and written back when next saved. How an upgrade step is written is open (Q14).
  • The storage adapter is the one way in: read, write, list, remove, watch. Disk first; S3 or Git later. Writes keep using the page server's file lock.
  • Indexes (_index.jsonc) are rebuilt from a folder's files whenever one changes.
