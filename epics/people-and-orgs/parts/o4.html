A person and an org are small JSON5 files, one per thing, read and written through a storage adapter whose first version is the local disk.

  • They live in a spaces folder chosen when the server starts (Q10).
  • Either with --spaces <dir>, or with the setting SPELL_SPACES_DIR.
  • By default it's spell-spaces, beside the main checkout and outside any repo (J2).
  • A folder per org, people's spaces inside it as owen@/; special files start with __: a person's is __me.json5, an org's __org.json5, its memberships inside it. 
spell-spaces/             beside the spell-app checkout
  @spell/
    __org.json5           the org, its memberships inside
    owen@/
      __me.json5          who Owen is
 
// Who you are, to spell:  written on first start from git's name and email
{
  "$type": "Person",
  "id": "owen",
  "names": "Owen Williams",
  "emails": ["owen@example.com"],
  "dates": [{ "label": "birthday", "day": "1970-01-01" }], // saved inside the person
}
  • JSON5 (Q4): read and written in one file, json5.ts: an edit writes the whole value back, and the comments stay where they were, keys and text in double quotes.
  • The class checks a file (Q3): each read is checked against its class, its problems returned and the file read anyway; JSON Schema is only generated, for VS Code, which checks __me.json5 and __org.json5 by name through the repo's settings.
  • Versions: a type's version steps rename or drop a property (a person version 2 renames name to names), and an upgrade method does the rest; the saver writes "$version" past 1, and an old file reads as the newest.
  • A version goes up only when an existing property changes, never for a new one.
  • The storage adapter, SpaceStorage, is the one way in: read, write, list, remove, watch.
    • Disk first, DiskStorage; S3 or Git later.
    • Writes go through the page server's file operations, under the file's lock.
    • It keeps each folder's list in memory, dropped when anyone changes the folder.
  • The people store reads a person, their orgs and everyone they name; the first start writes a starter __me.json5 from git's name and email.
