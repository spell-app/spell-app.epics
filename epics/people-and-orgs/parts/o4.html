A person and an org are small JSON5 files, one per thing, read and written through a storage adapter whose first version is the local disk.

  • They live in a spaces folder chosen when the server starts (Q10).
  • Either with --spaces <dir>, or with the setting SPELL_SPACES_DIR.
  • By default it's spell-spaces, beside the main checkout and outside any repo (J2). 
spell-spaces/             beside the spell-app checkout
  people/
    owen/
      person.json5        who Owen is
      friend-lists/
        family.json5      one file per list:  two edits rarely touch the same file
  orgs/
    three-degrees/
      org.json5
      members/
        matt.json5        matt's membership:  his role here
      _index.json5        built from the folder, never edited by hand
 
{
  "$schema": "@spell:library/people/Person", // its type, by spell address
  "@version": 2,                               // none means version 1
  "id": "owen",                                // built in:  every thing has one
  "names": ["Owen Williams"],
  "nickname": "Owen",
  "emails": ["owen@example.com"],
  // comments survive when the app saves
  "dates": [{ "label": "birthday", "day": "1970-01-01" }], // dated events are saved inline
}
  • JSON5 (Q4): edited with @croct/json5-parser, which changes one value and keeps every comment (J41). The app's own project files lose their comments on every save today (T1).
  • VS Code opens .json5 as "JSON with comments", and spell writes keys and text in double quotes, so VS Code checks a file against its schema.
  • The schema is the spell declaration (Q3): it compiles to a checker the store runs on every read and write, and to JSON Schema.
  • A file's "$schema" is the spell address of its type (J3). The spell VS Code extension turns it into JSON Schema, so VS Code underlines a mistake in the file.
  • Versions: "@version" in the file says which version it is; a file without one is version 1 (Q14).
  • A version goes up only when an existing property changes, never for a new one.
  • An old file is upgraded step by step when read, and written back as the newest version when next saved.
  • The storage adapter is the one way in: read, write, list, remove, watch. Disk first; S3 or Git later. Writes keep using the page server's file lock.
  • Indexes (_index.json5) are rebuilt from a folder's files whenever one changes.
  • The folder is set at server start, by default spell-spaces beside the main checkout (Q10).
  • A file's schema is a spell address naming its type, no longer spell:person@1 (J3).
  • The version is the file's "@version", bumped only when an existing property changes (Q14).
  • The folder sketch starts at the spaces folder, and an org's member file is a membership.

Owen switched the file format to JSON5 (Q4): the files are .json5, edited by a JSON5 library that keeps comments (J41), and VS Code checks them as "JSON with comments". The rest of spell's .json files follow in JSON5 Everywhere (P12).
