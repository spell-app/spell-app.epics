When the app asks for two projects at once that are both missing their compiled files, and one imports the other, the imported project can be compiled twice, at the same time.

  • The app's API runs one compile per project at a time, keyed by the project asked for (ProjectBuild)
  • Each compile is a separate spell compile, which first compiles what its project imports, if that has no compiled file
  • e.g. Solitaire and cards both requested on a fresh checkout: the compile for Solitaire compiles cards too, while the compile for cards runs beside it
  • Left as it is: both write the same content, the last write wins, and it can only happen before the first compile
  • The page server's start-up build compiles the built-in projects in one run, so it doesn't happen there

Net effect (once fixed):

  • an import is compiled once, however many requests need it
  • e.g. by making a request wait on any running compile of a project it imports
