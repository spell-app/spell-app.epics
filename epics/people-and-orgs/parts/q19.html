A saved person file has to say which version of Person it was written as, so an old file can be upgraded. This asks WHERE in the file that version is written: in the type's address, in a key of its own, or both.

Where it comes from, the judgement call on a file's schema and version (J3):

  • Owen decided its first question: every internal key of saved JSON starts with $, so the version key is $version, not @version.
  • He also decided how a type's address names one version: Person$v2, with a dollar sign, because @ already means a space or a place in an address.
  • Its second question, below, was left open.

What's already fixed, whichever option wins:

  • A type's address may end in $v2, naming that version's schema; without it, the address means the newest version.
  • A file that names no version is version 1, as the decision on upgrades (Q14) says.

The catch that makes this a real choice:

  • VS Code asks for a schema by its address alone. It never sees the rest of the file.
  • So VS Code can check an old file against that file's OWN version only if $schema names the version.
  • Otherwise a version 1 file is checked against the newest Person: a renamed property shows as a mistake, though the store reads the file fine. 
// A:  both
"$schema": "@spell:library/people/Person$v2",
"$version": 2,

// B:  the address only
"$schema": "@spell:library/people/Person$v2",

// C:  the key only
"$schema": "@spell:library/people/Person",
"$version": 2,
  • VS Code checks every file against its own version.
  • The store reads $version, as the decision on upgrades (Q14) said.
  • A save writes both, at the newest version.
  • Cost: the version is said twice. A hand edit that makes them disagree gets a warning from the store.
  • A saved file writes "$schema": "...Person$v2" and "$version": 2
  • The store reads $version, and warns when the two disagree
  • The version is said once, and VS Code checks each file against its own version.
  • There's no $version key, which Owen's note and the decision on upgrades both asked for.
  • A file whose address has no $v is version 1.
  • A saved file writes only "$schema": "...Person$v2"
  • The store reads the version from the address; no $version key anywhere
  • As the judgement call (J3) stood, with $ in place of @.
  • An old file shows false mistakes in VS Code until the app saves it again.
  • Person$v2 is then used only where a version must be named, such as an upgrade sentence.
  • A saved file writes "$schema": "...Person" and "$version": 2
  • VS Code always checks against the newest Person

Where it's built:

  • One Address Scheme (P4) reads $v2 in a type's address, whichever option wins.
  • Schema From Spell (P5) serves one schema per version, for Person$v2.
  • Versions And Upgrades (P6) reads and writes the version where this question puts it. It needs the answer before it starts.
  • A saved file writes both "$schema": "...Person$v2" and "$version": 2
  • VS Code checks an old file against its own version, not the newest
  • The store reads $version; a file with none is still version 1 (Q14)
  • Versions And Upgrades (P6) builds it this way

Wherever this question says Person$v2, read Person__v2 (J51): an address can be typed in a shell, which reads $v2 as an empty variable. The "$version" key keeps its $ (J50). The options and the recommendation are otherwise unchanged.
