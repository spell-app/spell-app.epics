Where the two slashes go in an address. Owen's answer to the question on telling a file, a type and a page apart (Q32) was "// instead of :". I read it as: two slashes step from a place, a space or a project in it, to a thing inside that place. 

@spell/library/people//Person              a type in the people library
owen@spell/solitaire//Card.spell           a file in Owen's Solitaire
matt@three-degrees/bubble-trouble//folder/ a folder:  the slash at the end
owen@spell//$me.json5                      a space's own file
owen@spell/solitaire/rules                 a page of the running app:  no two slashes
Card#26@matt@three-degrees/bubble-trouble  a reference to another place:  unchanged
  • The other reading, word for word: One Address Scheme put the colon right after the space, @spell:library/people/Person, so // in its place would be @spell//library/people/Person.
  • Why after the project: everything before the two slashes is one whole place, so the reader never has to look up where a project ends to read a file or a type. Today that lookup (the longest project name that exists) is needed for every address.
  • What still needs the lookup: a page of the running app, owen@spell/solitaire/rules, which has no two slashes.
  • A file or a type: both follow the two slashes. Where the address is used says which: a "$schema" or a reference names a type, a URL or a project's file list names a file. Nothing is read from a name's case or its dot, as Owen asked.
  • Checked, and no clash:
    • a version, @spell/library/people//Person$v2: the $ is still the last mark
    • the $ keys of a saved file: an address is always a quoted string, so JSON5 never reads its // as a comment
    • spell's own // comments: a project names another by address only in its project file, a quoted string, never in spell code
    • a reference to another place, Type#id@place: its place has no thing after it, so no two slashes
  • One Address Scheme's second half (P4) splits an address at its first //
  • the spaces page's examples follow this reading
  • if Owen meant the other reading, only the reader's split and the examples change; no phase is built yet

The forms with __ names (Q33): @spell/library/people//Person__v2 (J51), owen@spell//__me.json5. The split at the first // is unchanged.
