The tests of each package type-check with that package's own settings: each test folder has its own small TypeScript project file, which extends the package's.

  • Chose: one TypeScript project file per test folder, in tests/core/ and its siblings, each extending its package's own.
  • Over: one TypeScript project file for the whole of tests/, as the layout page sketched.
  • Why:
    • The packages differ: JSX or none, which JSX, decorators, which global types.
    • One shared file would fit none of them, so tests would type-check differently from the code they test.
    • Vite finds the repo's aliases through the same file, so a test's imports resolve as its package's do.
{
  // core's tests:  core's own settings (packages/core/tsconfig.json), over this folder
  "extends": "../../packages/core/tsconfig.json",
  "include": [".", "../../types"]
}
  • a small TypeScript project file in each tests/<package>/
  • a test type-checks exactly as the code it tests does
