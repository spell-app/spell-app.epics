You named json5-writer for TypeScript, and commentjson or libcst for Python. I tried each on one test file (comments, bare keys, single quotes, trailing commas): set a value, remove a key, add one. The findings, with sources: analysis Q4, the update.

  • TypeScript: json5-writer works, but it was last released in June 2020, has no types, and pulls in an old jscodeshift and Babel (160 packages). @croct/json5-parser does the same job better: it changes one key in place, writes a new key in the file's own style, is written in TypeScript, has one dependency, and was released in December 2025.
  • Python: neither named library can do it.
    • commentjson failed on bare keys and single quotes, and writes plain JSON, comments gone.
    • libcst is a tree of Python source: it failed on the file.
    • json-five keeps comments with its "model" loader and dumper. Adding a key means writing its spacing by hand, so it sits behind one small helper, its version pinned.
    • Python's core uses the standard library only, and needs json-five only where it edits a file a person wrote: the files spell generates are written as plain JSON, which is JSON5 too.
  • TypeScript: typed and kept up; edits one key at a time, so a comment stays exactly where it was.
  • Python: json-five, the only one of the libraries checked that keeps comments.
  • TypeScript: the library you named. We'd write its types, and it moved a comment in the test.
  • Python: as A.

  • json-five, pinned, only where Python edits a hand-written file (P12)
