Saved JSON numbers things afresh on every save, so nothing can point at a thing in another file.A writer saves each thing that isn't inline as its own entry, keyed by its id, and a reference as {"@ref": ...}; a reader resolves references through a lookup it's handed. Python's saving code gets the same twin.
  • A card in two piles saves once, and reloads as one card, in both piles
  • A saved reference reads {"@ref": "matt@spell"}: the address of the other thing (Q2)
  • Inline things, such as dated events, save inside their owner, as everything does today
  • JavaScript and Python save the same shape
