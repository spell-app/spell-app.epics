spell-solid's namespace is E, as the spaces page drew it. Spell UI's core re-exports ALL of it, so Spell UI's E is the same names plus Spell UI's own: E.UIComponent is one class, by one name, everywhere.

  • the import: import { E } from "spell-kit/element"
  • Spell UI's core: spell-ui/core
  • Spell UI's own ~260 component files are unchanged.
    • They still import E from spell-ui/core, which carries spell-solid (its core bundle has to anyway).
    • Its element core's remaining files import spell-solid's classes directly.
  • The packs: 43 element files of the epics', the brand's and the app's now import E from spell-kit/element.
  • 21 keep spell-ui/core's E, because they also use Spell UI's own pieces, and one name can't come from two places:
    • E.IconGlyph above all
    • E.LoadableBody
    • E.NativeFallback
    • E.Converters
  • no file changes namespace; a pack file imports spell-solid unless it needs Spell UI's pieces
  • two names for one class (E.UIComponent in Spell UI, another in the packs)
