A project counts as out of date when anything in spell's compiler changed after its oldest built file, not only when its own sources did.

  • The compiler, for this check: the parser and its writers, spell's rules, the language server's scope packs, Python's writers, and core's built-in declarations
  • Not core's runtime: compiled code imports it, so a change to it needs no rebuild
  • Why: after a change to the grammar or a writer, the output on disk is wrong for every project, though no project file changed
  • By modification time, as make does: a file saved unchanged still counts
  • Cost: after any compiler edit, merge or branch switch that touches it, the next --stale run, the page server's start-up run included, recompiles every project
  • The list: COMPILER_SOURCES
  • the examples are rebuilt by themselves after spell changes, the next time the page server starts
