How the server and the app get compiled Person. Nothing compiles spell at build time today: the runner compiles a project when it runs it.

  • spell compile @library/people writes people.lib.ts beside the spell files; the server imports it like any TypeScript.
  • Marked generated, so a merge regenerates it instead of line-merging it (as the highlighter bundles are).
  • A test fails when it's stale, so nobody forgets to recompile.
  • The diff shows what the compiler made, which is a free review of the library writer.
  • import { Person } from "@library/people" compiles the spell when the server or vite loads it.
  • Nothing generated to commit; but a plugin for vite AND for node's loader, and a slower start.
  • A new generated file, people.lib.ts, in the root's merge rules and the merge command's list
  • a staleness test beside the library
