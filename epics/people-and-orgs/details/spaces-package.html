A __ at the start of a name means "this place's own", never a project, a source file or an element's folder: __me.json5 (who a person is), __org.json5 (who an org is), __project.json5 (a project's file), __members/, __settings/, components/__pack/ (a set's built pack), a set's docs/__parts/ and docs/__data/.

  • Why __, not $ (your note): "to avoid shell problems. Also sorts special files to the top of file listings". A shell takes cat __me.json5 as it is; with $ it read $me as an empty variable.
  • Names on disk only. The keys inside a file keep their $: "$schema", "$version", "$type", "$id", "$ref", "$items", already built in this epic's addresses phase. A key is never typed in a shell, and "$schema" is the name VS Code looks for.
  • A type's version too: @spell/library/people//Person__v2, not Person$v2, since an address can be typed in a shell (spell ... @spell/library/people//Person$v2 loses its $v2 there).
  • Top of the list: VS Code's Explorer lists __ names first. A terminal's ls lists capitalised names first (Errors.spell, then __project.json5), then __ names, then lower-case ones; a space's folders are lower-case, so there they're on top.
  • Look-alikes: Python's __init__.py and __pycache__/, the tests' __snapshots__/, and the pack templates' __Class__.tsx.template also start with __, but they END with __ too, and ours never do. None of them is in a space, and spaces checks its own names, not just the prefix.

I checked how // travels in a URL. It works as it is, with four rules; on the epic page, J48. So a file's URL is still its address under /spaces/.

  • What keeps it: the browser and node's URL keep the empty part between the slashes; the page server's router matches the path as it arrived; vite's proxy passes the editor's calls on unchanged.
  • Rule 1, split first: path functions, and the page server's static-file lookup, squash // to /. So spaces' routes split the address at its first // before they turn it into a folder on disk.
  • Rule 2, no ../ across it: from /spaces/owen@spell/solitaire//Card.spell, a link to Deck.spell stays inside, but ../x lands on /spaces/owen@spell/solitaire/x, a page. Tools write /spaces/ links whole.
  • Rule 3, never start with it: a link starting // names another web site (//Card.spell is the host card.spell). Every URL starts /spaces/ or /api/.
  • Rule 4, encode by parts: encoding a whole address in one go turns // into %2F%2F, which the server refuses.
  • Not recommended: /~/ in place of // in URLs only. Safe from any tool that squashes slashes, but a URL's tail stops being its address, and nothing we run needs it.
