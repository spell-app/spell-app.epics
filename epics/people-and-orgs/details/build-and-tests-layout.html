The repo with build/ and tests/

Your plan for the repo's layout, adopted. Everything compiling writes goes to a build/ folder beside packages/, not checked in. Every test, snapshot and test project goes to a tests/ folder beside it. Both mirror packages/. Below: the repo before and after, what has to be solved to get there, and four choices inside the plan.

  • What you decide here: four choices inside the plan.
    • Q1: how build/ mirrors the sources (spell compiles a project, not a file).

  • Source: what a person writes. A project's .spell files, its project.json, its CSS.
  • Compiled output: what compiling a project writes.
    • Its JavaScript, which the runner runs. Today Solitaire.compiled.js.
    • Its declarations: what a project importing it can use. Solitaire.declarations.json.
    • Its words: the Thing Explorer's labels. Solitaire.en.js.
    • Its scope pack: what the Type Explorer shows. Solitaire.scopes.js.
    • When project.json asks for them: TypeScript (.compiled.tsx), Python (.compiled.py), Python's page and words (.elements.js, .py.en.json).
  • Library: a project compiled for other code to IMPORT, not to run: People.lib.js and its types file, People.lib.d.ts (the js/lib target, this epic's phase 3).
  • Snapshot: a file a test compares its result against. Vitest keeps them in __snapshots__ folders beside the test.
  • Test project (a "fixture"): a frozen copy of a spell project that tests compile, with the snapshots of what it compiles to beside it, e.g. People.snapshot.js.
  • Mirror: your rule. A file's path under build/ or tests/ is its path under packages/: swap the first folder name, and you have it.

The compiled rows add up to 37 files that leave git: the 8 examples', the cards library's, and one of your projects'. The 4 compiled files in test projects are test data, and stay (1.6).

  • Your example has one output per spell file: build/folder1/folder2/foo.spell.js, beside foo.spell.ts and foo.spell.py.
  • Spell compiles a whole PROJECT into one file: Solitaire's four spell files become one Solitaire.compiled.js.
  • Why: a project's files share one scope, with no imports between them. A file can add to a type another file declares: Pile.spell says "a card belongs to one pile", which gives Card a property.
  • So either build/ mirrors project folders, or the writers change. That's Q1.
