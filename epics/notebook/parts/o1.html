Before this epic, a notebook was a page with a few writing shortcuts, plus a page the editor drew for it alone. What follows is that starting point, kept as the record.

In the language

  • Its body is the drawing: loose text is drawn as markdown, a new block at each ##.
    • In a <spell-page>, loose text is a comment, and only a <draw> draws.
  • It holds its own views (<spell-view "counter">): the parser lifts them out to just before it.
    • A view inside a <spell-page> is an error today.
  • locked: a lock property on the built-in notebook template, read only by the editor.
  • No longer notebook-only:
    • starting by itself: every app or page does, since epic editor
    • <example>: plain markup, the same in any drawing
<spell-notebook "counter notebook">
	# A counter
	A button that counts its clicks.
	<spell-view "counter"> ... </spell-view>
	## Try it
	<example "one counter"><counter/></example>
</spell-notebook>

<spell-view "counter"> ... </spell-view>
<spell-page "counter page">
	<draw>
		<markdown># A counter ...</markdown>
		<example "one counter"><counter/></example>
	</draw>
</spell-page>

In the editor

  • A notebook's project shows a docs-style page instead of the running app (<NotebookPage>): title, sticky foldable sections, "On this page".
  • Each example's code edits in place: only its cell's text changes, only its cell draws again, saved 600ms later.
  • Spellx / Spell code views; locked makes every edit a try-out; outside changes redraw only the cells they touched.
  • Per-cell tools: Add below, Move up / down, Delete, and the header's ⋯ menu.
  • It switches on for the <spell-notebook tag alone (NOTEBOOK_TAG).

Who uses it

  • Spell UI's component pages, @spell/notebooks: 94 projects, about 360 notebook files, one per tab.
  • No built-in project writes <spell-page> yet.
