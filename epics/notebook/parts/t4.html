The Spell view can't tell a web tag from a component when an example mixes an HTML block with other markup.

  • The code-spell writer (SX.CodeSpellWriter.writeMarkup()) writes a top-level HTML block's markup without its <html> tags: code spell reads web tags as they are.
  • So the way back can't tell <div> from a component.
  • The old pattern did the same.
  • An example that's ONE HTML block is fine: it shows as written in both views.

The Spell view keeps a top-level <html> block's tags, so the way back finds it just as it was written.

  • Today the code-spell writer drops the block's tags at the top of an example, and a one-line block disappears from the Spell view entirely.
  • writeMarkup() writes a body holding a top-level HTML block as it would inside an element, where the block's tags are already kept, then takes that wrapper back off.
  • The way back already leaves an <html> block as written, so a body that mixes one with other markup comes back the same.
