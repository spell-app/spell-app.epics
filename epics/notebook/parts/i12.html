A value like style=" followed by a line break compiles to a string holding raw line breaks. The parse reports no error, so the site's tests pass, but in Run the page shows SyntaxError: Invalid or unexpected token.

  • Seen failing in Run: Panel's Examples and Menu's Examples.
  • The same shape is in Popup's Examples and Comment's Usage; not opened in Run.
  • Kitchen Sink had two; those are joined onto one line in its own file.
  • The fix belongs in the compiler, which should escape the value's line breaks.

Proposed fix

  • Where: the JavaScript writer's ASTStringLiteral(). It writes a text as the source spelled it, and an attribute's spelling can run over several lines.
  • The fix: write each line break in that spelling as \n. Escapes already there stay whole, and a backtick-quoted text is left alone, since line breaks are legal there.
  • TypeScript goes through the same writer, and a plain attribute in JSX may run over lines, so it is right either way.
  • Python needs no change: its quoting already escapes line breaks.
  • Test: an attribute over two lines in JSX.test.ts, in all three targets, its javascript parsed.
