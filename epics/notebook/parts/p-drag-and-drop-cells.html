A notebook's cells move, get added and get deleted only through per-cell buttons and a ⋯ menu that the rest of the editor doesn't have.

  • An example, a section or a run of prose is dragged to a new place on the page, or in the Views tree, and the file changes to match; ⌘Z puts it back (Q4).
  • A run of prose can be picked and moved: the <markdown> block it reads as says where its text is written.
  • Selecting a cell is the Inspector's selection; cut, copy, paste, duplicate and delete work on it.
  • The palette offers what a page adds: an example, a run of text, a section, a view.
  • Gone: each cell's Add below, Move up, Move down, Delete (<CellTools>), the header's ⋯ menu (<NotebookMenu>), and their "selected cell".

The editor's drag and drop, the Inspector and the palette work on a page's cells as on any app's parts, prose included.

The cell tools go.

  1. Prose has a mark. Each <markdown> block the twin makes from a run of prose carries a source mark naming that run's span in the .spellml file, as tags do (SourceMarks).
  2. Moving. PartEdits moves an example, a section or a prose block by its mark, like any part; the Views tree shows them; ⌘Z is the editor's.
    • A prose block moves as whole lines, at the page's indent.
  3. Selecting. A click picks the part through the Inspector; cut, copy, paste, duplicate and delete work as on an app.
  4. Adding. The palette offers an example and a section through their components' own vocabulary snippets (ComponentDefinitions.palette()): ui-example and ui-section get snippets; a run of text comes from ui-markdown / ui-text's, as fits.
    • Only the "view" row is the page's own, in its "This page" group, for a page drawing its body.
  5. Gone: <CellTools> and its CSS, <NotebookMenu>, the controller's add, move and delete, the "selected cell", their texts in AppTexts.
  6. Checked: PartEdits tests on a page file: move an example, a section, a prose run, the rest byte for byte; headless, drag and undo, add an example and a section from the palette.
  7. Left out: a new kind of drag: the one there is does it.
  8. (coherence) Step 4 changed: the components' own snippets, not page-made rows.
  • On a notebook page: click an example, a run of text, a ## section or a header to pick it (the Inspector's marching ants); drag it to another place, or drag its row in the Views tree; ⌘Z puts it back byte for byte.
  • Cut, copy, paste, duplicate (⌘D) and delete (Backspace) a cell, from the keys or the right-click menu, text and sections included.
  • The palette adds an Example and a Section (their components' own snippets, so every app's palette offers them now) and, under "This page", a View.
  • The ⋯ menu and the notebook's own selected cell, add, move and delete are gone; a try-out's Reset is File › Reset to Saved (J21).
  • Loose text now carries a mark of where it's written, so it can be picked and moved (J17); text dropped beside other text joins it (J20).
  • Rough (I6): a move redraws the whole page, about 2 s on Button's Examples; typing stays fast. M2 is the live-window check of the drag.
