  • Typing in an example redraws only that example (I3): measured again on Button's Examples (2.5 s today) and Dropdown's (3.4-4.6 s), aiming well under half a second after the typing pause.
  • The rest of the page stays drawn, scrolled and folded where it was.
  • The page's spellx is unchanged: the split into views is the reader's, not the author's.

Each section and example is drawn as a view of its own, so the editor's edit-without-redraw redraws only the one that changed.

  1. Each example draws on its own. The compiler writes an example as core.drawPart(this, () => h("spell-example", ...)): the core draws it in a memo of its own, inside the page's drawing, so it can be drawn again without the rest. Nothing changes in the spellx, the twin or the TypeScript target. (parser: ExampleBlock, JSWriter, core drawing.ts; core declarations, py not_ported_yet)
  2. The edit says which example changed. LiveEdit splits a changed drawing into its examples: when only examples changed, it hands the core each one's old and new code, not the whole type; core.drawAgain() finds that example by its code and draws it alone, from the new program's drawing. (app: runner/LiveEdit.ts, runCompiled.ts)
  3. A new line no longer redraws everything after it. A line typed moves every later element's place in the file (data-spell-at): a drawing that differs only in those places isn't drawn again, its elements get their new places instead. So the example editors still find their examples.
