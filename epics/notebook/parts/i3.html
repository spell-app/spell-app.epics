Measured headless on this worktree's editor, a key typed in an example's code to the example drawn with it (the wait for typing to pause included):

  • Button's Examples, 61 examples: about 2.5 seconds
  • Dropdown's Examples, the biggest notebook, 76 examples: 3.4 to 4.6 seconds

Where it goes:

  • the wait for the typing to pause: 1 second (the code column waits 10)
  • the project's compile: about 0.5 to 0.6 seconds
  • the program drawing its WHOLE page again: 1.2 seconds (Button), 1.8 to 2 seconds (Dropdown). The page is one draw, so an edit to one example draws every example again; the page waits while it does.

So an example now draws again once the typing pauses, not as it's typed. The way to fix it: each section or example drawn as a view of its own, so LiveEdit draws again only the one that changed.
