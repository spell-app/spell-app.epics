is <spell-page> written in spell or TS?

TypeScript, by hand, today. Only two of the core's classes are written in spell: two sided view and notebook.

  • Page (Page.ts): hand-written, a View with one method, start(); Python's twin, page.py, hand-written too.
  • View, Thing, App: hand-written as well.
  • Written in spell, in core/templates/: TwoSidedView.spell and Notebook.spell, each with a Spanish .es.spell.
    • yarn core:gen:templates compiles each into a generated TypeScript class and a Python one, and both languages' words.

So Q8 asks which way the lock property moves when the notebook template goes:

  • A: Notebook.spell becomes Page.spell, generating a base class; the hand-written Page extends it, keeping only start(). A page is then half written in spell.
  • B: lock is typed into Page.ts and page.py by hand, and its English and Spanish words declared separately. A page stays all TypeScript.
Would it be better for <spell-page> to be a base class like View?

Yes: I'd now pick B. Page sits beside View and App, and every one of those base classes is hand-written TypeScript, with a hand-written Python twin.

  • The two templates written in spell (two sided view, notebook) are types BUILT ON a base class: what a person could have written. A page isn't that.
  • A, a generated half of Page under a hand-written half, would make Page the one base class written two ways, and the generator learn a second name for its class.
  • B's "three copies" (Page.ts, page.py, the Spanish word) is what every member of View and App costs already: the usual way, not a new one.
  • The notebook template's content slot goes too: a page that draws its body is read straight into its own drawing (Q2 B), so it needs no slot.
Page stays a plain base class like View, lock one more hand-written member; Notebook.spell goes with nothing replacing it.
