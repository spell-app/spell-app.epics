How a question goes from Claude to the page, and Owen's answer back.

  1. Claude makes the page: yarn details new <slug> --title "...", from the template (details.html). It prints the page's path.
    • by default in pages/details/: ignored by version control, swept after 14 days
    • with --epic <name>, in the epic's details/ folder: committed, and linked from the decision it led to (D3)
  2. Claude fills it: the picture first (a table, code, a diagram, a live example), then one or more questions.
    • each question is a list of option cards: radio buttons, or checkboxes to pick several
    • one marked recommended
    • plus "Other", and a notes box
  3. Claude runs yarn details show <slug> --wait, IN THE BACKGROUND:
    • it starts the page server if needed
    • shows the page in this session's window
    • then waits for <slug>.answer.json
  4. Claude ends the turn: "answer in the side bar".
  5. Owen picks, adds notes, and clicks Send.
    • the page posts to /api/details/answer
    • the route module writes <slug>.answer.json beside the page
    • the page shows "Sent" and locks; a reload keeps it so
  6. The waiter sees the file, prints the answer as plain text, and exits: the session wakes with it, and goes on.
  7. Other ways it can go:
    • Owen answers in chat instead: Claude stops the waiter
    • no page server or extension: the modal, as before (the top 3, and "Other")
