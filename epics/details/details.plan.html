The answer goes back to the session through the page server, which wakes the session up -- no 4-option limit, no copying letters into chat.

Kickoff prompt

Owen's ask: "Some sessions need more explaining than can happen in chat -- e.g. I need a visual to make a call. Upgrade VSC extension so we can use the right sidebar for that -- e.g. we are interacting and you want to show me a modal, but there are more than 4 options for me to choose. You would create a little HTML page, show it in the sidebar, then show the modal with questions. If this is a quick one, just do it on main. If you think it should be a skill `/details` or some such, make an epic for this."

Chosen scope (modal answer: "Epic: answer on the page"):

A `/details` skill: when a question needs a visual or has more than 4 options, Claude writes a small HTML page (from a new `templates/details.html`, into a git-ignored folder) and shows it in the right sidebar's "Spell Docs" view (`node scripts/window.mjs show <file>`, which already works -- no extension change needed for showing). Owen answers ON THE PAGE: radio/checkbox options, a notes box, Submit; the answer goes back to the session through the page server (new endpoint), and Claude waits for it (Monitor / a script that blocks until answered), so AskUserQuestion's 4-option limit stops mattering. Also: a CLAUDE.md line so Claude reaches for it unprompted; the modal stays as fallback (top 3 + Other to type a letter) when the page server or extension isn't available.
