In the classes split, one rule reads a rule registered after it, so it imports it through the folder, not its file.

  • DefinePropertyHas.getLongForm() checks specifier.is(OutlineSpecifierEnum).
  • But outline_specifier_enum registers AFTER define_property_has.
  • Importing ./OutlineSpecifierEnum would load (and register) it first.
    • The "_testable_" order in ruleNames.test.ts's snapshot would change.
  • Chose: import { OutlineSpecifierEnum } from "$/spell/rules/classes", the folder's own index.
    • A cycle, but the class is read only when getLongForm() runs, long after the folder loaded.
    • A comment above the import says why.
  • Over: swapping the check to is(TypeSpecifierEnum), registered earlier, so a plain import.
    • The same for every real input, but not for a nonsense one, e.g. its have a x as one of a, b.
    • So a behaviour change, in principle.
  • Breaks only if something imports DefinePropertyHas.ts directly, before the folder: nothing does.
