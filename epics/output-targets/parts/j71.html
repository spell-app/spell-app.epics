Each rule test's input is parsed once, then written by both writers; blessing writes the TypeScript into the source.

  • Tuples stay tuples: [input, js, ts]. Chose that over turning about 480 tuple tests into objects, which would only reformat them.
  • The TypeScript writer sees the one rule's match as the whole project, and writes just that code, without the import lines a module starts with.
  • yarn test:rules:bless (in spell) runs the rule tests with BLESS_RULE_TESTS=1, then the formatter. Chose that name over SPELL_BLESS_TS: the parser package knows no language.
  • The rewriting is a small TypeScript class, RuleTestSource, reading the source with the parser Vite+ already ships: no new dependency. It finds each test by its input and js; a test it can't place fails the run, saying why.
  • The speed test's rule run checks js only, so its numbers stay comparable: 117ms on HEAD and on the diff.
  • Drive-bys: that run's failure log printed the input as "EXPECTED"; the events test was titled "expressions".
  • output is gone from rule tests: js everywhere.
  • A TypeScript writer change fails the tests of each rule it touches; yarn test:rules:bless accepts it, and the diff shows it.
