• Formula slots (T16): a method parameter named for a property of its class gets that property's type: isASuit(suit: Suit) for a card "is a (suit)" for its suits.
  • Getter types: a getter whose type spell knows says it, get state(): string. Without it TypeScript went round in a circle (a pile's state reads its cards, a card reads its pile) and quietly made each loop's item unknown.
  • An event's payload (T16): typed on the handler's parameter, (event: { card: Card }) =>, which core's on() now takes (on<Payload>()). Named arguments the same way (T18): createANewTask(props: { title?: string } = {}).
  • A property over an inherited member: a joker's color property over a card's color getter keeps javascript's getter / setter pair, as TypeScript refuses an accessor there (TS2612).
  • Each is the smallest rule that types what spell says; the contract test checks none of them changes behaviour
