Spell warns only where a program says nothing of a type, and never where it works one out: a default value, as one of ..., a loop variable, (a card).

The five places it warns, each with its message:

  • A property with no type, a calculator has an input (define_property_has). Under the whole line: 
    Say what "input" is, e.g. "a calculator has an input as text"
  • A property holding a list of nothing said, ... has a property tasks as a new List. It asks for a list type (see the issue about as a new list of tasks): 
    Say what "tasks" holds, e.g. declare "a task-list is a list of tasks",
then "a todos-app has a property tasks as a new task-list"
  • A parameter with no type and no default, (digit) (var_method_arg). Under the name; also inside (with title) lists, and on x with y handlers: 
    Say what "digit" is, e.g. "(digit as text)"
  • A NEW variable set to a list spell can't say the items of: set state to [], or set card-names to a new list (the assignment rule). Under the value: 
    Say what "state" holds, e.g. "set state to a new list of text"
    • The rule: the new variable's datatype is plain list, so [1, "a"] counts too.
    • Checked across every project: it fires only on [] and a new list.
  • A property a set declares, from a value that doesn't say what it is: set the name of cards-to-move to the name of the start-pile. Under the name of cards-to-move: 
    Say what "name" is: declare it, e.g. "a pile has a name as text"

Each message's example type is a guess from the name.

  • A type of that name, if there is one: (card as a card), a new list of tasks.
  • Else text.
  • Spell types nothing by its name: it's only the example.
  • Warnings across all projects, before the examples were typed:
    • Calculator 8, Todos 1, Todos - Form Based 2, Solitaire 3, OutlineSolitaire 3, Solitaire-import 1
    • the library's cards 2
    • fixtures: Cards 1, Klondike 1, OutlineSolitaire 3, Solitaire 3; FizzBuzz none
  • No false alarms found.
