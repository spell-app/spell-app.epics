What do we call the DESTINATION: the thing named js/solid, ts/solid, py? The sketch said "target", but the spell command line already uses "target" for something else.

  • Today, "target" in the CLI means the project or file a command acts on: spell compile <target...> (packages/cli/src/commands/compileCommand.ts), and its help text calls the argument TARGETS_ARG.
  • So spell compile Solitaire --target py would use one word for two things.
  • The epic's own name, "output targets", already leans one way.

Net effect (A):

  • the destination is an OUTPUT: js/solid, ts/solid, py are outputs
  • the CLI flag is --to; "target" keeps its CLI meaning
  • the sketch guide (Compile Targets) is renamed to match at Doc Review
ChoicesA · Output (recommended)
  • "Compile Solitaire to the py output."
  • spell compile Solitaire --to py
  • Code: Output, OUTPUTS, output.can.draw
  • No clash with the CLI's "target".
  • Risk: "output" also means the compiled text; "an output" vs "the output" reads fine in practice.
B · Target
  • The standard word: TypeScript's target, LLVM's targets.
  • spell compile Solitaire --target py
  • Means renaming the CLI's argument to "project" or "what": spell compile <project...>
  • Cost: the CLI's help, commands.json, and every doc that says "target".
Answer · Target: js/solid, ts/solid, py are targets; the CLI's old 'target' argument becomes 'project'
