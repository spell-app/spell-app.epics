For the TS Magic in JS phase (P19): should compiled javascript name methods and properties in camelCase, as TypeScript does, or keep spell's own names?

  • Spell's own name for a thing comes from the parse, in snake_case: add_card_to_pile.
  • Each writer chooses how it writes that name.
    • The javascript writer (js/solid) writes it as it is: add_card_to_pile().
    • The TypeScript writer (ts/solid) camelCases it (camelCaseOf()): addCardToPile().
    • A later Python writer would keep snake_case.
  • camelCase in javascript renames every compiled program's methods and properties. What reads them by name has to follow:
    • the Thing Explorer
    • saved JSON's keys
    • <Project>.scopes.js
    • the editor's completions mapping
 
// B: spell's own names (javascript today)
card.turn_face_up()
// A: camelCase (TypeScript today)
card.turnFaceUp()

  • It's what a person writing javascript writes.

  • The Thing Explorer, saved JSON keys, scopes and completions read the camelCase names.
