The javascript writer writes each element as a call to Solid's h(), with the page's own spellings, as the TypeScript writer does.

  • The wrapper's other jobs move into the writer or core's error net.
  • The wrapper stays as a deprecated name, for programs compiled before.
  • Why: compiled javascript should draw as a person writing Solid without JSX would, calling Solid's own h().
    • Today every element goes through spell's own wrapper, spellCore.element().

  () => this.short_suit
] })
// after
h("span", { class: "suit" }, () => this.short_suit)

// today
spellCore.element({ tag: "td", children: [() => spellCore.drawThing(stock)] })
// after
h("td", () => spellCore.drawThing(stock))
  • The javascript writer writes the page's spellings itself, as the TypeScript writer does (the caveat about HTML's spellings, C19).
    • className becomes class, htmlFor becomes for, colSpan becomes colspan.
    • A live value or an object on a ui-* tag is written "prop:value", decided when it compiles.
    • The two writers share that rule, rather than each having a copy.
  • The wrapper's other jobs move or go.
    • A dotted tag (<UI.Form>) is a compile error: h() would silently draw a <UI> with class Form.
    • Made at once: core's error net makes the element a draw() returns, once, so re-reading its children never makes it again. Elements inside it need nothing: h() makes them with their parent.
    • spellCore.element() stays as a deprecated name: programs compiled before still run.
  • Still no compile step: compiled javascript is a plain module, its imports linked by the runner as today.
