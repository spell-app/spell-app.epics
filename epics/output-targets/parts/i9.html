A spell object's JSON didn't follow its VALUES: the form's debug view went stale when a task changed from outside the form.

  • Found while checking test V14 (Todos - Form Based), once the debug view showed the tasks at all.
  • How to see it: press Change name in the grey Test menu.
    • The first row's title field turns to "New title".
    • The debug JSON still said "Create todos app".
  • Changes made IN the form did show: the form redraws its debug view after each change event of its own, which covered for the missing tracking.

Why:

  • A thing's JSON comes from getProps(), which tracked the SET of keys only, on purpose.
  • So a reader of the JSON re-ran when a prop was added or deleted, but not when one changed.
  • Spell UI's form says the opposite of its debug view: "the JSON reads every property it shows, so a reactive object redraws it as it changes".

The fix: getProps() reads each value's cell too, while something is tracking.

export function getProps(target: any): Record<string, any> {
  const extended = extendedFor(target)
  if (isTrackingCells()) {
    ;(extended[KEYS] ??= new Cell()).read()
    for (const property of extended[PROPS].keys()) cellOf(extended, PROP_CELLS, property).read()
  }
  return Object.fromEntries(extended[PROPS])
}
  • Costs nothing when nothing is tracking (a plain JSON.stringify()).
  • Test: "`toJSON()` tracks each value too" in cells.test.ts, failing before; the runner's browser test presses Change name and reads the debug JSON.
  • A form's debug view follows every change to its spell object, wherever the change comes from.
  • Anything reading a spell object's JSON inside a tracked scope re-runs when one of its values changes.
