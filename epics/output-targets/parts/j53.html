Only spell objects (Thing and List, and what extends them) write "@type". Observable.toJSON() stays its props alone.

  • The shape is one helper in util's records, typedJSON(target), beside getProps().
    • The key is a constant, TYPE_KEY.
  • Why not every Observable: tasks, files and the editor's store are Observables too, and their JSON isn't spell's to change.
  • "@type" is the CLASS's name, even when an instance says another type.
    • The class is what fromJSON() rebuilds.
  • "@type" and "items" are never props.
    • So keys(), and the Thing Explorer, never list them.
{
  "@type": "Todos_App",
  "tasks": {
    "@type": "Task_List",
    "items": [{ "@type": "Task", "title": "Create todos app", "completed": true }, ...]
  },
  "filter": "all",
  "newTaskName": ""
}
  • Every spell object's JSON starts with its class's name; every other Observable's JSON is unchanged.
  • The core contract snapshots did NOT change: print shows a thing through node's inspect, never its JSON.

Maybe it should be `@items` ?

You asked: Maybe it should be @items?

Yes. It's the same reason "@type" has its @, and today's "items" can collide.

  • "@type" is spelled with @ because no prop can start with @: spell's names are words. So it can never clash with a prop.
  • A list's "items" key is written right after its props, so a list type with its OWN property named items loses it.
    • e.g. a shelf is a list of books plus a shelf has items as a number: its JSON keeps only the books, and the number is lost when it's read back. 
// writing:  List.toJSON()
return { ...typedJSON(this), items: this.items }
// reading:  rebuild()
const { items, ...props } = fields
 
{ "@type": "Shelf", "items": [ ... ] }              // its own "items" prop was overwritten
{ "@type": "Shelf", "items": 3, "@items": [ ... ] } // both kept
  • Nothing saved needs to keep loading: typed JSON first shipped in P15, and only reached main today. So no fallback that still reads "items".
  • An ITEMS_KEY = "@items" constant beside TYPE_KEY in util, used by List.toJSON() and core's rebuild().
  • The JSON tests and the Todos form's debug view follow.
  • About 15 minutes, done at the start of P19.
  • A list type can't have its own items property, and its JSON stays a little plainer.
  • A list's JSON reads { "@type": "Task_List", "@items": [...] }.
  • Both keys a spell object adds start with @, so neither can clash with a property.
