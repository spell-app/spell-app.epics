Why the phases come in this order. Each one leaves spell working and the tests green.

  1. P1 removes the second way each tree node writes itself (the unused ASTViewer's coloured copy), so P2 has ONE thing to move.
  2. P2 and P3 change where JavaScript is decided, never what comes out: the fixture snapshots must stay byte-identical, which makes them safe to review.
  3. P4 draws the tree once it's clean, and is the easiest way to check P3 by eye.
  4. P5 is the one phase that changes compiled JavaScript on purpose (the declarations comments leave it), so its snapshot diff is about one thing only.
  5. P6 makes targets a real choice; P7 is the first second target.
  6. P8 proves two targets behave the same, and leaves the test programs ready for a Python target (T1).
