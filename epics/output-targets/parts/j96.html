Owen asked (J93) to weigh a safeH(): h() wrapped in a minimal error boundary. Weighed, and NOT built:

  • Every drawing a spell program makes already sits in an error boundary: the thing's, from spellCore.drawThing(card) (javascript) or @drawn draw() (TypeScript).
  • A safeH() at the top of a draw() would be a second boundary around the same drawing: it catches nothing more.
  • It can't replace the thing's boundary either. The boundary must hold the WHOLE draw(): what it reads before its h() (the is face down an if chose by) must re-run that card alone. Around the h() only, those reads would land on the parent, and the parent would redraw.
  • A finer boundary, around one part of a card, has no spell words to ask for it: nothing would call it.
  • Its code would be small (about ten lines on drawInBoundary()), but an export nobody calls is a promise to keep. 
// what the writer writes today, and keeps writing
draw() { return h("div", { class: "card" }, () => this.rank) }   // drawThing(card) wraps it

// safeH(), not built
draw() { return safeH("div", { class: "card" }, () => this.rank) } // a second boundary, inside the first
  • Core keeps one error boundary per drawn thing, as now; no new export
  • If spell ever gets words for a boundary around part of a drawing, safeH() is the way to build it
