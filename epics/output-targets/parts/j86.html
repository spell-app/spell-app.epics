A getter is read by its member name only if the writer knows it IS a getter.

  • A whole project's compile sees every file; code written alone didn't.
  • So three things read card.short_rank, while the getter is get shortRank():
    • the editor's view of one file
    • a hover's compiled preview
    • a rule test

The fix:

  • New JSWriter.writeMatch(match): writes a file, a statement or a rule test as if it were the whole project, in its scope.
    • The editor's file view uses it (SpellFile.compile()).
    • So do the language server's previews (compileQuietly()).
    • And the rule-test harness, and the parser speed test.
  • WriterProject.of() also reads the project's own scope:
    • each type's getters
    • a type another file declares is known as an imported one is: its members, its super-type
    • A whole project's compile already knew all that, so its output is unchanged.
  • So TypeScript's rule tests changed too, where they read a getter or a list class from their test scope:
    • the short rank of the card was card.short_rank (wrong: the getter is shortRank), now card.shortRank
    • a pile can take a card if: it is empty is this.isEmpty
    • thing is a Bee is thing instanceof Bee
  • One test's comparison needed a note (SpellDeclarations.test.ts).
    • Solitaire compiled against the library's SOURCES vs its DECLARATIONS now differ by one more line.
    • That's this.name == 'diamonds' vs ===, as the sources auto-declare a pile's name.
  • The editor's per-file view and hovers show the names the program really uses.
  • Fixture snapshots (both targets) don't move from this; some rule tests' ts do, for the better.
