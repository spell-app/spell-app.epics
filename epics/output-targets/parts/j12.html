The targets table lives in spell, not in the parser's writers, and says only whether a target can draw.

  • The plan put targets.ts in the parser's writers/, each target naming its writer, its core, and whether it can draw and react.
  • I put it in spell's targets.ts: SP.TARGETS, SP.targetFor(), SP.RUNNING_TARGET.
    • A target is about a spell project: its suffix, the file it writes, whether spell code that draws can go there.
    • And the parser shouldn't know spell's projects exist.
    • The writers stay in parser.

Each target is { name, writer, suffix, can: { draw } }.

  • No core field and no can.react yet:
    • only one core exists, @spell/core, shared by js/solid and ts/solid
    • nothing checks reactivity today
  • They join the table when Python (T1) needs them.
  • Also: js/solid is ALWAYS compiled, whatever the targets say, since the app, runner and language server run it.
