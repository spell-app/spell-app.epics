The new on(), off(), once() and trigger() each use the CURRENT program's event lists, found as they're called. Compiled JavaScript calls them as spellCore.on(...), so those names had to change what they meant.

  • Before: spellCore.on(...) kept its own lists, on spellCore itself. Those outlived every run, and every trigger in a program also reached them.
    • Nothing used them except the console, which triggers a "console-log" event for each line. Nobody listens to it.
  • Now there's one set of lists per run: a program's listeners end with it. A new run hears nothing of the last run's.
  • Programs compiled before this still call spellCore.RUNTIME.on(...). That reaches the same lists, so they keep working.
  • With no program running:
    • trigger() does nothing and answers []. It must never throw, because the console triggers lines before any program starts.
    • on() and once() throw, saying to call spellCore.resetRuntime() first. The old spellCore.RUNTIME.on threw too, less clearly.
  • Also: a trigger used to answer nothing when called on a thing. Now it answers what each listener returned, as its docs always said.
