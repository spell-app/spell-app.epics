Where do a project's DECLARATIONS go in a non-JavaScript output? Declarations are what a project offers projects that import it: its types, functions and the syntax to call them.

  • Today each declaring statement compiles with a comment just above its code, read back with JSON5 (SpellDeclarations.ts). From FizzBuzz's real output: 
/*! SPELL: DECLARES {
  syntax: "play fizzbuzz", output: "play_fizzbuzz", rule: "method_call",
  alias: ["statement", "expression"], kind: "function",
  defined: "/FizzBuzz.spell:23-331",
} */
export function play_fizzbuzz() {
  • /*! ... */ is a JavaScript comment; Python's is #, one line at a time.
  • output: "play_fizzbuzz" is a JavaScript name: with spell names in the tree (1.3), each output names it its own way.
  • js/solid output keeps its declarations comments, byte for byte
  • declarations hold the spell name; each output's own name for it is worked out by its writer
  • Each writer writes the same JSON5 in its own comment form: /*! SPELL: DECLARES {…} */, or # SPELL: DECLARES {…}
  • The reader learns the second comment form.
  • js/solid output unchanged; still one file per project.
  • Solitaire.declarations.json, the same for every output.
  • A Python project could import a JavaScript-built one.
  • Cost: js/solid output changes (comments gone), and the runner, LSP and imports read the new file.
