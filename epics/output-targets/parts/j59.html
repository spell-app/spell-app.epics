Chose to type a property only when EVERY value the program gives it is alike, over typing it from the values it can tell and skipping the rest, because a wrong type is worse than a marker: tsc would pass a wrong string on an untyped object, and nobody would see it.

  • Counted: a value given when one is made (a new stock-pile with name = "stock"), a value it's set to anywhere (set the name of the pile to ...), and its initial value.
  • Not counted: a set on something the writer can't tell is that class (it may be a different thing with a member of the same name), and a value read off the same member (set the name of a to the name of b says nothing new).
  • A value it can't tell (a variable spell knows nothing of), or two kinds (text and a number): the marker stays.
  • Solitaire's and OutlineSolitaire's @prop() accessor name!: string, from "stock", "discards", "clubs" ... and `Tableau${number}`
  • A program setting name to a number anywhere keeps the marker
