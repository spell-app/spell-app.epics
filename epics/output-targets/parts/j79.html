The methods folder has four classes that aren't rules on their own, each in a file named for it:

  • MethodDefinition.ts: the base of to_do_something, create_animation, quoted_type_expression
  • DynamicMethodRule.ts, MethodPostfixRule.ts, MethodInfixRule.ts: the call-site rules a definition specialize()s while parsing

They're listed in index.ts first, after the parser and shared file, as they came first in the old file; none registers, so where they sit can't change the tie-break order.

  • MethodDefinition and DynamicMethodRule import each other: a definition makes a DynamicMethodRule (getRule()), and a call looks up its method with MethodDefinition.findMethod().
  • Both uses run inside methods, while parsing, never at load (neither extends the other), so the loop is harmless: left as is, no direct-import workaround needed.
  • TypeMethodArg is a rule AND the base of bare_type_arg: it's just a rule file, which BareTypeArg.ts imports. It came first in the old order too.
