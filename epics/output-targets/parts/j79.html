The methods folder has four classes that aren't rules on their own, each in a file named for it:

  • MethodDefinition: the base of to_do_something, create_animation, quoted_type_expression
  • the call-site rules a definition specialize()s while parsing:
    • DynamicMethodRule
    • MethodPostfixRule
    • MethodInfixRule

They're listed first in the folder's index, after the parser and shared file, as they came first in the old file. None registers, so where they sit can't change the tie-break order.

  • MethodDefinition and DynamicMethodRule import each other.
    • A definition makes a DynamicMethodRule (getRule()).
    • A call looks up its method with MethodDefinition.findMethod().
    • Both uses run inside methods, while parsing, never at load: neither extends the other.
    • So the loop is harmless: left as is, no direct-import workaround needed.
  • TypeMethodArg is a rule AND the base of bare_type_arg.
    • It's just a rule file, which BareTypeArg.ts imports.
    • It came first in the old order too.
