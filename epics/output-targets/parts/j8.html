Two calls about how the tree diagram sizes itself.

  • Boxes are sized from character counts, not by measuring the rendered text.
  • It stops shrinking at three quarters of natural size (--ui-tree-diagram-min-scale: 0.75); after that the diagram scrolls sideways inside the element.
  • Character counts: each monospace character is 0.6 of the font size.
    • The layout stays a pure function: same tree, same picture, testable without a browser.
    • It runs before fonts load.
    • Monospace fonts are 0.6 wide: SF Mono, Menlo, Courier, DejaVu. Consolas is 0.55, so its boxes are a little roomy.
    • Measuring with the DOM would be exact, but it would need a live element, and the boxes would move once fonts arrive.
  • Minimum scale 0.75: labels are 13px in 16px text, so the smallest is about 10px, still readable.
    • 0.6 (about 8px) was too small.
    • 1.0 (never shrink) would make every medium tree scroll on a phone.
    • It's a token, so a page can change it.
  • Every box in a row is as tall as the tallest one, so lines leave a row at one height and slot labels between two rows line up.
