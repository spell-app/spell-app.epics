• Radios bind by VALUE (chosen while the property is its value; choosing writes it), not !!value.
  • type=number / range controls write a number (null while blank); other controls keep a number property a number while what's typed reads as one.
  • After reset() / clear() / a native reset, the object takes the controls' values.
  • A ui-* control whose family loads later (docs site, <ui-root>) is bound once its tag is defined (customElements.whenDefined); found on the docs page, where the checkbox family loaded after the form's.
  • Template children are COPIED into the template's inert document and the originals removed (moving upgraded elements there broke their pending stylesheet adoption); the template is attribute-only: later framework updates to it don't reach rows. Ids repeat per row: use aria-label.
  • Plain objects: writes land, but only the form sees them (debug redraws by a change counter); <ui-repeat> follows a list only when the property is reactive and REPLACED (a list changed in place isn't seen). Solid stores can't be bound for writing: a direct store.x = is ignored in Solid 2.
