The form binding follows a few rules beyond what was asked for, each found while building it.

  • Radios bind by VALUE, not !!value.
    • A radio is chosen while the property is its value; choosing it writes that value.
  • Numbers:
    • number and range controls write a number, and null while blank
    • other controls keep a number property a number, while what's typed reads as one
  • After reset() / clear() / a native reset, the object takes the controls' values.
  • A Spell UI control whose family loads later is bound once its tag is defined (customElements.whenDefined).
    • That happens on the docs site, and inside a <ui-root>.
    • Found on the docs page, where the checkbox family loaded after the form's.
  • Template children are COPIED into the template's inert document, and the originals removed.
    • Moving upgraded elements there broke their pending stylesheet adoption.
    • The template is attribute-only: later framework updates to it don't reach rows.
    • Ids repeat per row: use aria-label.
  • Plain objects: writes land, but only the form sees them (debug redraws by a change counter).
    • <ui-repeat> follows a list only when the property is reactive and REPLACED: a list changed in place isn't seen.
    • Solid stores can't be bound for writing: a direct store.x = is ignored in Solid 2.
