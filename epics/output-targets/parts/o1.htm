Owen's idea (2026-10-05): just as spell will be WRITTEN in several human languages, it should RUN in several programming languages. Today it writes js/solid only; it could also write ts/solid, js/react, Python, and more.

  • His contention: scopes, methods, types and so on are similar enough across languages that spell can express the concepts once, with one tree-walker per language.
  • Some concepts won't apply everywhere: drawing in Python might do nothing, or write server pages.
  • Each language gets its own spellCore, to pave over the tricky bits (lists counted from 1, and so on).
  • Compiled output runs in its own language; loading it is not this epic's problem.
  • He asked for a tree diagrammer as one of the phases (1.4).

The sketch this plan starts from, with diagrams, FizzBuzz written three ways and a table of where languages disagree: Compile Targets.

What the sketch found, in short:

  • The seam already exists: nearly every rule builds a tree node (getAST()), 76 kinds of them.
  • But each node writes its own JavaScript, twice: compile() for the text, renderChildren() for the AST viewer.
  • The big concepts carry over; the work is in small things languages disagree on (truthiness, text plus a number, nothing, multi-line lambdas, names). Known datatypes let a writer use the language's own operator; unknown ones fall back to a core call.
