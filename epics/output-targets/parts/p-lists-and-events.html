The TypeScript still reads as spell's machinery: spellCore.filter() where a list could filter itself, spellCore.RUNTIME.trigger() for an event, a ! on every read that might be nothing, and == everywhere.

Spell's TypeScript reads as a person would write it, not as spell's machinery.

  • Core's list gains its own methods, and core gains on() / trigger().
  • The TypeScript writer uses them, compares the way TypeScript does, and writes ?. where it wrote !.
  • The JavaScript changes only for events and ?..

  • Events read as events (Q34, B; both targets): trigger("card-click", ...), not spellCore.RUNTIME.trigger(...).
    • Core exports four:
      • on(), off()
      • once(), trigger()
    • Each finds the CURRENT runtime when it's called: a new one is made each time a program starts, so none may hold on to the first.
    • TypeScript imports them, as it imports prop.
    • The payload's type is a type argument, and the handler takes it apart in its parameter.
    • JavaScript calls spellCore.on(...) / spellCore.trigger(...): its snapshots change once. 
    // today
const click = () => spellCore.RUNTIME.trigger("card-click", { card: this })
spellCore.RUNTIME.on("card-click", (event: { card: Card }) => {
  const { card } = event
  card.play()
})
// after
const click = () => trigger("card-click", { card: this })
on<{ card: Card }>("card-click", ({ card }) => card.play())

  • Comparisons a person would write:
    • Spell's is defined tests for undefined only, so it's === undefined, or its opposite.
    • === / !== wherever both sides' types are known and alike.
      • this.operator === "+"
      • this.value === card.value + 1
    • A choice compared to yes is written bare: pile.droppable && ..., not pile.droppable == true.
    • is no is !x.
  • Type tests in TypeScript's own words:
    • A class: startPile instanceof Tableau, not spellCore.isOfType(startPile, "Tableau").
    • A number: typeof x === "number".
    • Spell's other built-in kinds: an isOfType() method, on Thing and List.
  • Text that spell knows is text uses text's own methods:
    • spellCore.isEmpty(this.right) is !this.right: empty, or never set.
      • === "" only where it can't be unset.
    • spellCore.includes(this.input, ".") is this.input.includes(".").
    • spellCore.upperCase(x) is x.toLocaleUpperCase() where x is known text.
      • Where it might be nothing, `${x ?? ""}` first.
    • A list written out in place: ["diamonds", "hearts"].includes(this.suit).
  • Loops:
    • A for each statement is list.forEach(...), not spellCore.map().
    • One whose body waits is a plain loop, so the waits happen in turn: for (const card of cards) { ... await ... }.
  • A helper used often is imported by name: import { positionOf } from "@spell/core".
    • It's today's itemOf, renamed in the next phase, P16.
  • Small writing changes in the TypeScript:
    • a list's const and its type grouped together: the docstring, the const, the type
    • the members merged into a class (export interface Pile): ONE block per class, one member per line, not one block per member
    • } else { on one line
    • a true boolean attribute written bare: hidden
    • a handler that only sets a property, on one line: onClick={() => (this.operator = "+")}
    // today

export interface Pile { canPlayCard(card: Card): boolean }
// after
export interface Pile {
  canPickUpCard(card: Card): boolean
  canPlayCard(card: Card): boolean
