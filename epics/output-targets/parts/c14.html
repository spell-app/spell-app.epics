spellCore.element() builds its DOM nodes the moment it's called, not later when Solid would ask for them.

  • Nobody notices today.
  • It matters only if spell ever wants Solid to decide when, or whether, to build part of a drawing.
  • Why: @solidjs/h hands back a function that builds the node (a "thunk": work put off until it's called).
    • element() calls it at once.
    • Left as a thunk, the node would be built AGAIN each time the error net around it re-reads its children (C13).
  • The cost: a drawing builds every element it names, even one a later step throws away.
    • A card's draw() builds a handful, so it doesn't show.
  • P12's real JSX in a TypeScript .tsx doesn't go through element(), so this is about compiled JavaScript only.
  • none today; revisit if compiled JavaScript ever needs lazy children
