In the expressions folder, three things went into expressions.shared.ts rather than into one rule's file:

  • Precedence and OperatorOperands: every operator-suffix file uses them, so they had to be shared.
  • SuffixLeft: only one rule in the module uses it.
    • CompoundExpression sets it while it parses a suffix.
    • But it's the module's side channel for OTHER modules' suffixes: classes and methods read SuffixLeft.couldBeA().
    • So I treated it as the module's shared API, not a helper private to CompoundExpression.ts.
    • The other option: move it into that file. Nothing outside the folder would notice either way, since the folder's index re-exports both.
  • Also: Negatable's four registrations (is, can, will, has) live in Negatable.ts, right after the class.
    • The folder's index lists Negatable BEFORE InfixOperatorSuffix, which imports it, so the list shows the order files really load in.
    • The order rules register in is unchanged, and ruleNames.test.ts still passes.
