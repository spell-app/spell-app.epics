Where the classes split put what several rule files share:

  • classes.shared.ts holds:
    • the declare module adding enumeration / enumerationValues to ScopeVariable
      • set by define_property_has and value_kind, read by quoted_property_formula
    • MethodBody: for list_guard, property_value_getter, draw_side
    • placeholderData() and QuotedPropertyFormulaBits: for both QuotedPropertyRule and quoted_property_formula
  • QuotedPropertyFormulaBits moved there, over a type-only import of it from QuotedPropertyFormula.ts: the recipe says shared types go in the shared file.
  • Base and unregistered classes, a file each:
    • TypeDeclaration.ts: the base of create_type and create_list_type
    • QuotedPropertyRule.ts: made per formula by quoted_property_formula
    • Their docstrings keep their first line: neither has a rule name of its own.
    • TypeSpecifierEnum, Datatype and YesOrNo are bases too (of the outline_specifier_* rules), but registered rules, so in their own rule files anyway.
  • The shared augmentation's docstring said "only used in this file": now "this module".
