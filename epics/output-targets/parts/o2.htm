What happens when a project compiles, in order. Steps 1 and 6 are as today; the rest is what changes.

  1. Parse. The project's .spell files are matched against one syntax's rules (English today), building scopes as they go. Unchanged.
  2. Build the tree. Each match builds its tree node (getAST()), as now. But the node holds only what the program MEANS:
    • equals, not ==
    • the value up, not the already-quoted text 'up'
    • the spell name is a {suit}, not the JavaScript name is_a_$suit
  3. Check the output. Each output says what it can do (draw? react to changes?). A project that draws, compiled for an output that can't, gets an ordinary error in the editor.
  4. Write. The output's writer walks the tree and returns CODE: text pieces, each tagged with the tree node it came from.
  5. Finish. That one value gives the file's text, the AST viewer's coloured copy, and a source map: they can't drift apart, as compile() and renderChildren() can today.
  6. Run. The code imports its language's core (@spell/core for JavaScript), which papers over the rest: lists counted from 1, drawing, reactive properties.
