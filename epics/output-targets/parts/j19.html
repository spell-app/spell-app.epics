A to draw that ends if X return A, then "return B", becomes a Show tag in the order spell wrote it.

  • The condition as is, A as the children, B as the fallback.
  • 1.6 sketched it the other way round: when={!this.isFaceDown}, the face-up card as the children.
@drawn
draw() {
  const className = () => `Card face-${this.direction} ${this.rank} ${this.suit} ui button compact fluid `
  const click = () => spellCore.RUNTIME.trigger("card-click", { card: this })
  return (
    <Show
      when={this.isFaceDown}
      fallback={
        <div onClick={click} class={className() + this.color}>
          {`${this.shortRank} `}
          <span class="suit">{this.shortSuit}</span>
        </div>
      }
    >
      <div onClick={click} class={className()}>
        <i class="fitted bicycle icon" />
      </div>
    </Show>
  )
}
  • Why:
    • It keeps the condition as spell wrote it: no ! added.
    • Two or more ifs become a <Switch> the same way: each if a <Match>, the last return the fallback.
  • The cost: the face-up card, usually the bigger drawing, sits in fallback.
  • Reads in spell's order; flip it only if you'd rather the main drawing were the children

The else is the fallback

You said: "The else is the fallback."

That's how it's built: what the drawing returns when the if is false is the <Show>'s fallback, and the if's own return is its children. 

// if it is face down
//   return <div ...><i className="fitted bicycle icon"/></div>    the if's return:  the children
// return <div ...>{the short-rank of the card + " "} ...</div>      the else:  the fallback
<Show
  when={this.isFaceDown}
  fallback={
    <div class={className() + this.color} onClick={click}>...</div>
  }
>
  <div class={className()} onClick={click}><i class="fitted bicycle icon" /></div>
</Show>
