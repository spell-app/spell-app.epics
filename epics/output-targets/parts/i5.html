A ts/solid project that reads another project's derived property would read the wrong name. Found fixing I1.

  • The TypeScript writer renames a read to TypeScript's name (card.shortName) when it knows the member is a getter.
  • For a type imported from another project, it knows only what the import's declarations say:
    • "method" for card "is face up" if ...: renamed, fine
    • but "property" for the short name of a card is ..., the same as for a stored property (is_set_up) 
spellCore.echo(card.short_name) // Cards.compiled.tsx names the getter shortName:  undefined at run time
  • No fixture reads one today: Klondike reads only is face up and is face down, which are renamed.
  • The fix:
    • the declarations record a derived property as such (e.g. "getter": true)
    • the import layer keeps it
    • P.TSProject reads it, as it reads imported methods now
  • Until then, a ts/solid project reading another project's derived property gets undefined.
  • The contract test would catch it, on a fixture that does.
