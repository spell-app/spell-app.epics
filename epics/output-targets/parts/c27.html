Compiled javascript now imports helpers by name, so the runtime it links against must export them.

import { spellCore, Thing, List, App, positionOf, trigger, on } from "@spell/core"
  • The runners point @spell/core at spell-runtime.js, which now exports them (spellRuntime.ts).
  • A runner built BEFORE this change has the old spell-runtime.js.
    • That's the installed VS Code extension, or a built dist-element/.
    • A program compiled now fails to link there: trigger isn't exported.
  • Rebuild:
    • spell dev vscode
    • yarn build:element / build:runner, in packages/app
    • The editor's dev server picks it up by itself.
  • Also: a project compiled before P19 (snake_case names) that imports a library compiled after it (camelCase) won't find its methods.
    • Every committed example and the cards library are recompiled together.
    • A user project compiled earlier recompiles on its next compile.
  • Rebuild the VS Code extension and the element bundles before running freshly compiled examples there.
