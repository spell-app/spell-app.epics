Compiled javascript now imports helpers by name: import { spellCore, Thing, List, App, positionOf, trigger, on } from "@spell/core". The runners point @spell/core at spell-runtime.js, which now exports them (spellRuntime.ts).

  • A runner built BEFORE this change (the installed VS Code extension, a built dist-element/) has the old spell-runtime.js: a program compiled now fails to link there (trigger isn't exported).
  • Rebuild: spell dev vscode, and yarn build:element / build:runner in packages/app. The editor's dev server picks it up by itself.
  • Also: a project compiled before P19 (snake_case names) that imports a library compiled after it (camelCase) won't find its methods. Every committed example and the cards library are recompiled together; a user project compiled earlier recompiles on its next compile.
  • Rebuild the VS Code extension and the element bundles before running freshly compiled examples there.
