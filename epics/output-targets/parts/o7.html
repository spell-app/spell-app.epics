Errors with other causes

Beyond the markers, the other projects' errors come from five places the writer or core can fix:

  • Statics set after the class (OutlineSolitaire, 13 errors and 5 inferred anys).
    • The outline style: a "deck" is a list of cards with: - "suits" as one of ...
    • It writes Deck.Suits = [...] below the class, which TypeScript doesn't see as a static.
    • And static get instanceType() (read when set) leaves Deck as a plain List, not List<Card>.
  • A member patched on from another project (Solitaire-import, 1 error): C6, now seen for real.
    • export interface Card { play(): ... } clashes with the imported Card (TS2440).
  • Named arguments typed Object (both Todos, 3 errors and 3 inferred anys).
    • to create a new task (with title as text) becomes create_a_new_task(props: Object = {}).
    • So let { title } = props fails, though spell says the title is text.
  • Enumerations widened (cards, 2 errors).
    • static Colors = ['red', 'black'] is a string[].
    • So a joker's color can't override a card's, whose getter returns 'red' | 'black'.
    • Written as const (as 1.6 plans), every enumerated property becomes the union of its values.
  • Core's loose returns.
    • The four helpers above return unknown.
    • itemOf(this, card) inside a List sub-class is string | number, not a position.
    • KeyOf can't resolve this: 1 error each in the example Solitaires.
