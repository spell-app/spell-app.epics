contract.test.ts compiles every fixture for both targets, runs each the way spell run does, and compares.

  • It runs each in runProject.ts, the child process spell run uses.
    • The TypeScript runs from a .mts file, which tsx strips.
  • It checks two things:
    1. both print the same, line for line
    2. what they print matches <Project>.out.txt
  • The snapshot is what catches a broken core method, since both targets share @spell/core.
    • Breaking spellCore.getRange() by one failed FizzBuzz, as it should (tried, then put back).
