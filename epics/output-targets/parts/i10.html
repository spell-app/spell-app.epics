Todos - Form Based's All / Active / Completed menu never filtered the list: it only moved its highlight.

  • Owen flagged it in test V14: "filters don't work".
  • Not a regression of this epic. The git history of the example says so:
    • The first Todo app (2020) filtered: its to draw (a task) drew nothing for a task the filter hid.
    • The form-based rewrite (2020-08-18, "Todo example uses a form (not quite finished)") repeated EVERY task, and never read the filter again.
    • P11 kept that, and its test step said "It never filtered the list, and still doesn't".

The fix, in the example's spell only: a derived property, the tasks the filter shows, and the repeat draws those.

the shownTasks of a todos-app is:
	if its filter is "active" return tasks in its tasks where it is active
	if its filter is "completed" return tasks in its tasks where it is complete
	return its tasks

<ui-repeat name="shownTasks">
  • Each row still binds to the task itself, so a tick or a title change writes to the real task.
  • Ticking a task under Active hides its row at once: it isn't active any more.
  • The compiled JavaScript was regenerated (a plain getter, spellCore.filter()), and checks clean.
  • Test: the runner's browser test clicks Active and Completed in the real compiled example and reads the rows.

Left for later, a design choice: how spell hands <ui-repeat> its list.

  • name is the JavaScript name of a property of the form's object, typed as text.
    • So the property has to be called shownTasks.
    • A spell-style name, shown-tasks, compiles to shown_tasks, which the person would have to know to type.
  • Options:
    1. Keep it: a repeat names a property, as every other control in a bound form does.
    2. <ui-repeat items={...}>: a spell expression for the list, e.g. items={tasks in the tasks of the app where it is active}, no derived property needed.
    3. The compiler turns a name written in spell's words into its JavaScript name.
  • All shows every task; Active, the tasks not done; Completed, the tasks done.
  • The example gains one derived property, shownTasks.
  • Fixed in the worktree, not committed yet; the repeat's spelling is open.
