For the TS Solid for Realz phase (then P10, split since into P10 to P13; the sketch: 1.6): which decorators does ts/solid use? Owen: "it can use decorators".

  • Compiled JavaScript can't: it runs from a blob: URL, with no build step.
  • So today each property is four lines.
  • ts/solid output is built, so it can.

The repo has two families of decorators:

  • spell's, for hand-written spell classes (spellDecorators.ts):
    • @prop(info) accessor x!: T: a property, stored in spell cells
    • @derived get y(): a remembered derived value
    • @thing: runs create() after the class's fields
    • The editor's EditorStore uses them.
  • Spell UI's, for <ui-*> elements (Reactive.ts), over each element's own record:
    • @E.state, @E.controlled
    • @E.onChange ...

Let's work toward combining SpellUI and Spell decorators.
If we can make the reactivity work exactly the same way, so much the better

Yes, it can be one reactivity, and the two are closer than they look. Both already keep each object's values in a plain record that reads back fresh right after a write. They differ in one thing: how a change reaches Solid. Spell uses "spell cells", its own small tracker with a single hook into Solid. Spell UI gives each member its own Solid signal. Making them the same means ONE engine (spell cells) under both, in $/util, with Spell UI's element-only decorators on top. P10 can take the first step. Moving Spell UI over is its own piece of work, after the spell-element epic merges.

  • For P10's output nothing changes: ts/solid still writes @prop, @derived and @thing, imported from @spell/core.
    • Spell programs have no internal state and no "when this changes" yet, so Spell UI's @state and @onChange have nothing to compile from
    • Spell UI's members come in by being the SAME decorators later, not as a second set beside spell's (the second set was the cost option C named)
  • The catch: Spell UI would run on spell cells, so the cells' hook into Solid would sit on every Spell UI page. That has to be measured, and Spell UI's tests would flush differently (C12).
  • Today the two can't see each other inside a derived value: a Spell UI @E.derived reading a spell Thing's prop never recomputes, and the other way round (C11). One engine fixes that.

The two today, side by side

Words used below:

  • record: the object holding an instance's values; the only truth, read and written at once
  • spell cell: a small marker per value that remembers who read it and tells them when it changes (cells.ts)
  • notifier: Spell UI's Solid signal per member, holding no value, set on each change so Solid re-runs whoever read the member
  • bridge: bridgeSolid(), spell's one hook into Solid (Solid's enableExternalSource): every Solid computation also tracks the cells it reads 
// packages/util/src/spell/spellDecorators.ts:30-53 (trimmed)
export function prop(info: PropInfo = {}) {
  return function (_target, context) {
    const name = String(context.name)
    declareInMetadata(context.metadata!, name, info) // the class's schema:  type, default, oneOf
    return {
      get() { return extend.getProp(this, name) },
      set(value) { this.setProp(name, value) } // a Thing checks the type here
    }
  }
}

// packages/util/src/spell/extend.ts:124-134 -- every write ends here
export function storeProp(target: any, property: string, value: unknown): boolean {
  if (value === undefined) return deleteProp(target, property) // nothing:  the key goes
  const extended = extendedFor(target)
  const record = extended[PROPS] // a Map:  the truth
  const added = !record.has(property)
  if (!added && record.get(property) === value) return false
  record.set(property, value)
  extended[PROP_CELLS]?.get(property)?.changed() // its spell cell marks its readers
  if (added) extended[KEYS]?.changed()
  return true
}

// packages/ui/src/elements/Reactive.ts:586-609 (trimmed)
function stateAccessor(context, { equals = isSame, ownedWrite = false }: StateOptions) {
  const name = context.name
  return {
    get() {
      const record = Reactive.recordOf(this)
      if (collecting || getObserver()) reading(notifierFor(record, name, ownedWrite))
      return record.values[name] // a plain object:  the truth
    },
    set(next) {
      const record = Reactive.recordOf(this)
      if (equals(record.values[name], next)) return
      record.values[name] = next
      record.sources.get(name)?.changed() // its notifier tells Solid
    },
    init(initial) {
      Reactive.recordOf(this).values[name] = initial // the initializer IS the starting value
      return initial
    }
  }
}

// Reactive.ts:397-421 (trimmed) -- the notifier
class Notifier {
  version = 0
  private signal?: Signal<undefined>
  track() {
    if (!getObserver()) return
    ;(this.signal ??= createSignal<undefined>(undefined, { equals: false, ownedWrite: this.ownedWrite }))[0]()
  }
  changed() {
    this.version++
    if (this.signal) notify(() => this.signal![1]()) // inside a render Solid forbids it:  a microtask later
  }
}

// Installed ONCE per page by the HOST (the app's cellsBridge.ts):  util and core never import Solid,
// so spell-runtime.js, which compiled JavaScript loads from a blob: URL, holds none
export function bridgeSolid(solid: SolidForBridge): void {
  const context = cellsContext
  if (context.bridged.has(solid.enableExternalSource)) return
  context.bridged.add(solid.enableExternalSource)
  solid.enableExternalSource({
    factory(compute, trigger) {
      const reaction = new Reaction(trigger) // every Solid computation also reads cells
      return { track: (previous) => reaction.run(() => compute(previous)), dispose: () => reaction.dispose() }
    },
    untrack: untrackCells
  })
  addCellsHostFlush(solid.flush)
}

What "exactly the same" takes

One engine has to win, and it can only be spell cells:

  • core can't run on Spell UI's: compiled JavaScript loads only @spell/core from a blob: URL, which must hold no Solid, and the React drawing and observe() read cells outside Solid
  • it was already measured: solid-2.html, "The candidates", compared "record + notifiers" (N, Spell UI's design) with spell cells (X) and picked X, the only one that is exact, memoizes, and lets a drawing write freely; it calls N "X without memoization", sharing the record

The steps:

  1. The engine moves to a generic folder of util, reactive/: cells, Cell, Derived, Reaction, bridgeSolid(), the records (extend.ts) and Schema.
    • No lodash (only setState()'s dotted paths use it; they stay in $/util/spell), no Solid
    • so Spell UI can import it file by file, as index.ts imports util's other generic files today
  2. One decorator set there: @prop, @state, @derived.
    • with Spell UI's options: { equals } on @state and @derived
    • an initializer allowed on @state; warned only where a create() runs first, as @prop warns today
    • @state is the decorator WWOD §13 has as a TODO ("a @state decorator for Observables?"): hand-written spell's getter / setter pairs over getState() / setState() become one line (SpellFile.ts, lines 102-137, has five)
  3. Spell UI installs the bridge itself, from its core. The tracking context is shared on globalThis, so the editor, a <spell-app> and a Spell UI page share one bridge.
  4. Reactive.ts keeps only what needs a DOM element: @controlled, the attribute getters, @cssState, @onChange, $ and spell-element's additions. Its sources become cells; Notifier, DerivedCache and notify() go. E.state and E.derived are $/util's.
  5. @thing stays spell's (spellDecorators.ts): it orders Thing.create(), which Spell UI has no use for.

What changes for a reader afterwards:

  • one @state and one @derived, which work the same in a component, the editor and a Thing
  • a derived value may read anyone's members (C11 gone)
  • Spell UI's @derived gets the real cutoff: its Solid readers re-run only when its value changed
  • no write is deferred a microtask inside a render, and { ownedWrite } goes

The costs, to check before switching (C12):

  • the bridge wraps every Solid computation on every Spell UI page: re-run the 1,000-button check and yarn measure
  • Spell UI's test helpers must call flushCells(), since a derived-only reader hears a microtask later
  • the static server render has never run the bridge
  • spell-element rewrites Reactive.ts and isn't merged: the switch comes after it
