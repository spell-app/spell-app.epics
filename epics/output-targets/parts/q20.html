For the TS Solid for Realz phase (P10; the sketch: 1.6). Owen: "it can use decorators". Compiled JavaScript can't (it runs from a blob: URL with no build step), so today each property is four lines; ts/solid output is built, so it can. The repo has two families of decorators:

  • spell's, for hand-written spell classes (packages/util/src/spell/spellDecorators.ts): @prop(info) accessor x!: T (a property, stored in spell cells), @derived get y() (a remembered derived value), @thing (runs create() after the class's fields). The editor's EditorStore uses them.
  • Spell UI's, for <ui-*> elements (packages/ui/src/elements/Reactive.ts): @E.state, @E.controlled, @E.onChange ..., over each element's own record. 
// before:  4 lines
static { this.declareProp('rank', { oneOf: Card.Ranks }) }
get rank(): (typeof Card.Ranks)[number] { return this.getProp('rank') as (typeof Card.Ranks)[number] }
set rank(value: (typeof Card.Ranks)[number]) { this.setProp('rank', value) }

// after:  1 line, the same runtime shape
@prop({ oneOf: RANKS }) accessor rank!: Rank
  • re-exported by @spell/core, so compiled code still imports only its core (and Solid)
  • the same runtime shape as today's pairs: Thing checks and stores a property as now
  • @derived only where a getter loops over a list (Pile.state), as house style says; @thing only on a class with a to create
  • least change; nothing new to build
  • four lines per property; not what a person writes
  • @E.state, @E.onChange on spell classes
  • a second state system beside spell cells: a Thing's state must read fresh right after a write and print as its properties, which only spell cells give
  • @spell/core re-exports prop, derived and thing
  • every compiled property is one @prop line
