Each new list method calls its spellCore twin, so there's one copy of the logic.

  • Two twins were wrong for lists, so I fixed the twin, not the method.
  • That also changes what compiled JavaScript does, in two edge cases.
  • Removing a range of a list threw.
    • remove items 2 to 4 of the pile stopped the program with a TypeError ("Cannot set property length").
    • It worked only on plain arrays.
    • Now a list removes them one by one, last first, so a pile's cards lose their owner as they should.
  • A range with nothing in it was a plain empty array, even from a pile: item 5 to 6 of the pile, when the pile holds 2 cards.
    • Now it's an empty list of the same class: an empty Pile, which owns nothing.
    • So pile.between(5, 6).isEmpty works, instead of reading off a plain array.
    • Plain arrays and text still get [].
