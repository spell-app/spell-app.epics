Solid 2's JSX types accept only the page's own spellings. So the ts/solid writer must translate the React spellings spell programs write, as element() does at run time for JavaScript.

  • tsc rejects React's names (TS2322), measured through typecheck().
    • Rejected: className, colSpan, htmlFor, tabIndex.
    • Write instead, lowercase as in HTML: class, colspan, for, tabindex.
  • prop:value={...} type-checks only on a <ui-*> tag; on a div it's an error.
    • The <ui-*> tags are typed loosely, by app's solid.types.ts.
  • At run time, a plain prop on a tag with a dash is a STRING attribute.
    • So an object or a live value on a <ui-*> tag MUST be prop:value={...}.
    • That's what element()'s isPropertyOf() decides, for JavaScript.
  • onUiChange type-checks on a <ui-*> tag (the types are loose), but Solid listens for "uichange".
    • A hyphenated event (ui-change) needs a ref directive, as the Solid 2 rules say (solid-2.md).
  • Accepted:
    • colspan={2}, or "2"
    • style={{ color: "red" }}
    • class={["a", { b: true }]}
    • onClick={(event: any) => ...}
export const a = <div className="x" />    // TS2322
export const b = <td colSpan={2} />       // TS2322
export const c = <td colspan={2} />       // ok
export const e = <div prop:value={{ a: 1 }} />  // TS2322
  • The writer lowercases attribute names.
  • It routes rich values on <ui-*> tags to prop:, as element() already does at run time.
