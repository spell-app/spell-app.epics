Solid 2's JSX types accept only the page's own spellings, so the ts/solid writer must translate React's spellings that spell programs write, as element() does at run time for JavaScript.

  • Rejected by tsc (TS2322), measured through typecheck(): className, colSpan, htmlFor, tabIndex. Write class, colspan, for, tabindex: lowercase, as HTML.
  • prop:value={...} type-checks only on a <ui-*> tag (typed loosely, by app's solid.types.ts); on a <div> it's an error.
  • At run time, a plain prop on a tag with a dash is a STRING attribute: an object or a live value on a <ui-*> tag MUST be prop:value={...}, as element()'s isPropertyOf() decides for JavaScript.
  • onUiChange type-checks on a <ui-*> tag (loose types), but Solid listens for uichange: a hyphenated event (ui-change) needs a ref directive (guides/solid/solid-2.md).
  • Accepted: colspan={2} or "2", style={{ color: "red" }}, class={["a", { b: true }]}, onClick={(event: any) => ...}. 
export const a = <div className="x" />    // TS2322
export const b = <td colSpan={2} />       // TS2322
export const c = <td colspan={2} />       // ok
export const e = <div prop:value={{ a: 1 }} />  // TS2322
  • The writer lowercases attribute names and routes rich values on <ui-*> tags to prop:, as element() already does at run time.
