Two shapes the plan left open:

  • @derived: on a getter whose body has an inline function, i.e. it loops over a list.
    • For example Pile.state, Game.state.
    • WWOD says memoize only pure, worth-it getters; spell can't prove "pure" yet.
    • So this is the plan's rule of thumb, checked by the core contract printing the same on both targets.
  • @prop() with no arguments: for a property spell never declared a type for, like the name of a pile.
    • JavaScript writes no declareProp() for it.
    • The decorator declares it with no type, which checks nothing either.
  • Every property is one decorated line; the contract test is what keeps both from changing behaviour
