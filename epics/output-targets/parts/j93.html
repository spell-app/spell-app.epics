h() hands back a thunk (a function that makes the element). A draw() returns it as is, and core's error net makes it. The net makes ONLY h()'s own thunks, and tells them apart by the mark h() puts on them.

  • The mark is a symbol @solidjs/h keeps to itself. Core reads it off a thunk of its own when it loads, h("i"), which makes nothing and touches no page (H_THUNK in drawing.ts). It's exact: the same copy of h core exports to compiled javascript.
  • Any other function a draw() returns is a live value, left for Solid to call (and call again when it changes). A test pins both, and pins the mark, so a Solid bump that drops it fails there.
  • Not made by the net: an ARRAY of thunks from a draw(). The writer never returns one: a drawing is one h() at the top.
  • The stand-in a failed drawing shows is made at once too (it was a thunk, left as the memo's value).

Measured (rc.13), with and without the net making the thunk:

  • A throw while the thunk is made (a part of the drawing that can't be drawn): with it, the stand-in and one console line; without it, an EMPTY spot, no stand-in.
  • Made more than once: neither core's fake page nor the browser runner's 22 tests made a card or pile again when a card was added, either way. The rule's real work is the error net; "once" is kept and pinned by a test anyway.
  • Compiled javascript returns h(...) straight from draw(); nothing wraps it
  • A drawing that throws while it's made shows its stand-in, as a draw() that throws does
