For the One Rule per File phase (P18): each rule moves to a file of its own. What should each file be called?

  • A rule's class name IS its rule name: the build keeps class names (keepNames), and the parser reads the rule's name from its class (parser's AGENTS.md).
  • Rule names are snake_case: list_add_relative, list_item_ordinal.
  • The file and the rule match, so a search for the rule's name finds its file at once.
  • A parse error or a test that names the rule names its file too.
  • Unlike the rest of the repo's file names, which are camelCase or kebab-case.
  • Matches most of the repo's TypeScript files.
  • The file name and the rule name differ: one more step to get from a rule to its file.
  • Matches the repo's kebab-case files (identifier-blacklist.ts).
  • The file name and the rule name differ, as B.
  • Each rule's file is named for the rule: list_add_relative.ts.
  • P18's files are named this way; nothing else changes.
