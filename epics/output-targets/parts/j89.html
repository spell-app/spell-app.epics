Fixing the six spell-ui/* lint errors in ui-form, two uses stay hand-written, each with a disable comment and an allow-list entry (the lint patterns test):

  1. FormBinding keeps its createEffect: it is a helper class, not a component, so no @E.onChange can reach it. It makes one effect per bound control, each in a root of its own that is disposed when the control goes: a per-item effect, which the Solid authoring rules leave explicit. Same reason as SlottedItems.
  2. UIRepeat's template watch is @E.whileConnected plus its own MutationObserver, not @E.watches. It watches only while connected, as before (and as UIForm / UIRoot do). @E.watches would watch for the element's whole life, and a watched method is not called at the start, so it would need a second hook to take the template on connect.

The other three errors were fixed as the rules say: queueMicrotask() became E.afterSolidUpdate() (the same microtask), and FormBinding's two untrack() calls became @E.untracked on writeBack(). That decorator works on any class.
