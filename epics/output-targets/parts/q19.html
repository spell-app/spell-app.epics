For the TS Solid for Realz phase (then P10, split since into P10 to P13; the sketch: 1.6): how does a spell drawing become Solid?

  • A spell to draw is statements: a local, an if with an early return, a loop.
  • React copes by running the whole method again on every change, and diffing.
  • Solid has no diff: a component runs ONCE, and re-running a drawing makes brand-new DOM nodes. Focus, scroll and animations are lost.
  • So how the statements become Solid matters. Card's drawing, in spell:
 
to draw a card:
	set className to "Card face-" + its direction + " " + its rank + " " + its suit + " ui button compact fluid "
	if it is face down
		return <div onClick={fire event card-click with card = it} className={className}>...</div>
	return <div onClick={fire event card-click with card = it} className={className + its color}>...</div>
  • a computed local becomes an accessor: const className = () => ...
  • a chain of ifs that return becomes <Show> / <Switch>
  • draw cards in it becomes <For>
  • Card's whole drawing becomes one <Show when={!this.isFaceDown} fallback={...}>
  • any other shape (a loop building a list, a local set twice) still works: the drawing re-runs whole, inside its error net
  • cost: the bulk of the writer's new work; each shape needs tests
  • draw() keeps its statements; whoever draws it re-runs it when anything it read changes
  • simple, and every program works
  • a flipped card rebuilds its DOM; the game's drawing rebuilds the whole board when the score changes. Not what a person writes on Solid
  • the purest output: every drawing in Solid's shapes
  • a program with a shape the writer can't translate fails to compile for ts/solid
  • the TypeScript writer learns to write accessors, and Solid's Show, Switch and For tags, from a drawing's statements
  • any other drawing still draws, re-running whole inside its net
