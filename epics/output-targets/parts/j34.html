Owen asked for a keys getter on lists, beside values. It isn't there, because the name is taken.

  • Every list already has a keys() method, from the class all spell things are built on: it lists the list's own properties (a pile's name, say), not its positions.
  • The Thing Explorer calls it on every thing it shows, lists too. A keys getter would break the explorer, and TypeScript refuses a getter that replaces a method.
  • So a list's positions stay getKeys(), which answers [1, 2, ... length]. The values getter is there.
  • If you want a getter anyway: a new name, e.g. positions. Say so and it's one line.
