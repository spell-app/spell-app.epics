Once compiled JavaScript draws with Solid (stage 1 of P10, Q23), the React kits that spell programs reach as UI.* and SUI.* have nothing left to draw them. One example uses both: examples/Todos - Form Based, which would stop drawing.

  • What the kits are: spellRuntime.ts registers UI (the app's forms, F in packages/app/src/ui/forms/, plus SUIPassThroughs) and SUI (semantic-ui-react), all React. Both keys are spell's public names: .spell sources write <UI.Form> and <SUI.Menu>.
  • What todo.spell uses, and the Spell UI element each could draw:
    • SUI.Container, SUI.Segment, SUI.Menu, SUI.Menu.Item: <ui-container>, <ui-segment>, <ui-menu>, <ui-item>
    • UI.Button, UI.Input, UI.Checkbox: <ui-button>, <ui-input>, <ui-checkbox>
    • UI.Form value={the app}: <ui-form> only if it can bind each field to a Thing's property by name, as F does
    • UI.FormRepeat name="tasks": no twin; it repeats its fields once per item of a list
<UI.Form debug value={the app}>
	<UI.FormRepeat name="tasks">
		<UI.Checkbox name="completed" width={1}/>
		<UI.Input name="title" width={10}/>
	</UI.FormRepeat>
	<UI.Input name="newTaskName" placeholder="New task name" label="New task:" width={11}/>
	<UI.Button disabled={the newTaskName of the app is ""} onClick={create a new task} content="Add Task"/>
</UI.Form>
  • The way out, to settle while building stage 1: UI.X and SUI.X name a <ui-x> element; the form's binding and FormRepeat become plain spell in the example (a draw ... in it loop, each field's value and onChange), or a small Solid form kit in core. Either way the example changes, and stays as short as it can.
