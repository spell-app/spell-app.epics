Fix 1 of the untyped gap (1.7), the biggest single cause of any in ts/solid's output: spell works a type out while parsing, but the tree node made from the match doesn't keep it, so TSWriter finds nothing and writes a marker (any /* spell: type unknown */).

  • Where spell has the type:
    • a loop's or a where's variable is in its nested scope, with its datatype (list_iteration.getNestedScopeForMatch() and getWhereScope() in packages/spell/src/rules/lists.ts)
    • an item read from a list has it as the match's datatype (ListItemExpression.getDatatype(), same file)
  • Where it's lost:
    • getAST() builds new P.ASTVariableExpression(item, { name }), without it
    • ASTNode.datatype is the node's own _datatype, never its match's (packages/parser/src/ast/AST.ts)
  • The change:
    • ASTNode.datatype falls back to this.match.datatype. That's allowed in a writer: getDatatype() reads only match.data and child matches, never scope
    • a loop's or where's argument node carries its ScopeVariable (as variable), noted in match.data while parsing, as getAST() mustn't look it up
  • How many: 152 of the 285 untyped places across the 9 projects. 85 are loop and where variables (a Card or a Pile), 67 are locals read from a list (getItemOf() 29, filter() 18, randomItemOf() 8, and the rest).
