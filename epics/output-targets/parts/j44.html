For J20 / I5, a project's declarations now mark a derived property "getter": true. Loading it sets isGetter on the imported member's record, a new field documented on P.ScopeVariable. The TypeScript writer reads it.

  • Marked: the short rank of a card is: ..., its "color" is red if ... otherwise black, and - to "draw its front".
  • Not marked: a value kind's property (the color of a suit is: ...). It's a static method, read through readAs.
  • A belongs to one member (pile on a card) is a getter too. Its declaration doesn't repeat it, since exclusive already says so, and loading works it out. That keeps those declarations unchanged.
  • Every fixture's declarations snapshot gained "getter": true on its getters.

Why do we need this?

You asked: Why do we need this?

Today, only because the TypeScript writer names a getter and a stored property differently. Once P19 names every member the same way, the flag can go.

  • The TypeScript writer camelCases a getter or method (short_rank becomes shortRank).
    • A stored property keeps spell's own name (face_up stays face_up), because saved JSON, the Thing Explorer and scopes read it by that name.
  • So, writing the short rank of the card, the writer must know which short_rank is.
    • Declared in the same project: it can see the is: ... definition, so it knows.
    • Declared in ANOTHER project (Solitaire's Card, imported): all it has is that project's declarations. Without "getter": true it would write card.short_rank, which is undefined at run time.
  • That's the only reader: TSProject.getters, used in one place, TSWriter's member naming (TSWriter.ts:188). 
const property = this.project.getters.has(name) ? camelCaseOf(name) : name

Your answer to the javascript-names question (Q51) changes this. P19 camelCases methods AND properties, in both writers, and moves saved JSON, the Thing Explorer and scopes over too. After that, every member is written camelCaseOf(name) whether it's a getter or not, so the flag tells the writer nothing.

  • Imported getters stay right in TypeScript until then.
  • P19 drops "getter": true from declarations and isGetter from the scope's records, once names no longer depend on it.
  • Every fixture's declarations snapshot loses the line again: one diff in P19.
  • Until P19, TypeScript reads an imported getter by the wrong name (card.short_rank), so the Solitaire examples that import Card break in ts/solid.
  • Nothing changes now.
  • P19's goal gains one line: remove the getter flag once every name is camelCase.

You asked: explain "once every member" -- member of what?

  • A member of a CLASS: anything a thing of that class has. Cards' Card has three kinds:
    • stored properties, e.g. direction: a value it holds
    • getters, e.g. is face up: worked out each time it's read
    • methods, e.g. turn face up: something it does
  • "Once every member is camelCase" meant: if stored properties went camelCase too, every name a class has would be written one way, and the writer would never need to know which kind a name is. That's the open part, now its own question, Q56, with examples.
  • Tonight P19 keeps stored properties as they are (your Q51 answer, "as TypeScript"). So the "getter": true flag is still needed, and stays.
  • This waits on Q56. With B there, the flag stays; with A, it goes.
