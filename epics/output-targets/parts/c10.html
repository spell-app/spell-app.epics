An enumeration's "kind" (OutlineSolitaire's Suit and Rank) is written as an empty class holding its formulas as statics. Used as a type, it looks typed and checks nothing.

  • Once spell's types reach the writer (fix 1 of 1.7), a parameter spell knows is a suit is typed Suit.
  • And used as a type, an empty class accepts ANY value.
// the "color" of a suit is:  red if it is diamonds or hearts, black otherwise
export class Suit {
  static color(suit: Suit) {      // suit is really 'clubs' | 'diamonds' | ..., but Suit has no members:
    ...                           //   Suit.color(42) type-checks
  }
}
  • Where: 2 parameters in OutlineSolitaire (Suit.color(), Rank.is_a_face_card()).
  • The fix, when it's worth it: a type named for the values, beside the formulas.
    • For example export type Suit = (typeof Deck.Suits)[number].
    • And the formulas in a Suit object of functions: a type and a value may share a name.
