Where do the writers live?

  • The tree's 76 node classes live in the PARSER package today: AST.ts, as P.ASTIfStatement and friends. Several are spell-specific already (ASTSpellCoreExpression, ASTJSXElement).
  • The parser calls into them: match.compile() calls the rule's compile(), which for spell's rules is getAST().compile(). So whoever writes JavaScript must be reachable from there.
  • Dependencies flow one way: spell → parser. The parser can't import spell.
  • new folder writers/; nothing else moves
  • a CODE-DEBT.md entry: the parser holds spell's tree and writers
  • writers/: Writer.ts, JSWriter.ts, TSWriter.ts
  • P.JSWriter; match.compile() reaches it with no new wiring.
  • Least churn. A later move into a package of their own stays possible.
  • Cost: the "generic" parser holds more spell-specific code.
  • packages/outputs/ ($/outputs): the tree AND the writers, moved out of the parser.
  • spell → outputs → parser.
  • Cleanest: the parser goes back to being generic.
  • Cost: moving 76 classes and every P.AST* use (rules, app, LSP, tests); the compile call needs a hook the parser exposes.

Owen's own choice, typed in: parser/src/writers, a sibling of src/ast/ rather than inside it (option A had src/ast/writers/).
