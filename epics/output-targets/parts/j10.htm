How declarations moved into <Project>.declarations.json (Q8). The /*! SPELL: DECLARES */ comments did TWO jobs: they carried declarations to importing projects, AND they marked where each declaration's code is in the compiled output, which the runner's Type Explorer reads to show a declaration's code from a scope pack. Chose to keep the comments as an INTERNAL marker while compiling, and split them out at the end, over generating the declarations separately from the tree.

  • Compiling still puts a marker on each declaring statement (commentFor()), never written to disk. SpellDeclarations.split() takes them out: the compiled .js is just code, and the declarations file gets each marker's object plus codeLines, the line its code starts on.
  • The Type Explorer (packages/lsp/src/ScopesSource.ts) finds code by codeLines; the runner fetches the declarations lazily, only when you open a declaration's details: from the server (/api/projects/declarations/<id>, new), beside a src= app's .compiled.js, or pushed by <spell-editor>.
  • Older compiled files still work: importing reads the comments when there's no declarations file (fromComments()), and the Type Explorer falls back to scanning markers.
  • Scope packs didn't change: the examples' .scopes.js came out identical.
