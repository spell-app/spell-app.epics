What happens when a project compiles, in order, as built.

  • Two targets so far: js/solid and ts/solid.
  • Python is in the picture to show where it would go: it's a later epic (C28).
  1. Parse: the project's .spell files are matched against one syntax's rules (English today), building scopes as they go. Unchanged by this epic.
  2. Build the tree: each match builds its tree node (getAST()), as before. The node holds what the program MEANS (P3):
    • equals, not ==
    • the value up, not the already-quoted text 'up'
    • Not yet: names. The tree still holds the JavaScript name is_a_$suit, not the spell name is a {suit} (J4, C31).
  3. Check the target: each target says what it can do; so far only whether it can draw (J12). A project that draws, compiled for a target that can't, gets an ordinary error in the editor.
  4. Write: the target's writer walks the tree and returns its code as plain text.
    • The javascript writer (JSWriter) holds every shape both targets share: a list's own methods, ===, template text, camelCase method names (P19).
    • The TypeScript writer (TSWriter) adds only TypeScript's own: types, decorators, JSX (P12).
    • Javascript draws each element with Solid's own h(), with the page's spellings, and is formatted as TypeScript is: const, no extra parentheses or braces, double quotes (P20, P22).
    • Every member's name is camelCase in both writers, stored properties too (Q56).
    • Tagging each piece with the tree node it came from waits for source maps (J2, C29).
  5. Finish: the compiled files go beside the project.
    • <Project>.compiled.js for javascript
    • <Project>.compiled.tsx for TypeScript, when the project lists that target
    • <Project>.declarations.json: what the project declares, for projects that import it (P5)
    • <Project>.en.js: each member's compiled name to spell's wording, which the Thing Explorer shows (P22)
  6. Run. The code imports its language's core (@spell/core for JavaScript and TypeScript), which papers over the rest:
    • lists counted from 1
    • drawing, with Solid, each drawn thing in its own error boundary (P10)
    • reactive properties, on spell cells
