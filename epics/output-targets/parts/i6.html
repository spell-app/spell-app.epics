The cards library reads a pile's name that only the project importing it ever sets. On its own, its TypeScript has one error: Property 'name' does not exist on type 'Pile'.

  • The library: @system:library:cards, and the Cards fixture, its copy.
    • It reads the name of the pile in the state of a pile.
  • Checked with Klondike, which gives piles a name, it clears.
    • Klondike declares it for TypeScript in a declare module block.
  • The fix belongs in the library: a pile has a name as text.
  • Spell's new warning (Q24) doesn't cover a property read but never declared.
  • One tsc error in the cards library until it declares the name
