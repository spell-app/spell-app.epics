The new list methods do exactly what spell does today, odd edges included. A list type of your own can also hide one of them.

  • Starting with an item that isn't there gives the WHOLE list. pile.startingWith(card), when the card isn't in the pile, answers every card in it.
    • That's what cards of the pile starting with the card compiles to today: the card's position is nothing, so the range starts at 1.
    • An empty list would be safer. It's a change to spell, so it's yours to call.
  • all() on an empty list is no. TypeScript's own every() says yes. Spell's all has always said no.
  • A list type with a property or action named like a list method hides that method, e.g. a pile has a max as number, or an action compiled to reverse().
    • The names: max, min, values, isEmpty, firstItem, filter, remove, reverse, and the rest of the list.
    • In JavaScript the program's own one wins, silently. Spell itself never calls these methods, so only hand-written code that does is affected.
    • In TypeScript, a property replacing a method is an error (TS2425 / TS2426).
    • The Thing Explorer also hides such a property on lists: it takes the name for a built-in one.
    • No fixture does this today.
