"Item" means both an element and its position in core's names: itemOf() returns a position, and the item parameter of getItemOf() is a position.

Core says "position" wherever it means a position, and "item" only for an element of a list.

  • The helpers that take or return a position are renamed; each old name stays as a deprecated alias, so a saved compiled program still runs.
  • The rules, the TypeScript writer, the tests and the guides follow; the JavaScript changes only by the new names.
  • Why: in core's names, "item" means both an element of a list and its position, so the names mislead (Q47).
    • itemOf(list, card) returns a POSITION (3), not an item.
    • The item parameter of getItemOf(list, item) is a position too.
  • Every parameter, local and docstring where item means a position says position (or key, for a plain object).
    • The iteration callback's parameters read (value, position, collection).
  • The renames (table below). Each OLD name stays on spellCore as a deprecated alias:
    • saved compiled programs call the old names, and nothing recompiles them
    • a test runs a program compiled with the old names
    itemOf              -> positionOf        // spellCore, List, CollectionLike
removeItemsOf       -> removeItemsAt
getItemOf           -> getItemAt
setItemOf           -> setItemAt
removeItemOf        -> removeItemAt
duplicateCollection -> duplicateList     // these three take lists only
mergeCollections    -> mergeLists
mergeCollectionsInto -> mergeListsInto
// each old name kept on spellCore, marked @deprecated
