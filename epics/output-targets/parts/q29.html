For P10 (JS Solid Drawing): should a card's draw() run again when what it chose its face by changes?

  • P10's goal said each drawn thing's draw() runs "once, untracked": drawn one time, and only its live values update after that.
  • But a card's draw() chooses its face with an if: face up, its rank and suit; face down, its back.

Settled while building: yes. A thing's draw() runs again when something IT read changes, outside its live values; that thing's node is drawn again, and nothing else.

  • Why not "once, untracked": compiled JavaScript has no <Show> yet.
    • Turning an if in a drawing into <Show> is P12's translation (Q19).
    • Until then, a draw() run only once would never flip a card.
  • How far a redraw reaches: one thing. Each draw() sits in its own memo inside its own net (drawThing()), so a card flipping redraws that card, not its pile or the board.
  • Pinned by a runner browser test: "an if in draw() redraws that card alone".
  • Once P12 writes <Show>, a TypeScript draw() could run once, as planned. JavaScript keeps re-running.

A card's draw(), as compiled JavaScript writes it now:

  • When is_face_down changes, draw() runs again, and the card's node is replaced.
  • When short_suit changes, only its text updates.
