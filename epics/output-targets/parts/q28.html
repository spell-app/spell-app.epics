For P10 (JS Solid Drawing). The error net question (Q21) chose B: each drawn thing's net is a decorator on its draw(). Compiled JavaScript writes no decorators yet; P12 writes @drawn for ts/solid. What does compiled JavaScript write in the meantime?

Settled while building: nothing extra. Every way a thing gets drawn already goes through ONE core function, spellCore.drawThing(), in packages/core/src/drawing.ts, and the net lives there.

  • The three ways a thing is drawn, all through drawThing():
    • draw the card in a drawing
    • App.start(), drawing the whole app (through mountApp())
    • draw cards in it: drawItems(), one net per item
  • So compiled JavaScript needs no wrapper around draw(): it calls core, as it did before P10.
  • P12's @drawn will call the same drawThing(), so both targets share one net.
drawThing(drawable?: unknown): Drawing | null {
  const thing = drawable as Partial<Drawable> | undefined
  if (typeof thing?.draw !== "function") return null
  // through `createComponent()`, as Solid's JSX does:  untracked, so what it reads is its own, not the caller's
  return createComponent(Errored, {
    fallback: (error: () => unknown) => drawingFailed(thing as Drawable, error()),
    // `draw()` in a memo, inside the net:  it runs again only for what IT read, never because the net re-reads
    // its children (it does, whenever anything under it changes:  a list grows, a card flips)
    get children() {
      return createMemo(() => drawOrStandIn(thing as Drawable)) as unknown as Drawing
    }
  })
}
  • no decorator, and no new code, in compiled JavaScript for the net
  • P12's @drawn is a thin call to spellCore.drawThing()
