Spell has no short way to give a list PROPERTY its item type.

  • set tasks to a new list of tasks works for a variable.
  • But in a property declaration, only a new thing is taken after as.

Why, in the grammar:

  • type_specifier_instance is as {new_thing}.
  • new_thing is a new {type}.
  • So as a new list of tasks matches as a new list.
  • That leaves "of tasks" over: a parse error.

What works today: a list TYPE, then a property of that type.

  • So the warning suggests that, and both Todos examples now say it.
  • Not changed here: the brief was to ask nothing new of the grammar.
a task-list is a list of tasks
a todos-app is an app
a todos-app has a property tasks as a new task-list

The fix, if wanted:

  • type_specifier_instance becomes as ({new_thing}|{new_list}).
  • Its getDatatype() and getAST() read either.
  • Then the warning's example becomes as a new list of tasks (define_property_has.warnUntyped()).
  • Todos and Todos - Form Based each declare a task-list type they didn't need before.
  • Their JavaScript gains class Task_List extends List { static instanceType = Task }.
