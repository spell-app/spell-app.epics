Spell has no short way to give a list PROPERTY its item type. set tasks to a new list of tasks works for a variable, but in a property declaration only a new thing is taken after as.

  • Why: type_specifier_instance is as {new_thing}, and new_thing is a new {type}, so as a new list of tasks matches as a new list and leaves of tasks over: a parse error.
  • What works today: a list TYPE, a task-list is a list of tasks, then ... has a property tasks as a new task-list. So the warning suggests that, and both Todos examples now say it.
  • Not changed here: the brief was to ask nothing new of the grammar.
a task-list is a list of tasks
a todos-app is an app
a todos-app has a property tasks as a new task-list

The fix, if wanted: type_specifier_instance as as ({new_thing}|{new_list}), its getDatatype() / getAST() reading either; then the warning's example becomes as a new list of tasks (define_property_has.warnUntyped()).
