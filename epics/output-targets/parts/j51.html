Core had no list of a program's classes, only of its things, so spellCore.things now keeps one, by name.

  • fromJSON() looks a "@type" up in it, with classNamed().
  • A class (and each one it extends) goes in as soon as one of its things is made, even in a test or a scratch list.
  • A runner adds every class the program exports (setTopLevel()), and every class each project it imports exports (runCompiled()), so a class shows before any of its things are made.
  • Spell's own, Thing, List and App, are always known.
  • A new run forgets them, as it forgets its things: the next run's Card is another class.
  • Hand-written code can add its own: spellCore.things.addClasses({ Card, Pile }).
  • The other ways, not taken:
    • each compiled class registers itself as it's declared (a line per class from both writers): every fixture snapshot changes, and it's the writers' half of P15
    • register in declareProp(): misses a class with no props, e.g. Stock_Pile
  • In the editor and <spell-app>, every class of the program and its imports is found by name once it has run.
  • spell run and the core contract find a class only once one of its things is made: they never call setTopLevel(). Nothing there calls fromJSON() yet.
  • A fromJSON() in a program's OWN top-level code finds its classes only once their things are made: its module hasn't finished loading.
