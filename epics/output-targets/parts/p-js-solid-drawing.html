Compiled spell drew with React, one broken drawing took the whole app down, and spell's reactive engine and Spell UI's were two engines that couldn't see each other (C11).

Compiled javascript draws with Solid now, on one reactive engine meant to be shared with Spell UI.

  1. First, spell's reactive engine and its decorators moved into util's reactive folder: the one engine spell and Spell UI will share.
  2. Then core gained its Solid side, and compiled javascript drew with Solid, before TypeScript changed.
  3. Each drawn thing sits in its own error boundary, core's drawThing(), with no wrapper in compiled javascript.
  4. Core's React drawing was deleted here (J18); the React kits stayed for P11.
  • Moved the shared runtime into util's reactive folder: the cells, the records, Schema, and the decorators @prop, @derived and a new @state, both of the last two taking { equals }; no lodash, no Solid.
  • Built core's element() on @solidjs/h, so compiled javascript still needs no build step; every live value in a drawing is written as a function, so it updates its own node.
  • Mounted a program with Solid's render(), in the editor, VS Code's runner, <spell-app> and spell run.
  • Made one broken drawing show a small stand-in, a line on the program's console and a cancelable ui-error, while the rest keeps drawing.
  • A thing's draw() runs again when what it read changes, that thing alone, not once: compiled javascript had no <Show> yet.
  • Made notify, alert, confirm and prompt work, as Spell UI's toast and dialogs.
