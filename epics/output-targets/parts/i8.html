A spell list turned into JSON as {}, so the Todos form's debug view showed "tasks": {} and ticking a task changed nothing you could see.

  • Found in the review of test V14 (Todos - Form Based), where Owen saw "checkboxes don't work".
  • The checkbox itself worked all along:
    • a real click ticked it, and wrote completed = true into the task
    • Remove Completed then removed that task too
  • But nothing on the page showed the change: the debug JSON had no tasks in it, and the filters didn't filter.

Why the JSON was empty:

  • A thing's JSON is its props (Observable.toJSON()).
  • A list keeps its items as STATE, not a prop, so its JSON had nothing in it.

The fix: a list's JSON is its items, as an array's is.

  /**
   * Our items, as JSON shows a list:  `JSON.stringify(todosApp)` shows its tasks, each by its own `toJSON()`.
   * - Props a list sub-class declares for itself aren't in it:  a list IS its items here, as an array is.
   * - Tracked:  a reader re-runs when the items change (and, through each item's `toJSON()`, when they do).
   */
  toJSON(): T[] {
    return this.items
  }
  • A choice made here: a list sub-class's OWN props (say, a pile's name) are left out of its JSON.
    • The other way: { ...props, items }, so the debug view would read "tasks": { "items": [...] }.
    • No spell example gives a list props of its own today.
  • The Thing Explorer listed a thing's props from its JSON; it now asks for its keys(), so a list's items don't show up there as properties named 0, 1, 2 (ThingRegistry.propertiesOf()).
  • Tests: two in List.test.ts ("JSON"), both failing before; the runner's browser test ticks a task in the real compiled example and reads the debug JSON.
  • Todos - Form Based's debug view shows every task, its title and whether it's done.
  • Ticking a task, or typing a title, changes the JSON as you go.
  • Any spell list in JSON (a debug view, a print) is an array of its items.
