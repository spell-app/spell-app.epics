Half-way: what today's output does that a person wouldn't

ts/solid as P7 built it is the JavaScript target's output with types added. It runs, and tsc checks it, but nobody would write it.

From the real output for Card, as spell compile Solitaire --target ts/solid --stdout prints it:

  • JSX isn't JSX: each tag becomes a call to spell's own wrapper, which core turns into a React element.
    • The call: spellCore.element({ tag: "div", props: { className, onClick }, children: [...] })
    • Core's side: React.createElement(), in ui.ts
    • So the output draws with React, not Solid, and says className.
  • A drawing re-runs whole. React's bridge (view()) redraws all of Card's draw() when anything it read changes; nothing is fine-grained.
  • Four lines per property, where a person writes one: @prop(...) accessor rank!: Rank.
    • The output declares it in a static block: static { this.declareProp('rank', ...) }.
    • Then a getter and a setter read and write it, through getProp() / setProp(), with a cast.
    • Compiled JavaScript can't use decorators: it runs from a blob: URL, with no build step (the header of spellDecorators.ts).
    • But TypeScript is built anyway.
  • Lists lose their values: the ranks are static Ranks = ['ace', 2, ...], without as const.
    • So a rank's type is string | number, not the 13 ranks.
  • Types spell knows are dropped: is_a_$suit(suit: any /* spell: type unknown */), though spell wrote for its suits.
    • The whole untyped gap: 1.7.
  • JavaScript's names: names made legal JavaScript while parsing (1.3), not TypeScript's own.
    • is_a_$suit, where TypeScript says isASuit
    • turn_face_up, where it says turnFaceUp
    • short_rank, likewise
  • Members patched on from outside sit far below the class.
    • the pile of a card is written in Pile.spell.
    • It becomes export interface Card { readonly pile: any },
    • plus Object.defineProperty(Card.prototype, 'pile', ...).
    • play(), from Solitaire.spell, is already folded into the class.
  • Machine tidiness:
    • let for everything
    • extra parentheses: (((("Card face-" + a) + " ") + b)
    • { return x } braces
    • an unused (event: any) => on every handler
    • the same handler written twice
  • No error net. Nothing guards a drawn thing: a card whose draw() throws takes React's whole tree down with it.

The full monty: what changes

One bullet per change, each with the question that settled it. The after below shows Owen's answers, and the recommended option where a question was still open that day.

  • Real JSX, compiled by Solid: the file becomes Solitaire.compiled.tsx.
    • A spell tag is written as the tag: <div class={...} onClick={click}>.
    • Solid's own compiler turns it into its DOM calls, each {...} its own live binding, as for any hand-written component.
    • Decided: Q18, A (real JSX, not h() calls or Solid's compiled calls).
  • A drawing in Solid's shapes: the statements of to draw become Solid's.
    • A local that's computed becomes an accessor: const className = () => ....
    • A chain of ifs that return becomes <Show> or <Switch>.
    • draw cards in it becomes <For>.
    • Any other shape re-runs whole, inside its net.
    • Decided: Q19, A.
  • Decorators: @prop({ oneOf: RANKS }) accessor rank!: Rank.
    • From util's spellDecorators.ts, re-exported by @spell/core.
    • The SAME runtime shape as the output's declareProp and accessor pair, so Thing checks and stores it as before.
    • @derived only where a getter loops over a list (Pile.state).
    • @thing only on a class with a to create.
    • Still open that day: Q20.
      • Owen picked Spell UI's reactive members too: he wants Spell and Spell UI to share ONE set of decorators, ideally with the same reactivity.
      • So which decorators these are, and where they come from, is per Q20.
      • The after below still shows spell's @prop.
  • Spell cells stay the state: properties stay spell cells, never Solid signals or stores.
    • Under the decorator, they're still read and written through getProp() / setProp().
    • Why: spell needs a read right after a write to see it, which Solid 2's staged writes can't give (solid-2.md, "Spell's decisions").
    • Solid follows them through the cells bridge, as the editor app does.
  • An error net per drawn thing, from a decorator on draw(): @drawn draw() { ... }.
    • The decorator, from core, runs the drawing ONCE, untracked, inside Solid's <Errored>.
    • So a parent draws a child with a plain call, {card.draw()}.
    • That call neither re-runs when the card's reads change, nor dies with the card's errors.
    • When a drawing throws, the net does what spell-element's UIComponent.mount() does for an element:
      • logs once, on the program's console
      • sends a cancelable ui-error
      • shows a stand-in, while the rest of the board keeps drawing
    • Compiled JavaScript has no decorators, so it applies the same function by hand, as it lowers @prop: ONE net for both targets.
    • Decided: Q21, B (not the <Drawn> component this sketch first showed).
  • <ui-root> and UI: a program mounts into the page's root element, and talks to the person through Spell UI.
    • start the game mounts with Solid's render().
    • The root loads any <ui-*> tag a drawing uses, by itself (UIRoot.tsx's banner).
    • So a spell program could write <ui-button> and it would just work.
    • Spell's notify, alert, confirm and prompt compile to spellCore methods nobody wrote yet (the NOTE in ui.ts).
    • They become Spell UI's toast and dialogs (UIRuntime.ts). For example UI.toast() and UI.modals.alert().
  • Types where spell knows them:
    • lists as const RANKS = [...] as const, plus type Rank
    • parameters spell knows: isASuit(suit: Suit)
    • a callback's item: (pile: Pile) =>
    • the rest of the gap: 1.7
  • TypeScript's names: methods, getters and functions in camelCase.
    • For example isASuit, turnFaceUp.
    • A function too: playFromTheStockPile.
    • Properties keep spell's names, as they're data a program prints.
    • Decided: Q22, A.
  • One class body per type: every member of Card, wherever in the project spell wrote it, inside class Card.
    • get pile() moves in, and its merged interface goes.
  • Tidy as written by hand:
    • const where a variable is never set again
    • template text: `${this.rank}-of-${this.suit}`
    • no extra parentheses or braces, no unused parameters
    • a shared handler written once
  • Imports:
    • solid-js: Show, For
    • @spell/core: spellCore, Thing, prop, drawn
    • UI from @spell-app/ui, only when the program uses it
  • JavaScript moves first: js/solid draws with Solid before ts/solid changes.
    • It's the "Core + JSX" move for compiled spell (solid-2.md, "Spell's decisions").
    • spellCore.element() builds on @solidjs/h, as compiled JavaScript still has no build step.
    • Every live prop and child is written as a function.
    • App.start() mounts with Solid's render().
    • React leaves compiled spell there, and the runners and the app in P11, once the last example is on Spell UI (I2).
    • Decided: Q23, B, "Do the js => solid first".

/** card ranks */
const RANKS = ["ace", 2, 3, 4, 5, 6, 7, 8, 9, 10, "jack", "queen", "king"] as const
/** card suits */
const SUITS = ["clubs", "diamonds", "hearts", "spades"] as const
/** card direction:  up or down */
const DIRECTIONS = ["up", "down"] as const

export type Rank = (typeof RANKS)[number]
export type Suit = (typeof SUITS)[number]
export type Direction = (typeof DIRECTIONS)[number]

/** definition of a Card with nice english aliases for working with it */
export class Card extends Thing {
  ////////////////
  // ## properties of cards
  ////////////////

  static Ranks = RANKS
  @prop({ oneOf: RANKS }) accessor rank!: Rank

  static Suits = SUITS
  @prop({ oneOf: SUITS }) accessor suit!: Suit

  /** color as derivation of suit */
  get color() {
    if (spellCore.includes(["diamonds", "hearts"], this.suit)) return "red"
    return "black"
  }

  /** value as a derivation of rank */
  get value() {
    return spellCore.itemOf(Card.Ranks, this.rank)
  }

  static Directions = DIRECTIONS
  @prop({ oneOf: DIRECTIONS }) accessor direction!: Direction

  /** a card is in one pile at a time (from `Pile.spell`):  the pile holding it */
  get pile() {
    return Pile.ownerOf(this) as Pile | undefined
  }

  ////////////////
  // ## aliases
  ////////////////

  /** "card is face up/down" */
  get isFaceUp() {
    return this.direction == "up"
  }

  get isFaceDown() {
    return this.direction == "down"
  }

  /** `card is a face card` */
  get isAFaceCard() {
    return spellCore.includes(["jack", "queen", "king"], this.rank)
  }

  /** "card is a spade", "...is a club" etc */
  isASuit(suit: Suit) {
    return this.suit === suit
  }

  /** "card is a queen", "...is an ace" etc */
  isARank(rank: Rank) {
    return this.rank === rank
  }

  /** "card is the queen of spades" etc */
  isTheRankOfSuits(rank: Rank, suit: Suit) {
    return this.rank === rank && this.suit === suit
  }

  /** name as a derivation of name/suit */
  get name() {
    return `${this.rank}-of-${this.suit}`
  }

  get shortSuit() {
    if (this.isASuit("clubs")) return "♣️"
    if (this.isASuit("diamonds")) return "♦️"
    if (this.isASuit("hearts")) return "♥️"
    if (this.isASuit("spades")) return "♠️"
    return "?"
  }

  get shortRank() {
    if (this.rank == undefined) return "?"
    if (spellCore.isOfType(this.rank, "number")) return `${this.rank}`
    return spellCore.upperCase(spellCore.getItemOf(this.rank, 1))
  }

  get shortDirection() {
    if (this.direction == "up") return "+"
    return "—"
  }

  get shortName() {
    return this.shortRank + this.shortSuit
  }

  get state() {
    return this.shortRank + this.shortSuit + this.shortDirection
  }

  ////////////////
  // ## actions
  ////////////////

  /**
   * Turn card face up or face down
   * Note that this will animate if you `wait for turn the card face up`
   */
  async turnFaceUp() {
    this.direction = "up"
    await spellCore.pauseFor(50, "msec")
  }

  async turnFaceDown() {
    this.direction = "down"
    await spellCore.pauseFor(50, "msec")
  }

  /**
   * Flip card to opposite direction
   * Note that this will animate if you `wait for turn the card face up`
   */
  async turnOver() {
    if (this.direction == "up") this.turnFaceDown()
    else this.turnFaceUp()
    await spellCore.pauseFor(50, "msec")
  }

  /** Runs ONCE per card, in its own error net (`@drawn`):  a parent draws it with `{card.draw()}`. */
  @drawn
  draw() {
    const className = () => `Card face-${this.direction} ${this.rank} ${this.suit} ui button compact fluid `
    const click = () => spellCore.RUNTIME.trigger("card-click", { card: this })
    return (
      <Show
        when={!this.isFaceDown}
        fallback={
          <div onClick={click} class={className()}>
            <i class="fitted bicycle icon" />
          </div>
        }
      >
        <div onClick={click} class={className() + this.color}>
          {this.shortRank + " "}
          <span class="suit">{this.shortSuit}</span>
        </div>
      </Show>
    )
  }

  /** from `Solitaire.spell`:  `to play a card` */
  async play() {
    const startPile = this.pile
    if (!spellCore.canGiveUp(startPile, this)) return false

    if (startPile == stock) {
      playFromTheStockPile()
      return
    }

    const endPile = spellCore.getItemOf(
      spellCore.filter(allPiles, (pile: Pile) => pile.droppable == true && spellCore.canTake(pile, this)),
      1
    )
    if (!spellCore.isDefined(endPile)) return false

    const cardsToMove = spellCore.rangeStartingAt(startPile, spellCore.itemOf(startPile, this))
    cardsToMove.name = startPile.name
    spellCore.console.log(`moving (${cardsToMove.state}) to (${endPile.state})`)

    spellCore.map(cardsToMove, (card: Card) => {
      spellCore.move(card, endPile)
    })

    if (spellCore.isOfType(startPile, "Tableau") && !spellCore.isEmpty(startPile)) {
      await spellCore.pauseFor(200, "msec")
      const it = spellCore.getItemOf(startPile, -1)!
      spellCore.console.log(`turning over (${startPile.name}: ${it.state})`)
      it.turnFaceUp()
    }

    if (spellCore.isOfType(endPile, "Foundation")) game.score = game.score + 10
    else if (startPile == discards) game.score = game.score + 5
    return true
  }
}

// @spell/core's Solid side, sketched:  each drawn thing in its own error net, as spell-element's
// `UIComponent.mount()` gives each element one.  BOTH targets draw on it.
import { Errored, runWithOwner, untrack } from "solid-js"
import { render, type JSX } from "@solidjs/web"

/**
 * `@drawn draw() { ... }`:  the drawing runs ONCE, untracked, inside its own error net.
 * - So a parent draws a child with a plain call, `{card.draw()}`:  it neither re-runs when the card's reads change,
 *   nor dies with the card's errors.  A drawing Solid can't follow in pieces re-runs whole, inside its net.
 * - Compiled JavaScript has no decorators:  it applies this same function by hand, as it lowers `@prop`
 *   (its exact lowered form, and the decorator set it belongs to:  per Q20).
 */
export function drawn<T extends Thing>(draw: (this: T) => JSX.Element, _context: ClassMethodDecoratorContext<T>) {
  return function (this: T): JSX.Element {
    return untrack(() => <Errored fallback={(error) => drawFailed(this, error())}>{draw.call(this)}</Errored>)
  }
}

/**
 * `thing.draw()` threw:  log it ONCE on the program's console, send a cancelable `ui-error` from the app's
 * `<ui-root>`, then show a small stand-in, unless the app cancelled the event.  The rest of the page keeps drawing.
 * - Outside any owner (`runWithOwner(null)`), so it may change state:  as spell-element's `onError()`.
 */
function drawFailed(thing: Thing, error: unknown): JSX.Element {
  const showsStandIn = runWithOwner(null, () => {
    spellCore.console.error(`${thing.type} failed to draw:`, error)
    const detail = { error, thing }
    const event = new CustomEvent("ui-error", { bubbles: true, composed: true, cancelable: true, detail })
    return spellCore.appElement()?.dispatchEvent(event) ?? true
  })
  return showsStandIn ? <ui-label color="red" icon="exclamation triangle">{thing.type}</ui-label> : undefined
}

export class App extends Thing {
  start() {
    render(() => this.draw(), spellCore.appElement() ?? document.querySelector("ui-root")!)
  }
}

What stays the same, on purpose:

  • Spell's built-ins stay spellCore calls, which keep spell's rules.
    • getItemOf(rank, 1) counts from 1.
    • includes() and isOfType() take spell's lists, and nothing.
    • A person would write this.rank[0].
    • But the contract test (P8) needs both targets to print the same.
  • Spell's is stays ==, which is forgiving: "2" is 2.
  • turnOver() still calls turnFaceDown() with no await.
    • Spell waits only when told to, with wait for.
  • The headings and the test still run when the file loads, as in JavaScript: spellCore.heading(), testCardSetup().
  • A class name spell builds as text stays text (class={className()}), not Solid's array form: the writer can't know which words a string holds.

The catch: what makes it hard

  • Core draws with React, so core moves to Solid, for both targets, JavaScript first.
    • Today element() builds React elements.
    • Thing.Component is a React class, through view().
    • App.start() uses React's createRoot().
    • The move:
      • element() on @solidjs/h
      • draw() returning Solid's JSX.Element
      • @drawn
      • App.start() with Solid's render()
    • That's the whole "Core + JSX" move (P10). React leaves compiled spell with it.
    • The runners and the app lose React in P11, once Todos - Form Based draws with Spell UI (I2): view(), the forms kit, semantic-ui-react.
  • spell-runtime.js and Solid: compiled JavaScript's core must share the page's one Solid.
    • Compiled JavaScript imports only @spell/core, never Solid.
    • It runs from a blob: URL (core's AGENTS.md, "Who may value-import it").
    • Its core, spell-runtime.js, now draws with Solid.
    • It must use the page's ONE shared Solid, spell-solid.js, through sharedSolid(), and never bundle its own.
    • Two Solids on a page fail silently (solid-2.md, "Spell's decisions").
    • ts/solid output imports solid-js itself, and needs a build: Solid's compiler, the decorators lowered.
  • Running it: the .tsx needs a build step before the contract test can run it.
    • Today the contract test (contract.test.ts) runs ts/solid output through tsx, as a .mts file.
    • A .tsx with Solid JSX and decorators is built first:
      • esbuild for the decorators (vite.decorators.ts)
      • then Solid's compiler, @solidjs/compiler (rc.13, already installed)
    • It runs on Solid's CLIENT build under node, which resolves the server build by default (solid-2.md, "Testing").
    • And on the fake page (linkedom).
  • Translating to draw: the bulk of the writer's new work.
    • Spell's drawing is statements: locals, ifs, early returns, loops.
    • The common shapes turn into accessors, and Solid's own Show, Switch and For tags.
    • Every other shape must still be right, re-running whole (Q19).
  • Names shared across projects: a project and the libraries it imports must agree on names.
    • A library's declarations (Solitaire.declarations.json) name its members as JavaScript does.
    • A ts/solid project importing a library must use the same names its own writer gives (Q22).
  • as const lists are read-only: core's types must take read-only arrays.
    • That's spellCore.itemOf(Card.Ranks, ...) and friends.
  • tsc and the snapshots change once, whole.
    • typecheck() gains JSX settings, and the JSX types of Solid and the <ui-*> tags.
    • Every fixture's .snapshot.ts becomes .snapshot.tsx, and changes whole, once.
    • The .snapshot.tsc.txt files are blessed again.
    • The JavaScript snapshots change once, in the JavaScript stage (live values as functions), and must not move after it.
