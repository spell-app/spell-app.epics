A spell object's JSON can't be read back as what it was (a list is only its items, and nothing says its type), and a <ui-repeat> names its list by JavaScript's spelling.

Spell objects round-trip through JSON, and a repeat takes its list from spell.

  • Every spell object's JSON says its type, in "@type"; a list's holds its own properties plus its items.
  • spellCore.fromJSON() rebuilds them, each as its own class.
  • <ui-repeat items={...}> takes a spell expression for the list it draws.
  • Where this comes from: Owen's review, 2026-10-10, of two issues found in test V14 (Todos - Form Based):
    • a list's JSON was empty (I8); his answer is Q49
    • the All / Active / Completed filters didn't filter (I10); his answer is Q48
  • Every spell object says its type (Q49): a thing's JSON carries "@type", its class's name, before its properties.
    • Why "@type", JSON-LD's spelling: no spell property can be named @..., so it never collides, where "type" would. 
    { "@type": "Card", "rank": "ace", "suit": "clubs", "direction": "down" }
  • A list's JSON holds its properties AND its items (Owen, on I8: "a list's JSON holds its own properties as well as its items").
    • This revises I8's fix, committed in e2cfe02dc, where a list's JSON was its items alone, as an array's is.
    • The items go under "items", each written by its own JSON.
    { "@type": "Pile", "name": "stock", "items": [{ "@type": "Card", "rank": "ace", "suit": "clubs", "direction": "down" }] }
  • JSON reads back as what it was: spellCore.fromJSON() rebuilds each object by its "@type".
    • The class is found by name among the program's classes: the ones it declares, and the ones it imports.
    • A list comes back with its own properties and its items, each item rebuilt the same way.
    • An unknown "@type" (no class by that name) comes back as a plain object, its "@type" kept, not an error; a test says so.
    • Whether Thing.fromJSON() is a way in too, beside spellCore.fromJSON(): decided while building, and said in Done.
  • What reads JSON today keeps working:
    • Todos - Form Based's debug view shows each task, now with its "@type", and follows each tick and title as it does now.
    • The Thing Explorer lists a thing's properties by its keys() (moved there by I8), so neither "@type" nor "items" shows up there as a property.
    • spellCore.echo(), and the core contract test's printed output, show the new shape.
      • The contract snapshots may change ONCE, on purpose: review that diff as the new shape, not as a regression.
  • A repeat takes its list as a spell expression (Q48, on I10): <ui-repeat items={the shown tasks of the app}>, in place of name="shownTasks".
    • The expression compiles to a live value: the repeat redraws when the list changes, or anything it's worked out from.
    • Spell UI's <ui-repeat> takes that list as its items property. Today items only reads the form's object by the repeat's name; name keeps working for plain HTML.
    • Spell-style names never meet JavaScript's spelling: nobody has to know that shown-tasks compiles to shown_tasks. 
    <ui-repeat name="shownTasks">
<ui-repeat items={the shown tasks of the app}>
