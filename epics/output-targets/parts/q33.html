Owen, 2026-10-09, reading Solitaire's TypeScript: "we know that allPiles is a List, which has filter, right? Can we just call allPiles.filter(...) instead of spellCore?"

Today, no. A List has no filter(): every collection helper lives on spellCore.

  • List has the basics:
    • getItem(), counting from 1
    • itemOf(), add()
    • removeItem(), getValues()
  • spellCore's helpers take ANY collection, so spell never has to know which kind it holds.
    • For example spellCore.filter(), map(), forEach(), getItemOf() ...
    Any collection:
    • a List
    • a plain array
    • text (the first character of its rank)
    • an object
    • nothing
  • A filtered list is SCRATCH: a list of the same class that owns nothing. Otherwise filtering the piles would take each card out of its pile (AGENTS.md, "Membership and guards"). 
const droppablePiles = spellCore.filter(allPiles, (pile: Pile) => pile.droppable == true && pile.canPlayCard(this))
const endPile = spellCore.getItemOf(droppablePiles, 1) as Pile
// with list methods:
const droppablePiles = allPiles.filter((pile) => pile.droppable == true && pile.canPlayCard(this))
const endPile = droppablePiles.getItem(1)!
  • core: List gains filter(), map(), forEach(), forEachSequential(), isEmpty ...
    • each doing exactly what its spellCore twin does: scratch results, counting from 1
  • the TypeScript writer calls them when spell knows the receiver is a list
    • all-piles is a list of piles; start-pile is a pile
    • it keeps spellCore where it doesn't know, or for text
  • JavaScript keeps spellCore: no change there; the contract test keeps both printing the same
  • cost: M; reads as a person writes it, and TypeScript types each result by itself (fewer as Pile)
  • as A, and the JavaScript writer uses them too
  • every JavaScript snapshot changes once; compiled JavaScript reads the same way
  • cost: M-L
  • one spelling for every collection; nothing to build
  • reads less like hand-written TypeScript
  • allPiles.filter(...), deck.getItem(1) in TypeScript, where spell knows it's a list
