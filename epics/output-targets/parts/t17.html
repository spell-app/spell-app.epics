Fix 5 of the untyped gap (1.7): in OutlineSolitaire, a type's statics are written after its class, so TypeScript never sees them. 13 of its 19 tsc errors, and 5 getters typed any. 

// a "deck" is a list of cards with:
//   - "suits" as one of clubs, diamonds, hearts or spades
export class Deck extends List {             // not List<Card>:  instanceType is a getter, Card comes later
  static get instanceType() {
    return Card
  }
  ...
}
Deck.Suits = ['clubs', 'diamonds', 'hearts', 'spades']
// TS2339: Property 'Suits' does not exist on type 'typeof Deck'.   (13 times)
  • The statics: write them in the class body (static Suits = [...]), as the plain style already is (Solitaire's Card.Ranks). Where the order must stay (a value read before the class is done), declare static Suits: ... in the body, and keep the assignment where it is.
  • The item type: TSWriter.superTypeOf() reads only a plain static instanceType = Card; read the getter's returned type too, so Deck extends List<Card>.
  • P10's "one class body per type" does this by itself, if it covers statics: worth a line in its Verify.
  • OutlineSolitaire: 19 tsc errors to 6, and 5 fewer inferred anys
