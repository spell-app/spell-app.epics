The @drawn decorator lives in core, beside spellCore.drawThing(), in drawing.ts. Not in util's reactive folder, as P12's Files field says.

  • Why: the net is Solid's (<Errored>, a memo), and util never imports Solid.
  • In core, drawThing() and @drawn share ONE function, drawInNet(): no copy.
  • @drawn marks the method it returns (with a symbol).
    • So drawThing(), on a thing whose draw() is already @drawn, calls it straight.
    • One net, never two.
  • The two targets:
    • JavaScript output keeps calling spellCore.drawThing(card).
    • TypeScript writes @drawn draw(), and draws a child with a plain {card.draw()}.
    • mountApp() works for both.
  • @spell/core exports it, with util's prop, state, derived and thing.
export function drawn<This extends object, Draw extends (this: This) => Drawing>(
  draw: Draw,
  _context: ClassMethodDecoratorContext<This, Draw>
): Draw {
  const drawInItsNet = function (this: This): Drawing {
    return drawInNet(this, () => draw.call(this))
  }
  Object.defineProperty(drawInItsNet, DRAWN, { value: true })
  return drawInItsNet as Draw
}

what is this net business?

You asked: "what is this net business?"

An error NET is what keeps one broken drawing from taking the whole page down.

  • In Solid 2, an error thrown while drawing stops Solid for the WHOLE page (REACTIVITY_HALTED): nothing updates any more, anywhere.
  • A net is Solid's <Errored> around one drawn thing. When that thing's draw() throws, the net catches it, and only that thing is replaced:
    • one line on the program's console
    • a cancelable ui-error event from the app's element
    • a small stand-in, "⚠ Card can't draw", where the card was
    The rest of the board keeps drawing and updating.
  • Spell UI gives every <ui-*> element one the same way (spell-element).
  • Compiled spell gets one per drawn thing:
    • JavaScript: spellCore.drawThing(card) wraps the card's drawing in it
    • TypeScript: @drawn on draw() does the same, so a parent can draw a card with a plain {card.draw()}
    Both call the same function in core (drawInNet() in drawing.ts), so the two targets behave alike. 
@drawn
draw() {
  return <Show when={this.isFaceDown} fallback={...}>...</Show>
}  // throws?  only this card shows "⚠ Card can't draw";  the pile, the board, the score keep working
  • One bad drawing breaks one thing on the page, never the whole app
  • "Net" is the word used in core's docstrings; say if you'd rather it said "error boundary"
