Today there are two reactive engines, and a derived value only notices changes from its own engine. Found while answering Q20 (which decorators ts/solid uses).

  • Nobody hits it yet.
  • Mixed hand-written code would: a Spell UI component reading a spell Thing, or the other way round.

The two ways it misses:

  • A Spell UI @E.derived getter that reads a spell Thing's prop (a spell cell) never recomputes when the prop changes.
    • Its cache checks only record members. Spell UI's reactive code (Reactive.ts) says so as a rule, in its header (lines 28-30).
  • A spell @derived getter that reads a Spell UI @E.state member never recomputes either.
    • It's only marked stale by spell cells (Derived).
    • A Spell UI write sets only a Solid signal: Notifier.changed(), in Reactive.ts, lines 416-420.
    • Found by reading the code, not measured.
  • Plain getters on either side are fine: they read fresh every time.
  • Until the two share one engine: a derived value reads only its own side's members; otherwise, use a plain getter.
  • Gone once Spell UI moves onto spell cells (Q20's reply).
