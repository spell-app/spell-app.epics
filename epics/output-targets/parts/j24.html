The plumbing for .compiled.tsx: how it's checked, built and run, and two dev dependencies it needed.

  • Checked: typecheck() adds jsx: "preserve" and jsxImportSource: "@solidjs/web" (as app and ui do), and checks app's src/solid/solid.types.ts with the files, for <ui-*> tags' JSX types (@spell-app/ui ships none). Its temp folder links the repo's node_modules, so solid-js resolves from outside the repo. Standard decorators with accessor check as they are: no experimentalDecorators.
  • Built: buildTsx(), packages/spell/src/node/buildTsx.ts: esbuild first (types stripped, decorators lowered, as vite.decorators.ts), then Solid's compiler (generate: "dom"). The app's own order; Solid's compiler takes TypeScript too, so the other order works as well.
  • Run: runCode() builds a .tsx to a .mjs first; the contract test runs ts/solid as .tsx. hooks.mjs now finds Solid from @spell/core's folder, so the built program (in a temp folder) and its runtime share ONE Solid.
  • Dev dependencies: @solidjs/compiler 2.0.0-rc.13 for spell (already installed, through @solidjs/vite-plugin; now declared); linkedom for core's tests. Its tests now run Solid's CLIENT build (vitest.config.ts), so drawing.test.ts can draw into a fake page.
  • A spell node tool reading an app file goes against the one-way package order, but it's a declaration file, read by tsc only. The alternative, a second copy of those 5 lines, would drift. 
const lowered = await transform(code, {
  loader: "tsx", jsx: "preserve", target: "es2022", format: "esm", keepNames: true, sourcefile: filename
})
const drawn = await compileSolidJsx(lowered.code, {
  filename: filename.replace(/\.tsx$/, ".jsx"),
  generate: "dom",
  moduleName: "@solidjs/web"
})
return drawn.code

Proven on a hand-written sample of the target's output, packages/spell/src/test/Cards.sample.tsx (@prop, @drawn, @thing, <Show>, <For>, a <ui-button>): it checks clean, and under runCode(..., { extension: ".tsx", dom: true }) it draws, a click flips a card through <Show> and a <ui-button>'s handler bumps the score.

  • .compiled.tsx checks, builds and runs with no change to the JavaScript side.
