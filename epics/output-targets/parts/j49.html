A <ui-repeat> can now be given its list two ways, and when both are there, items wins:

  • items: the list itself, as a property.
    • Spell writes it <ui-repeat items={the shownTasks of the app}>.
    • Both targets set it live: javascript items: () => app.shownTasks, TypeScript prop:items={app.shownTasks}.
  • name: the list by its property name in the form's value (or the row around it), as before, for plain HTML.
  • The repeat's own list of rows was a getter named items; it's shownItems now, so the property can have the name (Spell UI names a member for what it is). 
<ui-repeat name="shownTasks">
<ui-repeat items={the shownTasks of the app}>
  • Todos - Form Based filters through items; the runner test that clicks Active / Completed passes on its compiled javascript
  • A page that sets both gets items, without a warning
