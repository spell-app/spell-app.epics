Q45's warning (A pile never says it has a name ...) shows only where spell is sure. Two calls made without you:

  • Checked late. A later line or a later file may declare the member, e.g. a pile has a name in a file further down, or set the name of the pile to .... Checking while the line parses would warn about those. So the warning is noted while parsing but reported only if it still holds when the warnings are gathered. That needed a new way to note a warning: SpellWarnings.noteIf().
  • Only types spell knows in full. It warns only on a type the project declares, all of whose super-types are the project's own or spell's. It never warns on an imported type, or on one built on an imported type. Why: Klondike's foundation is a pile from the Cards fixture, and Klondike gives piles a name without declaring it. That compiles and type-checks fine, so a warning there would be a false alarm.
  • It never warns on a built-in member, a method, or a type spell doesn't know.
