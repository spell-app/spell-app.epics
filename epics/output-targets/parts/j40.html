A list's own methods (Q33) are used only where the writer KNOWS the value is a spell List, as spell's list datatype covers plain arrays too. It knows from where the value came from:

  • new List(...) or new Pile(...), this in a list class, a parameter or loop item typed as one ((a pile)), a property declared as one, what a list's own helper gives back (a filtered pile is a pile)
  • top-level variables are looked up project-wide, as a class above may read one set below it (all_piles in Card.play)
  • the same knowledge gives comparisons their === (both sides known and alike), and a getter's type from what it returns (a card's color is text)
  • text is tested with typeof x === "string", beside typeof x === "number" (Q40 named numbers only)
  • a statement looping over a plain array (getRange(1, 7), Card.Ranks) is the array's own forEach() when it takes the item only
  • Where the writer can't tell, it keeps spellCore.* and ==: never wrong, just less tidy
