The notebook as a docs page

You want a .spellx file's notebook to read like a Spell UI component page, not like Jupyter cells. Before I plan the new phase, these questions settle what the page shows.

A component page (Spell UI's Button page) has three parts:

  • a masthead: the name and one line on what it is
  • sticky sections you can fold
  • examples, each with a description, the live result, and its code under a button

A template already has that shape. Card.spellx even has its own ## headings ("card rank", "card suit", "turning the card over" ...), which would be the sections.

How should the page be split into foldable sections?

Each ## heading in the file becomes a section ("card rank", "turning the card over"), so the author decides the order, as a component page's author does.

A file with no headings gets one section per kind (B) instead.

Properties, Aliases, Actions, Events, Drawing, Tests, always in that order. The file's headings show as sub-headings.

Each live example needs a Thing to show on (a card: the queen of spades). Where should those come from?

Every get a new card whose ... in the tests becomes a sample you can pick in the masthead. Nothing new to write, and the samples stay true to the tests.

The author writes <sample "queen of spades">rank is queen ...</>: new syntax, a new chunk kind.

A new Thing with each property at its first value (an ace of clubs, face down). You change it with the property chips.

Pick every live result the first version should have. Anything left out shows only its description and code.

On a component page the code hides behind a button. How should a chunk's spellx show?

As on the Button page: a code button opens the chunk's spellx in an editor right there. Edits save into the file, and the live result updates.

Code under every example. Better for writing, but a long page.

A property opens its form, and the code is one more click. Other chunks work as in A.

Where do you switch between the page and the plain .spellx text?

Notebook / Text tabs under the masthead, like the Button page's Examples / API tabs. Nothing in the editor's toolbar.

Keep it in the toolbar, drawn as the toolbar's own buttons.

A list, a game or a plain template has nothing to draw. What goes in the masthead's picture spot?

The sample's properties and their values, like an inspector, and it updates as actions run.
