  • Each row is one name, where it's declared. File opens it at that line in VS Code; Current is how the code reads today; Recommended is Claude's call, already filled in.

Modals, flyouts, sidebars, dimmers, popups, toasts, nags, transitions. Today a cancelable ui-open / ui-close comes first, then ui-show / ui-hide once the animation ends: each pair is ONE pair now, opening / opened, both rows saying it.

A fold that keeps its header: opens and closes (accordion, section) in your round 1, shows and hides (a note, a thread) in your round 2 -- Q65 asks which. A tab's pane is shown.

A value changing as you type or drag, a change committed, a form's validation and saving. Every change is changing / changed; a submit is saving / saved, held edits applying / applied; a failure's shape is Q66.

An item chosen, a label removed, a message dismissed, a column sorted, progress.

The root getting ready, files loading and saving (the source layer every source element shares), code coloured, scrolling into view, sticking.

The <ui-docs-*> elements the components pages are built from: not components a program would use, but the same event names.

<spell-app> (to be <spell-viewer>, Q16) and <spell-editor>: a component pack's events keep their own names, never translated.

A drag's moments are single names, as your drag start: drag start, dragging, drag end, drag enter, drag over, drag leave; a drop is dropping / dropped (Q67).

The words a handler says today, when clicked: or on-click= / when-clicked= on a tag in a layout. Handler words follow the events they catch: a pair's handler can catch either half.

The language's own event words (spell-parser): trigger / fire / send and on, the drop event, the console's, when created.

The <epic-*> pack: a pack's events keep their own names (epic-...), except those it shares with Spell UI (ui-open, ui-change, ui-filter).
