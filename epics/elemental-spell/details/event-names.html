Event names

One sentence: which names these are, and what your calls decide.

name -- what that work is for, in one line. what happened that led to these calls. what changes for you once you press Do it.
  • Each row is one name, where it's declared. File opens it at that line in VS Code; Current is how the code reads today; Recommended is Claude's call, already filled in.
  • Agree: leave the box as it is. Disagree: type what you'd write instead. A changed box is marked; its round button puts the recommendation back.
  • What you type is saved every few seconds (the bar says when it can't): a reload or a closed tab keeps it.
  • Do it sends every box and your feedback to Claude. Change anything after and press it again: the new answer replaces the old one.

Modals, flyouts, sidebars, dimmers, popups, toasts, nags, transitions. Today a cancelable ui-open / ui-close comes first, then ui-show / ui-hide once the animation ends: Owen's rule (Q27, Q51) makes them opening / closing (cancelable) and opened / closed.

<ui-section> already says it Owen's way: ui-opening / ui-opened, ui-closing / ui-closed. The accordion still says ui-open / ui-close.

A value changing as you type or drag (ui-input), a change committed (ui-change), a form's validation and saving. A cancelable ui-change (the calendar, the tabs) would be changing by the -ing rule.

An item chosen, a label removed, a message dismissed, a column sorted, progress.

The root getting ready, files loading and saving (the source layer every source element shares), code coloured, scrolling into view, sticking.

The <ui-docs-*> elements the components pages are built from: not components a program would use, but the same event names.

<spell-app> (to be <spell-viewer>, Q16) and <spell-editor>: a component pack's events keep their own names, never translated.

Spell's own drag (Dragging) sends the web's drag events, so a page can follow it as it would the browser's. Platform names: the recommendation spells them as spell would say them, drag start, as mouse down.

The words a handler says today, when clicked: or on-click= / when-clicked= on a tag in a <spell-app> layout, and the browser event each means (LayoutSpell's DOM_EVENTS). Owen's words (Q30, Q32) are on the right.

The language's own event words (spell-parser): trigger / fire / send and on, the drop event, the console's, when created.

The <epic-*> pack: a pack's events keep their own names (epic-...), except those it shares with Spell UI (ui-open, ui-change, ui-filter).

Window and document events the docs runtime, the site's router and the page server's live client send. spell-site:* and spell-server:* are the kit's page server's, which spell-epic's pages listen for.
