Nothing reads a .spellx file: today's tokenizer would swallow a template tag as one piece of markup.

A new reader of our own turns a .spellx file into a tree of chunks, in English and Spanish.

An unknown word is an error that names it.

  • prefixed template tags outside, short words inside (Q37); tag heads may be spell phrases with spaces (Q45)
  • quoted names on every tag (Q39); repeatable attributes (Q6)
  • </> closes the innermost tag, a named closer is checked, /> self-closes (Q40, Q47)
  • bodies kept as raw spell, indented from their tag (Q7); loose text is a markdown prose cell (Q12)
  • the words are a closed set per language, from the words files: spell- / encanto-, accents kept (Q25, Q36, Q49)
  • our own reader, never an HTML or JSX parser (Q5, Q8)
  • Where to see it: README-spellx.md in spell-parser, and the reader's outline of o1's examples (__snapshots__): one line per chunk, kind, name and place in the file.
  • Built: SX.SpellxReader.read(text) gives a SpellxFile: templates, prose cells, declarations (property, alias, action, draw, event, test, menu), handlers (on, when, while), notes (description, comment), code lines, and in a drawing elements, text, holes, if-chains, loops and placed parts -- every node with its exact span.
  • Words per language: a spellx table in English and Spanish words (J24: the Spanish words coined); an unknown word is a diagnostic naming the closest ones.
  • o1's examples now follow Q39, Q53, Q55 and J9, and are the reader's test fixtures, both languages.
  • Limits: a body line ending in </> ends its body (C10); only " starts a string in a head (J25). The reader checks no component names: that's P6.
  • Checks: spell-parser 3841 tests (+26, the reader's); every repo's tests and type check pass (spell-brand's stale-pack test fails on main too); parser speed unchanged (233 vs 231 ms).
  • Also: J15 -- spell describe says template and action; the examples' declarations re-made after P2.
SX.SpellxReader reads a .spellx file into a tree of chunks with exact spans: prefixed template tags, short words, spell-phrase heads, quoted names, repeated attributes, </> / named / /> closers, if-chains, raw bodies, prose cells, drawing markup; each language's spellx words; collected diagnostics

A new spellx, with its namespace and README-spellx.md; the tokenizer's JSX reading (Tokenizer.ts, Tokens.ts) where drawings need it.

Reader tests: every o1 example reads to the expected chunk tree; bad input gives the named error.
