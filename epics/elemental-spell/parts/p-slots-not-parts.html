Spellx and code spell call a template's named places in its drawing "parts": a new idea to people, and spellx already uses slot= for Spell UI's elements.

  • People write it has slots "front" and "back": slots, the web's word, never parts
  • A drawn view's slot can be filled where it's drawn, <card><text slot="front">Ace</text></card>; unfilled slots draw as before
  • Old programs saying has parts still run, and spell lint --fix puts them right

Owen, 2026-10-27: "it should just be slots -- it's a new concept to people and 'slots' makes as much sense as anything else to explain." Parts renamed slots everywhere, and a template's slot filled from where it's drawn with slot=.

  1. Slots in code spell and spellx
    • Symptom: a template's named places in its drawing are "parts", a word people don't know here.
    • Changes: - it has slots "front" and "back"; Spanish - tiene las ranuras "frente" y "dorso" (J172).
    • Spellx's <draw "front"> and <draw "front"/> stay as they are: no spellx word said "part".
    • The rules and the names around them say slot: has_slots, draw_slot, the type's slots, a class's static slots.
    • A slot's drawing still carries part="front", so ::part(front) still styles it; spell and spellx never say "part".
  2. The old wording
    • Symptom: every program written with has parts would stop reading.
    • Changes: it still reads and compiles the same, as an error naming "slots"; spell lint --fix writes it (J174).
  3. slot= from outside
    • Symptom: a template's slots can only be drawn by the template, or a template built on it.
    • Changes: where a view is drawn, its slots can be filled there: <card><text slot="front">Ace</text></card>.
    • Each placed slot becomes the web's <slot name="front"> around its own drawing, in the view element's shadow root: the way Spell UI's elements take slotted children (J175).
    • Code spell's twin: the same markup, with spell's own in= or slot= (J173).
    • A Spanish file's slot name is put in the slot the template compiles it to (frente => front).
  4. Everywhere people read it
    • The two sided view and the notebook templates, Solitaire's card (and Solitario's), the examples, notebooks, tests, the READMEs (README-spell, README-spellx), the spellx guide and the Views guide.
  • Where to see it: merged into main. Code spell says - it has slots "front" and "back" (Spanish - tiene las ranuras "frente" y "dorso", J172); spellx's <draw "front"> is unchanged. Hand test: M11.
  • slot= from outside: <card><text slot="front">Ace</text></card>; code spell's twin is the same markup, with in= or slot= (J173). A Spanish file's slot="frente" fills the template's front.
  • How: a placed slot compiles to the web's <slot name="front"> around the slot's own drawing, in the view element's shadow root: unfilled it shows that drawing (a sub-type's when it draws it again), filled the page's element takes its place for that one element (J175). The drawing keeps part="front" for ::part(front).
