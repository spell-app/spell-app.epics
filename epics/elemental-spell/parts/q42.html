Owen offered two ways to write a handler: <on-mouse-down> or <when-mouse-is-down>, with on-mouse-down={...} as the attribute shorthand. Which is the tag?

Now: is a handler on plus the event's name, or a phrase written for each event?

Shaped by Q37 (a short word inside the template, no prefix) and Q45 (whether a tag head may hold spaces). Below in Q45's recommended form, spaces; with hyphens it would read <on-mouse-down>. 

A · on, and the event's name
	<on mouse down>
		if it is face down
			turn it over
	</>

B · a phrase per event
	<when the mouse is down>
		…
	</>

Not folded into Q45: spaces or hyphens is Q45's; on or a phrase is a choice either way.

  • One pattern for built-in and declared events: <on flipped>, <on closing>.
  • The same words as code spell (- on mouse down:) and as the attribute shorthand.
  • Owen's own Q45 note writes it this way: <on mouse down>.
  • Spanish: <al presionar el ratón>, as Spanish spell says al evento.
  • Reads as English; but a declared event (flipped) has no phrase of its own.
  • Two ways to write every handler.
  • A handler is <on and the event's name>; code spell and the shorthand use the same words.

Choices

A · <on-mouse-down>: on- and the event's name, for every event (recommended)

  • One pattern for every event, built-in or declared: <on-card-picked>, <on-closing>.
  • The same words as the attribute shorthand (on-mouse-down={...}) and as code spell (- on mouse down:).
  • Spanish: al and the event, as Spanish spell writes al evento ... today: <al-presionar-raton>.

B · <when-mouse-is-down>: a phrase per event

  • Reads as English; but every event needs its own phrase, and a declared event (card picked) has none.

C · Both

  • Cost: two ways to write every handler.
  • A handler is <on-<event name>>; its attribute shorthand and its code spell use the same words.
