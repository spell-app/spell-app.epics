Now: a named menu is a list of actions, reused in a toolbar, the app's menu bar and a context menu (Q34). Where is it written, and how does each place use it?

Shaped by Q37 (short words inside a template) and Q46 (bare component names: <menu> is Spell UI's menu). Inside a <menu>, <action> runs a declared action (Q50's context rule). 

<spell-app name="solitaire" menu-bar="GameMenu">     <- the menu bar
	<menu name="GameMenu">                          <- a member, beside the app's actions
		<action "start a new game" />
		<action "undo the last move" />
	</menu>

	<draw>
		<toolbar menu="GameMenu" />                   <- a toolbar
		<solitaire-card context-menu="GameMenu" … />  <- a context menu
	</draw>
</spell-app>

Nothing dropped by Q37's answer.

  • Written beside the template's actions; every place names it.
  • An <action>'s target is the template it's in, unless it says target=.
  • Costs: a card's context menu then depends on the app having drawn its toolbar first.
  • Good once there are many; overkill for one game's three items.
  • A <menu name> inside a template is one of its members; toolbars, menu-bar= and context-menu= use it by name.
  • Code spell's form for it (- its "game menu" is a menu of:) is settled in the events phase.
 
<ui-menu name="GameMenu">                          <- a member of the app, beside its actions
	<ui-action name="start a new game" />
	<ui-action name="undo the last move" />
</ui-menu>

<spell-draw>
	<ui-toolbar menu="GameMenu" />                    <- in a toolbar
	<solitaire-card context-menu="GameMenu" ... />   <- as a context menu
</spell-draw>

Choices

A · A member of its template, used by name (recommended)

  • Written beside the template's actions, like a property; every place names it: menu="GameMenu", context-menu="GameMenu".
  • An app's menus can also be its menu bar: <spell-app menu-bar="GameMenu, EditMenu">.
  • <ui-action>'s target= defaults to the template it's in, so most need none.

B · Markup inside a drawing, named there

  • Cost: a context menu on a card then depends on the app having drawn its toolbar first.

C · A file of its own, GameMenu.spellx

  • Good once there are many; overkill for one game's three items.
  • A <ui-menu name> inside a template is one of its members; toolbars, the menu bar and context-menu= use it by name.
  • Code spell needs a form for it (e.g. - its "game menu" is a menu of: with the actions under it); settled with the events phase.
