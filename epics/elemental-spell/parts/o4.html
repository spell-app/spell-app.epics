A .spellx file is spell in a third style, beside sentences and the outline: spell's own parser reads it, and it compiles straight to JS (Q69, Q70).

  • A spellx tokenizer reads each tag at a line's start as a tag token, so a tag and its indented body are a line and its block, like an outline item. Each tag line is then read as its code-spell TWIN by today's rules (<property "suit" one-of="..."> as its "suit" is one of ...), so it builds the same tree by construction (J44, P6); each language's twin words are data in its words file.
  • Tag heads go through the real grammar, and bodies are parsed in place by today's rules: so Card.spellx and Card.spell compile to the same JS.
  • Drawings go through spell's JSX tokenizer (P7, C28):
    • a component is named bare, and found through the project's packs
    • </> closes any element
    • a drawing draws several things in a row, loops and branches
  • Positions are native, so errors, hover, completion and the notebook's edits land on the right .spellx line with no map in between (P8, P11).
  • The code spell a spellx file means is something to look at, not a step in the compile:
    • written rule by rule, as the Spanish translator writes another language (P8)
    • the same machinery runs the other way as the one-off converter, which lays a code spell file out afresh as spellx (P12, Q19)
  • Last, standard source maps in the build folder point a runtime error at the .spell or .spellx line (P14).
