Some of Spell's tags carry the language's prefix (<spell-property>), and some in Owen's card don't (<description>, <event>, <on-mouse-down>). Which ones carry it?

The prefix is the language's word for Spell: spell- in English, encanto- in Spanish (Q36).

  • <spell-description>, <spell-comment>, <spell-event>, <spell-on-mouse-down>.
  • One rule, nothing to remember; any tag without the prefix is markup.
  • Cost: long, and the handler tags read badly.
  • Prefixed: <spell-view>, <spell-property>, <spell-phrase>, <spell-action>, <spell-draw>, <spell-event>, <spell-test>, and <spell-section> (it stands in markup, so it must not look like HTML's).
  • Not prefixed:
    • handlers, named by their event: <on-mouse-down>, <on-card-picked>
    • blocks that live only inside a member: <description>, <comment>
  • So Owen's <event name="card flipped"> becomes <spell-event>: it declares a member.
  • <spell-view>, <spell-thing>, the page and app tags; everything inside them is short: <property>, <phrase>, <action>, <draw>.
  • Cost: <section>-style clashes with HTML come back, and a member tag means something different inside markup.
  • A tag that declares something carries the prefix; a handler is <on-<event>>; <description> and <comment> stay bare.
  • o1's examples are written this way.
