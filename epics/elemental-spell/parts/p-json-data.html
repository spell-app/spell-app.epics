Data written in a page has no element of its own: <script type="application/json"> is the only form, so a notebook needs an <html> block to hold it, and it can't come from a file.A notebook holds data with no <html> block, and JSON text survives spellml as written.<ui-json> (spellml <json>) holds JSON data, as its text or from a source file. It draws nothing; value and ui-changed are how others read it. <ui-tree-diagram> reads a <ui-json> child. The old script form still works.
  1. A new family, ui-json: a LoadableComponent, so source, load, reload(), loaded and the errors are the ones <ui-code> and <ui-markdown> have. No second loader.
  2. It draws nothing. value is the parsed JSON, set or read; ui-changed says when it changed; bad JSON warns, sends ui-error and value is undefined.
  3. A small shared reader for elements that take JSON children: a <ui-json> child, then a <script type="application/json"> child. <ui-tree-diagram> takes it, following a source as it loads.
  4. Spellml: json becomes a raw-text tag in the parser, as markdown is, so { and [ stay as written. Speed test against HEAD.
  5. Registrations as P28's <ui-space>: exports, vite entry, Spanish, catalog, site data, docs page, tests.
  6. The notebooks, by hand (the converter was retired by epic content P1): Tree Diagram's data blocks become <json>, and a Json notebook set. New <html> count.
