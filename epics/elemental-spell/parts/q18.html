Should Spell write standard source maps, so the browser's developer tools and runtime errors point at the .spellx (or .spell) line instead of the compiled JavaScript?

Owen asked whether we make code maps today, for .spell to JavaScript. We don't: nothing in spell-parser or spell-app writes a source map, and a project compiles to one file (Solitaire.en.js).

  • A source map is a standard file (version 3) that says, for each piece of a compiled file, which line of the source it came from. Browsers read it.
  • The .spellx to .spell span map (Q11) can be written in the same format.
  • Two source maps chain: .spellx → .spell → .js, so an error in the JavaScript lands on the .spellx line. 
Card.spellx  line 12   <spell-property name="color" ...>    red if it is a diamond ...
     |  map 1:  .spellx -> .spell   (this epic's span map, written as a standard source map)
Card.spell   line 7    - its "color" is one of red, black:   red if it is a diamond ...
     |  map 2:  .spell -> .js       (none today)
Solitaire.en.js  line 140   get color() { return this.isADiamond || this.isAHeart ? "red" : "black" }

the browser's error:  TypeError at Solitaire.en.js:140  ->  with both maps:  Card.spellx:12

The cost, honestly: every writer (JavaScript, TypeScript, Python) has to record where each piece of its output came from as it writes.

  • Each AST node already links to its match, which knows its position, so the "where from" is there.
  • But the writers build plain strings, piece by piece; each method would wrap its pieces with their node.
  • Python has no browser to read the map; its errors would need their own mapping.
// Today:  each node is written as a plain string (Writer.ts)
ASTIfStatement(node) {
  return `if (${this.write(node.test)}) ${this.write(node.consequent)}`
}
// With source maps:  each piece remembers where its node came from (node.match.start)
ASTIfStatement(node) {
  return this.at(node, ["if (", this.write(node.test), ") ", this.write(node.consequent)])
}
  • Recommended if it's cheap enough: the positions are already on the AST nodes.
  • Errors in a running app, and breakpoints in the browser, land on the line Owen wrote.
  • Cost: every writer method touched (84 node kinds, three targets); a phase of its own, maybe 4-6h.
  • This epic stays about the two forms.
  • Cost: runtime errors keep pointing at the compiled JavaScript until the other epic lands.
  • The span map stays private to the editor and the language server.
  • Cost: no help in the browser's developer tools, ever.
  • the .spellx reader writes a standard source map beside the .spell text
  • the JavaScript and TypeScript writers write a source map for each compiled project; Python's waits
  • the two chain: developer tools show the .spellx line
