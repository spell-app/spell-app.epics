Spellx drawings name components bare, and there's no plain HTML (README-spellx, "The edges"). So a converted drawing that uses the web's own elements changes:

  • <div> (52, in 9 of the 10 examples): an error, isn't a component any pack here has; the JavaScript is still the same, the tag written as it was
  • <button> (tic-tac-toe) and <label> (bill-splitter): silently Spell UI's <ui-button> / <ui-label>, a different program
  • <h2> is untouched: a digit isn't a bare name

The examples test allows the <div> error, and marks tic-tac-toe and bill-splitter as known gaps (test.fails).

Options:

  1. Recommended: a spellx drawing may name a web element (div, span, h1 ...) that no view or pack has; for the ones a pack has (button, label), an escape that says "the web's", which the converter writes
  2. The converter writes Spell UI's nearest component (<segment> ...): a different program
  3. Leave it: a converted file with plain HTML needs a hand edit
