A file's functions, tests and starting lines, and a member written some other way, have no tag. The converter writes them as they were, inside <spell> ... </spell> (<encanto> in Spanish), one tab in.

  • The tokenizer takes the chunk's tag line out and puts its lines in its place, so they parse at the chunk's level: a function stays at the file's top, so its classes still hoist and its start code still runs there.
  • Its closer stays and compiles to nothing, as every closer does.
  • The pre-pass that finds what a file declares reads a chunk's lines as written, so a call above a chunk's function works.
  • A chunk is a template's member or a top-level tag; inside a member's body it's an error (spellx-nested-template).
