If a .spellx file isn't tags, what shape is it? Four shapes, the same playing card written in each, and what each one does to the answers already given.

Owen, 2026-10-24, on Q15:

"I'm kinda leaning away from .spellx being HTML -- it's too much rope to hand an agent creating a spell, and HTML tags can't be translatable. Let's dig into this now before making the plan."
  • Rope: everything an agent could write that looks right and isn't. HTML invites a whole language of habits: class=, style=, a stray <div>, a property tag nested inside a drawing, quotes and escapes inside attributes.
  • Translatable: a Spanish author writes .es.spell today, every word Spanish. A tag like <spell-property one-of="..."> is English whatever the file's language.

The yardstick is the kickoff prompt's four goals, plus Owen's two worries:

  1. a novice can read it
  2. a notebook: prose and spell side by side, like Jupyter's or Observable's
  3. each chunk gets its own editor (a property's is a <ui-property> form)
  4. an agent can walk the chunks one by one, and find one by name

The cards below use phrase where round 1 said "alias" (Owen's comment on Q17: "Let's use phrase for this").

A · closed tags, named in the file's language

  • The tags of round 1, but a CLOSED set: only Spell's tags and attributes, and spell lint rejects any other.
  • Their names come from the language's words file, as code spell's keywords do.
  • Both worries are only half met: it still looks like HTML, so agents (and people) bring HTML habits, and lint has to catch them after the fact. 
<spell-view name="playing card" aka="card" template="two sided view">
	A playing card has a suit and a rank.
	It shows its front when it's face up, and its back when it's face down.

	<spell-property name="suit" one-of="clubs, diamonds, hearts, spades"
		description="Which of the four suits it belongs to"
		phrase="is a (suit)"
	/>
	<spell-property name="color" one-of="red, black"
		phrase="is (color)"
		phrase="is a (color) card"
	>
		red if it is a diamond or it is a heart
		black otherwise
	</spell-property>
	<spell-property name="rank" one-of="ace, 2 ... 10, jack, queen, king"
		description="Ace is low:  ace = 1 ... king = 13"
		phrase="is a (rank)"
	/>

	<spell-phrase name="is the (rank) of (suit)" />
	<spell-phrase name="is a face card">if its rank is jack, queen or king</spell-phrase>
	<spell-phrase name="is a number card">if it is not a face card</spell-phrase>

	<spell-action name="turn it over">
		<description>Flips the card:  face up becomes face down, and back.</description>

B · a markdown notebook

The file is an ordinary markdown page. Spell reads three things in it:

  • A heading that starts with a kind names a chunk: # view: playing card, ## property: suit, ## phrase: is a face card, ## action: turn it over, ## draw: front.
    • A template is a # heading; its members are ## headings under it.
    • Any other heading (## Suits and ranks) is a prose heading: a section title in the notebook.
  • A list of - key: value lines, right under the heading, holds the chunk's fields: - aka: card, - template: two sided view, - one of: clubs, diamonds, hearts, spades, - phrase: is a (suit) (a key may repeat).
  • A ```spell fence holds the chunk's body: a property's value lines, an action's steps, a drawing's markup. A field holds one value; anything that takes lines of spell goes in a fence.
  • Everything else is prose: the paragraphs right under a chunk's fields are its description; prose before the first member is the template's. 
# view: playing card
- aka: card
- template: two sided view

A playing card has a suit and a rank.
It shows its front when it's face up, and its back when it's face down.

## property: suit
- one of: clubs, diamonds, hearts, spades
- phrase: is a (suit)

Which of the four suits it belongs to.

## property: color
- one of: red, black
- phrase: is (color)
- phrase: is a (color) card

```spell
red if it is a diamond or it is a heart
black otherwise
```

- phrase: is a (rank)

Ace is low:  ace = 1 ... king = 13.

  • Equal to code spell as before (Q10): each heading and its fields become one declaration line, each fence is copied word for word under it, each paragraph becomes // lines.
  • Little rope: the only shapes are a heading, a key: value line and a fence. The kind words and keys are a closed list per language; lint names a misspelled one and the words it expected.
  • The only markup left is what a drawing puts on the page (<ui-text>), inside its fence. Those tags are English too; translating them is epic 's todo T2.
  • What it costs: the markdown parser we already have (Spell's MD package) finds the headings, lists and fences, with their positions; the new part is reading a heading's kind and its fields, per language.
  • The catch: a kind word at the start of a heading is reserved. A prose heading "Property: a note" would be read as a property; lint would say so.

C · no second form: the notebook is a view of code spell

  • The file stays .spell, outline style. The editor draws it as a notebook:
  • a ## heading is a section title; // lines with a blank line after them are a prose cell;
  • each - member line, with its body, is a code cell; the // lines right above it are its description.
  • Agents get the chunks from a command: spell chunks Card.spell --json.
  • Nothing to keep equal, so the least work. But the declarations stay sentences, not fields: a property's editor has to rewrite - its "suit" is one of ..., and the shape isn't the one Owen typed (Q2). 
// A playing card has a suit and a rank.                 <- prose cell
// It shows its front when it's face up, and its back when it's face down.

a playing card aka card is a two sided view where:       <- the template's cell
	// Which of the four suits it belongs to                <- the next cell's description
	- its "suit" is one of clubs, diamonds, hearts, spades  <- a property cell
		- it "is a (suit)"
	- its "color" is one of red, black:                     <- a property cell
		red if it is a diamond or it is a heart
		black otherwise
		- it "is (color)"

	// Flips the card:  face up becomes face down, and back.
	- to turn it over:                                      <- an action cell
		if it is face up
			turn it face down
		otherwise

D · indented keyword blocks, no markdown

  • Each chunk is a keyword line, its fields indented under it (like Pug, or Marko's concise syntax, or YAML).
  • Translatable and closed, like B. But prose has no home of its own: it goes under an about: key.
  • It renders as plain text everywhere; only our editor draws it as a notebook.
view playing card
	aka card
	template two sided view
	about:
		A playing card has a suit and a rank.
		It shows its front when it's face up, and its back when it's face down.

	property suit
		one of clubs, diamonds, hearts, spades
		phrase is a (suit)
		about: Which of the four suits it belongs to
	property color
		one of red, black
		phrase is (color)
		phrase is a (color) card
		value:
			red if it is a diamond or it is a heart
			black otherwise

	phrase is a face card
		if its rank is jack, queen or king

	action turn it over
		about: Flips the card:  face up becomes face down, and back.
		do:
			if it is face up
				turn it face down
			otherwise
				turn it face up

	draw front
		<ui-text color={its color}>{its picture}</ui-text>
	draw back
		<ui-image src="card-back.svg" />

The shape

  • Closest to what Owen typed; round 1's answers stand as they are.
  • Cost: still HTML-shaped, so the rope is still there; lint catches it after the fact.
  • Meets both worries: three shapes only (heading, field, fence), every word from the file's language.
  • The notebook comes free: it IS a markdown page, readable on GitHub and in any editor.
  • Agents read and write markdown better than anything else, and split it by heading.
  • Cost: kind words are reserved at the start of a heading; per-language words for kinds and keys.
  • Least work, nothing to keep equal.
  • Cost: declarations stay sentences, not fields; not the shape Owen asked for.
  • Fields as plain keyword lines, translatable.
  • Cost: prose has no natural home, and it's only a notebook in our own editor.
