An action is only a function: no title, shortcut or enabled state, and menus are built by hand.

An action is a described command, and named menus of actions are reused as a toolbar, the menu bar and a context menu.

  • an action has a title, icon, tooltip, shortcuts, enabled when and selected when (Q33, Q38)
  • a named menu is a member of its template, used by name (Q34, Q41); context-menu= (Q30)
  • every way of running an action goes through one step
  • Where to see it: spell-app's ActionMenus browser test's small Solitaire: its game menu as the menu bar and a toolbar, a card's right-click menu, a shortcut that runs only while enabled, Undo Deal, ⌘Z.
  • One run point (core.runAction()): nothing runs while not enabled; undone as makes one undo step through prefs-and-undo's recorder (C11); listeners hear key, click, menu or code.
  • Shortcuts start at the focused thing and go up to the app; the first enabled action takes the key; meta is ⌘ or Ctrl. Undo / redo are the app's own actions with live titles.
  • Menus: - its "game menu" is a menu of "deal", "-", "undo" and "redo", - its menu bar is "game menu"; spellx <menu> with <action/> children and menu-bar= (C26); context-menu=; Spanish.
  • <ui-action> in Spell UI: title, icon, key caps, greyed / ticked, click runs it; docs page and Spanish.
  • Not yet: a toolbar's actions only once it has drawn (C46); no visual baselines, Python, or VS Code menus (C47).
