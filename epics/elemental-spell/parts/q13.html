A <spell-property> can carry its own phrases, alias="is (color)", even several (Q6). How does code spell write a property's own phrases, so the round trip knows which phrases fold back into their property?

A phrase (the tag calls it an alias) is a new way to say something about a card: it "is a (color) card" lets a later line say "if the card is a red card". The (color) blank stands for one of the property's choices. 

<spell-property name="color" one-of="red, black"
	alias="is (color)"
	alias="is a (color) card"
>
	red if it is a diamond or it is a heart
	black otherwise
</spell-property>

<spell-alias name="is the (rank) of (suit)" />      <- two properties:  stands alone
<spell-alias name="is a face card">                  <- has its own body:  stands alone
	if its rank is jack, queen or king
</spell-alias>
  • A phrase whose only blank is one property's belongs with that property: it can be an alias= on its tag.
  • A phrase with its own body, or with blanks for two properties, stands alone as a <spell-alias>.
  • Today, code spell writes every phrase as a line of its own, beside the property, with no tie between them.

Three ways code spell could write the tie:

- its "color" is one of red, black:
	red if it is a diamond or it is a heart
	black otherwise
	- it "is (color)"
	- it "is a (color) card"
  • Reads as "and these are its phrases"; the writer knows exactly which fold into alias=.
  • Matches how a property's value lines already sit under it.
  • Cost: new grammar: a phrase line inside a property's body.
  • Cost: value lines and phrase lines share one body; the - bullet tells them apart.
 
- its "color" is one of red, black:
	red if it is a diamond or it is a heart
	black otherwise
- it "is (color)"
- it "is a (color) card"
  • No new grammar: today's code spell already reads it.
  • Cost: the tie is a guess: a phrase about color right after the color property folds in, one elsewhere doesn't. Moving a line changes the .spellx. 
- its "color" is one of red, black, aka "is (color)" or "is a (color) card":
	red if it is a diamond or it is a heart
	black otherwise
  • One line per property, like the tag.
  • Cost: long lines, hard to read with two phrases; new grammar too.
  • new code spell: - it "..." phrase lines inside a property's body, the property's own
  • .spell → .spellx: those become alias= on its tag; every other phrase becomes a <spell-alias>
  • a phrase line beside a property (today's way) stays a <spell-alias>: nothing in today's files changes meaning

Settled on Q17 (M9: "Let's use phrase for this"), recorded as Q22. So this question's tags and attribute are <spell-phrase> and phrase=. 

<spell-property name="color" one-of="red, black"
	phrase="is (color)"
	phrase="is a (color) card">
	red if it is a diamond or it is a heart
	black otherwise
</spell-property>

<spell-phrase name="is a face card">
	if its rank is jack, queen or king
</spell-phrase>
  • It matches what the docs already say ("Phrases become rules") and the parser's messages.
  • Inside the parser, "alias" stays the grammar's own word, for a rule's other names.
