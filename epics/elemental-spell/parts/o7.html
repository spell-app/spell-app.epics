Spell's events follow Owen's model, not JavaScript's (C4).

  • A thing sends an event to another, which can pass it on up or cancel it; handlers say when they run (on, when, while); the keys and the mouse can be read anywhere (P9).
  • An action is a described command with a title, shortcuts and an enabled state; every action runs through one point, which checks it's enabled and makes it one undo step (prefs-and-undo's recorder); named menus of actions are reused as a toolbar, the menu bar and a right-click menu, drawn by Spell UI's <ui-action>; undo and redo are the app's own actions (P10).
  • The events Spell UI, spell-epic and the app send are renamed by one rule: -ing while it can still be cancelled, -ed once done (J52, Q68).
