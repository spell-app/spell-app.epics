In the editor app, a .spellx file's tag lines are uncoloured: only comments and headings show colour. It's step 0 of P16, whose cells edit spellx in the same Monaco.

  • A background agent is fixing it now (elemental-spell-colours), beside P16; it commits as elemental-spell C50.
  • Why: one Monaco language serves both kinds of file, and every line is coloured by code spell's tokenizer, so a line like <property "rank" one-of=...> gets no tokens.
    • VS Code got its own spellx grammar in P8; the editor app never did.
  • The fix:
    • a second Monaco language, spellx, for .spellx files
    • the editor's tokens provider takes the tokenizer to use: spellx lines go through the spellx tokenizer, which rewrites a tag line into its twin's tokens (J44), so <property "rank" colours as property and rank do in code spell
    • the language server's semantic colours already map through the span map
  • Files: spell-app's SpellMonaco, SpellTokensProvider, SpellModels
  • Checked by: a browser test (the <property "rank" ...> line gets keyword and string tokens), and a headless screenshot of Card.spellx beside Card.spell.
