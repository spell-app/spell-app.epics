Other tools that keep two forms of the same code in step, or mix prose and code in chunks. What each one teaches this epic.

  • Marko has an HTML syntax and an indented "concise" one.
    • They compile to identical output, and its formatter can write either.
    • Lesson: two equal forms of one language is a solved, shipped idea.
    • Marko's concise syntax
  • Observable Notebooks 2.0 saves a notebook as HTML: a <notebook> holding one tag per cell.
    • An optional id on a cell keeps its identity while it's edited.
    • They chose HTML because it's "easy to review diffs ... to search, to find-and-replace".
    • Lesson: the closest precedent for a .spellx file.
    • Observable Notebook Kit
  • Vue and Svelte read the code inside a block as raw text, sliced exactly from the file.
    • Vue pads each block with blank lines, so line numbers in errors match the .vue file; Svelte blanks out the rest of the file for the same reason.
    • Lesson: how a .spellx reader keeps errors and hover on the right line (Q10).
    • Vue's SFC parser
  • recast and BiYacc print a changed tree back out by rewriting only the parts that changed, from the original text.
    • recast promises print(parse(source)) === source.
    • A plain pretty-printer (Prettier, Reason's refmt) loses the author's layout and wording.
    • Lesson: the round trip copies text, it never re-prints it (Q11).
    • recast
  • MakeCode switches between blocks and JavaScript.
    • Code it has no block for becomes a grey block holding the raw JavaScript, which goes back to text untouched.
    • Lesson: a line with no tag form goes over as a raw <spell> chunk, word for word (Q11).
    • MakeCode's blocks and JavaScript
  • Jupytext, Livebook and Pluto keep notebooks as plain text files.
    • Jupytext merges two prose cells side by side into one; Livebook needs a marker comment to keep them apart.
    • Pluto keeps two orders: the order the cells run in, and the order they show in.
    • Lesson: the boundary between two prose chunks must be explicit, and the order on screen is the order in the file.
    • Jupytext's formats
  • Unison stores code as trees, and keeps no comments at all: only its doc blocks survive.
    • Lesson: prose is a real chunk of the program, never a comment a tool may drop (Q12).
    • Unison's comments
