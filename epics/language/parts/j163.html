Card.editor.spell is text the Inspector reads (propertyEditorInSource()), never parsed or compiled: no JS, TS, Python, words or scope pack comes of it, and there's no property editor rule for P55's declaring tags to hook into. So <property-editor "card"> ... </property-editor> (or </>) is read beside "card" is a property editor in the same reader, and tested to give the same markup, byte for byte, for Solitaire's and Solitario's files. No SPELL: DECLARES, hover or scope-explorer entry: nothing is declared. A general top-level <type "name"> in a compiled file is left unbuilt: its children would be markup where a declaration's body is members.

Clarify impact

What changed: Card's property editor (Card.editor.spell) can now start <property-editor "card"> and end </property-editor>, as it does today, instead of "card" is a property editor.

The impact, all of it:

  • The Inspector shows the same card editor, whichever form the file uses: a test checks both give the same markup, for Solitaire and Solitario.
  • Nothing else reads that file: it isn't compiled, so no JavaScript, TypeScript, Python or words change.
  • So, unlike <deck "deck" hidden />, the tag declares nothing: no hover, no go to definition, no Scope Explorer entry for card's editor.

Not built: a <type "name"> ... </type> at the top of an ordinary .spell file.

  • Inside it, a declaration's body is properties and actions, not markup, so the tag form doesn't fit there.
  • For you: write either form in a property editor file; nothing else in the editor or the compiled app changes.
