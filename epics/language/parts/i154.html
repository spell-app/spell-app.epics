Fixed, merged into main (language-readahead; commits e867987d8 and 73ad50c20).

  • Why it broke, two causes:
    1. Reading ahead only looked for lines starting to ..., so a question like it "can go up" if ... was never found. Even if it had been, the step that makes a method usable early skipped questions on purpose.
    2. The a card line in Solitaire ends in a comment (a card -- play the card on click ...). The scan didn't count that line as starting a type, so it read nothing in that type's body ahead.
  • The fix:
    • the scan finds a question up to its if and leaves its body out: it "can go up" if, "is high" if:, a card "can go up" if, and Spanish si / es
    • a question is now usable early too. Once its real line has parsed, the early version gives way to it.
    • a type's line can end in a comment
    • left out on purpose: a question about a value kind (a rank "is a face card"), and one about a type the scan can't tell isn't a value kind. Read early, those would compile wrong.
  • Checked:
    • Solitaire with its a card block moved below the app compiles with no errors. Apart from the reordering, it compiles the same as with the block on top.
    • All 21 examples compile byte for byte the same as before.
    • New tests in outline.test.ts: the scan, in English and Spanish, and a question declared below the app being asked in its action
    • The parser's full unit tests: 6342 passed, 0 failed. The syntax tables were regenerated because two rule files moved by two lines.
    • Speed test against HEAD: 668ms before, 615ms after. That's noise: the same 40 rule tests fail on both, and they were already failing.
