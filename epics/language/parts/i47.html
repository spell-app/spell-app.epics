In spellml, <property "tip">, a newline, the amount * bill splitter's percent / 100, a newline, </property> is Don't understand: the body reads as statements and wants return. The same expression on the tag's line, <property "tip">...</>, works, and so do value-if lines ("" if ... / ... otherwise). The message doesn't say to add return, and the first guess (it can't see the app in another file) was wrong.

Today a one-line property returns its line only when that line can't be read as a statement. So the case in this issue works now, but a property whose one line is a CALL compiles to a getter that returns nothing, with no error. Actions and to ... methods never return a bare line.

  • Why: a body below a line is read as statements first.
    • Only when that fails, and the line takes a value (a property), is the one line tried again as a value: oneLineValue().
    • A call reads fine as a statement, so it never gets that second try.
    • An action's body never takes a value, so a bare value there is always Don't understand.

The rule to choose. Other languages:

  • Ruby and Rust: every block's last expression is its value.
  • Kotlin and C#: a one-expression function (= expr, => expr) returns it.
  • Python: only a lambda; every other function needs return.
  • A property is a value, so its one line IS the value, even a call: quadrupled n of it.
  • Fixes the silent case above.
  • A line that can only be a statement (print 3) is an error that says a property gives a value.
  • Actions stay as they are: a bare "hey" in one is still Don't understand.
  • Properties as in A.
  • An action or to ... whose one line can only be a value returns it: to shout of a bill: "hey", the n * 2.
  • A call line in an action stays a call: play the opening plays it, and nothing is returned.
  • So no line that worked before changes meaning, and nothing is ambiguous.
  • It's today's fallback, widened to actions.
  • As Ruby and Rust do: the last line of any property or action, if it's an expression, is returned.
  • The cost: to deal the cards ending in shuffle the deck would return what shuffling returns.
  • Spell records what each method returns, so a call to it could then be used as a value by mistake, and the editor would offer it as one.
  • People reading it can't tell "do this" from "give this back": in English or in Spanish (jugar la apertura).
  • Why B: it goes by what the definition IS, not by how a line is worded.
    • A property gives a value; an action does something.
    • The rule reads the same in English and Spanish, with no word lists.
    • A reader never has to wonder whether an action's last line is being returned.
  • A property whose one line is a call returns the call's result, instead of nothing.
  • A property whose one line is only a statement says "a property gives a value", instead of compiling to nothing.
  • An action or to ... whose one line is only a value returns it, instead of Don't understand.
  • Nothing that works today changes meaning; this issue (I47) closes with it.
