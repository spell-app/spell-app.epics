For P55 · Solitaire's New Forms: may a drawing declare the things it draws, so to draw it isn't a second list of what the app already listed?

Your words (2026-11-13):

a big one: can we declare hint/score/piles etc inline in to draw it rather than declaring them then immediately drawing them?

Today Solitaire names each pile twice: once as a member, once as a tag in its drawing.

solitaire is an app
	"stock" is a new stock pile
	"C1" is a new column
	"score" is a number
	to draw it
		<stock-pile "stock"/> <column "C1"/> ... Score: {the score}

With option A, the member lines go, and the tags declare them:

solitaire is an app
	"score" is a number
	to draw it
		<stock-pile "stock"/>
		<foundation "clubs" suit=clubs/>
		<column "C1"/>
  • A view's tag with a quoted id that names no member declares one: <column "C1"/> is the same as "C1" is a new column.
  • Its attributes are its with values: <foundation "clubs" suit=clubs/> is "clubs" is a new foundation with suit = clubs.
  • The reading of a tag's id as the member it draws is already there (I79, I80): only the declaring is new.

How it would be built, and the risks:

  • The scan before parsing (the read-ahead names of P17) collects those tags, so the actions above the drawing that read the stock still find it.
  • Incremental parsing: a drawing that declares changes the program's names, so an edit in it can't stay a quick body edit.
    • Kept quick when the ids it declares are the same as before, as a method's return type is today.
  • A typo declares a new, empty pile instead of failing: <column "C8"/>.
    • A warning when a member a drawing declared is never read anywhere else, or when the id is close to another.
  • The Inspector and hover show them as members, saying where they're declared.
  • Python and TypeScript: the same members as the declaring lines make today.
  • Spanish: the same, <columna "C1"/>.
  • Solitaire drops its 14 pile lines; its drawing is where each pile is declared.
  • The score (and a hint) stay one line each: a value has no tag to declare it.
  • As A, and the score line goes too: Score: {its "score", a number} declares it where it's shown.
  • A new form inside fill-ins; as a number can't be used, since it already converts ("5" as a number).
  • Piles and other views; values stay declared lines.
  • As A, plus a fill-in that declares a value.
  • The member lines stay, folded under the drawing in the editor.
  • Big enough to plan on its own, after the rest of P55.
