Chose a cache entry per project (keyed by its project file, every file's text, its targets, and each import's declarations or source files) over one per file, because a project compiles as ONE module: each class gathers its members from every file (combineCompiled(), hoistClassMembers()), and the writer reads the whole project first, so one file's code can't be told apart from the rest. And the record of what each type uses (editor P23's SpellDeclarationPlaces) doesn't count what a method's body uses yet, so it can't vouch for which files an edit leaves alone: trusting it would serve stale output.

What Owen asked still holds for the PARSE, measured on Solitaire: an edit to Card.spellml re-parses Card, Jokers, Deck, Pile and Solitaire; an edit to Solitaire.spellml re-parses Solitaire alone (the incremental parse, by file order). The writing (about 100ms of Solitaire's ~350ms in node) is whole-project. Across projects it's transitive by key: a library's edit is a new key for every app that imports it.
