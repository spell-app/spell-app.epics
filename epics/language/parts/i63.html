Left in PokeSpell's styles.css after T88, each a gap other examples would hit too:

  • A width for something in a row: the search field (16em to 26em), a strength bar (at most 36em), a card in a family (10em). T76's <ui-container width> centres a box, so it doesn't fit an item in a row or a lone card.
  • A heading that grows with the window: the logo and a Pokémon's name are clamp() sizes, bigger than massive on a desktop and smaller on a phone, in weight 900.
  • A picture with no hairline: the theme draws a 1px outline round every img (for photos with white edges); a transparent drawing on a coloured circle wants none.
  • A stack that turns into a column when narrow: the family's row becomes a column under 34em, its arrow pointing down (a container query).

Four looks, each a few attribute words that would take PokeSpell's last CSS out of its styles file. Every word below is built from words Spell UI already uses, and each has its Spanish name beside it.

  • Words Spell UI has now, which these build on:
    • the shared font (Spanish letra), every element: font="bold serif 14"
    • header size (tamano), mini to massive (gigante)
    • image appearance (apariencia): bordered, circular, rounded
    • stackable (apilable) on menus, grids, cards and button groups: "stacks on mobile"
    • icon rotated (girado): clockwise (horario)
    • zoom's max-width (ancho-max); width (ancho) on a container and on an image

1. A logo or title bigger than the largest header, in heavy letters with a coloured shadow

The PokéSpell logo and a Pokémon's name: bigger than massive on a desktop, smaller on a phone, weight 900, the logo with a yellow shadow. 

.title::part(header) {
  font-size: clamp(2.4em, 7vw, 4em);
  font-weight: 900;
}
.logo::part(button) {
  text-shadow: 0.06em 0.06em 0 #ffcb05;
}
  • size="poster" (cartel): the step past massive, growing with the window between a floor and a ceiling.
  • heavy (extranegrita): a new font word, next to bold.
  • shadow (sombra): a shared attribute taking a hue, a hard shadow down and right. 
<header size="poster" font="heavy" color="red">{its name}</header>
<button font="heavy" shadow="yellow" ...>PokéSpell</button>
  • The font size grammar (14, 10/20) gets a range: 32-64, which grows with the window.
  • A shadow-yellow word too.
  • One attribute, but a dense one to read and translate.
<header font="heavy 38-64">{its name}</header>
  • appearance="poster" (cartel) on a header: huge, heavy and growing, all at once.
  • Its shadow in the header's color's partner hue.
  • Quickest to write; nothing to tune, and a button can't have it.
<header appearance="poster" color="red">{its name}</header>

Why A: three small words a reader can read one at a time, each useful alone (a heavy label, a shadowed button), and size already means "how big" on every family.

2. The sunny circle behind each picture

Each Pokémon's drawing sits on a soft yellow circle, with a little room round it, and without the hairline the theme draws round every picture. 

.art::part(image) {
  outline: none;
  padding: 0.75em;
  background: radial-gradient(circle, #fff3b0 0 58%, transparent 59%);
}
  • background (fondo): a hue, drawn soft (the hue's light tint), with room round the picture.
  • With appearance="circular" that background is a circle.
  • A picture with a background has no hairline: the hairline is for photos with white edges, which appearance="bordered" already names.
  • The same word would work on a card, a segment or a label later.
<image appearance="circular" background="yellow" src={its picture} alt="" />
  • appearance="spotlight" (foco): a soft circle behind the picture, the picture never cropped.
  • Its hue from a new image color.
  • Closest to today's look, but a word only images have.
<image appearance="spotlight" color="yellow" src={its picture} alt="" />

3. A width for something in a row, or a lone card

The search field grows from 16em up to 26em, a strength bar stops at 36em, and a card in a family is 10em. A container's width CENTRES its box, which is wrong for a thing in a row. 

.find { flex: 1 1 16em; max-width: 26em; }
.strength { max-width: 36em; }
.evolution::part(card) { flex: none; width: 10em; }
  • Shared attributes, any CSS length, the box's own width where it sits: width (ancho), min-width (ancho-min), max-width (ancho-max).
  • The names CSS uses, and zoom's max-width already; fluid still means "grow into the room left".
  • A family with a width of its own keeps it: a container's centres, an image's is its pixel size. 
<form fluid min-width="16em" max-width="26em" ...>
<progress max-width="36em" ...>
<card width="10em" ...>
  • Only width, taking 10em, 16em to 26em, or up to 36em.
  • Spanish: ancho="16em a 26em", ancho="hasta 36em".
  • Reads well, but a container's and an image's width already mean something else, so the same word would mean three things. 
<form width="16em to 26em" ...>

4. A row that becomes a column on a phone, its arrows turning down

A Pokémon's family is a row (Bulbasaur, an arrow, Ivysaur, an arrow, Venusaur). Under 34em wide it runs down the page instead, and each arrow points down. 

@container (width < 34em) {
  .evolutions { flex-direction: column; }
  .arrow::part(icon) { rotate: 90deg; }
}
  • stackable (apilable), the word menus and grids use: a row becomes a column when narrow.
  • Alone it's a phone's width; a length says where: stackable="34em".
  • It goes by the stack's own room, not the window's, so it works in a side bar too.
  • A new rotated value, when stacked (al apilar): the icon turns a quarter while its stack is a column. 
<stack direction="horizontal" stackable="34em">
  ...
  <icon name="chevron right" rotated="when stacked" />
  • direction="horizontal vertical": a row while there's room, a column when not.
  • The arrow as A.
  • No new attribute, but no place to say where it switches.
<stack direction="horizontal vertical">
  • stackable as A; an arrow or chevron icon right inside it turns by itself.
  • Nothing to write on the icon, but it's magic a reader can't see in the markup.
<stack direction="horizontal" stackable="34em">
  <icon name="chevron right" />
  • Spell UI gets these new words: size="poster", the font word heavy, shadow, background, min-width / max-width / width on every element, and stackable on a stack.
  • Icons get one new rotated value, when stacked.
  • Each has its Spanish name: cartel, extranegrita, sombra, fondo, ancho, ancho-min, ancho-max, apilable, al apilar.
  • PokeSpell's styles file keeps only its theme (sky, ink, card corners) and the Who's That Pokémon shadow.
  • Building it is Spell UI work (vocabularies, CSS, docs), a phase of its own once you've picked.
