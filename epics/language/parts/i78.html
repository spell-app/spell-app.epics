Found building P53. In a plain-Spell drawing, <action "undo"/> as the drawing's FIRST line (or <action "undo"></action>) is refused Can't read "undo" in <action>; the same tag after another line, or inside an element, compiles. The quoted word isn't kept on that line's tag: the first line of a drawing is tokenized another way. Solitaire and Solitario aren't hit: their actions sit inside <buttons>. P53's tests wrap theirs in <buttons>.

A drawing's own line of markup reads an action's button and a right-click menu first, as it does a notebook's example.

  • Cause: not the tokenizer. A line of markup that IS the drawing is drawn_markup, which read only {markup:jsxElement}, the plain tag. <action "..."/>'s own rule (action_button) answers only where an expression or an element's child is read, so a drawing that was that line alone drew a plain <action>, which can't read its quoted word. With a second line the lines read as one fragment, and the action was its child, so it worked.
  • The same for <context-menu>: a drawing that is only a menu drew a plain <context-menu> tag, its items lost.
  • Fix: drawn_markup takes {markup:action_button} and {markup:context_menu_block}, registered before jsxElement, in English and Spanish, as it already does for example_block and markdown_block.
  • Tests: a drawing of only <action "deal"/>, only <action "deal"></action>, only a menu, and Spanish's <acción>.
