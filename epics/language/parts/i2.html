That was a poor name from a test. slow value was a made-up action that takes a moment before it gives its answer, such as looking up a score on a server. 

to get the high score:
  pause for 1 second
  return 5

to check:
  if get the high score is 5
    print "top score!"
  • Before P9: JavaScript didn't wait, so it compared "an answer that's still on its way" with 5. That is never equal, so "top score!" never printed, and no error appeared.
  • Since P9: this case waits for the answer, then compares, so it prints.
  • Still open here: the same mistake inside getters and draws, which P12 fixes.
  • This is the bug waiting by default exists to remove: a person writes the plain sentence, and it does what it says.
