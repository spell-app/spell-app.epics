  • From Owen, 2026-11-03: I want to be able to customize attributes of <ui widgets in a "theme" -- e.g. in my app, I want all buttons to be pills and all sections to be "raised".
  • Every <ui-button> inside an app whose defaults say appearance: circular draws as a pill; one that writes appearance="basic" itself keeps that.
  • Any attribute a component's vocabulary lists can have a default, checked against its values.

  • A root (<ui-root>) can hand its subtree default attribute values per tag, which an element uses when it doesn't set that attribute itself.
  • They change live, and a nested root inherits what it doesn't set.
  1. Where defaults live: each root's settings (RootSettings, which already gives icons and emoji their packs by the nearest <ui-root>) gain defaults: tag => attribute => value. A nested root inherits the outer one's and overrides what it sets.
  2. How an element uses them: when an element has no attribute of its own for a name, it reads the nearest root's default (in DOMElement, through the settings Spell UI installs, since spell/element can't import Spell UI). Its own attribute, or a property set in code, always wins. They are real attribute defaults, not CSS: the value is converted and checked exactly as the attribute would be; a bad value warns once, naming the root and the tag.
  3. Live: RootSettings.generation already bumps on every change; elements reading a default track it and redraw.
  4. Which attributes: any in the vocabulary but content ones (label, value, text); a default naming one warns.
  5. Giving a root its defaults: a defaults property on <ui-root> (an object, as rich attributes already allow); P29 is what writes it from Spell.
  6. pill: added as another word for circular in <ui-button>'s vocabulary (Spanish píldora), so appearance="pill" works.
