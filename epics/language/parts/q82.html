For P68 · Upgrading Old Spell. You wrote: "At the least, put a comment that a field is -- NEW as of <date> or -- APPARENTLY DELETED as of <date>".

That part is built: data's P53 writes those lines into a place's Spell file (<Name>.api.spell) when spell place update looks again, and its reference page shows them as labels. A field still used is kept, marked.

What's missing: the PROGRAM lines that use a field marked gone say nothing. And a rename on the server looks like one field gone and one new.

A catch: a -- line under a thing in a program is its description, so a dated comment written into program code would become one.

  • A line using a field marked gone gets a yellow underline: "user was apparently deleted from netbox (as of 2026-11-19)".
  • When the same look marked one field gone and one new in the same type, the fix offers "Use owner instead"; the person picks, nothing renamed silently.
  • Nothing written into the program's own text.
  • -- APPARENTLY DELETED as of 2026-11-19 written after each line using it. Visible without the editor, but it becomes the line's description where it's a declaration, and needs taking out again.
  • The place file's dated lines are enough; program uses wait for later.
  • Every use of a field the server dropped is underlined with the date; a likely rename has a one-click fix.
