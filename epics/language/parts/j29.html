Built (P26): a new card written in a project compiles to new (core.classToMake(Card))(), the running program's card, only when the project file lists Card in its exports.

  • Why: the plan says 'the project's own exported types', and 'compare: 0 changes'. Every project, or every project with a version, would change compiled output: with version, recipe-box, recetario, live-room and sala-en-vivo changed (5 files), their app and places made by name for nothing.
  • So a cards library that wants Solitaire's card made by its deck says "exports": ["Card", "Deck"]. Without it, its deck still makes its own cards, and Solitaire's own code still makes Solitaire's.

Today only a type named in the project file's exports list gets made as the running program's version, and nothing on disk lists one, so the feature is off unless you know to ask for it.

  • A project with a version is one made to be imported, so it needs no list: its a new card makes the running program's card, for every type of its own.
  • Except its app and its places: nobody replaces those, and making them by name only adds noise.
  • An explicit exports list still wins, and narrows it to what it names.
  • A project with neither stays a plain new Card(): Solitaire and the other examples compile exactly as they do now.
