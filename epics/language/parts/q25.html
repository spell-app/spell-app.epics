Each KIND of measure (length, weight ...) is a family of units that convert into each other; each kind is a small table, and the work grows with the number of kinds.

  • Length: mm, cm, m, km, inch, foot, yard, mile. Weight: g, kg, ounce, pound, stone. Temperature: °C, °F. Volume: ml, l, teaspoon, cup, pint, quart, gallon (US). Speed: km/h, mph, m/s.
  • Covers recipes, Star Wars and most of what people measure. Temperature isn't a plain multiply (°F = °C × 9/5 + 32), so it's the one special case.

Yes: the kinds are dimensions, and each one is written in Spell, the built-in five included.

  • How it's written: a dimension names its base unit, then each other unit as so many of another. The built-in five are a Spell file the core ships, dimensions.spell; a program declares its own the same way.
  • What the compiler makes of it: one table per dimension: each unit's names in each language, its Intl name for printing, and its factor to the base unit. The JavaScript and Python cores read the same table, so they can't drift.
  • What a program does with it: a property declares its dimension and stored unit; in converts by dividing through the base unit; a unit of another dimension is a compile error.
  • The odd one: temperature isn't a factor (0 °C is 32 °F), so a unit may say a formula instead, - fahrenheit is celsius * 9 / 5 + 32. 
a "data size" is a dimension measured in bytes:
	- a kilobyte is 1000 bytes
	- a megabyte is 1000 kilobytes
	- a gigabyte is 1000 megabytes

a photo is a thing:
	- its "size" is a data size in bytes

print the size of the photo in megabytes    // 2.4
 
core.dimension("data size", { base: "byte", units: { kilobyte: 1000, megabyte: 1e6, gigabyte: 1e9 } })
core.console.log(core.convert(photo.size, "byte", "megabyte"))
