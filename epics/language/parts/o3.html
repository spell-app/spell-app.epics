A local hides the property from where it's made, to the end of its block.

shuffle the stock          // this.stock.shuffle()
set stock to 3             // a new local:  const stock = 3
print the stock            // the local, 3
print its stock            // still the property
  • The same word can therefore mean two things in one action, with no error. The corpus has 17 such names today: 9 locals and 8 arguments or loop variables. None changes meaning, since none is read as a property with the yet (Q2).
  • An argument hides a property too: in to go on (a pile), the pile is the argument, and its pile the property.
  • Locals stay block-scoped: after if ...: set score to 1, the local is gone.

The trap is writing. Today set the score to 1 makes a local, so it would sit beside reads of the property and silently lose the write: 

if the side is front        // this.side
  set the side to back      // { const side = "back" }:  the property never changes

Rewriting today's 277 its X reads in actions to the X, as a test, showed what else has to be right:

  • 18 of 480 files compiled differently, and 12 errors appeared, 5 of them in a file that already fails.
  • Most of it was set the X making locals: 52 this.X = lines were lost.
  • Some was properties declared below their use: Solitaire.spellml reads its clubs above its property.
  • The rest is a gap in the prototype, not the idea: the position of the rank lost its enum lookup.
