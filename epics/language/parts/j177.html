The type-line scan (SpellParser.declaredTypes()) stubs a "stock pile" is a pile by name only, with no super-type. So if the card is in the stock at Solitaire line 87, above line 171, can't tell the stock is a pile, and it compiles to solitaire.stock.includes(this): a search of that one list, about 24 cards, which is correct.

To fix it, the scan would record each stub's super-type, as the real line does. An edit to a type line already re-parses the whole project (changesTypeKinds()). But stubs that know their super-type change what every chain() / isA() reader sees above a declaration (drawings, is a, typed calls), so it's a type-system change across many rules, not part of J148. Left as it is.
