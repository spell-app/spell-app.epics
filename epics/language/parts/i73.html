In plain Spell, a <for film in its films> written on a line of its own at a drawing\x27s top (not inside an element) parses as the in-element loop, and the javascript writer throws no ASTJSXExpression() method instead of saying what to write. Plain Spell writes that loop as for film in its films lines; the tag form read the tag line. Found when the tag tests moved to plain: ForTag.test.ts and placeReadsInDrawings.test.ts now wrap their loops in an element. Also: a place read inside an in-element <for> doesn\x27t set the drawing\x27s static drawsWaiting, as the line-of-its-own loop did.

A <for> that is a drawing's whole line draws as the loop itself, as for lines do.

  • Cause: an in-element <for> is a child value, {core.drawEach(...)}, in braces. On a line of its own, the drawn line returned those braces as they were, and no writer writes braces outside an element.
  • Fix: the drawn line (DrawnMarkup) returns what the braces hold, the loop, so the drawing is return core.drawEach(...) (or core.drawRead(...) with riders), the same as the plain for film in its films lines.
  • So a place read in that loop holds the whole drawing again (static drawsWaiting), as the plain loop does: a test says so.
  • Inside an element, a place read in a <for> shows its own "…" where the loop is (a child value that waits), and the rest of the element draws at once: kept as it is, its test says so too.
  • Tests: ForTag.test.ts and placeReadsInDrawings.test.ts, a loop on a line of its own.
