From r7. The request's own wording declares the KIND and the unit it's stored in; the value stays the plain number the data has, so swapi's 172 needs no change. 

// declaring it (all options)
its "height" is a length in cm
its "mass" is a weight in kg

// A:  shown in the person's units;  converted on request with "in"
print its height                  // 172 cm, or 5 ft 8 in for a US person
print its height in feet          // 5.64
print its height in feet and inches   // 5 ft 8 in

// B:  converted with "as"
print its height as feet

// C:  a measure is written with its unit, anywhere
set the height to 172 cm
  • Reads like English: its height in feet. feet and inches, pounds and ounces give the mixed form people read.
  • Plus C's literal (172 cm) where a number is written by hand, if cheap.
  • Spanish: su "altura" es una longitud en cm, su altura en pies.
  • as already means a type (x as text), so as feet is a second meaning for it.
  • 172 cm carries its unit wherever it goes, but data read from a place (swapi's plain numbers) would still need a declaration to know its unit.
  • A property says its kind and unit once; in <unit> converts; shown, it's in the person's own units.
