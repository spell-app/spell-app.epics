It reads each .spellml file as plain Spell: it writes FizzBuzz.spellml.es.spell with the English prose and tags left in, 7 lint errors, shape 0 of 0, exit 1, and copies the English .spellml files into the output too. Reproduce: spell translate @spell/examples/fizzbuzz --to es --no-ai --cold --out <empty folder>, then spell lint it. Cause, from the code: in parser/src/cli/translateProject.ts the file-naming regex (near line 781) and NOT_COPIED (near line 849) only know .spell. parser/README-spanish.md says so, and its example uses @spell/test/fizzbuzz until this is fixed.

Translate each tag file by way of its plain-Spell form, then write the result back as tags.

  • The translator only knows how to write plain Spell, one line for each line. A tag file becomes the plain Spell it means first, in memory (the "Show as .spell" writer), and the names, lines and fix-ups passes run on that, so they and the shape check see real statements.
  • Once the fix-ups finish, each of those files is written back as tags, in Spanish, by the writer spell spellx convert uses: FizzBuzz.spellml gives FizzBuzz.es.spellml. The project file names the new files, and the English tag files are no longer copied across.
  • Prose between tags goes through as comments, which is how the passes already translate words. It comes back as prose, not as // lines. With --no-ai nothing can translate a sentence, so it stays English, as comments do today.
  • After writing tags, the translation is linted and tested again. If the tag form is worse than the plain form, the run keeps the plain .es.spell files and says so, instead of leaving something broken.
  • --update reads a tag translation back through the same plain form, so lines a person edited stay. If the two don't line up, it writes every line again, as it does for any record that doesn't match.
  • spell translate works on the examples written in tags, and writes tags back.
  • The README's example can use FizzBuzz itself.
