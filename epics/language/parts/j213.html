How the roles were built (P60, part 2), each choice so every drawing stayed the same:

  • Roles live on the rule's class. English's addRule(Rule, { syntax, roles }) keeps them on the class, so Spanish's registrations read them too and say none. Saying different ones throws, and a test checks each role names a group that every language's syntax has.
  • A few rules say them on their class instead (@proto static roles): the ones built while parsing (a phrase, an action call) and yes / no and the spelled-out numbers, which each language registers as a class of its own.
  • A property's name has no role yet. property: "declaration" would put a bare it has a shape in a pill (it's bold today). A quoted name already draws as a pill, from the parse.
  • An action's pill runs from its first declaration or blank to its last declaration, which may be a word of the syntax (it in when a card is dropped on it). A blank takes the article before it.
  • An action's blanks are its signature's arguments. They come from the method_signature rule's own roles (bare_type_arg, method_arg), and are drawn only in an action's head. So a property's quoted (rank) isn't underlined, as before.
  • pause for 300 msec needs no role of its own: its measure is a quantity. The duration step's measure_literal check is now that role.
  • The snapshot is drawn in each project's parse, as the editor draws it. A snippet drawn alone (the docs pages) is BubblyLayout.test.ts's.
Nothing looks different: every example's and guide's drawing is the same as before.
