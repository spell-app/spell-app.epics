A site's group line takes its colour after its name, in any of three forms:

  • group "Teams", color purple: what jarvis and the mockup guide now write (your first example)
  • group "Teams" with color purple: the with an action's head line uses (with title "Deal")
  • group "Teams", colored purple: as a page's line says its card's colour
  • Spanish: grupo "Equipos", color morado, con color morado, , de color morado

How:

  • One more syntax for the group rule (DefineGroup) in the sites rules, using the colour word a page's card already uses (site_card_color), not a new list.
  • The action head line's option list (action_modifiers) reads ACTION details, so the group line follows its wording, not its class: one option, colour, so no list yet.
  • The colour compiles to nothing, as any group does: the site editor reads it from the text (SiteEdits); its section and its cards take it.
  • The group rule is shared with templates' groups, so group "x", color red also parses in a template's outline, and does nothing there.
  • A group's description is the first comment under it (P48's rule): jarvis's Workflows keeps // Baton there.
  • Not done: the site editor has no colour picker for a group (none for a page either); the three colour lists (UI's toast colours, the sites' card colours, Notify's) stay separate: the coordinator files that as a todo.
