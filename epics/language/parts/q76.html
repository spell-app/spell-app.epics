For P67 · Drag Events, from request r29 (epic from-jarvis). You asked: "Should we add ui-dragged-over for the normal drag? What would be gained?"

Today a card dragged over a pile sends no event of its own:

  • The page calls the pile's own handlers, when a card is dragged over it: and the rest.
  • The only event is the program's card-drop, and only when the pile has no dropped on it line.
  • Spell's drag also sends the browser's own dragenter, dragover and drop, but they don't say which card or which pile, and dragover comes on every move of the mouse.

What would be gained: code OUTSIDE the program could follow a drag, by listening for an event.

  • A help panel or tutorial: "now drop it on a foundation", as the card comes over one.
  • A sound, or a count of moves, kept by the page around the game.
  • Tests, and the editor's Inspector, waiting for "dropped" without knowing the program's handler names.
  • A Spell UI element around the board, drawing its own marker where the card would go.

The program itself gains nothing new: it already hears all of it in its own words. An event nobody listens for costs next to nothing. 

board.addEventListener("ui-dropped", (event) => {
  const { thing, list } = event.detail   // the card, and the pile it landed on
  playSound("thunk")
})
  • ui-dragged-over as the thing comes over a list, then again as it moves over it, at most every 100ms, with where the pointer is.
  • ui-dragged-out as it leaves, or is dropped where it isn't taken.
  • ui-dropped on a drop the list takes, even when the list has its own dropped on it.
  • The thing and the list in each one's detail. They tell, they never decide: none can be cancelled.
  • The same three, but ui-dragged-over comes once per visit, like the program's own when a card is dragged over it:. Nothing to rate-limit; no pointer place.
  • Ordinary drags stay as they are; only files from the desktop send events.
  • A list sends ui-dragged-over, ui-dragged-out and ui-dropped, the thing and the list in the detail
  • Spanish: arrastrado-sobre, arrastrado-fuera, soltado, as the file events' Spanish names in from-jarvis Q12
