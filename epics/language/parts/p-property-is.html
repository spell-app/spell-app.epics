A property's type or value is its tag's body, <property "score">a number</>, after everything else on the tag, and type="number" is a second way to give a type.

Owen's words (2026-11-10): “<property "score">a number</> let's do simple types like this as <property "score" is={a number} />. The type should come immediately after the property name, so <property "hint" description="...">text</> goes to <property "hint" is={text} description="..." />.” Then, on type=: “is everywhere, remove usage of type= in all the examples”; and on whether is= also takes a worked-out value: “Values too”.

  • is={...} holds exactly what follows is in the property's plain line, its "score" is .... So it means what that line means today:
    • is={a number}, is={a list of cards}: a stored property of that type
    • is={first 2 letters in (its by as upper case)}: worked out each time it's read
    • is={a new recipe with servings = 4}: whatever the plain line says today
  • A start value stays the body: <property "count" is={a number}>0</> reads as today's type="number">0</>, its "count" is a number starting at 0.
  • A worked-out value over several lines stays the body, as today, with no is=.
  • type="number" keeps reading, with a warning naming is={a number}. Spanish: es={un número} replaces tipo=.
  • The writers always put is= straight after the name; the reader takes it anywhere on the tag.
  • A property says what it is in one attribute, is={...}, right after its name: <property "score" is={a number} />.
  • type= goes from every built-in project; old files still read, with a warning.
  • A body stays only for a start value or a value over several lines.
  1. Reading. In SpellxTwin.property(), an is= attribute is the line's right side: its {name} is (the existing value shape) followed by the attribute's own Spell tokens, which the tag head already reads inside braces, a } in a string included (findMatchingDelimiter() in SpellxTokenizer). With a body as well, the body is its start value: a new shape, its {name} is {is} starting at, in both packs (words.property; Spanish empezando en).
    • is= beside a body over several lines is an error on the tag, as type= with a block is today (spellx-typed-body): a worked-out value is the body or is=, not both.
    • is= beside one-of= is an error too: both say what the property is.
    • type="number" reads as is={a number} (the article from the type's own word, as typed does now), with a warning naming the new form. Spanish's attribute word is es; tipo= warns the same way.
  2. Writing. SX.SpellxWriter, spell spellx convert, ingest's PlaceSpell and spell translate write a one-line right side as is={...} straight after the name, self-closing, and a start value as the body. A body over several lines is written as today.
  3. The rename. A codemod beside P41's spell rename tags (spell rename properties, or a step of it): rewrites type= to is=, moves every one-line body into is={...}, and puts is= first. Run over the built-in projects and docs; never the frozen test projects.
    • A one-line body with a comment after its closer, >text</> // an address: the comment stays at the end of the tag's line, is={text} /> // an address.
    • A body that already holds braces or quotes goes in whole: is={"Message " + its thread name}.
  4. Docs. README-spellx (its “Types and start values” section and the word table), PARSING.md, app/AGENTS.md's examples guidance, the language packs' docstrings; the commands page if a command is added.
  5. Tests. Each shape in both languages: a type, a project type, a list, a worked-out value, a new thing, a start value; old type= and old body forms compile the same as is=; the two errors; the writers' output.
