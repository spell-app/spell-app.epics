Proposed fix (language-caret2):

  • Cause: Spell's Enter rules (ENTER_RULES, and VS Code's copy in language-configuration.json) still go in a level only after a colon; heads have no colon now.
  • Fix: one more rule, before the colon's: Enter at the end of a head goes in a level. A head is a line starting with a handler's, action's or control line's word, in English and Spanish (when, on, after, to, for, if, otherwise, else, repeat, while, meanwhile; cuando, al, después de, para, por, si, sino, de lo contrario, repetir, mientras), or a type's line at the top (a "card" is a view, solitaire is an app). Only with nothing after the caret, so Enter in the middle of a head doesn't push its end in.
  • The same table in the editor and VS Code; the test holding them the same checks the new rule, and that it knows every pack's control words.
  • Not done: a group's line (group "Moves"), whose members are written at its own level; a one-line if with its step after it (if x return no) still goes in a level, as the rule can't tell.
Enter at the end of a head (`when creating solitaire`, `to draw solitaire`, `to "reset the stock"`, `for each ...`, `if ...`, a type's line at the top) goes in a level, so the new line stays in its body, in the editor and VS Code alike (`SpellKeywords.OPENS_BODY`, one more Enter rule); English and Spanish
