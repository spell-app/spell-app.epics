For P18 · Action Titles. The editor's menus are written once, in English, in AppMenus.spellml. On a Spanish page the Run menu's code item should read Código. Where do a title's other languages come from?

What Spell has today:

  • A project's words file, one per language (AppMenus.en.js, cartas.es.js): each member's wording, and what the core says to people in that language. A runner reads them all.
  • spell translate writes a whole program again in Spanish, and keeps a names dictionary (<Project>.es.names.json5) whose texts section holds its texts in Spanish.
  • The editor's own words are keys in AppTexts.en.ts / AppTexts.es.ts.
  • The English title is written once, on the action: title="Compile and Run".
  • Each language's words file gets a titles section: AppMenus.es.js says compileAndRun: "Compilar y ejecutar".
  • The runner picks the page's language, so core.actionTitle() gives the Spanish one there.
  • spell translate fills the Spanish titles from the names dictionary's texts, so nobody writes the file by hand.
  • Why: it's how Spell already speaks a program's members in another language; one file in, every language out.
  • AppMenus.es.spellml, written in Spanish with Spanish titles; the editor loads the one for its language.
  • Works with nothing new in the core, but the menus' structure is written twice and drifts.
  • title-key="compile-and-run", looked up in AppTexts.
  • Only the editor could use it: Spell would know the app's own files.
  • A title is written once, in the program's language; its other languages live beside the program, in the words file the runner already loads.
