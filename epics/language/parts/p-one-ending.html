Spell has two file endings for one language: .spell and .spellml. People have to learn the difference and type the longer one, and the 33 .api.spell files are the only large group still written the other way.

  • Owen's words, 2026-11-09: “I want it to just be .spell everywhere, simpler for people to grok and less to type.” And, for the API files: “<web-server "wikipedia" address="...">”.
  • Every Spell file ends .spell.
  • A file is tag-shaped when any line starts with < in the very first column, other than <ui-defaults>. Otherwise it's plain Spell. Lines inside comments don't count.
    • Owen picked this rule. Measured on all 593 files (the built-in projects, the core templates, his own projects): right on every one.
    • Owen's first idea was the first line that isn't a comment or a heading. It was wrong on 69 files, because a tag file usually opens with a # Heading and a line of prose.
  • The 454 built-in .spellml files become .spell. No two files collide on the new name (checked).
  • .spellml and the older .spellx keep opening, so nobody's own project breaks. Nothing writes them any more.
  • The places in the 33 .api files are written as tags: <web-server "wikipedia" address="...">, in both languages, with the same program compiled.
  • A file's shape comes from what it says, not its name.
  • The built-in projects, the editor's own pieces, the starter projects and the docs say .spell.
  • The Monaco editor and VS Code each treat .spell as one language that colours both shapes.
  • A place has a tag of its own, and spell place ingest and spell place update write it.
  • spell spellx convert rewrites a file in place, as it can no longer write one beside it.

  • A new empty file is plain until its first <.
