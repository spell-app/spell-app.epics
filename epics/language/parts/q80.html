For P68 · Upgrading Old Spell. What starts an upgrade?

Today spell lint --fix already rewrites Spell's retired words (parts to slots, wait for gone), old HTML habits and old page forms. The repo's list of shared mechanisms says not to build a second rewriter: "Flag: a new spell upgrade". The editor and VS Code offer no fix for any of them.

  • spell lint --fix stays the one rewriter, with old forms added to it.
  • Each old line gets a quick fix ("Change to ...") in the editor and VS Code, and "Upgrade this file".
  • Opening a project written for an older Spell shows a notice once: "Written for an older Spell. Upgrade", which runs the same rewrite.
  • A name people would look for; it runs the same rewrite as lint --fix (a second name, not a second mechanism), then records the version.
  • Plus A's quick fixes and notice.
  • The editor rewrites a project as it opens, and says so. No asking; the person's undo puts it back.
  • One rewriter, reached three ways: spell lint --fix, a quick fix per line, and the editor's Upgrade notice.
