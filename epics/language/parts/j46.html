Named it cacheLimit, written "200MB", "1GB", "512KB" or a number of bytes (SRV.sizeInBytes(), binary units). The kit's own part (its package.json's "pageServer") says "200MB"; a later part wins, so the epic repo's page-server.json5 can change it for this machine. The app's route module reads it as the page server starts. 'Used' is written or read: a read touches its file's time, and a write past the cap drops the oldest-touched first, never the entry it just wrote. A compiler version bump still starts an empty cache: the new version's folder has nothing in it; the newest 3 versions' folders stay (they count against the cap) rather than one, so the main checkout's page server and a worktree's, each with its own compiler, don't wipe each other's on every write.
