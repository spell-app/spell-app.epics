## Playing a card

// What a click or a drag does: the card's own moves, and each pile's, as the game plays them.

// the card, and every card on it, onto the first pile that takes it; it says whether it moved

// - the stock's card turns over onto the discards instead

to play a card

undoable as "Play Card"

if card's pile is solitaire's stock

play from the stock

return

set end pile to the first pile in every pile where it can take the card

if there is not an end pile return no

return put the card on end pile

// the card, and every card on it, onto the pile, if the piles' rules let it go and take it; it says whether it moved

// - the pile it left turns its new last card up; the move counts, and scores

to put a card on a pile

undoable as "Move Card"

set start pile to card's pile

if start pile cannot give up the card return no

if pile cannot take the card return no

set points to count the points for the card on pile

for card in (cards in start pile starting with the card)

move it to pile

if the start pile is a tableau and the start pile is not empty

pause for 200 msec

turn the last card of the start pile face up

set solitaire's moves to solitaire's moves + 1

set solitaire's score to solitaire's score + points

return yes

to count the points for a card on a pile

// what the move scores: 10 on a foundation, 5 from the discards, else nothing

if pile is a foundation return 10

if card's pile is solitaire's discards return 5

return 0

a card

// each card's events, and when it may be clicked: the Inspector lists them, as written here

clickable when it is face up or its pile is solitaire's stock

// only a card face up, or the stock's, can be clicked: the others show no pointer

on click

// a click plays it

play it

when dragged

// a drag starting clears the last hint

clear solitaire's hint

on drag cancelled

// dropped where no pile takes it, or Escape pressed: it slides back, and the score says so

set solitaire's hint to " -- Not there"

a pile

while card dragged over

// while a card it would take is over it, the score shows what the move would add -- gone as the card leaves

set points to count the points for the card on it

if it can take the card and points > 0: set solitaire's hint to " (+" + points + ")"

on card dropped

put the card on it

The plain drawings above are written the way you'd write them, not the way Spell reads them today. Each change is listed here, to make into a phase later.

  • An ability is a word before the template, not a line of its own (C6)
    • Today: a "card" is a two sided view: ... - it is draggable
    • This page: a "card" is a draggable two sided view
    • Tags: already an attribute, <view "card" template="two sided view" draggable>
    • The same for the other abilities: clickable, selectable, droppable. The word is in italics (C10).
  • A declaration's description is a comment, the first line inside its block (C7, then "ditch the description thing and put it as a comment INSIDE the block")
    • Today: // What a person, a test or the console calls it
      - group "names"
    • This page: - group "names"
      // What a person, test or console calls it
    • Tags: an attribute today, <group "names" description="..."/>
    • Every one-line comment right above a declaration, in every file on the page, moves inside: the first line of its body; a declaration with no body gets one holding just the comment. A block of comments, or one with a blank line after it, stays where it is. Today Spell reads the comment right ABOVE a declaration as its docstring (the writers' ASTDocComment, kept with the next definition; a tag's description= is written as that comment by SpellxTwin), and a comment inside the body as just a comment in the body: so the change is to read a body's first comment as the docstring instead. The card in tags (section 5) still shows description= as its source has it.
  • No colon at the end of a line (C8)
    • Today: - its "color" is one of red, black:
    • This page: - its "color" is one of red, black
    • Tags: never had one, a tag's body is between its tags
    • The band and its bracket already say a body follows, so the colon says nothing more.
  • An action's name is quoted, and its title is on its line (the analysis page's Q6, your first picture)
    • Today: - to deal the cards: ... - titled "Deal"
    • This page: - to "deal the cards" with title "Deal"
    • Tags: already one tag, <action "deal the cards" title="Deal">
    • Not drawn on this page yet: listed so the list is whole.
  • An action's title is its name in Initial Caps, unless it says otherwise ("the default title should be the action name in Initial Caps")
    • Today: - to auto play: ... - titled "Auto play"
    • This page: - to auto play
    • Tags: the same, <action "auto play"> shows as Auto Play
    • Today an action with no title shows its name as written, all lowercase: auto play. So Auto Play and Cheat drop their titled lines on this page; Restart keeps its own, start a new game being other words. The core's wordsOf() makes the default; the translated words files look titles up by their text, so their keys change with it.
