You want a <ui-chart> soon, working with Plotly and d3, each possibly drawn on the server. The full write-up, with every measurement, is the research note.

What it uses, and does not build: a shared way of drawing on the server already exists (assumed done). Mermaid and coloured code use it. It turns text into a drawing, keeps the drawing by a hash of what made it, and puts it in the page inside the element's Declarative Shadow DOM, which is kept when the element starts. The chart adds three drawers to it and nothing more.

  • One element that takes a chart as data: a spec and rows, in one of a few chart languages (engine): Observable Plot by default (decided), Plotly for Plotly's figures (the same JSON Python writes), and a d3 module of your own that gets the rows and size and returns a drawing.
  • Plotly can't draw in node: it failed at load without a real browser, so on the server it uses the shared mechanism's headless browser. d3, Plot, ECharts and Vega all drew in node with no browser.
  • Hover needs no library: the server's drawing carries each mark's row, and a small Spell UI layer (3-5 KB, estimated) shows tooltips, moves by keyboard and fires events. Only zoom, pan and redrawing load the library.
  • Accessible: a required label, a description, the data as a table under a "Show the data" fold, and arrow keys from mark to mark, each announced.
  • Light and dark: drawn with fixed placeholder colours, then each rewritten to a Spell UI token, so a drawing follows the page with no redraw (to check in a browser per engine).

For scale: Mermaid's lazy piece is 1,186 KB brotli, Solid itself 35 KB. On a phone, the full Plotly bundle costs more to parse than to fetch (inferred).

Risks:

  1. The headless browser (shared with Mermaid): ~100-200 MB and a second or two to start (estimated).
  2. Labels drawn on the server may sit a little differently from the page's font (inferred).
  3. A server drawing scales as a whole, so a narrow phone shrinks its labels.
  4. Any page that goes fully live with Plotly pays 325-1,092 KB brotli; the hover layer exists so most never do.
  5. The colour pass needs every engine to pass placeholder colours through untouched: check per engine.

Effort (estimated): the three drawers on the shared mechanism, S-M; the element with Plot, its English and Spanish vocabulary (Spanish <es-grafico>, which takes "gráfico" from the Mermaid element's other names), tokens, table and docs page, M; the hover layer, S-M; the Plotly engine, S-M; the d3 engine, S.
