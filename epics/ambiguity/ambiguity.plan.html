Spell grows a phrase at a time, and every new phrase, library, alias or translation can make an old line mean something else, or two things at once, without anyone noticing. This epic looks at how a novice stays safe as it grows: catching double meanings, explaining and checking what a line does, and guiding people to the right words, mostly without paying for an agent.

I'm really worried that as we add new features to the spell language that we will introduce ambiguity that would be hard for a novice to work with. Examples:
- a "card" is a spell-ui component, but a "card" in solitaire is app-specific.
- loading features from a library api might change the meaining of existing spell.
- upgrading the spell language itself might make your code unusable because we added a new spell feature that breaks one of your `to` rules.
- making alternatives for the language might introduce more ambiguity that we're not aware of
- it's extremely hard to know what exactly to write in spell, I often get confused myself. How can we guide the user to "the right" code, with and without an agent in play? (`agents-in-spell` is working on agent integration).
- how can we "explain spell code" in the editor without an agent prsent.
- how can we make language guides that are good for agents and humans? What do they look like? What would a "Programming in Spell" O'Reilly book cover?
- "how do I..." help in spell with or without an agent.
- how can we use verify (using an agent or not) from the compiler that the spell english as written is performing the most likely effect when looking at a line of code or a method, by using the english as natural language english and examining the output?
- how can we test all of the above in many languages?

Goal is that a novice can use spell fearlessly, and is guided to write the correct thing, without being expensive in terms of agent cost -- and we get a subset of that even without an agent running.

Big scope here, this is my major concern with the spell language.
First task is to create a number of pages which cover all of this. We'll review that before coming up with a plan.
