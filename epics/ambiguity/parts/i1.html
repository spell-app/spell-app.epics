Found by the coherence review, and run for real in a scratch project. With a card is a view in the program, a page holding <ui-card>Go</ui-card>:

  • spell lint . --fix printed fixed: <ui-card> is <card> in a page
  • before the fix it compiled to h("ui-card", "Go"); after, to h("cards-card", "Go"): a different component, silently

Three places decide what a bare tag names, each its own way: the compiler's componentTagFor() (the program's own drawn type wins), the editor's ownViewOf() (any type of that name wins, so hover and Go to Definition can point at the wrong thing), and lint's fixHtmlHabits() (never looks for the program's own). The fix: one test, the compiler's, used by all three.
