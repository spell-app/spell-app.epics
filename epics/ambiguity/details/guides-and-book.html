Six things make one guide work for a person and an agent at once.

  • Every example runs. Its Spell compiles in a test, and what it compiles to, or prints, is in a fold the test checks. The kit already does this for commands in READMEs (the README test), but not for Spell.
  • One fact, one place. A count, a phrase's wording or a warning's words are generated or quoted from the code, never typed twice.
  • Task first: "you want / you write / it means", in the order people ask, not the parser's.
  • Every phrase with its near misses, each saying what Spell does instead. Each near miss is a test too, so a change in what it does shows up.
  • Both languages: each entry's Encanto beside it. Testing that is Testing it in many languages's.
  • A short form for agents: the same entries, with the near misses kept and the prose dropped.

Could it be made from the rules?

Partly. Each rule carries some of an entry today, and not the rest.

A rule carries
  • a docstring, its first line the rule's purpose, written for people adding rules
  • its syntax in each language, in the parser's notation
  • its tests: lines, and what each compiles to; the first is the syntax table's example
 A rule doesn't carry
  • what a person wants when they reach for it
  • what it means, in plain words
  • its near misses, and which task it belongs to
  • And one task isn't one rule. "Changing a property" is one rule with five spellings; its near misses are other rules: a new name, a question.
  • So the facts can be generated (syntax, examples, outputs, counts, a warning's words); the judgement is written by hand (the task, the meaning, which near misses matter); a test checks both.

One phrase as a phrasebook would show it. Every line in it compiles today; the format is a proposal.

Changing a property

You want a thing to keep a new value: the scoreboard's home score back to 0
You write set its home to 0
It means its home is 0 from now on, and whatever is drawn from it redraws
Also right set the home to 0 and the home is 0, inside the scoreboard's own action
In Encanto poner su local a 0, or el local es 0
See also making a new name; asking a yes-or-no question; adding to a list
Near miss Spell reads it as You see

its home is 0, as the action's last line a question, "is its home 0?" nothing, today

5.2 Three jobs for "is"

In English, "is" both tells and asks. "The light is red" tells you; "is the light red?" asks.

Spell uses the word three ways, and tells them apart by where the line stands. Here's a scoreboard for a game between two teams:

Scores.spell · spell · 21 lines 
## The scoreboard
a "scoreboard" is a thing
	its "home" is a number
	its "away" is a number
	it "is a tie" if its home is its away

	to start it
		set its home to 0
		set its away to 0

	to cheer it
		// The home team scores
		set its home to its home + 1

to test the scoreboard
	the board is a new scoreboard
	start the board
	the board is a tie should be yes
	cheer the board
	the board is a tie should be no
	the home of the board should be 1

Read the ises from the top:

  • its "home" is a number declares: every scoreboard keeps a number called home.
  • it "is a tie" if its home is its away asks: its second is compares the two scores, and the answer is whether it's a tie.
  • the board is a new scoreboard, on a line of its own, sets: from here on, the board is that scoreboard.
  • the board is a tie should be yes asks again: should be makes the line a check.

So a line of its own that starts with a name and is sets. After if, before should be, or inside another sentence, is asks.

When you mean to change something, set is never in doubt: set its home to 0 can only set. That's why the scoreboard's actions use it.

Run the test, and Spell says what it checked:

1 passed

Change the test's last line to the home of the board is 1. The editor underlines it: "Don't understand". A line of its own can set a name, or the thing's own property, but not another thing's. Write set the home of the board to 1.

An action's last line is its answer, when that line is a value. So its home is 0 as the last line of an action sets nothing: it asks "is its home 0?", and gives back yes or no. Nothing warns you. Write set its home to 0. Appendix B lists the near misses like this one.

  • A book shouldn't need that last box. Whether the compiler should catch it is Does the line do what it says?'s question.
  • The test and the "Try it" were compiled as written; the box's words are today's Spell.
