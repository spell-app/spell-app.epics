The line What it does Why only Spanish
imprimir la fecha de nacimiento de la p, when a person tiene una fecha de nacimiento como texto p.nacimiento.fecha: "the date of the birth of p". The declaration errors; this line compiles silently. de is both "of" and part of a name. English names seldom need "of" (birth date); Spanish names use de all the time. Pinned as not working yet; in quotes, su "fecha de nacimiento", it works.
el nombre de la persona, in a loop over the people here (the live room's Spanish twin) persona.nombre, which is always empty. The English twin compiles to person.name. A built-in member's Spanish name is read in one place and not in another. TypeScript's check flags it, and its snapshot keeps the error as accepted. The shape check misses it: it takes names out before comparing.
la carta es roja No entiendo "es roja". Only la carta es rojo, which is bad Spanish, compiles. A card's colors are declared rojo, negro, and Spanish adjectives agree with their noun. Not silent, but the error doesn't say why.
imprimir 1,5 console.log(1, 5): two numbers. And precio es 1,5 is an error. Spanish writes one and a half as 1,5. README-spanish says 1,5 is a number; the Spanish language pack names the comma as its decimal mark, but nothing reads that setting yet. English has its own: print 1,000 prints 1 and 0.
la carta es el dos de espadas, Solitario's own example for its alias carta === "espadas".dos Not Spanish-only: Solitaire's English example misreads the same way. The translation carried the misreading faithfully, and a check that compares the two languages passes it, since they agree.
es and está both "is" Spanish has two verbs for "is", for what a thing is and what state it's in. Spell treats them the same, on purpose: lenient, but a meaning Spanish has and Spell drops.
  • Epic language's date words page found more, before they were built: la hora alone is the time as text, la hora de ahora the number 21; el número de already counts things, so el número del mes may read as "how many months" (Date and time words).
  • Where types settle it, both languages agree: el segundo del mazo is the deck's 2nd card, el segundo de ahora the seconds of the time, as in English.

Checks with no agent cost nothing more per language: they run the same rules over each language's words. Checks with an agent cost per line, per language, so they're sampled.

  • Haiku 5.5, 2026-11-20: six Spanish lines from Solitario, each with its JavaScript, asked whether the code does what the Spanish most likely means, and to flag bad Spanish.
  • It found 3 of 3 misreadings: el dos de espadas, jota, dama o rey, and imprimir 1,5 printing two numbers.
  • It did not flag la carta es rojo, which a native speaker would correct to roja. A cheap model reading for meaning is not a Spanish reviewer.

 Agents, now
  • whether each line's code does what its words say (the run above)
  • whether a name will split on the language's small words
  • whether the same English word got the same translation everywhere, against the glossary
  • whether a message reads plainly to a newcomer: the voice check, untried in Spanish
  • Miss: grammar, as above; regional words; how formal a sentence sounds
 Native reviewers, later
  • whether a phrase sounds like one thing or two: the double meaning a native hears
  • regional words: computadora or ordenador, agregar or añadir (epic spanish's open list)
  • gender and agreement: la carta es roja
  • how formal Spell sounds, tú or usted
  • Cost: someone's time, per language, per round of new phrases
  • Tests catch what neither can: a translation that runs a different program. They're the floor for every language, reviewed or not.
  • A review page per language could do for phrases what the names review page does for names: each new phrase, its words, the double meanings found, and Accept or retype.
  • Comparing two languages finds where they disagree, not where both are wrong: Solitario's el dos de espadas passes because Solitaire's example misreads too.
  • Each language has traps of its own (gender, the decimal comma, de inside names) that no English check would look for.
  • Code that matches the words of each language as patterns breaks quietly when a third one arrives; each language's words belong in its language pack, asked for by name.
  • Agent checks multiply by the number of languages; checks with no agent don't.
  • A third language may have nobody on the team to read it at all: agents and tests only, until someone does.
  • The docs teach English Spell; the Spanish syntax table exists, but no page reads it yet.
