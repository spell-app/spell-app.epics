Explaining Spell without an agent

The editor already explains a line, in its hover and in Explain This, but for many lines both say too little, or the wrong thing. This page shows where, what the parser keeps that could say more, and what we'd build on. It's one of seven pages for depth; the analysis pulls them together.

    • plain, the editor app's own: how an outline's line reads as a sentence, what a built-in step or an action does, what a name is
    • full, in VS Code and spell explain, or with the editor's "Compiler details in hover": also the rule's name and syntax, an example from its tests, and the JavaScript
  • "Reads as" (getLongForm()): only the first line of an outline's member, said as a sentence.
    • its "direction" is up or down reads as a card image has a direction as one of up or down.
    • In the file's language: a Spanish file says "Se lee".
  • Explain This, on the code's right-click menu (epic editor, its "Explain This" phase):
    • the Spell on the left, what it does on the right; nothing runs

    • then a summary from Claude Code on this Mac (ClaudeExplainer): Haiku, no tools, the code's text alone, up to 30 seconds; quiet when there's no Claude
    • not in the public preview, which has no server
  • The Spell Tree pane: "Click a line of your program to see how Spell reads it." Boxes, for programmers.
  • The Compiled Code pane: the JavaScript, TypeScript or Python.
  • On the command line: spell parse, spell parse --tree, spell explain, spell describe.

What Claude was asked, and its answer · 14 lines 
Asked (Explain This's own system prompt, model haiku, no tools):
  It's from the program @spell/examples/Solitaire.
  Explain what this Spell code does:
    a card
      to check it
        the card is the queen of spades
        print its rank + "of" + its suit
        print its rank and its suit

Its answer:
  This code defines a playing card and a check that confirms the card is the queen of spades, then prints its rank and suit.
  - It defines a `card`, which has a rank and a suit.
  - The `to check it` part is a routine that can be run on a card.
  - Its first line checks that the card is the queen of spades.
  - Its second line prints the card's rank, the word "of," and its suit joined together, such as "queen of spades."
  - Its third line prints the rank and suit again, without the word "of" in between.

  • Each rule's
    • name, syntax and tests: each test a line and the JavaScript it becomes
    • purpose, the first line of its docs: 476 of 477 rules have one, in English, for programmers
    • roles: what each part is to a reader, a question, a value, a choice, an action call; 76 registrations say them, for the bubbly look
    • what its match holds: a number, a card, a list of cards
  • Each language's "Reads as" sentences, in its parser messages: a {type} has a {property} ...
  • Where each line went in the compiled code (its source marks).
  • 50 built-in steps and values, each with plain docs.
  • Not kept: the reading it passed over.
    • "Nothing reports a tie", says the parser's README: when two rules read a line equally well, the first registered wins, silently.
    • So nothing can say "this could also read as ..." today.
