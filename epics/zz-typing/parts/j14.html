The commands page (guides/dev/commands/, and any page from templates/commands.html) now builds its tables and numbers as elements, with the DOM, instead of HTML strings: commands.js makes the same <ui-section> per family, <ui-table celled compact striped unstackable> round a real <table>, <ui-statistic>s and the file:// <ui-message>, through a small el() helper (the one spell-syntax.js already uses). It still draws them before loading spell-ui.js, as before.

  • Why not a new <epic-commands src="commands.json5"> element: it would draw in its shadow root, after the runtime has started, so the page's contents bar, its sticky family titles, the tables' expand buttons and the comment bullhorns (all built from main's light-DOM sections and tables, once, at start) would not see the families. Guides also don't load the epics pack yet.
  • Every Spell UI element it needs already fits exactly, so nothing new to write.
  • Checked: the page's drawn markup, after the runtime ran, is byte-for-byte the same as before (whitespace aside: 289 rows, 302 ids, 27 bullhorns, 13 table toggles); screenshots at 1200 and 390px, light and dark, are pixel-identical; check-spell.js passes on a served copy.
  • The alternative, if a page ever needs it: an <epic-commands> that draws into its own light DOM before the runtime runs. Not worth it while the elements above fit.
