Of the Epics page's behaviour, the docs runtime keeps one thing: wireEpicSort() adds an <epic-sort> to the page header (beside New epic) when the page has an <epic-list>.

  • Why: the header is outside the markers epic pages index writes between, so the list page's header can't carry it without a migration step.
  • Gone from the runtime: wireFavorites(), regroupEpics(), wireSagaChips(), the sort buttons' own code, and their CSS in spell-doc.css (about 250 lines).
  • Kept: the section's state chips (wireItemFilters()), shared with the saga pages' item lists; the list's class="spell-epics" and each card's data-status keep them working.
