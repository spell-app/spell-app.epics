Caveats merge into todos: what happens to the caveats already written?

  • A caveat (C) today is "a limit or risk we accept"; a todo (T), "later work". In practice many caveats are todos waiting to happen ("the countdown doesn't run in airplane mode").
  • There are 441 caveats on 43 epic pages, and other pages link them by id: #c4, "C4 of claude-design".
  • Some caveats are not work, just a limit to know about ("find-in-page misses text in bodies not opened yet"): they'd become todos you might never do.
  • New pages have no Caveats section: one Todos list, each todo either "to do" or "a limit we accept".
  • Old pages: a migration turns each C item into a todo with that flag, KEEPING its id (c4 stays c4), so every link still lands.
  • "Add caveat" goes; the new todo form gets a "limit" checkbox.
  • Cost: ids in one list look mixed (T1, C4, T2); the chip shows the letter, so it reads.
  • One clean series of ids. The old id kept as an alias: a link to #c4 lands on T19.
  • Cost: every quote in chat, commits and other pages ("C4") now names something called T19; confusing for months.
  • No migration; new pages simply have no Caveats section.
  • Cost: two shapes for good, and old pages still have the sea of caveats you wanted gone.
  • the Caveats section goes; Todos holds both kinds
  • a todo can be marked "limit we accept": drawn calmer, never offered for the next phase
  • a migration step turns C items into flagged todos in place, ids unchanged
  • epic add <name>#C still works, and writes a flagged todo

Owen's direction (M3), not yet a pick:

  • The one list is called Caveats, ids C; todos fold INTO it, not caveats into todos.
  • Tests take the letter T, freed by todos (today they're V).
  • So it's a bigger id change than the options above: the 441 C ids could stay, but every T (todo) id needs a new home as a C, and every V (test) becomes a T, while "T4" in old chat, commits and pages meant a todo.
  • The options above (keep ids, renumber, old pages keep theirs) still apply, now to todos and tests as well.
