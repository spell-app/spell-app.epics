Two problems in src/tools/migrate.js, found while adding the P3 step components-not-markup:

  • pageKind() treated anything under a details/ folder as a details page, epic pages included. So the details epic's own page, epics/details/details.plan.html, was listed as a details page, and the docs steps would have run on it.
  • migratePages() ran EVERY step of a page's kind once any one step had work on that page. answer-elements reports "old script and sheet dropped" whether or not there is one. As soon as the new step made pages with tables due, a dry run said it would rewrite 20 details pages and templates that had nothing to change.

Fixed in P3, both in src/tools/migrate.js:

  • pageKind() now checks for an epic page's path (epics/<name>/<name>.plan.html) before the details/ folder. epics/details/details.plan.html is an epic page again, so no docs step runs on it.
  • migratePages() now runs a step on a page only when that step's applies() holds, checked on the page as the steps before it left it. Chains still work: answer-elements followed by engine-asset-routes on an old details page.

Checked: new cases in tests/tools/migrate.test.ts (the details epic's page and one of its details pages; a template with a table runs only the new step). yarn test: 1331 passed. A full dry run on the real content now changes 0 pages; before the fix it would have changed 20.
