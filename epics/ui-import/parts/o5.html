An element that shows code, coloured, from a file or written inline.

<ui-code language="ts" source="..." line-numbers></ui-code>
  • In its shadow root, it draws the code as highlight.js expects it: <pre><code class="hljs language-x">.
  • The colouring engine is highlight.js 11.12, in ONE lazy chunk, CodeEngine:
    • 54 kB gzipped (C15)
    • it guesses a missing language from a "detect set" of 9: ts, js, html, css, json, bash, markdown, python, yaml
    • 21 more languages are registered, used only when named
    • one chunk, because a chunk per language would split Rolldown's runtime into a file of its own (D27)
    • CodeHighlighter.engineLoader can load it some other way: the docs pages use a classic script (D26)
  • Colours: highlight.js's classes map to Spell UI colour tokens, light and dark.
    • the tokens follow the docs pages' own palette, so docs pages match
    .hljs-*     ->  --ui-code-*    (light / dark)
docs pages: --hl-*  (the same palette)
  • A page adds a language with UI.code.register(name, grammar): a highlight.js grammar, or a function from code to coloured spans.
  • Spell (D4): the one place Spell UI depends on spell, and only on a PRE-COMPILED bundle.
    • The colours come from spell's own highlighter, SP.SpellHighlighter.spans(text) (D19):
      • first a token pass
      • then a best-effort parse that refines them, by each rule's highlightAs
    • yarn gen:spell, in Spell UI, bundles it into COMMITTED files (D15, as icon packs are):
      • the bundle, spell.<lang>.bundle.js: 138 kB gzipped (C11)
      • the wrapper SpellLanguage loads, spell.<lang>.ts
      • built with esbuild, names kept (keepNames), react-dom stubbed out
      • so Spell UI builds without building spell
      • loaded lazily, the first time a page asks for it
    • language="spell" means English spell, spell/en.
      • spell/es would load Spanish
      • no such translation yet: the code stays plain, with a ui-error naming it (C7, D17)
    • Spell isn't in the detect set (C5).
  • Not an editor: editing is a later epic (D12). The content property and saving are where an editor plugs in.
