Where an element's text comes from, and what it shows while it waits.

  • The first of these that's there wins:
    1. a source="url" attribute, fetched by UI.sources.load(url)
      • it gives back the text, its ETag and its URL
      • cached per URL, as a map of promises, the way IconPacks caches
    2. a <template> child, where a raw less-than sign or ampersand is safe
    3. a <script type="text/plain"> child, or text/markdown and the like
    4. the element's own textContent
  • Inline text is dedented: the common leading indent goes, and so do blank first and last lines.
  • Same origin only: a source on another origin is an error, and nothing is fetched. 
    new URL(source, document.baseURI).origin !== location.origin
  • A page opened from disk gets its own message (C3).
  • While it loads, a <ui-loader active inline> shows; if it fails, a <ui-message state="error">.
  • Two promises:
    • host.ready still means "styled", as on every element
    • host.loaded resolves with the content
  • Changes are followed:
    • a new source fetches again, and the fetch before it is aborted
    • inline text is watched by a MutationObserver, as UIProgress.hostText does
