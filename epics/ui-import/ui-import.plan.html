Plan doc for /epic ui-import, branch ui-import Worktree: /Users/owen/www/spell-app/spell-app/.claude/worktrees/ui-import Started 2026-10-02, updated 2026-10-05 Durable doc: UI Import: include, code, markdown

Three new ui families, <ui-include>, <ui-code> and <ui-markdown>, share one loader, UI.sources, that fetches same-origin text and saves it through a pluggable saver; highlight.js, marked and a pre-compiled spell highlighter load lazily, only when used. The page server learns to save non-HTML files, so docs pages can edit what these elements show.

Kickoff prompt

Time to create some new components!
- `<ui-include>` - import a `source` URL into the current page. Assume page is from the current server, show an error message if not. Functions kinda like Astro Islands. Build in "save" hook so we can use this in an editor soon.
- `<ui-code>` - from inline contents or `source` url, render code block in specified `language` (auto-detect if not specified). We'll also want a "spell" language formatter. Build in "save" hook for this as well. I'm thinking that "highlight.js" is a good choice for functionality -- have a quick look if there is something better.
- `<ui-markdown>` - from inline contents or `source` url, render as markdown. I'm thinking we'll use the "marked.js" package for parsing (for now) -- quickly evaluate if there is something better. We will eventually add inline editing to this. Use github markdown
- Do a quick analysis of what it would take to create a markdown parser using the spell/parser. This would live as a peer to the `spell` language.
