Plain words. An icon pack or emoji name set is a page-wide thing today: UI.icons and EmojiData are ONE per page, so two <ui-icon-set>s add up. A <ui-root> in the middle of a page could set them for just its own subtree (a docs demo that wants Lucide icons beside a page that uses Font Awesome), but every icon would then have to find its nearest root.

The problem case: two roots on one page disagree.

<ui-root icons="fa7-free">...</ui-root>
<ui-root icons="fomantic">
  <ui-icon name="home"></ui-icon>
  <!-- which pack? -->
</ui-root>

theme, size and tokens are CSS and inherit, so they are per-subtree for free. Only icons, emoji and lang are in question. (lang chooses a dictionary, which renames TAGS, and customElements is one registry per document: tags cannot be per-subtree.)

Recommend A: one runtime per page, so one set of page settings. Revisit B only if a docs page needs two icon sets side by side.

Settings apply to the whole page, merged in order, like <ui-icon-set> today. A second root with a conflicting emoji or lang logs a warning (last wins). Cheapest: no change to UI.icons. 

icons="fa7-free fomantic"
<!-- adds to UI.icons -->

Each icon asks its nearest root for packs. Needs a lookup through shadow roots on every icon, and a cache per root. Isolated demos, but dictionaries still can't be per-subtree. 

<ui-root icons="lucide">
  <ui-icon name="home">
<!-- nearest root's packs -->

Icons / emoji / lang page-wide, theme / size / tokens per subtree (they inherit anyway). In code the same as A: this is A, said out loud in the docs.

Owen: a root sets its own icons / emoji for its subtree; outside any root the page-wide set applies; an inner root inherits and adds (Q14). Language stays page-wide for now. Cost: each icon finds its nearest root once when connected (microseconds); an icon moved to another root, or a root whose packs change, redraws. SVG files stay cached once per page.
