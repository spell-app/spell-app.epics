Plain words. A skeleton is a grey stand-in sized like what will replace it, so the page doesn't jump when real content arrives ("layout shift"). But before a family loads, nobody knows how big a <ui-card> will be: its real size depends on its own content (a title, an image, three lines). 

<ui-root display="skeleton">
  <ui-card>
    <ui-header>Report</ui-header>
    <ui-description>
      3 lines of text
    </ui-description>
  </ui-card>
</ui-root>

What the skeleton can see: the TAG (ui-card), its ATTRIBUTES (size="small", fluid), its child TAGS. It cannot see the real text height until fonts and styles are in. A skeleton description (3.5) gives a default size per tag, in em, so size still scales it.

Recommend A for v1; B can reuse the child tags' own descriptions later.

Fixed width / height in em from the description, plus the attributes it understands (fluid => width fill). Slotted children ignored. Some shift is accepted; authors pin with style="min-height: 12em".
