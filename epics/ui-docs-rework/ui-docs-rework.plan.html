Kickoff prompt

The Spell UI docs need some love.
- Look at `packages/brand` and make the "Spell" theme based on our brand look. Don't worry about swoops. Also read this page `https://interfaces.dev/cheat-sheet` for things to do in our theme.
- Use the spell logo for favicon (on this and all other doc sites)
- The left sidebar is really ugly. Re-work in the direction of the mockups in `brand`
- We get a FOUC when the page loads, fix that! Maybe we have to start with `<ui-root hidden>` to account for this? Suggest alternatives.
- Every time you switch pages you get a new top bar / sidebar. Instead have a "layout" page and load the contents of each actual page as a `<ui-include>`.
- On a wide screen, lose the top bar entirely. Use the Spell logo and branding in the header of the right sidebar instead. When the page is narrow, you can put back the top bar like Fomantic does.
- Make the left sidebar a `panel` like the brands "color set chooser" example.
- Use nested `<ui-section>`s for content, e.g. in "Divider" page, `Types` is <ui-section title="Types">` with content and nested <section>s within it. Make the sections collapsible. Give each section a nested ID so we can deep link, e.g. `#examples-types-emphasis`
- Many components are linked together in one folder/page, e.g. "Button" actually has "<ui-button>` and `<ui-buttons>` and `<ui-or>`. Present options for how to split this up -- one component / page per `<ui-x` widget? How does this affect complexity / download size?
- The Page title "Examples|Usage|API|Theming" tabs should be sticky.
- On the `API` tab, show an empty right sidebar so the page width doesn't jump.
- Add a search field in the top toolbar that lets you jump anyway, kinda like the Fomantic one, but pretty and in our house style. This should work across components as well as within the current page.
- Merge the theme / light / dark controls into a smaller overlay and make it pretty. Make the switch between light and dark a single icon which shows the current state, clicking it switches it.
