A tag that has its own page (e.g. the radio) is named in a pages map, on its family's entry in pages.json. The nav, search and links all follow from that. 

"ui-checkbox": {
  "title": "Checkbox",
  "summary": "A checkbox allows a user to select a value from a small set of options, often binary.",
  "status": "done",
  "pages": {
    "ui-radio": {
      "title": "Radio",
      "summary": "A radio button lets a user choose exactly one value of a group.",
      "status": "done"
    }
  }
}
  • yarn site:data copies the map to SiteFamily.pages, and gives those tags:
    • href: components/TAG.html
    • a new SiteTag.page flag: the main tag, or a sub-tag with its own page
  • The nav marks a row current by page, not main; a row shows its own page's status.
  • SiteSearchPage.mainTag became tag (the tag the page documents). The search boost a main tag got now goes to every tag with its own page.
  • A typo in pages makes site:data throw.
  • The 14 summaries were written by the overnight run: worth a read.

The overnight run recorded no other options for this one.

  • own-page tags rank like main tags in search
