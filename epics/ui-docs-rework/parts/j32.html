Links using the old flat ids (#types) still land on the right section, and the address bar then shows the new id. You'd notice it following an old bookmark or link.

  • When a hash isn't an element's id, the page tries, in order:
    1. the tab's name before the hash, for each tab: #types lands on #examples-types
    2. the first section whose id ends with the hash, an example's old slug: #vertical-divider lands on #examples-types-vertical-divider
    3. a tag of the page's family (#ui-or): the API tab, at that tag's tables
  • The address then shows the new id (history.replaceState).
  • Not mapped: 169 old header ids that weren't their header's slug.
    • #usage-basics, for "Using it", is now #usage-using-it
    • #frameworks, for "Framework usage"
    • the site isn't deployed, so only links inside the site used them
    • the 33 prose links among those were rewritten to the new ids; demo links like href="#label" were left alone

The options:

  1. Land by suffix, then rewrite the address (chosen).
  2. Keep each old id as an alias attribute in the markup.
  • old links that match a new id's ending still work
  • 169 irregular old ids are gone; no link in the site uses them
