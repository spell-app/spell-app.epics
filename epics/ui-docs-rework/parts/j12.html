<ui-include> now fires a public ui-insert event, carrying the fetched page fragment just before it goes into the page. The router needs it; you'd only meet it reading ui-include's API.

  • The router needs the fragment before it's inserted, for two jobs:
    • keep each example's authored markup BEFORE it upgrades (the example shows that markup as its code)
    • fix the links in it (the relative-links call, J14)
  • Only the include ever sees the fragment.
  • Chose a generic event over code that only the router could use.

The options:

  1. A ui-insert event (chosen): small, and reusable by anyone.
  2. The router fetches and inserts pages itself, with no ui-include: against the kickoff prompt, which asked for ui-include.
  3. Every example always wrapped in a <template>: touches every page.
  • ui-include has one more documented event
  • examples show their authored code after a page swap, and the swapped-in links work
