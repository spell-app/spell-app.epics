Each result gets a score from how well it matches, weighted by what kind of result it is. The page you're on comes first and attributes last, and each group is ordered by its best hit.

How the whole query matches the result's title, or one of its terms (a term: its tag, an aka, a topic or a page name):

Match Title Term
exact 1000 700
at the start 800 500
at a word start 600 350
inside a word 400 200
  • Or, every word of the query at a word start somewhere: 300, plus 100 per word found in the title.
  • Times a weight per kind:
    • On this page: 1.25
    • Components and Pages: 1
    • other pages' Sections: 0.9
    • Attributes: 0.8
  • Plus boosts: the main tag +20, the shown page's own attributes +40. Minus 0.5 per character of the title.
  • A match inside a word needs 3 characters: or finds Or, never every color.
  • Each group shows its best 4-6, and groups are ordered by their best hit.
  • Examples:
    • vertical on the Divider page: On this page first, then Sections, then Attributes
    • or: Components first
export const KIND_WEIGHT: Readonly<Record<SearchKind, number>> = {
  here: 1.25,
  component: 1,
  page: 1,
  section: 0.9,
  attribute: 0.8
}

The options:

  1. Groups ordered by their best hit (chosen).
  2. A fixed group order.
  3. More, or fewer, results per group.
  • the likeliest answer is on top, whichever group it's in
  • the numbers live in ui-docs-search.types.ts (SCORES, KIND_WEIGHT)

Score = how the query matches (whole query vs title: exact 1000, start 800, word start 600, inside 400; vs a term such as tag, aka, topic, page: 700 / 500 / 350 / 200; every word at a word start somewhere: 300 + 100 per word in the title) times a kind weight (On this page 1.25, Components and Pages 1, other pages' Sections 0.9, Attributes 0.8) plus boosts (main tag +20, the page shown's own attributes +40) minus 0.5 per title character. Inside-a-word matches need 3 characters (or finds Or, never every color). Groups show their best 4-6 and are ordered by their best hit. So vertical on Divider: On this page first, then Sections, then Attributes; or: Components first. Options: a fixed group order; more or fewer per group.
