Every local web server in the repo answers favicon requests, whether or not it does live reload. But only pages served with live reload get the icon's <link> tags added to them.

  • The /_server/favicon.* routes and /favicon.ico are on every SRV.WebServer:
    • the page server
    • spell serve
    • the app's API server
    • VS Code's doc preview
    • ui's StaticServer
  • The icon LINKS are injected only where live reload is, which means pages served by the page server.
  • /favicon.ico answers with the 32px PNG directly: no redirect, so one request.
  • Where /favicon.ico sits in the order a request is tried:
    • AFTER the static folders, so a folder with its own favicon.ico wins
    • BEFORE fallback, so a single-page app's catch-all doesn't answer the request with its own index.html
  • A page whose <head> links its own icon gets no injected links.
 * - requests go:  host check -> `/_server/events` and `/_server/live.js` (when `live`) -> Spell's favicon
 *   (`FAVICONS`) -> `router` -> static files -> `/favicon.ico` -> `fallback` (e.g. an SPA's `index.html`) -> 404

  • a site's own favicon.ico still wins over ours
  • a single-page app's fallback never swallows the icon request
