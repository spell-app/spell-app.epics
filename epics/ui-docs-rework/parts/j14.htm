After a page swap, the router turns every relative URL in the swapped-in content into an absolute one. Without that, links like the footer's break once you've moved to a page in another folder.

  • ui-include rewrites a relative URL only when it would point somewhere else from the current page.
  • But after pushState moves the address to another folder, the URLs it left relative break.
  • Example: the footer's ../index.html is written for a page in components/. The router resolves it against the page it came from, so it still reaches the site's home page after a swap.
  • The router does this on the include's ui-insert event (J12).
  • Examples' shown code keeps the URLs as written: ExampleSource.keep() restores the originals.

The overnight run recorded no other options for this one.

Net effect:

  • every link in a swapped-in page works from any folder
  • the code shown under an example still reads as authored
