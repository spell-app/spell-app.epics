Building the docs' bundle warns that the search element might be left out of it. If a bundler does drop it, the nav's search field would never come to life on docs pages.

  • The nav imports the search element only for its define().
  • But the UI package marks that chunk as having no side effects, so a bundler (here esbuild) may drop the import, and the search tag never defines.
  • The Spell UI site is unaffected: it loads families through ui-root.
  • Where to look: the sideEffects list in ui's package.json.
    • checked 2026-10-04: it lists the source, ./src/docs-components/*/index.ts
    • but no built ui-docs-* chunk in dist/ 
import "$/ui/docs-components/ui-docs-search"
