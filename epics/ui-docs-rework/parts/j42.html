Picking an attribute in search (e.g. ui-button › circular) takes you to that tag's tables on the API tab, not to the attribute's own row.

  • ui-docs-api gives ids only to its tag headers (#ui-or), not to attribute rows.
  • So ui-button › circular links to components/ui-button.html#ui-button: the API tab, scrolled to Button's tables. The router's landing resolves tag hashes (J32).
  • A row anchor (#ui-button-circular) would need two changes:
    • ids on ui-docs-api's rows
    • SiteSections.resolve() finding them inside its shadow root

The options:

  1. Land on the tag's header (chosen): nothing new to build.
  2. Land on the attribute's row: the two changes above.
  • an attribute result lands near its row; you scroll the rest of the way
