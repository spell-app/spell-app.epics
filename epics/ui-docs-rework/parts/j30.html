On Spell UI pages that have no Examples / Usage / API / Theming tabs, a section's id starts with its own name, e.g. #general-usage. Old links to those pages' top sections mostly keep working.

  • The pages: those with an article.site-article and no tabs:
    • getting-started, grammar, theming, utilities, icons
    • the kitchen sink
    • the component index
  • A top-level section's id is the slug of its header (its title, lower-case, words joined by dashes). Nested ones add theirs: #general-usage-descriptive-attributes.
  • The home page (site/index.html) stays as it was:
    • it's a landing page whose headers sit inside grids and segments, not straight in the article
    • the converter only reads a content root's DIRECT children

The options:

  1. The header's slug (chosen).
  2. A fixed prefix, #page-....
  3. The page's name as the prefix.

Net effect:

  • most old top-level links on those pages land as before
  • the home page has no nested sections
