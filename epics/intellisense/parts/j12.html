The same event name has different details on different tags (ui-change: 18 Spell UI tags), and other sets send ui-* names too (the brand's colour picker, epic pages). So a single global type per name would lie.

  • Each tag gets its own event map, and its element in the DOM's tag map: querySelector of a ui-button, or a JSX ref, gives an element whose addEventListener knows its events, detail exact.
  • On any other element or the document, every ui-* name still completes, but its detail is unknown: narrow it, or listen on the tag.
  • Rejected: a union of every Spell UI tag's details per name. It broke three docs-site tests that cast a docs widget's own ui-change, and would refuse the brand's and epic's details the same way.
  • Side effect: querySelector of a ui-* tag now returns an HTMLElement (with its events), not a plain Element. Three spots needed a wider type written out: the site's section unfolding, and two tests.
