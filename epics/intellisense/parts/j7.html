The editor only needs TypeScript 6 because TypeScript 7 can't load plugins yet, and Microsoft hasn't given a date. The checks themselves don't need to be a TypeScript plugin, though.

  • TypeScript 6 is already in every repo for tools that use its JavaScript API (Spell UI's declarations build, the app's component reader). So the choice is only which TypeScript the EDITOR runs.
  • A VS Code extension can add the same completions and warnings itself, for .tsx files, next to TypeScript 7's own. It reads the same manifests, and can use TypeScript 6 inside, just to read the JSX, invisibly.
  • The editor goes back to TypeScript 7 alone: your useTsgo setting is left alone, and there's no "Use Workspace Version" prompt.
  • The slot, part and dashed-attribute completions and warnings come from the extension, reusing the plugin's code from the kit.
  • It can also carry the HTML and CSS data, which fixes the duplicate tags in I9 too.
  • Where it lives: the app's existing VS Code extension, which you already rebuild with yarn vscode.
  • Cost: a new phase, about 2-3h. The tsconfig plugin lines and the TypeScript window settings go.
  • TypeScript 7 alone; the plugin's code stays in the kit, tested, unused until TypeScript 7 loads plugins.
  • You lose slot and part completion, and the dashed-attribute warning, until then.
