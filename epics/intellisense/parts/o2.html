Spell UI generates its JSX types from its vocabularies, so VS Code's own TypeScript completes, explains and checks every <ui-*> tag, with no extension.

  • Where they come from: Spell UI's ElementManifests, the class that already wrote the HTML data and the Custom Elements Manifest (J1).
    • It writes one file, spell-ui/jsx, as part of yarn site:data.
    • A test fails while the file is stale.
    • Not a new generator in the kit, as first planned: the shared value sets (hues, sizes) are Spell UI's.
    • About 23,700 lines, types only: nothing at run time.
  • Who uses them: every program that writes <ui-*> JSX, by importing the file once.
    • Spell UI itself, its docs elements and tests
    • the app, whose loose hand-written stand-in for ui-* tags is gone
    • Spell Epic
    • the spell compiler's type check of compiled spell
    • The first run caught 21 errors, one a real accessibility bug; each fix is in J10.
  • What you get, typing <ui-button in a .tsx file:
    • completion of every attribute, then of its values: size=" offers mini to massive
    • hover docs: the vocabulary's description, its values, its default
    • a red squiggle on a misspelt attribute or a value it doesn't take (Q2), except a name with a dash in it (I2)
    • rich properties by their plain name; the prop: names stay, marked deprecated, until solid-17's custom props let them go (J5, C4)
  • Events (P3):
    • in JSX, one on-ui-change prop per event, its event.detail typed per tag; it fires, since built the element's side (its P5) (J11)
    • in plain code, querySelector("ui-input") gives an element whose addEventListener() knows its events (J12)
    • on the document, each event name completes, with an unknown detail
declare module "@solidjs/web/types/jsx.js" {
  namespace JSX {
    interface IntrinsicElements {
      "ui-button": UIButtonJSXAttributes
    }
  }
}

export interface UIButtonAttributes {
  /**
   * Size, `mini` ... `massive`;  `medium` is the default.
   * - takes:  `mini` · `tiny` · `small` · `medium` · `large` · `big` · `huge` · `massive`
   */
  size?: "mini" | "tiny" | "small" | "medium" | "large" | "big" | "huge" | "massive"
  /** `size`, as the DOM element's property. */
  "prop:size"?: "mini" | "tiny" | "small" | "medium" | "large" | "big" | "huge" | "massive"
}

export interface UIInputEventMap {
  /** `ui-input`:  The value changed as someone typed (every keystroke). */
  "ui-input": CustomEvent<{ value: string; originalEvent?: Event }>
}
