The proposal: generate each element set's JSX types from its vocabularies, so VS Code's own TypeScript completes, explains and checks every custom tag, with no extension.

  • One generator, in the kit, beside the root catalog: it loads every vocabulary the way the root catalog does, and writes one declarations file per set.
    • Spell UI's 104 <ui-*> tags first (Q3)
    • its docs components, Spell Epic's <epic-*>, Spell Brand's <brand-*> and the app's four: a todo (T1)
    • run by the pack build and yarn site:data, so it never goes stale; a test fails when it has
  • What you get, typing <ui-button in a .tsx file:
    • completion of every attribute the button has, and then of its values (size=" offers mini ... massive)
    • hover docs: the vocabulary's description, its values, its default, a link to its docs page
    • a red squiggle on a misspelt attribute or a value it doesn't take (how strict: Q2)
    • rich properties as prop:options, typed
    • events: typed through the event map, so addEventListener("ui-change", ...) knows its detail; the JSX event prop (onUIChange) is 's to make work, and this epic types it (Q4)
    • a bonus outside JSX: document.querySelector("ui-button") returns a UIButton
  • Each package ships its own, one import name: spell-ui/jsx first. The app's hand-written loose stand-in for ui-* tags goes. 
declare module "@solidjs/web/types/jsx.js" {
  namespace JSX {
    interface IntrinsicElements {
      /**
       * A button people press to act.
       * - [Docs](https://.../ui-button.html)
       */
      "ui-button": UIButtonJSX
    }
  }
}

interface UIButtonJSX extends UIHostAttributes {
  /** Its size;  default `medium`. */
  size?: "mini" | "tiny" | "small" | "medium" | "large" | "big" | "huge" | "massive"
  /** Where its icon's label sits. */
  labeled?: boolean | "left" | "right"
  /** Floats `left` or `right`. */
  floated?: "left" | "right"
}
