Wherever a ui-* event is heard, event.detail is untyped.

Each event becomes a typed on-ui-change prop in JSX, and joins the event map, so addEventListener and refs are typed too.
  • addEventListener("ui-change", ...) completes the event name, and event.detail is typed, anywhere.
  • A ref's listeners are typed the same way.
  • The JSX event prop is typed, once solid-17 makes it work.

solid-17 reports Owen chose the dashed prop, on-ui-change={f}, on its own Q3 (C). It works by the element catching setAttribute("on-ui-change", f), built in solid-17's P5 · Custom Event Props. So this phase generates "on-ui-change"?: (event: CustomEvent<Detail>) => void per event, the prop list kept closed so a typo errors. No onUIChange, no twin event.
