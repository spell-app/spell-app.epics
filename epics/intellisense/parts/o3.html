What VS Code reads, file kind by file kind, once this is done.

  • JSX and TSX: the generated types, through TypeScript itself. Nothing to install, nothing to configure past one import name.
  • HTML: the HTML data files, for every set, turned on in every window, not only spell-app's (Q5).
  • CSS, if we take it: VS Code's CSS data for each set's parts (::part(group)) and custom properties (Q5).
  • Spell: out of scope; the spell language server already knows its own tags.
  • Not planned: a TypeScript language-service plugin.
    • It could do what types can't (complete slot names in slot="...", warn on a child in the wrong slot).
    • It needs an extension, and its own tests; a todo for later, if the types leave a gap we feel.
