What VS Code reads, file kind by file kind, now that this is built.

  • JSX and TSX: the generated types (1.2), through TypeScript itself. Nothing to install; a program imports spell-ui/jsx once.
  • HTML: the HTML data for Spell UI and Spell Brand, carried by the app's VS Code extension since P7, so it works in every window, once (Q5, I9).
  • CSS: VS Code's CSS data, written beside the HTML data (J14).
    • custom properties, with their defaults: Spell UI's 1,326 and the brand's 62
    • ::part() and :state() names, offered after any selector, each listing the tags that have it
  • Spell: out of scope; the spell language server already knows its own tags.
  • What types can't say: the app's VS Code extension (P7), reading each package's Custom Elements Manifest.
    • slot=" on a child completes the parent tag's slots; a misspelt one gets a warning.
    • part=" in a component's own JSX completes its parts.
    • A misspelt dashed attribute or on- event prop gets a warning, with "did you mean" (J9).
    • Which children a tag takes isn't checked: no vocabulary says (J8).
    • The checks are the kit's JsxElementHelp, plain data for any editor; the extension reads the JSX with a bundled TypeScript 6, out of sight, so the editor runs TypeScript 7 alone (J7, J17).
    • The extension also carries the HTML and CSS data, so each tag shows once per window (I9); a vocabulary change shows after yarn vscode.
    • It began as a TypeScript plugin in the kit (P5), which needed VS Code on TypeScript 6's server; P7 moved it into the extension and deleted the plugin.
