The TypeScript plugin adds what generated types can't say: which slots a parent tag has, and which parts a component exposes. How far should it go?

  • A slot: a named place in a component where a child goes. A <ui-modal> has three: header, content and actions.
  • Types know a child's slot attribute is text, but not that it sits inside a <ui-modal>, so they can't offer the modal's slot names. 
<ui-modal>
  <div slot="actoins">  // warning: ui-modal has no slot "actoins"
    <ui-button>OK</ui-button>
  </div>
</ui-modal>
  • slot=" completes the parent tag's slots, with their descriptions
  • an unknown slot name shows a warning
  • the gap we'd feel most, and the smallest plugin
  • everything in A
  • part=" in a component's own JSX completes its parts
  • checks a child's tag is allowed in its parent, where a vocabulary says so
  • more to build and test; few vocabularies say which children they take
  • no plugin for now; built when the types leave a gap we feel
  • P5 builds slot completion and the unknown-slot warning only
  • parts and children stay a todo
