Each element set needs one declarations file telling TypeScript its tags. Three ways to make it:

  • a script loads every vocabulary (as the root catalog does) and writes a .d.ts
  • hover docs: each attribute's description, as a docstring
  • shared value sets (values: "hues") become their real lists
  • works for every set, Spell Epic and the app too
  • cost: a generated file, kept fresh by the build and a test
  • no generated file: "ui-button": JSXAttributes<typeof buttonVocabulary>
  • completion and checks, but NO hover docs (descriptions are values, TypeScript can't show them)
  • shared value sets stay plain string
  • the community tool (@wc-toolkit/jsx-types) reads the manifest
  • a new dependency; only sets with a manifest (Spell UI, Spell Brand)
  • our Solid-specific shapes (prop:, the jsx.js module) need its options or a fork
  • a generator in the kit, beside the root catalog
  • one jsx.d.ts per set, shipped as spell-ui/jsx ...
