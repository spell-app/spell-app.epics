Asked for: both in spell-epic's window template. Built: the TypeScript ones only.

  • A new key in a repo's epic settings, windows.settings: VS Code settings every window file gets. The kit's .epic/config.json5 names the three TypeScript ones, with the same comments as its .vscode/settings.json.
  • spell-epic stays generic: its window code names no setting of the kit's.
  • The HTML and CSS data are a FOLDER's settings in VS Code (resource scope), so the kit's .vscode/settings.json already applies in every window the kit is a folder of, resolved from each checkout: checked in VS Code's own HTML and CSS extensions.
  • Naming them in the window file too would load the same files twice, and VS Code's HTML completion lists each tag once per file.
  • Window-file paths would also have to be absolute: VS Code resolves a window file's relative customData path from the file itself as if it were a folder.
