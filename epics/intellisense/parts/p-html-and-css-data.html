Epic windows, opened on the kit, get no HTML completion for custom tags, and no window completes ::part() or custom properties in CSS.

ElementManifests also writes VS Code's CSS data.

  • The kit's VS Code settings and spell-epic's window template name both data files.
  • Typing <ui- in an HTML file completes the tags, in every window (Q5).
  • Typing ::part( in a CSS file completes the parts, and custom properties complete too.
  • Where to see it: in any window with the kit as a folder (every epic window), <ui- in an .html file completes tags; in CSS, Spell UI's custom properties, ::part() names and :state() names complete with docs (J14).
  • Spell Brand gets the same CSS data.
  • Epic windows get the TypeScript settings through a new epic config setting, written into new window files; existing ones need epic window init after the merge (T7).
  • Watch for: a window that also has spell-app as a folder may list each tag twice (I9).
