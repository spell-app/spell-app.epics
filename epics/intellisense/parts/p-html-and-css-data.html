Epic windows, opened on the kit, get no HTML completion for custom tags, and no window completes ::part() or custom properties in CSS.

ElementManifests also writes VS Code's CSS data, for Spell UI and Spell Brand.

  • The kit's VS Code settings, and epic windows through a new epic setting, named both data files; P7 moved them into the extension.
  • Typing <ui- in an HTML file completes the tags, in every window.
  • In CSS, custom properties, ::part() and :state() names complete, with their docs (J14).
  • Where to see it: any window with the kit as a folder (every epic window).
    • In an HTML file, <ui- completes the tags.
    • In CSS, Spell UI's custom properties, part names (::part()) and state names (:state()) complete, with their docs (J14).
  • Spell Brand gets the same CSS data.
  • Epic windows get the TypeScript settings through a new epic config setting, written into new window files; existing ones need epic window init after the merge (T7).
  • Watch for: a window that also has spell-app as a folder may list each tag twice (I9).
