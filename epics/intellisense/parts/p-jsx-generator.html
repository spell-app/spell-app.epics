In a .tsx file, <ui-button sise="large"> compiles, with no completion and no hover docs.

A new generator in the kit writes Spell UI's JSX types from its vocabularies, beside the root catalog.

  • It loads the vocabularies the way the root catalog does (VocabularyFiles).
  • Spell UI ships the result under one import name, spell-ui/jsx.
  • Every <ui-*> tag completes in JSX, and hovering it shows its description and a link to its docs page.
  • Every attribute completes with its real values.
    • size=" offers its sizes, mini to massive.
    • A shared value set (hues, sizes) is its real list, not plain text.
  • Hovering an attribute shows its description and its default; aliases work too.
  • Rich properties are typed as prop:options.
  • Outside JSX, document.querySelector("ui-button") returns a UIButton.
  • The types never go stale: the pack build and yarn site:data write them, and a test fails when they are out of date.

From epic solid-17 (Owen's decision there, its Q4): our JSX drops prop:. Objects, arrays and functions given to a dashed tag go to the property. So rich properties are typed by their plain name (options), and the prop: names are kept until solid-17's custom props merge (a todo).

  • Where to see it: any .tsx file in Spell UI that imports the types (import type {} from "spell-ui/jsx"): every <ui-*> attribute completes, shows its description on hover, and a wrong name or value is red.
  • yarn site:data writes the types beside the HTML data and the manifest; a test fails while they are stale.
  • Rich properties are typed by their plain name, and as prop: until solid-17 lands (J5, T2).
  • Rough: a misspelt DASHED attribute (text-alin) is not caught: TypeScript never checks dashed names in JSX (I2).
  • The generated file is large: about 14,000 lines, 507 KB, types only.
