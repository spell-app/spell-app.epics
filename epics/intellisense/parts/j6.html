Chose a tiny CommonJS entry beside the plugin, which loads the TypeScript source through tsx (already a kit dependency), over a built JavaScript file from esbuild.

  • Why: nothing to build or keep fresh, so the plugin can never be stale; tsx compiles only the plugin's own files, scoped to that one load.
  • tsserver finds a plugin the old Node way, by its path inside the package and ignoring the package's exports, so the tsconfigs name it with src in the path: spell-kit/src/element-tools/ts-plugin/plugin.cjs. An exports entry would not help.
  • Checked end to end: the real TypeScript 6 server, opened on a Spell UI file, logged the plugin as loaded, completed a dropdown's slots and warned on a misspelt one.
