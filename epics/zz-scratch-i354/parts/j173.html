Built:

  • A thing the app holds but doesn't draw is a row inside the row of the thing that holds it (the nearest, by its stored properties or list items), muted, the eye-with-a-slash icon, still selectable.
  • It goes first among that row's rows: a hidden tag (<deck "deck" hidden />) draws nothing, so the page has no element to place it by. Solitaire writes its deck first, so it lands in document order; exact order everywhere would need the compiler to leave a marker where the hidden tag is written.
  • A thing no tag draws at all (a property holding a thing never drawn) goes the same way, under its holder, so it's still reachable now the properties card's child links are gone (I205).
  • A top-level thing nothing drawn holds: a row at the tree's top level, after the app.
