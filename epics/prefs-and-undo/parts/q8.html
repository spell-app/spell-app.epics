The ideas include a third place to keep values: the browser's database, for big values, which has to be waited on. Build it now, or later?

  • The browser's quick storage holds about 5MB per site.
  • Only the editor's static files keep big values: whole files. Today a full storage throws there, unguarded.
  • Moving them to the database makes every read of a static file waited-on, which ripples into its callers.
  • The store's waited-on form is built anyway, so a database store slots in later with no change to callers.
  • The static files move onto quick storage, as now, and a full storage is logged, not thrown.
  • No 5MB ceiling for a project's files.
  • About 1-2 hours more: the database store, and the static files' reads waited on.
  • Pref Store builds the lasting, per-tab and in-memory stores
  • a todo: the database store, and the static files onto it
