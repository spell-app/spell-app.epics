Undo and redo as Owen built them in another project: a record per change, two stacks, and changes to the same thing folded into one step.

An undo record

  • A name in a person's words, e.g. "Change Margin".
    • The Edit menu puts "Undo" or "Redo" in front of it: "Undo Change Margin".
    • Short and capitalized like a menu item: "Add Register", "Copy".
  • How to undo it, and how to redo it.
  • Optionally, the thing it changed, and any data it needs.

Two stacks

  • Undo pops the newest record off the undo stack, puts it on the redo stack, then runs its undo.
  • Redo does the reverse.
  • A new change empties the redo stack: what was undone can't be redone after something else happens.
  • An optional limit drops the oldest records once there are too many.
  • The record's undo or redo runs just after the stacks have changed, so whatever it triggers already sees the new state.
  • Both stacks are cleared on a context switch, e.g. when another document opens.

Folding changes into one step

A new record with the same name AND the same thing as the newest one doesn't go on the stack. It replaces only the newest record's redo.

  • So typing "hello" into one field is one undo step, not five.
    • Undo goes all the way back to the value before the first letter.
    • Redo goes forward to "hello".
  • A change with no thing named never folds.

The menu reads live state

  • Can undo, can redo, and the two titles ("Undo Change Margin", or just "Undo" when there's nothing).
  • They update by themselves as the stacks change, so a menu or button just shows them.

Options on any step that changes something

  • Skip undo: for a step inside a bigger sequence, which records ONE undo at its end. E.g. moving ten items is one "Move Items", not ten.
  • The undo's name.
  • The thing it changed, so it can fold (above).
  • The state before the change, so undo can put it back.
