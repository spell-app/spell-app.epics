Each one-off store in the kit, Spell UI and the editor guarded its own storage and picked its own keys.

Moved them onto PrefStore, every key byte for byte, and the editor's static files onto the browser's database; the few that can't import anything stay, saying why.

  • On the one store:
    • the site header's light / dark and per-tab edit mode (the kit)
    • Spell UI's docs-site theme, nav favourites and open topics, saved theme, and the site's section folds, each importing the store by file (J2)
    • the editor's type explorer, at spellEditor:typeExplorer, its old key moved once
  • The editor's static files in the browser's database, store spell-static: no 5MB ceiling, reset() and hasEdits() waited on, the old keys moved over once.
  • New on PrefStore, for keys named whole: splitKey(), getAt(), setAt().
  • Stay as they are, each saying why:
    • Spell UI's nag dismissals: the page author's keys, whole, with a cookie mode
    • the page server's live reload: sent to the page as text, so it can't import
    • the head scripts: they run before any module loads
  • Nobody lost a setting: checked headlessly with a viewer from before, and the tests that pin the keys pass unchanged.
  • Where to see it: the docs site, and every page with the site header. Nothing looks different, and every preference a viewer had is still there: the same keys, the same bytes.
  • Checked headlessly on the worktree's page server, with no page errors:
    • A viewer from before, their scheme under the old spell-ui-site:scheme and their favourites as the Astro site kept them:
      • the scheme moved to spell-site:scheme as dark, unquoted
      • the page went dark
      • the favourites' bytes are unchanged
    • The site header's sun / moon on a guide: one click keeps dark, raw; a reload keeps it; a second click forgets it, and the page follows the OS again.
  • The kit:
    • <spell-site-header> keeps its scheme and its per-tab edit mode in a pref store, the edit mode still as 1.
      • The old scheme keys are moved over as before.
    • New on PrefStore, for keys named whole:
      • splitKey()
      • getAt()
      • setAt()
    • The kit's server folder may now use util's persist/ folder: both AGENTS.md files say so.
  • Spell UI: these keep their values in a pref store now, each importing it by file (J2):
    • ThemePreference
    • NavPreferences
    • SavedTheme
    • the site's section folds
    DismissalStore stays, and says why: its keys are the page author's, whole, and it keeps cookies too.
  • The editor:
    • The type explorer's state moved to spellEditor:typeExplorer; its old key, spell.typeExplorer, is moved once.
    • The static build's edits are now in the browser's database, store spell-static. The ones localStorage kept are moved once, read raw, so a file's text is never read as JSON.
    • reset() and hasEdits() are now waited on, and "Reset Example" waits for the reset before it reloads.
  • Stay raw, each saying why: the live-reload client (it's sent to the page as text) and the head scripts (no imports, and they run before the page draws).
