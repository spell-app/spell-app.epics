Each one-off store in the kit, Spell UI and the editor guards its own storage and picks its own keys.

They move onto PrefStore, every key byte for byte; the editor's static files onto the database store; the few that can't import anything stay, saying why.

  • On the one store:
    • the site header's light / dark and edit mode (the kit)
    • Spell UI's docs-site theme (its head script stays), nav favourites and open topics, saved theme, and which site sections are open
    • the editor's type explorer and theme
  • The editor's static files on the browser's database: no 5MB ceiling; their reads waited on; the old keys moved over once.
  • Stay as they are, each with a one-line comment saying why:
    • Spell UI's nag dismissals: the page author's keys, Fomantic's way, with a cookie mode
    • the page server's live reload: sent to the page as text, so it can't import
    • the head scripts: they run before any module loads
  • Nobody loses a setting: the tests that pin the keys pass unchanged.
