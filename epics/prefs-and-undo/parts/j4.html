Typed defaults changed two things people see.

An unset property now reads its type's default:

  • text: ""
  • a number: 0
  • a yes / no: false
  • a one-of: its first choice

What people see change:

  • The Task List, Lista de tareas and Habit Tracker examples: their Add button now starts disabled.
    • It's disabled while the new task's draft is empty; an unset draft was nothing before, and nothing wasn't "empty".
    • Now it reads "", which is, so the button waits until something is typed. Every target (JavaScript, TypeScript, Python) draws the same: the core contract's three snapshots changed by that one word each.
  • A drawn thing's element: it still shows no attribute for a value nobody set, as before (and as HTML does: an <input> with no type is still text).
    • So a card's element doesn't grow direction="up", though card.direction reads up.
    • A declared default of its own still shows, as it did.
  • Code that tested === undefined for "not set" sees the default now.
    • The tests that did were updated, each still checking that nothing was stored.
    • A list's name reads "".
    • A mirror's unset chip value reads 0.
  • the three examples' Add buttons wait for text
  • drawn elements look as before
