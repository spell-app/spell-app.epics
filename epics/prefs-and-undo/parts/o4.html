How things stood when this epic started (2026-10-24): two pref stores in the kit, a dozen one-off ones spread around the repos, and no undo anywhere.

  • A running Spell app had no name, and no one place that every action goes through.
  • Kept as the record of what each phase changed.

Preferences

  • The kit has two pref stores, both in Spell's own corner of its util folder, which Spell UI may not import:
    • getPref() / setPref(), with one prefix for the whole page: the editor app uses them.
    • They break importing ALL of Spell's util when the browser blocks storage: the file reads storage as it loads, outside any guard.
    • AppPrefStore, a class with a prefix per app: nothing uses it.
    • Neither has a test.
  • The one-off stores each pick their own keys and guard their own storage:

  • So the keys can't change: head scripts and plain scripts read them raw.
    • e.g. spell-site:scheme holds dark, unquoted.
    • The new store's name is everything before the key's first colon, so it writes the same bytes: the site header's store, spell-site, keeps its scheme at spell-site:scheme.

Undo

  • Nothing in the repos has undo.
  • The runtime has a seed: recordingSettings() runs a function, notes each property's value before it changes, and hands back what puts them all back.
    • A while handler uses it, e.g. a card lit only while the mouse is over it.
    • It misses what's set after the function first waits, and a list's items (a card added to a pile).
export function recordingSettings(run: () => unknown): () => void {
  const outer = recording
  const changes: NonNullable<typeof recording> = []
  recording = changes
  try {
    run()
  } finally {
    recording = outer
  }
  return () => {
    for (const { target, property, was } of changes.reverse()) (target as Record<string, unknown>)[property] = was
  }
}

The runtime

  • A compiled app imports ONE library, @spell/core, which the editor's runner builds from the runtime (spell-parser's core).
  • An app is a thing with a start(). At run time it has no name; the runner knows its project's id, e.g. @owen/solitaire.
  • An action is a plain method call: onClick: () => this.increment().
    • Nothing sits between a click and the action it runs.
    • Epic 's T1 plans that one place, where undo would hook in later.
  • Every property write goes through one place (noteSetting()); a list's items don't.
  • A running app has no keyboard shortcuts.
    • Spell UI has a registry for them, UI.keyboard, with ⌘Z-style chords.
    • The runtime's view of the page's Spell UI doesn't include it yet.
  • Epic elemental-spell was still in design talk: no phases, no code. The words (Template, Action) and the syntax wait for it (Q4).
    • By this epic's end it had built its first four phases, and its Actions and Menus phase may take over how an action is declared (Q21).
