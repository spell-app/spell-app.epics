Five building phases, about 10-14 hours: one pref store, the one-off stores moved onto it, an undo stack, then both wired into the runtime. The spell syntax (remembered, undone as "Turn Card") waits for elemental-spell.

  1. Pref Store: ONE store in the kit's generic util, with nothing to import, so Spell UI can use it.
    • Three places to keep values: lasting (per site), per tab, and in memory.
    • In memory is for servers and tests, and the fallback when the browser blocks storage.
    • Read with a default, save, forget; the keys under a prefix, forget a prefix, forget all.
    • A waited-on form of each, and "read, change, save" as one step.
    • It never throws on a storage failure: it logs it.
    • The editor moves onto it; the two old stores go.
  2. Stores Move Over: the one-off stores in the table above, keys byte for byte the same.
  3. Undo Stack: the stack in the kit's generic util, reactive, so a menu shows "Undo Change Margin" by itself.
    • Records, two stacks, folding a run of the same change into one step, a limit, clearing.
  4. Undo in the Runtime: one history per app, cleared on a new run and when the app opens a document.
    • An action marked undoable records ONE step, under its name, whatever it changes.
    • Every app has undo and redo, with live titles, and ⌘Z / ⇧⌘Z while focus is in it.
  5. Remembered Properties: a property declared remembered reads and saves through the app's pref store, under its project's id.
  6. Doc Review.
const history = new UndoStack({ limit: 100 })
history.record({ title: "Change Margin", target: box, undo: () => (box.margin = 4), redo: () => (box.margin = 8) })
history.undoTitle   // "Undo Change Margin"
history.undo()      // box.margin is 4 again
history.redoTitle   // "Redo Change Margin"
