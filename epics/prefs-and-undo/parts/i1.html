The persist folder had no exports key in the kit's package, so a bundle that reached it couldn't be built.

  • Every folder barrel in the kit has an explicit exports key in its package.json, e.g. ./util/reactive and ./server/site.
    • Why: esbuild and plain tsx, from another repo, find no folder's index through the wildcard.
  • P1 added the persist folder without one.
  • P3 made the site header import spell/util/persist. The site header is bundled into the epic pages' docs bundle (spell-ui.js), so that bundle failed to build: Could not resolve "spell/util/persist".
  • Found in P4, rebuilding the docs bundle. Nothing on the pages broke: the bundle is committed, and nobody had rebuilt it.
  • Fixed in P4: the key ./util/persist, beside ./util/reactive.
  • the docs bundle builds from main again once P4 merges
