The kit has two pref stores, neither usable by Spell UI, and one throws when the page loads if the browser blocks storage.

ONE PrefStore in util's new persist folder, with nothing Spell-specific in it. The editor moves onto it; getPref() / setPref(), AppPrefStore and the storage shim they needed go.

  • One pref store every repo can use, Spell UI included: spell/util/persist/PrefStore, importing nothing outside its folder.
  • Every key that exists today keeps working, byte for byte: the store spell-site keeps scheme at spell-site:scheme.
  • Three places to keep values to start:
    • lasting, per site (the browser's local storage)
    • per tab (its session storage)
    • in memory: for servers and tests, and the fallback when the browser blocks storage
  • Values a person or a plain script can read:
    • read as JSON when they look like it: starting with ", { or [, a number such as 1, or true / false / null
    • anything else is text, e.g. dark
    • written back the same way: a string is quoted only when it would read back as something else ("1")
  • Declared prefs, with defaults: store.declare("scheme", { oneOf: ["light", "dark", "auto"] })
    • nothing saved: the first choice, light; a declared default wins; a default passed to get() wins over both
    • a saved value that isn't one of the choices reads as the default, and says so in the console
    • the defaults come from ONE helper, defaultFor(), which spell properties use too (Typed Defaults)
  • Read with a default, save (saving nothing forgets), forget, the keys under a prefix, forget a prefix, forget all of its own keys.
  • A waited-on form of each, and "read, change, save" as one step, so the database and server stores slot in (Database and Server Stores).
  • It never throws when storage fails (blocked, full, bad JSON): it logs, and answers the default. Only a caller's mistake throws, e.g. an empty key.
  • The editor's mode, tabs, line numbers and panel sizes on one store; its doubled keys (spellEditor:spellEditor.mode) moved over once.
  • WWOD's examples, util's AGENTS.md and README-util say so.
