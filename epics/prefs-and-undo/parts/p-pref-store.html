The kit had two pref stores, neither usable by Spell UI, and one threw when the page loaded if the browser blocked storage.

Added ONE PrefStore, with nothing Spell-specific in it, and moved the editor onto it. The old getPref() / setPref(), AppPrefStore and the node-storage-shim dependency are gone.

  • One pref store every repo can use, Spell UI included: spell/util/persist/PrefStore, in util's new persist folder, importing nothing outside it.
  • Every key that existed keeps working, byte for byte: a store's name is the key's part before its first colon, so the site header's store, spell-site, keeps its scheme at spell-site:scheme.
  • Three places to keep values: lasting, per site; per tab; and memory, for servers and tests, and the fallback when the browser blocks storage.
  • Values a person or a plain script can read: JSON when they look like it (a quote, a brace, a bracket, a number), anything else text, e.g. dark; a string that would read back as something else is quoted ("1"). The words true, false and null read as JSON too (J1).
  • Declared prefs: declare(key, { oneOf, type, default }), read as the declared default, else the first choice, else the type's, from ONE helper, defaultFor(), which Typed Defaults uses too.
  • Read with a default, save (saving nothing forgets), forget, the keys under a prefix, forget a prefix, forget all of its own keys.
  • A waited-on form of each, and update() as one step, tested against a stand-in: the next phase's places slot in.
  • It never throws when storage fails: blocked storage keeps values in memory for the visit, a full one logs and answers the default; only a caller's mistake throws a TypeError.
  • The editor's mode, tabs, line numbers and panel sizes on one store, editorPrefs; its doubled keys (spellEditor:spellEditor.mode) moved over once.
  • Kept out of Spell UI's core bundle (it cost 1.9 kB): Spell UI imports it by file (J2).
  • WWOD's examples, util's AGENTS.md and README-util say so.
  • Where to see it: PrefStore, in the kit's util (spell/util/persist); README-util has a new section, "PrefStore: preferences people and plain scripts can read".
  • What changed for you: the editor keeps its preferences in one store, editorPrefs.
    • Its old doubled keys move over on load: 
      spellEditor:spellEditor.mode          =>  spellEditor:mode
spellEditor:spellEditor.lineNumbers   =>  spellEditor:lineNumbers
spellEditor:spellEditor.programTab    =>  spellEditor:programTab
    • Checked headlessly on the worktree's editor: the keys moved, and no page errors.
  • Values are text you can read:
    • a string is kept as itself, e.g. dark
    • anything else as JSON, e.g. 250 or {"open":true}
    • a string that would read back as something else is quoted: the text "1" stays text
    • the words true, false and null read as JSON too (J1)
  • Declared prefs: declare(key, { oneOf, type, default }). The default is the declared one, else the first choice, else the type's (0, "", false).
  • It never throws when storage fails:
    • blocked storage (a private window) keeps values in memory for the visit, and says so once
    • a full one logs, and answers the default
    • it throws TypeError only for a caller's mistake: no key, a store name with a colon, a value its declaration doesn't allow
  • The waited-on forms are built, and tested against a stand-in:
    • load() and save()
    • update() and loadKeysUnder()
    • No real waited-on place exists until P2.
  • Not in Spell UI's core bundle: it cost every page 1.9 kB (38.12 to 39.98 kB), so Spell UI's stores will import it by file in P3 (J2).
  • Gone, with WWOD's pref-key example and util's AGENTS.md following:
    • getPref() / setPref()
    • AppPrefStore
    • the node-storage-shim dependency
