The plan left the names of an action's undo options to be settled in the phase. They are:

static { this.declareAction("turnOver", { undoneAs: "Turn Card" }) }          // ONE step: "Undo Turn Card"
static { this.declareAction("hint", { cantBeUndone: "keeps history" }) }       // left out; earlier steps stay
static { this.declareAction("newGame", { cantBeUndone: "clears history" }) }   // left out; every step forgotten
static { this.declareProp("picked", { type: "choice", undoable: false }) }     // a property left out of every step
  • An action says exactly one of undoneAs and cantBeUndone: neither, or both, is an error.
  • cantBeUndone is a mode in words, not true / false, so the call says what it does to the history.
  • A property opts out with undoable: false, beside its other declarations: a selection or a hover isn't something people undo.
  • Epic elemental-spell's Actions and Menus phase may take declareAction() over (Q21): the spell that writes these waits for it.
  • undoneAs, cantBeUndone and undoable: false are the names the runtime reads
