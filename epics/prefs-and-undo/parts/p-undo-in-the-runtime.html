A Spell app couldn't undo: actions were plain method calls, and nothing recorded what they changed.

Gave each run an undo history, UndoHistory on UndoStack, which records property and list changes; only an action declared undoable is recorded, as one transaction; every app got undo and redo, with ⌘Z / ⇧⌘Z.

  • declareAction("turnOver", { undoneAs: "Turn Card" }) makes a method ONE step, whatever it calls and however long it waits; kept as planned, a thin wrapper elemental-spell's Actions and Menus phase can take over.
  • One history per run, forgotten when the app loads saved state, and when a new run starts, a recompile included.
  • What a step keeps: each property's value before its first change and after its last; each list's items before and after, whole (J6). At most 100 steps.
  • Every property write and list change comes through ONE place, noteSetting() and noteItems(), which a while's put-back shares.
  • Left out: a property declared undoable: false (a selection); an action declared cantBeUndone: "keeps history" (a hint) or "clears history" (a new game) (names: J7).
  • Every app: undo(), redo(), and live canUndo, canRedo, undoTitle, redoTitle, in the program's language (Deshacer Turn Card).
  • ⌘Z and ⇧⌘Z through Spell UI's keyboard registry, while the app has the focus or nothing does (J8); a text field keeps its own ⌘Z, a modal its own keys; undo waits out an undoable action still running (J9).
  • The compiler writes none of it yet: the runtime is built now, the syntax waits for elemental-spell; the tests use a hand-compiled card game.
