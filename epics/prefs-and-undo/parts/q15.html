Head scripts, the syntax colourer, the live-reload client and the headless checker read some keys raw, and can't import a store. So the store writes exactly the keys they read.

  • The site header's store keeps its scheme at spell-site:scheme: the key a head script reads before the page draws.
    • That's new PrefStore("spell-site"), its key scheme.
  • Every store that moves over keeps its keys: nobody loses a setting, and nothing needs moving over (but the editor's doubled keys, P1).
  • It beat AppPrefStore's name::key, which would have changed every key.
  • the tests that pin keys pass unchanged in P3 and P4
