PROPOSALS, not decided: how the ideas in 1.1 and 1.2 could look in Spell. The open choices are on the review page.

A remembered property

  • A property marked remembered keeps its value for each person, across visits.
  • The app picks the store (the browser, or the server for a signed-in person); the property doesn't say.
// code spell
- its remembered "theme" is one of light or dark

// elemental spell
<spell-property name="theme" one-of="light, dark" remembered />

Undo that records itself

  • Spell's things are reactive, so every property change can record its own undo, with nothing written by hand.
  • Changes fold per thing and property: typing into a card's title is one step.
  • An action names its undo, so the menu says what it does: to turn it over, undone as "Turn Card":. Every change the action makes is that ONE step.
  • A block can say "one undo for all of this", for a sequence that isn't an action.

Undo and redo as built-in app actions

  • undo and redo are actions every app has, with live titles for the Edit menu.
  • Their keys (⌘Z, ⇧⌘Z) come with them.

Ties to epic elemental-spell

  • Its words: a property belongs to a Template, an action is an Action.
  • Its event model (its T1): events and actions go through one place, which is where an undo would be recorded and a shortcut would fire.

"Undo that records itself" above was a proposal. Owen chose otherwise:

  • only actions marked undoable record undo (Q2), not every property change
  • an undoable action is a TRANSACTION (Q6): what starts while it is open, waits and promise chains included, folds into its one step
