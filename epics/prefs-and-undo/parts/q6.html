When an undoable action waits partway (an animation, a fetch), which of its changes belong to its ONE undo step?

  • Spell actions can wait: Solitaire's "turn it over" waits for its flip, and dealing waits between cards.
  • The browser can't tell which waiting action a change came from, so the runtime has to pick a rule.
  • Today's recordingSettings() keeps only what's set before the first wait.
 
async deal() {
  for (const card of this.deck) {
    await this.moveCard(card, this.tableau)   // waits for the card to slide
  }
}
  • "Undo Deal" puts every card back.
  • The cost: a change something ELSE makes while it waits (a timer, a second click) joins the same step. Rare in an app one person uses.
  • The simplest: today's rule.
  • "Undo Deal" puts back only the first card.
  • Nothing joins by accident.
  • Dealing 28 cards is 28 undo steps.
  • an undoable action records from its start until its promise settles
  • another undoable action started meanwhile joins the running one's step
  • a caveat records the cost

Owen's answer, in the planning modal, 2026-10-24, in his words:

"Transaction" concept -- e.g. if we're already in the middle of an undoable action, subsequent undoable things get folded into it. This should include promise chains. Individual actions w/in transaction are not undoable separately.

OK if it's easier for you to keep them as individual "undos" under the covers, but only the "transaction" is presented to the user.

Ideally the undo is only storing the minimal set of changes for "redo" -- and sometimes things aren't undoable.

For async action, "redo" should be instantanous (maybe)

  • Closest to option A, "everything until the action finishes", plus folding what starts while it's open.
  • A transaction stays open until its work's promise settles, chains included.
  • Undoable work started while it's open (nested, or begun while it waits) joins it: never a step of its own.
  • The records may stay separate inside; a person sees one step.
  • Each record keeps the least: per thing and property, the value before the first change and after the last; for a list, what was added and taken out.
  • Undo and redo apply those values at once: nothing re-runs, nothing waits, so an async action's redo is instant.
  • "Sometimes things aren't undoable": asked as Q10.
