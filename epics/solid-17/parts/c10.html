Family DOM classes now keep their state in declared members (no field definitions, so an element defined early is set up right). But DOMElement's clash check sees only members on the prototype: a declared one named like an attribute's property isn't caught.

  • It bit once tonight: DOMLoadableElement's new load was the load attribute's property; the loadable tests failed at once, and it's openLoad now.
