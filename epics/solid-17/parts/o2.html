Nothing in our source uses an API that rc.14-rc.17 removed: the type check should pass as it is. The risks are behaviour changes that only the tests, and the pages themselves, show.

  • rc.14: only onClick (capital after on) is an event; lowercase onclick becomes a plain attribute. We have none.
  • rc.15: <Errored> and <Loading> build their fallback once; async holds "follow the reader". spell-lang's drawing has a stand-in for the old <Errored> behaviour that may now be unneeded.
  • rc.16: <For>'s keyed reconciler was rewritten (48 of our files use <For>); writes inside a cleanup are allowed.
  • rc.17: the old 1.x attribute forms (on:, attr:, use:, classList ...) are compile errors (we have none); a cleanup that throws no longer stops the others; new dev warnings for a store written outside its setter.

Our two fragile spots both still hold:

  • ShadowEvents.ts reads Solid's event-delegation internals: every one is still there in rc.17.
  • Reactive.ts's note (an effect runs on every re-run, equal value or not): still true, and now documented.

One router change to check: next.40 decodes route params, and spell-app decodes the /edit/*address param again (SpellLocation.addressForUrl()): a name with %25 in it may break.
