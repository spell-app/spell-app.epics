Nothing in our source used an API that rc.14-rc.17 removed, so the type check passed as it was. What broke was behaviour, and the tests found it.

What changed in Solid, release by release:

  • rc.14: only a name with a capital after "on" is an event (onClick); a lowercase one is a plain attribute (onclick). We had none.
  • rc.15: <Errored> and <Loading> build their fallback once; async holds "follow the reader".
  • rc.16: <For>'s keyed reconciler was rewritten (48 of our files use it); writes inside a cleanup are allowed.
  • rc.17:
    • Solid 1's attribute forms are compile errors. We had none.
      • on:
      • attr:
      • use:
      • classList ...
    • A cleanup that throws no longer stops the others.
    • New dev warnings for a store written outside its setter.

What that broke here, and how each was fixed:

  • Elements built inside an effect (I3): 270 tests failed in five repos at first.
    • Solid inserts our elements from inside an effect's callback, and the browser builds each one right there, in a fresh Solid root with no owner.
    • rc.17's dev build throws for that: PRIMITIVE_IN_EFFECT_CALLBACK.
    • Fixed by Reactive.ownRoot(): a root made under one owner of our own, which holds nothing and never goes. Every element and every detached root uses it.
  • The editor's address (I1): the router decodes route params since next.40, and spell-app decoded the /edit address again.
    • A file named with %25 in it would have opened the wrong file.
    • The second decode, SpellLocation.addressForUrl(), is gone, and a route test pins the case.
  • A broken card's stand-in (J1): <Errored> now shows it once, as the drawing around it changes.
    • So spell-lang's drawing dropped its own catch, kept for rc.13's behaviour; a new test guards the case.
  • h()'s narrower return type needed six casts in spell-lang.

Our two fragile spots both still hold:

  • ShadowEvents reads Solid's event-delegation internals: every one is still there in rc.17.
  • Reactive's note (an effect runs on every re-run, equal value or not): still true, and now documented.
