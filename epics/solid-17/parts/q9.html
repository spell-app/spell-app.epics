Today a <ui-*> tag is defined (CSS :defined, script customElements.get()) exactly when its family has loaded. P7 defines every catalog tag up front, so "defined" no longer says that: an element can be defined with no component yet. The code needs a new mark for "its component is attached".

  • Where it's read: about 30 places (J6's census), e.g. the style sheets that hide an element until it's styled: 
ui-button:not(:defined) { visibility: hidden }

A custom state on the element, set when its component is attached (on its first connect after the family loads). 

ui-button:not(:state(attached)) { visibility: hidden }

Script: el.matches(":state(attached)"), or a promise, el.attached. Named for what happened to the element.

The same, named for its family having loaded. But "loaded" already means a source file loaded on <ui-code>, <ui-markdown> (loadStatus), so two meanings.

Works in every CSS selector and in older tools, but shows in the markup and a page could write it.

  • A: :not(:state(attached)) replaces :not(:defined) in our sheets and checks; invisible in the markup.

Use `:pending` for defined-up-front-and-not-loaded and `:ready` for "ready to go"
