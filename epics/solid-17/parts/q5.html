Owen, 2026-10-22, in the modal: "both but make global patch easy to turn off for purists (e.g. setting in <ui-root>)". Built in P5; it settles I2.

  • Early definitions: <ui-root> defines every tag in its catalog before the app first draws. The component attaches when its pack loads; until then the element holds what it was given.
    • It works: Solid copies a template holding a dashed tag with document.importNode() (flag 1), so a defined tag is a real element before Solid's setAttribute() runs. h() and spreads use createElement(), the same.
    • The catalog gains each tag's watched attributes and whether it's a form control.
    • Code waiting for a tag to be defined, or styling undefined tags, waits for "component attached" instead: RootLoader, FormBinding, SlottedItems, the visual fixture, native.css, utilities.css.
  • The patch, for tags not in a catalog: Element.prototype.setAttribute patched once; only a dashed tag given a value that isn't a string, held in a side table until the element upgrades.
    • Easy to turn off: a setting on <ui-root> (an attribute, named in P5) leaves the browser's setAttribute() alone.
  • on-ui-change={f} and tree={obj} work on elements whose pack hasn't loaded, every tag covered; a page can opt out of the patch and keep only the early definitions.
