A Solid page passes everything to our elements as plain props now: an event listener, an object, a list. No prop:, no on: (P5). 

<ui-dropdown
  options={options}
  value={value()}
  on-ui-change={(event) => setValue(String(event.detail.value))}
/>
  • on-ui-change={f} listens for the element's ui-change event: "on-", then the event's own name (Q3 C).
    • On a translated tag it listens for that tag's own name for the event.
  • A function or an object, given to any other attribute, sets the element's property: options={[...]}, tree={tree} (Q4).
  • Text stays an attribute, as the browser has it.
    • So each element given text for its script API reads the attribute too: <ui-code content={markup}> (Q7).
    • A later value or open attribute sets the current value (Q6).

How it works: Solid sets a prop it doesn't know with setAttribute(), the value as it is. Our elements catch it there, through the kit's RichAttributes.

  • A defined element catches it in its own setAttribute().
  • An element whose component hasn't loaded yet is caught by a page-wide patch on the browser's setAttribute().
    • It acts only for a dashed tag not yet defined, given a function or an object.
    • It holds the value until the element connects as one of ours, then hands it over.
  • <ui-root pure> turns the patch off (Q8): then a function or object given to a tag not loaded yet becomes text, as in plain Solid.

Where it shows:

  • All 17 hand-written prop: uses are gone: Spell UI's docs and Solid check, the app's dropdowns, tree viewer and project settings, the epics' choices bar, spell-lang's Cards sample.
  • Spell UI's Solid demo uses on-ui-change in place of ref listeners.
  • Spell UI's frameworks guide shows the Solid recipe with plain props.
