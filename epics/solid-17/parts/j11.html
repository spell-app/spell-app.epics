"Maybe a parent element with descendants that aren't :ready isn't ready either?"

It could work that way. Today :state(ready) means "this element has drawn with its styles", and only <ui-root> means "everything inside is ready".

  • An element turns ready when its own first styled draw is done (markReady()). It doesn't look at the elements inside it.
  • <ui-root> is the one that waits for every element inside, nested roots included, with a timeout (5s by default) so one broken element can't hold the page back.
  • So a <ui-card> can show :state(ready) while a <ui-dropdown> in it is still loading its family. The dropdown shows :state(pending) meanwhile.
  • CSS can already ask about one case today: ui-card:has(:state(pending)) matches a card holding an element whose family hasn't loaded. It can't ask "loaded but not drawn yet".

What "deep" ready (B) would take:

  • On its first styled draw, an element would wait for each of our elements inside it (light DOM) before turning ready. Those already drawn count at once.
  • It would happen once only. An element added later, a new row in a list, wouldn't make its parent un-ready, so nothing flickers.
  • The catch is a child that never gets ready, because its family failed to load. Its parents would then wait forever, so the deep wait needs the root's timeout, or "failed counts as ready".
  • The ready promise would change meaning too. The root, the test fixtures and the docs pages await it, so they would all wait longer. That's harmless, but every test that awaits one element would now wait for its whole subtree.
  • About 20 lines in the element base, plus tests: under an hour.

:state(ready) stays about the element alone, and <ui-root> stays the "everything inside" one. Wrap a part of a page in its own root to wait for that part.

An element turns ready once it, and every one of our elements inside it at that moment, has drawn. This happens once only. A child that failed to load counts as ready, so a parent never waits forever.

:state(ready) stays about the element alone. A new state, say :state(all-ready), means the elements inside are ready too. The meaning is exact, at the cost of one more name to learn.
