What's the impact of B on performance?

B saves 1.5 KB gzipped, and costs a little on every page view instead: in Chrome, about 1 µs more per element as it starts up, about 1 MB more memory, and 1 ms more defining the tags. A stays the recommendation.

What B saves:

  • The catalog as it ships, minified and gzipped: 4.4 KB with A, 2.9 KB with B (1.3 KB before P7).
  • So A's real cost over before P7 is 3.1 KB gzipped, not 3.5: J9's numbers were the source before minifying.
  • B's one list has 353 names. Today a tag observes 5 to 48 names, 13 for a typical tag (with the four shared ones and hidden).
  • Reading the catalog's script is about 0.07 ms quicker with B.
  • Writing A's names as numbers into one shared list doesn't save anything: 4.9 KB gzipped, more than A, because gzip already shrinks the repeated names.

What B costs, measured in real browsers:

  • Starting up each element, Chrome only: what Chrome spends upgrading an element grows with the tag's observed list. That's 0.85 µs more per element: 1,000 plain elements take 0.84 ms with 13 names, 1.7 ms with 353.
  • With real elements (the kit's DOMElement, rendering), 1,000 take 16.5 ms with A and 17.6 ms with B: about 1 ms, 6%, more.
  • Most <ui-*> elements are upgraded, so most pay it:
    • a page's markup, parsed before the root defines the tags
    • Solid's templates, which it clones (measured too: 0.7 ms becomes 1.5 ms per 1,000)
    • NOT an element made with createElement(), once its tag is defined: the same either way
  • Firefox and Safari showed no clear difference here (at most 0.2 ms per 1,000).
  • Memory, Chrome: Chrome keeps a copy of the list for each tag: with B, about 10 KB more a tag, so about 1.1 MB for the 112 tags (measured on 1,120 tags, then divided by 10).
  • Defining the 112 tags, once a page: Chrome 0.3 ms with A, 1.4 ms with B; Firefox and Safari about 0 and 1 ms. Through DOMElement.defineEarly(), 0.5 ms and 1.6 to 2.0 ms.
  • The extra callbacks you asked about: writing a name the tag lacks but another tag has (size on <ui-container>) now calls the element, which returns at once. That's 255 ns more a write through DOMElement (65 ns becomes 320 ns); Firefox about 260 ns, Safari about 100 ns.
  • They're rare. None of the attributes any element can carry is in the list (class, style, id, slot, title, role, tabindex, the aria and data ones), except inputmode, which only <ui-input> declares.
  • In real markup: 9 such attributes on 24,133 <ui-*> elements in Spell UI's docs and examples, and 167 on 11,257 in the docs and epic pages.
  • 161 of those 167 are header on <ui-section>, mostly in the changelog: an old word the tag dropped in the repo split, so it does nothing today, with A or B.
  • Firefox only: every attribute write on any <ui-*> element, even class and style, takes about 40 ns more (120 ns becomes 160 ns), since Firefox searches the list name by name. Chrome and Safari don't change.

/** Bytes of `file`:  source, minified (esbuild), and each gzipped (`gzip -c`, level 6). */
function sizes(file: string) {
  const source = readFileSync(file, "utf8")
  const minified = transformSync(source, { loader: "ts", minify: true, format: "esm" }).code
  const minFile = file.replace(/\.ts$/, ".min.js")
  writeFileSync(minFile, minified)
  const gzip = (f: string) => Number(execSync(`gzip -c ${f} | wc -c`).toString().trim())
  return { raw: Buffer.byteLength(source), rawGzip: gzip(file), min: Buffer.byteLength(minified), minGzip: gzip(minFile) }
}

function* files(folder: string): Generator<string> {
  for (const name of readdirSync(folder)) {
    const file = path.join(folder, name)
    if (SKIP.test(file)) continue
    if (statSync(file).isDirectory()) yield* files(file)
    else if (/\.(html|tsx|md)$/.test(name)) yield file
  }
}

// J9:  (1) compile + run time of each minified catalog in V8 (node);  (2) a third shape for size only:
// A's per-tag lists written as numbers into one shared list.
import { execSync } from "node:child_process"
import { readFileSync, writeFileSync } from "node:fs"
import path from "node:path"
import vm from "node:vm"

const HERE = path.dirname(new URL(import.meta.url).pathname)
for (const name of ["before-P7", "A", "B"]) {
  const code = readFileSync(path.join(HERE, `${name}.catalog.min.js`), "utf8").replace(/export\s*\{[^}]*\};?/, "")
  const times: number[] = []
  for (let r = 0; r < 200; r++) {
    const t0 = performance.now()
    new vm.Script(code, { filename: `${name}-${r}.js` }).runInNewContext({})
    times.push(performance.now() - t0)
  }
  times.sort((a, b) => a - b)
  console.log(`${name}:  compile + run ${(times[100] * 1000).toFixed(0)} µs (median of 200, V8 in node)`)
}

const { ROOT_CATALOG } = await import(path.join(HERE, "A.catalog.ts"))
const union: string[] = JSON.parse(readFileSync(path.join(HERE, "union.json"), "utf8"))
const index = new Map(union.map((n, i) => [n, i]))
const entries = Object.keys(ROOT_CATALOG).sort().map((tag) => {
  const { attributes, ...rest } = ROOT_CATALOG[tag]
  return `${JSON.stringify(tag)}:${JSON.stringify({ ...rest, attributes: attributes.map((n: string) => index.get(n)) })}`
})
const file = path.join(HERE, "A-indexed.catalog.min.js")
writeFileSync(file, `const N=${JSON.stringify(union)};export const ROOT_CATALOG={${entries.join(",")}};`)
