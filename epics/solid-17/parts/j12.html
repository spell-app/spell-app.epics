What happened, from spell-app's core contract (the same program printed by every target):

before:  <ui-form debug=""><ui-repeat>...
after:   <ui-form debug="" value="[object Object]"><ui-repeat items="[object Object], [object Object], ...">
         <ui-item selected>All</ui-item>   <ui-button disabled>
  • prop: is how Solid's SERVER renderer knows to leave a property out of the HTML. A plain name becomes an attribute, so an object prints as text.
  • In a browser it's fine (RichAttributes takes the object), but an element upgrading over that server HTML would read value="[object Object]".
  • The compiler can't tell an object from text when it writes the name: it only knows the value can change.
  • One thing got BETTER: booleans (selected, disabled) now show in the server HTML, which prop: left out.
  • The change is saved, not lost: details/p8-plain-props.spell-lang.patch and .spell-app.patch beside this page (git apply in each repo).
