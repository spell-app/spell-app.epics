Four bugs the review found while compiling test programs. Each blocks this design, so the phase fixes them first.

  • A server action isn't a real action (I101): so after completing a job is never run, cancel has nothing to stop, and the Inspector doesn't list it.
  • if that fails under a server action empties it (I102): the action compiles to nothing.
  • The place's action line above the type makes a loose action (I103): complete the job then doesn't read.
  • A second to complete a job silently replaces the server's (I104): no call, no warning.

Spell has no word for dropping an error. cancel is different: in a before step it stops the call before anything is sent, puts back what the steps changed, and skips the after steps; no failure step sees it. nevermind is in a failure step, after the call failed, and stops the error going further.
