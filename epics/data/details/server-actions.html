A job API. A button on a page runs complete job 6251. Steps around it in the API file, the app's file and the page.

	its "status" is text

after completing a job

		nevermind

	alert "Job done"

when any server call fails
	if the error is "not authorized"
		show the sign in menu
	otherwise if the error is "offline"
		alert "You're offline:  try again soon"
	otherwise
		do nothing
 
a "jobs page" is a page
	its "busy note" is text

while completing a job
	set the busy note to "Completing ..."

if completing a job fails
	if the error is "not permitted"
		alert "You can't complete jobs"
	otherwise
		pass the error

What runs, in order

  1. complete job 6251: job 6251 is read first, unless it's held, so every step has the job. Missing: the failure path, as "not found".
  2. The page's while completing a job sets the busy note. A page's before and during steps run only while it's shown.
  3. The API file's before completing a job: cancel stops it, nothing is sent, and what the steps changed is put back.
  4. The call: POST /api/jobs/6251/complete, its braces filled, its method from the description.
  5. The afters, nearest the call first: the API file's sets the status, then the app's says "Job done", then the page's, which run even if the person has left the page.
  6. The busy note is put back, whether the call worked or failed.

When it fails

  1. The API file's failure step first: a matching branch catches it; "not found" is dropped with nevermind.
  2. Then the app's, then the page's: the page catches "not permitted", and pass the error sends the rest on.
  3. Then when any server call fails, last: "not authorized" shows the sign in menu, with no word needed to end the branch; otherwise do nothing keeps Spell's notice away.
  4. Spell's notice shows only for what nobody caught. if that fails means if the error is anything.

The error names

The error is When Spanish
"not found" no such thing "no encontrado"
"not authorized" not signed in "sin autorizar"
"not permitted" signed in, not allowed "no permitido"
"out of date" someone changed it first "desactualizado"
"server not found" the place isn't there "servidor no encontrado"
"limit" too many rows, or asked too often "límite"
"offline" no network "sin conexión"
"anything" every error "cualquiera"

What happens when the button is pressed, in order

# Where The Spell What it does Today
1 the page complete job 6251 Starts the action. A parse error: a bare id isn't a form yet. complete job "6251" compiles, but reads "6251" as a NAME, in memory only. Choice 2.1.
2 Spell (nothing written) Reads job 6251 from the place first, if it isn't held, so the job is there for every step below. Missing: the failure path, as "not found". the job whose id is 6251 reads it, but a missing one crashes. Choice 2.2.
3 the page before a job is completed Shows "Completing ...". Outermost, so it runs first. Refused: only after completing a job exists, and no before. Choice 3.1.
4 the API file cancel if the job's status is "done" Stops it: nothing is sent, and step 3's change is put back. cancel exists and does exactly this for an action.
5 Spell (the call) POST /api/jobs/6251/complete, the id filled in. Fills no braces, always POST: P49 fixes it. A server action isn't a real action yet (bug, below).
6 the API file after a job is completed Sets the status. Innermost after, so first. Spell's word is after completing a job; the passive form is refused.
7 the app's file alert "Job done" Tells the person. Today the API file and the app's file are ONE level, run in file order. Choice 4.1.
8 the page set the busy note to "" Clears the note. Outermost after, so last. A page's step today runs on every page, not only while it's shown. Choice 4.2.

When the call fails

# Where The Spell What it does Today
F1 the API file when a job can't be completed Sees the error first: innermost. when plus words is an EVENT: this compiles to on("a-job-can") and a parse error. Choice 3.2.
F2 the API file if the error is "not found" → nevermind Drops it: nothing more runs, no notice. Compares the error to text, always false. nevermind doesn't exist. Choices 5.1, 5.3.
F3 the page otherwise if the error is "not authorized" Any other error went on out to the page, which catches this one. "not authorized" is no kind: a place says "refused", and why. Choices 5.1, 5.2.
F4 the page alert "Not logged in", show the login dialog Asks the person to sign in. alert exists; Spell says "sign in" (show the sign in menu), not "login".
F5 Spell (nothing written) An error no step caught reaches the person as a notice. A refused change already shows its own notice, "Couldn't save your change ...", with Retry. Choice 5.5.

Your first way, an action that wraps the call with call the server inside, does the same as these steps, written in one place: choice 3.3.

Four bugs the review found while compiling test programs. Each blocks this design, so the phase fixes them first.

  • A server action isn't a real action (I101): so after completing a job is never run, cancel has nothing to stop, and the Inspector doesn't list it.
  • if that fails under a server action empties it (I102): the action compiles to nothing.
  • The place's action line above the type makes a loose action (I103): complete the job then doesn't read.
  • A second to complete a job silently replaces the server's (I104): no call, no warning.
