Guard asks for a token only on writes elsewhere. Here reads need it too, because a read can spend a key. The recipe box's page is served by the page server, on another port, so it can't know this run's token: the demo's server uses DemoGuard, with a fixed token and any local page. That's only fine because it holds no keys and a throwaway folder. A stale token counts as no answer, so a change waits for the reload instead of being dropped.
