• The ingest: an object whose keys are all codes (two to four letters, one case: EUR, fra) and whose values are all text, or things of the same fields, is a list: its "currencies" is a list of currencies, a "currency" is a thing: its "code" is text, its "name" is text, its "symbol" is text.
  • Codes that differ from row to row, or four or more: a thing's few fields, the same in every row ({ lat, lng }), stay its fields. So REST Countries' demonyms, { eng, fra } in every row, stays a thing with an eng and a fra (an issue of its own).
  • "languages": { "fra": "French" }: a language's code and name.
  • The core reads such an object as that list wherever a list of things with a code is declared, no line needed, as lists side by side are (J192): the key in code, a plain value in the type's one other field.
  • Read as the first translation in its translations where its code is "fra".
  • Not a field name chosen by order (the first field): swapping two lines would change what's read.
