It compiles to core.removeWhere() on the read's scratch list: the list changes, the place doesn't, and nothing says so. for one in every favourite where ...: remove one from the favourites works (core.removeSaved()), and is what PokéSpell says.

details

Removing favourites with a where takes them out of a copy the program read, never out of the database on this device: the next read brings them all back, and the heart stays red. Two rules can say "remove", and only one of them knows about places.

  • The one that works, ListRemove (remove one from the favourites):
    • it asks "is the list every thing of a saved type?"; yes, so it compiles to core.removeSaved(one)
    • that takes the row out of its place, and records an undo step
    • it also refuses to compile for a read-only place
  • The one that doesn't, ListRemoveWhere (remove favourites in every favourite where ...):
    • it never asks that question: it always compiles to core.removeWhere(list, test)
    • core.removeWhere() is a plain list helper: it filters, then takes the matches out of that list object
    • the list is what core.savedThings() answered, the read's own list, so the place never hears of it
    • no read-only check either, so a web server's things "remove" too, silently
  • PokéSpell's heart (in its love it action) says the loop instead, so the example works today.

removeWhere<T = unknown>(collection?: CollectionOf<T>, condition?: CollectionIterationCallback<NoInfer<T>>): void {
  if (!assert.isDefined(collection, "core.removeWhere(collection)")) return
  const itemsToRemove = core.filter(collection, condition)
  if (core.isArrayLike(collection)) core.remove(collection, ...(itemsToRemove as unknown[]))
  else core.removeItemsAt(collection, ...Object.keys(itemsToRemove as object))
}

`remove favourites in every favourite where its address is address` could also be written `remove favourites in every favourite with address`?

Not today: Spell has no every favourite with address. It would be a new, short way to write a filter, and it fits a word Spell already has.

  • with already means "this field, set to the value of the same name" when making a thing: a new favourite with address sets its address to address.
  • So every favourite with address reading as every favourite where its address is address keeps one meaning for with: the field named, matching the value of that name.
  • It would work only where the word is BOTH a field of the type and a value in reach (a parameter, a local); anything else stays an error naming both.
  • Spanish: cada favorito con dirección, the same way.
  • Several at once, as a new takes them: every favourite with address and name.
