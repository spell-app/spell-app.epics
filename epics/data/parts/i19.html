Declarations don't carry savedIn or a place's kind, so in the importing project every recipe compiles to core.everyThing(): what's in memory, not what's in the place. No built-in project does this yet.

A project's declarations will say where its types are saved, so another project that imports one treats it as saved.

  • A place's type will say its name, its kind and, when it matters, its folder and what the compiler asks of its lines (searches, how often it's checked, which collections are found only by name or a search, read only).
  • A line like a recipe is saved in the family cookbook will say so in the declarations too: the type, the place, the collection.
  • Importing a saved type will bring its place along, as a type brings the types it depends on. A saved type whose place came from a third project still counts as saved, with nothing known about the place.
  • So in the importing project every recipe reads from the place, and add, remove, the warnings and refusals act as they do in the project that declared it. In English and Spanish, for JavaScript, TypeScript and Python.
  • Only new optional fields, so older declarations still load and no version bump: an older library's types stay in memory until it's compiled again.
