The core contract run of Star Wars timed out at 60s, and it would have asked real servers from a test anyway. So a project file can say "readsOtherPeoplesServers": true, and the contract leaves it out; its compiled snapshots are still checked. Why that run doesn't end isn't found. spell run itself is fine: it serves the app.

Found it: a place's check timer was keeping the run alive, for 16 hours. Nothing was stuck.

  • Star Wars says check it once a day at 5am, so the run set a timer for 59,594,819 milliseconds, which is 16.5 hours, and node waits for every timer before it ends. The fetches had all finished by 3.6 seconds; at 45 seconds it was still waiting on that one timer, so it never printed the page.
  • The fix: a check timer never keeps a program running by itself (pollWhileVisible()). Star Wars then finishes in 6.5 seconds, the 5 of them it holds its first reads.
  • The contract no longer asks anybody's server: a run can be offline (RunSpec.offline), every request failing at once without leaving the machine. So what each program prints is what it shows when it can't reach its servers, and readsOtherPeoplesServers goes, with all six examples back in the contract.
