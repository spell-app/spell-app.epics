I106 names an inside type after its schema whenever the spec gives one, as the issue's fix said, not only when owner + field words collide. So NetBox's whole spec now writes 37 types like 'tag summary', 'owner summary', 'device summary' (a list of BriefTag is 'a list of tag summaries', was 'a list of tags'). The other way: use the schema's name only when the field's own words are taken or too long -- fewer renames, but the names then say less about what they hold.
