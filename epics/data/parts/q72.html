For P50 · Server Actions. Owen: "what happens if you call complete job 6251 and there is no job record in memory -- my collection/app/page logic really wants to have a job available to it. Maybe we'd load the record if it is not in memory before starting all of that?"

P50 reads the job first, before any before step, so the job is there at every level. The fork is a job the program already holds. 

complete job 6251
completar trabajo 6251

before completing a job
	cancel if the job's status is "done"      <- read from the held copy, or fresh?
  • A: the held copy is used, and read only when it's missing. No extra request, and the place already keeps held things fresh by checking.
  • B: always read again, so the before steps see the server's latest. One more request on every call.
  • Ambiguity: with A, a before step can cancel on a status that changed on the server a moment ago.
