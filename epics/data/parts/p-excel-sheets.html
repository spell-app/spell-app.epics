  • Reads and writes, in a browser and in node; the most used, and still kept up.
  • Apache 2.0.
  • Its npm copy is stuck at 0.18.5 (2022), with two known security holes; the current one (0.20.x) installs from SheetJS's own site, a link in package.json rather than a version number.
  • Roughly 300 KB minified for its small build (900 KB full), loaded only by a page that reads a workbook.
  • The free edition drops cell colours and fonts on a save; values, formulas, other sheets and widths stay.
  • Reads and writes, browser and node; MIT; on npm.

  • About 1 MB in a browser.
  • Small, MIT, both released this year (9.3.14, 2026-10-29).
  • Two libraries: one reads, the other writes a NEW workbook from rows.
  • So a save would lose the other sheets, formulas and formatting: not a write "as a CSV's".
  1. Ask first: no dependency goes in until Owen picks one in this phase's Choices (WWOD's "Ask before adding a dependency"). Recommended: SheetJS (A).
  2. The reader: an Excel workbook read into the same rows a CSV gives, so SheetTable's id column, rows with no id and notes work unchanged.
    • a spreadsheet at "recipes.xlsx" reads Excel because the address ends in .xlsx; a .csv stays a CSV (Q31, A).
    • an excel file at "recipes.xlsx" names a workbook outright, whatever its ending (Q31, B): the same reader, the same SheetTable rows, the same writes.
    • Each sheet of the workbook is a collection, named by its tab; one tab alone answers any name, as a CSV does.
    • Numbers and dates come out as the cells hold them; text stays text.
    • The library is loaded only when a page reads a workbook, so no other program grows.
  3. Writes, as a CSV's: behind the place server only, beside CsvPlace.
    • The same rules: a row's version is a hash of its cells, a stale one is refused, no id column means adds only.
    • Saved under the file's lock, all at once.
    • A save keeps the other sheets, unknown columns, formulas and column widths; cell colours and fonts are lost (the free SheetJS drops styles), which the save's answer says.
  4. The ingest: spell ingest on an .xlsx address looks at the workbook: one collection per sheet, its header row as the fields, as it does a CSV.
  5. An example: Recipe Box gains a recipes.xlsx and one more commented line, family cookbook is a spreadsheet at "recipes.xlsx", beside its data folder and room lines, and a second, family cookbook is an excel file at "recipes.xlsx".
  6. Tests: reading (several sheets, an empty one, dates, numbers, a blank row), the place (writes, a stale version, no id), the compiler picking Excel by the ending, the new an excel file at kind in English and Spanish compiling to the same place, the ingest.
