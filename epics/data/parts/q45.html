For P49 · OpenAPI Ingest. The request asks that the state (unverified, untyped, verified, failed, disabled) show in .api.spell too, as a keyword or a standard trailing comment, so a reader and the compiler can tell spec-only lines from tried ones. 

acme is a web server at "https://dev.acme.test/service/v1"
	jobs live at "/api/jobs"            // verified 2026-11-17 on dev
	invoices live at "/api/invoices"    // not tried yet

	jobs live at "/api/jobs", not tried yet      <- a new word on the line
  • The ambiguity: a comment is for people, and the compiler never reads one, so only a word lets the compiler tell. A word on every line (not tried yet) reads as part of what the line says, and could clash with a name.
  • Recommended: a comment the tool writes and rewrites, the state itself kept in .api.json5; only disabled needs the compiler (next question).
