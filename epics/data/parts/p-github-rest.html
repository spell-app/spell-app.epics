  2. The token. GitHub works without one, at 60 requests an hour; when GITHUB_TOKEN is set in the environment, the core sends it, and the Spell says so. The key is never written into the Spell or its description; GitHub takes it as a Bearer key, so the ingest and the core send it the way they already do.
  3. Paging by the Link header. GitHub says where the next page is in a header, not in the answer. The ingest sees it and writes a line saying so; the core follows it, page by page, as it already follows a next page named in the answer.
  4. Rate limits. GitHub names what is left in its headers (how many requests remain, and when that resets). The ingest reads politely within them; the core waits, or says how long until it can read again, instead of failing with a bare 403.
