A set on a Thing goes nowhere beyond the page, and nothing recovers when a place says no or a message is lost.

  • An action's changes show at once and go out when it ends, so cancelling an unfinished action really drops them.
  • Live by default; a draft holds its changes until saved, for an Edit screen with a Cancel button.
  • A sent change that gets no answer resends with the same id until the outcome is known, and pending changes survive closing the tab.
  • Undo drops a change not yet sent, and sends a reversing one once it has gone.
  • A refused change heals back to the place's copy, with a notice anywhere in the app: Retry, or Show me.
  • Try it: nothing to see yet. Tests drive a place that fails, refuses and loses answers on purpose.
  • Every property write becomes a pending change, shown at once.
  • One heal routine: fetch the latest, replay what's pending.
  • Writes go out when the action ends, and cancelling drops them.
  1. PendingChanges: per field, each with a change id, in the order made, saved on the device.
  2. Hear writes at noteSetting() and list changes at writeItems(), doing nothing at all for a thing with no place, so no existing program changes.
  3. Browser-made ids for a new saved thing: read how Thing.id is made, and what happens when it's unique only on this page.
  4. A step that groups an action's changes, on UndoStack's transactions. The connection to language's core.runAction() comes with the words.
  5. PlaceHeal: fetch, replay, on opening, on a refusal and on demand. Reading your own write works because pending changes sit on top of what's read.
  6. Drafts: a draft of a thing keeps its changes apart until it's saved. A failed write raises one event the app shows as a notice.
  7. Checked by: tests with a place that refuses, fails and swallows answers; offline then back; undo before and after sending; a draft cancelled.
  8. Left out: other people, which is The Referee; the four cases that end stable but wrong, which need the compiler.
