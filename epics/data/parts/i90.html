A read by id (the user whose id is ...) that fails shows the row cached from an earlier search, rather than saying it failed.

  • Seen on GitHub's person page during a rate limit: it drew the search result (login and avatar, no counts, no bio), not the person, and no failure.
  • So the page can't tell the reader the full read failed, or to try again.

Net effect (once fixed):

  • a failed read by id shows its failure (and the example's quiet "try again" line), even when a cached row exists
