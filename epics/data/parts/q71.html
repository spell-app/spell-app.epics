For P50 · Server Actions. Owen: "cancel will abort". With the page's before running first, then the collection's, a cancel in the collection's comes after the page's has run. 

// the page
before completing a job
	set the busy note to "Completing ..."

// the API file
before completing a job
	cancel if the job's status is "done"
  • A: nothing is sent, and no after or failure steps run. What the page's before did stays, as with an action's cancel today, and one Undo takes it back.
  • B: as A, and the failure steps run, with the error saying it was cancelled, so the page can tidy up its busy note.
  • C: as A, and what the befores changed is put back by itself.
  • Ambiguity: A leaves the page's busy note up; B makes a cancel look like a failure.
