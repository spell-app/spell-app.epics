Found building P30's JSONPlaceholder page: <comment><content>...</comment> in a drawing compiles to a comment, so the drawing is empty, and lint says nothing. The page names it in full, <ui-comment>, and says why. Worth either a warning, or another short name for Spell UI's comment.

In spellml, <comment> is Spell's own comment tag, and it means that inside a drawing too. So a drawing that tries to draw Spell UI's comment by its short name draws nothing, and nothing says why.

  • Found building the JSONPlaceholder page (P30): each post's comments drew as empty boxes.
  • Everywhere else in a drawing, a bare name is a component's: <button> draws <ui-button>. Only Spell's own tag words win over that, and comment is one of them.
  • What a person sees: an empty drawing. No error, no lint warning; the whole <content> block under it became the comment's text.
  • The same trap waits for <description> written straight under <draw>: it's Spell's long description there. Inside markup (as the page now writes it, under <ui-comment><content>) both are markup, as they should be. 
<!-- drew nothing:  a comment, its text the four lines under it -->
<draw>
	<comment>
		<content>
			<author>{its email}</author>
			<description>{its body}</description>
		</content>
	</comment>
</draw>

<!-- now:  named in full -->
<draw>
	<ui-comment>
		<content> ... </content>
	</ui-comment>
</draw>
 
  private isTagHere(word: TagWord, indent: number): boolean {
    const owner = this.ownerOfTag(indent, word)
    // in a notebook's body, a drawing:  a word spellx doesn't know is markup, `<section>`, `<example>` (P16)
    if (isNotebook(owner)) return word.category !== "unknown"
    if (!owner || owner.category === "template") return true
    if (owner.category === "note" || owner.category === "code") return false
    if (word.category === "code" && word.kind === "html") return this.isInDrawing()
    // its actions, and the menus inside it:  sub-menus (epic `language` P19)
    if (owner.kind === "menu" && word.category === "declaration" && (word.kind === "action" || word.kind === "menu"))
      return true
    if (word.category === "control" && isForSlot(word.kind)) return owner.kind === "for each"
    if (word.category === "note" || word.category === "control") return true
    return word.category === "declaration" && word.kind === "draw" && this.isInDrawing()
  }
  • A note (comment, description, property-editor) is taken as spellx's in a drawing, then readTag() reads everything up to </comment> as its prose.
  • The tokenizer can already say what's wrong with a tag (spellx-mismatched-closer ...), each message a key in the language's parser messages.
  • A <comment> or <description> in a drawing whose text starts with a tag gets a message on its line: "In a drawing, <comment> is a comment, and draws nothing; for Spell UI's comment, write <ui-comment>".
  • A real comment in a drawing, plain words, is untouched.
  • Cost: about 10 lines in readTag()'s note branch, a key in English's and Spanish's parser messages (comentario too), a test in the spellx tokenizer's tests.
  • Read a note in a drawing as markup when its text is tags: <comment> then draws <ui-comment>.
  • Cost: about 15 lines, and the spellx writer has to write it back the same way.
  • But one word means two things by what's inside it: a commented-out piece of drawing would start drawing.
  • Spell UI gives <ui-comment> a second bare name a drawing can use (<remark>, say).
  • Cost: Spell UI's vocabulary, its docs page, and every language's word for it.
  • But <comment> still draws nothing, silently: the trap stays for whoever tries the obvious name.
  • <comment><content>... in a drawing compiles with a message naming <ui-comment>, in the editor and in spell lint.
  • The same for <description> straight under a drawing.
  • The JSONPlaceholder page keeps <ui-comment>, and its note about why can stay or shorten.
