Two people on one place can overwrite each other with nobody noticing, and nothing brings their screens back together.

  • This epic owns shared data and the one referee; epic crdt keeps the running-program mirror and the text library comparison, building on this.
  • No Yjs: long text is a plain field, the last save wins, and the losing text is kept with a notice.
  • Adds, removes, reorders and additions to a number each behave as the Overview's table says, and a delete of what someone's editing offers Restore.
  • A dropped connection, a missed change or a bug all heal through the same routine.
  • Airtable can run behind it, for people using the Spell app.
  • Try it: open the recipe box demo in two windows on a live room, and edit the same recipe at once.
  • One referee per shared space puts changes in order, and the last to arrive wins per field.
  • Everyone's screen is the referee's copy, with their own pending changes on top.
  1. Read StateMirror first, and say in the phase's notes whether the referee grows from it. It sends whole things with counted ids, which the Overview says isn't enough, so it may share only the JSON's shape and the in-place read Reads And Cancelling already took.
  2. Referee: orders changes, gives each a sequence number, keeps a log with snapshots replacing what's old, over the kit's own webSocket.ts, on any place as its store. That code drops what a page sends, reading frames only to answer a close, so reading them is new work here, and the pages it pushes to today stay as they are.
  3. LiveRoomPlace: sends pending changes, hears others, and heals on opening, reconnecting, a gap in the numbers, a periodic checksum and a refusal. Its socket is one small reconnecting socket in util, which ThemePreference moves onto instead of keeping its copy. liveClient is left standalone, since it's sent to pages by itself.
  4. Positions in a list as a parent and a fraction, and additions sent as additions. A named action can re-run on the referee: the compiler's choice of which comes with the words.
  5. The losing text kept and offered in a notice (J1). A change says what it had seen, so an old offline edit can be noticed.
  6. Checked by: tests that shuffle and drop messages and require everyone to end the same, and a measured time to heal on one machine.
  7. Left out: per-person rules (a room trusts everyone in it, and says so); who hosts it, which is The Cloud; Yjs.
