Ingesting NetBox's whole spec (version 4.7.5, with --no-ai, P49's step 1) wrote 138 of its 143 lists, in 80 seconds, and needed up to 60 compile rounds. The other 5 were left out because of how the ingest names an inside type.

  • Left out: front_port_templates, rear_port_templates, module_bays, module_bay_templates, module_types.
  • Also lost: the 13 label fields NetBox's small "value and label" objects have, to Spell's built-in Speed.

An inside type is a type the ingest makes for an object a field holds, rather than a list of its own. NetBox's module bay holds a list of objects in module_bay_types, so the Spell gets a type for one of them.

  • Its name is the field's words, one of it: module bay types => module bay type (insideTypeFor()).
  • But module bay type is already the name of one of NetBox's lists' types, so it puts the owner's name in front: module bay + module bay type.
  • The three lists that hold one (module bays, module bay templates, module types) each get their own: module bay module bay type, module bay template module bay type, module type module bay type.
  • Port templates the same way: front port template rear port, rear port template front port.

Those names don't compile. The same lines in a tiny file, with only the types they name, give this:

a "module bay" is a thing
	its "name" is text
	its "module bay types" is a list of module bay module bay types

a "module bay type" is a thing
	its "name" is text

a "module bay module bay type" is a thing
	its "name" is text

3:27 Don't understand "a list of module bay module bay types"
8:0 Don't understand "a "module bay module bay type" is a thing"
9:1 "it" and "its" mean a type only in its outline, indented under e.g. "a card is a thing where:"
  • Spell reads a type's name by the names it knows, so a name with another type's whole name inside it trips it.
  • Not every such name: front port rear port, NetBox's front port's inside type, compiles fine. Why one does and the other doesn't isn't traced.

"Left out" means the whole list is gone, not one field. The compile step (compileLeavingOut()) drops each line that fails, and a type's first line failing drops the list it belongs to.

  • So someone using the place has no module bays, no module types, no front or rear port templates: no type, no lives at line, nothing to read or write.
  • The description keeps them, each with why it was left out, in its notes.

Found writing this: the compile step finds a failing line by its TEXT, so it can take the wrong one. The first line anywhere in the file with the same words is the one left out.

  • The orphaned field lines under a dropped type (its "url" is text, its "name" is text ...) took real fields from other lists: device types lost manufacturer, object types description, scripts name, circuit group assignments url and display, connected devices position, and a circuit group assignment tag its id and slug: 8 fields.
  • The Speed errors below did the same, one round at a time.

The Speed collision is a different name problem. NetBox's console ports send their speed as a small object, written in place in the spec, with no name of its own: 

"speed": { "type": "object", "properties": {
  "value": { "enum": [1200, 2400, 4800, 9600, ...], "type": "integer" },
  "label": { "enum": ["1200 bps", "2400 bps", ...], "type": "string" } } }
  • Its inside type is called speed. That's a name Spell already has, a measure like km/h, but the check for Spell's own names (isSpellsOwnType()) doesn't count measures, so the owner isn't put in front.
  • Compiling a "speed" is a thing with its fields says Can't add "value" to Speed: it's built in, and every project shares it, and the same for label.
  • Matched by text, its "label" is text was left out of 13 other small types first: priority, status, kind, face, airflow, distance unit, length unit, action, profile ... Each kept only its value.
  • In the end a "speed" is a thing is written empty, and its "speed" is a speed means Spell's Speed, not NetBox's.

The fix: name an inside type after its schema, when the spec gives it one, instead of owner + field words. NetBox's field already points at a named schema: module_bay_types is a list of BriefModuleBayType. 

schema                    today                                 after
BriefModuleBayType        module bay module bay type   (x3)     module bay type summary   (one, shared)
FrontPortTemplateMapping  front port template rear port         front port template mapping
RearPortTemplateMapping   rear port template front port         rear port template mapping
FrontPortMapping          front port rear port                  front port mapping
  • "Brief" is NetBox's word for the short form of a thing, so it reads as "summary"; the three lists share one type, as the spec does.
  • The speed object has no schema name, so this fix doesn't reach it. It also needs Spell's measures counted as Spell's own names, giving console port speed (not in the old text: a suggestion).
  • Finding the failing line by where it is, not by its words, would stop a failure taking other lists' fields (also a suggestion).
  • NetBox's 5 missing lists come back (143 of 143), with names that say what they are: module bay type summary, not module bay module bay type.
  • With the measure check and the line-by-place fix too: the 13 label fields and the 8 fields taken from other lists come back, and a console port's speed is NetBox's, not Spell's.
