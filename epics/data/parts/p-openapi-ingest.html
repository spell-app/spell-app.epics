  • Owen, 2026-11-17, a request from another team writing its own OpenAPI converter: “new phase from another process”. Their aim: Spell does the whole job, so their converter can go away.
  • The whole spec is read: every path, method, parameter, request body and response, its $refs resolved; types and fields come from the schemas (required, enums, nested objects, lists, dates, ids), not sample rows. No cap on characters or collections when the spec is the source. Rows in a field other than items (a search's results) are found from the schema. Each type and field links back to its schema.
  • Trust, then verify: every collection, field and write carries a state in .api.json5 (unverified, untyped, verified with date and server, failed with status and reason, disabled), and the Spell shows which lines were tried. spell place verify <file> [--server dev] reads each list and each thing by its id, fills an untyped collection's fields from what it reads, and marks each read; it never writes unless asked. A disabled collection or write compiles, and refuses when it runs, saying why.
  • Writes come from the spec: adding, changing and removing per collection, unverified until tried; action routes with path parameters (POST /api/jobs/{id}/complete); request bodies typed from their schemas. --try-writes per collection, and only on a server marked safe for writes: never production.
  • No real data in checked-in files: real values left out of .api.json5, or kept in a folder outside the repo; the site data panel's sample rows read live or from that folder.
  • One place, several servers (dev, staging, production), each with its own address (a path prefix too) and its own key, picked when running without editing the file, each marked read only or safe for writes.
  • A sign-in that renews itself: a short-lived token minted from an API key at a token service (one per server), cached, and renewed before it runs out, so pages don't go empty when a pasted token expires.
  • spell place update on a place made from a spec re-reads the spec, adds what's new, marks what's gone, and keeps hand edits and verification states: no cut back to 12 collections.
  • A large API splits across several files by its tags while staying one place; a source can be marked internal, and its routes that only forward to another API already ingested are left out.
  • A readable reference for a place, from its spec and its verification states: routes, types and fields, what's verified.
  • Everything here is checked on a made-up API, @acme's: never a real company's name or data.
