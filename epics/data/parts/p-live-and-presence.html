People can't yet say that a list stays up to date, can't see who else is there, and aren't told when something changes under them.

  • A place with no announcements stays up to date with it is checked every 30 seconds.
  • A program can react with when a recipe changes: and when someone else changes it:, the parser trap handled, and can refresh the recipes.
  • Seeing who's there is the cheapest conflict tool, so a program can show them.
  • Something changed while you were editing gets a plain default notice.
  • Try it: open the recipe box in two windows, and see each other there.
  • Words for keeping up: a poll time, reacting to a change, refreshing.
  • Words for other people: the current person, the people here.
  1. The bullet for a poll time, on pollWhileVisible(), the compile warning it answers, through SpellWarnings, and refresh, which is recargar in Spanish since actualizar means a version upgrade.
  2. when a recipe changes: reaches further than when its X changes. when someone else changes it: gets a higher priority and a test.
  3. the current person from the place's identity, and the people here from the referee's room. On a file it's only you; on AT Protocol it means something different, which the AT Protocol phase, later, spells out.
  4. A default notice for a change under an open form, and the recipe box example using all of it.
  5. Checked by: compiled tests, and two headless pages.
  6. Left out: cursors; per-person rules.
