Nothing stops a read when nobody wants it any more, and a place that can't filter has no safe fallback.

  • Two parts reading one list share one request.
  • Moving to another page aborts what only that page was reading, and a search as you type lets the newest win.
  • A place with no filter still answers a filtered read, by loading pages in the browser, up to a limit, then a clear error.
  • Things come back as real Things, one object per id, and a refresh changes them in place, so what draws them redraws and undo isn't forgotten.
  • Try it: nothing to see yet. The tests show a read aborted by leaving, shared by two readers, and stopped at the ceiling.
  • A read lasts as long as something shows it, and the last reader leaving aborts it.
  • What a place can't do, the engine does, up to a ceiling.
  1. PlaceReads: counted sharing per collection and query, each read with its own abort controller, the last reader leaving aborts it, and about ten released results kept for a quick return. Check LoadOnce first: it sits above util, so move it down if it fits, and don't write a second one.
  2. PlaceQuery: what the place didn't handle is filtered, sorted or sliced here, with a ceiling in rows and bytes that ends in a thrown error naming the place.
  3. Newest wins for a read given a key, the shape Spell UI's request helper already has.
  4. places.ts in core: rows into Things. A new id is made with the existing Loader's entry reading, which stays synchronous. A known id is changed in place, the way StateMirror.read() does it, and never through Loader.load(), which forgets the undo history and hands a known thing back unchanged. Refreshes and heals take this path, with what they read marked as reading, so it doesn't come back as a write (J11).
  5. A read inside a memo aborts through onCleanup(), as the Overview's Solid check found.
  6. Checked by: tests for sharing, abort on leaving, newest wins, the ceiling, and one Thing per id, against the memory place with a slow wrapper, plus a refresh that changes a known Thing and keeps its undo history.
  7. Left out: writes; live updates; how this behaves across thousands of things, which is measured in Gathering Reads.
