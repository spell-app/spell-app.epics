Signing in from anywhere but 127.0.0.1 needs /oauth-client-metadata.json on that address. atProtoClientMetadata() makes its contents; no command writes it, and no page says so until signing in fails. Also not tried: signing in from inside the editor's preview, where the redirect would leave the editor.

Spell's cloud answers the file by itself, one per program, so publishing a program there needs no extra step.

  • The cloud is the one place programs get a real address today, many of them on one address.
  • One file can't serve them: it would have to list every program's page, and a sign-in comes back to the first one listed. So each program gets its own, beside its page: /apps/<program>/oauth-client-metadata.json.
  • The cloud's program page tells the sign-in where that file is.
  • A host reads the file with no sign-in, so it's answered for every name in an org's shared space, there or not: a stranger still can't find out what an org has.
  • A program on any other real address (your own host) still needs the file at the top of its address. If it isn't there, the sign-in now says which address it couldn't read, instead of the library's own words.
  • No new command: nothing else puts a program on a real address yet.
