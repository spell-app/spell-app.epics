No public API mints a short-lived token from an API key at a token service. So the tests run a small local server, in the kit's tests, as the earlier ingest phases' stand-ins are:

  • a token service that mints a short-lived token from a key id and secret, so renewing it can be tested in seconds
  • a second server for NetBox's description, answering from saved answers, marked as taking writes, beside the live demo: so picking a server, and refusing writes on one that's read only, are tested with no network

Writes and action routes are tried for real on NetBox's demo, its data reset nightly. The tests that run in CI use the saved answers only.
