A CSV can only be read, except through the demo's test servers.

  • Saving changes only the lines that changed: an added row, a moved row, an edited cell. The rest of the file stays byte for byte, so a diff in git or VS Code shows just that.
  • With an id column, a row is matched by its id, so an edit and a move at once are both understood.
  • With no id column, rows are matched by their whole text: an added or moved row is found, but an edited row reads as one removed and one added. Saving a change to a row with no id says so.
  • The file changed since it was read: merged per row and field with what's there, as a refused save is; a clash gets the usual notice.
  • Columns the program doesn't know are kept, as are the file's quoting and line endings.
  • A CSV behind the place server takes writes, saved by comparing new rows with old.
  • The compiler lets a program write to a CSV with a server in front.
  1. Keeping every byte: parseCsv() keeps each line's raw cells and line end; a new CsvFile (spell/util/places) compares new rows with old: by id, or by whole text with a longest-common-subsequence, and rewrites only the lines that differ. Checked in tests/util/places: quoted cells, embedded newlines and commas, CRLF, no last newline, unknown columns, a BOM.
  2. The place: a new CsvPlace (spell/server/places): read, apply() under the file's lock and all at once, a row's version as a hash of its content, a stale version refused so the engine merges per field; a half-saved, non-UTF-8 or unclear file refuses and says so; no id: inserts and a whole-list save only, a change says why not. A file's order reaches a program as a position field, so a move is what a live room's move is.
  3. The compiler: no new word: a sheet whose address is a place server (/api/places/...) is written through RemotePlace; a plain address stays refused. Parser tests, and a compiled program writing a row.
  4. The demo: RecipeFile stands on CsvPlace, its own writer and hash gone; /api/places/recipes-csv serves the file; the sheet frame on all-back-ends writes and moves, with its text rewritten; bundle rebuilt.
  5. Checked: the gates, then headless Playwright on my own port: add, move, edit, remove, with the file's real diff after each.

Left out: a whole-list save merging with a file changed underneath (it says out of date); a move made from an old copy lands by position, not re-checked; watching the file (it polls); Google Sheets are untouched.
