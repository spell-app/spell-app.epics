The people Spell is for already keep their data in spreadsheets, and those have no stable keys, no filter and tight limits.

  • Sheet or CSV is one of the seven back-ends, chosen because it tests the hard gaps together.
  • A CSV file works read only. The author names a key column, or its rows share no identity, and Spell says so.
  • A Google Sheet reads, and writes through the server side, within its rate limits.
  • Try it: change the demo's one line to a CSV file, then to your own Google Sheet.
  • A sheet place: CSV is read only with an author-named key, a Google Sheet goes further.
  • It's the hardest test of the interface's optional parts.
  1. Read the coherence catalog first for a CSV reader; none showed up in the code. If there's none, a small csv.ts for quoted fields, with no dependency. Util can't reach the parser's tokenizer, so this is one small copy under the catalog's Reading text, listed there with that reason.
  2. SheetPlace: rows, a stated id column, column names as fields, filtered in the browser up to the ceiling.
  3. GoogleSheetPlace behind the place server, checked against Google's own docs as it's written, since the survey didn't read them closely.
  4. RateQueue, here because this is the first place with a limit: one queue per named limit, waiting as a 429 says. It lifts retryAfter() and backoffFor() out of claudeRunners into util, and that file uses them from there. Polling is pollWhileVisible(), from REST And GraphQL.
  5. Checked by: tests with rows that have no key, a duplicate key, an edited sheet found by polling, and a limit hit.
  6. Left out: Excel files; other spreadsheets; formulas.
