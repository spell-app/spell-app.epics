A PLACE is where data lives: Spell's word for a back-end.

Every place answers one small interface and says what else it can do, and the engine covers the rest, the same way for all of them. This is a design from the survey, and nobody has built it.

What a place must do

  • Required: say what it can do, and list the items of a collection.
  • Optional: get several by key, apply changes, run a named operation, watch for changes, and report what changed since a token.
  • It says what it handled: a list comes back naming which of the filter, the sort and the selection the place did itself. 
interface Place {
  describe(): Capabilities
  list(collection, query: { filter?, sort?, select?, page? }, ctx: { signal }):
    Promise<{ rows, nextPage?, version?, handled: { filter?, sort?, select? } }>

  // Everything below is optional.
  getMany?(collection, keys, select, ctx): Promise<Row[]>
  apply?(changes, ctx: { identity }): Promise<{ rows, version? }>
  call?(name, input, select, ctx): Promise<unknown>
  watch?(target, onEvent): () => void
  changesSince?(token): Promise<{ rows, removed, token }>
}

interface Capabilities {
  keyOf                      // a key field, or none:  "don't share identity"
  filter, sort, select       // what it does natively, per field if need be
  page:   "none" | "offset" | "cursor" | "range"
  write:  "none" | ("insert" | "update" | "delete")[]
  atomic: boolean            // many changes, all or nothing
  live:   "none" | "poll" | "notify" | "push"
  rateLimit?, abort          // abort "soft":  we only ignore the answer
}

What the engine does instead

Missing The engine Does it say so?
Get several lists with a filter, or pages until found a note while developing
Filter, sort loads pages and filters in the browser, up to a ceiling a compile note; an error over the ceiling
Select fetches everything, then hides the rest no
Paging loads everything once, then slices a note over the ceiling
Live polls, and compares by key no: live just means slower
Write nothing: the compiler refuses, "this data is read only" an error at compile time
All or nothing sends one at a time, and puts back what's unsent on a failure a note
Key keeps rows inside their list, with no shared identity a note
  • The ceiling: filtering a 2 GB file in the browser looks exactly like asking a server. So a place's fallback has a limit in rows or bytes, then a compile note, then an error.
  • One cache, by type and id: two parts showing one recipe show one thing, so an edit appears in both. Saved things already have this shape (Person#owen).
  • Results say what they know: still waiting, complete, or from an earlier visit, in plain words, and changes show as saving, saved or couldn't save.
  • Adapters stay small: whoever writes a new kind of place writes a mapping and a list of capabilities, never a cache or a retry.

What it reuses

The coherence review found much of this already in the repo, so the plan builds on these, and doesn't rewrite them.

  • PrefPlace: today's swappable places, for preferences, key and value only, never throwing (Q4). It also gives the word "place".
  • SpaceStorage: read, write, list, remove and watch by path: nearly the file system place as it stands.
  • Loadable: loaded, failed, unsaved and cancelling state. Reused instead of a third kind of load state, though it holds one resource and not many.
  • UI.api: URL templates and a newer request replacing an older one, the shape cancelling needs. The REST place uses its behaviour, with no fourth fetch client.
  • Sources: a shared load per URL, a reader's signal aborting only its own wait, and saving with a version check.
  • EpicParts and LoadableBody: a list of summaries, each body in its own file, fetched on open. The chunked files place wraps these.
  • Saver and Loader: how a thing and its references become entries by type and id. The plug-in point is synchronous today, so it has to learn to wait.

No GraphQL client exists, so that place is new.
