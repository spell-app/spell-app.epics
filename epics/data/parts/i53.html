fieldsNeverFilled(), in the cli's placeIngest, compares each value with a new thing's, so locked and site admin, false on every row read, are noted as never filled. So are PokéSpell's baby, legendary, mythical.

After it writes a place's Spell, the ingest reads a page of rows through it, and lists each field no row filled: a hint that the line naming it may be wrong. It decides "filled" by comparing each value with a brand-new thing's, so a yes/no field that is no on every row it read looks the same as one the server never sent.

  • What a person sees: the description's notes say a field was never filled, when the server sent it on every row.
    • GitHub: locked on issues, site admin on users and contributors.
    • PokéSpell: baby, legendary, mythical, gender differences, forms switchable on the first page of species.
  • So the real notes (a list the server leaves empty, a field it never sends) are hidden among wrong ones.
  • The same comparison catches a number that is 0 on every row, and text that is always empty: the same trap, not seen yet. 
/** Each field `Class` declares that all of `things` left at its usual value. */
function fieldsNeverFilled(Class: new () => unknown, things: readonly unknown[]): string[] {
  if (!things.length) return []
  const usual = new Class() as Record<string, unknown>
  const isFilled = (value: unknown, field: string) => {
    if (value instanceof Date) return true
    if (value && typeof value === "object" && "items" in value) return (value.items as unknown[]).length > 0
    return value !== usual[field] && value !== undefined
  }
  return [...schemaOf(Class).declared.keys()].filter(
    // only looking:  a field holding an address isn't following it
    (field) =>
      !things.some((thing) =>
        isFilled(
          whileOnlyShowing(() => (thing as Record<string, unknown>)[field]),
          field
        )
      )
  )
}
  • The wrong line: value !== usual[field]. A new thing's yes/no reads as false, its type's default, and so does a row's "locked": false.
  • The reactive engine already tells the two apart: a value a row SET is stored on the thing, a default is not. peekProp() reads only what's stored.
  • A field is filled when some row stored a value in it that isn't nothing (null), read with peekProp().
  • A yes/no that's always no, a count that's always 0, text that's always empty: all filled, as the server sent them.
  • A field the server left out, or sent as null: still noted, as now.
  • Lists and dates keep their own checks.
  • Cost: about 5 lines in fieldsNeverFilled(), one test in the ingest's tests (a yes/no that's false on every row isn't noted), then spell place update on GitHub, PokéSpell and Open Library. That last step leaves the old notes in place until the fix for keeping old notes (I54) lands too.
  • Skip every yes/no field in the check.
  • Cost: one line.
  • But a yes/no the server really never sends goes unsaid, and a number always 0 is still noted wrongly.
  • Keep the check, but word a field that's always its default differently: "Every row read said no to issue's locked".
  • Cost: about 10 lines, and a second kind of note to read.
  • True, but noise: no is a fine answer, and nothing needs doing about it.
  • "No row read filled ..." means the server sent nothing there, never "it said no".
  • GitHub's descriptions lose 3 wrong notes (locked, two site admins), PokéSpell's 5 or so, once each is looked at again.
  • A count that's always 0, or text always empty, can't be noted wrongly later.
