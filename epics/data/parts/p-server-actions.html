A server action can be called by its id (complete job 7151), shows on its type with its parameters listed under it, and takes more than one parameter.

Steps can run before it, after it, and when it fails, from the API file, the app's file or one page, stacking around the server call.

  1. After P49, which fills an action's braces (Api.url()), sends its method from the description, lists its parameters in .api.json5, and says which operations are enabled.
  2. Calling by id, the job read first (Q65, Q72): complete job 7151 reads the job by its id, as the job whose id is already does, BEFORE any before step, so the job is there at every level. A job already held is used or read again, as Q72 decides. If the read fails, nothing is sent: the failure steps run with that error ("not found" for a missing job), the job is nothing there, and the error carries the id.
  3. Several parameters (Q64): each brace and body field filled from the action's blanks, then the thing's own fields, then with values; what's left goes in the body. core.callPlace() takes them all.
  4. The action's lines (Q66, Q67): its parameters under its is at line, the action shown on its type, both written by the ingest.
  5. Steps around it (Q68): a before and a failure hook join today's after hook (AfterHook, core.addAfterHook(), runActing()), from any file; cancel is today's.
  6. The wrapping action (Q69): the server action's words with no address, call the server inside, if that fails to catch; the same hooks underneath, so both ways stack.
  7. Errors (Q73, Q74, Q75, Q76): the error has a kind made from what places already throw (a place's not found and refused, the 401, 403, offline and 412 errors), matched by if the error is "...". A failure step stops what it handles, nevermind drops it, and the rest passes out a level at a time, then to today's notice. A mistake in the program's own steps never reaches a failure step.
  8. Stacking and cancel (Q70, Q71): page outermost, then the app's file, then the API file, around callPlace(), one undo step for all. cancel stops the call before it's sent; nevermind stops an error after it failed.
