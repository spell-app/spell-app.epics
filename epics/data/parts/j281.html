P52's plan named an element, <place-reference src=...>, in the app's components, with a page the page server serves. Built instead as a Solid page in the editor, /place/<description address> (PlaceReference.tsx), served by the page server's editor, linked from the Data tab's Reference button. Why: the element route touches the element build (vite.code.config entry), the component pack's catalog (element.build.test pins it), an App UI docs page and pages.json5, and a static page loading Spell UI by hand -- about twice the work and build risk, for a page only the editor links to tonight. What it would take to turn it into the element later: move PlaceReference into app/src/app/components/place-reference/ with a vocabulary (src attribute), add the entry to vite.code.config.ts, re-pin the pack catalog in element.build.test.ts, add app/docs/place-reference.html. The drawing code moves as is.
