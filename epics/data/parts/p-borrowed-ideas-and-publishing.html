The plan now starts with that review, and stops there until you agree. Here's what I found on user@org. It's a comparison, with nothing decided.

Spell address Saved thing AT Protocol
Example owen@spell/hello/hello.spell Person#matt@three-degrees at://did:plc:abc/com.example.recipe/r-12
Who owen@spell: a person at an organization not a who: after the @ is where it's kept an account, the same everywhere
What's next a project, then a path to a file a type a collection, which is a schema, not an app
Last part a file or folder an id a record key
  • Same: both start with who owns it, and a person has their own space.
  • Different "who": owen@spell only means something inside Spell, and it's fixed today: a machine has one person, whatever their name. An AT Protocol account is global, and moves between hosts.
  • Different middle: a Spell address goes through a project, and an AT Protocol address goes straight to a type shared by every app. A chunked place's "collection" could be either.
  • No match for an organization: @spell has no AT Protocol equivalent. An org would just be another account.
  • Worth watching: saved references already use the same @ differently. In Person#matt@three-degrees the part after it is a place: saving's own word for where a thing is kept. So Person#owen@spell reads as id owen at place spell, not as the person owen@spell, though the two line up for people.

Could user@org be the "who" for a place? On a folder or chunked place it plausibly could, since those files already sit in that person's space. AT Protocol would need something linking the two, such as the person's own file naming their account.

Open for the later design:

  1. Is a chunked address's "who" user@org, and is it there at all for a place that isn't a person's?

  3. Does saving's place, in Person#matt@three-degrees, become this epic's place? It's already the same word.
  4. Where does a person's AT Protocol account get recorded?
