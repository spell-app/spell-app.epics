I140: PlaceSpec reads a list as paging by offset when its GET takes a limit-like and an offset-like query parameter (limit, page_size, per_page / offset, skip, start), else when its wrapped answer has those fields. The place's line is the existing one, its next page is asked for with "limit" and "offset", for the pair most lists use; it gives up to N at a time is the smallest maximum their limits' schemas say, so a read never asks for more than FastAPI takes (a 422). The paging line is place-wide (RestPlace pages every collection one way): a list that pages otherwise is asked with them too.
