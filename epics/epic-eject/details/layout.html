In a worktree-only window (the worktree's code plus the pages folder, no main checkout: see 1.2), the Claude panel lists only sessions saved under the window's first folder. How do you still see, and open, every session of spell-app from any window?

Each option walks through the same three moments, in order: (1) starting a session, (2) finding it later from another window, (3) moving it to a new window. The example is a new epic, dark-mode.

None of these is tested yet: the test run on a throwaway worktree comes first.

Step by step

  1. Starting: You type /epic dark-mode. spell-epic makes the worktree and, in the same step, makes the worktree's session folder a LINK to main's.
  2. The new window opens: the worktree first, the pages folder second. The session starts in the code.
  3. Claude saves it under the worktree's folder, which is the link, so the file lands in main's folder with all the others.
  4. The code's AGENTS.md and CLAUDE.md load, the shell starts in the worktree, and the skills work, all as they would in main.
  5. Finding it later: In any other window (main's, or another worktree's), the Claude panel lists dark-mode: every window's first folder leads to the same session folder. You click it.
  6. Moving it to a new window: A session started in main's window that then moves into a worktree (as /isolate does) is already listed in the new window. The handoff opens it there.

The catch

  • Untested. Claude might replace the link with a real folder (it renames old files .superseded-*).
  • Claude's auto mode once refused to copy session files, calling it "transcript tampering".
  • Opening a session from a window whose folder isn't the one it started in (step 6) needs a try.

Where on disk should spell-epic put a worktree: a second copy of the code, on its own branch, made for one epic?

  • It makes worktrees for ANY repo, so this is its default; a repo's config can change it.

Each option walks through (1) making one, (2) working in it, (3) finishing the branch and cleaning up.

~/www/spell-app/spell-app.worktrees/<name>. Nothing nests inside main's folder, so no tool reaches up into main's copy by accident.

What you'd see

~/www/spell-app/
  spell-app/              main's checkout
  spell-app.worktrees/
    dark-mode/            the worktree: the code, on branch dark-mode
  spell-epic/
  spell-app-epics/

Step by step

  1. Making one: /epic dark-mode: the worktree appears in spell-app.worktrees/.
  2. Working: A tool missing from the worktree fails out loud. Today it silently runs main's copy, and yarn reads main's settings, because the worktree sits inside main's folder.
  3. Finishing: The branch merges into main; git worktree remove deletes the folder. spell-app.worktrees/ stays, empty when no epic runs.

The catch: about 33 files assume .claude/worktrees and change. Worktrees already running finish where they are.

spell-epic/worktrees/spell-app/<name>: every repo's worktrees in one place.

Step by step

  1. Making one: The worktree appears inside the engine's folder.
  2. Working: As A: nothing nests inside main.
  3. Finishing: git worktree remove deletes it from the engine's folder.

The catch: product code inside the tooling repo's folder. spell-epic's git must ignore it, and reinstalling the engine must never touch it.

  1. Making one: The worktree appears beside the epic's plan doc.
  2. Working: The pages repo, its page server and the epics index must all skip code/.

The catch: the skipping above, and an epic saved for later (not planned yet) has no code at all.

spell-app/.claude/worktrees/<name>. No paths change.

  • The place is a setting in each repo's spell-epic config.
  • Worktrees already running finish in .claude/worktrees/.
