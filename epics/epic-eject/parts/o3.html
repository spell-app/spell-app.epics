Worktrees move OUT of the repo, so a worktree window holds just the worktree and the shared content: no main root, no duplicate files.

  • Where: beside the repo, ../spell-app.worktrees/<name> (Q3). The kit's worktree hook makes them.
  • A worktree window has two folders: the worktree, then the shared-content repo.
    • No main root, so Quick Open and Find show each file once.
    • One repo in Source Control.
    • The window's settings are the worktree's own.
  • Finding sessions: the kit's VS Code extension adds a Sessions view, listing every session of the repo, from every worktree (Q4).
    • It reads every worktree's saved-session folder, the way the session command already scans them (sessions.ts).
    • It opens a session with the Claude panel's own command.
  • What goes away:
    • the root-first trick (O1)
    • the .spell-main marker
    • the worktree branch of the window script's file hiding
    • VS Code's git.detectWorktrees setting in package windows

The catch: opening, from the Claude panel, a session saved under another folder is untested. The papercuts log warns that a stand-in folder broke the handoff once. The build's first phase tries it out before anything is moved.
