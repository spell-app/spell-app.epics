Worktrees live OUT of the repo, so a worktree window holds just the worktree and the content folder: no main checkout, no duplicate files. Owen chose this layout on the layout page.

On in spell-app since 2026-10-18 (P8): built in spell-epic with every part off by default, then turned on in spell-app's config (C24), and its idle worktrees moved (C25).

  • Where: beside the repo, ../spell-app.worktrees/<name> (Q3), when the config's worktrees folder points there. spell-epic's worktree hook makes them.
    • Worktrees left in the old place, .claude/worktrees, keep working until their /isolate done: every tool reads both places (J26).
    • epic worktree path <name> says where one is; epic worktree move moves an idle one.
  • A worktree-only window has two folders: ⎇ <name>, then the content folder.
    • No main checkout, so Quick Open and Find show each file once.
    • One repo in Source Control.
    • The window's settings are the worktree's own.
  • Finding sessions: the worktree hook LINKS each new worktree's saved-session folder to main's (Q4).
    • Claude Code then saves every session in one place, whichever folder it started in.
    • So every window's Claude panel lists every session, without main in the window.
  • Packages first: a worktree beside the repo can't borrow main's packages, so the worktree hook runs the repo's install command before it hands the worktree over, and before any window opens (I2).
  • Coming back to the right folder (I3):
    • Every skill enters a worktree with Claude's EnterWorktree, never by starting in its folder: only then does Claude Code bring a reopened session back to its worktree.
    • A session-start guard tells a session that comes back elsewhere, or starts in a worktree unrecorded, to enter it.
    • The Claude panel's own reopen can't be fixed from here (I8).
  • epic shared rename spell-app.epics renames the content folder, leaving a link at the old name for old paths and running sessions (C23).
  • What went away:
    • the root-first trick (the duplicate files, above)
    • the .spell-main marker
    • the worktree branch of the window script's file hiding
    • VS Code's git.detectWorktrees setting in package windows
