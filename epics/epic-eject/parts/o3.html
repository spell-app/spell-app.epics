Worktrees move OUT of the repo, so a worktree window holds just the worktree and the content folder: no main checkout, no duplicate files. Owen chose this layout on the layout page.

  • Where: beside the repo, ../spell-app.worktrees/<name> (Q3). spell-epic's worktree hook makes them.
  • A worktree-only window has two folders: ⎇ <name>, then the content folder.
    • No main checkout, so Quick Open and Find show each file once.
    • One repo in Source Control.
    • The window's settings are the worktree's own.
  • Finding sessions: each worktree's saved-session folder is LINKED to main's (Q4).
    • Claude Code then saves every session in one place, whichever folder it started in.
    • So every window's Claude panel lists every session, without main in the window.
  • A worktree beside the repo can't borrow main's packages, so it needs its own yarn install before its window opens (I2). The worktree hook runs the repo's install command first.
  • What goes away:
    • the root-first trick (the duplicate files, above)
    • the .spell-main marker
    • the worktree branch of the window script's file hiding
    • VS Code's git.detectWorktrees setting in package windows

The layout test run so far

  2. The window's Claude panel lists main's sessions. Yes.
  3. A session started there shows in main's window: saved through the link into main's folder, and the link survived. Yes.
