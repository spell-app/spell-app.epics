EpicConfig.contentOf(checkout) is the config's contentFolder only when the config FILE exists and the folder is there; otherwise the checkout itself (a test's scratch checkout, a repo with no content repo yet, a config that won't read). So contentOf() of the content folder is the content folder (it holds no config), and classes handed either a checkout or a content folder agree. Without the file check, a scratch checkout would read the DEFAULT ../spell-app-dev whenever that happened to exist beside it.
