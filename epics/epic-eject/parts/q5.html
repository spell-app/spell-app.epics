How should the Epic Kit get spell's packages: Spell UI, the page server and the page assembler?

  • The plan-doc pages are drawn with Spell UI, and the kit's page server is built on spell's server package. Depending on spell is fine (kickoff prompt).
  • A file: or portal: dependency is yarn's way to use a package straight from a folder on disk, instead of from npm.
  • What's at stake: how a Spell UI change reaches the plan-doc pages, and what a release of the kit needs.
  • The kit depends on the packages in spell-app's MAIN checkout, by folder.
  • A Spell UI change on main reaches the kit at its next build.
  • At release, publish @spell-app/ui and the others to npm, and point the kit there.
  • The catch: until then, the kit only works on a machine with a spell-app checkout beside it.
  • Commit the plan-doc script and the Spell UI bundle into the kit.
  • The kit runs anywhere, with no spell-app checkout.
  • The catch: rebuilt by hand whenever Spell UI changes, and a 2.3 MB bundle in the kit's history each time.
  • The kit's package.json points at ../spell-app/packages/... for spell's three packages.
  • Publishing them to npm becomes a release-time task.
