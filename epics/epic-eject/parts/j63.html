• The content folder answers /worktrees/<w>/... AFTER that worktree's own files, for every <w> (a new Mount.skip option on StaticHandler: drop the first folder, sorted after the other mounts at /worktrees/ whenever mounted). Side effect: /worktrees/<any name>/epics/... serves the shared page even for a name no worktree has.
  • A content page's SPELL_SERVER.file is its path in the content folder, /epics/x/x.plan.html, from / AND from /worktrees/w/: the page editor saves it there, and the / change event matches it. Its badge still says worktree w (from the address).
  • Each content change is ALSO reported at every worktree's served path (<worktreesPath><w>/...), so a worktree-addressed page's styles and scripts from the content folder hot-reload; the page gets a second, harmless spell-server:file event for its own file.
