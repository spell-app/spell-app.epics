Where should new worktrees go: beside the repo, or inside it as today?

  • Today they're inside the main checkout, in .claude/worktrees/<name>. That nesting is why a worktree can quietly use main's tools and packages: node and yarn, looking for something missing, climb up into main's folder.
  • What's at stake: whether one-folder windows (O3) are clean, and whether a worktree ever runs main's code by accident.
  • In ../spell-app.worktrees/<name>, made by the kit's worktree hook.
  • Nothing nests, so nothing climbs into main.
  • The catch: every path that assumes .claude/worktrees/ changes (the hooks, the window script, the session lists).
  • No paths change.
  • The catch: the climbing-into-main hazard stays, and main still has to hide the worktrees folder from search.
  • New worktrees appear in ../spell-app.worktrees/; existing ones finish where they are.
  • The worktree folder is a setting in the repo's kit config file.
