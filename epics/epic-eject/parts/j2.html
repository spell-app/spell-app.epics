Q13 said .epic/config.json5 is read the way every other tooling data file is, through DataFile. The FORMAT is the same (JSON5, comments kept, DataFile can write it later for epic init), but EpicConfig reads it with its own 30-line reader.

  • Why: the hooks and the window script load EpicConfig with plain node, before a worktree has its packages installed.
    • DataFile needs the json5 package, so it can't load there.
  • The reader drops comments and trailing commas, then uses JSON.parse(): the same trick as the commands page's browser reader.
  • A test reads the committed config both ways and checks they agree.
  • Works in every hook and script, even before yarn install.
  • Only JSON5's JSON-like part: quoted keys, double-quoted text (as DataFile writes anyway).
  • One reader everywhere, exactly as Q13 said.
  • The hooks and the window script would break in a fresh worktree, or need the main checkout's node_modules.
  • Hand edits with unquoted keys or single quotes would be refused, with a message naming the file.
