Since a68076f, spell-epic writes part pages from the content folder's real place. It does that with spell-app MAIN's Linker, which doesn't know about the content folder yet. So code links came out as ../../../../spell-app.worktrees/epic-eject/... or ../../../../spell-app/.... Those tie a page to one checkout and climb above / on the page server. The 26 links, in epic-eject's and epic-engine's parts/, now read ../../../..., the form every other content page uses. On this branch the Linker checks the epic-eject parts with no problems. New links come out right once this branch's Linker reaches main (the cutover); until then, new parts can pick up the same bad form. The Linker leaves an existing href alone, so doc-links.js won't fix one. epic-engine's parts already mixed forms (../../../src/... from spell-epic's root), and those were left as they were.
