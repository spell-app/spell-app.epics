The server package imports no other package, so it can't read EpicConfig. Chose to have epics tell it, over a second copy of the value in the page server's settings.

  • The running-epics route module, in the MAIN checkout only, calls the server's new serveWorktrees(dir): that mounts /worktrees/<w>/, as the server used to do by itself.
  • The server then tells pages and /api/server the folder (worktrees): the choice page's file links, the syntax page and the VS Code doc view use it, not a written-in path.
  • Finding a worktree's main checkout (the server, spaces, the hooks): the new SRV.checkoutOf(), which follows the worktree's .git file to the shared repository folder, so a worktree beside the repo (P8) is found too.
  • Tests that set a route module up by hand now call server.routeContext(), and serveWorktrees() when they need the mount.
  • The VS Code doc view change reaches Owen only when the extension is next built from main; the code is in, nothing was installed tonight.
  • One place for the value; the server stays a leaf.
  • Without epics' route module, a server serves no worktrees.
  • Simpler to read.
  • A second copy of worktreesFolder, in package.json, to keep in step.
  • No change for Owen: the main server serves the same /worktrees/<w>/ pages.
