The running epics' route module calls ctx.serveContent?.(contentFolder) in the main checkout's server AND a worktree's (each serves the same pages at /), and skips it when the checkout holds its own pages. The contract it relies on from spell-app: serveContent(dir: string): void on RouteContext, optional (older servers lack it), mounting dir at / after the checkout and at each /worktrees/<w>/, live-watching it at /, and rooting page edits and file writes there. Typed in spell-epic as ContentRouteContext (runningRoutes.ts) until spell-app's RouteContext has it. The epic server already serves each repo's content folder, so its serveContent() does nothing; its API route modules no longer go through main's links, since pages.js and the route modules read EpicConfig.contentOf().
