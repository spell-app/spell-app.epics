The page server and the Review tab are per checkout, and the epic views ship inside the spell language extension.
  • One spell-epic page server per machine, for every repo.
  • spell-epic gets its own VS Code extension, built from its one checkout.
  • One spell-epic page server per machine serves every registered repo's content folder, listed in ~/.spell-epic/repos.json5.
    • spell-app's own server keeps serving the app and the Spell UI docs.
  • spell-epic gets its own VS Code extension, holding:
    • the Review tab
    • the window bridge and the handoff
    • "Open Epic…"
    • a Sessions view, built only if the layout test run (P2) finds that resuming a session from another window fails (its step 4)
  • It is built and installed from spell-epic's one checkout, so "whichever checkout built it last" is gone.
  • The spell language extension drops those parts.
  • spell-epic's server and VS Code folders, the latter from DocView, DocPreview and WindowBridge
  • spell-app's VS Code extension, trimmed
  • Both extensions are installed side by side.
  • The Review tab opens an epic page from any window.
  • A handoff to a new window works.
  • The spell language features are unchanged.
