The page server and the Review tab are per checkout, and the epic views ship inside the spell language extension.
  • One epic page server per machine.
  • spell-epic gets its own VS Code extension.
  • One spell-epic page server per machine serves every registered repo's content folder (listed in ~/.spell-epic/repos.json).
    • spell-app's own server keeps serving the app and the Spell UI docs.
  • A VS Code extension, spell-epic, holds:
    • the Review tab
    • the window bridge and the handoff
    • "Open Epic…"
    • the Sessions view, built only if the layout test run (P2) picked that fallback
  • It runs epic, not spell-app's CLI by its path.
  • The spell language extension drops those parts.
  • epic vscode builds and installs it from spell-epic's one checkout, so "whichever checkout built it last" is gone.
  • spell-epic's server and vscode folders, the latter from DocView, DocPreview and WindowBridge
  • spell-app's packages/vscode, trimmed
  • Both extensions are installed side by side.
  • The Review tab opens a plan doc from any window.
  • A handoff to a new window works.
  • The spell language features are unchanged.
