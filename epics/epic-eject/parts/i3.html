How a reopened session picks its folder

Two programs pick the folder, one after the other: the Claude panel (the VS Code extension), then Claude Code itself. Neither one looks for a worktree that sits BESIDE the repo.

  1. The panel lists the saved sessions. For each one it notes the folder the session was last in:
    • the newest "moved" note in the transcript, if any (a relocated line, which Claude Code writes when a session enters a worktree)
    • else the folder on the transcript's first line, where the session started
  2. It marks the session as a worktree's only when that folder ends in .claude/worktrees/<name>. A folder like spell-app.worktrees/try-layout never matches.
  3. Owen clicks the session. The panel opens its tab: a session marked as a worktree's gets that folder, any other gets none.
  4. A tab with no folder takes the window's FIRST folder, and starts Claude Code there, resuming the session by its id.
  5. Claude Code reads the transcript. It moves back into a worktree only when the transcript holds a "worktree" note (a worktree-state line).
    • That note is written only when a session ENTERS a worktree with Claude's EnterWorktree: what /isolate and /epic do, through the repo's worktree hook.
    • The "moved" note of step 1 is only copied forward. Claude Code never changes folder because of it.
  6. The try-layout session had neither note. It was STARTED in the side-by-side folder, so:
    • step 2 didn't mark it, and step 4 gave it the main checkout's root, the window's first folder
    • step 5 had nothing to go back to, so it stayed there
    • its transcript shows it: the first lines worked in spell-app.worktrees/try-layout, and from the reopen on (2026-10-17, 10:32) in spell-app
Where each step is in the code
  • Steps 1-4, the extension 2.1.301 (extension.js, webview/index.js, minified names):
    • step 1: dT() and Wy1(), the list entry's cwd: relocatedCwd from the tail, else the head's cwd
    • step 2: FS(), with Dc = /[/\\]\.claude[/\\]worktrees[/\\]([^/\\]+)$/, gives the entry's worktree field (sessionEntriesFromSdk())
    • step 3: the webview's Eq.fromServer(): if ($.worktree) X.cwd.value = $.worktree.path
    • step 4: the webview's launchClaude() falls back to defaultCwd, the host's this.cwd, which is Nk(): the window's first folder. The host's launchClaude() and spawnClaude() pass it on as cwd, with resume: <id>.
    • resolveSession() finds a session in another worktree's folder, but only to list it, not to pick its folder.
  • Step 5, Claude Code 2.1.296 (the claude binary; its code is readable in it):
    • restoreWorktreeForResume() (minified eOe() / Ne()), called on start-up resume, on /resume, and in the SDK's print mode (NC()), with the transcript's worktreeSession
    • no record: it stays where it was started. A record: it checks the folder (still there, a real worktree, safe to enter) and moves into it, or warns and stays.
    • the record is written by saveWorktreeState() (minified AM()) when EnterWorktree runs, and set to null by ExitWorktree
    • relocated lines: written by relocateSessionTranscript() on entering, and only re-stamped on resume

What the repo's own tools do on reopen:

  • openSession() (spell dev session open) opens the session in the window it's running in, else in the CALLER's window. It never looks at the session's folder.
  • Window.resume() (a handoff) opens the session in the worktree's window. Its comment counts on the session going "back into its worktree by itself": true only for a session that entered with EnterWorktree (step 5).
  • Window.launch() starts a NEW session in a worktree's window. That window's first folder is the main root, so the session starts on main and has to enter its worktree itself.
  • The worktree hook (worktree.mjs) only makes the folder and prints its path. It has no say on reopen.
  • No SessionStart hook today. One could notice a session reopened in the wrong folder, but it can't move it: a hook can only add a note for Claude, or warn.

Fix options

  1. Always enter by EnterWorktree. Recommended.
    • Every worktree session starts at the main root, as launch already does, and enters its worktree with EnterWorktree. The worktree hook returns the side-by-side folder.
    • Claude Code then writes its "worktree" note, and brings the session back from ANY window (step 5).
    • Costs: P8's hook returns the new path, and nothing starts a session straight in a worktree's folder (a window whose first folder is a worktree would).
    • Risk: not yet checked that Claude Code accepts, on resume, a worktree OUTSIDE the repo. Its safety checks look at where the worktree sits. P8 tests it first: enter, close the tab, reopen from main's window.
    • Still to run: the sibling test is set up. Session 67b926aa entered spell-app.worktrees/try-layout with EnterWorktree (by path), and its tab was closed. Reopening it and running pwd is the one step left. (A first try opened a new session, 3cd0ba48, by mistake.)
    • A session that left with ExitWorktree comes back on main, as it should.
  2. A SessionStart hook as a guard.
    • On a resume, it compares the folder the session last worked in with the one it got. They differ: it tells Claude to enter its worktree again before anything else, and warns.
    • Costs: one small hook; an extra step on a wrong reopen.
    • Breaks: it relies on Claude following the note, and can't move the folder itself. It must tell a session that LEFT its worktree on purpose from one that got lost.
  3. Send reopens to the worktree's window.
    • spell dev session open and /session read the session's last folder, and open a worktree's session in its worktree's window (opening the window if needed).
    • Costs: a small change to openSession().
    • Breaks nothing, but helps only reopens through our tools: the panel's own list still opens a session in the window you click in. And by step 4 it works only when that window's FIRST folder is the worktree; today's worktree windows put the main root first.
  4. End the side-by-side path in .claude/worktrees/<name>.
    • For example spell-app.worktrees/.claude/worktrees/<name>: the panel's check (step 2) then matches, and hands the session its folder from any window.
    • Costs: an odd-looking path.
    • Breaks: it leans on an undocumented detail of the extension, which may change in any release.

The pick: option 1, the way Claude Code itself means worktrees to come back. Add option 2 only if P8's test shows a gap.
