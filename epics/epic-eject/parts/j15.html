Chose two rules for the plugin's hooks, over running them as they ran inside spell-app:

  • They act only in a repo that has epic settings, .epic/config.json5: the behind-main notice, the turn-end shared-content commit.
  • They work on the SESSION's checkout.
    • The window script and the prompt gate get it as EPIC_CHECKOUT, from the hook's cwd.
  • Why: a plugin's hooks run in every repo on the machine, and the engine is now a repo of its own, never the one being worked on.
  • The worktree hook still runs everywhere: Claude Code needs its answer to make any worktree, and with no config it uses the defaults.
  • The prompt gate still renames and gates /epic, /isolate and /unpark in any repo.
  • Each hook that ran spell-app's epic.mjs runs the plugin's own bin/epic.
    • The window script's launch runs the plugin's worktree hook.
  • No notices or commits in Owen's other repos
  • A repo next to spell-app-dev would commit it at every turn's end
  • Installing the plugin changes nothing in a repo that doesn't use epics, except how its worktrees are made
