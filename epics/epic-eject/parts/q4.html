Once a worktree window holds only the worktree, how does Owen still find every session of the repo?

  • The Claude panel lists only the sessions saved under a window's FIRST folder. Today main's root is folder 1 so every window lists every session: the root-first trick (O1).
  • That trick is what puts main's files in every window, and it already fails: 18 sessions since 2026-10-02 were saved under their worktree instead.
  • What's at stake: the duplicate files go away only if main leaves the window.
  • A view in the kit's VS Code extension lists every worktree's sessions, and opens one with the Claude panel's own command.
  • Drops the root-first trick: one-folder windows.
  • The catch: opening a session saved under another folder is untested; the first build phase tries it first.
  • Link each worktree's saved-session folder to the root's, so every session lands where the panel looks.
  • The catch: main's files stay in every window, the duplicates with them.
  • The panel lists only that worktree's sessions; /session finds the others.
  • The catch: a session in another worktree is hidden unless Owen asks for it.
  • A Sessions view in the kit's extension, grouped by worktree.
  • Worktree windows lose main's root; the root-first code goes.
