Chose to keep the epics package and its tests inside spell-epic at the same paths as in spell-app, with the plugin's own parts at the root, over flattening the package to spell-epic's root.

  • Kept: the package and its tests
  • The plugin's parts, at the root:
    • .claude-plugin/, skills/, hooks/, bin/epic
    • the window script, the templates
  • Why: every path inside the package then means the same as in spell-app, and the move changed no code inside it but its links to other packages.
    • its tools' ../../tests/epics
    • the window script's ../packages/epics/...
    • Git.CODE_ROOT, five folders up
  • bin/epic: plain ESM with no extension, running epicMain.ts under tsx, as the CLI's epic.mjs did.
    • spell-epic's package.json is "type": "module"
  • Claude's rules: AGENTS.md at the root, loaded from the CLAUDE.md in its .claude folder.
    • Why: a CLAUDE.md at a plugin's root draws a claude plugin validate warning.
  • The skills link each other relatively (../isolate/SKILL.md).
    • That works from the plugin and from links in ~/.claude/skills alike.
    • The hooks and scripts they name go through ${CLAUDE_PLUGIN_ROOT}.
  • No path inside the package changes
  • A folder level more than the plugin needs
  • Shorter paths
  • Every relative path in the tools, tests and configs rewritten
  • spell-epic's layout is spell-app's for the moved files, the plugin's parts beside them
