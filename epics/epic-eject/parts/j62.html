• RouteContext.serveContent is optional in the type, so spell-epic's EpicServer.routeContext() still compiles against spell-app's main: callers write ctx.serveContent?.(contentFolder). PageServer.routeContext() always gives it.
  • One content folder a server: the same folder again does nothing; another throws a TypeError (logged by the route module loader, not fatal).
  • Live reload watches the content folder WHOLE (but the guides' scripts/ and experiments/), not the pageServer.watch names: those names stay in package.json and DEFAULT_WATCH for a checkout that still links them in; a name the checkout lacks is skipped as before.
  • The writable names (epics, guides, pages, brand) become folders of the content folder once it's served; writes then go only there.
