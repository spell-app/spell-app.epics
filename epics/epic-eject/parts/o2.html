The folders, when done

Sibling folders under ~/www/spell-app/, each with one job:

spell-app/                  the code
spell-app.worktrees/<name>  a worktree per branch
spell-epic/                 the engine:  the plugin (skills, hooks, bin/epic), the epics package
                            (tool, list, elements, Epic UI's pages, its tools and assets),
                            its page server, its VS Code extension, the templates
spell-app.epics/            pages about spell-app (was spell-app-dev):  epics, sagas, guides,
                            pages, templates, brand, agents, goals (parked)
spell-spaces/               Owen's own Spell projects:  not part of this epic,
                            found beside the main checkout

Owen's comment: “make spell-app-epics name spell-app.epics unless the dot in the name will mess up CLI/etc”.

The dot is fine, so the folder is now spell-app.epics everywhere on this page, matching spell-app.worktrees.

  • Shell, git, node and yarn treat a dot in a folder name as an ordinary character.
  • Page URLs: /spell-app.epics/... is a valid path, and the page server serves the content through the checkout's links (/epics/...) anyway.
  • Claude's session folders turn the dot into a dash, as with spell-app.worktrees in P2's test, which worked.
  • Only file names get split at their last dot for a file type, never this folder; P4 checks it as it adds the config.
  • The engine's data about ONE repo stays in that repo's content folder: the tooling home, the favourites and the list of sagas (Q12). Each repo has its own epics, sagas and tooling home.
  • Per repo, ONE config file, .epic/config.json5, read like every other tooling data file (Q13). It names:
    • the content folder
    • the base branch
    • the install command
    • where worktrees go
    • the window names
    • whether session folders are linked

It ships as a Claude Code plugin

A plugin is Claude Code's package of skills, hooks and commands, switched on per machine. spell-epic is loaded in place: from a local-path marketplace, a folder on this laptop that Claude Code reads the plugin from directly, so an edit there is the plugin, with no copy and no install step in between (plugin docs, "in-place and copied plugins").

What the plugin holds:

  • The skills:
    • planning: epic, epics, details, comment, docs-check, send
    • worktrees and sessions: isolate, park, unpark, wait-for, worktrees, session, title, wtf
    • background and offline: bg, bedtime, airplane
  • Bare /epic keeps working: the skills are also linked into ~/.claude/skills (Q6).
  • The hooks: making and removing a worktree, the prompt gate, and the end-of-turn hooks. Their paths start at the plugin's own folder (${CLAUDE_PLUGIN_ROOT}), not at spell-app.
  • The epic command, with every epic verb in it (P5). It is on every session's path while the plugin is on.

Around the plugin

  • Its own VS Code extension: the Review tab, the window bridge, the handoff, "Open Epic…", and a Sessions view only if the layout test needs one (below). Split out of the spell language extension.
  • Its own page server, built on spell's server package: one per machine, serving every repo's epics.
  • spell-app becomes spell-epic's first user. spell dev's epic verbs stay, as aliases for epic.
  • spell-epic links spell's ui, server, assembler, util and spell-solid packages from spell-app's main checkout for now; they go to npm when it's released (Q5).
  • Staying in spell-app, since they're about spell itself: WWOD, and the fussbudget, design, solid-2, spell-docs and spell-serve skills.
