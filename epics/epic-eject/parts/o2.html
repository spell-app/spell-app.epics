Owen's comment: “make spell-app-epics name spell-app.epics unless the dot in the name will mess up CLI/etc”.

The dot is fine, so the folder is now spell-app.epics everywhere on this page, matching spell-app.worktrees.

  • Shell, git, node and yarn treat a dot in a folder name as an ordinary character.
  • Page URLs: /spell-app.epics/... is a valid path, and the page server serves the content through the checkout's links (/epics/...) anyway.
  • Claude's session folders turn the dot into a dash, as with spell-app.worktrees in P2's test, which worked.
  • Only file names get split at their last dot for a file type, never this folder; P4 checks it as it adds the config.

One config file per repo

  • Each repo names its epic things in ONE file, .epic/config.json5, in its main checkout (Q13, P4):
    • the content folder
    • the base branch
    • the install command, and whether a new worktree runs it before its window opens
    • where worktrees go
    • the window names, and whether a worktree's window holds only the worktree
    • whether session folders are linked
    • the content folders every checkout links in
  • Every key is optional, and its default is spell-app's layout. epic config prints what's in force.
  • epic init writes the file for a new repo, and makes its content folder (P9).
  • The engine's data about ONE repo stays in that repo's content folder: the tooling home, the favourites and the list of sagas (Q12).
  • A repo's generated files, the ones a merge rebuilds instead of merging, are its own list, .epic/generators.json5 (T4).

It ships as a Claude Code plugin

A plugin is Claude Code's package of skills, hooks and commands, switched on per machine. spell-epic loads in place: from a local-path marketplace, a folder on this laptop that Claude Code reads the plugin from directly, so an edit there is the plugin, with no copy and no install step in between (plugin docs, "in-place and copied plugins").

What the plugin holds:

  • 17 skills:
    • planning: epic, epics, details, comment, docs-check, send
    • worktrees and sessions: isolate, park, unpark, wait-for, worktrees, session, title, wtf
    • background and offline: bg, bedtime, airplane
  • Bare /epic keeps working once the skills are linked into ~/.claude/skills (Q6, T7).
  • The hooks: making and removing a worktree, the behind-main notice, the worktree guard, the reminder on leaving a worktree, the prompt gate, and the end-of-turn hooks.
    • Their paths start at the plugin's own folder (${CLAUDE_PLUGIN_ROOT}), not at spell-app.
    • They act only in a repo that has .epic/config.json5 (J15).
  • The epic command, bin/epic, with every epic verb in it (P5): on every session's path while the plugin is on.

Around the plugin

  • One epic command (P5): the window, worktree, park, session, stock, shared and server verbs joined the epic-page verbs, each group a class.
    • Every verb runs ONE copy of the code, the called epic's, on the caller's checkout.
