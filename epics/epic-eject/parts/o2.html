The folders, when done

Four folders side by side, each with one job:

  • spell-app: the code, and nothing about epics.
  • spell-app.worktrees: one folder per branch being worked on.
  • spell-epic: the engine, the same for every project.
  • spell-app-epics: the pages about spell-app.
~/www/spell-app/
  spell-app/                 code
  spell-app.worktrees/<name> one folder per branch being worked on
  spell-epic/                engine: plugin (skills, hooks, bin/epic), plan-doc tool, <epic-*> elements,
                             page server, VS Code extension, templates
  spell-app-epics/           pages about spell-app (was spell-app-dev): epics, guides, agents, goals, brand, ui

A worktree window holds ⎇ <name> and spell-app-epics. The main checkout isn't in it.

It ships as a Claude Code plugin

A plugin is Claude Code's package of skills, hooks and commands, switched on per machine. spell-epic is loaded in place: from a local-path marketplace, a folder on this laptop that Claude Code reads the plugin from directly, so an edit there is the plugin, with no copy and no install step in between (plugin docs, "in-place and copied plugins").

What the plugin holds:

  • The skills:
    • planning: epic, epics, details, comment, docs-check
    • worktrees and sessions: isolate, park, unpark, wait-for, worktrees, session, title, wtf
    • background and offline: bg, bedtime, airplane
  • Bare /epic keeps working: the skills are also linked into ~/.claude/skills (Q6).
  • The hooks: making and removing a worktree, the prompt gate, and the end-of-turn hooks. Their paths start at the plugin's own folder (${CLAUDE_PLUGIN_ROOT}), not at spell-app.
  • The epic command-line tool: today's spell dev plan-doc, window, worktree, shared, agents, details, session, park and stock commands. It is on every session's path while the plugin is on.

Around the plugin

  • Its own VS Code extension: the Review tab, the window bridge, and a Sessions view if the layout test needs one (O3). Split out of the spell language extension.
  • Its own page server, built on spell's server package: one per machine, serving every repo's epics.
  • Per repo, ONE config file (.epic/config.json), naming:
    • the content folder
    • the base branch
    • the install command
    • where worktrees go
    • whether session folders are linked
  • spell-app becomes spell-epic's first user. spell dev plan-doc stays, as an alias for epic.
  • spell-epic links spell's UI, server and assembler packages from spell-app's main checkout for now; they go to npm when it's released (Q5).
  • Staying in spell-app, since they're about spell itself: WWOD, fussbudget, design, solid-2, goals, spell-docs, spell-serve.
