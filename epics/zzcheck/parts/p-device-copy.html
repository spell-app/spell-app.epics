Nothing a place reads is kept on the device: every page load reads the server again, and check it once a day at 5am only says when an open page reads again (T97).

A reload of Star Wars before 5am makes no request to swapi, and what's kept on the device never grows past its limit.

Each read is kept on the device, fresh until the place's next check time: a page draws from it with no request while it's fresh, and from it at once, re-reading behind it, once it's stale. What's kept has a size limit, discarding what was read least recently.

Owen: “make sure the caching is opt-in!”

Today

  • PlaceCache is in memory only: one row per id, shared by everyone reading it, gone with the page.
  • A drawing that leaves lets its read go, so coming back to a tab reads again.
  • Nothing is kept on the device.
  • Reads don't bypass the browser's HTTP cache: swapi sends only an ETag, so it asks every time; PokéAPI sends max-age=86400, so the browser may answer for a day.

Build

  1. Opt-in, per place: nothing is kept on the device unless the place says so, with a line under it.
    • - keep a copy on this device; with a cap, - keep a copy on this device, up to 20 MB. Spanish: - guarda una copia en este dispositivo, …, hasta 20 MB (settled as it's built).
    • Without the line, today's behaviour stands: memory only.
    • The ingest never writes the line by itself; its report may suggest it.
    • Star Wars and PokéSpell opt in, as the examples.
  2. A copy on the device (IndexedDB) of each read of a place that opts in: its rows, its pages, the things its links reach.
  3. Fresh until the place's next check time: check it once a day at 5am or check it every 5 minutes.
    • Fresh: draw from the copy, no request.
    • Stale: draw from the copy at once, re-read behind it with If-None-Match (a 304 costs almost nothing), and redraw only what changed.
    • A server's longer Cache-Control wins.
    • reload the films reads the server whatever the copy says.
  4. A size limit (Owen): what one program keeps has a cap, 50 MB unless the line says otherwise.
    • Over the cap: discard what was read least recently, not what was written least recently.
    • Every read moves its copy's last-read time on.
    • The browser refusing room (a quota error) discards the same way, then tries again.
  5. Privacy: a place that needs a key or a sign-in is kept only when its line says so explicitly, as any place; signing out clears that person's copies.
