Chose matching at run time (each place renames what it reads by its words, remembers the server's spelling, and saves under it) over the compiler reading StarWars.api.star-wars.place.json5, which I'd told you it would.

  • The settings file isn't part of a project the editor and compiler load: only .spell, .spellml, CSS and JS files are listed and preloaded, so reading it meant new plumbing through spaces.
  • Run-time matching serves every kind of place, a hand-written server too, with nothing to keep in step.
  • What run time can't know before a read (a first save, a GraphQL query) comes from one line instead, it writes names like "hair_color", which the ingest writes.
