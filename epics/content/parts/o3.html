Another epic that finds a content fix (a typo in an example, a notebook that no longer compiles, a guide that tells the old way) sends it here as a REQUEST, rather than fixing it on its own branch.

  • First the session asks you, in a modal: "Fix it here, or send it to the content epic?" (send recommended). It never sends one by itself.
  • How: /send content <what> from that session; it lands as a request (r1 ...), and this session files it into a phase.
  • Why: that epic's branch stays about its own work, and two branches never edit the same example at once.
  • Not content: a change the example needs BECAUSE that epic changed the language or a component. That stays in the epic that broke it, so its branch passes its own tests: caused stays, found comes here.
  • Today nothing tells another session to do this; WWOD even says the opposite, "fix it in place". A "Content requests" rule beside the root CLAUDE.md's "Tooling requests" tells them, and WWOD §1 names the exception.
  • The word is "request", as /send says: WWOD already uses "driveby" for a fix made in place.
