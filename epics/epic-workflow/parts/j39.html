How other epics hear that a new migration step has landed: a flag on the same command, migrate --all --notify, and a one-line message, not a request.

  • With --notify, an epic whose session is running is skipped, and printed as a line to tell, found the way send finds one (the session titled for the epic).
  • The session that ran it sends each one a single SendMessage, roughly: "New migration step updates-as-epic-update for epic pages. Run epic migrate <epic> at your leisure; you may commit it without asking."
  • Not a request (epic send): a request is a folder that gets filed into a phase, which is too heavy for a one-command chore.
  • An epic with no running session is migrated there and then: nobody's work is under way to disrupt, and the page lock still keeps the page server's edits safe.
  • A migration names itself in a commit as <epic> migrate <step>: ..., the shape of <epic> I3: ....
  • One flag, --notify, no new verb.
  • Running epics get a one-line message; idle ones are migrated by the sender.
