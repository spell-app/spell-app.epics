For P13: how a goal page is built, and where its Send goes. Claude makes it from the epics pack's elements, like an epic page, with a review inbox of its own.

  • A new element, <goal-page goal="pythonic-spell" title="Pythonic Spell">, in the epics pack beside <epic-page>.
    • Its sections and items are the same <epic-section> and <epic-item>.
    • So a goal page has items with ids (T3, Q1 ...), which <epic-link goal item> reaches.
    • Its own parts: an Overview, an Epics block drawn from the epics that name the goal, then its items.
  • Owen's "comment blocks per section" read as each section's note box, the one an epic page's summary and phases have. His "bullhorns" are the comments every docs page has.
  • Both are kept in the goal's review inbox, <goal-id>.inbox.json beside the page, the same shape as an epic's. Send works as on an epic page.
  • Who hears the Send: no session works a goal the way one works an epic. So:
    • a session that listens to the goal (/epic review <goal-id>) wakes at once
    • nobody listening: the page says so, and the comments wait for the next review or /airplane land
  • The listen-and-wait code is the one Guide Comments Sent (P11) widens to guides, so goal pages come after it.
  • Element names follow the standing rule (no HTML built from strings): new elements made freely, each with its page in the Epic UI set (P8) before merging.
