A block's bullhorn floats over the top-right corner of its title row, so it can sit on the block's own buttons (the fold, an item's review pills), and the page has to measure and nudge it out of the way.Every folding element's title row gets an actions slot: extra buttons go in it, laid out to the left of the element's own buttons (fold, collapse, review pills); the bullhorn goes there instead of floating.

Owen, 2026-10-17, seeing the bullhorn over an aside's fold button: “Suggestion: <epic-section> and other section variables could have an actions slot which puts additional buttons in the right spot, to the left of the ‘default’ buttons like collapse.”

  • Each element with a title row has an actions slot there: <epic-section>, <epic-overview>, <epic-phase>, <epic-item>, <epic-aside>, <epic-code>, <epic-update>, and any other that folds (as <ui-section>'s own actions slot does for guides).
  • What's put in it (<ui-button slot="actions">) sits in the row, after the title and before the element's own buttons; the title shrinks (ellipsis) rather than run under them; the fold button stops where the actions start, so a click on an action never folds.
  • The page runtime puts each block's bullhorn into its block's actions slot, instead of a zero-height line before the block with the button floated over its corner; makeRoom()'s measuring and nudging goes, and so does the CSS stopgap that shortens the fold button (commit 28e350907).
  • Blocks with no title row (a paragraph, a table, a list) keep today's corner bullhorn.
  • Each element's Epic UI page shows the slot, with an example.
