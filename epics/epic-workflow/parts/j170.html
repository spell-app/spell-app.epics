The TypeScript and Python views go through the same per-file path the JavaScript view always used: the target's writer (from SP.TARGETS, the registry spell compile --target uses) writes the one spell file, as if it were the whole project (writeMatch()). No second compile path. It's not the whole project's .spell.tsx / .py: no imports header, and members a type gets in OTHER files aren't in its class. Both writers are in $/parser / $/py, which $/lsp already reaches through $/spell, so the language server stays browser-safe.

  • Show Compiled TypeScript / Python show the file you're in, in that language, the way Show Compiled JavaScript does.
  • For the whole project's output, spell compile --target ts/solid or py as before.
