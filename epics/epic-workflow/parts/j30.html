Read as: the two sets' pages live in package folders, versioned with each branch, not in shared root folders. Epic UI's pages go in a new folder, packages/epic-components/. App UI's go beside the app's own web components, in packages/app/components/. Nothing found that blocks it, so both phases now say so (option A below).

  • What changes against a shared folder. Shared folders (guides/, ui/ ...) are one copy for every checkout, committed by the turn-end hook. A package folder is ordinary tracked code:
    • an element's page changes in the same commit as the element, so a branch's pages describe its own code
    • the pages merge with the branch, and can conflict like any file
    • the main checkout shows main's pages; a worktree's own pages show under its /worktrees/<name>/ address until it merges
  • A docs folder, not a new package. The element code stays in the epics pack (packages/epics).
    • The root lists its workspaces by name, so a folder of pages under packages/ with no package.json is fine: yarn never sees it.
    • It gets a row in the root's packages table and a short README, saying it holds pages, not code.
    • If the epic tooling ever moves out of the repo, the folder moves with it in one piece.
  • How the page server serves them. It already serves the whole checkout at /, so the pages work at their long address with no change. Two short routes make them read like Spell UI's:
    • /epic-ui/ serves packages/epic-components/
    • /app-ui/ serves packages/app/components/
    • the same under /worktrees/<name>/, as /ui/ is
    • simpler than Spell UI's route: its pages are shared and its build is laid over them; here pages and data sit in the one folder
  • The tabs are unchanged: Epic/UI and App/UI, in the places Owen's toolbar order gives them.
  1. Moving pages OUT of the shared guides is instant for every checkout, but the new copies reach main only when the branch merges. So the phase copies the element pages in, and the old shared pages stay until the merge. Deleting them and turning on the redirects is a merge-time step.
  2. Comments: the bullhorn takes comments only on shared pages today (guides, the docs home, epic pages). Spell UI's pages take none either. The element pages take comments now, so the comment route learns the two folders, and their waiting-comment files are git-ignored there.
  3. Shared guides linking into a branch's new pages show those links as missing in other checkouts until the merge. That is the known case the link check already reports.
  4. No new shared links or ignore-list entries: J30's two root folders needed both, and a spell dev shared link in each checkout. This saves all three.
  5. App UI's pages sit beside the two web components' code folders: the set's home and one page per component, with their shared bits in _parts/ and _data/.
