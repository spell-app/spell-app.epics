A request travels in four steps, from the session Owen is in (the SENDER) to this epic's session (the RECEIVER).

  1. Owen says it in the sender: "comment mechanism doesn't look right", maybe with a screenshot pasted in.
    • The sender sees it's about the epic tooling, not its own work (Q1).
  2. The sender writes a REQUEST with epic send: a small folder in the receiving epic, epics/epic-workflow/requests/r3/.
    • request.md: Owen's words verbatim, which session sent it, and what it was looking at (page, file, item id).
    • Any screenshots, saved as .png files.
    • Written first, so nothing is lost if the receiver isn't running.
  3. The sender wakes the receiver, if it's running, with a one-line message: "new request r3".
    • Not running: the sender opens the epic's window (epic window launch), a new session there with /epic request r3 already typed in, and Owen presses Enter (Q4).
    • Busy in a turn: Claude Code hands the message over when that turn ends (C2).
  4. The receiver turns it into a phase with /epic request: a background agent does it, and epic file writes Owen's words and screenshots into the phase's Requests (Q3).
    • It joins a matching phase not started yet, or becomes a new one before Doc Review.
    • The sender says one line back to Owen: "sent to epic-workflow as r3".
epic send epic-workflow --text "comment mechanism doesn't look right" --images 1

This epic stood open as the tooling's standing home (Q2), until 2026-10-18: since then the home is epic-engine, which epic home names, and epic send with no epic sends there.

  • Each phase merges into main on its own, as soon as it's done (P5).
  • The worktree and its session stay, ready for the next request.
  • epic send works for any epic, not just this one: "send this to seo" too. One setting names where tooling requests go.
