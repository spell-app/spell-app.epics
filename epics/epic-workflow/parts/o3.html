When the epic started, most of the pieces already existed; it joined them up.

  • Messages between running sessions: Claude Code's SendMessage, which /park <other> and /unpark already use ("Run /park now").
    • Text only, and lost if the receiver is closed: hence the request folder first.
  • Screenshots: a pasted image is kept in the sender's transcript (~/.claude/projects/.../<session>.jsonl), as base64.
    • packages/cli/src/dev/transcript.ts already reads transcripts for /wtf; the new command saves the newest images from it.
  • Finding the receiver: sessions are titled 🚧 <epic>, and epic worktree status <name> lists the running ones.
  • Making the phase: /epic phase ("10. Add a phase" in the epic skill) and spell dev plan-doc add-phase.
  • The plan doc's shared folder: every checkout writes into the same epics/epic-workflow/, so any sender can drop a request there.
