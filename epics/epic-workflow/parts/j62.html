Steps are keyed by page kind with the names P14 proposes (epic, goal, guide, cheatsheet, command, changelog, template, home, list, detail, choice, component, brand, goal-set). If Owen renames them at P14, the list changes in two places (PAGE_KINDS and the docs tool's KINDS, which a test keeps equal).

  • The other kinds' steps live in packages/docs/tools/migrate.js, run as a child (epics may not import docs). A page's kind comes from where it lives and what it loads; a review page counts as a detail page.
  • Wrapped: to-ui-section.js, as the step ui-section for guides, cheatsheets, command pages, the changelog, templates, home and list pages. No page needs it today.
  • Left: the shared-content repair (relocate.js). It moves files between folders rather than fixing a page's markup, and spell dev shared commit runs its reorg every turn already.
  • migrate alone runs every kind; --all means every epic. The docs tool lists only the pages it changed, then a total per kind, not each of its ~80 up-to-date pages.
