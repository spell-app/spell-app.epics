For Epic UI Docs (P10, J23): the element pages' live examples need the epics pack, which takes Solid and Spell UI from the page (SpellUI.packModules); Spell UI's site bundle had no such thing.

  • Built the same site again, from site/_src/sets.ts, into packages/ui/site/_assets/sets/ (yarn site:bundle builds both); the page server serves it as a set's _assets/.
  • Why not a lazy chunk of Spell UI's own: every module a pack may use has to stay whole, and in one build that cost Spell UI's pages +118 KB (36 KB gzipped) as a static import, more as import()s (measured); its own build leaves Spell UI's pages as they were (eager 302.9 KB before and after).
  • A pack's define() waits for every Spell UI family there, since its elements draw <ui-section> and the rest in their shadow roots, which the root never sees (the docs bundle has them all already).
  • App UI's pages use the same build; its packModules also carry @solidjs/h and ui-root, for the app's element bundles.
