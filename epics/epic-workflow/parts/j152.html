For P20: every writer (Spell UI's writeOrCheck(), the brand's, Epic UI's and App UI's site:data) passes each .json5 file through keepingCommentsIn().

  • While the file is plain JSON (nobody has commented it): the writer's own text, in its own layout (search's one section per line, icons' one icon per line), as before.
  • Once it holds a comment: the old file edited to the new value with json5-writer; comments stay, a value that didn't change leaves the file byte-for-byte (so --check and the staleness tests stay quiet), and what changed is written in json5-writer's layout.
  • json5-writer matches array items by position: a comment INSIDE an item stays with that position when an earlier item comes or goes (a comment above the array, or on an object's key, is safe).
  • The browser reads the files with SiteData.json(): JSON.parse first, json5 (a lazy chunk) only when that fails; the icon browser's page reads icons.json5 through window.SiteData. No fallback to the old .json names: every checkout serves its own sets with its own bundle (the page server's /worktrees/<w>/ too).
  • a hand comment in any docs/__data/*.json5 survives yarn site:data (tested in the assembler's and ui's tests, and by eye on Epic UI)
