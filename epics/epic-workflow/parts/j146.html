A saga page reuses the epic page element whole: <epic-page kind="saga" saga="<id>">, with the same Overview, sections and items. A new family would have broken every block that looks for <epic-page> around it (folds, signals, the review controls, the docs runtime, the tool).

  • So the tool edits it as any epic page: epic add SAGA:/epics#T, epic check SAGA:/epics, epic inbox SAGA:/epics wait.
  • What differs: crumbs DOCS / SAGAS / <ID>; a click on the id copies /epic review SAGA:/<id>; one meta line (its short address) and its dates; no step label, Plan hung?, See Also or Agents running.
  • kind is a string attribute, not an enum: next to the section kind enum it typed every element data as never.
  • epic is no longer required (a saga page has none); saga is the attribute p15-data adds for an epic saga, the same text in both branches.
  • One element for both page kinds; a saga page gets ids, marks, comments and Send for free.
