How the CLI is put together.

  • A command's path, from the shell to its code: 
    bin/spell.mjs  →  tsx  →  src/main.ts (commander)  →  src/commands/<name>Command.ts
    • each command is a function: (session, args, options) => exitCode
  • CliSession holds what an editor holds, so the CLI sees what an editor does:
    • SpellDiskWorkspace
    • SpellLanguageService
    • ScopeExplorer
  • Child processes live in runner/: run, test, and now speed.
    • they never import values from $/cli
  • It runs spell's SOURCE, with no build (C1).
