Since the Spell Cells phase (P11), a spell object notices when one of its properties is SET, but not when something inside a property's value changes. You'd notice a list that doesn't redraw after an item is pushed onto it.

  • Cells follow properties, not what they hold: no proxies.
    • so === holds everywhere
    • and raw() is gone
  • Before: easy-state made nested objects reactive, so editor.file.someArray.push() redrew. Now only setting the property does.
  • Audited:
    • spell's List copies on write
    • Loadable's loadState uses a dotted setState, which notifies loadState
    • the compiled examples hold only primitives and Lists
  • The gap: a plain array that a PROGRAM keeps in a property and changes with spellCore.append() won't redraw. None of the examples do that.
  • The design's Proxy for data with no class isn't built (solid-2.md). 
// no redraw now
editor.file.someArray.push(x)
// redraws:  the property is set
editor.file.someArray = [...editor.file.someArray, x]
