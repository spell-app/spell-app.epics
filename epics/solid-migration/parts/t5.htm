A host page that already runs Solid or @spell-app/ui needs a build of our elements that shares its copy. That build was designed but never made, so today such a page loads a second Solid, which fails silently.

  • Designed in the Web Components + Runner phase's Files (P7) and the one-Solid-per-page decision (D21).
  • It would leave these imports bare, for the page's import map to fill:
    • solid-js
    • @solidjs/web
    • @spell-app/ui
    • @spell-app/solid-element
  • No build script or config makes it. It would be vite.element.config.ts or vite.editor.config.ts without sharedSolid()'s output.paths.
  • Why a second Solid fails: solid-2.md, "One Solid per page".

Title, as first written: Import-map <spell-app> variant: designed, not shipped

P7's Files and D21 name an import-map variant of the elements (bare solid-js / @solidjs/web / @spell-app/ui / @spell-app/solid-element specifiers) for host pages that already run Solid or @spell-app/ui. No build script or config emits it: it would be vite.element.config.ts / vite.editor.config.ts without sharedSolid()'s output.paths. Until then such a host loads a second Solid, which fails silently (solid-2.md, One Solid per page).
