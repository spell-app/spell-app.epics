packages/parser/src/ast/AST.ts (was .tsx) and renderAST.ts build P.Markup: plain data ({ tag, attrs, children }, text, arrays) from render.h() / render.span(). The app's ASTViewer draws it with P.render.toDOM() in render, inside its <ErrorBoundary>: no <ReactHost>, no React in packages/parser. Why not Solid JSX: AST.ts loads wherever the parser does, and the CLI / language server run its SOURCE through tsx (esbuild), the parser / spell / lsp / core / cli tests through Vite's oxc: none can compile Solid's JSX, and Solid's DOM build would land in node tools. Moving the ~55 renderChildren() into an opt-in Solid module would split each class's drawing from its compile(). The tree is static (a new compile makes a new AST), so Solid's reactivity buys nothing. The pane's DOM is byte-identical to the React one (Todos, Solitaire).
