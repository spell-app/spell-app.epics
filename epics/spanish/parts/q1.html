Where does a project say it's written in Spanish: once per project, or file by file? It decides what a Spanish project looks like on disk, which parser a file gets, and whether English and Spanish files can mix. 

{
  description: "Solitario",
  language: "es",      // new, beside listsStartAt;  "en" when missing
  listsStartAt: 1,
  imports: [{ path: "@spell/library/cards", active: true }]
}
  • language: "es" in the project's settings file; files stay .spell
  • one parser per project scope: the simplest wiring, and what the language server and highlighter already read the parser from
  • the Project Settings panel edits it, as it edits listsStartAt
  • no mixing: an English library imported into a Spanish project keeps its English names (a caveat)
  • a file names its own language; a project could mix
  • the file's extension is everything after the FIRST dot, so .es.spell fails today's === ".spell" checks in the workspace, Monaco and the language server: four places to fix
  • each file needs its own parser; a scope shared across languages has to merge two vocabularies
  • a first line, ## idioma: español, or a tag
  • nothing to read before parsing, so the parser must sniff the first line in a language it doesn't know yet
  • same mixing cost as B
  • a new project setting, language, read where listsStartAt is
  • Card.spell-es moves into a Spanish project as Carta.spell, instead of living beside English files
  • mixed projects become a later question, with the parked goal G3
