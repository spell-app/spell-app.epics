Owen's plan review: "add CLI tools to verify/fix language packs, e.g. when new spell english rules are added. It'd be rad if the fixer for this used an AI to figure out the new words if necessary."

  • spell lang packs check [<lang>]: for each language against English, every rule registered in a <module>.en.ts has an entry in <module>.<lang>.ts (syntax and at least one test), and every word rule and every table (booleans, ordinals, type words, built-in members, JSX words, messages) has every key. It prints what's missing, per file, and exits 1 when anything is; it runs in spell-lang's yarn test as a test too.
  • spell lang packs fix [<lang>] writes the missing entries as stubs: the English syntax copied and marked TODO: translate, its tests copied with the English input, so the file lists what's owed.
  • spell lang packs fix --ai drafts the translation of each stub (the syntax string and the test inputs) by asking Claude, with the English rule's docstring, syntax and tests, and the pack's existing translations for its vocabulary, as context. Each draft is marked AI draft for review; the check then passes, and a review list is printed.
  • How the AI is reached: the claude command already on the machine (claude -p, a subprocess: no new dependency, Owen's own account), not the Anthropic SDK (a runtime dependency and an API key). A decision Owen can flip.
  • The English side is checked too: a rule class registered in no .en.ts is reported.
