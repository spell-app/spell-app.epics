Run Tests runs the project's tests in VS Code's Run panel (the webview), not in the language server after each clean compile.

  • The panel already runs programs in a browser page; the language server would need a node child process with a fake page (as spell test has), and a test that loops would hang it.
  • The tests run on a SECOND copy of the runtime (testApp()), so the game in progress is left alone.
  • The panel sends the results to the extension, which asks the language server where each failed check is (spell/testDiagnostics) and shows them in a set of diagnostics of its own, spell tests: so the parser's diagnostics, sent after every edit, don't clear them.
  • An edit to a file clears its test errors; the next test run shows them again.
