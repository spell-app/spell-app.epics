A card's its "suit" is one of clubs, ... now also declares the kind card suit (Spanish: palo de carta), so the foundation's its "suit" is a card suit is one of the card's suits, oneOf: () => Card.Suits.

  • Chose: the kind has NO class. Nothing compiles for it, the project doesn't export it or write it in its declarations, and an importer makes it again from the property's own declaration. So every other English project's output is unchanged.
  • So a property or phrase ON it (the "value" of a card rank is ...) is refused, saying it's one of the values a card lists; a member read off one warns the same. Rejected: compiling an empty class CardSuit {} per list, as the old "suits" as one of did: every project with a list of values would gain a class.
  • The card's own suit keeps no datatype (its declarations unchanged); its list Card.Suits is a list of card-suits, so for each rank in card ranks knows each is a card rank (TypeScript types it Rank).
  • A type declared with the same name (a card suit is a thing) keeps it, above or below.
  • The editor's scope explorer and spell describe leave these kinds out: the card's entry already lists Suits (clubs, ...).
