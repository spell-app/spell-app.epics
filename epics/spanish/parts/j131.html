Owen's Deck turns each card face down in to create it:, which pauses, so Python's Deck.create is async def. A constructor can't await it, so the deck stayed empty and dealing failed.

  • Now spell_core runs a create() that waits to its end inside __init__(), with its pauses not waiting: core.run_at_once().
  • That's what javascript does: its create() stays plain and calls card.turnFaceDown() without waiting, so every card is face down as soon as the deck is made.
  • The writer is unchanged: create is still async def, and its turns are still awaited.

Rejected:

  • An awaited factory (await Deck.make()). Every Deck() would have to wait: prop inits (prop(init=lambda: Deck())), the top-level solitaire = Solitaire(), copies. That's far from javascript.
  • A task running beside the program, as an event's handler runs. The deck would be made half set up, its cards still turning over (52 x 50 msec) while the game deals them.

It throws if a create waits for anything other than a pause. Nothing in spell does that today.
