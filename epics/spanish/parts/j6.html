Your steer on Q4 ("new rules which can be translated, e.g. is_or_is_not, before you add to the rulex") became three small rule classes, no rulex change:

  • Wording: forms in named groups, the group's name the MEANING.
    • a rule asks Wording.meaningOf(match)
    • e.g. list_end: ((start:start|front|top)|(end:end|back|bottom))
  • Negatable: a Wording whose one meaning is negated.
    • renamed to your style: is_or_is_not, can_or_cannot
    • and will_or_will_not, has_or_has_not
    • the old names stay as aliases, for declarations compiled before
  • Synonyms: forms that all mean the same, e.g. is_or_are
    • and the articles: indefinite_article, definite_article
  • Code that meets a word outside a parse asks Wording.reads(scope, rule, word).
  • About 30 word rules in all, each registered in its module's .en.ts; Spanish registers its own under the same names.
  • No rule class reads an English word; a guard test fails if one starts to.
