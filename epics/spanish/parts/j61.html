P13 moves the editor's inline strings into text packs, which WWOD §6 › "User-facing strings stay inline" forbids ("only ui localizes"). As you asked, I did not edit WWOD; the app is built as if you accept this wording.

Proposed replacement for that bullet (in agents/wwod/WWOD.md, §6): 

- **User-facing strings stay inline**, where they are used -- EXCEPT in code that speaks more than one language:
  - Spell UI:  its vocabularies (`UIButton.en.ts`) and dictionaries (`UIButton.es.ts`)
  - the editor app (`spell-app/app`):  every text it shows people is a key in `AppTexts.en.ts`,
    read with `appTexts.text(key, params)`;  each other language is a LAZY `AppTexts.<lang>.ts` beside it, with
    every key (its type says so)
  - the language server (`spell-app/lsp`):  its labels are keys in `LspTexts.en.ts`, read in the PROJECT's
    language (`LSP.LspTexts.of(scope)`)
  - A sentence that names something takes it as a param (`{type}`, `{theType}`), never glued from pieces:
    each language words it its own way.
  - NOT:  a `MSG.ts` of every string in a package that speaks only English -- one more file to keep in step,
    for no localization.

Also §7 might gain: "Building a sentence from pieces (`` `Created ${type} ${name}` ``) in code that speaks more than one language".
