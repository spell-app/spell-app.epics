A language is a set of rules, not a fork of the parser. Everything the table in 1.1 says "changes" is gathered into one thing, a LANGUAGE PACK: English is the first pack, Spanish the second, and a project names the one it's written in.

What a pack holds:

  • which characters make a word, and how words inflect (singular and plural, with irregulars)
  • the small words: articles, the subject words (it / its), booleans, number words, ordinals, the identifier blacklist, member stop words, dangling prepositions
  • the built-in types' words (texto, número, lista, cosa) and their members' (largo, año, caracteres), onto the same core calls
  • every rule's syntax and its tests, registered on the SAME rule classes as English
  • the messages an author reads: the warnings and the "Don't understand" fallback, with examples in that language
  • spell's own JSX words (children, in)

How one rule serves both languages, illustrative:

// the English module, today's registration (rules/expressions/IsEqual.ts)
expressions.addRule(IsEqual, {
  syntax: "{lhs:operand} (operator:is|(negated:is not|isn't)) {rhs:operand}",
  tests: [["the card is the ace", "card === ace"]]
})

// the Spanish module (languages/es/expressions.ts)
expressions.addRule(IsEqual, {
  syntax: "{lhs:operand} (operator:es|está|(negated:no es|no está)) {rhs:operand}",
  tests: [["la carta es el as", "carta === as"]]
})

// IsEqual.compile() reads match.groups.negated, never the word "not"

How a project picks its pack:

  • language: "es" in the project's settings file, beside listsStartAt; the Project Settings panel edits it. Files stay .spell.
  • the project's scope clones the Spanish parser instead of the English one
  • its words file is <Project>.es.js (and .py.es.json5 for Python)
  • the highlighter and the language server read the parser off the scope, so colours and completions follow

Names stay the author's:

  • para "mover (una carta) a (una pila)" compiles to moverAPila, as move (a card) to (a pile) compiles to moveToPile
  • an accent stays: corazón is a legal name in JavaScript and Python (question Q2)
  • the core's own names (itemCountOf, randomItemOf) stay English: compiled code calls them, nobody reads them

Spell UI gives every component an English vocabulary (UIButton.en.ts) and a Dictionary per language mapping those canonical names to local ones, a miss falling back to English. A rule class is the canonical name; its syntax string is the dictionary entry. Spell UI's SharedVocabulary.es.ts already names a few attributes in Spanish.
