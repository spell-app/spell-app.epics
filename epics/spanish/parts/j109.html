For I5, compiled Python names a drawable class's element tag in its body as plain text, element_tag = "test-project-card", worked out when it compiles by the same elementTagFor() javascript's core uses at run time.

  • Not a run-time call like javascript's core.defineElement(this, "Solitaire"): a Python class body can't hand the class over while it's being made, and the tag is all Python needs. Python has no page that defines elements, so it doesn't need the definer either.
  • Like javascript's, a subclass with no tag of its own takes its parent's. The writer writes a tag on every drawable class anyway.
  • core.draw_thing() draws a thing as its element only when its class has a tag. A hand-written Drawable with no tag draws as any thing does, as before.
  • When a slot is filled, each child goes in the FIRST slot that takes it, as a browser does. The javascript fake page's replaceWith() would move them to the last of two unnamed slots, but no program has two.
