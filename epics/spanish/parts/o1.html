Before this epic, English was built into Spell in six layers, from which characters make a word up to the docs. Each layer got a fix of its own shape; none was a rewrite of the parser.

Word characters

The tokenizer takes ASCII letters only, so año is three tokens: the word a, the symbol ñ, the word o.

The same ASCII patterns sit in:

  • the rulex tokenizer
  • the identifier and type patterns
  • the writers' "is this a legal name" checks
  • the language server's word patterns
  • VS Code's wordPattern
 about 12 regexes Unicode letters everywhere, as the markdown tokenizer already does.
Plurals

One util file wraps the English-only npm pluralize; every type lookup goes through singularize. It gets Spanish wrong:

  • corazón pluralizes to corazóns
  • reyes singularizes to reye
 1 file, 14 callers An inflector per language, handed to the parser.

Rule code

Some rules read the English word they matched:

  • === "is not"
  • .includes("not")
  • ["a", "an"]
  • "it" / "its"

Plus the word tables: the identifier blacklist (about 115 words), booleans, number words, ordinals, member stop words, dangling prepositions, the built-in types' words and members.

Around the language

English everywhere an author meets the language:

  • the words file is <Project>.en.js, its en hard-coded in three places
  • VS Code's grammar lists English keywords; its indent rule knows otherwise|else
  • about 14 warnings and the "Don't understand" fallback are English sentences, with English examples
  • the docs teach English spell
 3 tools, 15 messages, 2 docs pages Per language where it reaches an author; the docs later (1.4).

Some of it was ready for a second language already:

  • A rule class and its syntax are separate: addRule(Class, { syntax, tests }). The docs say so, "the class is the rule, reusable by other languages' parsers with their own syntax".
  • Negation has a translation hook, Negatable.specialize({ ruleName: "es" }) with (es|(negated:no es)), shown in spell's own AGENTS.md.
  • The built-in types' words are data, TYPE_WORDS, documented "a translation brings its own"; the parser's typeName() takes the table as a parameter.
  • The words file reader accepts any language code (es, pt-BR). The app's TRANSLATIONS has a spell/<lang> slot, "a translation will bring its own parser".
  • Spell UI's vocabularies are the house model: canonical English names, a dictionary per language, a miss falling back to English.
  • A Spanish card exists, Card.spell-es, 118 lines, hand-translated in 2025 and never parsed. It is the first target.

    • English singular: is a, is not a
    • English plural: are, aren't
    • Spanish singular: es un, no es un
    • Spanish plural: son, no son
