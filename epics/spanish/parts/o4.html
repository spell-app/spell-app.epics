This epic gets a Spanish project parsing, compiling, running and editing, with Spell UI's components under Spanish names and one real example. It stops before the docs and the app speak Spanish, and before any third language.

Now, in this epic:

  • Unicode words, everywhere a word is matched or named
  • the identifier blacklist slimmed to the words with a reason (Owen's M2)
  • the language pack: a <module>.en.ts per rules folder, the word tests in rule code turned into translatable word rules, the decimal separator in the tokenizer
  • Spanish rules, enough for the frozen cards project (Card, Deck, Pile and their tests), then the rest of the grammar
  • a project's language setting, its Spanish parser and its .es.js words file
  • agreement warnings: el carta in Spanish, a apple in English (question Q3)
  • Spell UI in Spanish, all four parts (Owen: "DEFINITELY in scope"): a dictionary per family, the page-wide runtime, the texts, and Spanish drawables and JSX in spell
  • the editor: Spanish colours, completions, warnings, VS Code's grammar and indent rules
  • one translated example, Solitario, from the combined Solitaire Owen provides
  • the runtime messages scoped (Owen's M6): a list and a proposal, built only if he says so

Not now, and why:

  • The docs in Spanish (README-spell's "What it reads", the syntax guide): once the grammar settles. The syntax guide is drawn from data, so a spellSyntax.es.json is cheap then.
  • The app's own words (the editor's buttons and panels, hover and completion labels): the app's component vocabularies (SpellApp.en.ts) are the place, together with Spell UI's translations. A separate epic; WWOD keeps the app's strings inline until then.
  • Mixed languages in one project: one language per project (question Q1). A Spanish project that imports an English library (@spell/library/cards) sees English names: a caveat for now.
  • Reading a spell in another language (the parked goal G6): a writer from the tree back to each language. Its own epic, once two languages parse.
  • Norwegian and Portuguese: each is a <module>.no.ts / .pt.ts per rules folder and a languages/<lang>/; friends translate the syntax strings and tests. The pack shape is built for it, the languages aren't.
  • Spell Epic's pages and the spell command: English, by Owen's note on 1.2.

Owen's review of the plan: Spell UI is in scope, all four parts; Spell Epic and the CLI are not. The blacklist analysis, the agreement warnings, the decimal comma and the runtime-message scoping are phases now.
