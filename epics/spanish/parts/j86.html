How one project's English and Spanish files share a scope (you asked me to pick):

  • The root: SP.Language.rootScopeFor(languages). A project in ONE language gets that language's own root, so every English project, and cartas, parse exactly as before. A project in several gets a root of its own, built once per set of languages: spell's built-in types, their members in every language's words (the length of the list and el largo de la lista both read .length).
  • Why not each file's own language root over the project scope: a type a Spanish file declares and an English file extends finds its members up its super-type chain, which goes through the PROJECT's root, not the file's. One root with both sets of words makes that work from either file.
  • The parser: the project parser is its first file's language's. A file in another language parses with that parser's TWIN in its language (SpellParser.twinFor()), set on its FileScope: the language's own rules, a copy of every rule the import layer and the project added, and every rule any twin adds after that, which all the others add too, into the same journal. So incremental parsing, rewinding and stubbing work across both.
  • So a Spanish file calls a method an English file defines by its English words (reset el p), reads its properties the Spanish way (el score del p), and the other way round.
  • Test helpers (parseSpellProject()): a path naming a language (/Mazo.es.spell) reads in it; a plain /test.spell reads as the root you pass, so the Spanish rule tests that pass Spanish's root keep working.
