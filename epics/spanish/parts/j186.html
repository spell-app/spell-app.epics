README-spanish's tested example is spell translate @spell/examples/fizzbuzz --to es --no-ai --cold --out /tmp/fizzbuzz-es. Without --cold, --out moves only the translation: the names dictionary and the record (fizzbuzz.es.names.json5, .es.translated.json5) are written beside the English project, into spell-app's spaces/@spell/examples/fizzbuzz/, so every README test run would leave two untracked files there. README-cli's --out row says 'writes it there instead', which reads as everything.

Is that what --out should do (the dictionary is the project's, for every later run), or should --out take the dictionary and record with it?

  • the example uses --cold, which writes only into --out, and shows every name left for a person
  • no code changed; the two stray files from a trial run were deleted

Decided in P31: --out now takes the names dictionary and the record with it, so a run with --out writes nothing beside the project.

  • A dictionary already beside the project (a person's, or a run's without --out) is still READ, and never written, so a hand-made dictionary keeps working with --out.
  • --update finds its record in the same place: pass the same --out again (or none, for a translation written beside the project). spell translate speedtest's update mode already does.
  • --learn with --out reads the dictionary from there too.
  • The cost: an imported project's translation is found by the project importing it only when it was translated without --out (spell-app's importsOf() looks beside the import).
  • No stray files were left in spell-app's examples or test projects: checked, in this worktree and main.
  • Tested: translateProject.test.ts, "--out keeps what it writes (J186)"; spell-app's Gizmo test reads it from --out.
