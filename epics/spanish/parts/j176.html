  • A new rule, create_hook, in a type's outline: English - when created (with title as text, completed as a choice):, Spanish - al crearla (con título como texto, completada como una opción):.
  • Canonical: when created, and al crearla (al crearlo for a masculine type), the correct written Spanish, which the translator writes. Also accepted: when creating it; al crear and al crear la (the pronoun apart, not standard Spanish, but read).
  • It's the type's create() hook, which - to create it: already compiled to. Core now hands create() the props the thing was made with (Thing, List, @thing), so its (with ...) reads them; a copy still runs no create().
  • Callers just make one: create a new task with title = "...". create a ... takes an optional new now (crear una nueva ...).
  • Only in an outline, and only its own words (create_hook_words): Spanish's al ... is also an event handler (al card click), which the hook beats on the same words (Priority.specific).
  • The todos example uses it (a task:, then the hook); checked in a browser: three tasks drawn, Add Item makes a fourth. The frozen @spell/test/todos-form-based keeps the old form, as fixtures do.
  • Not done: Python's core still calls create() with nothing, and its writer can't write named arguments yet, as before.

Owen suggested "when creating it": in Spanish that's al crearla ("cuando creando la" isn't Spanish).

  • Kept: para crear una nueva tarea (con título como texto, completada como una opción), called crear una nueva tarea con título = "…". para + infinitive is how Spanish says "to do something", and both now write and read back (the call's con was dropped before, and a call without it couldn't be written).
