The hard part is grammar, not words: gender, articles, plurals, verb forms. Each one below says what Spanish does and how the pack takes it (the grammar is P5 and P6's work).

  • Gender and articles.
    • the articles: un / una, el / la / los / las
    • the contractions: de + el = del, a + el = al
    • a type's gender is read off its declaration: una carta is feminine, un mazo masculine
    • the pack's article groups: (un|una), (el|la|los|las)?
    • and with a preposition: (de|del), (a|al)
    • agreement is checked and WARNED, never an error, in both languages (question Q3, P8):
      • el carta gets "la carta?"
      • a apple gets "an apple?"
  • Plurals.
    • -s after a vowel, -es after a consonant
    • z becomes ces
    • accents move:
      • corazón / corazones
      • joven / jóvenes
    • some words don't change: lunes, crisis
    • Spanish's inflector is Python-Inflector's Spanish rules, ported and widened (Owen's M3, Q26): the npm packages only pluralize
    • a type's own oddity goes in its declaration, as aka does today
  • Adjective after the noun: carta boca arriba, pila de descarte.
    • a declared name is a run of words looked up whole, so word order inside a name never reaches the parser
    • only the built-in two-word types need Spanish words (cosa dibujable)
  • Two verbs for "is": es (what a thing is) and está (its state).
    • both register as "is": (es|está)
    • negated: (no es|no está)
  • Conditions.
    • the statement: si … :
    • its other branch: si no, or de lo contrario
    • the value form: rojo si su palo es corazones de lo contrario negro
    • si no sits next to the boolean no: the choice order settles it
  • The dropped subject. Spanish leaves it out: tiene un mazo.
    • outline lines without a subject already parse (subject_implied)
    • su / sus stand for its
  • Ordinals with gender. primer / primera / primero, última: the ordinal word table lists every form.
  • Booleans and numbers.
    • booleans: sí / no / verdadero / falso / siempre / nunca, ok / cancelar
    • number words: uno … diez
    • the decimal comma is the pack's (Owen's M4): 1,5 is a number, 1, 5 a list
  • Methods and tests. Signature words are taken as written, so the phrase itself needs no rule change:
    • a method: para "mover (una carta) a (una pila)":
    • a return: devolver
    • a test: para probar …
  • Question marks. ¿ and ¡ already tokenize as symbols; no rule uses them yet.

Owen: "Can you find a spanish algorithmic inflector that someone else has written?"

Three, none a drop-in; P5 started from them:

  • pluralize-es (npm, 2015): plural only, no singularize; unmaintained
  • @boringnode/pluralize (npm, a TypeScript port of Doctrine Inflector): a locale parameter; its README carries a custom Spanish ruleset, hand-configured
  • bermi's Python-Inflector, its rules/spanish.py: the best-documented rule set, both directions; Python, so a port
    • with irregulars: país / países
    • and invariants: lunes, tijeras

What P5 did: Python-Inflector's rules ported into our own small inflector, since none of the npm packages singularizes and spell needs both ways; no dependency added.

Owen: "build this into the tokenizer?"

Yes: the tokenizer's number pattern is the pack's (P3), and Spanish sets a decimal comma (P5).

  • 1, 5 stays a list, as in como uno de as, 2, 3
