How P15 built J67:

  • name is a stored member of list in the built-in table, marked declarable: a pile has a name as text (or no type) is fine, a pile has a name as number is refused ("every list has one, built in, as text"). id stays undeclarable.
  • The refusal now asks the built-in type a type comes from: a card (a thing) may declare any name; a stub type with unknown super-types refuses only id.
  • Spanish's nombre compiles to .name in every place it can appear: reads (el nombre de la pila, su nombre), sets (poner el nombre de la pila a ...), a declaration (una pila tiene un nombre como texto declares name), and a new list's props (una nueva pila con nombre = "mazo" => new Pila({ name: "mazo" })).
  • Core's List.name is declared for TypeScript in an interface beside the class, its getter / setter put on the prototype in a static block: a getter / setter in the class body would make every sub-class's @prop accessor name!: string (what a pile has a name as text compiles to, and hand-written classes say) a TS2612 error.
  • Hand-written test classes that re-declared an untyped get name() / set name() on a list (core's carry, json, references, state tests; spell-app's SpellElement browser test) dropped it: the untyped getter clashes with the base's string | undefined (TS2416), and the list has it anyway.
  • A list's name is now a real prop: toJSON() / to_json() write it once set (before, Python left an undeclared name out).
