When you switch the bubbly look off, a page file in the CodeMirror editor shows fewer colours than it did in Monaco. The words inside a tag, and any markup it draws, stay plain black text.

Three words first:

  • A page file is a Spell file written as a page rather than as code.
    • It starts with a head line, "card api" is a notebook page.
    • Under it come lines of prose, and tags like <for card in its cards> that say what the page draws.
    • The editor knows one by its first line (SP.formOfText() says "page").
  • The bubbly look off means the code pane draws plain text with coloured words, instead of Spell's bands, rails and pills.
    • With the look off, the colours come from the words alone, the way any code editor colours code.
  • A tag's Spell twin is the line of ordinary Spell code the tag stands for.
    • <for card in its cards loading="Wait"> stands for for card in its cards.
    • The head "card api" is a notebook page stands for card api is a page :.
    • A page compiles by reading each tag as its twin (SP.PageTwin), so a page and its code twin do exactly the same thing.

What CodeMirror colours today, from the page's own pieces alone (CodeMirrorTokens.pageSpans()):

  • the prose lines, and <!-- ... --> comments, as comments
  • the head: its name as text, the rest of it as keywords
  • a tag's opening angle and its first word (for), and closers like </for>
  • quoted text and numbers inside a tag

The simple route, colouring a page with the colourer every other Spell file uses (SP.SpellHighlighter.spans()), gives wrong colours, for two reasons:

  • It reads the page's text as if it were plain Spell code.
    • A prose line like A card, face up or down. would be coloured as code words, not as a comment.
  • Its finer colours come from the file's parse, and a page's parse is a parse of the TWINS, not of the text you see.
    • The twins hold words the file doesn't have, like to draw it. And they drop ones it does, like < and loading=.
    • So a word's place in the parse isn't its place in the file, and its colour lands on the wrong letters.

Matching Monaco means doing what Monaco's colourer did, in CodeMirror. It was deleted when Monaco went (phase P6, The Swap), but its code is in git: SpellTokensProvider.

  • For each tag, build its twin, and colour only the twin's tokens that are really in the file, at their own places.
  • Colour attribute names (loading), the head's flags (notebook), and a tag's closing angle, plain or self-closing.
  • Colour markup as HTML: the bubbly look's own reading of markup (CodeMirrorMarkup's shared marks) could give the pieces.
  • Roughly 100 lines in CodeMirrorTokens, and a few more cases in its test: half a day.

private twinTokens(parser: SP.SpellParser, tokens: P.Token[]): P.Token[] {
  const [root] = parser.tokenizer.breakIntoIndentedBlocks(tokens)
  const line = root && firstLineIn(root)
  const twin = line && SP.PageTwin.lineOf(line, undefined, parser)
  if (!twin) return []
  const own: P.Token[] = []
  P.Tokenizer.forEachToken([twin.line, ...(twin.body ? [twin.body] : [])], (token) => {
    if (!SP.PageTwin.isSynthetic(token) && !(token instanceof P.LineToken)) own.push(token)
  })
  return own
}

Built B. With the bubbly look off, a page file now gets the colours Monaco gave it, and a few more.

  • The words inside a tag take the colours Spell code gives its twin: in <for card in its cards>, in and its are keywords and cards a member, as in for card in its cards.
  • Attribute names (loading) and the head's flags (notebook) are coloured, and so are the equals sign and a tag's closing angle.
  • Markup is coloured as HTML: tag names, attribute names, quoted values, and the angles, as in <tag />.
  • A {its rank} in markup is coloured as Spell.

How it works:

  • The colours come from the page's own parse, which already reads each tag as its twin. It keeps only the twin's tokens that really sit in the file, at their own places.
  • The twin's own words (to draw it, while waiting) stand at their tag with no text of their own, so they're left out. So is any token whose letters in the file aren't its own: a <for>'s loading="…" rider was placed on the prose line, and would have coloured r down as text.
  • Markup is read the way the bubbly look reads it (BubblyMarkup.treeOf()).
  • Spell code's colouring and this one share the parse step now (SpellHighlighter.matchSpans()).
