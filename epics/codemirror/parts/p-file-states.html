The test page's CodeMirror shows one file with no memory: switch away and back, and its undo and folds are gone.

  • On the test page, each file you open keeps its own text, undo and folds when you switch to another file and back, as the app's Monaco does.
  • It parses as typing pauses (200 ms), saves 2 s after an edit (answered on the test page, nothing written), and shows problems.
  • Edits made from outside the code (the Inspector, the side bar, a rename, the value picker) land in that same file state, so every view of the file follows.
  • Every CodeMirror editor starts from one base setup; the language service's answers reach it through one converter.
  • Every word CodeMirror shows is an AppTexts key, its Spanish in AppTexts.es.ts, loaded only on a Spanish page, and the editor follows the app's language (appTexts.lang), not a switch of its own.
  • The gutter is Monaco's: no line numbers, fold arrows over the bubbles' padding shown while the mouse is on the edge, no change bar.

One CodeMirror state per file, one base setup and one converter from the language service; CodeMirror's words in AppTexts; the gutter as Monaco's.

  1. One shared base (J4). The editor-free half of SpellModels moves into FileStatesBase, which both editors' file states extend, so epic editor's changes to it land once:
    • the parse wait and save wait, reading the existing PARSE_WAIT / SAVE_WAIT
    • use() / disposeProject(), saveAfterEdit()
    • applyEdits() and EditWay: the one way in for outside edits
    SpellModels keeps only Monaco's half. Its waits move to util's after() as they move, never a raw timer.
  2. One state per file (J5). FileStates, on that base: one CodeMirror state per file path, made on first use, kept across tab switches (text, undo history, folds, selection).
    • The same timings as Monaco's, from the base; problems from the language service.
    • The Inspector, the side bar, rename and the value picker hand applyEdits() ranges and text, one undo step each.
    • One "not typed" mark. Every edit that comes in this way carries one transaction annotation holding its EditWay, defined here with the file states; P4's typing helps read it to leave such edits alone.
    • The code pane, every Inspector slice and both diff sides will read these file states (P3, P6): nothing else keeps its own copy of a file's text.
  3. One base setup. CodeMirrorSetup: the extensions every CodeMirror editor takes (keys, history, the look's theme, the gutter, the phrases), as SpellMonaco.OPTIONS is for Monaco; the code pane, slices, the diff and the compiled code add theirs on top. SpellCodeMirror is built on it.
  4. One converter. LspToCodeMirror, the twin of LspToMonaco: positions, ranges, suggestions, hovers, problems and edits from the language service into CodeMirror's shapes. CodeMirrorLanguage's own position helpers move into it, and its tests come from LspToMonaco's.
  5. The Solid editors. CodeMirrorEditor and a CodeMirror FileEditor in a solid/codemirror folder, as Monaco's are, so the swap (P6) only changes which one each place imports. The test page shows them.
  6. Words through AppTexts (Q3). Each of CodeMirror's 33 phrases becomes an AppTexts key, with a small map from CodeMirror's English to the keys; our own words (OWN_WORDS: Go to Definition, Find…) become keys too. The Spanish goes into AppTexts.es.ts, lazy with the rest, with the two fixes the Overview names ("match case", "Revert this chunk"). CodeMirrorTexts goes. The phrases follow appTexts.lang, reconfigured when it changes.
  7. The gutter. No line numbers (View › Line Numbers turns them on, through a compartment); CodeMirror's fold gutter with its own arrow, a 16px column pulled 8px over the code, each arrow 4px toward it, hidden until the mouse is over the edge, a folded block's arrow always shown; a press folds without moving the caret. No change bar (Q1).
