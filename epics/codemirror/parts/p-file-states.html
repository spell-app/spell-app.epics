The test page's CodeMirror shows one file with no memory: switch away and back, and its undo and folds are gone.

  • On the test page, each file you open keeps its own text, undo and folds when you switch to another file and back, as the app's Monaco does.
  • It parses as typing pauses (200 ms), saves 2 s after an edit (answered on the test page, nothing written), and shows problems.
  • Edits made from outside the code (the Inspector, the side bar, a rename, the value picker) land in that same file state, so every view of the file follows.
  • Every CodeMirror editor starts from one base setup; the language service's answers reach it through one converter.
  • Every word CodeMirror shows is an AppTexts key, its Spanish in AppTexts.es.ts, loaded only on a Spanish page, and the editor follows the app's language (appTexts.lang), not a switch of its own.
  • The gutter is Monaco's: no line numbers, fold arrows over the bubbles' padding shown while the mouse is on the edge, no change bar.

One CodeMirror state per file, one base setup and one converter from the language service; CodeMirror's words in AppTexts; the gutter as Monaco's.

  1. A copy of SpellModels' editor-free half (J4). FileStates gets its own copy of the half of SpellModels that has nothing to do with Monaco; no shared base class, and the original is left as it is until P6 removes it:
    • the parse wait and save wait, reading the existing PARSE_WAIT / SAVE_WAIT
    • use() / disposeProject()
    • saveAfterEdit()
    • applyEdits() and EditWay: the one way in for outside edits
    The copy's waits use util's after(), never a raw timer. Until the swap the two are kept in step by hand: any change epic editor makes to SpellModels meanwhile gets copied over, and P6 checks it before deleting it.
  2. One state per file (J5). FileStates, with that half in it: one CodeMirror state per file path, made on first use, kept across tab switches (text, undo history, folds, selection).
    • The same timings as Monaco's, from the same two constants; problems from the language service.
    • The Inspector, the side bar, rename and the value picker hand applyEdits() ranges and text, one undo step each.
    • One "not typed" mark. Every edit that comes in this way carries one transaction annotation holding its EditWay, defined here with the file states; P4's typing helps read it to leave such edits alone.
    • The code pane, every Inspector slice and both diff sides will read these file states (P3, P6): nothing else keeps its own copy of a file's text.
  3. One base setup. CodeMirrorSetup holds the extensions every CodeMirror editor takes:
    • keys, history, the look's theme, the gutter, the phrases
    • as SpellMonaco.OPTIONS is for Monaco
    • the code pane, slices, the diff and the compiled code add theirs on top
    • SpellCodeMirror is built on it
  4. One converter. LspToCodeMirror, the twin of LspToMonaco:
    • it turns the language service's positions, ranges, suggestions, hovers, problems and edits into CodeMirror's shapes
    • the test page's own position helpers (in CodeMirrorLanguage) move into it
    • its tests come from LspToMonaco's
  5. The Solid editors. CodeMirrorEditor and a CodeMirror FileEditor:
    • in a solid/codemirror folder, as Monaco's are
    • so the swap (P6) only changes which one each place imports
    • the test page shows them
  6. Words through AppTexts (Q3). Each of CodeMirror's 33 phrases becomes an AppTexts key:
    • with a small map from CodeMirror's English to the keys
    • our own words become keys too (OWN_WORDS: Go to Definition, Find…)
    • the Spanish goes into AppTexts.es.ts, lazy with the rest, with the two fixes the Overview names ("match case", "Revert this chunk")
    • CodeMirrorTexts goes
    • the phrases follow appTexts.lang, reconfigured when it changes
  7. The gutter, as the Overview's left edge says:
    • no line numbers; View › Line Numbers turns them on, through a compartment
    • CodeMirror's fold gutter, with its own arrow: a 16px column pulled 8px over the code, each arrow 4px toward it
    • the arrows hidden until the mouse is over the edge; a folded block's arrow always shown
    • a press folds without moving the caret
    • no change bar (Q1)
