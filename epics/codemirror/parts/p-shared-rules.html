The typing rules, file addresses and settings live inside the Monaco folder, and the CodeMirror test page re-states some of them.

  • Nothing you see changes: the app still runs on Monaco, and every typing help works as before.
  • The rules behind the typing helps live in one place, the language service, beside LSP.SpellKeywords: where a letter on a blank line lands, which words open quotes, what a space after a tag writes, where Enter puts the caret.
  • Monaco and the CodeMirror test page both read those rules, so the test page stops re-stating three of them and gains the two it drops.
  • File addresses (spell:/…) are written by one helper with no Monaco in it, which the language service's scope explorer uses too.
  • The settings table (hover with ⌥, suggestions where they help), the shortcut table and the colour table each stay the ONE table: the test page's own copies go.

Spell's own rules move out of Monaco into one place each; Monaco and the test page both read them.

Monaco stays the editor, its tests green.

  1. Typing rules out of Monaco. SpellTyping's pure half (the static line readers: indent to add, indent to snap, opens quotes, tag before a space, open tag, comment indent, pasted lines, lines under) and its word tables move to a new LSP.SpellTyping in the language service, beside SpellKeywords. They read lines and columns only, so the language service stays browser-safe and editor-free.
    • Monaco's SpellTyping keeps only its event wiring and calls the shared one.
    • The Enter rules (SpellMonaco.CONFIGURATION's onEnterRules) become one editor-neutral table there; Monaco's configuration is built from it, and the VS Code check in the keywords test compares language-configuration.json with that table.
    • Its unit tests move with it to the language service's tests; the browser tests stay with Monaco until the swap.
  2. The test page uses them. CodeMirrorTyping drops its own copies of next-line indent, open quotes and space after a tag, and calls the shared readers; trim-on-Enter likewise.
  3. One address helper. AppAddresses is rewritten without Monaco's URI (plain string work on spell:/ plus encodeURI) and moves up to the app's ui folder. CodeMirror's CodeMirrorAddresses goes; the scope explorer's hand-built spell:/ asks the same rule (a shared constant in the language service, since it can't import the app).
  4. Language features, editor-neutral. What SpellLanguageFeatures works out without Monaco (which row the rename sits in, what a hover says, which code actions apply) is lifted into plain functions the CodeMirror side calls too, so the test page's CodeMirrorLanguage stops re-deriving it.
  5. One table each. CodeMirrorLanguage drops its own SUGGEST_WHERE_IT_HELPS and HOVER_MSEC and reads codePopups (suggestsByItself(), the hover delay); its menu's shortcut labels read EDITOR_HOTKEYS.
  6. One rule for a drawn tag. Both bubbly drawers ask the parser whether a tag is one of the project's own views (SpellJSX.isDrawnType(), reached through SP; exported there if it isn't yet), and drop their copies of its list of base types.
  7. Checked: yarn review in app/ passes with the Monaco tests unchanged in what they check; the test page loads headlessly, and typing a letter on a blank line, group and <action do the same in both editors (node epic/src/tools/check-spell.js from the kit's root).
  8. Left out: the Monaco-wired half of the typing helps (snap, paste, Shift+Tab ...) stays as it is; P4 gives CodeMirror its own wiring over the same readers.
