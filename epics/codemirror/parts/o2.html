The test's code in spell/app/app/ui/codemirror grows into the real editor layer; what's Spell's own, not either editor's, moves out of the Monaco folder first, so it's written once.

  • One state per file: a CodeMirror twin of SpellModels.
    • each open file keeps its text, its undo and its folds across tab switches
    • it parses as typing pauses (200 ms), saves 2 s after an edit, and shows problems
    • the code pane, every Inspector slice and the diff read the same one; edits from the Inspector, the side bar, rename and the value picker go through it
  • Typing rules in one place: the nine typing helps' line readers (SpellTyping's pure half) and the Enter rules move beside LSP.SpellKeywords; the editor keeps a thin adapter. The test page already re-states three of those rules and drops two.
  • One base setup every CodeMirror editor takes (like SpellMonaco.OPTIONS today), one converter from the language service (LspToCodeMirror, for LspToMonaco), one AppAddresses for spell: file addresses.
  • Settings and keys stay where they are: codePopups (hover with ⌥, suggestions where they help) and EDITOR_HOTKEYS drive CodeMirror as they drive Monaco; the test's own copies go.
  • Colours: one table from token to --ui-code-* colour (CodeRules); with the bubbly look off, Spell and page files are coloured by the parser's own token pass, as Monaco's tokens provider does now.
  • The right-click menu is Spell UI's, one popup shared with the Palette's <PartMenu>, its shortcuts from EDITOR_HOTKEYS.
  • Still lazy: CodeMirror loads after the parser compiles and the app runs, never in the main bundle.
