Your question: is it the uneven room after a block ends? Partly.

  • The lines that moved were the last lines of blocks, the ones with feet under them:
    • turn over the next card
    • pause for 500 msec
    • reset the stock
  • Each grew or shrank by 13-25px, several of them above the caret.
  • But CodeMirror wasn't re-measuring them at each key.

This is what happened:

  1. You type a letter. The marks just move along with the text, and nothing changes height.
  2. 150ms later, the pause's layout redrew the file from its own text alone. That drew those feet shorter.
  3. 50ms after that, the project's parse came in and drew them full height again.

So the caret's line jumped twice, by up to 101px. Keys a loaded machine handles more than 150ms apart triggered both jumps on every key: at 300ms a key, 20 keys moved the caret's line 33 times.

Fixed:

  • The pause now waits for the project's parse (4s at the most) and doesn't draw the file from its text alone. The parse draws it once.
  • When a new layout changes the heights above the caret, the caret's line stays where it was on screen. This holds while you're typing and the caret is on screen (CodeMirror's own scroll snapshot, put on the caret's line).
  • Typing was slow because each key made the browser lay the whole code pane out 3 extra times:
    • two hidden probes (tab stops, the selection's band height), and the gutter being rebuilt at every key
    • now each runs only when something it depends on changes
