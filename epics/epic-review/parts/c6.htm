A review run from a worktree session, of an epic whose doc is on the main checkout, writes its marks into main's file, but can't commit them there.

  • Why: worktree sessions refuse git -C on the main checkout.
  • The marks land in main's working tree, uncommitted.
  • The next session in main, or you, commits them.
  • "Finish Review" must say so: the epic skill names the checkout holding uncommitted marks.

Net effect:

  • after such a review, main shows the plan doc as changed until someone commits it
