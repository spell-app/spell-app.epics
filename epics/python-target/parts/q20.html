  • The catch: a drawing reads more than its type's properties.
    • Solitaire's card reads three getters: its short rank, its colour, and whether it's face down.
    • Its stock pile's placeholder calls a program function when clicked, play_from_the_stock_pile().
    • A card's click fires an event, card-click, which the game handles in Python.
  • The card's drawing, as compiled Python writes it today:
 
def draw(self):
    class_name = f"Card face-{self.direction} {self.rank} {self.suit} ui button compact fluid "
    if self.is_face_down:
        return h(
            "div",
            {"class": class_name, "onClick": lambda event: core.trigger("card-click", card=self)},
            h("i", {"class": "fitted bicycle icon"}),
        )
    return h(
        "div",
        {
            "class": class_name + self.color,
            "onClick": lambda event: core.trigger("card-click", card=self),
        },
        f"{self.short_rank} ",
        h("span", {"class": "suit"}, self.short_suit),
    )
  • Per type: its properties, the getters its drawing reads (and what they read in turn), its to draw, and its styles.
  • Left in Python: every method that changes things, and every event handler.
  • A function the drawing calls (auto_play()) is written as a stand-in that sends the call to Python.
  • Cost: the writer works out what a drawing reads, a walk over the tree; a getter that changes things is an error at compile time.
  • Why: the page can only draw; nothing it runs can change the game behind Python's back.
  • The bundle is the JavaScript compile as it is (always compiled anyway), run on the page as a mirror.
  • The page never calls its methods; events and calls are sent to Python instead.
  • Cheapest to write: nothing to work out.
  • Cost: all the game's logic ships to the browser, and a method run there by mistake changes only the mirror, silently.
  • No JavaScript compiled from the program: Python draws HTML as it does today (P12) and sends it; each click handler gets an id the page sends back.
  • The way Phoenix LiveView and htmx work.
  • Simplest, reuses P12 whole; but it isn't what Owen asked: no web component per type, HTML over the wire.
  • a new writer beside the JavaScript one, writing <Project>.elements.js for the py targets
  • the page holds no logic; every click goes to Python
