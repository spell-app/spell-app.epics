For P20 · Quart Spell Apps: what does a Python programmer see of the Flask app, and how do they start it?

  • A Flask app is usually a small file a person owns, app = Flask(__name__), with their own routes added to it.
  • The question is whether spell writes that file, or spell_core hands one over, ready to add to.
  • create_app() in spell_core returns a Flask app for a compiled program: Flask's own "app factory" pattern.
  • A person adds routes to it, as to any Flask app.
  • Nothing new is compiled: the Python file stays the program, and only the program.
# from a terminal
#   uv run python -m spell_core.web Solitaire.compiled.py --seed 1

# or in a file of your own
from spell_core.web import create_app

app = create_app("Solitaire.compiled.py")

@app.get("/high-scores")
def high_scores(): ...
  • Compiling to Python also writes Solitaire.app.py, a Flask app with every route spelled out.
  • Easy to read and change; a person sees the whole server.
  • Cost: a generated file a person edits, overwritten at the next compile, or never updated again.
  • The Python writer writes the routes into the compiled program itself, when it draws an app.
  • One file to run, flask --app Solitaire.compiled run.
  • Cost: every compiled app needs Flask, even to run in a terminal or in the core contract.
  • a web module in spell_core: create_app(), and a command that runs it
  • the compiled program is unchanged
  • Named Solitaire.app.py, beside Solitaire.compiled.py; compiling again rewrites it only while nobody has edited it: J45.
  • Written by the py/asyncio target (Q23), on spell-quart (Q26).
  • P20: the py/asyncio target writes a second file, the app
  • run with uv run python Solitaire.app.py
