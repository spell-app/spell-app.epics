spell_core is the Python twin of the core: what compiled Python imports to do what Python has no word for.

  • It lives in the py package, in its core folder, beside spell-quart and the TypeScript that writes Python:
    • a pyproject.toml and a spell_core folder, the standard Python layout
    • pytest and ruff, run through uv run
    • py's yarn test runs its tests, so yarn review does too
    • It began inside the core package, beside the JavaScript it ports (Q6); since P21 it has been in py.
  • What it ports (about 3,000 of the core's 4,450 lines are plain logic):
    • things, with declared properties (a plain dictionary, no reactivity)
    • spell lists: owners ("a card belongs to one pile"), guards, moving between lists
    • types and equality
    • spell's tests: expect, the ✅ / ❌ lines, the indented groups
    • events (on, trigger) and processes
    • pauses
    • JSON with "@type" and "@items"
    • the seeded random and its shuffle (below)
  • What it doesn't:
    • drawing with Solid, on a live page: spell_core draws HTML text instead (P12)
    • the Thing Explorer's registry
    • the old names marked deprecated
  • A machine-readable list of the core's methods comes first, so the port can't miss one:
    • written in the format projects already write for themselves (<Project>.declarations.json): spellCore.declarations.json
    • generated from what a core must have, committed, and tested against the core's exports
    • a test checks spell_core against it, in snake_case; a missing method fails, unless listed as not ported
    • It found four methods spell writes that the core didn't have: absoluteValue, which P5 added, and three for rounding (I3).
      • Since P24, rounding needs no core method: each target says it in its own words, e.g. Math.ceil() and math.ceil().
  • A seed owned by the core (Q13; Owen: "add runtime seed mechanism to JS/spellcore"):
    • spellCore.seedRandom(n), after which every random is repeatable
    • its own number generator and shuffle, with no lodash and no Math.random
    • spell_core copies them exactly, so one seed deals the same cards in both
    • the contract seeds through it, rather than patching Math.random from outside
  • The list and the seed are built in P5 · Core List And Seed; spell_core starts in P6 · spell_core Basics.
  • Python 3.13 and uv are on this machine; compiled Python needs 3.12 or later (Q11).
