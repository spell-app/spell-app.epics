Should every tab of one browser share one Solitaire game, as it does today, or should each tab get a game of its own?

  • Owen asked, trying the Python web app (V6) on 2026-10-11: "Use sessionStorage rather than localStorage?"
  • The page uses neither today.
  • A browser is ONE visitor to the server, named by a cookie (spell-visitor), so every tab of that browser plays the same game.
    • That is by design: V6's own expected result says a second tab shows the same game and follows the clicks.
    • The trouble Owen saw was a bug in how the server sent to each tab, now fixed (I17): the tabs stay in step.
  • A game of its own per tab would mean naming the visitor by an id the page keeps in sessionStorage, which each tab has its own copy of, instead of by the cookie.
  • Every tab of one browser shows the same game, and follows the others' clicks.
  • A second browser, or a private window, gets a game of its own.
  • Nothing to build: this is what the server does now that the bug is fixed.
  • The page names its visitor by an id kept in the tab's sessionStorage, not by the cookie.
  • Reloading a tab keeps its game: the tab's id survives the reload.
  • Duplicating a tab copies its sessionStorage, so the copy shares the original's game.
  • Closing the tab ends its game: the id is gone, and the server's copy waits to be cleaned up.
