Only FizzBuzz runs in Python: there are no things, spell lists or spell JSON yet.

Things become Python classes with declared properties; spell lists become real Python sequences.

Cards, and the copy that counts from 0, print what JavaScript prints.

  • A thing is a Python class:
    • its properties declared in the class body, with prop()
    • getters as @property
    • statics, and the class's set-up, in the class body
    • made by keyword: Card(rank="queen", suit="spades")
  • A spell list is a real Python sequence (a MutableSequence):
    • owners ("a card belongs to one pile"), exclusive families and guards
    • moving between lists
    • native indexes, by the project's listsStartAt
  • Where the kinds are known, they decide equality, truthiness and f-strings; where not, a core call does.
  • JSON with "@type" and "@items" reads back as the same things.
  • Cards and CardsFromZero compile to Python that prints exactly what their javascript prints. The core contract checks it on every run; see Cards.snapshot.py beside the test program.

    • class Card(Thing):, with its docstring
    • constants as tuples, properties declared with prop()
    • @property getters
    • things made by keyword: Card(rank="queen", suit="spades")
    • Python's own words for lists: len(deck), card in pile
    • Python's own indexes: deck[2]
    • f-strings, isinstance(), and a lambda for a block passed along
