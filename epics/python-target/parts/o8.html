Owen added two phases on 2026-10-11, after Doc Review: a Python spell app becomes a web app, its logic in Python on a Flask server, its drawing in the browser.

  • His words:
    • P17 · Web Components For HTML: "python compiler outputs compiled JS web components for the HTML bits"
    • P18 · Flask Spell Apps: "spell apps" in python are python flask based apps, using these web components
  • Why it's new ground: P12 made Python draw HTML TEXT, printed when the program ends, so nothing can be clicked. The browser half already exists for JavaScript: a drawable thing is its own element, <solitaire-card>, on the editor's runtime.

What would happen, step by step, with the recommended answers (each step's fork linked):

  1. Compiling Solitaire to Python writes the Python as today, and beside it the drawing half in JavaScript: each type's properties, the getters its drawing reads, its to draw and its styles (Q20).
  2. One command starts a Flask server for the program (Q25); the program runs once, and deals the cards (Q24).
  3. The browser opens the page: Spell UI, the spell runtime, the drawing half, and the program's things as JSON, each with an id (Q21).
  4. The page rebuilds the things as stand-ins, and its elements draw the board.
  5. A click on a card sends card-click and the card's id to the server (Q22).
  6. Python finds that card, and runs the game's on card-click, in the plain py target (Q23).
  7. The new state streams back to the page, after the handler and at each pause in it, and the page redraws only what changed.
  • Flask is installed only for a web app; spell_core stays standard library only (Q26).
  • The seven questions are open: P17's two (Q20, Q21) before it starts, P18's five (Q22 to Q26) before it does.
