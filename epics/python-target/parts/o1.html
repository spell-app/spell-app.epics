Python becomes a third target: spell compile FizzBuzz --target py writes FizzBuzz.compiled.py, and it runs under python3.

  • Four pieces, as the targets guide's "Adding a target" lists them:
    • a WRITER, PyWriter, walking the same spell tree the JavaScript and TypeScript writers walk
    • an entry in the targets table, SP.TARGETS: py
    • a RUNTIME, spell_core: a small Python package, the Python twin of @spell-app/core
    • a place in the core contract: the five test programs print the same lines on every target
  • Three things change for the JavaScript targets too, because Python needs them first:
    • a project can count its lists from 0 ("Lists start at 0", 1.3)
    • each target says in one table how it writes names ("Names by target", 1.5)
    • the tree holds spell's own names, not JavaScript spellings like is_a_$suit or 'up'
  • The editor, the runners and the language server still run the JavaScript target: Python is compile-only.
    • A project asks for it in its project.json: "targets": ["py"].
    • --target py asks for it on one run.
  • the JavaScript writer: 1,601 lines; the TypeScript writer on top of it: 1,278
  • the facts both writers share about a project (getters, members, item types): 525 lines, mostly reusable
  • the core: about 4,450 lines; the plain-logic part a Python port needs, about 3,000 of them
  • a first spell_core in Python: roughly 1,500 lines to run Cards and Solitaire's logic
