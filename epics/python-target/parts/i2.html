As the brief asked, the JavaScript core with no seed picks one with Math.random(), so each run deals differently, as today. Python's core (P6) always starts from seed 1, so every unseeded Python run deals the same cards.

The contract passes seed 1 to both, so its snapshots agree. A person running a Python program twice, though, gets the same game twice.

Net effect (once fixed):

  • Python's core starts from a random seed too, unless the runner passes --seed (the Python runner, P9, would pass it on)
  • its test that a new core starts from seed 1 changes to seed explicitly
