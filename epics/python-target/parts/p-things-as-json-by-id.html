Python's things can't leave the Python process as themselves: spell_core's JSON has no identity.

  • A card held by a pile and by the game comes back as two cards.
  • Nothing can be found again by its id.

spell_core writes the program's whole state as JSON: every thing once, with an "@id", and each later mention a reference to that id (Q21, A).

It reads that JSON back by id, so a card in two places is one card, updated in place when a newer state arrives.

The javascript core reads the same JSON into mirrors, the stand-ins P19's web components draw from. No page and no server yet: tested in Python, and in TypeScript.
