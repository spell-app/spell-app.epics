For P25, Hints For The Unknown: how compiled Python tells the checker a value that may be nothing is there.

  • Owen (cm17): "python has a `<type> or Null` or something like that, right? Can we use that?"
  • It does, and compiled Python already writes it: X | None, as in def pile(self) -> Pile | None.
  • The 9 pinned errors (C3, J38) come from USING such a value as if it's there.
  • The fix is narrowing: telling the checker that at this point the value is there.
  • 7 of the 9 are this kind, in Solitaire, Klondike and OutlineSolitaire: a card's pile, a list's last item, a number that may be nothing.
  • The other two aren't: a value spell only knows as an object, called; and a method set on another project's class (J54). P25 looks at each on its own. 
def can_take(self, card: Card) -> bool:

  • Where spell can tell a value is there (the last item of a list it just checked isn't empty, a card that's always on a pile), the hint leaves out | None.
  • Clean code, no extra lines; needs spell to know more, so it covers only some of the 7.
  • In order:
