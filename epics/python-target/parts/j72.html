Owen asked, on Q29, for each platform's own rounding, and a core.round() only if needed.

  • Round up and round down were easy: math.ceil() and math.floor().
  • Plain rounding needed a choice, because Python's own round() doesn't round a half the way javascript does.
  • What compiled code says now:
    spell javascript Python
    round price Math.round(price) math.floor(price + 0.5)
    round price up Math.ceil(price) math.ceil(price)
    round price down Math.floor(price) math.floor(price)
    • Python has import math at the top, first, as PEP 8 orders the standard library.
  • Why not the others:
    • Python's round() takes a half to the even number: round(2.5) is 2, javascript says 3.
    • decimal's ROUND_HALF_UP takes a half away from zero: -2.5 becomes -3, javascript says -2.
  • math.floor(x + 0.5) gives what javascript gives for every number the new test runs.
    • The test, rounding.test.ts, compiles: 2.5, -2.5, 2.4 and 3.5 rounded; 2.1 and -2.1 up; 2.9 and -2.9 down.
    • It RUNS the Python, and checks it prints what javascript's Math does.
  • Plain Python a reader can follow, and the same answers as javascript, halves and negatives too.
  • Reads shorter, but hides one line of arithmetic behind a core method Owen asked to avoid if not needed.
  • The most Pythonic word, but 2.5 rounds to 2: a program prints differently in Python than in javascript.
  • spell's rounding prints the same on every target; no rounding method in either core
