For P25, Hints For The Unknown: how compiled Python marks a value whose kind spell doesn't know.

  • Owen (cm8): "Would be good to flag where spell doesn't know, what's the pythonic way to do that?"
  • Today compiled Python leaves such a value with no hint at all, so a reader can't tell "spell doesn't know" from "nobody wrote one".
  • The Pythonic way is typing.Any: the type checkers' own word for "could be anything, don't check it" (PEP 484). A parameter with no hint is treated as Any anyway, so writing it changes no check, only what the reader sees.
  • object means something else: "anything, and you may only do what every object can", so suit.name is an error. 
def is_a_suit(self, suit) -> bool: ...           # today:  no hint
def is_a_suit(self, suit: Any) -> bool: ...      # A:  spell doesn't know, said so
def is_a_suit(self, suit: object) -> bool: ...   # C:  every use of suit checked as a bare object
  • Every unknown parameter, property and return says Any; from typing import Any where a module uses it.
  • pyright checks exactly what it checks today.
  • A reader, or a search for Any, finds every place spell couldn't tell.
  • Shorter lines; the same checks.
  • "spell didn't know" stays invisible.
  • Strict: pyright reports every use of such a value as an error.
  • Many new pinned errors in programs that run correctly.
  • compiled Python says Any wherever spell can't tell a value's kind
  • pinned pyright output unchanged by this part

Owen picked A. P25 builds it.
