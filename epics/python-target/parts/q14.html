When a spell name would clash with something Python owns, the writer does what PEP 8 says. Owen: "python tends to use __xxx__, check out python docs canonical uses".

What PEP 8 says (Descriptive: Naming Styles):

  • single_trailing_underscore_: "used by convention to avoid conflicts with Python keyword", as in class_.
  • __double_leading_and_trailing_underscore__: "magic" objects. "Never invent such names; only use them as documented."
  • _single_leading_underscore: marks a name for internal use.
  • __double_leading_underscore: makes Python mangle the name inside a class.
  • cls is the first argument of a class method.

So, in compiled Python:

  • a spell name never becomes a dunder (a "double underscore" name like __init__)
  • a keyword gets a trailing underscore: class_, from_
  • so does a local that would hide a builtin: list_
  • spell_core implements the documented dunders, so Python's own words work on spell's lists and things:
    • __len__: len(deck)
    • __iter__: for card in deck
    • __contains__: card in pile
    • __getitem__: deck[0]
    • __eq__: a == b
    • __repr__: what printing a thing shows
  • the clash rules and the dunders are built in P7 · Python Names
