Klondike adds a method, to play a card, to Cards' Card class. Since P18 compiled Python set it on the class after the function (J54): Card.play = _card_play. pyright refused that line (Klondike 313: "Cannot assign to attribute play for class type[Card]"): a class doesn't gain an attribute by assignment, as far as pyright knows.

  • spell_core's SpellObject gained two class decorators: add_method(name) and add_property(name) (a getter, as @property).
  • Klondike, before: 
    async def _card_play(self) -> bool | None:
    ...


Card.play = _card_play
  • After: 
    @Card.add_method("play")
async def _card_play(self) -> bool | None:
    ...
  • This is J54's alternative B, now taken. The decorator says where the method goes right above the function, and the error is gone.
  • In things.py, with tests in test_things.py.
  • pyright accepts it, and the reader sees the target class before the body.
  • Hides the error rather than fixing it, and the line still sits after the body.
  • pyright stays quiet, but it reads as a trick; no better for the reader than the assignment.
  • a method one project adds to another's class is written @Card.add_method("play") above its function
