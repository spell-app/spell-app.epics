Owen named one helper, position(), for a position going in. A range needed one more, endPosition(), because spell's ranges include their end and slice() leaves its end out.

  • "items 2 to 4" is slice(1, 4): the start goes through position(), the end stays as it is.
  • A number written out is worked out as it compiles: deck.slice(1, 4), deck[1:4].
  • One known only when it runs goes through endPosition(n).
    • javascript: deck.slice(1, endPosition(n))
    • Python: deck[1:end_position(n)]
    • -1, the last item, gives no end, so the range runs to the end.
      • No end: undefined in javascript, None in Python.
    • Further from the end, one on: -2 gives -1.
  • The other two: spellPosition(), a position coming out ("the position of the ace"), and withSpellPositions(), for a loop whose function takes the position.
  • One short call, right for every end spell can say, the last included.
  • No new name, but wrong for the last item: position(-1) + 1 is 0, an empty range.
  • "items 2 to n of the deck" compiles to deck.slice(1, endPosition(n)) / deck[1:end_position(n)]
