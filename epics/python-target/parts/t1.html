  • Only if P15 · Terminal Drawing Study recommends it; its prototype and findings decide.
  • Owen's idea behind it: "python programs could translate widgets/etc into CLI programs" (Q2).
  • Likely its own future epic: a new target in the targets table, and a terminal half of spell_core (Textual, say).

P15 recommends it: a py/terminal target on Textual, as a future epic of its own. The findings are in 1.7 Drawing in a terminal, and its choices in A terminal target?.

  • The prototype drew Solitaire's board from the same element tree h() makes, in a live terminal app, and a click on a card fired card-click with that card.
  • Textual is the pick: of Ink, Textual and Rich, only it has mouse clicks, a style sheet that reads the page's class names, a headless test driver, and a way into the browser (textual-serve).
  • Its steps, roughly:
    1. spell_core's h() builds a tree, which still prints as the same HTML
    2. a terminal half of spell_core draws the tree with Textual, clicks calling back
    3. a style sheet: a plain one for Fomantic's classes, and a project's own beside its CSS
    4. Spell UI's elements as Textual's widgets
    5. redrawing only what changed
    6. the contract clicking through a game, headless
  • About 20-30 hours. Rich's still picture of the board (option C there) is a cheap first step of it.
  • Where to start: the prototype, in experiments/terminal/.
