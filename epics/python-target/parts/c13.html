Owen wants both modes (Q34, 2026-10-12): a browser's tabs sharing one game, or each tab its own.

  • Today: a browser is one visitor, by the spell-visitor cookie, so its tabs share a game and follow each other.
  • Per tab: the visitor named by an id kept in sessionStorage, sent on the WebSocket instead of the cookie.
    • A reload keeps the tab's game; closing the tab ends it; a duplicated tab (Chrome's right-click, Duplicate) shares its original's.
  • Where the flag goes, Owen's words: "probably in <spell-app> and some sort of flag in the spell english".
    • An attribute on <spell-app>, e.g. <spell-app src="..." players="per-tab"> (name to settle).
    • A line in the program, e.g. each tab plays its own game (wording to settle), compiled into the app's settings.
  • Both targets: spell_quart's SpellSessions for Python, and the javascript side once Spell Server State exists.
  • An app chooses shared or per-tab games; shared stays the default.
