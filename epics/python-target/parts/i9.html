Each change to a spell list writes a new Python list of its items, as JavaScript's copy-on-write items do.

  • Why: for card in pile sees the items as they were when the loop started, even while the loop moves cards out.
  • The cost: O(n) per change, so building a list one append at a time is O(n²).
  • Fine for a deck of 52; slow for many thousands of items.
  • a non-exclusive list could change in place, and copy only when a loop is running, if it ever matters
