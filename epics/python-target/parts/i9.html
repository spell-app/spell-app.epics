Each change writes a new Python list of items, as JavaScript's copy-on-write items does. That way for card in pile sees the items as they were when the loop started, even while the loop moves cards out. The cost is O(n) per change, so building a list one append at a time is O(n²). That's fine for a deck of 52, but slow for many thousands of items.

  • a non-exclusive list could change in place, and copy only when a loop is running, if it ever matters
