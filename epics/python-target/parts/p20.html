After every click, and at every pause, Python draws the whole page again and sends all of it with the whole state: a few kilobytes for Solitaire, too much for a bigger program or a slow connection.

spell_core notes each property set and each list change, and sends only those, by id, to the page's mirrors (Q21, B).

Python redraws only the things that changed, or whose drawing read something that changed, and sends each one's HTML under its spell-id.

A safety net compares the patched page with a whole drawing, so a missed change fails loudly in tests.

  • Only the drawings that changed.
    • While a thing draws, spell_core notes which things its drawing reads, as Solid notes what an effect reads.

    • The page morphs each one in by its spell-id (J43).
    • When a change can't be placed (the app itself redraws, a new thing at the top), the whole page is drawn, as in P17.

    • a difference is an error naming the thing; the tests run with it on
