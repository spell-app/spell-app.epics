For P19, where Python keeps drawing the page (Q20, C), spell_core's drawing gains a web mode that writes the same HTML as today plus a few marks the page client reads.

  • Each event handler gets an id for this drawing, as an attribute named for its event: spell-on-click="h12".
    • Python keeps the handler (the card's lambda) under that id until the next drawing.
    • A click on the page sends the id back; Python runs that handler.
    • The lambda already holds the real card, so no thing is looked up by id to run a click.
    • An id from an older drawing (a click racing a redraw) is ignored, with a warning on the console.
  • Each thing drawn carries its id and type on its drawing's outermost element, spell-id="17" spell-type="Card": what the page swaps by.
  • Its plain properties as attributes (Q21, C):
    • on a drawable thing's own tag, bare, as the browser's elements read them: <solitaire-card rank="queen">
    • on any other thing's drawing, under data-
      • so they never clash with the drawing's own attributes, like class or style
  • A drawing that isn't one element (text, or a list of elements) is wrapped in a <spell-thing>, so every thing has one element to carry its marks.
  • Off by default: the core contract's HTML stays exactly as P12 left it.
<div class="Pile Tableau staggered" spell-id="9" spell-type="Tableau" data-name="T1">
  <div class="Card face-up queen spades ui button compact fluid black"
       spell-id="17" spell-type="Card" data-rank="queen" data-suit="spades" data-direction="up"
       spell-on-click="h12">Q <span class="suit">♠️</span></div>
</div>
  • spell_core's h() keeps handlers in web mode, and draw_thing() marks each thing's element
  • the spell- and data- names are the page client's whole contract with Python
