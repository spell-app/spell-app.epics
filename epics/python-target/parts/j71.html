A Python slice and the core's range_between() read the same range the same way, but for one case: a start further back than the first item.

  • A deck of 5, from item -10 to item 2:
    • Python's slice clamps the start: deck[-10:2] is the first two items.
    • core.range_between(deck, -10, 2) gives nothing, as javascript's spellCore.rangeBetween() does: a position before the first reaches no item.
  • Compiled Python writes the slice for a spell list, and the core call only for a value it can't slice.
  • Python's slices stay plain Python; no spell program the tests run says such a range.
  • The same answer everywhere, but a spell list's slice would then act unlike Python's.
  • a range starting before the first item reads the front of the list in Python, nothing in javascript
