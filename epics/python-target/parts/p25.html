Where spell can't tell what kind a value is, compiled Python has no hint at all, and pyright pins 9 errors in the solitaire games (C3, J38).

A value spell can't tell is hinted Any, on purpose, so a reader sees spell doesn't know.

A value that may be nothing is checked before it's used, so pyright knows it's there, and the pinned errors go.

  • Owen, on the durable doc, word for word:
    • cm8, on "Hints go only where spell knows what kind a value is; where it can't tell, there's no hint at all.": "Would be good to flag where spell doesn't know, what's the pythonic way to do that?"
    • cm17, on "All but one are a value spell's tree says may be nothing, used as if it's there: a card's pile, a list's last item.": "python has a `<type> or Null` or something like that, right? Can we use that?"
  • Unknown kinds: hinted Any, Python's own word for "could be anything" (Q30, recommended). def is_a_suit(self, suit: Any) -> bool, where it has no hint today.
  • "Type or nothing": Python writes it X | None, and compiled Python already does: def pile(self) -> Pile | None. The errors come from using such a value as if it's there. The fix is narrowing, telling pyright it's there at that point: Q31 (recommended: spell's own knowledge where it has it, an assert x is not None where it doesn't).
