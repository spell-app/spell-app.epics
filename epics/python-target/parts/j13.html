spellCore.declarations.json lists one entry per name on spellCore, then the names compiled code imports by name: Thing, List, App, Drawable, DrawableList, h, positionOf, on, off, once, trigger.

Chose to leave some names out, rather than list everything on spellCore, because the list is what another core must have:

  • names starting with _, e.g. _randomKeyOf(): the core's own helpers, which compiled code never calls
  • the old names deprecated.ts keeps for programs compiled before they changed
  • prop, derived, drawn and the other decorators: only compiled TypeScript imports them

Also chose:

  • Drawable and DrawableList are in, though the brief's list didn't name them: compiled javascript imports them.
  • Each entry has one key more than a project's declarations, module: the core's file it's in, e.g. collection-core, so the Python port can find it.
  • No spellVersion or version: the core can't import the language's version, no project imports this file, and a version would make the file go stale at every version bump.
  • the list has 127 names on spellCore and 12 imported names
  • a test checks every other name on spellCore is listed, so a new module can't be missed
