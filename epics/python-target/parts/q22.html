For P20 · Quart Spell Apps: a click on the page must reach Python, and what Python changed must reach the page. Over what?

  • The catch is pauses: Solitaire's auto-play moves a card, pauses 100 msec, moves the next.
    • In the editor's runner, each move shows as it happens.
    • Over the web, the page sees a move only if the server can tell it, mid-handler.
    • A program can also change things on a timer, with no click at all.
  • Three ways browsers and servers usually talk:
  • The page posts each click or call to the server, one small request each.
  • A stream the page keeps open, server-sent events, carries each new state to the page: after the handler, and at every pause inside it, so auto-play animates.
  • Plain Flask does it (a response that keeps writing); no extra package. The browser reconnects by itself.
const stream = new EventSource("/stream")
stream.onmessage = (message) => spellCore.updateFromJSON(message.data)

// a click on a card
fetch("/events", { method: "POST", body: JSON.stringify({ event: "card-click", card: { "@id": 17 } }) })
  • The simplest: one request, one answer, nothing kept open.
  • Cost: a handler that pauses shows only its end (auto-play jumps to the finished board), and a change made on a timer never shows until the next click.
  • One connection carries clicks up and changes down.
  • Cost: a second package (Flask has no WebSockets of its own: flask-sock, or Flask-SocketIO), and Flask's server then needs a thread, or gevent, per open page.
  • More than a game's clicks need.
  • two routes beside the page: one the page posts clicks to, one stream it listens on
  • spell_core's pause tells the stream before it sleeps
  • The cost the question named, a second package and a thread per open page, goes with Flask: Quart (Q23) has WebSockets of its own, on asyncio, so one thread serves every page.
  • The page client (J43) opens /ws when the page loads; Python sends a drawing after each handler, and at each pause inside it, so auto-play animates.
  • P20: one WebSocket route, /ws, in the app file
  • a pause sends the drawing before it waits
