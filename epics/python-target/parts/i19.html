spell_core's class registry holds only the last run's classes, so on a server with several visitors it can read an earlier visitor's JSON as the wrong classes.

  • The server runs the program once per visitor; each run defines its own classes, and the registry keeps the last.
  • Reading JSON back into things (from_json(), and the state mirror) looks classes up there by name.
  • So an earlier visitor's JSON would come back as the latest run's classes.
  • Nothing on the server reads JSON back today, so it bites no one yet.
  • References avoid it: they find a type among the things themselves.

Net effect (once fixed):

  • Reading JSON back is right for every visitor, e.g. a registry per run, or classes found from the run's things.
