pause for 50 msec makes JavaScript methods async. Should Python's be async def too, or plain functions that sleep?

  • The catch: compiled JavaScript calls async methods without waiting for them. Card's turnOver() calls this.turnFaceDown() bare. In JavaScript that still runs; in Python, an async def called that way does NOTHING, so "the card is face down" would fail.
  • Python without a page has no animation to wait for: a pause only slows the program down.
  • def turn_face_up(self), and core.pause_for(50, "msec") calls time.sleep.
  • The simplest Python, and what a person would write for a script.
  • A test run can make pauses instant.
  • Limit: "wait for" and two things running at once (Solitaire's animations) run one after the other.
  • Matches JavaScript's shape; every caller of a pausing method becomes async too, and awaits it.
  • The writer must add the awaits JavaScript leaves out, or start tasks.
  • Heavier Python: asyncio.run(main()), await on many lines.
  • no async in compiled Python; core.pause_for() sleeps, instantly in tests
