Chose to track changes on one side only: Python, where the program runs, writes patches; the javascript core, on the page, only reads them.

  • Python tells each state writer of every change to a thing's property or a list's items, so patch() knows what to send.
  • The javascript core's writer writes whole states only, and its mirror reads both whole states and patches.
  • Why: the page never sends state back, only events: a click names a card by id, and Python does the rest.
    • So nothing on the page ever needs to send a patch.
