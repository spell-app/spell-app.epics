Python has no WeakMap whose value lives only as long as its key, which is what JavaScript's ListFamily relies on. A strong link to the pile would keep every pile, and every card in it, alive for the whole run. So I chose weak links both ways over that leak. The cost: a pile that nothing but its own cards holds is let go, and its cards then have no owner. JavaScript keeps that pile alive.

  • Pile([card]) thrown away straight off leaves card.pile as None
  • a pile the program keeps, in a variable or a list of piles, behaves exactly as in JavaScript
