Q21's options were written for a page that draws itself from the program's state (Q20, A). Owen chose Python drawing (Q20, C), then A and B as later phases. So what A and B are FOR changes; here is how P19 and P20 read them.

  • With Python drawing, the page doesn't need the state to draw: every drawing arrives as HTML.
  • P19 (A, the whole state by id): the page keeps a mirror of each thing beside Python's HTML.
    • Gives: code on the page can read the real things (a hand-written element, a host page, a test, a Thing Explorer later).
    • Costs: the state travels beside every drawing, though nothing on the page draws from it.
  • P20 (B, only changes): the changes to the mirrors, AND only the drawings they touch.
    • The second half is the one that saves most: Python redraws and sends a card, not the page.
    • That is how Phoenix LiveView works too: it sends only the parts of a drawing that changed.
  • If Owen meant A and B as steps toward the page drawing itself, that is Q20's A coming back: P19 and P20 would grow a JavaScript drawing per type.
