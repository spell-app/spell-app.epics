For P21, Python Package: what goes in the one place Owen asked for, and what it is called in code.

  • Owen asked for one place for "all of the python stuff" (cm1, cm16).
  • spell_core and spell-quart are Python, so they clearly move.
  • The open part is the TypeScript that WRITES Python, which lives in parser today beside the javascript writers.
  • And what the new package is called in code.
  • The TypeScript in question:
    • PyWriter and PyAsyncWriter: the parsed tree as Python
    • pyText: Python's blocks and indents
    • ElementsWriter: a Python program's drawing half, in javascript, for its page
    • quartApp(), in spell: the app file's text
  • They are built on parser's shared writer, P.ProgramWriter, and its helpers, so a py package imports parser either way.
  • A namespace is the package's short name for itself in code (WWOD §8):
    • parser's is P
    • spell's, SP
    • core's, SC
 
// today
py: { name: "py", writer: P.PyWriter.instance, ... }
// A:  import { PY } from "$/py"
py: { name: "py", writer: PY.PyWriter.instance, ... }
  • spell_core, spell-quart, the Python writers, ElementsWriter and quartApp all live in packages/py.
  • Imported as $/py; its namespace PY, as the other packages have one.
  • Anyone looking for "how spell becomes Python" finds it all in one folder, Owen's ask.
  • Cost: parser's writers barrel loses four exports; spell's targets import one more package.
  • new workspace @spell-app/py
    • alias $/py
    • namespace PY
  • P.PyWriter becomes PY.PyWriter
  • SP.quartApp() becomes PY.quartApp()
  • dependency arrows: spell -> py -> parser
  • packages/py holds spell_core and spell-quart; the TypeScript writers stay in parser, beside JSWriter and TSWriter.
  • All writers stay together, but "all of the python stuff" is in two places again.
  • No new alias: py would be a folder of Python projects, not a yarn workspace with TypeScript.
  • As A, but imported by name: import { PyWriter } from "$/py".
  • Shorter for a small package, but unlike every other package here.
  • one package, @spell-app/py, holds every piece of Python and the TypeScript that writes it
    • imported as $/py, namespace PY
  • parser keeps only the language-neutral writers and the javascript and TypeScript ones

Owen, word for word:

"typescript that writes python into `/packages/py/ts`. Does this complicate monorepo setup?"

Only a little.

  • packages/py is one yarn workspace, @spell-app/py, whose TypeScript sits in its ts folder rather than a src folder.
  • The alias table points $/py at packages/py/ts.
  • py's own tsconfig and vite config cover that folder.
  • The Python projects, packages/py/core (spell_core) and packages/py/quart (spell-quart), sit beside it as uv projects, which yarn ignores.
  • P21 builds it.
