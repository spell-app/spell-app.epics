A list class whose set-up adds items puts those items into every scratch result of it, in both cores: every filter(), slice, range and copy.

  • Why: new_scratch() makes a new list, which runs its create(), and only then marks it as scratch.
    • JavaScript's newScratch() does the same; the two cores are kept alike.
  • An exclusive list class takes those items first, too.
  • Cards never meets this: compiled spell's "to set up a deck" is a method of its own, set_up(), not create().
  • both cores could skip create() for a scratch list
