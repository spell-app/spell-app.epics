new_scratch() makes cls(), which runs create(), and only then marks the list as scratch. JavaScript's newScratch() does the same. So a list class whose create() adds items puts those items in every filter(), slice, range and copy of it, and an exclusive one takes them first. Compiled spell's to set up a deck is a method of its own (set_up()), not create(), so Cards never meets this. I kept the two cores alike.
