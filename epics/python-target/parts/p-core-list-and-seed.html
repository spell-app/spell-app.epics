  • The core's method list, in the format projects already write for themselves (<Project>.declarations.json):
    • named spellCore.declarations.json, generated from what a core must have, and committed
    • a test fails when the list and the core's exports differ
    • so the Python port (P6 · spell_core Basics) can be checked against it, and can't miss a method
  • A seed in the core (Owen: "add runtime seed mechanism to JS/spellcore"):
    • spellCore.seedRandom(n) makes every random after it repeatable
    • the core's own number generator, and its own shuffle (Fisher-Yates: walk the list from the end, swapping each item with a random one before it)
    • no lodash, no Math.random, so Python can copy it exactly
    • a random number, a random item and a shuffle all go through it
  • The contract seeds through it, not by patching Math.random; a run takes a --seed option.
  • Printing a whole thing (print the card) writes its dump to STDERR; the contract compares STDOUT only, so no lines need skipping (Q4).
  • absoluteValue, which a rule writes but the core doesn't have, is added.

The core's own shuffle keeps lodash's order, walking from the front, not a Fisher-Yates walk from the end. So JavaScript deals today's cards from the same seed, the saved games need no rebase, and Python's spell_core (built in P6) already matches it. See J8.
