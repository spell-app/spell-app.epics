There are two Python targets, py and py/asyncio, so every test program is compiled, pinned and checked twice.

One target, py, on asyncio, writing what py/asyncio writes today:

  • a function that waits is async def, and its callers await it
  • a program that never waits stays plain def, so FizzBuzz reads exactly as it does now

py/asyncio, its six snapshots and the plain target's sleeping pause go; py writes the app file.

  • Owen, on the durable doc, word for word (cm6, on "PyAsyncWriter extends PyWriter"): "Why 2? Why not assume we can use PyAsync everywhere?"
    • And (cm15, on "It became a target of its own, py/asyncio, not a project setting"): "just one target, see above".
  • Why there were two, for Owen coming back cold:
    • Plain functions were the default (Q3): with no page, a pause only slows a program down.
    • asyncio became a target of its own so the contract ran both on every test program (Q18).
    • Since the web app (P20), only the asyncio one is useful for a program with a page, and a program with no pauses comes out the same either way.
  • PyWriter writes what PyAsyncWriter writes now. The two classes become one, PyWriter, with the "which functions wait" pass as its own (J34, J35, J36 still hold).
  • What changes, and what doesn't:
    • FizzBuzz never waits: its Python is unchanged (its two snapshots are identical today).
    • Cards waits, as in today's asyncio snapshot:
      • its turn_face_up() is async def
      • turn_over() awaits it
  • The targets table:
    • py gets the app file, .app.py
    • py/asyncio is gone: asking for it says there's no such target, listing the ones there are
  • spell_core loses its blocking pause: a pause is always await core.sleep(...). Its core, events and runtime methods lose their branches for plain Python.
  • The tests:
    • the asyncio tests fold into the Python ones
    • the contract runs one Python target, not two
    • the Quart app's tests compile with --target py
  • The six *.snapshot.asyncio.py files are deleted, and each *.snapshot.py is blessed again as the asyncio output. pyright's pinned errors stay as they are.
  • PY.PyWriter is the one Python writer.
    • It does what PyAsyncWriter did:
      • a function that waits is async def, and its callers await it
      • the top level runs through asyncio.run()
    • It builds on PY.PyBaseWriter, which writes everything but waiting (J65).
    • A program that never waits is plain Python: FizzBuzz is unchanged.
  • The py/asyncio target is gone (targets.ts).
    • So are its six .snapshot.asyncio.py files.
    • py now writes the web app, <Project>.app.py, beside its page file.
  • spell_core has one pause, async, named as javascript names it: await core.pause_for(50, "msec") (runtime_methods.py, J66).
    • The blocking one, on time.sleep, is gone.
  • Every test program's .snapshot.py is its old asyncio snapshot, but for the rename.
    • pyright's pinned errors are the same ones, on shifted lines.
