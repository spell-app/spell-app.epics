The naming table has no Python case, and nothing stops a spell name from becoming a Python keyword or hiding one of Python's builtins.

Python's names, in one line of the naming table.

A clashing name gets PEP 8's trailing underscore.

spell_core's lists and things answer Python's own questions, so len(deck) works.

  • Names follow PEP 8, Python's style guide:
    • functions, methods, variables and properties in snake_case: turn_face_up
    • classes in PascalCase: Card
    • constants in capitals joined by underscores: Card.RANKS
    { type: "PascalCase", constant: "SCREAMING_SNAKE_CASE", all: "snake_case" }
  • Clashing names, as PEP 8 says:
    • a Python keyword gets one trailing underscore: class_, from_
    • a local that would hide a builtin gets the same: list_, type_, id_, max_
    • a spell name never becomes a "dunder", a name with two underscores each side like __init__: PEP 8 says never to invent one, and the naming table never makes one
    • a class method's first argument is cls
  • The dunders are where spell_core meets Python, as Python documents them, so these just work:
    • len(deck)
    • card in pile
    • for card in deck
    • deck[0]
    __len__  __iter__  __contains__  __getitem__  __eq__  __repr__

The dunders (__len__, __iter__, __contains__ ...) move to P10, which builds spell_core's Thing and List: they're those classes' methods. P7 kept to the names.

  • Python's names are PEP 8's: Card.RANKS, turn_face_up.
    • See the tests in naming.test.ts.
  • A keyword steps aside with a trailing underscore: class_, from_.
  • A builtin steps aside only as a variable: list_, self_.
    • A member keeps its name: card.type, pile.max.
  • Soft keywords stay names: match, case, type.
  • A spell name never becomes a dunder.
  • The dunders for lists moved to P10.
