For P18 · Flask Spell Apps: compiled Python comes in two kinds (Q18). Which one should a Flask app run?

  • py: plain functions, and a pause sleeps.
  • py/asyncio: a function that pauses is async def, and a pause awaits.
  • Flask is synchronous at heart: each request runs in a thread of its own, start to finish. It can run an async def route, but in a fresh event loop per request, which ends with it.
  • A click's handler runs in the request's thread, one handler at a time per program (a lock).
  • A pause sleeps that thread; the stream (Q22) has already sent the move before it.
  • What "flask based" means to a Python programmer: no asyncio to learn.
  • Quart is Flask's asyncio twin, by the same project (Pallets), with the same API.
  • A pause awaits; one thread serves every page; a timer can outlive the click that started it.
  • Cost: Quart, not Flask, which isn't quite what Owen said.
  • A py program is served by Flask, a py/asyncio one by Quart.
  • Cost: two servers to build and test, for one game.
  • the Flask app runs py output; py/asyncio stays compile-and-run only, for now
