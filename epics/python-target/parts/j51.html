Chose one JSON reader per core: the old reader, fromJSON() in javascript and core.from_json() in Python, now hands its JSON to a new mirror instead of keeping a reader of its own.

  • JSON with ids, as a state writer writes it, keeps identity: a card mentioned twice comes back as one card.
  • JSON without ids, as toJSON() writes it, reads exactly as before: a new thing for each mention.
  • The javascript core lost its own copy of the reader, about 50 lines in json.ts.
    • Its note that "a card in two places comes back as two cards" now says that holds only without ids.
Nothing changes for JSON without ids; JSON with ids gains identity for free.Two copies of the same rules, to keep in step.
  • fromJSON() and from_json() keep identity when the JSON has ids
  • their old behaviour, and its tests, unchanged otherwise
