The first time a visitor comes, spell-quart runs the compiled program for them in a thread of its own, not on the server's event loop.

  • Why: a program compiled to py/asyncio starts itself with asyncio.run() at its top level.
  • That can't be called while an event loop is already running, and Quart's is.
  • The thread still runs on the visitor's core: asyncio.to_thread copies the context variables in, so using_core() carries over (J60).
  • Once it has run, the visitor's clicks and pauses run on the server's loop as usual.
  • No compiled program changes.
