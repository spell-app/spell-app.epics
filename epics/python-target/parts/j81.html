The core reference page is drawn in the browser, from the core's method list, by whichever checkout serves the page. Owen would notice it as a page that is always right for the branch he is looking at, with no generated page to keep.

  • The phase asked for a page "made and checked as the list is, so it can't go stale".
  • The page, Core Reference, is a plain page with a script, core-reference.js.
  • The script fetches two JSON files from the checkout serving the page:
    • the core's method list, spellCore.declarations.json
    • Python's not-ported list, not_ported_yet.json
  • So main's page server shows main's core, and a worktree's shows its own.
  • The list itself is what's checked: the core's test fails when it is out of date, so the page can't be.
Each branch shows its own core, nothing can go stale, and no generated page sits in the shared guides folder for branches to fight over.The guides folder is ONE copy for every branch: two branches with different cores would each fail the other's test.
  • No generated page and no new command: yarn gen:declarations, in core, writes the extra fields.
  • The page needs the page server: opened as a plain file, it can't fetch the lists.
