For P18 · Flask Spell Apps: when two browser tabs open the app, do they play one game together, or a game each?

  • Today a compiled program runs once, top to bottom: Solitaire's last lines deal the cards and start the game.
  • And spell_core is ONE core object for the whole Python process (J5): one page, one set of event handlers, one random seed.
  • So "a game each" means a core each, which spell_core isn't built for yet.
  • The server runs the program once, as it starts; every tab sees and plays the same game.
  • As spell run runs one program, and the editor's runner shows one.
  • Fits a local app and a demo; nothing in spell_core changes.
  • B becomes a todo, for an app with real visitors.
  • Each browser session gets its own run of the program, kept in memory, found by a cookie.
  • spell_core's core becomes per-session (a context variable), and the compiled module runs again in a fresh namespace per session.
  • What a real web app needs.
  • Cost: about 3-4 hours more, and it touches everything that imports the core.
  • The Flask app starts a child Python per session, and talks to it over a pipe.
  • No change to spell_core.
  • Cost: heavy; a process per tab, and their clean-up.
  • one game per server; a todo for a game per visitor
