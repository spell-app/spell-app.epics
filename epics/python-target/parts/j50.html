Chose what a program's state is: every thing or spell list it keeps at its top level, under its name in the compiled Python. python -m spell_core.run --state prints it when the run ends. 

{ "game": { "@type": "Game", "@id": "1", ... },
  ...
  "stock": { "@type": "StockPile", ... },
  ...
  "deck": { "@type": "Deck", ... },
  ... }
  • Why not the game alone: Solitaire keeps its piles as names of their own, stock = StockPile(...), not on the game. The game alone would leave them out.
  • The catch: whatever else is left at the top level comes too.
    • Loop variables and temporaries, such as card and it_2 (a foundation made by an add).
    • They are extra names for things the state holds anyway, not extra things.
  • P18's click-by-click check reads the same set of names.
