Python's shuffle is lodash's, step for step. P5's Goal describes the other usual way, walking the list from the end. The two give different deals from the same seed, so P5 must build the same one, or the cores deal different cards.

Chose lodash's order over the one P5 describes, because:

  • it's what this phase's brief asked for
  • the JavaScript core shuffles with lodash today, so the contract's saved games (Solitaire, Klondike) deal the same cards as now, with nothing to rebase

How it goes, for a list of n items:

for index in range(n):
    swap = index + floor(random() * (n - index))
    items[index], items[swap] = items[swap], items[index]
  • It takes one random number per item, even the last, as lodash does.
  • The numbers are Park and Miller's, as the contract's runner makes them today, starting from seed 1.
  • A seed isn't checked: 0 gives only zeros, as the same arithmetic does in JavaScript.
  • Tested against lodash's own shuffle, run in node on the same numbers.
  • P5's shuffle walks from the front, as lodash's, and its Goal's wording changes to say so
  • if Owen picks the walk from the end instead, both cores change, and the contract's saved games are rebased once
