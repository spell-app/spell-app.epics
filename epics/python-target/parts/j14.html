coreDeclarations() builds the core's method list from the running core.

  • It loads the core, walks each module's methods object (coreMethods, collectionCoreMethods ...), and reads each function's parameter names from its source text.
  • yarn gen:declarations writes the result.
  • coreDeclarations.test.ts fails while the file differs.

Chose this over reading the TypeScript files with a TypeScript parser, because:

  • it lists exactly what the running core has, with nothing listed by hand
  • TypeScript 7, which the repo uses, has no stable JavaScript API to parse with

What it gives up:

  • no parameter types (a spell datatype like Pile isn't what the core's TypeScript types say anyway)
  • h's parameter is Solid's own name, ...rawArgs
  • a rest parameter keeps its dots, as javascript writes it
  • a destructured one is called options
  • parameters are listed by name only: {"name": "collection"}
  • after adding a name to spellCore, run yarn gen:declarations in spell-lang/src/core
