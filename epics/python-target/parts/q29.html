  • Owen suggested (cm18) one Python method with the direction as a word, spell_core.round(number, "up"|"down"|"closest"): "whatever the pythonic syntax is for that".
  • Either way, plain rounding takes a half up, as javascript's Math.round() does, in Python with math.floor(x + 0.5) (spell_core already has it, for its text measuring).
  • The core's method list (spellCore.declarations.json) is checked name for name against spell_core, in snake_case. So roundUp must be round_up there, unless it's listed as an exception.
  • Pythonic: the standard library itself uses separate names for this, math.floor() and math.ceil(). A mode word is how decimal does it (rounding=ROUND_HALF_UP).
  • Each method, javascript's name (as spell compiles today) / Python's:
    • spellCore.round(x) / core.round(x)
    • roundUp(x) / core.round_up(x)
    • roundDown(x) / core.round_down(x)
  • The method list lines up one for one, with no exceptions; the spell rule doesn't change.
  • Both cores, one method:
    • up: round(x, "up")
    • down: round(x, "down")
    • closest: round(x) or round(x, "closest")
  • The spell rule compiles "round price up" to core.round(price, "up").
  • One name to remember; a misspelt word fails only when it runs.
