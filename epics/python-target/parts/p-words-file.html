The Thing Explorer labels an action from its compiled name, so Python's move_to_pile would have lost spell's wording.

Compiling to Python writes a words file, <Project>.py.en.json, spell's wording keyed by each Python name; spell_core reads it. Nothing reads it yet: Python has no Thing Explorer.

  • A Python-compiled project carries spell's own wording beside its output, as a JavaScript one does.
  • Keyed by spell's names, not compiled ones, so every target can share the keys.
  • Owen's reason, from output-targets: "carry the original wording somewhere for reflection, especially into other languages".
  • Compiling to Python also writes a words file, <Project>.py.en.json, beside the Python:
    • spell's wording of each member, keyed by its Python name
    • e.g. "move_to_pile": "move (a card) to (a pile)"
  • It's plain JSON, so any reader can use it.
    • spell_core reads it: core.load_words(path), then core.words_of(card).
  • A target says whether it has words of its own (wordsSuffix in the targets table); javascript keeps its <Project>.en.js.
  • Nothing reads it yet: Python has no Thing Explorer.
