The core's position methods count from wherever the calling project's lists start, rather than always from 1. Owen: "core methods in JS should respect listStartAt".

  • Each method that takes or returns a position takes a startAt too, 1 when left out.
  • Compiled code passes its own project's setting on every call.
  • It's per call, not one switch for the whole program:
    • one core serves every project in a program
    • so a library counting from 1 and a program counting from 0 can share it, and neither reads the wrong item
  • It replaces the earlier plan, "the core stays 1-based, and the compiler shifts every position".
  • Built in P2 · Lists Start At 0.
getItemAt(deck, 0, 0)     // item 0 of the deck:  the first card
positionOf(ranks, "queen", 0)   // 11, where counting from 1 gives 12
  • the core's position methods each take a startAt
  • the Overview's "Lists start at 0" (1.3) says so
