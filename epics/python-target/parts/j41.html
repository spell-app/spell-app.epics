Q15's answer says compiled Python counting from 0 writes its own words: deck[n] for an item, and a slice, deck[2:5], for a range.

  • The writer writes deck[n] for an item, as Q15 says.
  • A range goes through the list's own between(): aces = deck.between(0, 3, start_at=0) in CardsFromZero.snapshot.py.
  • J3 chose that for javascript, because spell's ranges include their end and take negative ends; its net effect says Python could still write native slices where both ends are known numbers, and nothing did.

The Python Target page describes what was built, and gives J3's reason. If slices are wanted where both ends are known numbers, it's a writer change and a snapshot rebase.
