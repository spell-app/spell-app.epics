Two departures from plan item 5:

  • Placement: at the setting file's top, EXCEPT when the type's class is declared in that same file -- then right after it. Why: a class can't be patched above its own declaration (Deck.declareProp(...) before export class Deck throws). e.g. Deck.spell's is_set_up follows class Deck; Pile.spell's Card.pile is at its top.
  • The set's SPELL: DECLARES comment sits on that declaration, NOT the set line. Why: the set is usually in a method's body, whose AST is memoized and KEPT when an edit above only moves it -- the incremental suite caught its defined offsets going stale. A file's AST is built afresh each compile. It also puts the comment on the code that declares the property.
  • Option: the comment on the set line without defined (no source location for importers).
