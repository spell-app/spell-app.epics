Call rules learn their parameter types, so two same-shaped methods stop colliding:

two `put` methods 
to put (a card) on (a pile)
to put (a chip) on (a pot)
put the chip on the pot   // today:  chip.put_on_$pile(pot) -- Card's, throws when run
                          // after:  chip.put_on_$pot(pot)

Proposed: a rule is rejected ONLY when the argument's type is known AND not assignable. Unknown type = still matches, so nothing that parses today stops parsing. Stricter (unknown rejects) would break untyped code everywhere.
