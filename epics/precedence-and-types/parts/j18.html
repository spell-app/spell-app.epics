In plain words.

  • Writing to move a card to a pile makes a CALL RULE, so later lines like move the card to the pile parse.
  • Since P5 each method has TWO: the statement rule (its last argument takes a whole expression) and an expression twin (inside a bigger expression its last argument stops before an operator: if double x is 4 → double(x) == 4).
  • A compiled library saves its rules in SPELL: DECLARES comments, so a project importing it can rebuild them. You'd picked "declarations list both rules" (D27).
  • Built: the comment lists ONE rule, the statement one; registering it (in the library, or in an importer) creates the twin automatically. So the importer still gets both.
  • The choice, with a real saved declaration: details page, Q1.

D27 said the saved declaration lists BOTH rules. The twin is derived at registration from the one rule (its class says operandInExpressions, its syntax ends in {x:expression}), so loading a declaration through scope.addRule() makes both again: no change to the saved format, and the importer still rebuilds both (pinned in SpellDeclarations.test.ts and methods.export.test.ts).
