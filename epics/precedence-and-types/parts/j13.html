Folding TYPE_VALUE_MAP / SIMPLE_TYPES into SP.typeName() changes what a few phrasings compile to -- each a fix, as the runtime's typeOf() already speaks these words:

  • as choice / as a boolean / is a boolean: 'choice' (was 'boolean', which isOfType() never matched -- the suspected bug)
  • as a string / is a string: 'text' (was 'String', also never matched)
  • as a fraction: 'number'; as a char: 'character'
  • classes stay Type_Case for compiled code: List, Thing, Object
  • a method on a date / nothing arg is no longer promoted to an instance method: isSimpleType() is now every value type, not a hand list
  • a declared property's datatype comes from its specifier's datatype: as a new thing => thing, as a list => list (was List)

No fixture or live example used any of the changed spellings; probe T2 pins choice.
