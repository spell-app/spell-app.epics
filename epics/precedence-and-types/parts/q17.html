The two rules. Both start with draw:

// draw_thing:  draw ONE thing, reactively
"draw {expression}"                                                   => spellCore.drawThing(x)
// draw_items:  draw each item of a list
"draw (each {variable}|(the|all)? {plural_identifier}) (of|in) {expression}"  => spellCore.drawItems(list)

The clash. draw the cards of the deck matches BOTH, in the same 6 words:

  • draw_thing reads the cards of the deck as one thing: drawThing(deck.cards)
  • draw_items reads it as "each card of the deck": drawItems(deck) -- what's meant

A Choice picks the highest priority (was precedence), then the longest, then the rule registered FIRST.

  • Today: draw_thing has priority 100, so it always wins; draw_items' test for this line was skipped because it always failed.
  • draw_thing can't drop to 0: a project's own to draw (a card) makes a call rule (priority 0) that also matches draw the stock, and stock.draw() skips the reactive redraw. So it needs 1.
  • Prototype: BOTH at 1, and draw_items moved ABOVE draw_thing in the file so it wins the tie. Works, but only because of file order: move the rule and it silently breaks.
