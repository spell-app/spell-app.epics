• a method call's datatype is its record's returns, which nothing fills until P5's return inference: every call is unknown
  • an enumerated property (as one of clubs, diamonds ...) has no datatype, so the suit of the card is unknown
  • x has items where ...: the item's type is unknown -- the list is the suffix's left side, which a suffix can't see while parsing
  • its X is unknown when no it is in scope (meaning this)
  • a variable keeps the datatype it was declared with: a later set x to something else doesn't change it (first datatype wins)

Unknown is compatible with everything, so none of this changes what parses.
