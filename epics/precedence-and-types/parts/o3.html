Binding power

  • Two numbers, two jobs (D26): an operator's precedence, from the Precedence table, on suffix rules only -- * 14, + 13, comparisons 11, is 10, and 6, or 5, X if C otherwise Y 4. A rule's priority (was precedence) only breaks a Choice's tie: highest, then longest, then earliest (D15).
  • compound_expression is THE expression rule: an operand, then each suffix binding tighter than its bound. Parsed once per level, not twice. A postfix pops like an infix: x + y is empty => isEmpty(x + y).
  • operand (D29): an expression with no operator at its top. A prefix's last slot is {list:operand}, there is a too (D23); absolute value / round take {x:arithmetic_expression}, the sum (D3); statements and slots closed by a word keep {expression}.
  • Give-back in Sequence, the one change in packages/parser: a required word the slot before swallowed re-parses that slot shorter -- remove the card of the pile.
  • Calls and wait for: whole arguments as statements; inside an expression their LAST slot is an operand (D24, D27, D33) -- if double x is 4 => double_$n(x) == 4. One flag, operandInExpressions: a statement rule plus an operand twin, derived at registration (J17, J18).
  • The model: Parser Model §4.5; the mechanics: PARSING.md "Expressions".

A datatype on every match

  • match.datatype = rule.getDatatype(match), in spell's words (P.Datatype: text, choice, list of cards, Card; D16); ONE normaliser, SP.typeName(), for what a user writes (J13). Unknown fits everything.
  • Lookups stay in parse(), into match.data; about 20 rules override getDatatype().
  • TypeScope: itemType, chain() / isA() / getMember() (moved from the LSP); methods get P.ScopeMethod records -- in the project's own methods when the type is built in or imported (J11).
  • Return types inferred once a body parses (mutateScopeFromBody(), J20); a getter's type is its property's, so getters change scope (D9).
  • is a takes a KNOWN type (D32), declared anywhere in the project: a line pre-scan stubs them first (J19).
  • Declarations gain params / returns / itemType, no SPELL_VERSION bump (D37, J14).

Signatures, calls, members

  • Paren-free typed parameters (D2): to give a card to a pile ~== to give (a card) to (a pile); to create a card => Card.create().
  • A call rejects an argument only when its type is known and UNRELATED to the parameter's (D6, J16): put the chip on the pot picks Chip's.
  • Members: member_words, 1..N words up to a stop word, blacklist skipped (J25). the X of Y is ONE rule, resolved through Y's type, else one loose word (D5, J23), at priority 1 (J24). class_member replaces EnumerationRule; new list_count (J26).
  • Auto-declare at the first set the X of Y (D10): on types the project declares only (J28), at the file's top or after the type's class (J29).
  • Built-in member tables, SP.BUILT_IN_TYPE_TABLE (D34): thing, list, app, text, date; a member compiles per type, the length of the name => name.length, of the deck => spellCore.itemCountOf(deck) (J35). The Type Explorer is built from it (J34); declaring or setting a built-in member is refused, with a reason (J33).

Exclusive lists

  • a pile is an exclusive list of cards (D7): a card is in at most one list of the family, Pile and its sub-types; a deck is outside it.
  • the pile of a card: a read-only member of Card, declared by Pile's line, compiled as a getter patched on after Pile's class, Pile.ownerOf(this) (J39); set the pile of … is refused.
  • Runtime: one WeakMap per family, every write to a list's items through List.writeItems(); adding a held card moves it (J37); scratch results (filter, copy, merge) own nothing (D8, J38).
  • Pile.spell's to move a card to a pile is now add + pause (D36).
