Found re-running the probes: after solid-migration P11, whether a property is reactive depends on whether it was declared: 

// 'a card has a pile' somewhere:  setter -> setProp('pile', value):  reactive
// never declared:                    plain field 'card.pile = pile':   NOT reactive, no warning
card.pile = pile

With types plumbed (P2), the parser knows the value's type at the first set, so it could declare the property there: reactive and typed. Options: (A) auto-declare (recommended); (B) warn "undeclared property"; (C) leave it. Exclusive lists remove the main case (the pile of a card) either way.
