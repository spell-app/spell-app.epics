Do the javascript and TypeScript targets use the list? No: it's written FROM the javascript core, for the cores that come after it.

  • The javascript and TypeScript targets compile against the core's TypeScript itself.
    • What spellCore has is the type SC.SpellCore, and compiled code calls it directly.
    • Neither compiler nor runner opens the list.
  • The javascript core writes it: spellCore.declarations.json, at core's root.
    • yarn gen:declarations, in core, runs writeCoreDeclarations.ts.
    • The names are read from the core as it runs: nothing is listed by hand (coreDeclarations.ts).
    • Each name's heading and description come from the comments in its source file.
    • It's in the format a project's own <Project>.declarations.json is written in, with one key more: module, the core's file that has it.
  • A core test fails when the list is out of date: coreDeclarations.test.ts.
  • Its readers:
    • Python's test, test_core_declarations.py: spell_core must have each name, snake_cased, or list it in not_ported_yet.json with why.
    • So a name the javascript core gains fails Python's test, until it's ported or listed as not yet.
    • And this page.
