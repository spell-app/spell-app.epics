Choice Pages

A choice page is for calls made name by name: one row per name (or any bit of syntax), Claude's recommendation pre-filled, Owen typing over the ones he'd write differently, then "Do it".

Written for: Claude, when a decision is really a list of small ones Status: built (epic wwod-spell-ui) Template: syntax-choices.html; tool: choices.js
  • A rule has been proposed (a details page or epic-page question picked it), and Owen wants to see every name it touches, with its context, before it's applied: P13's boolean names were the first.
  • Too many rows for a details page's option cards, and each row's answer is TEXT (the name he'd write), not a pick.
  • A rule question with a handful of options stays a details page (spell dev details) or a epic-page question; this page is for after it.
  1. Write the rows as JSON (the format: 3. The rows): every row's file and line current at the branch's HEAD, since the page links them straight into VS Code.
  2. spell dev choices new <slug> --rows <rows.json> [--epic <name>] [--title "..."] -- prints the page's path:
    • an epic's: epics/<name>/details/<slug>.html, kept with the epic page
    • else scratch: pages/details/<slug>.html, swept after 14 days
    • beside it, <slug>.rows.json: the rows, ids filled in
    • the rows are in the page too, as the epics pack's elements (epic epic-workflow P12): a section each, holding an <epic-choice-rows> of <epic-choice-row>s, and the <epic-choices-bar> at the end (their pages: Epic UI, "Pages Owen answers on")
  3. spell dev choices show <page> --wait, in the BACKGROUND (as details show --wait): it exits with Owen's answer when he presses Do it, which wakes the session. Then end the turn with the page's link pair (spell dev docs link <page>).
  4. spell dev choices answer <page> prints the last answer again; spell dev choices list shows every choice page, answered, draft (typed, not sent) or waiting.
  • title, lede, askedBy, where ({ epic, justNow, decides }): the page's own words, as a details page's; HTML allowed except in the title.
  • fileColumn: false drops the File column, for rows whose place in the code doesn't matter to the reader, such as a list of commands (Owen's comment CM4 on epic epic-workflow). The rows still name their file and line, which the printed answer shows.
  • sections[]: { id, title, description?, icon? }, in page order. The description is one line: which question it answers and the recommended rule.
  • rows[]: { id?, section, file, line, purpose, current, recommended, note? }
    • purpose: what it's for, in words a reader new to it follows: 1-3 words for a name ("menu open", "reduced motion"), a short sentence and when it's used for a command
    • current: as a reader sees it at a use site (this.isOpen(), { isDirect: true }); recommended: that use site as Claude would write it, equal to current for an example that stays
    • note: a short why, under the purpose; `code` shows as code
    • no id: one is made from the section, file and line (q22-UISection-169)
  • The page draws each section folded, its rows by file then line; syntax-choices.rows.json is a small working example.
One section, one row · 18 lines 
{
  "title": "Boolean names, one by one",
  "sections": [
    { "id": "q22", "title": "Q22 · Our own members", "description": "`is` / `has` / `can`, or a verb" }
  ],
  "rows": [
    {
      "section": "q22",
      "file": "packages/ui/src/elements/LoadableComponent.tsx",
      "line": 70,
      "purpose": "save in flight",
      "current": "this.saving.set(true)",
      "recommended": "this.isSaving.set(true)",
      "note": "the `:state(saving)` key stays"
    }
  ]
}
  • Columns: File | Purpose | Current | Recommended; no File with fileColumn: false.
  • File opens VS Code at the line.
    • It links vscode://file/<checkout>/<file>:<line>.
    • The checkout is the one the page server serves (for a /worktrees/<w>/ page, that worktree).
    • In the side bar the frame can't follow the link, so the page hands it to the view, which opens it (vscode.env.openExternal()).
  • Recommended is a box, pre-filled.
    • A changed one is marked orange, with a round button putting the recommendation back.
    • Each section's title counts its renames, the rows that stay, and the changed.
  • Saved as Owen types, to <slug>.draft.json.
    • It saves 5 seconds after the last change, and as the page goes away.
    • A reload restores it.
    • The toolbar says "saved 5:42 PM", or why it can't.
  • The toolbar, pinned at the bottom, ivory like the one at the top:
    • the feedback box (it grows with its text)
    • Do it, its tooltip the count ("Send 3 changed of 180 ...")
    • Expand all
    • the save status, only when saving failed
  • Do it writes <slug>.answer.json. Pressed again after changes, it sends again.
  • The page server's route module: choicesRoutes.ts (/api/choices/draft, /api/choices/answer).
  • wait and answer print the CHANGED rows by section, how many were left as recommended (accepted), then the feedback. Rows not changed are in the rows file: recommended is the answer for them.

  • Saving and sending need the page server: they go through a route. From file:// the rows still draw (they're in the page since P12; before, a page script fetched them), and Do it says where to open it.
  • Route modules load when a page server STARTS: a server older than choicesRoutes.ts answers 404, and the toolbar says "page server too old, restart it".
  • A worktree's page shows from the MAIN checkout's page server, whose routes are main's: until the branch that adds the route merges, open the page from the worktree's own server (spell dev server status in the worktree gives its base URL).
  • The file link opens through VS Code's vscode://file handler: in Chrome it asks first; it opens in whichever window VS Code picks for that file.
