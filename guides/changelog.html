P3 · Binding Power

  • compound_expression is THE expression rule: an operand, then operators binding tighter than its bound; each level parsed once, not twice
  • Operators get precedence (the Precedence table); a Choice's tie-break is renamed priority
  • Postfix operators pop like infix: x + y is empty => isEmpty(x + y)
  • Sequence give-back: remove the card of the pile parses (the one change in packages/parser)
  • List prefixes and there is a take {x:operand}; absolute value / round take the sum; simple_expression renamed operand
  • the number of cards in the deck where … counts a filter; draw rules get explicit priorities (draw the cards of the deck draws each)
  • Live cards library and Solitaire examples lose their forced and defensive parens
  • Parse time halved: rule tests 67.7 → 54.5ms, Solitaire project 109.6 → 55.2ms

P4 · Types Plumbed

  • A datatype on every match, in spell's words: P.Datatype, Rule.getDatatype(), match.datatype; one normaliser, P.typeName()
  • TypeScope itemType / chain() / isA() / getMember() (moved from the language server); P.ScopeMethod records
  • Arguments, this / it, new variables, loop and where items typed
  • Built-in type names (text, number …) are types in the root scope
  • is a takes a known type: is a crad is a parse error
  • as choice / as a boolean declare 'choice' (suspected bug fixed)
  • Declarations carry params / returns / itemType, no version bump; hover says card: Card

P5 · Typed Calls, Signatures

  • Paren-free typed parameters: to give a card to a pile; to create a card => Card.create()
  • Call rules reject an argument of an unrelated type: put the chip on the pot picks Chip's
  • Return types inferred from returns; getters change scope
  • Inside an expression a call's last slot is an operand (if double x is 4); statements keep whole arguments; wait for too
  • is a sees types declared later in the project (a line pre-scan)
  • Language server reads parameters from the method record; Todos' to create a task renamed to create a new task
