Outline Spell

Spell can be written as an OUTLINE: a type's heading line, then a bulleted list of what's true of it. It compiles to exactly the same code as the sentences it stands for.

  • Words in quotes teach spell new language.
  • It's for people who glaze over at spell's "reads like a novel" sentence style.
  • Lauren's sketch of a card and a deck is the model.

  • The outline names its subject ONCE, in the heading; each bullet says one fact about it.
    • Sentence style: a card has a suit as ..., the color of a card is ...
    • Outline: a "card" is a thing where:, then - its "suit" is ...
  • Both styles stay, with the same meaning (Q1): every outline line is shorthand for a sentence-style line.
    • hovering an outline line in the editor shows Reads as: the sentence it stands for
    • a test compiles those long forms and gets the same javascript, character for character (outline.test.ts)
  • New on the way, usable in either style:
    • a list of values as a kind of thing, with properties of its own (the "color" of a suit)
    • phrases that find their blanks by themselves (it "is a (suit)")
    • values filled into text ("images/[rank]-of-[suit].png")
  • The numbers above:
    • 0: every saved project compiles exactly as before (spell 1012 tests, lsp 115, parser 486, core 405)
    • 30: the outline Solitaire's cards pass the same 30 checks as today's cards, and it plays in the app (V2)

In a type's body, a line can leave out its it / its: one that starts with a quoted name or a verb since P8, and one that starts with a bare name since P9. Both styles compile to the same JavaScript, and may be mixed in one body.

With it / its · 7 lines The same, without · 7 lines
  • Works for every member: properties, getters, phrases, belongs to, is saved inline, and a list type's guards (- can take a card if: ...).
  • The hover's Reads as puts the subject back: - "rank" is a number reads as a card has a rank as a number.
  • - "x" is ... is always a property. A phrase without it needs if, a colon, or a body such as always.
  • A bare name is the type's own property or getter (P9): - suit is a suit of its deck, - state is: with a block under it.
    • are works as well as is, quoted or not: - piles are a list of piles.
    • A line starting with a statement's first word stays that statement: - return x is 1 is a return. A property named type, start, stop, test, each or get keeps its quotes: - "type" is one of ....
    • A getter that is just a value warns: - score is 0 says "score is always 0: to give it a type, write "score is a number"". The same for its score is 0.
    • A kind keeps its quotes: - "suits" as one of clubs, ....
  • Outside a body nothing changes: "rank" is a number at the top level is an error, and score is 0 sets a variable. Inside a getter or method in the body, total is 2 still sets a local.

A value kind is a list of values that's a kind of thing of its own. The values stay plain text and numbers when the code runs (Q10).

Excerpts from the outline Solitaire's compiled output, OutlineSolitaire.compiled.js, its SPELL: DECLARES comments left out.

  • A body compiles FLAT: each line as if written at the top level, right after the type's line (J2).
  • Members (properties, getters, phrases) then move into the class as always, so either style gives export class Card extends Thing { ... }.
  • So a set x to 1 in a body makes a file-level x, as at the top level.
  • The deck keeps the list; the kind is a class with only statics.
  • A kind's property is a static method taking the value.
  • is diamonds or hearts is a lookup in the list (J5); it used to be always true.
Suit and Rank · 15 lines 
Deck.Suits = ['clubs', 'diamonds', 'hearts', 'spades']
export class Suit {
  static color(suit) {
    if (core.includes(['diamonds', 'hearts'], suit)) { return 'red' }
    return 'black'
  }
}

Deck.Ranks = ['ace', 2, 3, 4, 5, 6, 7, 8, 9, 10, 'jack', 'queen', 'king']
export class Rank {
  static is_a_face_card(rank) {
    return core.includes(['jack', 'queen', 'king'], rank)
  }
}
  • A property holding a kind checks its value against the kind's list when SET, through a function: oneOf: () => Deck.Suits (J6).
  • Reading a kind's property is a call: the color of its suit is Suit.color(this.suit).
  • Inferred phrases compile like the written-out ones: is_a_$suit(suit). A phrase on a kind is a static call.
  • Used: the card is the queen of spades is card.is_the_$rank_of_$suits('queen', 'spades'); the card is a 2 is card.is_a_$rank(2).
class Card, excerpts · 19 lines 
static { this.declareProp('suit', { oneOf: () => Deck.Suits }) }
get suit() { return this.getProp('suit') }
set suit(value) { this.setProp('suit', value) }

get color() {
  return Suit.color(this.suit)
}

is_a_$suit(suit) {
  return this.suit === suit
}

is_the_$rank_of_$suits(rank, suit) {
  return this.rank === rank && this.suit === suit
}

get is_a_face_card() {
  return Rank.is_a_face_card(this.rank)
}
  • The deck's class names the card's (instanceType), and the card's reads the deck's list: whichever comes first can't see the other yet ("Cannot access 'Card' before initialization").
  • So oneOf is a function, and a list type whose item type is declared BELOW it reads it through a getter. Every existing project's output is unchanged.

Q17 VS Code's extension built from the branch, at P6 so outlines can be tried in the editor before merging
  • VS Code runs THIS branch's parser, in every window, until the extension is rebuilt from main (C6). It's rebuilt after merging, or with spell dev vscode from the main checkout.
  • An outline in the editor (V1) hasn't been tried by hand yet. The outline Solitaire plays in the app (V2).
  • The rule tests run 16% slower than on main, after P6 (C5).
    • spell speed --against main: average 87 vs 75, min 83 vs 71, max 100 vs 93.
    • That's on 727 rule tests vs 681: about +9% per test.
  • Where from: the new rules each get tried on many lines.
    • Every type declaration tries 2 syntaxes (quoted or not), each with an optional where:.
    • Every X if Y line tries value_if.
    • is_in's value_choices is tried on every is.
    • Inferred phrases are tried on every a card "..." line.
    • Each phrase checks its owner.
  • P8 (leaving out it / its) added about 5% more: average 116 vs 111, on its own start (C5).
  • P8 and P9 together: all 11 test projects parse about 5-7% slower than before P8 (276-300 ms vs 263-282 ms, the fastest of 20 runs each). The rule tests: 128 vs 119.
  • The rule tests are a stand-in: what people feel is a whole project's parse. Measure Solitaire before and after, before merging.
  • Across files, the deck's file must come before the card's: each file parses in turn (J13).
  • In one file, either order works (I3).
  • Each left-out word is a guess; a wrong guess reads right and does something else (C2).
    • Guard: a guess only when ONE answer fits.
    • Guard: the hover's Reads as.
  • A blank is always written in parens, it "is a (suit)", so a phrase is never guessed into one.
    • it "is my color" means those words (J9).
    • An is phrase with no blank and no if ... is an error, as is any phrase with no body (I6).
    • A phrase true for every one of the type says so: - it "can move" always.
  • Values are one project-wide list (J8):
    • whether its color is red or blue parses depends on whether another kind ABOVE lists blue
    • another kind's value can be assigned, set the color of the card to blue: caught only when it runs
    • completion and "go to definition" see every kind's values
  • A phrase checks whose it is right after an operand, and after and / or (J11, I7); after anything else it isn't: x + 1 is a king isn't checked.
  • Phrases on a value kind: only is ... ones, no infix phrases.
  • No hover or go-to inside a fill-in: each is parsed on its own. A fill-in that doesn't parse says only "Don't understand".
  • Any [ in existing text now fills in (C3); no saved project had one.
  • Typographic marks are deferred (T1): — headings and comments, curly quotes, a capital A starting a line. Use ##, // and straight quotes.
  • create a type called "hand" takes no quotes.
  • A card with its own to draw a card: AND two sides gets two draw()s: the later wins.
