Shared Content

Where the docs pages, plan docs, templates, goal sets and logs live, and why no branch tracks them any more.

Plan doc: epic shared-content Written for: anyone editing docs or logs, or wondering why a page isn't in git status Status: built, on main since the cutover, 2026-10-04 Checked: the shared CLI's tests, and every open worktree moved onto it by 2026-10-10
  • All docs content lives in ONE git repo beside the main checkout, the shared repo, ../spell-app-dev.
  • Every checkout, main and each worktree, links to it with eight folder links at its root.
  • So every worktree sees every plan doc and docs edit at once.
  • It's committed by itself, after every Claude turn: nobody commits these files by hand.
  • No branch tracks them, so the changelog, the docs index and the logs never conflict on a merge.
  • The tools that read and write the pages stay in spell-app, versioned per branch.
  • That's inside the shared repo: /Users/owen/www/spell-app/spell-app-dev/<path>.
  • A worktree session's Edit refuses a path through the links.
  • Reading, and the tools, use the links as usual.

Each folder below is a link at a checkout's root, into the same folder in the shared repo.

Folder Holds
epics plan docs, with their inboxes and details pages
guides every other docs page, with its Markdown, data and experiments; the changelog is one
pages the docs home, and the scratch details pages (never committed)
templates one starting point per kind of page
ui Spell UI's hand-written docs pages; each branch's built bundle and data are laid over them
brand the Brand tab's pages
goals the goal sets
agents the three logs (papercuts, suspected bugs, code debt), and WWOD, the house style
  • Page URLs follow the folders: /epics/seo/seo.plan.html.
  • The page server serves them from any checkout, through its links.

The tools stay tracked, versioned with the code on each branch.

  • The docs scripts, their _assets and the goals tooling: docs' tools folder.
  • Which folders a checkout links: the manifest, "shared" in the root package.json.
  • Git ignores the links: a marked block in the root .gitignore.
  • Each checkout's links follow its OWN branch's manifest.

  • After every turn, the Stop hook runs spell dev shared commit.

  • A lock keeps two sessions' commits apart.

  • Its trailers:

  • No git run inside a shared folder: that's the shared repo there.
  • A branch touches no shared file, so the changelog and the logs can't conflict.
  • The changelog entry goes straight into the shared page, from any checkout.
  • After merging a change to the manifest: spell dev shared link.

The links are git-ignored, so a search must be told to follow them.

  • grep -R follows them; grep -r doesn't.
  • rg needs -L --no-ignore-vcs.
  • Or search the shared repo itself.

Every shared-content operation is a spell dev shared verb.

Verb What it does
status each checkout's links, and the shared repo's state (the default)
link [--all] puts this checkout's links back, or every checkout's
commit commits the shared repo; the Stop hook runs it
repair [--dry-run] after merging a branch from before the move: moves pages it left in the docs package into their shared folders, and fixes links written for an old layout
migrate <worktree> [--dry-run] moves a worktree cut before the cutover onto the shared content, keeping its other work
init [--import] makes the shared repo, once per machine
spell dev shared --help · 4 lines 
spell dev shared status | init [--import] | link [--all]
                 | commit [--session <id>] | migrate <worktree> [--dry-run]
                 | repair [--dry-run]
--json:  status, migrate, repair print their data as JSON

Docs tracked per branch cost twice.

  • A worktree couldn't see another worktree's plan docs or docs edits, nor main's newer ones.
  • The same few files conflicted on most merges: the changelog, the docs index, the papercuts log.
    • 7 of the 50 commits before the move were "Merge main into X".
  • An ordinary git repo next to the main checkout, with no GitHub remote: "it's still just me" (Owen).
  • Rejected:
    • a repo nested inside the main checkout: Owen doesn't want a nested git folder
    • a hidden bare repo: it works, but the main checkout would be the odd one out
    • a git-ignored folder alone: a worktree only gets tracked files, so it wouldn't be there; the link is what makes it visible
  • Backups: Time Machine only, until a remote is added.
  • Node runs a linked script from its REAL path, in the shared repo.
  • There's no node_modules there, and no $/ aliases.
  • And the docs tools import packages: linkedom, Playwright, esbuild, the page server, Spell UI.
  • So the scripts stay in spell-app, and only the content is linked.
  • The docs' one-off experiment scripts ride along with their pages: nothing runs them as tools.
  • Templates are content, not tools: a template change shows in every worktree at once.
  • The first spike found that Claude's Edit refuses a link to a single FILE, whatever the settings.
  • Edits through a FOLDER link work, and land in the shared repo.
  • So every shared thing is a whole folder.
  • Nobody has to remember to commit docs, and no docs commit ever lands on a branch.
  • The shared repo's history is many small auto: commits, each naming its checkout and session.
  • At first a hook swapped a path through the links for the real one, before every Edit.
  • Claude Code's worktree guard refuses such an edit before any hook runs, so the hook could never help.
  • The hook is gone; the rule lives in the root AGENTS.md and CLAUDE.md instead.
  • Without trust, every write into a linked folder stops for a permission prompt: its target is outside the repo.
  • So the shared repo is trusted in both the user and the project settings.
  • Every package window shows it as a folder.
    • It's permanent, unlike a worktree, so "never add a worktree's folders" doesn't apply.
    • Its Source Control shows the auto commits, and VS Code's search covers it.
  • The commands page and its data are shared, but each branch's CLI differs.
  • So its check is tolerant:
    • a yarn row for a package this checkout lacks is a note, not a failure
    • a command this checkout has, and the page lacks, still fails
  • A search skips the links unless told to follow them (see "Searching").
  • Checking out a commit from before the cutover, or bisecting across it, writes real files where a link was.
    • The shared repo stays safe: git never follows the link.
    • That checkout stops sharing until spell dev shared link puts the links back.
  • The public repo (origin) has no docs, changelog or plan docs since the cutover.
    • Links to docs pages from its README or code comments are dead there, and in a fresh clone.
    • Accepted: "no worries, it's still just me" (Owen).
  • The Solid and precedence experiments can't run in place.
    • Node runs them from the shared repo, with no node_modules and no aliases.
    • To re-measure, copy one into the repo.
  • Hooks run from the MAIN checkout, where every session is saved.
    • A change to the linking or commit hooks takes effect only once it's on main.
  • Shared pages may link code that only another branch has yet.
    • The link check reports those as missing in this checkout, until that branch merges.
    • Not a bug: the links are right, just early.
  • No off-machine backup: the shared repo has no remote yet.
  • The shared repo's own README still names the three links it held at the cutover.
  • Spell projects, examples and guides are still tracked; moving them is a later todo.
