ui and WWOD

@spell-app/ui follows the house style (WWOD) everywhere, except in the few places this page lists, each with the reason it departs.

Written for: anyone writing or reviewing code in packages/ui, who knows WWOD and wants to know where ui differs Status: built (branch, not merged) Researched on: branch wwod-spell-ui, 2026-10-05 to 10-06; sizes from yarn measure, counts from a grep census (see Sources) Plan doc: WWOD for Spell UI
  • The rules live in packages/ui/AGENTS.md: every section named like a WWOD rule starts "As WWOD §N, plus:" and lists only what ui adds or changes. This page is the why behind them.
  • Most departures have ONE reason: bundle size. A web component library ships every byte to every page, so where WWOD's shape costs bytes in a family's chunk, ui picks the smaller shape.
  • The rest come from what ui is: a port of Fomantic UI (its class grammar stays), code node must load without a DOM (vocabularies, the static render), and a forked custom-element layer that keeps upstream's shape.
  • The restyle (epic wwod-spell-ui, P1-P11) changed public names and signatures, and fixed every caller in the repo (app, docs, brand, cli).
  • Write ui code as WWOD says; where this page names an exception, follow the exception.

Each row: what WWOD says, what ui does instead, and why. The letter after it is the plan doc's question that settled it.

WWOD ui does Why
§12: a constant one class uses is a private static a module const below the class, not exported (Q18) a module const minifies to one letter; t.LIST_SEPARATOR doesn't
§12: statics after the main methods @proto static defaults stay at the top (Q11) they're the class's declared config, read first
§19: log through a Logger Warnings.warn() / devWarn() from $/ui/util (Q5) $/util's Logger and its colours would land in every component bundle
§4: one namespace per sub-system yes, as E / F / UI / UIT; but load-time uses (extends, @proto, static initializers) are direct imports (Q4) the element core imports itself: a namespace read while a module evaluates hits the cycle
§4: import a package through its entry code BELOW core (runtime, vocabulary, icons, util, types files) never imports the $/ui/core entry (I16) core re-exports the runtime's loader; the lazy runtime chunk importing it split a chunk every page loaded
§4: one alias vocabularies and types files value-import UIT from its file, not through $/ui/core node imports them (yarn site:data, gen:root); core loads Solid's DOM layer, which node can't
§9: a set of values is a const array + type yes; a single vocabulary word stays a named ALL-CAPS constant (Q2) a class word or part name is one value, not a set
§6: every member has a docstring an override that only fills a documented hook (render(), a fallback's build()) has none (Q3) the base class documents each hook once
§9: undefined, never null null only at platform boundaries: getAttribute(), setFormValue(), the fork's toAttribute, useContext (Q9) those APIs speak null
§17: render pieces are inner functions private methods on the controller, named for what they draw: thumb() (Q12) an element is a controller class, not a function component
§18: PascalCase root classes, nested parts shadow sheets keep Fomantic's class grammar, .ui.small.button a mechanical port of the .less; the override vocabulary people know
§18: private tokens two shapes: --_ui-<tag>-* aliases a public token, --_<tag>-* is variation plumbing (Q13) the name says whether a page can set it
§20: describes name the call path an element's is "<ui-button> keyboard" (Q8) the tag is the element's call path
§10: server code is .server.ts all of src/static/ is, except its barrel (Q20) the static render is node only
all of WWOD packages/solid-element and generated files are out of scope the fork maps 1:1 to upstream PRs; generated files are only regenerated
  • Namespaces cost a family nothing: Rolldown turns E.Cell back into a plain import, so family chunks came out byte-for-byte the same in P1's spike. core pays about 0.8 kB gzipped for the E object.
  • Constants as private statics cost forms.js about 1.0 kB minified (0.27 kB gzipped) when P3 first tried them: a static keeps its name when minified. That measurement is why Q18 moved them below the class.
  • yarn measure's runtimeChunks and coreOutsideCore checks catch a shared module split into a third chunk: I12 and I16 were both that, and both are fixed.
  • core.js is 113,020 B (33,299 gzipped) in ONE chunk now; at the start it was 90,953 B (26,385) plus 4 split-off chunks every page also loaded, so the two aren't directly comparable.

  • Never import an element-core leaf by path ($/ui/elements/UIElement): entering the import cycle there breaks it. src/elements/barrel.test.ts checks every export is live.
  • A family's only constant goes BELOW its class; above it only when a static initializer or decorator reads it while the class loads, with a one-line comment saying so.
  • yarn test:hmr prints 85 Solid STRICT_READ_UNTRACKED warnings, as it did before the epic (I15).
  • WWOD §20's { ...instance } compare is an error under oxlint's no-misused-spread; one of the two needs to change (I22).
  • Two visual baselines are stale from main (ui-menu/appearance, ui-step/equal), and 17 Firefox / WebKit tests failed before the epic too (I23, I24).
  • Behaviour that changed on purpose: flag emoji follow one rule (J47), progress reads indeterminate as a boolean (J63), <ui-tabs> reads its host's document (J65), toast display-time="auto" no longer counts button labels (J71).
  • Loose ends are the plan doc's open todos (T3, T8, T14, T16-T21, T23).
