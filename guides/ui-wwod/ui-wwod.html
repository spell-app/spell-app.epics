ui and WWOD

@spell-app/ui follows the house style (WWOD) everywhere, except in the few places this page lists, each with the reason it departs.

Written for: anyone writing or reviewing code in packages/ui, who knows WWOD and wants to know how ui is built and where it differs Status: built through P17, merged into main Researched on: branch wwod-spell-ui, 2026-10-05 to 10-08; sizes from yarn measure (2026-10-08, after P17), the rest from the code and the plan doc (see Sources) Plan doc: WWOD for Spell UI
  • The rules live in ui's AGENTS.md.
    • A section named like a WWOD rule starts "As WWOD §N, plus:", and lists only what Spell UI adds.
    • This page is the why behind them.
  • Most departures have ONE reason: bundle size. A web component library ships every byte to every page.
  • The rest come from what Spell UI is:
    • a port of Fomantic UI, whose class grammar stays
    • data that node loads without a DOM (vocabularies, the static render)
    • custom elements built on Solid's custom-element layer (Spell UI's own code since epic spell-element)
  • Every tag has two objects: its COMPONENT (the class behind it) and its DOM ELEMENT (the tag in the page). See section 2.
  • A component's changing values are fields with a decorator, read fresh right after a write. See section 3.
  • The restyle (epic wwod-spell-ui, P1-P17) changed public names and signatures. It fixed every caller in the repo: the app, docs, brand and cli packages.
  • Write ui code as WWOD says; where this page names an exception, follow the exception.
  • The COMPONENT: the class behind a tag, UIButton.
    • One instance per element.
    • It holds the state, draws the shadow DOM (render()) and handles events.
    • Its base class is UIComponent.
  • The DOM ELEMENT: the <ui-button> in the page, with its attributes, properties and events.
    • An instance of DOMElement, as an <a> is an HTMLAnchorElement.
    • It's what the browser and every framework talk to.
  • They point at each other: component.domElement, domElement.component.
  • "Host" is only the platform's word now (:host, ShadowRoot.host); "controller" is retired.
  • The custom-element layer (Solid's, folded into ui's DOMElement and UIComponent by epic spell-element) defines the tag and builds the component on first connect.
Component base DOM element For
UIComponent DOMElement every tag
FormComponent DOMFormControl a control with a form value: value, form, checkValidity()
LoadableComponent DOMLoadableElement a tag that shows a text file: source, inline text, save()
PartComponent DOMElement the generic parts (<ui-header>, <ui-content>), styled by their owner
UINag DOMNagElement a family with a script API of its own: nag.close(), nag.dismissed
  • ONE class setting holds what the platform reads when the tag is defined.
  • It's merged down the class chain, base first: a subclass states only the keys it changes.
  • Every literal ends satisfies Partial<E.ElementSetup>, so a misspelt key fails TypeScript.
  • Read the merged result through setup, never elementSetup itself.

  • A FALLBACK is plain DOM, no Solid, shown when an element's render throws (UI<Name>.fallback.ts).
  • Only form controls keep one, so a broken control still submits, validates and resets: button, input, checkbox, dropdown, select, search, calendar, slider, rating; brand's colour picker and composer.
  • Every other element shows its children through a bare <slot>.
  • Owen (P15): "ditch the fallback stuff unless it's necessary for e.g. form functionality".
  • The list and why: fallback.md.
  • A component's changing values live in ONE RECORD per instance: a plain object behind its decorated members.
  • So this.isOpen = true; this.isOpen is true at once, with no flush.
  • Solid still follows every read, in JSX and effects.
  • The decorators are in Reactive.ts; WWOD §12 › "Reactive members" has the rule.
Decorator What it does Example
@state the component's own state @E.state accessor isOpen = false
@controlled the DOM element's property when the page sets it, else the starting value; a write goes to the property @E.controlled("open") accessor isOpen = false
@derived a cached value for real work, recomputed only when something it read changed @E.derived get rows()
@cssState the element's :state() follows the member @E.cssState("active") get isActive()
@onChange runs the method when a named member's value really changes; a returned function is the cleanup @E.onChange("isReady", "hasText") onNameChanged(isReady, hasText)
  • Attributes: a getter and setter per vocabulary attribute, this.size, already converted.
    • One line below the class types them: export interface UIButton extends E.AttributeValues<typeof buttonVocabulary> {}.
    • A base class never uses an attribute's name for a member (elementDefinition, not definition); a test checks it.
  • Raw attributes: this.attributes["aria-label"], the DOM's string or null.
  • An accessor for Solid APIs that want one: this.$.isOpen.
  • Events: this.send("ui-change", detail) to dispatch, this.on("command", ...) to listen for the element's whole life.
  • Booleans read as English (isDirty, looksDisabled); the PUBLIC API is bare, like the platform's (nag.dismissed, readOnly).
  • One folder per family, named for its main tag: ui-button/.
  • Every file in it is named for its COMPONENT, as any class file is named for its class.
  • No one-liner files: a family's DOM element class lives in its component's file.

Each row: what WWOD says, what ui does instead, and why. The letter after it is the plan doc's item that settled it.

WWOD ui does Why
§12: a constant one class uses is a private static a module const below the class, not exported (Q18) a module const minifies to one letter; t.LIST_SEPARATOR doesn't
§12: statics after the main methods a class setting sits with its property group: its @proto static default beside its declare (Q11) Owen: "locate code near its siblings"
§3: booleans start is / has / can inside, yes (isOpen); the public element API is bare (nag.dismissed, readOnly) (J13) a page reads el.dismissed as it reads input.disabled
§19: log through a Logger Warnings.warn() / devWarn() from $/ui/util (Q5) $/util's Logger and its colours would land in every component bundle
§4: one namespace per sub-system yes, as E / F / UI / UIT; but load-time uses (extends, @proto, static initializers) are direct imports (Q4) the element core imports itself: a namespace read while a module loads hits the cycle
§4: import a package through its entry code BELOW core (runtime, vocabulary, icons, util, types files) never imports the $/ui/core entry (I16) core re-exports the runtime's loader; the lazy runtime chunk importing it split off a chunk every page loaded
§4: one alias vocabularies and types files value-import UIT from its file, not through $/ui/core node imports them (yarn site:data, gen:root); core loads Solid's DOM layer, which node can't
§9: a set of values is a const array + type yes; a single vocabulary word stays a named ALL-CAPS constant (Q2) a class word or part name is one value, not a set
§6: every member has a docstring an override that only fills a documented hook (render(), a fallback's build()) has none (Q3) the base class documents each hook once
§9: undefined, never null null only at platform boundaries: getAttribute(), setFormValue(), useContext (Q9) those APIs speak null
§17: render pieces are inner functions private methods on the component, named for what they draw: thumb() (Q12) a component is a class, not a function component
§18: PascalCase root classes, nested parts shadow sheets keep Fomantic's class grammar, .ui.small.button a mechanical port of the .less; the override vocabulary people know
§18: private tokens two shapes: --_ui-<tag>-* aliases a public token, --_<tag>-* is variation plumbing (Q13) the name says whether a page can set it
§20: describes name the call path an element's is "<ui-button> keyboard" (Q8) the tag is the element's call path
§10: server code is .server.ts all of src/static/ is .ssr.ts, its short form, except its barrel (Q20, J19) the static render is node only
all of WWOD generated files are out of scope generated files are only regenerated (packages/solid-element was out of scope too, until epic spell-element folded it into ui)
  • No longer an exception: a PLATFORM string (an attribute name or value, an ARIA word, an event type, a tag name) is written inline. WWOD says so itself now (P17): "a platform string is API, not data".
  • Our own names (ui-* attributes, events, parts) stay vocabulary names or constants.
  • Namespaces cost a family nothing: Rolldown turns E.Cell back into a plain import, so family chunks came out byte-for-byte the same in P1's spike. core pays about 0.8 kB gzipped for the E object.
  • Constants as private statics cost forms.js about 0.27 kB gzipped when P3 tried them: a static keeps its name when minified. That's why Q18 moved them below the class.
  • The decorators (P14) cost core 1.09 kB gzipped, once their helpers were shared; 4.06 kB before (I26).
  • Fallbacks for form controls only (P15): 17.9 kB gzipped less across the families.
  • Platform strings inline (P17): core.js 0.5 kB gzipped less.
  • Now: core.js 70,852 B (25,800 gzipped), ONE chunk; forms.js 6.4 kB gzipped; a page with one button 65.3 kB gzipped.
  • yarn measure's runtimeChunks and coreOutsideCore checks catch a shared module split into a third chunk: I12 and I16 were both that, and both are fixed.
  • UILoader.tsx, cut down.
  • Shared code through E, peers direct, the sheet last.
  • Class settings first, then members grouped by subject, each decorated for how it works.
UILoader.tsx · 95 lines 
import type { JSX } from "@solidjs/web"

import { E } from "$/ui/core"
import { loaderVocabulary } from "./UILoader.en"

import loaderCSS from "./UILoader.css?inline"

/****************
 * ### `UILoader`
 * The component behind `<ui-loader>`:  a spinner, with optional text, showing that something is loading.
 * ...
 ****************/
export class UILoader extends E.UIComponent<typeof loaderVocabulary> {
  @E.proto static vocabulary = loaderVocabulary
  @E.proto static styleSheets = { loader: loaderCSS }
  @E.proto static elementSetup = { delegatesFocus: false } satisfies Partial<E.ElementSetup>

  constructor(...args: ConstructorParameters<typeof E.UIComponent>) {
    super(...args)
    const { internals } = this.domElement
    internals.role = "status"
    internals.ariaLive = "polite"
  }

  ////////////////
  // ## The name
  ////////////////

  /** Which of its slots have content in the light DOM:  slotted text names the status. */
  readonly slots = new E.SlotContent(this.domElement)

  /** Has slotted text?  Tracked. */
  get hasText(): boolean {
    return this.slots.hasContent("")
  }

  /** The element's accessible name:  the `loading` text while nothing is slotted. ... */
  @E.onChange("isReady", "hasText", { writesDOMElement: true })
  protected onNameChanged(isReady: boolean, hasText: boolean) {
    const label = isReady && !hasText ? this.translationForKey("loading") : undefined
    // `null`:  `ariaLabel` is the platform's, and `null` removes it
    this.domElement.internals.ariaLabel = label ?? null
  }

  ////////////////
  // ## States
  ////////////////

  /** Shown (`active`).  `:state(active)`. */
  @E.cssState("active")
  get isActive(): boolean {
    return !!this.active
  }
  ...

  render(): JSX.Element {
    return (
      <div class={this.rootClasses} part={this.partForName("loader")}>
        <slot />
      </div>
    )
  }
}

/** The vocabulary's attribute getters, typed (see "Attributes" in `UIComponent`). */
export interface UILoader extends E.AttributeValues<typeof loaderVocabulary> {}
  • Never import an element-core file by path ($/ui/elements/UIComponent): entering the import cycle there breaks it. barrel.test.ts checks every export is live.
  • A family's only constant goes BELOW its class; above it only when the class reads it while it loads, with a one-line comment saying so.
  • Never write state inside render(), a getter or an effect's first function: Solid 2 forbids it. Write in handlers and @onChange methods.
  • brand's 12 components still use the old layer (I27).
    • The old layer: attrs, controlled(), Cell.
    • Controlled and Cell stay in core until they move.
  • Event names are still open (Q27): keep ui-hide, plain hide, or on-hide.
  • A broken element that isn't a form control shows its children, but not those in NAMED slots; not every docs page says so yet (T27).
  • <ui-components> has no docs page or element example, and the static render ignores packs (T24).
  • Folding solid-element into DOMElement / UIComponent, and a custom-elements guide, moved to epic Spell Element, which has built both.
  • Two problems from before the epic:
    • yarn test:hmr prints 85 Solid STRICT_READ_UNTRACKED warnings (I15).
    • 17 Firefox / WebKit tests fail (I24).
  • Behaviour that changed on purpose:
    • attributes renamed: <ui-form validate-on>, <ui-dimmer show-on>, <ui-popup open-on> (P14)
    • flags are emoji only (J47); <ui-checkbox off-value> (J44); progress reads indeterminate as a boolean (J63)
    • <ui-tabs> reads its own document (J65); toast display-time="auto" no longer counts button labels (J71)
  • Loose ends are the plan doc's open todos (T3, T8, T14, T16-T21, T23-T27).
