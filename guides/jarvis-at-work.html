Spell at Work

Two folders, built on the home machine, become the two work GitLab repos, and run Spell there.

  • jarvis-spell: the app. It installs Spell and runs its page server and editor.
  • epics: the epic repo, with the Jarvis projects in spaces/@psiquantum/jarvis/.
  • They sit side by side: jarvis-spell reads ../epics.

From the home machine, copy both folders, side by side:

  • ~/www/psiquantum/jarvis-spell: 5 small files; Spell itself comes from npm (0.8.10)
  • ~/www/psiquantum/epics: 14 MB

Neither has a .git: copy each into its GitLab clone, keeping the clone's own.

rsync -a --exclude .git <copied>/jarvis-spell/ ~/www/psiquantum/jarvis-spell/
rsync -a --exclude .git <copied>/epics/ ~/www/psiquantum/epics/

In each clone:

git add -A
git commit -m "Spell setup"
git push
  • Already pushed the .tgz? Copy jarvis-spell again, then git rm spell-0.8.9.tgz (step 6).

Node 24.11 or later, then:

cd ~/www/psiquantum/jarvis-spell
yarn install
yarn start
  • Open http://127.0.0.1:4747/.
  • The first time, it asks your name, labelled @psiquantum.
  • The home page shows the Jarvis projects under the org's group.
 
cd ~/www/psiquantum/jarvis-spell
yarn epic init --no-commit
  • It finds the settings already there and ../epics already cloned: nothing new on GitLab.
  • It installs the epic plugin for Claude Code and Spell's VS Code extension, once per machine.
  • It asks your short name and your colour on the pages.

Anyone can run it: Spell installs from npm.

  1. Clone both repos side by side, named jarvis-spell and epics.
  2. Node 24.11 or later.
  3. yarn install && yarn start in jarvis-spell; each person gives their own name.

Spell 0.8.10 is on npm (2026-11-17). A checkout still on the .tgz moves over:

  1. In jarvis-spell's package.json: "spell": "^0.8.10".
  2. Delete spell-0.8.9.tgz.
  3. yarn install, then commit and push.
