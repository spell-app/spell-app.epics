The Epic Elements

The 25 <epic-*> tags a plan doc is made of, how they nest, and a page for each.

Written for: anyone reading or writing a plan doc's markup, or changing an element Status: built every tag in components/ The full markup rules: PLAN-DOC.md
  • Each tag is an element: it draws itself.
    • Its ATTRIBUTES are data (an item's status).
    • Its CHILDREN are prose (the doc's own words).
  • What it draws (chips, title lines, buttons, card headings) lives in its shadow root, never in the file.
  • Each is described once, in its vocabulary file (<Name>.en.ts): its attributes, their values, and which children it takes.
    • The browser and the plan-doc tool both read it.

Why it's built this way, and how a page draws: Epic Pages as Components.

Tag Its role
epic-page The whole doc: holds its data (epic, title, branch, dates) and draws the header, crumbs, Send and Review Now.
epic-overview The Overview: the summary, the kickoff prompt and the plan's prose parts, with the estimate total.
epic-summary The Overview's two-sentence lede.
epic-prompt The prompt that started the epic, as typed, folded under "Kickoff prompt".
epic-section One section by its kind: its numbered title, count and state filter; or an Overview part.
epic-phase A phase: its status, estimate and fields.
epic-field A labelled block: a phase's Symptom, Goal, Done ..., or "Where:" in an item.
epic-updated A dated change to a phase's plan: the orange Updated fence.
epic-update The orange UPDATE marker on something changed while its phase runs.
Tag Its role
epic-item Any item (its kind is its id's letter): the line with its chip, the review buttons, the folded details.
epic-question A question's text as first asked, under "Question".
epic-choices A set of option cards, on any item; which one was chosen.
epic-option One option card: its letter, title, the recommended thumbs-up, the Choose pill.
epic-answer A question's answer card.
epic-more The "More Details" card that Add Details writes.
epic-reply A reply card, Owen's or Claude's, dated at the right of its band.
epic-status Claude's status card on a mark: blue "Underway", then green "Done".
epic-original The folded Original Discussion: text a rewrite replaced.
epic-version One earlier version inside it, dated.

Blocks prose used to shape by hand. Each goes wherever prose goes: an item's text, a reply, an option card, a phase field.

Tag Its role
epic-net-effect "Net effect (A, recommended):" over its list.
epic-code A folded, highlighted code block.
epic-aside A folded "Aside:" the main text can skip.
epic-note A small orange UPDATE (or green DONE) note that stays in the prose.

epic-field (above) is one too, with a label: "Where:", "Step:".
Tag Its role
epic-commit A commit under a phase or an item, linked through the page's repo.
epic-event One line of the log, in its own date format.
  • A new one: spell dev pack element epics epic-<name>. Change the vocabulary first, then the class and its sheet.
  • Then yarn pack:build in the epics package, and commit its built pack (pack/) with the change.
    • yarn test fails while the pack is stale.
  • Plan docs draw with main's pack, so a change shows only once it merges.
    • Small fixes go straight on main.
  • A tag the docs already use, changed in its markup: a converter run, never a second way to read the old markup.
