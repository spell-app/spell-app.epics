<epic-aside>

A folded aside in prose: a digression the main text can skip. It draws an ivory panel headed "Aside: <title>"; the aside is its children.

For anyone reading or writing a plan doc's markup, or changing this element. Its vocabulary (every name it uses): packages/epics/components/epic-aside/EpicAside.en.ts. Its component: packages/epics/components/epic-aside/EpicAside.tsx, with its .css and .test.tsx beside it.

A real one, from epic docs-workspace (O3). Click its heading to unfold it.

Ids, icons, UPDATE markers and the "updated" stamp must agree across the phase list, the phase sections and the items. Agents editing by hand drift; the script also locks the file so parallel agents take turns.

Its parents:

  • Anywhere prose goes: it's a prose element:
    • <epic-item>: among an item's own text, before its cards
    • <epic-answer>, <epic-more>, <epic-reply>: the cards under an item
    • <epic-option>: an option card's pros and cons
    • <epic-field>: a phase's field, or a labelled block
    • <epic-updated>: a change to a phase's plan
    • <epic-section>: an Overview sub-section's prose, or a report's
    • <epic-version>: an earlier version, kept as it was
    • another prose element (a note inside an aside), or plain HTML around it (a <li>, a <div>)

A slot is where the element's own children show.

Slot Holds
(default) The aside.

A part is a piece of the drawing a page's CSS can reach.

Part Is
base The panel.
toggle Its heading, a <button> that folds it: the chevron, then heading.
heading The heading's words.
body What it folds; hidden (until-found) while folded.

A state is set by the element on itself; none is ever written in the doc.

State When
open Unfolded: the reader opened it.
  • The brand's ivory panel, as the docs' asides (ui-accordion.spell-aside): warm, rounded, no border (--epic-aside from <epic-page>, with a fallback).
  • Its heading in the headings' italic serif, so it reads as an aside, not a section. Its text a step smaller than the page's.
  • No state colour: the ivory is the panel's, not a meaning.
  • Folded to start with. A click on the heading, or find-in-page, unfolds it; folding is the page's, never written.
  • It shares its shape with <epic-code> (EpicPanel, in the same family folder).
  • Claude writes it inside the HTML it passes to spell dev plan-doc (add ... --details, decide --details, details --file, updated): no command makes one by itself.
  • The tool's way in (IncomingHtml, ProseRewrite) turns the OLD hand-shaped markup into this element in any HTML a command takes (add --details, decide --details, details --file, updated), so a doc never holds the old shape. Prose edited by hand in a part file isn't passed through it. The old shape: ui-accordion.spell-aside.
  • The converter did the same to every converted doc (ProseUpgrader).
