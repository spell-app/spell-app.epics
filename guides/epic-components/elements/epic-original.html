<epic-original>

An item's Original Discussion: the text a rewrite or a second answer replaced, kept so nothing is ever lost. It draws a warm panel headed "Original Discussion", folded, with one <epic-version> inside per earlier version, oldest first.

Written for: anyone reading or writing a plan doc's markup, or changing this element Its vocabulary (every name it uses): packages/epics/components/epic-original/EpicOriginal.en.ts Its component: packages/epics/components/epic-original/EpicOriginal.tsx, with its .css and .test.tsx beside it

Two of them. The first is a real one (from epic solid-migration, C18): one version, dated when it was replaced. The second holds two versions, so the first is headed "As first written". Click a heading to unfold it.

Its place in an item, with the item's other children: packages/epics/src/tool/PLAN-DOC.md, "Items".

Its parents:

  • <epic-item>: at most one, after the replies and before the commits (an item's children go in a fixed order)

Its children:

  • <epic-version>: one or more, oldest first

Everything that reads an item skips it: its option cards are never counted for a pick, and its links are never checked. Ids inside are renamed data-original-id, so no link lands in it.

None: its versions carry the dates.

A slot is where the element's own children show.

Slot Holds
(default) The versions.

A part is a piece of the drawing a page's CSS can reach.

Part Is
base The panel.
toggle Its Original Discussion heading, a <button> that folds it.
body The versions; hidden while folded.

A state is set by the element on itself; none is ever written in the doc.

State When
open Unfolded. It starts folded.
  • A warm panel, rounded, no border: the brand's ivory (--epic-aside from <epic-page>, with a fallback), as the docs' asides.
  • No state colour: it's history, nothing to act on.
  • Its heading is a button: a chevron, then "Original Discussion" in the headings' font. The chevron turns down while it's open.
  • Folded to start with. Folding is the page's, never written to the doc.
  • Folded, its body is hidden="until-found": find-in-page still reaches the text, and unfolds it.
  • spell dev plan-doc details <name> <id> --file <html>: a rewrite of the item's text moves the old text here, as a new version.
  • decide again, and details ... --more again: the answer or More Details they replace.
  • spell dev plan-doc original <name> <id> --file <html> [--as-of "YYYY-MM-DD HH:MM"]: text recovered from git (old markup welcome).
  • The tool makes it when the item has none (PlanDoc.keepOriginal()), and skips a version that says the same as one already there.
  • The converter (spell dev plan-doc convert) turned the old markup's Original Discussion into it (CardConverter).
