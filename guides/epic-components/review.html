Reviewing an Epic Page

Owen presses Revisit on a judgement call, types "one JSON file for the pack templates, or a file each?", and sends. A blue "Claude • Underway" card appears on that item; minutes later it turns green "Claude • Done", with the answer in the item itself. Like a pull-request review, the comments sit on what they're about; unlike one, a listening Claude session answers them INTO the page.

Written for: Owen reviewing a doc, and any session or skill answering a review Status: built the review controls moved into the elements at P9-P10; status cards P13; picks anywhere and the new buttons P14 The loop step by step: plan-doc.md, "Review inbox"; the skill: epic's SKILL.md, "7. Review"
  • The controls show only while a session reviews the doc (<epic-page reviewing>), and only from a page server with the review routes.
    • Not from disk: from file:// there are none.
  • Nobody listening: the page says so (orange, inverted), in its review line and in Send's tooltip.
    • The line also shows the command to type, /epic review <name>; a click copies it.

On every item's line: ONE group of three, then Do Now apart.

Button Colour Asks Claude to
Approve (check) green accept it as it stands: a question answered with its recommended option, a judgement call closed, a test passed
Revisit (history) blue look again, with the note; answered as a reply in the item, talked over one at a time
Make Todo (list check) green file a todo "Follow up: <title>" linking back, with the note
Do Now (paper plane), apart blue do it now, no send needed: Add Details (a More Details card), or a revisit now when the note box holds a note
  • The note box under an item keeps Revisit later and Make Todo.
    • What Owen types is saved as he types, and survives a reload.
  • A running Do Now clicked again is "nevermind": the session stops that item's agent.
  • The page header has Send (paper plane) and Review Now (wand).
    • Review Now sends every mark AND asks every waiting revisit now, answered at once by background agents.
  • An item Claude has answered keeps its three-button group, so Owen can still approve it.

A review button's fill says how far along Owen's mark is: dashed when he's pressed it, outline once sent, grey again once Claude is done. The buttons are his INPUT to Claude, so they never show Claude's verdict; the id chip does.

Fill Means
grey outline available: nothing pressed
DASHED, in its colour pressed, not sent (a Do Now not taken yet)
OUTLINE, in its colour sent, or in progress (a Do Now taken: its icon turns while Claude works)
cleared to grey handled: Claude applied it or finished it; the id chip carries the result
  • While a mark is live, the item's id chip MATCHES the chosen button: an Approve pressed, not sent, is a dashed green chip; a revisit sent, an outlined blue one.
  • Once handled, the chip shows the item's state, solid: green decided, yellow still open, red needs Owen.
  • review-as stays in the doc as the record of how a mark was handled; it's never drawn on the buttons.
  • The whole colour scheme: Epic Page Colours.
  • Every option card shows a Choose pill while reviewing: a question's own, and those in a judgement call's text, a reply or More Details (P14, I8).
  • The mark names WHICH card set by its position in the item: { pick: "B", choices: 1 }. An Original Discussion's cards are never counted.
  • Applied, a pick answers a question with that option.
    • Any other item is APPROVED with it: an open judgement call is closed, accepted.
  • Either way the item gets a green Done card, "Chose B · <title>", and the applied pill turns solid.
  • A pick with a note ("B, but ...") is a revisit carrying the pick: talked over, never applied by itself.
  • A closed item's cards take pills too, but only while Owen revisits it: "pick B instead, because ..."

Each card says what Claude took a mark to mean, and then that it's done (P13). There's one card per mark, under Owen's note, and only the tool writes them.

Mark Card
Revisit (soon or now), Do Now, a pick with a note blue "Claude • Underway" the moment Claude takes it: one or two sentences on what Claude understood, no file names. When the work lands, the SAME card turns green "Claude • Done"
a plain pick, Make Todo a green Done card at once, saying what was filed (Q19): "Chose B · Keep one file per template"
a plain approval none: nothing to read, nothing to report
  • A summary follows on a Done card only when there's something worth saying: a surprise, a choice made, something left undone.
  • An Underway card makes its item blue (Claude is working on it) until it's done.
  • A later mark on the same item gets a new card; the old ones stay, as the record.
  • The commands:
    • epic update <name>#<id> underway "…"
    • then done ["summary"], or done --filed "…"

  • Marks wait in the doc's INBOX FILE, epics/<name>/<name>.inbox.json, until a session takes them.
    • It's git-ignored: pending state on this machine, never the record.
    • It's absent until the first mark, and deleted once empty.
  • The page writes it through the page server, with ONE review client per page.
    • The client: ReviewClient.
    • The server's routes, /api/review/...: reviewRoutes.ts.
  • One mark per item. Typed notes are kept as drafts until the mark that uses them.
  • A page whose server restarted takes the new token and retries once: nothing typed is lost.
  • The session's heartbeat: after 90 seconds of silence, the page says nobody is reviewing again.
  • Read it: epic inbox <name>. Never edit it by hand.

What a /epic review session runs, in order, so the work card goes up BEFORE any agent starts:

Command Does
inbox <name> listen the page stops saying nobody is reviewing
inbox <name> wait, in the background exits when there's work, which wakes the session; prints each mark with its item and note
inbox <name> apply the mechanical marks (approve, pick, todo) into the doc, each logged, with their Done cards
status <name>#<id> underway "…" first, for every work mark, before any agent starts
details <name>#<id> --append | --more --file f an agent's answer, into the item
status … done, then inbox <name>#<id> done the card turns green; the mark and spinner go
inbox <name> unlisten on leaving
  • Every answer goes INTO its item, on the page; the chat only links it.
  • Owen comes to a review cold: never a bare id in chat, always what it is in words.
  • Each Overview sub-section (o1, o2 ...) takes review marks too (Q14), so the plan's prose can be commented on, not only its items.
  • It has Make Todo, Revisit and Do Now, a note box and status cards.
    • Not yet: no Approve, and no picks (J35).
  • A todo made from one links back to #o3; a kept note is a paragraph at its end.
