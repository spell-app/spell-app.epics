WWOD ("What Would Owen Do?") is the house style every agent follows here: how we write any code, in any package. It's a set of Markdown files an agent reads, not a linter.

  • It started as Owen's rules for another project, construct-app (Svelte 5, Tailwind, SvelteKit). Epic wwod made it this repo's:
    • sorted every rule (353 of them)
    • translated the Svelte ones to Solid 2
    • dropped what only fit construct-app
    • merged in this repo's own style rules
  • It lives in agents/wwod/: 10 files, 20 numbered sections, and 225 rules, each with a bold title an agent can cite.
    • a HUB (WWOD.md, §1-7)
    • eight topic SPOKES (§8-20)
    • a README.md
  • Owen reviewed every file, one at a time, in plan mode's comment tab: 92 comments over 10 files, through the new /comment skill.
  • The root AGENTS.md now holds only what's about THIS repo, and sends every agent to WWOD first.
    • Package AGENTS.md files say "As WWOD §N, plus:" where they add to a rule.
  • Code that doesn't follow WWOD yet is recorded in CODE-DEBT.md, not rewritten: this epic wrote rules only.
  • spell wwod check keeps the rules from rotting: every citation and repo path must resolve.
  • Also on the branch: a worktree's VS Code window now has two folders, the main repo root and ⎇ <name> (window.mjs).
  • One home per rule; everywhere else, a one-line SEE:.
    • House style goes in WWOD.
    • What's about one repo or package goes in its AGENTS.md.
    • How Solid 2 works goes in solid-2.md.

One hub every task needs, and spokes an agent reads only when the work touches their topic. The § numbers run on across all of them.

Every rule has exactly one home, picked by what it's about.

WWOD House style: how we write any code, in any package. Naming, errors, classes, tests ... AGENTS.md The root's: what's about THIS repo (packages, dependency direction, worktrees, changelog, toolchain, ledgers). A package's: only what's local to it. solid-2.md How Solid 2 itself works: its mechanics, measured. The house style on top of it is WWOD §17.
  • Anywhere else a rule is needed, it's one line pointing home: SEE: WWOD §N › "title".
  • For example, the six Solid mechanics this epic first added to solid-2.md (reading once with untrack, onCleanup, <Loading>, <Show keyed>, useContext, ClassBuilder) moved into solid.md, beside the house rules that use them. solid-2.md keeps the mechanics only.
  • A doc's own distilled rules (docs' AGENTS.md, "Agent rules") stay about ITS topic; house style never goes there.

Where each kind of agent picks the rules up, in the order it reads them.

  1. Claude Code loads the root CLAUDE.md, which @-imports AGENTS.md and then WWOD.md, so the hub is in every session.
  2. Codex and other agents read every AGENTS.md from the root down, and the root's first rule says READ WWOD.md before any code.
  3. The spokes are read on demand: the hub's "Touching → Also read" table names the spoke for what the work touches.
  4. A package's AGENTS.md holds what's local to it, and the hub's table sends agents there for anything inside a package.

Every rule can be pointed at exactly, so review comments, epic pages and other rule files never have to restate it.

  • A rule is a bullet with a bold title (or a ### heading) under a numbered section.
  • Cite it as WWOD §N › "title", for example WWOD §5 › "Sentinel errors as control flow". A whole section: WWOD §18.
  • Inside WWOD, a bare §5 means WWOD's; elsewhere, always write WWOD §5.
  • Sections are numbered across the hub and the spokes: §1-7 in the hub, §8-20 in the spokes.
    • Renumbering is allowed: the check finds every citation it breaks.
agents/wwod/classes-state.md, a rule and its rejected option · 5 lines 
- **TS `private`, never `#private`:**
  - `private` / `protected` for fields and methods alike.
  - Why:  `#private` throws when reached through a `Proxy` wrapping the instance, and tests can't reach it.
  - NOT:  `#` for private fields, TS `private` for methods -- see above.
  • A package AGENTS.md section that shares a WWOD rule's name EXTENDS it. It says so in its first line, "As WWOD §12, plus:", then gives only what's local.
  • Today 10 packages do it, mostly for §4 (imports, with the package's own alias), §8 (its self-namespace) and §12 (classes).
    • ui also does it for §18 (its CSS layers), and cli for §20 (its tests).
  • The same form works one level up: docs' AGENTS.md opens "As the root's AGENTS.md and WWOD, plus:".
spell-app/src/cli/AGENTS.md, "Tests" · 7 lines 
## Tests

As WWOD §20, plus:

- They read spell's frozen projects, `../spell/projects/test/` (`@test/<Project>`) -- see "Overview" in
  `../spell/AGENTS.md`.  NEVER write into one:  compile with `--stdout`, or make a temp project, as
  `cli.test.ts` does.
  • NOT: under a rule records the option we chose AGAINST, with the why, so nobody proposes it again.
    • Many are WWOD's original rule where ours won: #private, a UI_* prefix, isSelected state classes, a MSG.ts per package.
  • Each spoke opens with a From: line naming the original WWOD sections and the repo files it came from. Those lines cite the ORIGINAL numbers, so the check skips them.

The steps, from wwod's README.md, "Adding a rule":

  1. Put it in the spoke for its topic, or in the hub if every task needs it, as a bullet with a bold title.
  2. A rule we chose against: a NOT: line under the winning rule, with the why.
  3. Cite real code by repo path, so an agent can read the example.
  4. A new section: number it after the last one.
  5. Run spell wwod check. A retitled rule breaks its citations, and the check lists them.
  • Move a rule, never copy it. Leave a SEE: line where it was, if anyone looks for it there.
  • Code that doesn't follow a new rule yet gets an entry in CODE-DEBT.md (see Ledgers), not a silent rewrite.
  • spell wwod check (wwod.ts, ported from the epic's cites.py) exits 1 on any broken citation or path.
  • Every WWOD §N must name a section, and every WWOD §N › "title" a rule in it.
  • Every backticked repo path must exist (packages/..., agents/..., .claude/... ...).
  • Files checked: WWOD itself, the root and package AGENTS.md / CLAUDE.md, goals' AGENTS.md, solid-2.md; and skills, for their citations only (their paths are relative to the skill).
  • A new file that starts citing WWOD must be added to CITERS in wwod.ts, or the check never reads it, and never says so.

Problems we know about and live with go in three shared files. Each has one ## <package> section per package, and its own rules in its header.

  • CODE-DEBT.md: structural debt we chose not to fix yet, including code that doesn't follow a WWOD rule yet. Each entry names the rule and, for this epic's, the todo that fixes it.
  • SUSPECTED-BUGS.md: looks like a bug, not sure yet.
  • PAPERCUTS.md: anything that slowed development down; check it first when tooling fails.
  • The rule that sends agents there: WWOD §1 › "Record deviations and known issues; NEVER fix them silently".
    • Where they live, and their format: the root AGENTS.md, "Long-term debt".

The calls that shaped WWOD, with their reasons. Each is an answered question in the epic page (Q1-Q32): don't re-argue one without new facts.

  • Hub and spokes: Owen liked WWOD's structure. The hub holds what every task needs; a spoke is read only when the work touches its topic.
  • In the shared agents/wwod/: one copy for every checkout, beside the ledgers, its edits committed by themselves (Q18).
    • It first went to wwod/, to get agent sources out of .claude/, where they're hard to see (Q1).
    • Then main's shared-content move made agents/ the better home.
  • § numbers across hub and spokes, cited WWOD §N › "title": a review comment or a plan doc can point at one rule exactly. Renumbering is fine (Q2).
  • House style in WWOD, repo-specific rules in the root AGENTS.md: package map, dependency direction, aliases, worktrees and windows, changelog and ledgers stay in the root (Q2).
  • CLAUDE.md @-imports the hub: §1-7 used to sit in the root AGENTS.md, which Claude loads every session.
    • Without the import, they'd load only when an agent followed the READ line; with it, Claude's behaviour didn't change.
    • Codex has the READ line only (judgement call J15).
  • CLAUDE.md holds Claude-only rules: it loads AGENTS.md and WWOD, then adds what only Claude needs. Its repeats of AGENTS.md were trimmed (Q25).
  • One home per rule: the redundancy audit found about 60 repeats and contradictions across WWOD, the AGENTS.md files, CLAUDE.md and solid-2.md.
    • About 45 moved to one home, with SEE: lines.
    • 9 statements found wrong against the code were fixed.
  • Five package rules moved into WWOD because they were house style: names aren't identifiers, browser-safe barrels, writing for people, "people" never "users", ask before adding a runtime dependency (Q24). Each package keeps a SEE: or its local example.
  • One namespace per package; a types-only leaf import is PT, never a bare T: WWOD's T was only for files that can't load the barrel, and a bare T confused people (Q4).
  • TS private, not #private: # throws through a Proxy (every spell Thing is one), and tests can't reach it. The code had about 1730 TS private to 50 # (Q5).
  • test() for new tests, one style per file: renaming about 3400 it() calls would touch about 350 files, and clash with every running branch. The codemod is debt (Q6).
  • Error classes stay in <folder>.types.ts, with X.prototype.name = "X" after the class, because minifiers mangle a name taken from constructor.name. Details go in a typed cause, and guard messages name their method, the problem and the fix (Q7).
  • Classes everywhere: singleton services are classes, and stateless ones too (Q12).
  • Subclass for behaviour, spread for plain config: spell's classes subclass on purpose (@proto static defaults, specialize()), and plain spec records spread (Q13).
  • SPELL_* for every environment variable, ui's too (SPELL_UI_*), so one prefix finds every variable we own (Q17).
  • Server files end .server.ts, and a package's environment variables are read in its environment.server.ts only, so server code stays out of the browser bundle (Owen's review of server-env.md).
  • CSS sub-parts nest, unprefixed, under the component's root class; custom properties are prefixed. That matches the app, and native nesting already scopes them (Q15).
  • Lowercase state classes (.Row.selected), as Fomantic and ui do (Q8). Also from Q8: a README.md required per package, and no CORRECTED <date> markers.
  • Ours over WWOD's where the tools or measurements decide: oxfmt at 120 columns, standard (TC39) decorators only, and no "memoize every getter", because a cheap getter memoized measured about 2x slower (Q8).
  • No MSG.ts: strings stay inline, and only ui localizes (Q10).
  • Booleans: never a positional boolean. One mode switch is a sentinel string; several options are a params object, where named booleans are fine (Q19).
  • Switches by who sets them: an ALL-CAPS static is a developer or debug switch; @proto static is behaviour a subclass or instance overrides (Q21).
  • Constants: at module level, BEFORE the function that uses them (after won't work). In a class, helpers and constants go AFTER the main methods (Q22).
  • Runnable scripts in scripts/ or tools/ keep kebab-case names, named for their command (Q23).
  • Solid 2 facts beat Svelte rules: never destructure props, no module-scope context, no deep-state mutation, no use:. The framework decides these, so they weren't choices.
  • Four of WWOD's CachedResource rules kept for Loadable, our equivalent; the other three were dropped (Q16).
  • Rules plus debt entries, no code rewrites: each place the code disagrees is a CODE-DEBT.md entry, so later epics can fix them one at a time. New code follows the rules at once (Q3).
  • Helpers written as if built: setDebugGlobal(), safelyCall(), debounce() and makeErrorWrapper() appear in the rules. Building them is a todo for later, setDebugGlobal() included (Q11, Q30, Q32).
  • Dropped as construct-app-only: Circuit records, undo and action maps, CachedResource, PostHog and Sentry, Tailwind, APITransaction, Dynamo.
  • Left open on purpose:
    • WWOD's x ?? die("msg") idiom stays out until util's die() is settled (Q9).
    • How a TypeError thrown in a route answers waits for the error-classes work (Q20).
  • Spokes are read on demand, not loaded.
    • An agent that skips the hub's table misses the spoke, as it could always miss solid-2.md.
    • Codex doesn't load even the hub by itself: it has the root's READ line only.
  • Our files don't line up one to one with the originals in wwod-original/. Spokes were merged, split and renamed: 9 spokes and §1-22 there, 8 spokes and §1-20 here. Each spoke's From: line names its sources.
  • Some rules are ahead of the code. Each gap is a CODE-DEBT.md entry; until it's closed, use the hand-written form.
    • Four helpers don't exist in spell-kit/util yet: setDebugGlobal(), safelyCall(), debounce(), makeErrorWrapper().
    • Nothing reads SPELL_DEBUG yet.
    • Most packages don't follow §5 (errors), §11 (environment) or §19 (logging) yet.
  • The check reads a fixed list of files. A doc or skill that starts citing WWOD is checked only once it's added to CITERS.
