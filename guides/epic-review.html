Epic Review

Owen picks "Todos · 17/21", ticks four cards on a details page, and Claude brings them up one at a time: Accept, Explore, Explain further or Defer. Each answer is in the epic page before the next item shows. That was /epic review [<name>] as first built: an issue-triage pass, except nothing is left to update afterwards. Its modal walk has since been replaced by reviewing on the page (Status, below); this page is for whoever runs, changes or extends what's left of it.

Epic page: epic epic-review Written for: Claude sessions running a review, and whoever changes the skill or the epic tool Status: built 2026-10-04; its modal walk through items was replaced by reviewing on the page (epic review-review P6): today's loop is in Epic Pages The rules: epic's SKILL.md, section 7
  • Epic pages pile up open items: caveats, todos, issues, questions, judgement calls, things to test. Nothing recorded which ones Owen had already gone through.
  • A review picks a section, and Owen ticks the items on a details page.
    • Then each comes up in chat: the item as clean bullets, then a modal to accept, explore, explain further, or defer.
  • Every answer lands in the epic page at once, and the item is marked reviewed, so the next review starts where this one stopped.
  • Work an answer calls for goes on the epic's to-do list; the next review offers to start it in its own worktree.
  • The docs' home page shows every epic, running and merged, in one Epics list, each with its state and an Open | All filter.

Every modal is headed Epic Review: <name>, asks one plain question, and never shows a bare id: Owen comes to a review cold, with 5+ epics on the go.

How a review starts: Owen types /epic review <name>, clicks the orange "No Claude session is reviewing" pill on the epic page, or presses Send, Review Now or Do Now there while no session listens (epic epic-workflow P16).

  • The page server then types /epic review <name> into the epic's running session, or opens a new session in the epic's window (or a main window, for an epic with no worktree).
    • Owen presses Enter there: it never sends the prompt for him.
  • The pill says what it did ("Typed /epic review seo into 🚧 seo: press Enter there") until a session listens.
  • It wakes a session at most once per epic per 10 minutes.
    • Nothing is woken with several sessions titled for the epic, in airplane mode, or for a Send with nothing new.
  • A review page (epic ask create ... --from a spec that epic items <name> --section todos --spec <file> writes), titled "Choose todos to review", no site header.
  • Each card is in two columns:
    • the tick box, a (?) "Provide more details", and a state icon (orange circle: not reviewed; grey pause: deferred; green check: reviewed; blue list: to do)
    • then the title and the item's whole text from the epic page, its links rewritten to work from the page
  • Select all / Select none (one button), and Open | All: Open hides the reviewed ones.
  • The answer names the ticked ids, and More details wanted on: the (?) ones: those skip the short version and start with the full explanation.
  • A details page: plain words, the real code, a table, the options side by side.
    • Kept with the epic (epics/<name>/details/) when this checkout holds its live doc, else a scratch page.
  • Then a second modal: up to two options, recommended first, then Defer and Exit.
    • Choices that don't fit a modal are answered on the page.
Mark Means Label, after the item's id
data-reviewed="2026-10-03" gone through with Owen; the outcome is in the log green "reviewed 10-03"
data-deferred put off; still not reviewed grey "deferred" (date on hover)
data-queued + data-work work a review decided on, not started yet; also reviewed blue "to do" (the work on hover)
  • REVIEWED also counts an item that's struck, decided, or linked from a decision's details, so a doc settled before the marks existed isn't all "not reviewed".
  • Kept current: every /epic session marks the items it talks through with Owen.
    • Older docs: a one-off epic backfill finds items Owen named in past sessions (his messages, modal answers), a dry run unless --apply.
epic ... · review commands 
list [--json]                                every epic (main + worktrees):  status, not reviewed / items
items <name> [--section s] [--filter f] [--json]   where reviews stand, the to-do list, sections
items <name> --section s --spec <file>      the item picker, as a details page spec
review <name>#<id> ["outcome"]             mark reviewed today;  the outcome goes in the log
defer <name>#<id>                         put off;  still not reviewed
queue <name>#<id> "work"  /  unqueue       on / off the to-do list
backfill <name> | --all [--apply]           one-off:  what past sessions show Owen went through
  • Every command edits the epic's one epic page, the same file in every checkout (shared content, since 2026-10-04): no per-worktree copy to find or avoid.
  • The prompt hook lets /epic review ... through untouched (review is a reserved epic id): a review runs from any window, and keeps the session's name.
  • One Epics section, from two writers:
    • epic pages index writes the merged epics' cards and a slot
    • the main checkout's page server (RunningEpics) fills the slot with the running ones, dropping a merged card of the same name
  • Each card's title starts with its state (since 2026-10-10, epic airplane P8):
    • [3/6]: in progress (blue)
    • a red exclamation: errors (every phase done, items need you)
    • a grey pause: paused (phases left, no session, no update for 3 days)
    • a green check: done
  • Since epic airplane P8: the cards sit in five groups (Favorites, Active, Planning, Urgent, Done), and epic pages filter their items by state chips in the toolbar, in place of Open | All.
  • A details page to pick items, not ids typed in chat.
    • Owen ticks; nothing to remember or type.
    • The first design had him type "I4, I5" or filter words.
  • The item's whole text on the picker. One-line summaries were too dense to parse. The cost is length, so long ones clamp at 150px with Show more.
  • Fast by default. The item as bullets and one modal; the full explanation only when Owen asks (Explain further, or the picker's (?)).
  • Work is never done mid-review. It goes on the to-do list, so a review stays quick; "Start work" opens it in its own worktree.
  • Every epic-page command edits the live doc. Otherwise, a review of a running epic from main would fail on a decide or a close, or edit a stale copy.
  • Modals hold four options. So:
    • the epic picker pages two at a time with More
    • the section picker shows three
    • Exit is typed in Other on the item modal
  • A mockup first. The interaction was clicked through on canned data and reshaped six times before any real state existed.
  • Backfill is heuristic, and finds little: Owen rarely types item ids.
    • The marks sessions add from now on matter more.
  • A card's state is only as fresh as what drew it:
    • served by the page server, it's judged on every load (a session running, today's date)
    • opened from disk, it's as of when docs index last ran
  • "Start work" ends the review's turn (the session moves to the new window); /epic review <name> picks it up again.
  • A details page replaces the epic page in the side bar until the review reopens it.
