Airplane Mode

On the plane, Owen marks items, comments and adds new epics in VS Code's side bar, and every click saves on the laptop. On the ground, /airplane land gathers it all and works through it in the background.

Airplane mode is how Owen works on the epics and docs with no Claude (a plane, bad wifi), and how Claude takes what he left once he's back. Most days a mark goes straight to a session that answers it; here it waits in an inbox on this laptop until the landing.

  • Everything Owen does on a page saves to this laptop's page server: no internet, no Claude.
  • /airplane before the flight: checks the laptop is ready, fixes what it can, turns airplane mode on. It asks first whether to run /docs-check on the epics merged since the last flight.
  • On the plane, in VS Code's side bar:
    • read any epic page or guide
    • mark items, note a phase or the summary
    • comment on any block or selected text
    • add new todos, questions and epics
  • /airplane land after: gathers everything he left, by place, and works through it in the background. Then /epic review for what came back.

Three things, because the side bar shows the MAIN checkout's page server:

  • The airplane branch is merged into main.
  • The VS Code extension is reinstalled from main.
  • /airplane runs in the main checkout.

Five parts, one per gap the explore agents found, then what reviewing all day on 2026-10-10 asked for: toolbars, the header, the side bar, comment threads.

  • Every docs page loaded its code highlighter (highlight.js) from the internet, and waited for it. On a hanging network, the page showed raw markup for tens of seconds.
  • The repo now has its own copy, highlight.min.js.
  • The page server points each page at that copy as it serves it (localHighlight()): no page changes on disk.
  • New epic pages and list pages use the local copy from the start.
  • epic pages offline lists anything a page still fetches from the internet; with --fix, it points the old tags at the local copy.
  • One switch per machine, in a small file: ~/.spell/airplane.json (read and written by AirplaneMode, in the epics tools).
    • It was the page server's own until epic epic-eject (P4): on main it stays there until that epic merges.
  • epic airplane on | off | status flips and reads it.
  • The page server tells each page whether it's on, as it serves the page (SPELL_SERVER.airplane).
  • With it on, an epic page says "queued for when you land" wherever it said "no Claude session is reviewing".
  • Its review line names /airplane land, with no orange warning.
  • /airplane asks, every time, whether to run /docs-check first, on the epics merged since the last flight. Its fixes wait in Source Control to review on the plane.
  • The summary and every phase take Revisit, Make Todo and Do Now, as Overview sections do (no Approve).
  • A new item is a mark of its own kind in the inbox (action: "new"), keyed new1, new2 ...
  • It shows dashed at the end of its section until it's applied.
  • epic inbox apply <name> makes the items, as epic add does.
  • With --all, it also takes marks never sent.

What Owen does:

  • Starts one with the bullhorn beside a block (sections, tables, asides, code, items, phase fields), or ⌘ I on selected text, which keeps the quote and highlights it softly.
  • Writes it in a small floating pane, just under the selection:
    • drag it by its header; the page never scrolls
    • it saves as he types: the floppy shows saved, or turns red
    • Tab or a click elsewhere saves it; × or Escape closes it
    • never an empty comment: nothing typed saves nothing, and emptied, it goes
  • Reads it after as a THREAD: one ivory pane under the paragraph the quote is in.
    • each message starts with a bold You: or Claude:, its time at the top right
    • while it's his turn: the item's pills, ✓ (that's good), Revisit (reply) and × (skip it)
    • a reply box at the end of every open thread
    • Done folds it, with Undo; a closed thread shows Reopen
  • Deletes one with one click on the trash; Undo in the toast brings it back for 6 seconds.
  • Send hands over waiting comments and replies, as it does marks.

What Claude does:

  • Finds them where they wait, on this laptop, git-ignored:
    • a docs page's in <page>.inbox.json, beside it
    • an epic page's in the epic's review inbox (ids cm1, cm2 ...)
  • Marks one he's thinking about: the thread shows "Claude: thinking…" until his answer replaces it.
    • docs pages: epic comments working <page>#cmN on
    • epic pages: epic inbox working <name>#cmN on
  • Answers on the thread:
    • docs pages: epic comments answer <page>#cmN --file <answer.html>
    • epic pages: epic inbox done <name>#cmN --file <answer.html>
  • Or, at the landing, epic comments gather puts each docs page's comments into the standing epic feedback, one phase per page (epic epic-engine T9; guide-changes before).
  • A docs page an epic owns is left out of that (epic epic-workflow P13): its comments go to that epic, with the page header's Send, and its session answers them, as an epic page's.
  • Comments replace P3's page notes (J31). Notes already written still show, read only, and epic notes still answers them.
  • Every docs page has a sticky toolbar under its title, edge to edge, with a rule below and none above.
    • a guide's: a button per top-level section, titles shrinking to fit
    • an epic page's: a round icon per section, with a red or orange badge counting what waits on Owen; on its right, the state chips, collapse-all and the new-item button
  • The epic page's header: only its /epic <name> row sticks; the title under it scrolls away.
  • At its right: Send and Review Now (grey when there's nothing to send), Bedtime when set, the step pill, git.
    • the step pill carries the epic's state: its icon and colour, and why in its tooltip
    • the orange "nobody is reviewing" pill (or the airplane one) sits under the review line, and scrolls away
  • An item folds once Owen picks its action, animated (300ms, as sections do); none under reduced motion.
  • No more jumping: a fold, a click on a line or a link's landing never moves the page.
  • Narrow (VS Code's side bar), the site header shows the breadcrumb instead of its tabs, and the page starts right under it.
  • VS Code's keys work from inside a page in the Review and Spell Docs tabs: ⌘ ⇧ P, ⌘ P, ⌘ B, ⌘ W, F1 ...
    • the page's own keys stay its own: ⌘ A / C / X / V / Z / F, ⌘ K, ⌘ I
  • Right-click shows VS Code's menu: Cut / Copy / Paste / Select All, Back / Forward / Reload, Open in Browser, Inspect.
  • Inspect and Show Console, in each tab's title bar, open the developer tools; a second click closes them.
  • The catch: VS Code can't open them on a given tab, so the tooltips say which to pick.
  • A judgement call or issue Claude records is yellow (calm) unless it would surprise Owen or go against what he said: then red.
  • So the red badges in the toolbar are only what needs him.
  • epic calm <name>#<id>... calms items already written; --loud makes them urgent again.
  • Queue only, no Claude mid-flight (Q6): plane wifi is too flaky to run a session on. Everything waits for the landing.
  • Comments wait on this laptop, as marks do (J33). Q2 first put notes inside the page. P11's comments replaced them, kept in a git-ignored file until the landing gathers them.
  • The landing takes every mark, sent or not (Q3): nobody was there to send them to. Drafts are asked about, since Owen never submitted them.
  • The landing works in the background, then hands over to a review (Q4): like /bedtime, so a 30-60 mark backlog isn't hours of one-at-a-time talk.
  • The page server swaps the internet highlighter for the local one (J1).
    • The shared pages keep the internet one until this branch is on main, so main's pages never lose their code colours.
    • /airplane rewrites them after.
  • Old marks get taken too (J9): an inbox can't tell a mark made on the plane from one left earlier. /airplane's waiting line lists them before the flight.
  • Comments are threads, answered on the page (J56): the whole talk in one place, under the paragraph it's about. Owen answers with the same pills as an epic page's item.
  • Judgement calls are calm by default: a red badge should mean Owen is needed, not that Claude decided something he'd have decided the same way.
