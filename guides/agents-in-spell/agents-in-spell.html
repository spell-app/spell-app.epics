Agents in Spell: the discussion docs

Where the agents-in-spell discussion docs land, in one place: the short answer to each kickoff goal, the recommended stack as one picture, where the docs disagree, and which questions to answer first.

Epic page: epic agents-in-spell Written for: Owen, reviewing the discussion docs before any plan Status: draft (discussion) Researched on: branch agents-in-spell, 2026-11-20. Drawn from the docs below; their facts cross-checked against each other, and the code they name opened to check it's there (see Sources).
  • Spell already has its first agent flow: Change This (⌘K) in the editor.
    • Select a part, say what should change, and Claude Code on this Mac changes the code.
    • It's the same shape as Claude Design, v0, Lovable, Bolt and Cursor: select, say, see it change.
  • The docs agree on one plan: keep that flow, grow it, and put standard plumbing under it.
    • the editor watches the agent work through AG-UI events
    • the agent changes the project only through the editor's MCP tools, into the person's draft
    • ONE agent client in the kit, src/agents/, behind which any model or agent plugs in
  • Behind that client, three kinds of thing can do the work:
    • a hosted model: the Claude API first, then OpenRouter for every other model
    • a local model: Ollama or LM Studio, found by the editor's own local server
    • an agent the person already has: Claude Code, Codex, Gemini CLI ... through ACP
  • Cost is not the problem it was.
    • A small edit is about 0.3 cents on Haiku 5.5, 1.4 cents on MAI Code 2, 11 cents on Opus 5.5.
    • A free-tier person making 30 edits a day costs Spell about $1.30-2.60 a month on a cheap model.
    • These are estimates from guessed token counts, not measurements.
  • MAI Code 2, Microsoft's cheap coding model, is $0.50 in, $2.50 out until 2027-05-17, then double.
    • It runs only inside GitHub Copilot today: no API yet.
  • The biggest unknown is Spell itself: no model has ever seen it.
    • How often a model's first Spell parses has never been measured.
  • Build the editor's MCP tools and src/agents/ first: every goal below stands on them.
  • Run one experiment before any price or local-model promise: real edits on 3-4 models, logged.
  • Then add models and agents one piece at a time: Claude, OpenRouter, Ollama, ACP agents.
  • The word in code and in what people read is agent ().
  • ONE agent client, in the kit's new src/agents/ ().
  • Change This keeps its flow; its plumbing becomes AG-UI and MCP ().

Owen's kickoff goals, one at a time: the short answer, and where the long one is.

  • Built: Change This is exactly this flow, today, on this Mac (flows, section 2).
  • What it lacks next to Claude Design and v0:
    • a follow-up: each request starts afresh
    • more than one part, and a queue of requests
    • one undo step per request: today it's one per changed file
  • The new plumbing gives the conversation for free: a follow-up is the same run's next message.
  • Claude Design's sliders aren't needed: the Inspector already edits a part's real properties, live, with no agent call.
  • Questions: (where a change lands), (where the conversation lives), (sliders), (a queue), (the agent looks at its work).
  • No agent flow yet, but the pieces exist: New App, a site's new page, about 40 examples to start from (flows, section 3).
  • A "component" in a person's project is a Spell view; a Spell UI element is ours, not theirs.
  • The agent writes Spell only, never TypeScript: it's what people read and the Inspector edits (editor-surface, section 4).
  • The best tier is for creating: a small new app is about 2 cents to $1.40, by model.
  • Questions: (a short plan first?), (what it may write), (how a model learns Spell).
  • The same box, opened with nothing selected, asks about the whole project (flows, section 4).
  • A project's requests read as one conversation, each with its own undo.
  • The agent acts as a designer of the project: it writes the draft, never publishes.
  • A change to data (a place, a server) should say what it will touch before it starts.
  • Questions: , (where the tools run), (how fine the edit tools are).
  • Every provider speaks one of two shapes, OpenAI's or Anthropic's, so the client needs no provider SDKs (standards, layer 1).
  • Start with the Claude API, then OpenRouter: about 480 models behind one key.
  • Microsoft's model is MAI Code 2 (models, section 2):
    • $0.50 in, $2.50 out until 2027-05-17, then $1 / $5
    • about 20 times cheaper than Opus 5.5 per task, by Microsoft's own run
    • GitHub Copilot only today; added when it reaches OpenRouter or Foundry
  • Pick models by tier, never by name: an edit is fast, a new app best. The tiers already exist in the parser.
  • How Claude hands work to cheaper agents, and the todos to evaluate Codex, Gemini, Copilot with MAI, Cursor and open-weight agents: delegation.html (being written).
  • Questions: (provider first), (how a task picks its model), (measure first), (hosted Chinese open models).
  • Qwen earned its name: Qwen3.8 27B is the pick, about 18 GB, so a 32 GB Mac (local models, section 3).
  • The gap is real: on an independent board, the best open model scores 41.8% against Opus 5.5's 64.8%; a laptop model is a step below that, and far slower.
  • Good for small, checked edits; not yet for "make me an app".
  • Electron isn't needed to start: the editor's own local server can reach Ollama or LM Studio today. Electron later buys one-click install, model downloads and Apple's on-device model.
  • The phone is best as a remote: ask, watch, review and approve an agent running elsewhere.
  • Spell's checker makes a hybrid work: try the local model, check in milliseconds, step up to a hosted one when it fails.
  • Questions: to .
  • Recommended: OpenRouter sign-in (the person pays, no key pasted), plus a small free tier Spell pays for, on a cheap model (who pays, section 3).
  • Cost controls: caching, small context, the cheapest tier, metering, daily limits.
  • Anthropic forbids spending a person's Claude Pro or Max plan from another app.
  • Not possible yet: spell.app runs on the house network only, and needs its production build and public sign-in first (a todo of epic atmosphere).
  • Questions: (what to offer first), (where a key lives), (Sign in with ChatGPT).
  • It costs Spell nothing: the person's own plan pays.
  • Two directions, both resting on the same MCP tools (who pays, section 4):
    • their agent drives Spell: Spell offers an MCP server, Claude Code or Codex connects to it
    • Spell runs their agent: through ACP, as Zed does, with the chat in Spell's own window
  • Today's Change This is already a hand-made "Spell runs their agent", for Claude Code alone.
  • Allowed: a person's own, unmodified Claude Code, signed in by them. Not allowed: Spell signing anyone in to Claude.ai.
  • Questions: , , , . How they fit together: section 5.
  • One standard per layer, each now with a neutral home or a 1.0 (standards, section 2):
    • MCP: the agent reaches tools (Agentic AI Foundation)
    • AG-UI: the page watches the agent work (1.0 on 2026-09-30)
    • ACP: the editor hosts an agent the person has (49 agents)
    • A2UI and MCP Apps: an agent shows UI; later
    • Agent Skills, AGENTS.md, llms.txt: teaching an agent about Spell
  • create-ag-ui-app is a thin wizard that hands off to React; its plain TypeScript example is the useful part.
  • No chat kit fits Spell UI and Solid 2: take a headless client, draw the chat with <ui-*>.
  • What Spell still writes itself: the tools, the chat views, and an ACP-to-AG-UI bridge (none found).
  • Questions: (which kit runs the loop), (cards in the chat).

The recommended stack, top to bottom. The accent boxes are Spell's to write; the dashed one comes later.

  • The editor can't tell who did the work: a local model's events look the same as a hosted one's, and a label says which.
  • Tools only the open page can run (the selection, the running app, a picture) go from the page server to the open editor over its live channel ().
  • No tool writes a whole file, and none publishes: Publish stays the person's own click.

Each doc was written on its own. Read side by side, these are the seams.

  • Who pays () recommends their agent driving Spell through a local MCP server first, and ACP later: "more to build, desktop only".
  • Standards () recommends ACP as THE way for outside agents, and () the MCP server local first, online later.
  • They fit once Q3 is counted in:

    • so ACP (or the Claude Agent SDK) is needed anyway, not later

  • Suggested: answer Q26, Q29 and Q32 together: the local MCP server first, ACP right behind it.
  • Who pays also settles standards' guess on Q29's option B: the Agent SDK can't spend a person's Claude plan; only their own unmodified Claude Code can.
  • Editor-surface's question 3 and local models' question 4 ask the same thing; Owen merged them into .
  • Their recommendations differ in shape:
    • editor-surface: a short pack of a few thousand words, then look-up tools, lint correcting it

  • Both say the same thing is missing: a measure of how often a first try parses. It fits in 's experiment.

  • Checked and matching across docs: MAI Code 2's prices and dates, the cost of a small edit, the free tier's $1.30-2.60 a month, OpenRouter's 5.5%, the 49 ACP agents, AG-UI 1.0's date.
