Who pays, and bringing your own agent

The ways a person's agent in Spell can be paid for, what each provider's terms allow in November 2026, and how someone's own Claude Code or Codex could drive Spell instead: so we can choose what spell.app offers.

Written for: Owen, reviewing epic agents-in-spell before planning; whoever builds spell.app's agent route Status: draft (discussion) Researched on: branch agents-in-spell, 2026-11-20. Terms read on the providers' own pages where they'd load; browser access checked by sending each API a browser's preflight request (see Sources). Model prices: models.html.
  • There are five ways to pay; they aren't exclusive, and most apps offer two or three:
    • Spell pays: a free tier on a cheap model, then credits or a plan
    • the person's own API key
    • the person signs in to OpenRouter, and pays OpenRouter: no key to paste
    • the person's existing subscription: only ChatGPT allows it, in a preview
    • a model on their own machine (local-models.html)
  • Anthropic forbids apps from offering Claude.ai sign-in, or spending a person's Pro / Max plan on their behalf.
    • But it DOES allow a person's own, unmodified Claude Code, signed in to their own plan, to run inside another product.
    • That's exactly what the editor's Change This does today, on this machine.
  • OpenAI's "Sign in with ChatGPT" lets an app spend a Plus or Pro plan, but only through a preview: open source and personal projects, else an interest form.
  • Bringing your own AGENT costs Spell nothing: the person's Claude Code, Codex, Gemini CLI or Cursor talks to Spell through an MCP server Spell offers, on their own plan.
    • Locally, this is small to build; remotely, on spell.app, it needs sign-in for the agent too.
  • A free tier is cheap if it's on a cheap model: 30 small edits a day is about $2.60 a month on Haiku 5.5, $1.30 on MAI Code 2 Flash (estimates; see models.html).
  • spell.app can't take any of this yet: it runs on the house network only, and needs its production build and public sign-in first (a todo of epic atmosphere).
  • On the desktop: bring your own agent first (Claude Code and the rest, through MCP), then your own key.
  • On spell.app: OpenRouter sign-in, plus a small free tier on a cheap model that Spell pays for.
  • Never ask for a Claude.ai sign-in; add Sign in with ChatGPT when OpenAI opens it.

What an agent route on spell.app would stand on, as the code is on this branch.

  • The cloud: a small web server of its own (SpellCloud), behind a proxy that gives it spell.app and spell.space.
    • It serves sign-in, people's data folders, the built-in programs and orgs' home pages.
    • Today it runs on the house network only, from Owen's Mac.
  • Sign-in: email and password, an emailed link, or an atmosphere (Bluesky) account; SignInCheck says who's asking on every request.
  • The editor at test.spell.app is the main checkout's dev server, with no sign-in: house network only.
  • Before anything public: the production build and sign-in in front of the editor (a todo on epic atmosphere).
  • A model proxy would be one more route on the cloud (its router, errors as HttpError), not a new server: whoever SignInCheck names is who's billed.
  • Keys on a machine already have a home: SRV.Secrets, the environment first, then ~/.spell/secrets/, readable only by its owner, and scrubbed out of anything Spell prints.
    • Today's Claude runner reads only ANTHROPIC_API_KEY from the environment.
  • The editor's agent today: Change This and Explain This start the person's own claude on this machine (ClaudeStarter), headless, allowed to edit only the project's files. That's already a bring-your-own-agent, local only. As decided (), its flow stays and its plumbing becomes AG-UI and MCP.

  • A free tier: a few small edits a day on a cheap model (Haiku 5.5, GPT-6 Luna, MAI Code 2 Flash when it has an API).
    • 30 edits a day: about $2.60 a month on Haiku 5.5; 10 a day, under $1.
    • One new app on a workhorse model is $0.50-1.40: a free tier allows a few a month, at most.
  • Credits: the person buys $5 or $10; Spell charges the token price plus a margin, as Copilot's AI credits do (1 credit = 1 cent).
  • A plan: a monthly price with an allowance, as Cursor, Copilot and Lovable do: the most familiar, and the most risk (heavy users).
  • All three need billing (Stripe or the like), metering, and limits: see Cost controls.
  • One Claude-specific limit: if Spell ever HOSTS Claude Code (in a sandbox, say), Anthropic forbids paying for it on people's behalf; each person signs in with their own key or plan. Spell's own API calls are fine.
  • Where it's kept:
    • desktop (Electron or the page server): SRV.Secrets, or the system keychain
    • spell.app: either in the browser, sent straight to the provider, or kept encrypted by spell.app and used from its server. The first means spell.app never sees it; the second means spell.app holds many people's keys.
  • Calling a provider straight from the browser: every API tried on 2026-11-20 answered a browser's preflight from spell.app, except Gemini's.
    • Anthropic needs the header anthropic-dangerous-direct-browser-access: true; "dangerous" because a key in a page can be read by any script on it.
    • OpenAI, OpenRouter, xAI, Mistral and DeepSeek allowed any origin.
    • Gemini refused that preflight; it wasn't retried with Gemini's own headers.
    • This is a preflight check only: a real call with a key wasn't made.
  • Who it suits: developers, and companies with their own Azure / AWS / Google account. Not novices: "go make an API key" loses most of them.
  • The person clicks "Connect OpenRouter", signs in there, and is sent back; Spell gets a key that's THEIRS, billed to their credits (OAuth with PKCE, no client secret).
  • The sign-in page can suggest a spending limit and an expiry; the person can change both.
  • Works from a browser, a desktop app (a localhost callback, any port) and headless (the person copies a code back).
  • OpenRouter says to keep the key encrypted on a server or in the system keychain, NEVER in browser storage.
  • What it costs the person: the model's price, plus 5.5% when they buy credits.
  • It gives them every model in models.html, behind the same key.

Here the person's own coding agent does the thinking, on their own plan, and Spell only offers its editor to it. Two directions; the protocols themselves are in standards.html.

Their agent drives Spell (MCP)
  • Spell offers an MCP server; Claude Code, Codex, Gemini CLI or Cursor connect to it.
  • The agent asks Spell for the thing selected, the project's files, a preview; and asks it to change them.
  • Spell pays nothing; the person's plan pays.
  • Local: one command to add it (claude mcp add spell ...), talking to the page server.
  • Remote, on spell.app: an HTTP MCP server, with sign-in (MCP's OAuth) so the agent acts as that person.
Spell runs their agent (ACP)
  • Spell starts their agent and talks to it through the Agent Client Protocol, as Zed does: the editor is the client.
  • The person stays in Spell: the chat, the changes, the approvals are Spell's own.
  • Claude Code there must be Anthropic's, unmodified, signed in by the person: allowed, as above.
  • Desktop only: the agent is a program on their machine.
  • Today's Change This is a hand-made version of this, for Claude Code alone.
  • Both need the same thing from Spell: a set of tools an agent can call (editor-surface.html). Built once, they serve Spell's own agent too.
  • On a phone, only the first works, remotely: the agent runs on their computer or in the cloud, and the phone shows the result.

What keeps Spell's bill small when Spell pays; most of it lowers the person's bill too.

  • Prompt caching: a cache hit costs 2-10% of input on the frontier models.
    • Keep what's the same every time first: instructions, then the tool list, then the project's outline.
    • Put what changes (the request, the selection) last.
    • Don't switch models mid-conversation: a switch throws the cache away.
  • Small context: send what the agent needs, not whole files.
    • the selected element, its source lines and where it sits in the page
    • an outline of the project (names, not bodies), and tools to read more when it needs to
    • a picture only when asked about looks
  • The cheapest tier that does the job: fast for edits, best only for new things (models.html, Routing).
  • Metering: every reply says how many tokens it used; record them per person, per day, beside who SignInCheck says asked.
  • Limits: a daily allowance per person, a cap on steps per request, a cap on output tokens, and a total for the whole site that stops the free tier, not the bill.
  • Abuse: free model access draws people who'd use it as a free chatbot.
    • free tier only for signed-in people, with a confirmed email
    • only Spell's own tools and prompts: no free-form chat through Spell's key
    • rate limits per person and per address; the abuse contact the sign-in bar already shows
  • A gateway (Cloudflare's, OpenRouter's) can do the caching, limits and logs, if we'd rather not build them.
  • Keys:
    • on a machine: SRV.Secrets or the keychain, never in a project or repo
    • in the browser: readable by any script on the page, so only on pages with no third-party scripts
    • on spell.app's server: encrypted, used only for that person's requests, never logged (Secrets' scrubbing)
  • What leaves the machine, way by way:
    • hosted model: the request, the selected thing and whatever the agent reads, to the provider (and the gateway)
    • bring your own agent: to their agent's provider, under their own terms with it
    • local model: nothing
  • Say it plainly in the editor: which model, which company, before the first request.
  • What an agent may do: as Change This does now, only the project's files; everything else asks the person. A remote MCP server signs the agent in as that person, with that person's access, no more.
  • Untrusted text: a page or data an agent reads can carry instructions; the tools it can call are the real limit, not the prompt.
  • Providers' data terms (training, retention) differ, and weren't read for this page: a question for planning.
  1. What does spell.app offer first? A. OpenRouter sign-in + a small free tier recommended No keys pasted, every model; Spell's cost capped by the free tier. B. Own API key only No cost to Spell, nothing to bill; loses novices. C. A paid plan from the start The most familiar; needs billing, metering and support first.

    Why it matters: it decides whether spell.app needs billing before it needs anything else.

  2. Where does a person's own key live on spell.app? A. Only in their browser, calls go straight to the provider recommended spell.app never holds it; but Gemini needs checking, and page scripts can read it. B. Kept by spell.app, encrypted Works on every device they sign in on; spell.app holds keys worth stealing.

    Why it matters: holding many people's keys makes spell.app a target.

  3. Bring your own agent: which direction first? A. A local MCP server for their agent recommended Smallest step; every agent speaks MCP; the same tools then serve Spell's own agent. B. Spell runs their agent through ACP The person stays in Spell's own window; more to build, desktop only. C. Remote MCP on spell.app Works from anywhere, phones too; needs public sign-in first.

    Why it matters: it's the cheapest way to give people a strong agent, at no cost to Spell.

  4. Apply for OpenAI's Sign in with ChatGPT preview now? A. Yes, the interest form now recommended Costs a form; ChatGPT plans are the largest pool of paid AI users. B. Wait until it's open to all Nothing to do now; the terms may still change.

    Why it matters: it's the only "use what you already pay for" a hosted app can offer.
