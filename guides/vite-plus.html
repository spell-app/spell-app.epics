Vite+

yarn ts takes 3.1s, down from 6.0s, and five tool dependencies are now one. The repo's build, test, lint and format run on Vite+ 1.0, and its cache is the one thing here you mustn't trust.

Written for: anyone touching configs, scripts or tool versions Status: merged into main 2026-10-04 Checked 2026-10-02: every package's checks run before and after, on the same machine (see Measured)
  • vite-plus 1.0.0 (command vp, MIT) replaces five tools in every package.json: vite, vitest, oxlint, oxfmt and tsgolint. Their versions now move together.
  • The engines underneath are the same, so dev, build and one package's tests are no faster.
  • The gain is vp run. Root scripts run the packages in parallel, and carry on past a failing one.
    • yarn ts: 6.0s to 3.1s.
    • Every package's tests: about 15% faster.
  • The cost: its pins trail the standalone tools by a week or two (vitest 5.0.1, oxlint 1.85, oxfmt 0.70). That rewrapped 4 files, and added no lint warnings.
  • It needs Node 24.11+.
  • vp run --cache replayed "TSC PASSED" for a package with a type error. Its file tracking can't see TS 7's native tsc, so a cached task needs explicit inputs (Limits).
  • Every version is in one yarn catalog:, in .yarnrc.yml, and packages say "catalog:":
    • vite is npm:@voidzero-dev/vite-plus-core@1.0.0 (Vite 8.3.1 repackaged)
    • vitest and @vitest/* are 5.0.1
    • vite-plus is 1.0.0
  • Bump them all together, to what vp toolchain lists; never one tool on its own.
  • One exception: spell-app/vscode is its own yarn project, and stays on plain vite.

  • They live in ONE module, vite.lint.ts at the repo root: lintBase, reactLint, packageLint(), rootLint(), fmtConfig.
    • It replaced three files: .oxlintrc.json, .oxlintrc.react.json and .oxfmtrc.json.
  • Every vite.config.ts spreads them into its lint / fmt blocks, and vp lint / vp fmt read the nearest one.
  • The catch: the editor (oxc.disableNestedConfig) and vp check read only the ROOT block.
    • So rootLint() carries React's rules as overrides for app, cli, core, lsp, parser, spell and util.

  • In a package or at the root: yarn vp lint, yarn vp fmt [--check], yarn vp test, yarn vp check.
    • yarn oxfmt and yarn oxlint no longer work in a package; yarn vitest does.
  • Tests import from vite-plus/test (/browser, /browser-playwright), and configs from vite-plus.
    • The lint rule vite-plus/prefer-vite-plus-imports holds them to it.
  • The root's ts, test:packages and review run vp run --fail-if-no-match -F '@spell-app/*' <task>, 4 packages at a time.
    • review runs one at a time (--concurrency-limit 1).
  • vp run -r includes the root package, so its all-in-one test runs too.
  • A filter that matches nothing exits 0: hence --fail-if-no-match.
  • Flags go BEFORE the task name; after it, they're handed to the task.

In a worktree on an M-series Mac, with Node 24. "Before" is the same checks, run first on main's tools.

  • Vite+'s pinned versions across the board, not the newer standalone ones: one set to bump, and nothing to drift.
  • Node 24 LTS, not the minimum 22.18: one bump covers the next pins too.
  • The settings are folded into vite.config.ts, through ONE module, by hand.
    • vp migrate left each package's lint.extends pointing at deleted files, and dropped every comment saying why a rule is set.
  • No options.typeCheck: yarn ts already runs tsc, and a second type check reports every error twice.
  • The imports were rewritten to vite-plus/test in their own commit: 380 lines, nothing else.
  • Root scripts are on vp run, because it runs packages in parallel, and runs every package instead of stopping at the first failure.
  • No git hooks, no cached tasks and no root check script yet (see Limits).
  • No caching. Input auto-tracking misses TS 7's native tsc, so vp run --cache replays a stale pass.
    • To cache a task: a run.tasks entry with explicit cache.input globs.
    • They must include the packages its type check reads through $/ aliases.
  • vp check fails today, on 63 files already unformatted on main (56 of them in docs).
  • The Oxc editor extension must read fmt from the root vite.config.ts. If saving a file adds semicolons, it isn't.
  • Fixed: a fresh install's first app browser test run used to fail on a cold vite deps cache, on main too.
    • The tests import spellRuntime.ts by URL, so it's now listed in Vite's dependency entries (optimizeDeps.entries, vitest.config.ts).
  • cli's process-spawning tests can time out at 5s when everything runs at once; they pass alone.
  • Vite+ also manages Node and the package manager. We don't use that: we keep corepack yarn 4.18.
