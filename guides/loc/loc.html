Every file git tracks in each repo, sorted into code and docs by its extension.

column what it counts
code files files with a code extension
code lines lines of actual code: the lines left after taking out comments, blank ones not counted
code chars the characters on those lines, without their indentation
all lines every line of the code files: comments and blank lines too
all chars every character of the code files
doc files files with a docs extension
doc lines every line of the doc files, added up
doc chars every character of the doc files
  • Code: .ts .tsx .js .mjs .cjs .css .py .spell
  • Docs: .md .html
  • Anything else (JSON, SVG, images ...) isn't counted.
  • Tracked files only (git ls-files): nothing git ignores, so no node_modules, no built bundles, and none of the content repo (spell.epics).
  • Tests: everything under a repo's tests/.
  • Python: lines starting #.
  • Everything else: /* ... */ blocks, and // to the end of a line (not in CSS).
  • It's a quick pass, not a parser: a // or /* inside a string counts as a comment too.
  • So "code lines" is close, not exact.

Files a person didn't write, so they'd only make the numbers bigger:

  • generated files: marked linguist-generated in a repo's .gitattributes
  • component packs (__pack/), vendored code (vendor/), .yarn/, minified files, the app's static/
  • test snapshots (.snap, __snapshots__/)
  • a file saying GENERATED in its first 800 characters, or with lines over 400 characters long on average (bundles)
  • The GENERATED test also catches files that only TALK about generated files, e.g. StyleGenerator.ts, FoundationTokens.ts, ReportTables.ts, colors.contrast.test.ts.
  • About 1.5k lines of real code, mostly spell-ui's, are missing for it.

Run the scan over the kit's folder, then copy its numbers into this page by hand.

Re-run the scan · 4 lines 
cd ~/www/spell/spell.epics/guides/loc/experiments
node scan.mjs ~/www/spell          # the table, tab-separated, then the files left out
node scan.mjs ~/www/spell --json   # the exact numbers, for the tooltips
# then update sections 1 and 2, the lead's date and the footer
  • It needs nothing installed: plain node and git.
  • Each child repo is scanned at whatever branch it has checked out.
  • Short numbers: 1.2k is 1,200, 1.4M is 1,400,000.
