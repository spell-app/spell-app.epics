Every file git tracks in each repo, sorted into code and docs by its extension, as the settings file guides/loc/loc.json5 says.

  • It sits beside this page, in the content folder: one for the project, every repo in it.
  • Per repo, by its folder name, or "*" for all: which folders are rows (rows, globs: src/*, docs), which files are tests, the code and doc extensions, and what to leave out.
  • A repo's own key replaces "*"'s, but leaveOut, which adds to it.
  • Missing, epic loc writes it with the defaults, and says so: tweak it, then run it again.
column what it counts
code files files with a code extension
code lines lines of actual code: the lines left after taking out comments, blank ones not counted
code chars the characters on those lines, without their indentation
all lines every line of the code files: comments and blank lines too
all chars every character of the code files
doc files files with a docs extension
doc lines every line of the doc files, added up
doc chars every character of the doc files
  • Code: .ts .tsx .js .mjs .cjs .css .py .spell
  • Docs: .md .html
  • Anything else (JSON, SVG, images ...) isn't counted.
  • Tracked files only (git ls-files): nothing git ignores, so no node_modules, no built bundles, and none of the content repo (spell.epics).
  • Tests: everything under a repo's tests/, and files named *.test.* or *.spec.*.
  • Python: lines starting #.
  • Everything else: /* ... */ blocks, and // to the end of a line (not in CSS).
  • It's a quick pass, not a parser: a // or /* inside a string counts as a comment too.
  • So "code lines" is close, not exact.

Files a person didn't write, so they'd only make the numbers bigger:

  • generated files: marked linguist-generated in a repo's .gitattributes, or saying GENERATED on their first line
  • component packs (__pack/), vendored code (vendor/), .yarn/, minified files, the app's static/
  • test snapshots (.snap, __snapshots__/), and files named *.generated.*
  • bundles: lines over 400 characters long on average
  • and what the settings file's leaveOut names: spell-ui's src/jsx.ts and spell-parser's two_sided_view.py, generated with their marker a few lines down
  • The first scan left out any file saying GENERATED in its first 800 characters, which also caught files that only talk about generated files, e.g. StyleGenerator.ts.
  • epic loc looks at the first line only, so those count now; a generated file with its marker further down goes in the settings file's leaveOut.

Run epic loc from any folder of the checkout: it rescans every repo and rewrites this page's tables, its dates and the files left out, keeping the rest as written.

Rescan · 3 lines 
epic loc            # rescan, rewrite this page, print its links and the totals
epic loc --print    # the by-repo table, in the terminal;  the page is left as it is
epic loc --json     # the exact numbers, every column
  • It works in any project: the repo it runs in, and, in a project of several repos, every child repo cloned in it.
  • epic loc replaced the first one-off scan, experiments/scan.mjs, which is kept beside this page.
  • Each child repo is scanned at whatever branch it has checked out.
  • Short numbers: 1.2k is 1,200, 1.4M is 1,400,000.
