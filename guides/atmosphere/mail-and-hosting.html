Mail, Domains And Hosting

One company for every domain, one for every mailbox, one for Spell's own mail, and one machine for a public spell.app. Each section is a sitting of its own, in this order.

The registrar and the place you add records aren't always the same company. Looked up today:

  • spell.space: Spell's domain for handles (ana.rs.spell.space) and lexicons, registered at Squarespace on 2026-10-31, its records at Squarespace (section 2). It was missing from this page.
  • spell.app: still on Google Domains' name servers, carried over when Squarespace bought Google Domains; its records are edited at Squarespace too (section 2).
  • spell.social: on Cloudflare's name servers, so its records go in Cloudflare's dashboard (dash.cloudflare.com › spell.social › DNS › Records › Add record), not Squarespace's; or first point it back at Squarespace's name servers (Squarespace: the domain › DNS › Domain nameservers).

Check any domain yourself in Terminal:

dig NS spell.space +short

Every record on this page goes in the same way, once per domain:

  1. Open account.squarespace.com/domains and click the domain.
  2. In the side panel: DNS, then DNS Settings.
  3. Scroll to Custom Records › Add record. Pick the type, then fill in:
    • Name: only the part before the domain; @ means the domain itself
    • the value (for MX it's called Mail Server), and for MX the Priority
    Then Save. It may ask for your password first.
  4. Before the first one, look at what's there:
    • delete any MX record, and any Google Workspace or other email preset, with the trash can (presets can't be edited, only deleted)
    • leave the "Squarespace Defaults" records alone: they're the website, not mail
  5. No quotation marks around a TXT value: extra ones break the SPF record.
  6. Changes usually show in minutes; Squarespace says up to 48 hours.

The SPF record needs nothing for Postmark: its bounces come from pm-bounces.<domain>, which carries its own. A domain you keep for your own mail (from IONOS) needs only the Fastmail rows and DMARC.

spell.space only receives, for its abuse address (abuse@spell.space), so it needs the Fastmail rows, its SPF and DMARC, and nothing of Postmark's. Its records go in at Squarespace, like spell.app's.

The order matters: the new mailboxes work BEFORE any domain leaves IONOS, so no mail is lost.

  1. Sign up at fastmail.com, with a plan that allows your own domains.
  2. At IONOS, write down every address, alias and forward you use: Fastmail makes each again by hand.
  3. Add each domain at Fastmail: Settings › Domains › Add domain › "I'll set up DNS myself". It shows the records of section 2 with its own signature values.
  4. Put them in at Squarespace by hand, or let Squarespace do it: the domain › DNS › Add preset (top right) › Fastmail › Continue › Add. For a domain still at IONOS, change its records in the IONOS panel the same way (Domains & SSL › the domain › DNS).
  5. Back at Fastmail: Settings › Domains › Recheck DNS, until each is green.
  6. Bring the old mail over: Settings › Migration › Import › Other (IMAP), server imap.ionos.com, port 993, your IONOS address and password. It copies every folder, and can keep fetching new mail until you stop it.
  7. Make the addresses: owen@spell.app, owen@spell.social, an abuse@spell.app alias to yours, an abuse@spell.space alias to yours (add spell.space as a domain first, as in step 3), and every alias from step 2 (Settings › Aliases).
  8. Point your phone and mail app at Fastmail; send yourself a test from another account.

Before Postmark: on a machine whose own mail already works, such as a Mac whose postfix relays to a mail service, Spell can send through that. Start the server with SPELL_MAIL=sendmail and SPELL_MAIL_FROM=sign-in@spell.app. Each mail goes to the machine's sendmail, and is still kept where spell space cloud mail shows it. With neither set, nothing leaves the machine.

Spell's server, run from the repo on a rented machine, in place of a machine of yours.

  1. Sign up at railway.com; the Hobby plan is $5 a month, with $5 of use included.
  2. New Project › Deploy from GitHub repo › the Spell repo. Claude writes the start command and settings it needs, in the Real Sign-In Mail phase or after it.
  3. Add a volume, mounted where Spell's server keeps its data: the spaces, the backups and the save queue live there, and a deploy must never wipe them. Hobby volumes start at 5 GB.
  4. Settings › Networking › Custom Domain › www.spell.app. Railway shows a CNAME (and maybe a check record): add them at Squarespace (section 2). Railway makes the https certificate itself.
  5. The bare spell.app can't take a CNAME at Squarespace: forward it to www.spell.app (Squarespace's domain forwarding), unless Railway's page offers an answer of its own.
  6. The Postmark key goes in Railway's Variables, never in the repo.
  7. People's handles (the epic's Handles Under Spell phase): ana.rs.spell.space must reach Spell's server, which answers other apps' look-up of it.
    • In Railway: Settings › Networking › Custom Domain › *.spell.space. Railway shows the records it needs, for the address and for its https certificate.
    • At Squarespace, on spell.space: add those records. The address is a CNAME, host *, value Railway's. If Squarespace won't take a * host, add one per org instead, *.rs.
    • Check it: curl https://<handle>/.well-known/atproto-did prints the account's id, once an account on Spell's Spaces host has one.
    • An org with a domain of its own (rs.org) does the same at its own registrar, *.rs.org, and its org file names that domain.

The Spaces test host (the epic's Q17, option D) could run there too, as a second service.

Spell's cloud at real-looking addresses, for the Macs in one house, with nothing public changed. The names exist only in each Mac's hosts file.

  1. Once, on the Mac that runs it, after brew install mkcert caddy: spell space local setup. It prints a folder: copy that to any other Mac and run its script.
  2. For real mail, make a Gmail app password, then run spell space local mail. Without it, mail stays on the Mac: spell space cloud mail shows it.
  3. From then on the main checkout's page server runs the site, at https://test.spell.app and https://test.spell.space. Restart that once now to start it: spell server stop, then spell server start. To watch it in a terminal instead, run spell space local stop, then spell space local start.
  4. Sign in from the page, or with spell space local sign-in.

The site keeps running when the page server restarts, which happens after every merge to main. When the cloud's own code has changed, the page server builds the new version first, while the old one keeps serving, then swaps them. That gap is a few seconds, and a page opened during it just waits. If the build fails, the old one keeps serving and ~/.spell/local-site/site.log says why. To stop the site for good until the next page server starts: spell space local stop, or spell server stop all for everything.

Signing in lasts 30 days and survives a restart, a reload, and a link from another site. It belongs to one address, though: https://test.spell.app and https://test.spell.space each need their own sign-in.

Every site's front page, /, lists the spaces the person asking may read, and an org's home is at its address, such as /@willzalone.

The Mac running it has to stay awake, and a phone can't use it: phones have no hosts file. Sign in with Bluesky doesn't work here, because Bluesky's servers can't reach a house-only address.
