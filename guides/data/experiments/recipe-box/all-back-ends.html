Sharing nothing

This device only this browser

family cookbook is this device
  1. Start the servers at the kit's root, and leave them running. They print where the CSV file and the folder are: open both in VS Code. Restart them if they're from before this version. 
    yarn tsx scripts/recipe-servers.ts
  2. Change a recipe in REST. It's in the CSV file at once, and GraphQL and the sheet show it within a second or two.
  3. Edit a row in VS Code, and save. All three show it within a second.
  4. A clash: type in the same recipe's title in REST, and in VS Code or GraphQL, within a second of each other. REST keeps yours, and a notice holds the other, with Use theirs. Change another field or another row, and both stand with no notice.
  5. Change a recipe in the folder frame, or its file in VS Code. Both room windows show it at once. Change it in the room, and it's in the file, and the folder frame shows it within a second.
  6. Clash in a room: type in one recipe's title in both windows. Each may flicker, then both show one of them, and whoever lost a long text keeps it in a notice.
  • The CSV file: a copy of recipes.csv, made the first time the servers start, in the system's temporary folder. The file beside this page never changes. On the recipe box's own page, the sheet still reads that one.
  • Versions: a CSV file has no version column, so a row's version is a hash of what it holds. Editing one row moves only that row's version, so only that row can clash.
  • How close "at the same time" is: every request reads the file first, so a save is seen at the next request. VS Code has its own say: with unsaved edits, it warns you the file changed on disk.
  • A file that doesn't read: half saved, or with a blank or repeated id. REST and GraphQL answer as they last read and refuse to save over it, and the sheet says why it can't read it.
  • The folder: the live room's referee keeps its recipes there, in the same files. A recipe added in the folder frame has no place in the room's order yet, so it shows last.
  • This device is only in this browser, with no server. It starts empty, and a reload keeps what you add.
  • One process. The servers are one program on one port, so stopping it stops the six frames that need it.
  • Not a compiled program. Each frame runs the page's <recipe-box>, on the same places a Spell program uses. The lines of Spell above are what a program says to reach that same place. The built-in example @spell/examples/RecipeBox is that program.
