Every Back-End

The same recipe box seven times, each frame keeping its recipes somewhere different. Add a recipe in one, and no other frame changes, except the live room's second window, which is the same room on purpose.

Five of these need the recipe servers. Start them at the kit's root, and leave them running:

yarn tsx scripts/recipe-servers.ts

Without them, each of those frames says it can't reach them. The sheet and this device work anyway. If they were started before 2026-10-31, restart them: GraphQL's own recipes are new.

REST

Its own recipes, in the server's memory, so a restart starts over. It says versions, so a clash merges. 

family cookbook is a web service at "http://127.0.0.1:4791":
	- a recipe's title is called "name"
	- its versions are in "version"

GraphQL

Its own recipes, in memory too. It says no versions, so the last save wins each field.

family cookbook is a graph service at "http://127.0.0.1:4791/apart/graphql":
	- a recipe's title is called "name"

A folder

One JSON file per recipe, kept between restarts. Edit a file in VS Code, and this frame follows.

family cookbook is a folder at "http://127.0.0.1:4791/api/places/recipes"

A sheet

A CSV file beside this page, with no server. It's read only, so there's nothing to type in.

family cookbook is a sheet at "recipes.csv":
	- its ids are in "id"

A live room

Its own folder, with a referee putting every change in one order. Nothing polls: changes arrive.

family cookbook is a live room at "http://127.0.0.1:4791/api/rooms/recipes"

The same live room, a second window

Press Go offline here, change something in both windows, then come back: they heal to one answer. 

family cookbook is a live room at "http://127.0.0.1:4791/api/rooms/recipes"

This device

Only in this browser, with no server. It starts empty, and a reload keeps what you add.

family cookbook is this device
  • No recipes. REST and GraphQL have a box each, the folder and the room a folder each, and the sheet and this device need no server.
  • One process. The servers are one program on one port, so stopping it stops all five frames that need it.
  • Not the demo's GraphQL. On the recipe box's own page, GraphQL shows REST's recipes, so switching back-end finds the same ones. Here it's the one with its own.
  • Not a compiled program. Each frame runs the page's <recipe-box>, on the same places a Spell program uses. The lines of Spell above are what a program says to reach that same place. The built-in example @spell/examples/RecipeBox is that program.
