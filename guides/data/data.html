Data in Spell

One line says where a program's things live. The rest of the program reads and changes them as if they were in memory: it waits, cancels, saves, heals and shares by itself.

Epic page: epic data Why it's built this way: The Data Problem: A Survey Written for: someone writing a Spell program that keeps data, or working on the code under it Status: built P1-P23; real Google Sheets, Airtable and AT Protocol accounts are still manual tests
  • Where is one line. family cookbook is a web server at "...", then it lives in family cookbook on each type kept there. Changing that one line moves the data: nothing else in the program changes.
  • Reading waits by itself. A drawing that reads shows a loader, then the things; leaving it cancels the request. <for> adds Try again, an empty message, pages and a title.
  • Changing is saving. There's no save step: each change is kept on the device, sent when its action ends, undone by undo, and healed when the server says no.
  • Several people settle. Two people on one thing see it wobble, then agree: per field, the last change wins, with a notice for the one who lost. No CRDT.
  • The server's spelling is its own business. its "hair color" is text finds hair_color, and "1,200" reads as a number.
