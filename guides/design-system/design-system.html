Design System

Spell's brand, as Claude Design drew it, rebuilt on Spell UI: where the pages are, the theme and elements they're made of, and how to add to them.

Plan doc: epic design-system Written for: anyone building a page in the brand look, or adding a brand element Status: built on branch design-system, not yet merged Checked 2026-10-05: every brand page and docs page loads clean, light and dark; yarn compare figures from P8
  • Claude Design made 13 brand pages (mockups, colour tools, logo and art pages). Each now has a copy built only from Spell UI elements, beside its original in packages/brand/spell-design-system/.
  • The Brand tab in the site header lands on the Brand index: every page with its original, its copy, and a Compare view of the two.
  • A new theme, spell-brand, carries the brand's look and its own tokens (the "brand roles"). The copies, and now every docs page, wear it.
  • 12 new elements: <ui-panel> (already moved into Spell UI) and 11 <ui-brand-*> families in packages/brand/components/, each with a docs page.
  • 37 gaps the pages hit were fixed in Spell UI itself: new tokens and attributes for menus, tabs, markdown, lists, buttons, cards, labels, sliders, toasts and sections.
  • The copies come within 3-11% of their originals' pixels on most pages; the furthest are explained in Compare.
  • This lives on branch design-system. Until it merges, packages/brand, the theme and the docs' brand look exist only in that worktree (the main page server serves them under /worktrees/design-system/).

Everything brand lives in one package, packages/brand (@spell-app/brand), served by the page server at /packages/brand/.

  • packages/brand/index.html: the Brand tab's home. Components first, then the 13 pages in three tables (product mockups, tools, brand), each with Original, Spell and Compare links.
  • packages/brand/spell-design-system/: Claude Design's export, untouched. Each <Name>.dc.html original has its <Name>.spell.html copy beside it.
  • The originals are Claude Design's own templates, compiled into React at load: they need the internet (React, Font Awesome) and four need the page server.
  • The copies need the page server too (their bundle is an ES module), but not the internet.
  • packages/brand/components/components.spell.html: the specimen page, Spell UI and the brand elements together in the theme.

compare.html?page=<Name> shows an original and its copy at the same layout width, so you judge them as the same page.

  • modes: side by side, overlay (with a "Copy on top" slider), original only, Spell only
  • widths: 390, 768, 1280 (default), 1600; each frame scaled to fit its pane, scrolling in step
  • the view lives in the address, so a reload or a shared link comes back to it

yarn compare [<page>...] in packages/brand does the same headless: a screenshot of each, side.png, diff.png and the share of pixels that differ, into .compare/. It hides the copy's site header. A rough guide: one taller card moves everything below it, so LOOK at side.png.

packages/ui/src/styles/themes/spell-brand.css is Spell UI's spell theme, copied, then changed wherever a copy showed it differed from its original. It's in the theme registry, so UI.themes.apply("spell-brand") and Spell UI's theme picker ("Spell Brand", second) both work.

  • The look: purple and aubergine, House of Owen grey-blue as the neutral, Polished Ivory as the accent; Palatino headings; pill buttons; soft violet shadows; an aubergine dark mode.
  • An accent hue: color="accent" tints any element while the theme is on (--ui-accent-*; the brand bundle adds the name to Spell UI's hues, packages/brand/src/hues.ts).
  • spell itself is unchanged: the Spell UI site and everything else keep it.

The brand's own semantic tokens, which no --ui-* token covers, as --spell-*, each a light / dark pair. A brand page reads these and --ui-*, never raw colours.

Group Tokens
surfaces --spell-surface-tint (lavender wash), -warm (ivory), -selected, -code, -inverse (aubergine)
text --spell-text-strong, -body, -muted, -subtle, -accent, -inverse, -on-accent
accent --spell-accent, -hover, -press, -soft, -ring
type --spell-type-display, -lede, -eyebrow, -body, -ui, -code, -spell; --spell-font-serif / -sans / -mono
borders, status --spell-border-subtle ... -accent, --spell-hairline; --spell-success, -warning, -danger and their -soft
art, depth, motion --spell-blob, --spell-line-flourish, --spell-spark; --spell-shadow-xs ... -lg, -focus; --spell-dur-*, --spell-ease-*

New elements start in packages/brand/components/ as <ui-brand-*>, written exactly like a Spell UI family; the generic ones move into Spell UI later, without the brand-. Each has a docs page in Spell UI's format (Examples, Usage, API, Theming), listed on the Brand index.

In Spell UI: <ui-panel>
  • An inspector, as the Color Set Chooser's left column: a tinted box of fields under a full-width header band; a panel inside a panel is a sub-head band in small capitals. Every band folds.
  • A <ui-section> underneath: every section attribute, slot and event, the chevron at the band's far end (fold-icon="end").
  • color: any hue, primary by default; color="accent" is the brand's ivory panel. Tokens --ui-panel-*. Works without the brand theme.
  • Moved from <ui-brand-panel> on 2026-10-05: packages/ui/src/components/ui-panel/; docs page on the Spell UI site (/ui/components/ui-panel.html).
Element What it is
<ui-brand-field> One control with its label, value readout, actions, info tip, help and error; <ui-form> validates it like a <ui-field>. Compacts its controls to the inspector's 30px.
<ui-brand-color> A square colour chip: hex, OKLCH or a name; an AA contrast mark; click to copy; a details tip.
<ui-brand-color-set> A row or grid of chips, to show or to pick one from (a radio group: arrows, Home / End).
<ui-brand-color-range> A 17-step ladder of shades from one base colour, the brand's own recipe; the anchor ringed.
<ui-brand-color-picker> An HSL square and a rainbow hue slider; HSL, RGB and OKLCH rows, each with a copy button; a form field.
<ui-brand-composer> Write a spell and cast it: a serif text box, chips, a round Cast button, Cmd / Ctrl+Enter; a form field.
<ui-brand-checklist> Round-marked lines (<ui-brand-check>): build progress driven by one step, or things to tick off (checkable).
<ui-brand-phone> A phone frame with a status bar around a live preview; dimmed while it builds.
<ui-brand-logo> The logo, outlined (no font needed): the hat mark or a lockup, in six tones. Page art.
<ui-brand-flourish> A generated swoop, blobs, curls, sparkle trail or wave behind the content: Claude Design's script, ported shape for shape. Page art.
<ui-brand-blob> One soft lavender shape in a corner: organic, mound or wave. Page art.
  • Page art (logo, flourish, blob) stays in the brand package for good; the rest are candidates for Spell UI.
  • Palette (packages/brand/src/Palette.ts): the brand's colour math in TypeScript (sRGB, OKLCH, HSL, contrast, 17-step ladders), pinned to Claude Design's lib/palette.json; pages reach it as window.Palette.

    <script type="module" src="../_assets/ui/brand-ui.js"></script>
  </body>
</html>
  • Dark mode: Spell UI's ui-dark / ui-light on <html>, never the brand's data-theme.
  • Something the theme or an element can't do: fix it at the source (a token or attribute in Spell UI, or the brand element), as P8 did, rather than ::part() rules or a HACK script on the page. Can't yet: an issue in the plan doc, and a row in Limits.
  • A new element: a family folder in packages/brand/components/ with its vocabulary, then yarn build (the bundle in _assets/ui/, committed), yarn site:data, and a docs page copied from a sibling. The rules: packages/brand/AGENTS.md.

Every docs page (durable, cheatsheet, commands, plan docs, details, goals, the changelog and the index) wears the brand, with no page edited: the docs' bundle applies spell-brand instead of spell, and the docs' CSS reads its brand roles.

  • Headings: the brand's Palatino serif, bold, in the strongest ink. One token, --spell-heading-font in spell-doc.css, puts the system face back.
  • The breadcrumb above the h1 is the page's eyebrow: small mono capitals, the links in the accent.
  • The lede under the h1: italic serif. A lede inside a section (a plan doc's summary) stays upright: five lines of italic are hard to read.
  • Asides: ivory panels. Code: framed code wells.
  • The contents: on a lavender card. Table column heads: mono eyebrows.
  • Plan docs: pill id chips, rounder boxes. Index cards: titles in heading ink, not underlined links.
  • Dark mode: aubergine.
  • Only the branch's docs CSS and bundle changed (packages/docs/tools/_assets/): the pages and templates are shared content, so main sees the look only when this branch merges.
  • The docs' own accent token is --spell-doc-accent (was --spell-accent, which clashed with the brand's).
  • The Spell UI docs site keeps its look (the spell theme).

  • yarn compare's figure is a rough guide: use it to see a page get better or worse, judge by eye.
  • The theme outlines every <img> with a hairline, logo files too: a page showing artwork as an image turns it off itself.

  • Colour range: ui-change fires when its attributes change the ladder, not on a user action; anchor="auto" puts House of Owen on step 400 (the brand pins it at 500).
  • A chip's details tip is read-only: copying is the chip's own click.
  • <ui-panel source> waits for epic claude-design's <ui-section source>.
  • Docs markup for merge time: an eyebrow on the pages without a breadcrumb (the index, cheatsheets); short ledes with the rest as an intro.
