Spell in Spanish

- "es una figura" si su rango es jota, dama o rey is a line of Spell, from a Spanish card. It compiles to a getter, get esUnaFigura(), and a test that uses it prints ✅ Como se esperaba when it passes.

Spanish is the second language Spell reads. It isn't a translation layer over English, and it isn't a fork of the parser: the same rule classes are registered twice, once with English words and once with Spanish ones, and each file's name says which set it's written in.

  • A file's name says its language: Carta.es.spell is Spanish, Card.spell (or Card.en.spell) English. One project may mix them.
  • A Spanish file parses with Spanish words, plurals and articles, and compiles to Spanish names, accents kept.
  • Every language is a LANGUAGE PACK: its rule words, its word tables, its inflector (singular and plural) and its messages. English is the first pack, Spanish the second.
  • spell translate check says whether a pack has every rule English has.
  • spell translate writes an English project again in Spanish: its names first, then each line by its own rule, then Claude fixes what fails lint, a test, or compiles to a different program.
  • A wrong article is a warning, in both languages:
    • el carta asks ¿Querías decir "la carta"?
    • a apple asks Did you mean "an apple"?
  • Spell UI's components have Spanish names on a Spanish page: <es-boton>.
  • The editor, VS Code and the parser's messages speak each file's language, and a test's run-time lines the program's; the editor's own buttons and panels speak the page's.
  • Name its files .es.spell: Carta.es.spell.
  • The example @spell/examples/Solitario, Solitaire in Spanish line for line, is a whole project to copy from.
  • The language's own page, with pictures and commands to try: README-spanish.

What Spanish needed that English didn't:

  • Articles with gender: un / una, el / la / los / las, and two contractions, del and al.
  • Spanish plurals: accents move (corazón / corazones), and some words don't change (lunes).
  • Two verbs for "is": es and está both mean "is" to the parser.
  • A dropped subject: tiene un mazo needs no "it"; su / sus stand for "its".
  • The decimal comma: 1,5 is a number, 1, 5 a list of two.
  • Accents in names: año is one word, not three tokens, everywhere a word is matched.

Names are the author's, accents and all: esUnaFigura, dirección. The runtime's own calls (core.includes) stay English, because nobody reads them.

spell compile @spell/examples/Solitario --stdout, from Carta.es.spell · 15 lines 
  /** "la carta es una figura" */
  get esUnaFigura() {
    return core.includes(["jota", "dama", "rey"], this.rango)
  }

  /** "la carta es una carta numérica" */
  get esUnaCartaNumérica() {
    return !this.esUnaFigura
  }
  ...
  get color() {
    if (core.includes(["diamantes", "corazones"], this.palo)) return "rojo"
    return "negro"
  }

Its words file, which maps each compiled name back to its Spanish words, is named for the language: Solitario.es.js for JavaScript, Solitario.py.es.json5 for Python.

A parser generator gives each language its own grammar file. Spell keeps ONE set of rule classes, the code that says what a rule compiles to, and gives each language its own words for them.

  • Each folder of rules holds the rule classes, and nothing about words.
  • Beside them, <folder>.en.ts registers every rule of the folder with its English syntax and tests, and <folder>.es.ts the same rules, in the same order, with Spanish.
  • A third language is a third file per folder.
one rule in both languages · illustrative · 9 lines 
// expressions.en.ts
expressions.addRule(IsEqual, {
  syntax: "{operator:is_or_is_not} {expression:operand}",
  tests: [["thing is other", "(thing === other)"], ["thing is not other", "(thing !== other)"]]
})
// expressions.es.ts:  the same class
expressions.addRule(IsEqual, {
  syntax: "{operator:is_or_is_not} {expression:operand}",
  tests: [["cosa es otra", "(cosa === otra)"], ["cosa no es otra", "(cosa !== otra)"]]
})

Rule code used to test the English word it matched, e.g. === "is not". Now no rule reads a word.

  • The small words are WORD RULES each language registers, about 30 of them: the articles, "is" or "is not", "it" ... some word rules, English and Spanish · illustrative · 4 lines 
    definite_article      the            el | la | los | las
indefinite_article    a | an         un | una | unos | unas
is_or_is_not          is | is not    es | está | no es | no está
it                    it             eso | ello
  • A rule reads what its word rule matched (negated or not, which article), never the word itself.
  • A guard test fails if an English word comes back into rule code.

SP.Language is one language's pack, in languages/<lang>/:

  • its parser, with every rule registered in its words
  • its inflector: English's wraps the npm pluralize; Spanish's is ported from Python-Inflector's rules, and widened
  • its word tables: the identifier blacklist, booleans, number words, ordinals, the built-in types' words
  • its article agreement, and the messages a person reads

Each file's scope picks its pack from the file's language, so its colours, completions and warnings follow. A Spanish program never loads English's inflector.

A new English rule must never leave a language behind without anyone noticing.

spell translate check es · 1 line 
Spanish (es):  complete, 19 modules
  • check compares each pack with English, module by module: a rule missing, out of order, or with no syntax or tests; and the word tables. It exits 1 on anything missing, and runs in spell-parser's tests too.
  • fix writes stubs for what's missing. With --ai, Claude drafts each one through the command line, marked for review.
  • A difference on purpose is marked in the pack's file, so the check passes: // packs: ok -- why.
  • A type's gender is read off its declaration: una carta es una cosa makes it feminine.
  • Spanish warns on gender and number: el carta, un cartas. English uses the same check for a apple and an card.
  • It's a warning in the editor, never an error: the line still compiles.

On a Spanish page, every Spell UI component has a Spanish tag, Spanish attributes and Spanish texts.

Spell UI's Spanish demo page, translate.html · 9 lines 
<html lang="es">
  <es-boton primario>Guardar</es-boton>
  <es-boton color="rojo" tamano="grande">Borrar</es-boton>
  <es-boton alternable color="verde">Votar</es-boton>

  <es-desplegable seleccion busqueda marcador="Género" name="genero">
    <es-elemento value="f">Femenino</es-elemento>
    ...
  </es-desplegable>
  • The page's language is its <ui-root lang="es">, else the document's lang. Every component then loads on demand as es-*, its texts in Spanish.
  • Tag and attribute names are ASCII: es-boton, tamano. Values keep their accents, and are found without them too: pequeno finds pequeño.
  • A Spanish tag's properties are Spanish too: desplegable.abierto.
  • The Spanish costs a page 10.3 kB gzipped, and only a Spanish page loads it.
  • From code: UI.vocabulary.defineComponents({ prefix: "es", dictionary: es }) for the names, and UI.i18n.registerDictionary(es) for the texts.
  • Each component's Spanish sits beside its English: UIButton.es.ts beside UIButton.en.ts. What many share is translated once, in components.es.ts.

In Spell, a Spanish program's JSX writes <es-*> tags as they are, and its views get tags from their Spanish names: <solitario-carta>.

  • A keyword typed without its accent gets it back as you type a space or Enter: numero becomes número.
    • Both VS Code and the editor do it.
    • It never touches a word that's right both ways (si, sí), or a name a person chose.
  • VS Code and the editor colour Spanish keywords; their keyword lists are written from the packs, English and Spanish in one grammar.
  • si no: and de lo contrario go back out a level, as otherwise does.
  • In a Spanish project, completion offers Spanish keywords (si, para, devolver), and the Type Explorer's built-in types are Spanish's.
  • An accented word is one word to double-click.
  • The editor speaks the PAGE's language: the document's lang, else the browser's. 168 of its texts have Spanish, loaded only on a Spanish page.
  • The language server's 32 labels (hover, completion, the Define fix, the Type Explorer) speak the language of the FILE they're about, in any editor: a Spanish program's hover says declarado en.
  • Each text is a key, read with appTexts.text(key, params). A sentence naming something takes it as a param, never glued from pieces, so each language words it its own way.

spell translate <project> --to es writes an English project again in Spanish, as a project of its own beside it. Solitaire comes out linted clean and passing its six tests, with no person in the loop, in under a minute.

  1. Names: every name the project chose (types, properties, values, methods, texts, comments), each noun with its gender.
    • First from the Spanish glossary, shared by every project, so one English word is one Spanish word in every program.
    • The rest by Claude: the types in one call, then the other names in up to 6 calls at once.
    • They land in the project's dictionary, <Project>.es.names.json5, for a person to review.
  2. Lines: each line read in English, then written again by the same rule in its Spanish words, articles agreeing. No model writes these.
  3. Fix-ups: the translation is linted, its tests run, and each statement compiled beside its English one (the shape check). A line that fails, couldn't be written, or compiles to a different program goes back to Claude, in context, up to 3 rounds.
  • A line it can't write keeps its English, marked // TODO: translate (why), and the command exits 1.
  • <ui-*> tags, their attributes and values become Spell UI's Spanish ones, and a style sheet's selectors with them. A project it imports keeps its own words.
  • --update re-translates only the English lines changed since the last run: hand edits to the Spanish stay.

With no Claude (--no-ai) and no glossary (--cold), every line is Spanish but its names: para number de 1 a 100.

  • Through the Claude API when ANTHROPIC_API_KEY is set, else through claude -p, which says once that a key would be faster.
  • Either way an answer can only be JSON of the shape asked for, and the glossary rides in the system prompt.
  • --effort fast|balanced|best says how much each pass spends, balanced unless asked. More thought made no better names, so today only best's fix-ups think harder.
  • Solitaire through claude -p: about 52 s from nothing at all (--cold), 31-41 s from the glossary; the todos example 10-16 s.
  • spell translate speedtest times it: each run on a scratch copy it deletes after, a table of min, median and max, and how many names agree with Solitario's.
  • --learn adds a project's reviewed names to the glossary, for every project after it.
  • A file's language is in its name, not the project file. It began as one language per project; a file's name won because one project can then mix an English library with Spanish files, each file parsed by its own language's parser over the project's shared types.
  • Compiled names are Spanish, accents kept, over stripping accents or translating to English.
    • esUnTrébol is legal in JavaScript, TypeScript and Python 3, and the author can read it.
    • Two ways of typing é are one name: names are normalized to one form of each accent.
  • Rules were refactored first, not overridden in Spanish. Turning the English words in rule code into word rules cost one big move, but a third language now costs words, not code.
  • Agreement warns, never fails, over strict Spanish where a wrong article is "Don't understand". A strict parser would need gender at match time, which it doesn't have.
  • The inflector is the pack's, not util's, so a Spanish program never pays for English's. Spanish's is a port of Python-Inflector's rules: the npm packages only pluralize, and Spell needs both ways.
  • Unaccented keywords are accepted, and the editor fixes them, over a quick fix on save: typing on an English keyboard just works.
  • Spell UI's tags start es-, over the smoke page's earlier ie-.
  • The pack fixer calls the claude command, not an SDK: no key to configure, no new dependency. The translator does too, or the Claude API by plain fetch when a key is set: still no SDK.
  • The translator writes lines by the rules, not by a model. Each line is read by its English rule and written by the same rule in Spanish, so it reads and compiles; Claude only names things and fixes the lines that fail.
  • The shape check compiles each statement in its scope, and compares the two programs, names and texts aside. Comparing the two parse trees was tried and dropped: on Solitaire it named 4 good lines, and missed the one real mismatch, a loop that lost its variable.
  • One glossary per language, shared by every project: Spell as a corpus of programs, the same English name the same Spanish name everywhere.
  • One --effort flag, in no provider's terms; each runner maps it to a model and how hard it thinks.
  • The parser's own messages speak Spanish, examples and all: a Spanish project says Di qué contiene "nombres-de-cartas", p. ej. "poner nombres-de-cartas a una nueva lista de texto". Still English: the compiled code's comment for a JSX tag it can't draw, the project-level errors (imports, exports, targets), and the runner console's "on line N".
  • The docs teach English Spell. The Spanish syntax table is generated, but no page reads it yet.
  • An English library imported into a Spanish project keeps its English names, and a plural English type name in a Spanish file is made singular by Spanish's rules: una lista de cards looks for a type named Cards.
  • ser and estar are the same to the parser.
  • Spell UI's Spanish, and the editor's, are a first draft, for a native speaker to review.
  • Still English in a Spanish editor: the project prompts, the property editor's field names, Monaco's own menus.
  • Developer-facing run-time messages stay English: assertions, thrown errors, type checks.
  • A translation reads differently from a person's. Translated cold, about 7 in 10 of Solitaire's names match the hand-made Solitario's (reina where it says dama): a first draft that runs, for a Spanish speaker to review. Only English into Spanish has been tried.
  • Not yet: a phrase like which are not a face card inside a where-clause, reading a Spell file back in another language, and a third language (Norwegian and Portuguese are next, with help from friends).
