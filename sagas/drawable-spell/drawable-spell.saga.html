A spell type is a web component: drawn, styled, laid out in HTML, and speakable in spell.

Spell types became web components: a type you write in spell now draws itself on a page like any Spell UI element.

  • drawable-thing, done and in main since 2026-10-12: "a card is a drawable thing" makes the card type a real tag, drawn on the same Solid engine as Spell UI, styled by its own <css> block.
    • Its attributes and its thing always agree, and a plain page can use the tags.
    • A <spell-app> can be laid out in HTML with spell inside it.
    • One thing can be named by its name or its place (Tableau#T1, tableau T1).
    • An edit keeps the game in progress, without running the program's start again.
  • The two epics after it are written down as future epics, not planned yet.

Two future epics wait on drawable-thing, and the parked goals had more ideas for spell on any page.

  • Spell UI In Spell: write Spell UI's simpler components (a divider, a label, a card, then the form controls) in spell, compiled ahead into the TypeScript Spell UI ships today.
    • Spell UI becomes spell's biggest real test, and its sources something a spell author can learn from.
  • Spellify Components: every Spell UI attribute and value gets a spell phrase in each language of its vocabulary ("is disabled", Spanish "está deshabilitada"), so programs read and set components in their own words.
  • From the parked goals, Web components: <spell-app> and <spell-editor> on any web page, for docs, blogs and teaching.
  • From the parked goals, The spell app: building a program by dragging things around, once things draw themselves.
